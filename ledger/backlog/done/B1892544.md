`[x]` **Two direct controls replace four.** `MapFinder.jsx`'s decide-bar tail now renders exactly "Plan this site" (the `site` verb, unchanged handler) and "Record info ▾", which opens an `AnchoredMenu` (the same shared floating-menu primitive every other dropdown in the app uses — `menuPanelStyle`'s default surface, untouched, so it needs no bespoke styling) holding three `MenuItem` rows: **Log a comp** / *Sale, lease, or land comp*, **Place a site plan** / *Attach a drawing or concept*, **Add a note** / *Pin a comment to the map* — each a 16px stroke icon (new `CompIcon`/`SitePlanIcon`/`NoteIcon` in `components/icons.jsx`, same 24×24-viewBox/`currentColor` idiom as every existing icon there) + a two-line title/subtitle column (`FONT_SIZE.control`/`FONT_SIZE.label` — no raw `fontSize`, so this adds nothing to the design-drift ceiling), separated by 1px `var(--chrome-divider)` dividers with 14px horizontal margin. `[x]` **`verbLabel("site", …)`'s singular changed "Plan a site" → "Plan this site"** (`lib/decideBar.js`) — the owner's brief specified the new wording directly; the plural ("Plan N parcels") is untouched. The bar's own accent-color "priority treatment" moved with it: `recordLeads = orderedVerbs[0]?.key !== "site"` decides which of the two OUTER buttons renders filled with its verb's accent — "Plan this site" when site leads, "Record info ▾" (tinted with the leading record verb's own accent — e.g. comp's blue) when a record verb leads — so the accent cue that used to mark "verb #1 of 4" now marks "direct action, or menu with something inside it flagged."
