### B688 — Header crumb didn't live-update when you rename the CURRENT project (Review / Library) `[Header-Nav / Review + Library]` (bug) #ui #doc-review #library  *(owner report 2026-07-07 with screenshot: "I changed the name below and it should auto update but didn't." `[x]` **DONE — shipped + sandbox+headless-verified this session (Verify: sandbox). 2,840 unit tests green (+4 `resolveCurrentName` cases) · build green · `ui-audit/verify-review-rename-header.mjs` 6/6, with a negative-control run confirming it reproduces the owner's exact symptom pre-fix.**
- Verify: sandbox
- Origin: filed 2026-07-07 from chat (screenshot)
- **Repro (owner's screenshot):** in **Review**, rename the open project in the Row-1 switcher dropdown — the dropdown ROW updated to the new name and the store persisted it, but the breadcrumb crumb ABOVE the dropdown kept the OLD name until a reload/project-switch.
- **AUDIT-FIRST root cause:** the shared `ProjectBreadcrumb` renders the crumb from the `currentProject` **prop**. In the Site-Planner planner header that prop tracks a rename live (routes through `commitSiteLabel` → `setSiteLabel`), but **Review** (`markupProject`, a `useMemo` keyed on `[projectId, meta.projectId, meta.project]`) and **Library** (`libraryProject`, recomputed per render) derive it from the **route id** and never re-derive the NAME from the store on a same-tab rename. So `commitRename → storeRename → refresh()` updated the breadcrumb's own list (the row) but not the parent's prop (the crumb) → stale crumb.
- **Fix (self-contained in the shared component — one place fixes Review, Library, and cross-tab):** new pure `resolveCurrentName(currentProject, projects)` in `projectModel.js` prefers the freshly-refreshed switcher list's name for the current project, falling back to the prop (cold/empty list, or a project not in the list) — never a regression. `ProjectBreadcrumb` now renders `currentName = resolveCurrentName(currentProject, projects)` for the crumb. Because the list is refreshed on rename **and** on the cross-tab `storage` event, a rename in another tab now updates the crumb for free too. Controlled hosts (Scheduler) are unaffected — they feed a fresh `projects` list + `currentProject` back over the bridge; the planner header is unaffected — its prop is already live and the list agrees (synchronous store write before `refresh()`).
- **Files:** `src/shared/projects/projectModel.js` (+`resolveCurrentName`, +export), `src/shared/ui/ProjectBreadcrumb.jsx` (import + `currentName` in the crumb span), `test/projects.test.js` (+4), `ui-audit/verify-review-rename-header.mjs` (new headless spec), `MAP.md` (regenerated — new export).
