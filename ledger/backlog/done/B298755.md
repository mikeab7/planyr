- **⛔ TICKING IT GOES THROUGH THE OPEN EDITOR WHEN THAT NOTE IS ON SCREEN.** The obvious implementation — read the page's JSON, flip the flag, write it back — is a silent data-loss bug for exactly the note you are looking at: the editor holds its document in memory, has up to a debounce of unflushed typing, and would write the whole of its stale copy back a moment later. So the mounted editor REGISTERS itself on the store and a tick for its page arrives as a real editor transaction. Every other page takes the JSON route and the store announces the change.
- **⛔ THE KEY IS AN INDEX **AND** THE TEXT, and the index is trusted only while it still describes the row the rollup showed.** An index alone is a position in a document somebody may have edited since; text alone cannot tell two identical "Follow up" lines apart. With two identical lines, one already ticked, an index that merely matched by text would tick the DONE one and leave the open one on the list forever — so the index must also still be in the state being changed away FROM. When neither resolves, nothing changes and the app says so.
