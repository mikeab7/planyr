`[x]` **✅ DONE — the detail view's total-rent row now formats as whole-dollar currency, matching the convention the create form's own live rent preview already used in the same file.**
- Verify: sandbox — a pure formatting-function fix, exhaustively unit-tested; no rendering ambiguity a browser could add on top of a deterministic string.
- **ROOT CAUSE.** `compFieldRows`'s lease branch formatted every dollar figure (Price, TI allowance, Total annual rent) through one shared `fmtMoney` helper using `{ maximumFractionDigits: 2 }` with no matching `minimumFractionDigits` — `toLocaleString` only CAPS the fraction digits, it doesn't pad them, so a non-round total like `4783022.4` printed with its one real decimal intact instead of being rounded to a consistent precision. The app's own convention elsewhere (`measure.js`/`SitePlanner.jsx`/`pondLabelText.js`/`yieldBar.js`) always pairs `minimumFractionDigits`/`maximumFractionDigits` so a formatter never floats between decimal counts depending on the input.
- **THE FIX, scoped narrowly.** Rather than change `fmtMoney` itself (still used for TI $/SF and Price, which are legitimately fractional per-SF rates and need their cents), added `fmtMoneyWhole` — real `Intl` currency formatting, `maximumFractionDigits: 0` — used ONLY for the derived `totalRent` row, matching the exact convention the create form's own live rent preview already used elsewhere in this same file (`toLocaleString(undefined, { style: "currency", currency: "USD", maximumFractionDigits: 0 })`). TI and Price are untouched.
- **VERIFIED** — `test/comps.test.js`: `.65 x 613208 x 12 = 4,783,022.4` renders as `"$4,783,022"` (not `not.toMatch(/\.\d/)`), and the existing Price/TI formatting tests still pass unmodified.
