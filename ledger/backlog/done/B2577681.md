- **What shipped.** `lib/univerSave.js` (pure): ONE object for the debounce, a SYNCHRONOUS IDEMPOTENT `flush()` that returns the up-to-date workbook, `dispose()` that flushes BEFORE stopping, the echo guard as a QUEUE of emitted-but-not-yet-echoed saves (two flushes before React renders the first no longer rebuild the grid to the older one), and `report()` on any failure (the edit stays pending; the next flush retries). `UniverSheet.jsx` builds on it, exposes `onReady({ flush, commitEditing })`, flushes URGENTLY on `beforeunload`, `pagehide`, tab-hidden and unmount. `ModelApp.jsx`: `flushUniver()` (Export reads the flushed workbook via `workbookForExport` — a failed flush STOPS the export with a message, never a stale file; CSV too), `setUniverOn` (commits text typed in an open cell editor, flushes, then toggles), a hidden module tab, Close file (flush before `fw.flush()`), and a layout-effect cleanup on the scope (project / org workbook / file) that flushes BEFORE the load that replaces the workbook. An urgent save is persisted SYNCHRONOUSLY by `persistUniverNow` (local copy + dirty mark → next open pushes it via `decideLoadSync` "push-local"; React does not render before a page dies); a grid being replaced saves into the workbook it was SHOWING (`scopeRef`), never the one being opened, and `uploadLeavingUniver` starts that workbook's upload at once (best effort — the regular push effect for it is cancelled by the change). `useFileWorkbook.noteWorkbookNow` takes the newest workbook into the file hook's refs + on-device draft synchronously so the leaving-file upload carries the last edit. A failed save → status badge error + message + telemetry `model-univer-save-failed`. `<UniverSheet key={scope}>` so a project / org workbook change remounts it.
