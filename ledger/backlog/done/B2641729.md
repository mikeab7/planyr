### B2641729 — a Walk or Buffer on a REAR / END wall could not be shortened by its handle — the dragged end snapped back to the full wall `[Site Planner / wall layers]` (bug) #site-planner #ui #geometry  *(found by the B2641728 handle gate, 2026-11-03)*
`[x]` **✅ Done (Verify: sandbox + live check inside V2086400).** Found while confirming that EVERY layer kind on EVERY wall role can be shortened by a handle (the precondition for removing the typed Length box). Court / trailer / buffer / walk / road on the dock wall, and parking / trailer / road on rear and end walls, already worked; a **Walk** or **Buffer** on a rear or end wall did not: both are DERIVED from the wall span (`relayoutWallKids` → `sidewalkFullRunPatch`), and a handle resize wrote no extent, so the relayout re-derived the full wall and the dragged end snapped back (red proof: e2e wall-layer-handles with the stamp disabled → `sidewalk/*` and `buffer/*` "len 1200→1200" on rear, "400→400" on ends).
- **Fix (`refitChildren`, the wall-strip branch):** when a USER resize really changes the strip's run along the wall, stamp `extentFieldsFor({run, alongShift}, span)` on it (the same three keys the typed length used to write: length, the end it was held from, offset) BEFORE `relayoutWallKids`, so the relayout keeps the held end. A depth-only drag, a host refit and the load-time heal never stamp. Guard: e2e **wall-layer-handles** (both ends, rot 0 and 315, dock / rear / end).
