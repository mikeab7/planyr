Verified point-for-point that MDI's own `redo` path is the exact horizontal mirror of `undo`'s, so "if one is filled, both are filled; if one is a 2px stroke, so is the other" holds by construction — both are single `fill="currentColor"` paths, no stroke, drawn from the one MDI source.
- **(b) Zoom to fit** — replaced `⤢` with MDI's `arrow-expand-all`: four arrows pointing OUTWARD to the corners, never a magnifier (a magnifier says "zoom", not "fit", and would be confused with the separate zoom in/out controls elsewhere on the canvas).

- **(d) File button** — was a bare "File ▾" with no border and no visible pressed state (the owner's report: he couldn't tell what it was). Now carries a 1px border, a 3px corner radius, and a 9px disclosure caret, and stays visibly "pressed" (accent border + tinted fill, `aria-expanded`) for as long as its menu is open — confirmed via computed style in both themes (border goes neutral → accent orange on open). Deliberately NOT given an `aria-label`: the visible "File ▾" text is already a complete accessible name, and several `ui-audit/` harnesses match this exact button by that name — an `aria-label` would have silently overridden it (an accessible-name footgun caught before it shipped, not after).
- **(e) Select parcels** — relocated off the permanent toolbar. It's genuinely not pointless (it's how a site gets its parcel basis, and the only way to add a lot that was missed or swap the one you started from), but it's touched once per site, so it doesn't earn a permanent seat beside Undo/Redo/Fit. It now lives in the Parcels panel (the site-setup context where choosing ground actually happens), with a route back from the canvas via right-click on the parcel itself (`onParcelContext` → a new top row in the parcel's context menu). Same control, same `setParcelSelect` behavior and per-plan persistence — only the location changed.
