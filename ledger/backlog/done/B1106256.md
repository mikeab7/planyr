`[x]` **SHIPPED THIS SESSION.** `AnchoredMenu`'s full-viewport, hit-test-blocking click-away backdrop is GONE — dismissal is now a document-level, CAPTURE-phase `mousedown` listener that is never itself a hit-test target, so it can never stand between a press and whatever is actually underneath it.
- **Root cause, exactly as the reporter measured it — two independent swallow paths, both closed by removing the backdrop rather than patching either:**
  - *post-#1371* (the shipped code): the backdrop closed on its own `onMouseDown`, unmounting between mousedown and mouseup — a native `click` only fires when mousedown and mouseup share a target, so a left-click on a real control under the backdrop (a ribbon button, a re-press of the menu's own trigger) never produced a `click` at all: the menu closed, but the control underneath never activated.
  - *pre-#1371* (still worth guarding — B1076480's own regression case): closing on `onClick` alone let a right-click's `mousedown` land on the backdrop and stay there through `mouseup` (per spec `click` never fires for the secondary mouse button), so the backdrop — still topmost — won the browser's own `contextmenu` hit-test instead of whatever the right-click was actually aimed at.
  - A document listener isn't a hit-test target at all, so both paths close at once: it observes every mouse button on every element without ever painting over anything, and closing the menu there — without `preventDefault`/`stopPropagation` — lets the underlying mousedown→mouseup→click(or contextmenu) sequence resolve exactly as if no menu had ever been open.
- **hoverSafe collapses into the default.** hoverSafe (RowInfo/SourcesLegend, B930) already used this exact "no backdrop, dismiss via a document mousedown that exempts the anchor and the panel" shape — because a hover-opened popover's own appearance under an interactive backdrop fired a spurious `mouseleave`, flashing it open/closed. Since there is no backdrop for anyone now, every consumer gets that same non-pointer-stealing behavior; `hoverSafe` stays an accepted prop (existing call sites unchanged) but no longer branches anything internally — one dismiss mechanism, not two.
- **The anchor is excluded from the dismiss listener**, same as hoverSafe's pre-existing exemption — a re-press of the menu's OWN trigger stands down here and is left to the trigger's own `onClick` toggle, so re-clicking a trigger to close it can't double-toggle back open.
