### B1895544 — Toolbar collapses (align → dropdown, insert icons → "+") under ~1000px of editor width, never wraps `[Notes]` (feature) #notes #ui  *(Same dispatch as B1895536 — item 9 of 9. Minted **B1895544**. DEDUPE-FIRST — searched for "COMPACT_BREAKPOINT_PX", "data-compact": no prior item.)*

`[x]` A `ResizeObserver` on the toolbar's OWN rendered width (never the browser window — a docked History/Outline panel eats into the same space identically) drives a `compact` state against a measured ~1000px breakpoint. Below it: the three alignment buttons collapse into one dropdown (`AlignMenu`) showing the current alignment; Link/Table/Image/Attach fold into the existing "+" Insert menu (which already held Divider/Quote/Code block/Toggle/Callout, so this is one shared trigger with two content layers, never a second plus-icon button). Bold/Italic/Underline, the font/size chips and the list buttons are never touched by either fold. The bar's own `overflowX: auto` is the safety net for anything a future addition still doesn't fit.
`[x]` **A real bug in the fold logic was caught and fixed in the same pass, not just the feature built.** The first draft's `ResizeObserver`-attaching effect had an empty `[]` dependency array — but this component returns `null` on its very FIRST render (before Tiptap's `editor` resolves), so the ref the effect needed was never attached to real DOM, and because the deps array was empty the effect never ran again once `editor` became available. Measured live: a genuinely 756px-wide toolbar (well under the 1000px threshold) sat permanently stuck at `data-compact="0"`. Fixed by adding `editor` to the effect's own dependency array, so it re-attaches on the render that first produces real DOM.
`[x]` **Phone (`narrow`) no longer selects a separate LAYOUT.** The old bottom-sheet "More" drawer is retired along with the rest of the pre-redesign overflow system (see B1895536); `narrow` now only controls tap-target sizing (44px, WCAG 2.5.5) and the pinned "‹ Notes" back control — a phone's available width is always under the compact breakpoint, so it gets the identical fold logic every other narrow window does, plus horizontal scroll for anything still left over.
