`[x]` **✅ Done — V1515280 PASSED 2026-10-05 (planyr.io build 55c9c3a, signed in).**
- **Root cause (AUDIT-FIRST):** `AppHeader` Row 2's three-zone layout (tabs | centre chip | toolbar) used `flex-wrap: wrap` (B1012560) — a deliberate "wrap the toolbar to a second line" fallback, so any shortfall below ~1100 CSS px put the whole action cluster on its own row (header 58→99 px tall). Browser zoom and OS display scaling shrink the CSS viewport, so a big monitor never meant a wide viewport.
- **Fix:** Row 2 is `nowrap`; `AppHeader` measures the row's OWN box (ResizeObserver, never window width) and hands every zone a budget in a fixed priority — centre chip (never shrinks) · module tabs · toolbar. Tabs are a `PriorityToolbar` (labels→icons from the right, then a More-modules menu, the ACTIVE tab never collapses); the toolbar budget is published through `ToolbarBudgetContext`. Phone `narrow` path untouched (sideways-scrolling rows, same chevrons).
- **Existing mechanisms kept:** the shell was already exactly viewport (`height:100%`, `overflow:hidden`, flex column + `minHeight:0` main) with `pageContainmentGuard`; the sweep proves no page scroll at every size. Row 1's breadcrumb/centre-slot/right-zone flexes (NEW-2 "navigation wins", B384064) were already correct and are unchanged.
