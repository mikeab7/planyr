- Verify: sandbox — pure UI wiring; no GIS/timing/auth dependency.
- **THE STATE.** `mode` (`'site'|'comp'`, persisted `planarfit:mapMode:v1`) lives in `MapFinder.jsx` and is the ONLY thing either surface reads or writes — `<SiteCompSwitch mode={mode} onChange={setMode}>` (the toolbar) and `<RailTab active={mode==="site"} onClick={()=>setMode("site")}>` (B831777's rail) both close over it directly. `setMode` also cancels whatever the LEAVING mode had armed (`placingCompPin`/`selectMode`), so a mode flip can never leave a stale one-shot click-handler live under the other mode's toolbar.
- **THE ACTIONS, exactly as specified.** Site active → "Select parcels" (existing `setSelectMode(true)` flow, unchanged) + "Start blank" (new in the toolbar — reuses the EXISTING `startBlankHere()` fallback the "county service is down" banner already calls; no second implementation, and the row-1 header keeps its own copy for when the map route isn't on screen). Comp active → "Drop a pin" (the old "＋ Comp" button, relabeled, unchanged `setPlacingCompPin(true)` wiring) + "Comp from parcel" (`setSelectMode(true)`, same underlying parcel-select flow Site mode uses, distinguished at commit time by `mode`). Once a parcel is selected, the commit button is chosen BY mode too — "Plan N parcels →" (site) XOR "Comp here" (comp), never both at once (the old design showed both simultaneously on one selection, which is exactly the two-unrelated-actions confusion this redesign exists to remove).
- **COMP_ACCENT — a second hue, and why.** The Comp segment/actions use a blue (`#2f6fb0`, matching the leasing-comp map marker's own "building sale" color) instead of `PAL.accent` (the existing site/plan orange) — reused consistently for the switch, "Comp here", and B831781's armed-state ring, so "blue" reads as "this is a comp action" everywhere in the cluster at a glance.
- **A real layout regression found and fixed in the same session, not shipped separately.** The switch's added width pushed the toolbar's right-section content (esp. the `placingCompPin`/`selectMode` hint text + Cancel) past the bar's `maxWidth` at ~900px, hiding Cancel under the Layers panel's corner (`Collapse layers` intercepted the click in a headless proof). Fixed by making every label button in the right section shrinkable (`flex:"0 1 auto"`, a small `minWidth`, ellipsis) instead of `flex:"none"` — at tight widths a label truncates ("Select…") rather than the row overflowing its box; Cancel and the small ✕ stay fixed-width since they're always short enough not to need it. Re-verified clean at 900/1400/2400px after the fix (see the shared harness, B831780).
