- **Anti-overlap self-thinning (the real fix, before you touch a knob):** `inlineLabelEls` floors the effective spacing to the label's OWN on-screen width + ~50% breathing room (`minGapPx = labelLen·fs·0.9`, converted back to feet at the live zoom), and takes the LOOSER of that and the requested feet-spacing. So restamps can never physically overlap, a SHORT label keeps its per-type/typed spacing at working zoom (unchanged), and only labels that would collide are thinned — which also self-thins further on zoom-out. Deliberately NOT a big fixed floor (an earlier `max(150, …)` draft dominated every zoom and made the spacing control inert — caught by the adversarial review and fixed before merge). Mirrors the `dimCalloutVisible` / label-collision level-of-detail patterns.
- **Controls persist per-feature, NON-STICKY:** new `labelSpacing` / `labelSize` / `labelHalo` fields written by direct `setMarkups` / `setSelEl` (never `mkStyle`/`liveMarkup`), so a tweak can't bleed into the next drawn shape (the B620 trap). One undo frame per commit. **No schema migration** — the fields ride through `markups`/`migrateRoad` verbatim (additive, like B620's `inlineLabel`). Defaults keep the per-type spacing (150/350/700) · size 11 · halo on; a short label at working zoom renders exactly as before, only overlapping / zoomed-out cases thin. The "background on" state reuses the existing white halo (`paintOrder` stroke `#fff`) for legibility over aerial; "off" removes it. Panel controls live in a render-body FUNCTION `inlineLabelControls` (returns JSX, not a `<Component>` — no remount).
- **DEDUPE-FIRST:** direct follow-on to **B620** (inline line labels — shipped the renderer + per-type spacing); this adds the per-label knobs + self-thinning the owner asked for on live use. Not a recurrence — B620's behavior held; these are net-new controls. Not shared with Doc Review (`inlineLabelEls` lives only in `SitePlanner.jsx`; DocReview has no labeled-line renderer).
- **PDF-PARITY note (pre-existing, honest):** the export path (`buildExportSvg`) CLONES the live SVG, so inline-label density in a PNG/PDF tracks whatever zoom the export ran at. This zoom-dependence already existed pre-B678 via the `minSegPx` LOD (B620); the anti-overlap min-gap mildly amplifies it but is far gentler than the rejected fixed floor. No `data-export="skip"` on the label, so halo/size/spacing render identically on screen and in export at a given zoom. A fully zoom-independent export (re-render at the export scale) is a larger, separate change, noted for a future pass.
