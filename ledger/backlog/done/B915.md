- **The one shared primitive (DEDUPE-FIRST):** reused the existing portal/placement pattern rather than writing a new positioner. `AnchoredMenu`/`anchoredMenuPlacement.js` (B734) anchor to a TRIGGER element (dropdowns/flyouts); a context menu anchors to the CURSOR and must FLIP, which that math doesn't do — so the new pair sits beside it:
  - **`src/shared/ui/contextMenuPlacement.js`** — pure `placeContextMenu({cursorX,cursorY,menuW,menuH,viewportW,viewportH,margin,gap})`: (1) anchor top-left at the cursor; (2) flip LEFT if it would overflow the right edge; (3) flip UP if it would overflow the bottom edge; (4) a final hard-clamp to an 8px margin on all four edges (covers corner clicks where both flips fire, browser zoom, and a menu larger than the viewport); (5) a `maxHeight` of viewport−2·margin so an over-tall menu scrolls. Framework-free, 7 unit tests.
  - **`src/shared/ui/ContextMenu.jsx`** — portal-to-`document.body` (escapes any `overflow:hidden`/transform-trapped ancestor), `position:fixed`, MEASURES itself in a `useLayoutEffect` (before paint — no flash) → `placeContextMenu` → applies left/top/maxHeight, hidden until placed. Re-places (not closes) on content-grow via a `ResizeObserver`. Closes on Escape, outside click, and page scroll / window resize (a scroll INSIDE the menu is exempt). Props: `x,y,onClose,width/minWidth,zIndex,margin,gap,panelStyle,className,role,ariaLabel,testId`.
- **Every cursor-positioned menu migrated to it** (removed each one's assumed-dimension math): MapFinder `statusMenu` (the repro) + empty-map `mapMenu`; SitePlanner `vtxMenu`, `parcelMenu`, `mapMenu` (canvas/deed), `typeMenu` (element Arrange), `ovMenu` (overlay); Doc Review markup `ctxMenu` (Arrange); Library `FolderContextMenu`; ProjectBreadcrumb project-manage menu. `data-testid` (`folder-context-menu`, `project-manage-menu`) + role/aria-label preserved via props. `createPortal` imports dropped where they became unused (FolderTree, DocReview).
