### B555 — Planner two-finger pinch is "super buggy" on mobile Safari `[Site Planner / mobile]` (bug)  *(owner-found 2026-06-28 once actually planning a parcel on mobile Safari; minted **B555** = highest real B# across both files (B554) + 1; branch `claude/mobile-safari-pinch-menu-3gon8x`)*
`[x]` **DONE + verified. lint 0 · 1782 tests · build green · headless 3/3.** The Site Planner's pinch-zoom ran on **pointer** events. iOS Safari's multi-touch pointer-event support is unreliable — it routinely fires a spurious `pointercancel` on the first finger the instant a second touches, which tore down the pinch mid-gesture and let a one-finger pan fight it (the "super buggy" feel: jumpy, dropping out, sticking). Rewrote the gesture on **native touch events** (`onTouchStart/Move/End/Cancel` on the canvas `<svg>`):
  - `e.touches` always carries every active finger each frame, so the gesture never "loses" a finger the way pointer events did on iOS.
  - View updates are throttled to **one per `requestAnimationFrame`** so a heavy plan doesn't re-render on every raw `touchmove` (the other half of the jank).
  - On the 2nd finger landing, any one-finger pan that just started is torn down **and the view restored** to its pre-pan offset, so the pinch can't jump in.
  - While ≥2 fingers are down (`touchCountRef`), the pointer-driven pan/draw/vertex-edit handlers all bail, so nothing competes with the pinch. Single-finger pan/draw are untouched (the guard is false for one finger).
  - The canvas already sets `touch-action: none`, so the browser's own pinch-zoom is suppressed and the (passive) React touch handlers need no `preventDefault`. Blur/visibility recovery (`abortGesture`) also clears the new pinch state + cancels any pending frame. The old pointer-pinch refs (`pinchRef` etc.) are left vestigial only where `abortGesture` still clears them.
  - Reuses the shared `pinchZoom`/`midpoint`/`distance` engine (`shared/viewport/viewportTransform.js`) — the math was already correct; only the event source changed.
- **Verify:** `ui-audit/verify-planner-pinch.mjs` (CDP multi-touch, 390×844) 3/3 — pinch-out zooms in, pinch-in within the same gesture zooms back out, a second pinch still works (not stuck). The actual iOS flakiness only reproduces on a real device (headless Chromium's pointer multi-touch is well-behaved) → real-device confirm owed as **V169**.
