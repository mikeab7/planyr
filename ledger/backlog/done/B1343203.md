- **⛔ TWO REAL BUGS, both found by the live harness, neither visible from reading the source.** (1) The FIRST measurement heuristic used the wordmark's own width to derive the available budget — under-measured by ~17px of padding/divider/flex-gap between the wordmark and the breadcrumb, so the owner's own reported case (Goose Creek / Phase II - Revision at 375px) never compacted. Fixed by measuring the real DOM position instead of reconstructing it from parts (the breadcrumb's own left edge against the row's right edge). (2) A React ref-ordering bug: `rowRef` belongs to an ANCESTOR element (AppHeader's row div, which CONTAINS this component), and React attaches refs bottom-up in the same traversal as layout effects — a descendant's layout effect (this one) can fire before an ancestor's own ref is attached, so the FIRST measurement on mount could read `rowRef.current === null` and never retry, permanently under-compacting. Fixed with a one-frame `requestAnimationFrame` re-measure (by which point every ref in the tree has committed) that also starts observing the row for resize at that point — proven with a dedicated live-resize-after-mount test (rotate the harness in place, no reload) so this exact class of bug — correct on first load, silently stuck on a later resize — cannot come back unnoticed.
