### B2577680 — Univer grid: a plain drag on a selected row / column header MOVES it; Excel only moves with Shift `[Spreadsheet]` (bug) #ui #testing  *(owner brief 2026-10-30, cutover plan step 4; spike parity row "Dragging an already-selected header")*
`[x]` **✅ DONE — merged (PR #2746, build `d73c86c`) and PASSED live 2026-10-30 (V2033376 arm H).** Repro (spike parity run): click column C's header, then press and drag on that header → Univer MOVED column C (C1 "cherry" became null). Expected (Excel): a plain drag on a header, selected or not, extends the header selection; **Shift+drag** moves; rows the same; the border still resizes and a double-click still autofits.
- **Root cause (measured, not assumed).** Two things, not one. (1) Univer's `HeaderMoveRenderController` starts a move on ANY drag from an already-selected header. (2) Univer's selection controller, on a press on an already-selected header, RETURNS EARLY and leaves it to the move controller — so merely disabling the move left a dead press (selection stayed `C:C`), not an extend. Found by probing: the first gate attempt "passed" the old check only because the gate was never installed (`render.with(HeaderMoveRenderController)` throws until Univer's `Rendered` lifecycle stage registers the module — now retried until it exists).
- **Fix (no package patched).** `lib/univerHeaderMove.js` (pure) + `UniverSheet.jsx`: (a) a Shift gate put in front of the controller's own `HEADER_MOVE_PERMISSION_CHECK` interceptor point (priority above Univer's permission check, which still gets the last word when Shift is held; Shift state is fed from capture listeners on the host, the interceptor is handed no event); (b) a capture-phase `pointerdown` that, for a plain primary-button press on an already-selected header with no modifier and not on a resize border (canvas cursor `*-resize`), collapses the selection to one in-view cell first so Univer builds a fresh header selection from the pressed header and the drag extends it. Ctrl/Cmd+click (adds a range) and right-click never collapse. Re-installed on every unit the grid builds (an outside reload creates a new unit).
- **Verified in the sandbox (real mouse, real Chromium, `ui-audit/verify-univer-parity.mjs`):** `header-drag-moves` (C → C:E, C1 still "cherry"), `header-drag-moves-rows` (2 → 2:4), `header-shift-drag-moves` (Shift+drag moves column C and row 2), `header-press-keeps-others` (Ctrl+click still adds E:E to C:C), `header-resize-autofit` (border drag 120 → 188, double-click autofit 188 → 120). **Red-proof both halves:** with the gate and the restart removed the check FAILS with "column C was MOVED …" / "row 2 was MOVED …"; with only the restart removed it FAILS with "selection is C:C (should extend to C:E)". Unit: `test/modelUniverSave.test.js` (gate handler, Shift tracking incl. a lost keyup, `pressOnSelectedHeader` incl. the modifier / button cases, wiring).
