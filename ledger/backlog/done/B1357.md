`[x]` **Shipped — the harness and the reading. `ui-audit/perf-harness.mjs --long-session`, protocol in `ui-audit/lib/longSession.mjs`, decision layer unit-tested in `test/longSession.test.js` (15 tests).**
- **THE READING, on the reference Goose Creek plan at 4x CPU throttle.** `hold` arm (**the plan never changes**, so anything that moves is retention): 5 rounds of pan / zoom / travel to unvisited map area / panel open-close / select-deselect. Wheel median **116.7 → 133.4 ms**, inside the measured ±12.5% floor. JS heap **29 → 30.1 MB**, no trend. Canvas DOM nodes **967 → 948** (down). Document nodes flat. Drawn elements flat at 64 — the control holding. `grow` arm (20 paving elements added through the real draw tool): wheel **100 → 150 ms** with canvas nodes **967 → 1,068** and document nodes **1,838 → 1,948**, correlating at **r=0.93** (document nodes) and **r=0.83** (canvas nodes).
- **THE ANSWER: on this evidence the cost tracks HOW MUCH IS DRAWN, not how long the session has run.** Same plan, same gestures, twenty minutes apart → no move that clears the floor. Add twenty elements → the cost rises in lockstep with node count. "The plan got bigger" is load and is not a bug; the retention story is not supported here.
- **THE ONE COUNTER THAT DOES MOVE, repeatably, in BOTH arms and unexplained:** DOM-commit deliveries per pointermove, **2.2 → 7.6–9.3** across three separate runs. It is a STEP between rounds 1 and 2 rather than a gradual trend, which points at a session STATE left behind by the workload (a panel, a selection) rather than unbounded growth. Not chased in this PR — recorded, so the next pass starts from a number. **Owned by B1359's sibling work; if it is still there after that, it gets its own item.**
- **⛔ THE SUSPECT THIS CANNOT EXERCISE, stated rather than routed around.** No basemap tile DECODED in any run (`tilesLoaded` 0 → 0): this sandbox blocks the external tile hosts, and decoded map imagery is the largest single suspect for the owner's ~278 MB tab. Nothing here clears or convicts it. **V539 stays open**, and **V518 stays open** — its acceptance terms are retained-tile count and decoded bytes, neither of which exists in a run where no tile decodes.
- **THREE DEFECTS IN THIS HARNESS, each found by running it and each fixed:** (1) a **zero noise floor** — a steady pan reports the identical quantised median every repeat, so the spread is 0 and a later 16.8 vs 16.7 reads as a regression; the floor is now never smaller than one frame quantum. (2) **one endpoint is not a trend** — the same `hold` arm reported "within-noise (+0.1%)" and "SLOWER (+14.3%)" on consecutive runs, so a move is only called real when the last TWO checkpoints clear the floor in the same direction (`unsustained` otherwise). (3) the `grow` arm **added nothing** on its first run (the draw button was addressed by a selector that does not exist) and silently degenerated into a second copy of `hold`; it now reports that in a named block instead.
