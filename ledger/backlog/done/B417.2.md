- **Repro (owner screenshots):** a 580′(w) × 664′(h) building. Because h > w the dock sides resolve to **left/right**, yet a 135′ truck-court stack (court → trailer → buffer) sat **stranded on the TOP** — a non-dock short side. Trailer parking must appear ONLY on dock faces (`dockSidesFor(b).dockSides`): single-load → one dock side, cross-dock → both, never a non-dock side.
- **Root cause (evidence-first — the filed hypothesis was off):** the named suspect (the legacy opposite-dock trailer row `OPP_TRAILER_D` / `oppTrailerGeom` / `fitWallTrailer`) was **already dead**, gated on an `oppSide` tag nothing creates. The REAL leak: a dock-zone stack is **pinned to the side it was created on** (`truckCourt.side`); when a building's long-side axis flips (a reshape) or its dock preset changes, `relayoutAllSides` re-laid the stack on the now-non-dock side and nothing pruned it. `trailerSides` from the old inline `dockSidesOf` was confirmed unread and dropped.
- **Fix:** new pure, unit-tested `lib/dockZones.js` helpers — `dockSidesFor` (one shared rule for canvas/panel/depth/guard), `strandedZoneIds`, `pruneStrandedZones` — prune a stranded stack **on reshape commit** (pointer-up, so one undo restores size + apron), **on dock-preset change** (`changeBuildingDock`), and **on plan open** (`useState` init → existing stranded plans self-heal). Removed the dead opp-trailer path. +10 dockZones unit tests incl. the requested "zero trailer elements on a non-dock side" for BOTH presets; headless V120 (stranded-on-top → pruned; identical stack on a real dock side → kept, so the prune is targeted).
