### B627 — Chambers County "can't click / GIS is down": TxGIO disabled the parcels `/query` op — route outlines via `/export`, clicks via `/identify` `[Site Planner]` (bug) — high  *(owner-reported 2026-07-03 "figure out why i cant click / why chambers county gis is down"; minted **B627** = highest real B# across both files (B626) + 1 after merging `origin/main` — a concurrent session took B625/B626 for the deed-alignment work below; branch `claude/chambers-county-gis-down-ttqfnv`)*
`[x]` **Fixed + shipped this session.** Chambers County parcels are served by the **TxGIO statewide parcel MapServer** (`feature.geographic.texas.gov/.../Parcels/stratmap_land_parcels_48_most_recent/MapServer/0`), which is also every county's outage fallback (`STATEWIDE_PARCEL_LAYER`). **Root cause (confirmed live):** TxGIO **disabled the layer `/query` + `/find` operations** on that service — both now 400 with `"Requested operation is not supported by this service."` (extendedCode -2147220222) — even though the layer metadata still advertises `capabilities: Map,Query`. The service's **`/identify` and `/export` ops still work.** Because the app renders parcel outlines with esri-leaflet's **`featureLayer` (which draws by QUERYING)** and identifies a clicked lot with a **point `/query`**, both went dark on Chambers: **no outlines painted AND no lot could be selected** — exactly "can't click / GIS is down." Working counties (HCAD/FBCAD, whose `/query` is healthy) were unaffected.
- **The two symptoms, both root-caused to the same dead `/query`:** (1) `makeParcelLayer` → `EL.featureLayer` renders via `/query` → blank Chambers (no lines); (2) `queryAtPoint` → point `/query` → capability error → click selects nothing.
- **Fix — outlines via `/export`:** new `makeParcelImageLayer` (an esri `dynamicMapLayer` → server `/export` image, `transparent`+`minZoom`-gated) and a single smart entry point `makeParcelDisplayLayer(url)` that routes **only** the known query-disabled `STATEWIDE_PARCEL_LAYER` to the image overlay; every other (queryable) CAD stays the styleable vector `featureLayer` (which also backs the instant B441 client-side click highlight). Applied at both display sites — MapFinder's Select-parcels tool and SitePlanner's in-planner Add-parcel outline. `parcelDisplay.js`.
- **Fix — clicks via `/identify`:** `queryAtPoint` now wraps its `/query` in try/catch; on the **specific** capability error (`isQueryCapabilityError`) **and** only for a `/MapServer/<id>` layer, it retries the MapServer **`/identify`** op (`identifyAtPoint`) — building a small synthetic map frame around the click and returning the parcel that actually **contains** the point (even-odd PIP) in the same `{geometry:{rings},attributes}` shape. A real timeout/network/other error still surfaces as an outage; FeatureServers are untouched; **self-heals** (the fallback never fires once TxGIO re-enables `/query`). `arcgis.js`. The eager multi-county click path + circuit breaker heal automatically (a successful identify records the source healthy), so the "statewide backup / unavailable" notices clear too.
- **Honest residual (documented, self-healing):** typed **ID/address search** on Chambers stays down until TxGIO restores `/query` (text search needs `/query` or `/find`, both dead — `/identify` is spatial-only). The app already degrades to "search unavailable — pan/zoom (click the lot) instead," which works. Noted in `counties.js` + surfaced to the owner.
