### B2671280 — The first click after switching measure tools is eaten when it lands on (or, for an Area, inside) an existing measurement `[Site Planner]` (bug) #site-planner #selection #ui  *(owner chat block "NEW-1", 2026-11-13, Bain plan; AMENDS B910)*
`[x]` **FIXED, MERGED (PR #2958, aca82c7) AND LIVE-VERIFIED 2026-11-13.** Owner: after an Area measurement, choosing Length — "the FIRST click on the map does not register; subsequent clicks work"; his lead: the dropped click landed on the boundary of an existing measurement. **Confirmed, and wider than his lead.**
- **Measured (real Chromium, real mouse, logged-out blank site; `e2e/measure-first-click.spec.js`, RED on the pre-fix build):** open ground NEVER dropped the click, in any mode pairing; a press on an existing measurement's **vertex** (15 of 16 mode pairings), **edge** (11 of 12) or — for a finished **Area** — **anywhere inside it** (a transparent filled grab polygon covers the whole shape) was eaten. Fresh tool from nothing, an unfinished draft left open at the switch, and right-click all behaved. (Some pairings read "pass" in the red run only because an earlier soft failure left state behind; the green run is the acceptance.)
- **Root cause:** B910 let a finished measurement's grab layer take a press while a Measure tool was armed and no draft was open (`canGrab = tool === "select" || (tool === "measure" && !measDraft.length)`); `startMoveMeasure` then selected it and called `setTool("select")` — no point placed, tool silently changed. Only this one press-starter had the exception: every other (`startMoveEl`, `startMoveMarkup`, callouts, parcels, overlays, every grip) is gated on `tool === "select"`, so no other drawing tool shares the cause (pinned structurally by `test/measurePressNeverSwitchesTool.test.js`, red on main: 3 assertions).
- **Fix (`SitePlanner.jsx`):** a LEFT press on a finished measurement is handled in the Select tool ONLY (`canGrab = tool === "select"`; `startMoveMeasure` returns otherwise and never calls `setTool`); in Measure the shapes stay hit-testable (`hitLive`) for RIGHT-click alone, so `onMeasureContext` still selects + opens the menu from any tool; the press bubbles to `onBgDown` and places the point; the "move" cursor is Select-only (crosshair in Measure). Read-only test hook: `data-testid="measure-draft"` + `data-points` on a wrapper of the in-progress draft (the pinned inner markup in `test/measureSheet.test.js` is untouched).
- **Product consequence, stated plainly:** B910's "left-click a finished measurement from the Measure tool to select it" is RETIRED (owner constraint #56 in CLAUDE.md). A measurement is picked in the Select tool or by right-click. `e2e/measure-select.spec.js` now drives the Select tool (and asserts a Measure-tool click places a point); its cycling test's crossing moved off the summary chips (chips capture presses in Select by design).
- **Not built (optional per owner: "snapping to it is fine and probably desirable"):** snapping the first point onto an existing measurement's vertex/edge. Not needed for the fix; a separate feature if wanted.
- **Noticed, not changed:** switching measure mode while a draft is open silently discards the draft (`selectTool` clears `measDraft`); the owner asked only about the dropped click.
- Verify: live — ✅ PASSED 2026-11-13 on planyr.io, signed in as the test account, served build aca82c7 read in the same run as the verdicts (`node ui-audit/verify-measure-first-click-live.mjs https://planyr.io --expect-sha aca82c7`): a throwaway plan with a finished Area and Length measurement; for each next mode (Length, Area, Polylength, Count) a real-mouse press on open ground, the area's corner, its edge, inside the area, and the length's edge each placed ONE first point (`measure-draft` data-points=1), nothing selected, tool still Measure (20/20, run twice); known-good arm (Select tool press on the area's edge selects it) held; throwaway plans deleted and verified gone. Also passed on the PR preview (build 0a62406). Pre-fix: the same press SELECTED the measurement on production build 26e1573 (instrument VOID for the draft read there, by design).
