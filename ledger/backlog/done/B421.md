### B421 — Markup z-order ("Arrange"): Bring to Front / Forward / Send Backward / to Back via Bluebeam shortcuts + a right-click menu `[Doc Review / Markup]` (feature)  *(owner-dropped 2026-06-23 as "NEW-1"; minted **B421** = highest B# across both files (B420) + 1; deduped net-new)*
`[x]` **Filed AND built + verified + shipped to main the SAME session per STANDING RULE #1 (branch `claude/gallant-turing-mcempv`). lint 0 · 1335 tests · build green; headless `ui-audit/verify-b421-arrange.mjs` 17/17 (V122).**
- **What:** when two markups overlap on a sheet, control which draws on top — Bluebeam's four Arrange ops on the selected markup (Bring to Front, Bring Forward, Send Backward, Send to Back), reachable two ways from ONE shared core: keyboard chords and a new right-click context menu. Net-new — there was no z-order control before.
- **Core (one engine, both entry points):** new pure module `src/workspaces/doc-review/lib/arrange.js`. `reorderWithinPage(markups, id, mode)` permutes the selected markup within its **same-page** siblings (draw order IS z-order — the overlay paints `pageMarks` in array order, so the last same-page entry is on top), then splices the reordered group back into the global array **without disturbing other sheets' markups** (they keep their absolute slots, so an arrange never silently shuffles another sheet's stack). Returns the SAME array reference on a no-op (already at that end / a lone markup / unknown mode) so a top/bottom arrange skips the history push + state write. `arrangeFlags(markups, id)` reports `{page, count, index, atTop, atBottom}` for the greying. `DocReview.arrange(mode)` wraps it with `pushHistory()` so every arrange is one undoable step (B303) and persists for free (markups are already saved/mirrored).
- **Keyboard:** the existing `onKeyRef` handler gains an arrange branch **before** the `if (mod) return` early-out (which previously handed every other modified key back to the browser, so a branch after it would never fire). Gated on `mod && sel`; matches **`e.code`** (`BracketRight`/`BracketLeft`), NOT `e.key` — Shift turns `e.key` `]`→`}`, which would silently miss the Bring-to-Front chord. ⌘ works via the existing `e.ctrlKey || e.metaKey`; the INPUT/TEXTAREA guard already blocks firing mid-text-edit. `]`=up / `[`=down, Shift=jump to the end: `⌘/Ctrl+]` Forward · `⌘/Ctrl+Shift+]` Front · `⌘/Ctrl+[` Backward · `⌘/Ctrl+Shift+[` Back.
- **Right-click menu:** new `onContextMenu` on the viewport runs the existing `hitTest` (B33) at the cursor — a hit selects that markup and opens the menu at the cursor; a **miss** does nothing (no `preventDefault`, so the native browser menu shows over blank canvas — never an empty custom menu). The menu is **portalled to `<body>`** (`createPortal`, the same escape-the-clip pattern as `AnchoredMenu`/the Site-row context menu) so the canvas's `overflow:hidden` + stacking can't clip it; cursor-positioned + viewport-clamped; dismissed on click-away / right-click-away / **Escape**. Items: the four Arrange ops (with platform-aware shortcut hints), a divider, then **Edit text…** (text notes only, reuses the B293 inline editor) and **Delete** (reuses the existing `pushHistory` + filter-by-id). Arrange items **grey out** at the top (Front/Forward) / bottom (Back/Backward) of the stack; a lone markup disables all four. Not opened while an inline editor / calibrate entry is active.
- **Scope / parity:** built in `DocReview.jsx` (the single-sheet markup surface). **Skipped `Stitcher.jsx` deliberately** — it renders only `measures` (distance/area), with no overlapping fillable markups (rect/cloud/text), so an Arrange menu there would be empty/no-op. Toolbar buttons for Arrange are out of scope (shortcuts + right-click only) — an easy follow-up.
- **Tests:** `test/arrange.test.js` — **14 unit tests** (all four ops; single-step Forward/Backward are inverses; SAME-reference no-ops at the ends / lone markup / unknown id / unknown mode; other-sheet slots preserved through an interleaved-page reorder; input not mutated). Headless **V122** (`ui-audit/verify-b421-arrange.mjs`, **17/17**): three overlapping rects, every chord + every menu item reorders correctly verified BOTH via the DOM order AND the persisted localStorage draft, each undoable, greyed at top/bottom, blank-canvas right-click shows no menu, Edit-text only on a text note, Delete works, and the order **survives a full reload**. 0 page errors.
