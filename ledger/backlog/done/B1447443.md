### B1447443 — iPhone 15 Pro Max landscape: the left icon rail is bottom-clipped and the phone Properties sheet never appears `[Site Planner]` (bug) #site-planner #ui #mobile  *(found by the B1447440 phone-orientation harness, 2026-09-09, running WebKit against real `planyr.io`: the largest current iPhone in landscape (iPhone 15 Pro Max, 814px effective width) exceeds the app's 760px phone/desktop breakpoint (`useNarrow()`), so it silently renders the full DESKTOP layout — the fixed left icon rail (Land/Analysis/Drainage/Yield/Properties/Overlays/Standards) does not fit the 380px-tall landscape viewport and its bottom two entries ("Overlays", "Standards") render partly below the visible area with no scroll container to reach them; separately, because the phone-only Properties bottom sheet is gated on the SAME 760px breakpoint (`isPhoneSheetMode`), selecting an element on this device/orientation never offers it at all — only the docked desktop Properties panel does. Minted **B1447443** from the B1447440 session's reserved block against `origin/main` 3db7429e. Filed as FINDINGS ONLY; this entry is the follow-up dispatch that fixes it.)*
`[x]` **FIXED THIS SESSION.** A width-only breakpoint can't distinguish a real phone held LANDSCAPE (wider than the cutoff, but shorter than it too, and touch-operated) from an actual desktop browser window that happens to be that wide. `isPhoneShape` (new pure function, `src/workspaces/site-planner/lib/deviceShape.js`) widens the test: a device is treated as phone-shaped when it's narrow by WIDTH (unchanged legacy rule) **or** when it has a COARSE (touch) pointer **and** a short viewport height — reusing the existing `FLOAT_MIN_WIDTH` (760) token for both the width and the new height check, no new magic number. `coarsePointer` is never true for a mouse, so this can only ever ADD phone-shaped devices to what the old width-only test already caught; it can never turn a real desktop window into a phone at any height. `SitePlanner.jsx`'s single `narrow` state (previously raw `matchMedia("(max-width:760px)")`) is now `isPhoneShape({ narrowWidth, shortHeight, coarsePointer })`, so every downstream consumer of `narrow` in this file — including `isPhoneSheetMode` (`propertiesSheet.js`), which is why the Properties-sheet half of this report is fixed by the same one-line change — now agrees a landscape phone is a phone. Separately, the left rail container gained `overflowY:"auto"`/`minHeight:0` unconditionally (matching the right tool rail's own pre-existing pattern a few lines below it in the same file), as a second, independent line of defense: even inside the correct phone/overlay layout, a rail with more entries than a very short viewport has room for needs a scrollbar to stay fully reachable, and a rail that already fits (the desktop case) renders no scrollbar and is visually unaffected.
