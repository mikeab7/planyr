`[x]` **AUDIT-FIRST — the brief's premise was partly stale, and the code reality is recorded here.** `lib/notesZoom.js` (named in the brief) was already DELETED by B1815024; the canvas is a transform viewport (`lib/notesViewport.js`: `zoomAbout`, `zoomForWheel`, `stepZoom`, per-page persistence), not a scroller, so "scrollTop arithmetic" does not exist — the pointer anchor is `zoomAbout` (both axes, the viewport is unbounded). Ctrl+wheel/pinch, Ctrl+=/−/0/9 and the pill were already there and are unchanged.
`[x]` **What the site plan does, and how Notes matches it.** `SitePlanner.jsx` `onWheel` (attached non-passive to the canvas wrapper): a PLAIN wheel, no modifier, zooms about the cursor — up = in, down = out — at ×1.12 per notch through `zoomAround`, with `[data-wheelscroll]` panels exempt so they scroll themselves. It has no modifier to scroll instead. Notes now does the same: plain wheel → `zoomAbout` at the pointer, same direction. **Deliberate difference, stated:** Notes keeps its existing PROPORTIONAL curve (`zoomForWheel`, e^(−Δ/400): a mouse detent ≈ ×1.28, trackpad deltas continuous) so plain wheel, Ctrl+wheel and pinch are ONE curve, smooth within the 10%–800% clamp (not snapped to the ladder — the ladder is for the keys); the pill reads the level either way and persistence is the existing per-page store, unchanged.
`[x]` **Moving around a long note without the wheel (the site plan has no scroll modifier, so this is added):** **Shift+wheel pans vertically** (macOS reports it as deltaX with deltaY 0 — the non-zero one is taken); **a mostly-sideways delta pans horizontally** (a trackpad swipe or tilt wheel is never a zoom intent); left-drag on grey, middle-drag, space-drag, and the zoom keys are unchanged. ⚠ **Owner-facing consequence, told plainly:** a laptop trackpad's ordinary two-finger up/down scroll is a wheel event, so it zooms now; two-finger sideways pans; Shift + two-finger up/down pans vertically.
`[x]` **The wheel does not hijack what scrolls itself.** The listener is on the canvas only, so the toolbar menus (portaled), the notebook rail, the Outline/History panes and dialogs never receive it. Inside the canvas, `wheelOwnerUnder` (`NoteEditor.jsx`) leaves the event NATIVE (no `preventDefault`) when the pointer is over an element that can really scroll on the axis the browser would use (a wide `.tableWrapper`, an overflowing list), or `[data-wheelscroll]`, or a menu/listbox/dialog role; Ctrl/⌘+wheel still zooms over those and the browser's own page zoom stays suppressed. A table that only scrolls sideways still zooms on a vertical wheel (nothing to scroll that way).
