### B1830912 — Bin view is sticky after clicking a real page `[Notes]` (bug) #notes #ui  *(owner chat block, "NEW-1," 2026-09-22: viewing a binned page (Bin → Read it), then switching back to Pages and clicking a real page, left the editor showing the binned page's content while the sidebar highlighted the clicked page as if navigation had happened — the sidebar lied about what was on screen. Minted **B1830912** from this branch's reserved block B1830912–B1830927 against freshly-fetched `origin/main` 465aa91. DEDUPE-FIRST — searched Open/⏳Verify/Done/Done-archive for "bin peek sticky", "peek" + "activePageId", "notes-peek": no prior item names this. Net-new.)*

`[x]` **ROOT CAUSE.** `Notes.jsx` renders the read-only bin reader whenever its `peek` state is set, unconditionally ahead of the normal editor (`{peek ? <bin reader/> : <normal editor/>}`) — but nothing that opens a REAL page (`onSelectPage`, `onSelectHit`, `onOpenTask`, the cross-workspace `noteIntent` open, creating a page, QuickOpen, the duplicate-finding banner's "open the other copy") ever cleared `peek`. Each of those correctly set `activePageId` (which is what drives the sidebar's `aria-selected` highlight), so the sidebar looked right while the editor pane kept rendering the stale peek. Confirmed live before touching any code: seeded a binned page + a live "Platting" page, peeked the binned one, switched to the Pages tab, clicked Platting — sidebar highlighted Platting, editor still showed the bin reader.
`[x]` **THE FIX — the bin is a MODE, and every way of leaving it now closes the peek, not just the one path the report named:** every real page-opening callback in `Notes.jsx` now calls `setPeek(null)` before/alongside `setActivePageId(...)` (`onSelectPage`, `onSelectHit`, `onOpenTask`, the `noteIntent` cross-workspace open effect, `handleAddPage`, `handleAddSubpage`, `handleOpenFinding`, QuickOpen's `onPick`). Restoring or permanently deleting the entry currently being peeked (`handleRestore`/`handlePurge`) also closes the peek, since there is nothing left in the bin to keep reading. **And leaving the Bin tab itself (Pages/Tasks, with no page click at all) now closes it too** — `NotesTree`'s `onViewChange` handler clears `peek` whenever the view isn't `"bin"` — because a tab switch away from Bin is exiting the mode exactly as much as a page click is, and the old code left that path unfixed (a plausible re-report waiting to happen had only the literal repro's callback been patched).
`[x]` **Unit tests:** no pure-library change (this is UI wiring in `Notes.jsx`/`NotesTree.jsx`, not `lib/`); covered instead by the new live harness below and the existing `test/notesModule.test.js`/`test/notesReachability.test.js` suites (unaffected, still green).
`[x]` **New live regression guard, real browser, real build, logged out:** `ui-audit/verify-notes-bin-mode-exit.mjs` (22 checks) — peeks a binned entry, switches tabs, clicks a real page, and asserts the peek reader is gone, the clicked row is genuinely `aria-selected`, and the editor's own title field reads the real page's title (not stale bin content); a second arm proves switching to Tasks with no page click also closes the peek; a third exercises the sidebar's own Restore/Delete-forever/Back-to-pages actions (see B1830913) and confirms each one closes the peek too.
