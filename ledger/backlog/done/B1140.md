- **Report.** Tsakiris, Contour lines (1 ft) on, z17+. Hover any contour: the tag paints AT the cursor and the pointer glyph — a large grab hand while the Pan tool is armed, which is most of the time — sits on top of the number. Owner: *"my mouse shows a grab and it ends up covering the elevation that I'm trying to see."*
- **Fix.** `contours.js` gains the pure placement decision (`hoverLabelPlacement` / `hoverLabelSize` / `HOVER_LABEL_GAP_PX`): the tag's NEAR EDGE sits a fixed number of SCREEN pixels off the pointer (so the clearance is identical at every zoom), default up-and-right, and the quadrant FLIPS — up-left, down-right, down-left — for the first one whose whole rect fits. Nothing fits (a box barely bigger than the tag) → the least-bad quadrant is clamped inside the box, and a clamp that would slide the tag back under the glyph re-flips the other axis instead. The gap is sized against the LARGEST cursor glyph in use (grab/grabbing), not the arrow.
- **The box is the VISIBLE canvas, not the container.** `terrainLayers.visibleBox` measures the clip parent against the overscanned map container, so the tag can't be silently cut off by the clip (container coordinates run well past what the user can see). A bottom band is reserved for the furniture the planner floats over its own bottom edge — the coordinate/elevation chip bottom-left, the scale bar and zoom cluster bottom-right. The right-hand **Tools rail needs no reserve**: it is a flex SIBLING of the canvas, so it is outside this box already.
- **One trap worth recording:** an in-flow `inline-block` sits on the marker div's LINE BOX, so the inherited font's baseline strut pushed the tag a few px below the anchor — invisible when a label is merely centred "about" its point, decisive when the placement is exact arithmetic against a canvas edge. The offset variant is `position:absolute;left:0;top:0` so its top-left IS the anchor. Permanent index labels keep the historic centred markup byte for byte.
- **Everything B1095 shipped is preserved and re-asserted:** one tag at a time, own sublayer cleared every move, same white-halo style and size, the ≤40 px no-double-stamp rule, the z16 gate, the shared throttled mousemove (no second listener), and B1087's supersession guard. The hover key now carries the pointer's whole-pixel position, because the tag is anchored at the CURSOR — without it the tag would sit still while the pointer moved along one contour.
- **Tests.** `test/pointerRegistration.test.js` (15 cases on the pure placement: default quadrant, every edge and corner, the reserved bottom band, a tiny box, screen-invariance, the width over-estimate) **including an explicit "B1095's placement would have FAILED this" case** so the guard can't be vacuous. `e2e/contour-hover-elevation.spec.js` gains a browser test that runs a lap just inside all four canvas edges with contours ON and asserts, per painted tag: it never intersects the pointer glyph's footprint, never leaves the visible canvas or the reserved bottom row, and that BOTH flips actually fired (else "never clipped" could pass vacuously). Stale frames are detected and skipped rather than asserted.
- **Sandbox evidence.** `npm test` 6364 green · lint 0 errors · build green · the whole `contour-hover-elevation` spec file green (7 tests, incl. the pre-existing one-label/no-ghost/no-double-stamp assertions).
- **One residual, stated rather than implied:** the glyph clearance is asserted against a stated pointer footprint (headless Chromium renders no cursor bitmap). An OS "large cursor" accessibility setting draws a bigger hand than that; if that ever comes up, the gap is one named constant.
