**ROOT CAUSE, measured, not guessed (item point e asked directly: was this pixel arithmetic? No.)** The toast's `position:fixed; bottom:28px; left:50%; transform:translateX(-50%)` centering is ordinary, correct layout, unrelated to the defect. The actual bug: `showToast` (`public/sequence/index.html`) built its pill as a `display:flex` row carrying BOTH `maxWidth:"420px"` AND `whiteSpace:"nowrap"`. `max-width` genuinely capped the pill's own painted background at 420px — but a flex item's default `min-width:auto` means it never shrinks below its own content's intrinsic size while `overflow` stays `visible`, so the nowrap text span rendered at its full, uncapped width and simply overflowed past the (correctly capped) background. That is exactly the screenshot: a pill that ends, with the sentence continuing past it in plain page text.

**THE FIX.** Dropped `whiteSpace:"nowrap"`; the message span gets `minWidth:"0"` (so the flex item can actually shrink to the container's cap) and `overflowWrap:"break-word"`, so a long message WRAPS onto more lines instead of escaping sideways — nothing is truncated or shortened (item point c). `maxWidth` becomes `"min(420px, calc(100vw - 32px))"` so the cap itself never exceeds a phone viewport (item point d), and `alignItems` moves from `"center"` to `"flex-start"` so a wrapped, multi-line message's icon sits at the top of the block instead of mid-paragraph. Checked EVERY message this shared component renders (item point b), not just the meeting-step one — the same container fix covers the B624 weekend/holiday-roll toast, the paste/cut/copy confirmations, and the import/restore toasts; none needed a per-string change.
