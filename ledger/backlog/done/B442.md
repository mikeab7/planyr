### B442 — Merge/Clear banner buttons unclickable; canvas grab-cursor + pan bleeds through `[Site Planner]` (bug)  *(owner-reported 2026-06-24 via screenshot+voice as "NEW-1"; minted **B442** = highest real B# across both files (B441) + 1)*
`[x]` **Fixed + shipped (branch `claude/gallant-euler-sk8kwd`). lint 0 errors · 1421 tests · build green · headless V (`ui-audit/verify-merge-banner.mjs`, 6/6).**
- **Repro (owner):** Select tool → Shift-click 2+ parcels → the floating "N parcels selected · Merge parcels ⏎ · Clear" banner appears → hovering Clear showed the canvas **grab hand** (not a pointer), and clicking it **panned the map** instead of clearing the selection; Merge was likewise dead.
- **Root cause (confirmed in code):** the banner is a sibling of the SVG canvas under `wrapRef`, and the SVG carries `zIndex:1` while the banner had **no z-index** (auto). A positioned `zIndex:1` paints *over* an auto sibling, so the transparent canvas sat on top of the banner — it swallowed the clicks and showed its own `cursor:grab`. The buttons' own `cursor:pointer` never won because the press never reached them.
- **Fix (`SitePlanner.jsx`, merge-banner block ~L6871):** gave the banner an explicit **`zIndex:6`** (clears the SVG's `1`, below the slide-in tool rail) so its buttons are the topmost element — clicks land, the pointer cursor applies, Clear runs `setCombineSel([])`, Merge runs `mergeParcels()`, neither starts a pan. Added defensive `onPointerDown`/`onMouseDown` `stopPropagation` on the banner container (belt-and-suspenders for any future reparenting under a pointer-handling ancestor — the z-index is the actual fix). Applied the **identical guard to the sibling parcel-edge easement banner** (`tool==="easement" && easeMode==="parceledge"`), which had the same latent bug.
- **Dedup:** NOT **B271** (that fixed interrupted-gesture recovery via pointercancel/blur — a stuck-capture *recovery* path); this was a plain missing z-index on a normal press. NOT **B441** (that was MapFinder county-map identify *latency*; this is the planner's banner stacking). Cross-referenced both.
