- **THE FIX.** New `requestDelete(taskIds)` replaces the direct `deleteTasks(...)` call at BOTH row-delete entry points (the keyboard Delete key's full-row-selected branch, and the context menu's "Delete Row"/"Delete N Rows"). If none of the targeted rows has any children, it deletes immediately — **no prompt, no extra click, exactly as before** (asserted live: a leaf delete shows zero modal). If any targeted row has children, it opens a new `DeleteChildrenModal` with exactly two choices plus Cancel — no menu, no settings toggle, no remember-my-choice, per the owner's explicit "keep it minimal":
  - **"Delete all N"** (cascade) — the whole subtree goes. Reuses the existing, unchanged `deleteTasks`.
  - **"Keep subtasks"** (promote) — new `promoteAndDeleteTasks`/pure `promoteChildrenAndDelete`: every child is reparented to the DELETED row's own parent (never "the row above," which the brief flagged as a DIFFERENT and NOT ALWAYS EQUIVALENT reading — implemented per the owner's own final correction, "they'll move up to this task's parent"). Handles a whole deleted CHAIN transitively: deleting a parent together with one of its own children (an explicitly tested adjacent case) promotes the child's own children past BOTH deleted ancestors, straight to the nearest SURVIVING one — `survivingAncestor` walks the parent chain skipping every id in the delete set, not just one level. No repositioning logic is needed for promote (unlike outdent): filtering out the deleted rows never changes the relative order of the survivors, so a promoted row already sits exactly where it needs to among its new parent's other children.
  - **"Cancel"** — closes the prompt, changes nothing (verified live: tree is byte-identical after Cancel).
- **EQUAL-SIZED BUTTONS, measured via `getBoundingClientRect`, not asserted in prose.** All three buttons render at 134.65–134.67 × 34 px (the ~0.02px spread is Chromium's own documented Blink LayoutUnit rounding on independently-shrinking flex siblings — the SAME measured floor this repo's OTHER modal's own equal-width test already tolerates, `EQUAL_WIDTH_TOLERANCE_PX=0.1` in `verify-successor-complete.mjs`).
