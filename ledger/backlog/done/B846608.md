`[x]` **SHIPPED.** Root cause confirmed exactly as the report's own hypothesis. `AccountControl.jsx` renders one of two mutually-exclusive pills when nobody is signed in — `supabaseConfigured()` (`site-planner/lib/supabase.js`) is a pure build-time truthy check on `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY`, inlined as string literals by Vite. CI's required `build` check (`.github/ci-gates.yml`) always carries the repo's real, owner-provisioned secrets on its Build step, so its canonical logged-out state is the **"Sign in or create an account"** pill. A build made without those two env vars set — the default on a bare `npx vite build` with nothing exported — falls through to the **"Cloud sync isn't set up"** pill instead: a real, correct rendering of a real, different app state, just never the one CI measures. The committed `docs/UI-INVENTORY.md` had been regenerated against an unconfigured build, so its embedded copy held the wrong branch's text; CI's own `--check` regenerates fresh every run and always disagreed with it, on any PR that happened to touch that file, regardless of what the PR actually changed. `ci-parity.mjs` already closes this exact gap for a session that regenerates *through* it (it substitutes a truthy dummy secret when the real one is absent — B927104) — nothing stopped a session from running `ui-inventory.mjs` directly against a hand-built preview server and committing the wrong state with no warning at all.
