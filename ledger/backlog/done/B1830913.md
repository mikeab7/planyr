### B1830913 — Bin action buttons drift with page title length `[Notes]` (bug) #notes #ui  *(same owner chat block as B1830912, "NEW-2," 2026-09-22, with an approved reference mockup: the bin-peek reader's "Restore it"/"Close" buttons sat inline after the banner text, so a short title ("Notes") left them mid-banner while a long one ("Phase 2 Site Infrastructure Coordination Meeting Notes — Sept 2026") pushed them to the far right or wrapped them onto a new line. Minted **B1830913** from the same reserved block. DEDUPE-FIRST — searched Open/⏳Verify/Done/Done-archive for "bin banner buttons", "Restore it" + "Close" + "drift", "notes-peek-restore": no prior item names this. Net-new.)*

`[x]` **FIXED per the approved mockup's shape: Restore / Delete forever / Back to pages moved out of the editor and into the sidebar, in one fixed spot the peeked page's title can never move.** `NotesTree.jsx`'s `BinList` gains a `peekEntryId` prop; the entry currently being read gets a highlighted border (`e.id === peekEntryId`) and a "viewing" action cluster (`notes-bin-viewing-actions`) renders once, stacked below the whole entries list — `↩ Restore to pages` (reuses the existing `onRestore`), `✕ Delete forever` (reuses `onPurge`), and `← Back to pages` (leaves bin mode via the same `changeView("tree")` the tab strip already uses, which in turn closes the peek — see B1830912's `onViewChange` fix — one mechanism, not a second way to dismiss the same state). `Notes.jsx` passes `peekEntryId={peek?.entryId || null}` down to `NotesTree`.
`[x]` **The editor's own status row is now a slim, button-free read-only indicator** — "🔒 Read-only preview from the bin — nothing you do here changes it." — with no interactive controls except the pre-existing narrow-only "‹ Notes" phone-back link (kept because on a phone the sidebar, and its new action cluster, is off-screen while peeking — that link is still the only way back there, not a duplicate of the removed buttons). `notes-peek-restore`/`notes-peek-close` are gone.
`[x]` **Root cause of the drift, for the record:** the removed buttons lived inside a `flex` row alongside the banner's own text span (`flex: 1`), so their position was a direct function of how much room the title left them — correct-looking at any one title length and wrong the moment a real title varied, which is exactly why nothing caught it earlier (PERCEPTUAL-PARITY-style "looks right at the one length someone tried").
`[x]` **New live regression guard** (shared with B1830912): `ui-audit/verify-notes-bin-mode-exit.mjs` peeks a SHORT-titled entry, records the action cluster's bounding box, switches to peeking a LONG-titled entry, and asserts the cluster's position drifts by `< 1px` between the two (measured `0.00px` live) — plus that the editor's own status bar carries zero `<button>` elements at both title lengths. A pre-existing sibling harness, `ui-audit/verify-notes-project-integrity.mjs`, exercised the old `notes-peek-close` button as part of its own (unrelated) bin/peek coverage — updated to read/switch peeked entries the new way instead of clicking a now-removed button, and re-verified green (73/73) rather than left to bit-rot red.
