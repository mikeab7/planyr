- **AUDIT-FIRST — what the code actually did.** The app was ALREADY split into 11 chunks and `React.lazy` already gated every workspace. The defect was not missing splitting: `src/app/Shell.jsx` ran `prefetchOnIdle(["scheduler","doc-review","library"])` at mount (B223), and its `requestIdleCallback` fired at **~t=304 ms — BEFORE first-contentful-paint at ~328 ms**. So B223's own premise ("nothing here runs at boot; lazy-loading still gates the first paint") was false in practice: `requestIdleCallback` fires in any main-thread gap, including gaps *during* boot while the critical path is still in flight. Worse than the bytes, `import()` fetches at HIGH priority **and evaluates** the module, spending parse/compile time in exactly the window the planner needs to become interactive.
- **Reproduced locally before editing**: a Site-route load against the real build fetched all 11 chunks, the second wave (Scheduler · DocReview · pdf · pdf.worker.min · uploadQueue · Library · folders) landing ~85 ms after the first — matching the owner's resource-timing trace exactly. `pdf.worker.min` (471 KB) rides along because Vite records the `?url` worker asset as a STATIC import of DocReview, so warming DocReview drags it in.
- **Fix.** Removed the boot-time warm entirely (`prefetchOnIdle` deleted; `Shell.jsx` effect removed). Warming is now driven purely by navigation intent from the module tabs: the existing `onMouseEnter` (`AppHeader.jsx`, B223's other half) **plus a new `onPointerDown`** so the touch/tap path — which has no hover — still gets a head start before the click commits. B223's instant-switch UX is preserved for anyone aiming at a tab; a session that never leaves the Site route now pays nothing.
