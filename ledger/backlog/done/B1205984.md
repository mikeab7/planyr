`[x]` **FIXED AND VERIFIED THIS SESSION, both headlessly (unit tests) and live (headless Chromium against a real local build).** A new pure gate, `workbookHasContent(workbook)` (`src/workspaces/model/lib/sheetModel.js`), decides whether the CURRENT workbook has anything an Import Excel action would actually throw away — more than one sheet, or any cell/format/style/merge/named-range on its one sheet; a brand-new, never-typed-into workbook still reads as empty. `ModelApp.jsx`'s `onImportXlsxFile` now checks this BEFORE ever reading the chosen file: an empty workbook imports immediately exactly as before (no regression to the "drop a file, it just works" case); a non-empty one queues the file and shows an inline confirm (`FileMenu.jsx`, the same no-`window.confirm` shape this app already uses for every other destructive action — `ReviewsBar.jsx`/`VisitPanel.jsx`/`CompEntryGrid.jsx`'s `DiscardCloseConfirm`) naming the sheet count and the file, with "Keep this workbook" / "Replace" buttons.
