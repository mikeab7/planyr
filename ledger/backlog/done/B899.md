### B899 — `next-id.mjs --against-main` silently degraded to a stale local-only max on BACKLOG-DONE.md (1.4 MB+, past the default 1 MB execSync buffer) → caused a real B896 mint collision `[Tooling]` (bug) #infra  *(self-discovered 2026-07-18 mid-session while late-binding B898's real number for the Layers-panel redesign (B898 chat brief): `npm run next-id -- --against-main` reported "highest assigned: B895" (stale) right after a concurrent session had already shipped B896/B897 to `main` for an unrelated feature (numeric-typeface unification) — this session's code/tests/comments had already been written under the provisional label **B896**, matching the just-taken number exactly. Caught before push via a manual `git show origin/main:BACKLOG-DONE.md` cross-check; renumbered this session's work to **B898** before shipping.)*
`[x]` **IMPLEMENTED + unit-verified this session.** `readOriginMain` (`scripts/next-id.mjs`) calls `execSync("git show origin/main:${file}", …)` with NO explicit `maxBuffer` — Node's default is 1 MB, and `BACKLOG-DONE.md` is 1.7 MB and only grows (write-only archive). The call threw `ENOBUFS`, which the `catch { return null; }` swallowed with zero visible signal, silently degrading `--against-main` to the LOCAL-ONLY max (exactly as if `--against-main` had never been passed) — the one failure mode this flag exists to prevent, and a LOUD-FAILURE violation in the shared tooling every session's late-bind mint depends on.
