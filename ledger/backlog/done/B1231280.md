- **What changed.** `src/app/HelpReportControl.jsx`'s FAB `onClick` (`toggleOpen`) now calls a single new `armCapture()` the moment the panel OPENS (never on close) — the earliest point compatible with a keyboard Enter/Space activation, not just a mouse press. `armCapture` calls `perfRecorderArmed()` / `requestPerfCapture("manual")` / `perfCaptureDelivery()` — the SAME bind seam `perfRecorderHandle.js` already exposes, no second capture path — and freezes the outcome in one `cap` state value (`{armed, taken, deliveryPromise}`) for the whole time the panel stays open. Both "Report a problem" (`submitProblem`) and "Something was slow just now" (`somethingWasSlow`) read that ONE frozen `cap` via a shared `perfOutcome()` resolver; neither calls `requestPerfCapture`/`perfCaptureDelivery` again. `cap` resets to null when the panel fully closes, so the next opening re-arms fresh.
- **Three honest states, carried into every `context.perf`, never a silent omission (LOUD-FAILURE):** `captureArmed:false` (the recorder hasn't installed on this page yet — `main.jsx` defers it to an idle callback on every route, so a press in the first few seconds after load can race it) · `captureArmed:true, captureTaken:false` (armed but this press's own budget/allowlist refused it) · `captureTaken:true, captureDelivered:<bool>` (taken; delivered or not, matching #953/#958's existing vocabulary). An empty ring (nothing happened before the press) is NOT a fourth case — `requestPerfCapture` still returns `taken:true` for it and the capture itself carries `note:"no-frames"` (`perfCapture.js`, pre-existing), which is the honest "nothing was happening" answer rather than a failure to record.
- **Said so, not just done so.** The "Something was slow just now" row shows a plain hint line ("Performance recording hasn't started on this device yet — try again in a few seconds") when `cap.armed` is false, instead of just greying the row with no explanation. The "Report a problem" disclosure ("What will be sent with this") now names the attached performance snapshot when one exists, and says plainly when none will be attached — this is a NEW disclosure line, since the old form never attached a capture at all (see B1231281's adjacent finding below on "Report a problem" not carrying one before this session). Help text updated to describe the new behavior in plain language.
