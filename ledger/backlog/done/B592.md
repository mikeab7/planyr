The owner never wanted that: it should stay ON the building and only slide ALONG its length, and never onto a corner bump-out (where the real depth differs, so the printed value would be a lie). Fixed by constraining the drag to one axis + a geometry-derived clamp band; same pure clamp runs at render time so legacy/stale offsets self-correct.
- **Pure module `src/workspaces/site-planner/lib/dimSlide.js`** (`dimSlideRange` + `clampDimOffset`, 14 unit tests). `dimSlideRange(el, bumps, posF)` returns the slide axis (the LONG/length axis, matching renderElPx's `horizLong = w>=h`), the perpendicular (depth) axis that is pinned to 0, and the `[min,max]` band the along-offset is clamped to. The band is the footprint length minus each corner bump-out's along-span at its end (`endNeg`/`endPos`) — i.e. the clear middle run where the depth equals the displayed value. `clampDimOffset` drops the perpendicular component to 0 and clamps the slide component.
- **Drag (`startDimMove`/`dimMove`, `SitePlanner.jsx`):** the valid band (fixed geometry) is resolved once at grab time via the new module-level `dimSlideFor(el, allEls)` (which gathers the host's dog-ears through `bumpsAlongLength` → `dogEarSize().along`); each move slides along the length axis only and clamps — so the line tracks the pointer along the building but won't follow it off the shape or onto a bump.
- **Render (`renderElPx`):** the stored offset is run through the same `clampDimOffset(dimSlideFor(...))` for DISPLAY too, so a pre-B592 free-drag offset (off the shape / carrying a depth component) or one stranded by a later resize/bump edit renders back on the footprint; the next drag persists the clamped value. The dashed off-building **leader line was removed** (nothing to bridge once the line always stays on the shape). Applies to buildings (with bump-out exclusion) and, for consistency, to road/paving width callouts (no bump-outs → just the stay-on-the-shape clamp).
- **Reuse, not a parallel pattern:** `footprintDepth`/`horizLong` semantics, `dogEarSize` (B362), and the existing B146 drag flow are reused untouched; only the offset math changed. Additive — no schema/persistence change (`dimOffset` field unchanged, just always clamped now).
