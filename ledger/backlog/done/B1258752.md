- **THE FIX — gate per band, per seam, never on the section minimum.** `lib/roadCrossSection.js` gains two named floors, `XSEC_BAND_FILL_MIN_PX` (3, same number the old single gate used) and `XSEC_STRIPE_MIN_PX` (1 — a hairline stripe stays legible far past the point a solid fill of the same width would just be visual noise). `SitePlanner.jsx`'s `renderElPx` now checks each band fill against `e.band.w * ppf >= XSEC_BAND_FILL_MIN_PX` individually, and each lane-marking seam against the NARROWER of its two adjacent bands (`bandStripeMarksWithWidth`, a new export carrying `minBandFt` per seam alongside the existing `atOffset`/`style` — `bandStripeMarks` itself, and its shape, is untouched, so the dialog's preview is unaffected). A band or seam that's genuinely sub-pixel simply contributes nothing, which is what it would contribute anyway; every other band keeps painting.
- **The designated-ROW line block is untouched by this item** (already ungated on band width; separately fixed for a different gate in B1258754 below).
