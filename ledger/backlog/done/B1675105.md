- Verify: sandbox — closed. A real browser CSS-cascade check (below) plus a pure stylesheet-text unit suite both pass; nothing here needed a signed-in account.
- **AUDIT-FIRST: this was never a schema/editor bug.** Every `<ol>`, nested or not, starts its own counter at 1 with `list-style-type: decimal` by plain browser default unless told otherwise — so a genuinely nested numbered list showing "1." at both levels is the browser doing exactly what it always does; the gap was a missing stylesheet rule, not a defect in `sinkListItem`, the schema, or the already-shipped B1656400–B1656403 Tab/Enter/Backspace fixes (which are explicitly re-verified untouched below, per that item's own "ALREADY VERIFIED LIVE TODAY — do not redo and do not regress" instruction).
- **THE CONVENTION, stated as a decision (as instructed) rather than left implicit:** decimal → lower-alpha → lower-roman for numbered lists, disc → circle → square for bulleted lists, cycling every third real level — the same cycle length Word and Google Docs both use. **A checklist is deliberately NOT part of this**: `ul[data-type="taskList"]` already renders `list-style: none` (the checkbox IS the marker), so there is no glyph left to step — nesting there stays communicated by indentation alone, unchanged. This is stated explicitly rather than silently applying only to two of the three list types.
- **TWO INDEPENDENT MECHANISMS DECIDE DEPTH (per `lib/notesListIndent.js`'s own header), and both are stepped — DELIBERATELY NOT SUMMED, and that limit is named rather than hidden.** REAL structural nesting (`sinkListItem`, a genuine nested `<ol>`/`<ul>`) cycles by DOM depth via pure CSS descendant-selector chains (`lib/notesIndentLevel.js`'s new `listMarkerCssRules`, mirroring `indentCssRules`'s existing generated-table pattern) — specificity, not source order, does the correct depth ordering for free (each added `:is(ol,ul) > li >` hop is one more type selector, so a genuinely-deeper item's rule always outranks a shallower one that also matches it, proven live below). The FLAT `data-indent` attribute (Tab's fallback for an item with no sibling to sink under — the "Tab again" case named in the brief) cycles by ITS OWN VALUE, independent of any real ancestor depth the same item might also carry — summing the two would need a combinatorial cross-product of every real depth × every indent value × two list types for a genuinely rare compound case (an item both really nested AND flat-indented on top); this file accepts that small, documented inaccuracy rather than bloating the generated stylesheet for it. **The ONE KNOWN BEHAVIOUR the brief flagged (a second Tab applying a flat attribute rather than a third real level) is UNCHANGED** — this item only changed which marker glyph an already-existing level renders, never the mechanism that decides what a level IS.
- **A COLLISION FOUND AND CLOSED BEFORE IT SHIPPED: a bare `ul` selector would have put a bullet back in front of every checkbox.** `ul[data-type="taskList"] { list-style: none }`'s `none` is INHERITED by its `<li>` children, and inheritance loses to ANY rule that targets the element directly — so an unqualified `ul > li { list-style-type: disc }` would have overridden it. Every "ul" this generator writes is qualified `ul:not([data-type="taskList"])` (`PLAIN_UL`, one constant, both as a styling target and as a counted ancestor hop — nesting a plain list inside a checklist item does not count a level against a marker glyph that was never drawn), and a unit test asserts EVERY "ul" token the generator ever emits carries the exclusion, not just a sample.
- **PDF-PARITY, by construction and by test.** `lib/notesIndentLevel.js`'s `listMarkerCssRules(scopePrefix)` is the ONE generated table both `NoteEditor.jsx`'s `EDITOR_CSS` and `lib/notesPrint.js`'s `PRINT_CSS` read — a unit test asserts the two outputs are identical modulo the scope prefix, so the screen and the printed/exported sheet cannot drift. Markdown export is unaffected (it already expresses nesting as indentation, per `notesMarkdown.js`'s existing design; no marker glyph to carry).
- **VERIFIED LIVE, in a real Chromium via a new harness (`ui-audit/verify-notes-list-markers.mjs`, 16/16), against the actual built app — not just that the rule EXISTS but that a real browser cascades it correctly:** a real ordered list three levels deep (decimal → lower-alpha → lower-roman → cycles back to decimal at level 4), a real bulleted list three levels deep (disc → circle → square), the flat `data-indent` fallback for both list types (levels 1–2), MIXED nesting (a bulleted list nested inside an ordered one correctly reads as depth 1 — circle, not disc — proving the ancestor-hop counting is type-agnostic), and the checklist safety case (a top-level AND a nested checklist item both stay `none`, checkbox only, at every depth).
