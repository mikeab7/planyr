`[x]` **Bug half — Save was always lit.** Repro: Settings → Profile, touch nothing → "Save profile" bright and enabled. **Fix:** new pure `lib/settingsForm.js` (`savedProfileValues` / `profileDirty`); Save is `disabled` unless the form DIFFERS from the SAVED values (trimmed), so editing a field back to its original value disables it again (a comparison, never a "touched" flag — the old `dirty` ref is now only the don't-clobber-a-background-reload guard), and a successful save moves the baseline so it returns to disabled. Label reads **Save** when clean, **Save changes** (orange) when dirty. Other Settings sections: "Update password" was already gated on a ≥6-char entry (its own dirty rule); Interface has no save (changes apply at once); Team's buttons are actions gated on their own input. I removed my own extra grey override so the app's global disabled fade applies once (PANEL/contrast rule: no stacked fades).
`[x]` **Design — phone width only.** At ≤560px (the breakpoint the old `.settings-shell` CSS already used) Settings opens on a MENU page only: "Settings" + Close, identity row (green avatar initial, full name, email muted), a grouped rounded list — Profile (Name & organization) · Team (Who's in your org) · Account & security (Password, sessions) · Interface (Theme, zoom), each with a chevron — and a separate one-row group with **Sign out** as centred red (`--danger-text`, already in the theme) text, not a filled button. Tapping a row DRILLS IN to that section as its own page: "‹ Settings" back link left, section title centred, Close right; the menu is not in the DOM on the section page and no form is in the DOM on the menu (a `matchMedia` hook, not CSS — hidden is still walked by a screen reader). The avatar menu's **Settings** row opens the menu; its **Profile** / **Team** rows name a section so they land straight on it. Profile page: muted "Signed in as <email>", First/Last side by side and Organization full width, each with a real `<label htmlFor>` ABOVE the input (placeholders removed — they duplicated the label), full-width Save.
`[x]` **Unsaved-changes guard.** Back, Close, Escape and a backdrop click with unsaved Profile edits show "Discard changes?" — **Discard** (reverts the form to the saved values, then leaves) / **Keep editing**. Never silent. (`requestClose` is a stable callback because `Wrap`'s focus-trap effect depends on `onClose`.)
`[x]` **Desktop — said plainly: a two-column layout ALREADY existed** (section nav beside the content, `.settings-shell`), which a drill-in would break, so per the brief desktop KEEPS it and gets only the shared fixes: visible labels, dirty-aware Save, Sign out restyled to destructive text. No new colors (only the existing danger token).
