### B1129 — A Denver site lost its MHFD answer whenever the GIS endpoints were down `[Site Planner / detention]` (bug) #yield #gis #floodplain  *(minted via `git fetch origin main && npm run next-id -- --against-main`. Found 2026-07-29 by the B1105 DOM harness, which failed for exactly this reason. DEDUPE-FIRST: no existing item covers the regime resolution's input precedence. Net-new.)*
`[x]` **✅ Done 2026-07-29 (sandbox — proved headless with every external host blocked, which is the whole point).**
- Verify: sandbox
- **The defect, and why it mattered more than it looks.** `coRegime` resolved from the **identified** county only — `drainCtxData.authority.jurisdiction.county`, which comes from the drainage GIS context. With that context unresolved (external hosts blocked, a county service down, a plan opened offline) the regime was null, the fail-closed seam did its job, and a Denver site silently dropped to the blanket "not available in Colorado" guard instead of its MHFD answer. That **directly contradicts the principle the entire Colorado tier is built on**, stated in `siteRegion.js`'s own header: the guard has to hold when every GIS endpoint is down, *because that is exactly when a site is most likely to fall through to a default*.
- **Fix.** The plan's OWN saved county is the fallback; the identified county still wins when it exists, because it is the better fact. Applied consistently to the regime, the evaluator's county argument and the jurisdiction note.
- **Why this cannot introduce a wrong answer.** `coloradoRegimeFor` maps Colorado county slugs and nothing else, so the `county` field's well-known Harris default (the B1091 warning in the Site Planner folder pointer) returns **null** and falls straight through to the hard guard — and `computeMhfdDetention` re-checks membership against whatever it is handed and refuses a non-member. The fallback can only ever ADD a correct resolution.
- **Evidence.** `ui-audit/verify-b1105-mhfd-panel.mjs` asserts "the regime resolved with all GIS endpoints down (plan's saved county)" against a seeded Denver plan in a browser with no network, and asserts a Larimer plan still names no district.
