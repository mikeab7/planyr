### B2024624 — Site planner "Click a lot on the map": the outline layer mounted 36+ nationwide parcel images and flashed gold (statewide) then blue (Chambers) on every view change `[site-planner / parcels]` (bug) #site-planner #gis #perf  *(Owner report 2026-10-03 (NEW-1), Grand Port `smqfy2r7pdec`, build fe6574f. Site-planner twin of B1976336, which only fixed the Map finder.)*

`[x]` **Cause (AUDIT-FIRST, confirmed in code):** the identify-mode effect looped over EVERY `COUNTIES_MAP` key and mounted each one's display layer, with no view scoping and no failure handling — so the statewide TxGIO composite sat under Chambers' own layer (gold under blue; the gold showed whenever the Chambers image reloaded) and Harris, Hawaii, Georgia… each added a full-viewport image.
`[x]` **Fix:** new `lib/parcelOutlineSet.js` (dependency-injected, unit-testable): ONE source per area from `displaySourcesForView` (the same function the Map finder uses — B137 holds: what is drawn = what is clickable), re-synced on `moveend` and when the county geometry lands; a statewide composite is added for a state ONLY while a county source under the view has actually failed (error event, or no first draw in 8 s, the Map finder's own guard) and is swapped back out on recovery; aliased URLs share one layer; listeners are attached before `addTo`. A slow-but-alive county source is never swapped out, so nothing flashes to a second dataset during a reload (esri-leaflet keeps the previous image until the new one loads). Read-only `window.__plannerParcelOutlines()` (diag-armed) reports what is mounted. The Map finder path is untouched.
- **Red-proof:** `test/parcelOutlineSet.test.js` — (a) only in-view sources mount, never the whole registry; (b) with the Chambers export pending, no statewide layer ever mounts over it; failed county → statewide once; plus a structural guard that fails on the pre-fix per-`COUNTIES_MAP` mount loop (verified red on the pre-change source). Real browser: `ui-audit/verify-click-a-lot-outlines.mjs` (seeded Chambers plan, hosts mocked) — **before: 2 images, parcel requests to 12+ hosts (Harris, Larimer, Arkansas, Esri-hosted counties…), statewide mounted, no hook; after: 0 images at this zoom, parcel requests to `gisdata.pandai.com` only, outline set `["chambers"]`, no statewide.**
- **Adjacent cases (reported, not all live):** Harris view → `["harris"]`; Fort Bend view → `fortbend` (bbox fallback also lists neighbours only until the county geometry asset lands, then releases them — re-sync wired); no-county-source view → the statewide composite only (pure function; geometry-dependent, so asserted in the Map finder's own suite); Chambers slow/failed → statewide takes over once (unit-tested with fake layers); re-click removes only that lot (untouched path); Map finder Select-parcels path unchanged.
- **NOT reproduced here — "the map view jumps when the Parcels panel opens on entering the mode":** the harness reads the view before/after entering the mode on a seeded plan and it does not move (aerial and county hosts are blocked in the sandbox, so the owner's exact case could not be driven).
