- **CURRENT BEHAVIOR, reported as instructed before changing anything.** The message rendered through `MapFinder.jsx`'s generic, page-corner `err` banner — shared with a dozen unrelated notices (address-search failures, parcel-service errors, sharing errors, KMZ export errors). That banner is `position:absolute`, spans from near the TOP of the pane on narrow/mobile widths down to the bottom-left zoom-control floor, with its content anchored to the BOTTOM of that span — so on a narrow layout it rendered right under the search bar while the actual locate button sits at the bottom-left corner, exactly the "floats near the top-left … no visual connection to the control" the owner described. **It never auto-dismissed at all** — grepped every `setErr` call site: no timer anywhere clears it; the only way it disappeared was an unrelated later action (a new address search, a parcel pick) happening to reset the same shared state, so in the worst case it could sit on screen indefinitely.
- **THE PATTERN CHOSEN, and why.** This app has two existing anchored/popover mechanisms: `ContextMenu` (positioned at a click's x/y coordinate, for right-click menus) and `AnchoredMenu` (positioned relative to a trigger ELEMENT via `getBoundingClientRect`, portal-to-`document.body`, already the shared mechanism for every other rail/flyout in the app — B734/B127). **Chose `AnchoredMenu`**, since the message is about a specific persistent CONTROL (the locate button), not a click point — the same reasoning that already governs every other anchored popover in this codebase. Its placement math (`anchoredMenuPlacement.js`) had three modes (`left`/`below-left`/`below-right`), none fitting a BOTTOM-LEFT corner control (a `below-*` placement would push off-screen); added a fourth, `above-left` (left-aligned, sits above the anchor — small, additive, backward-compatible), unit-tested alongside the existing three. Rendered in `hoverSafe` mode (no interactive full-viewport backdrop) so the popover never blocks ordinary map interaction while it's up — a passive notice, not a gate.
- **AUTO-DISMISS.** `LOCATE_NOTICE_MS = 6000` (6s) — chosen because the message is one short sentence (reads as two lines in the popover's width): long enough to read twice with room to spare, shorter than the app's general sync-conflict toast default (`TOAST_TTL_MS`, 8s) because there's no action to weigh here, just a fact to notice. Still dismissible immediately by hand (an explicit ✕, `AnchoredMenu`'s own click-away, or Escape) — none of those wait for the timer.
