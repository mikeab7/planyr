### B2671190 (×2) — Zoning / Future Land Use (every GIS AREA fill) cut out in a block around the site on the site plan view: the stored map snapshot (×1) and a dropped reference picture (×2) were drawn over the fills `[Site Planner / Layers]` (bug) #site-planner #layers #gis #ui #pdf-parity
- Reported: owner, 2026-11-05 (project smvsphq82qqu "Academy", plan "Concept A"): Jurisdictions › Zoning and Future Land Use paint all around but a roughly rectangular block surrounding the site is unfilled, edges just outside the site boundary; the Map view fills straight across.
- **Root cause (MEASURED, not inferred):** the plan carries its pinned "Aerial backdrop" capture (`legacy-aerial`, `fromMap`, opaque, locked, 5,660 × 10,800 ft ≈ 1.8× the parcel each way). With the Map Base dropdown on **Off** the planner drew that capture as an SVG `<image>` inside the canvas — ABOVE the backdrop map — so an opaque rectangle painted over every GIS AREA fill (all area layers live in the Leaflet panes under the SVG). With the live basemap on it stands down, so no hole. Reproduced on planyr.io 2026-11-05 on a throwaway plan with the owner's snapshot record: basemap on → every point the city's service holds is loaded AND painted; Map Base Off → the rectangle. The print was never wrong (`exportSheet.js` lays the snapshot under the GIS overlay images): only the screen drifted (PDF-PARITY).
- **Not the cause (ruled out):** the grading "Paper background" (grading is off on his plan, `settings.grading` null); `layerAbove` (only `fema`); request cells / draw budget / the planner's cull (service truth = loaded = painted on a 3,100 × 6,000 ft parcel fixture at 1500 × 950 and 1913 × 1000, 0 and 85 elements); his second overlay PNG (a hand-dropped reference — references sit above fills by design, mapStack).
- **Fix:** `lib/aerialSnapshot.js` — a located plan's snapshot is hosted in the backdrop map as an `L.imageOverlay` in `mapStack.PANE_SNAPSHOT` (z 150, under the GIS panes; bounds through the same feet → lat/lon the tiles and print use); the canvas no longer draws it (`snapshotDrawnInCanvas`); an unlocated plan is unchanged. Applies to EVERY area-fill layer (Counties & Cities tint, School Districts, TIRZ, Airport Zoning, flood zones …) — one shared cause.
- **Not fixed / stated plainly:** the Map Base "Off" control still reveals the snapshot (as a bottom-of-stack picture) rather than blank paper; its tooltip says "No aerial — plain drafting background". Not changed without the owner's say-so — the snapshot has always been the aerial when the live tiles are off, and the print follows the same rule.
