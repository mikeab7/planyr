DEDUPE-FIRST — searched Open/⏳Verify/Done for "ProblemsList", "validateComp", "rowHasBlockingFlags", "quiet affordance": the rate/period blocking flag (the one case that IS meant to be immediate) was built deliberately by B986096-HARDENING-6/7 and is explicitly preserved, not touched; no prior item gates the plain `missing`/required-field message behind any touch state. `[x]` **SHIPPED THIS SESSION.** `CompEntryGrid.jsx`'s `ProblemsList` ran `validateComp` unconditionally for every row on every render — a row straight out of the parser (which by construction is usually missing a date and always missing a Location, since nothing sets an anchor until the user picks one) immediately read as an error, in the same red/warn styling as a genuine mistake.
- **The fix.** A row now carries `touched: true` once the user has genuinely acted on it — committing a cell edit (`finishEdit`'s commit path), resolving the rate/period ambiguity, fill-down, an Excel-style spill-paste onto it, or picking a map location for it (`CompsPanel.jsx`'s `pendingAnchor` effect, which also now stamps `touched: true`). `ProblemsList`'s `missing`-field message now renders in the normal warn styling ONLY when `row.touched || attemptedSave` (the latter set the moment the Save button is pressed, so a row Save silently skipped over — it only ever saves the READY rows — still explains itself). An untouched, incomplete row instead shows a QUIET note (`quietMissingLabel`, muted `--text-tertiary` colour, phrased as "needs a date and a location" rather than "is required") — visible, but not an accusation.
- **What was deliberately left alone, per the brief's own instruction.** The lease rate/period ambiguity flag ("Rate has no period, monthly and annual differ by 12x," with its one-click $X/SF/mo / $X/SF/yr buttons) stays fully immediate — it's a genuine parser-flagged ambiguity about what WAS pasted, not an accusation about what hasn't been typed yet, and the brief named it explicitly as the model to preserve. Every other `cellFlags` soft/blocking note (k/m-suffix flags, the county-resolution flag) is the same shape and is likewise untouched. The ambient footer count ("0 of 2 ready — …") was already correct and unconditional and needed no change.
