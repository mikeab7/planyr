- **The defect.** `yieldVerdicts.detentionVerdict` had no branch for `req.kind === "unavailable"`. That kind matches none of the numeric branches, so it fell through to `loadingRow` — pill `…`, sentence **"checking flood data"**, `loading: true` — **permanently, on every Colorado site.** The Colorado guard's whole purpose is a NAMED state rather than a wait: its own code comment says "UNKNOWN" was rejected because it "would read as *we could not look it up*, inviting the reader to wait for a number that is never coming". A spinner does exactly that, only worse.
- **Why nothing caught it.** The carrier was correct the whole time; 26 guard unit tests passed; the shipped-bundle harness passed (the copy WAS in the right chunk). Nobody asserted what the *strip* rendered. Reproduced mechanically in four lines of Node before any code was changed, then in the browser.
- **A second, compounding half.** `SitePlanner.jsx` computed `detChip = "N/A · CO"` and never passed it to the group header — it only fed a tone comparison — so the detention group's closed face read `"{N} ponds · check"` and **nothing on screen said Colorado**. The one honest line lived inside the collapsed "Assumptions & method" fold. So the state was invisible on the two surfaces a reader actually looks at.
- **Fix.** A named `unavailableDetentionRow`: pill `N/A`, `loading: false` explicitly, `short:false`/`action:false` (nothing is wrong with the design, so no ⚡ Optimize cure is offered), `sortRank 2.5` so it sits below real verdicts and above "not checked yet", carrying the components and what each still needs.
