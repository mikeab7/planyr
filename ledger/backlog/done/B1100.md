- **The report.** "For the parcel standards, we've got the parcel line, then we have also got the setback line. I should have all the same tools available to edit the setback line as well as the parcel line."
- **What it was.** The ring was hardcoded at the ONE place it was drawn — `stroke={PAL.setback} strokeWidth={strokeZoom(1.25, zk)} strokeDasharray={dashZoom("7 6", zk)}` — with no user control of any kind, and its dimension chip hardcoded to the same colour. Meanwhile `PARCEL_STD_KEYS` gave the boundary `stroke` / `weight` / `dash` / `fill` / `fillOpacity`, surfaced as Outline color · Line weight · Line style · Fill new parcels.
- **What it is.** Three new parcel keys — `sbStroke` / `sbWeight` / `sbDash` — following the boundary pattern **end to end**: stamped at creation via `parcelDefaultStyle`, listed in `PARCEL_STD_KEYS` so the retroactive **Apply** picks them up and its object count stays honest, and overridable per parcel from the selected-parcel panel (with its own **Reset setback line**, mirroring **Reset outline**). The dimension chip now follows the setback line's colour instead of staying hardcoded, so recolouring the line takes its numbers with it.
- **ONE derivation, so the ring and its chip can't drift.** `planStyle.setbackLineStyle(pc, PAL.setback)` resolves colour + weight + dash for both, and `setbackDashArray` scales the dash off the weight so a heavier line keeps its rhythm. It is pure, which is what lets the "nothing changes on upgrade" claim be a unit test instead of a screenshot.
- **BOTH lines are LABELLED (the owner's explicit instruction).** The Parcels section now styles two different lines, so it carries a **PARCEL LINE** and a **SETBACK LINE** sub-heading (`StdSubLabel`, module-scope per MODULE-SCOPE-COMPONENTS) rather than two unlabelled colour rows. Hierarchy comes from weight + uppercase letter-spacing, never from fading text toward the background (theme rule).
- **AN EXISTING PLAN IS UNCHANGED — enforced, not asserted.** The defaults ARE today's look (weight 1.25; `dashed` at that weight is exactly `"7 6"`), and `parcelDefaultStyle` stamps an `sb*` key **only when it differs from that default**, so a plan upgraded onto this build gains no keys at all and an untouched parcel resolves to the identical stroke, width and dash. `applyAllStandards` with an unset setback standard REMOVES the key rather than storing a null.
- **PDF-PARITY.** The export path rescales `stroke-dasharray` by the same factor it applies to `stroke-width` (`exportSheet.js`), so a dash expressed as a multiple of the weight survives the sheet unchanged — which is why `setbackDashArray` is weight-proportional and is unit-tested as such (`"7 6"` at 1.25 → `"14 12"` at 2.5). B880's sub-pixel suppression and the zoom scaling are untouched.
- **GUARDS.** `test/standardsApply.test.js` gains 9 cases: the untouched default is byte-identical, a partial per-parcel override leaves the rest at the default, the dash scales with weight, the new keys round-trip through `applyParcelStandard` / `applyAllStandards` / `allStandardsImpact` counted in DISTINCT objects, nothing is stamped when the standards match the built-in, and the account-under-project ladder holds. `test/bugHuntGuards.test.js`'s B880 source pin was updated to forbid the hardcoded values it used to require. `e2e/standards-footer-setback.spec.js` drives the real canvas logged out: both sub-labels render, a picked colour reaches the ring and the stored key through Apply, the style select drives the dash, a clean parcel carries none of the three keys, and a per-parcel override + reset works on one parcel alone.
