- **THE REAL GAP, which IS a gap and is what this item fixes.** Nobody updated #866's PR **title** or **body** after the renumber, and the squash-merge commit therefore carries the pre-renumber numbers. So `git log --oneline` and the GitHub PR list both show two commits announcing the same three numbers for entirely different features — which reads, correctly, as a collision, and is what the owner saw. #865 has the same defect on a smaller scale: its title says V531 while it filed V532. **Renumbering is exactly when this breaks**, because B779's late-bind rule moves the heading at the last possible moment and the subject was written first. Nothing checked the two against each other.
- **RECONCILED, and what was done about the existing commits:** nothing is edited in merged history — rewriting `main` to fix two subject lines would cost far more than it buys, and the FILES (the actual source of truth, and what every cross-reference resolves against) are already correct. The record instead lives here and on **V532** / **V534**, so anyone who later hits "#866 says B1144" has the answer. **What is fixed is the mechanism**, so it cannot recur.
- **THE FIX.** `scripts/check-mint.mjs` gains an ANNOUNCEMENT check beside the existing mint check: every `B###`/`V###` named in a commit subject this branch adds (measured from the merge base, so it covers exactly what this push adds) must exist as a `### B###` / `### V###` heading in this branch's backlog / verification files. Merge commits and `Nudge CI` commits announce nothing and are skipped. It checks the PROPERTY ("the number I announce is the number I filed"), never the ceremony — so a correct late renumber that also fixes the subject passes untouched, and a **recurrence passes too**, because a recurrence re-opens an existing heading and the heading is right there. It runs everywhere the gate already runs: the pre-push hook and the required build step.
- **WHY THE COMMIT SUBJECT IS THE RIGHT THING TO CHECK** even though the defect is visible in the PR title: GitHub pre-fills the PR title from the first commit subject and a squash merge writes the PR title back as the commit subject, so the two are the same string in practice — and the commit subject is the half that is checkable locally, before the push, with no API call.
