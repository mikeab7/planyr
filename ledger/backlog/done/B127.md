`[x]` Repro: in the right tool rail, open the **Measure** tool's mode dropdown (the **▾** caret next to "Length"). Expected: the menu opens above all adjacent UI — fully visible and clickable. Actual: the flyout was partially/fully hidden — clipped by the rail, painting "behind" the neighbouring rail/zoom rail. **Root cause = the two classic CSS layer traps, both introduced/exposed by B117.** The rail container (`SitePlanner.jsx`) sets `position:relative; zIndex:30` (a **trapped stacking context** — caps every child's z-index against the canvas/map siblings no matter how high) **and** `overflowY:"auto"` (B117 changed this from `narrow ? "auto" : "visible"` to always `"auto"` to fix the desktop scroll-to-bottom). Per the CSS spec, once `overflow-y` is non-visible the `overflow-x:visible` **computes to `auto`** too, so the rail now clips horizontally — and these flyouts open sideways out of the rail (`right: calc(100% + 10px)`), so they got cut off. You cannot have a vertically-scrolling rail that also lets a child overflow sideways, so bumping z-index can't fix it.
