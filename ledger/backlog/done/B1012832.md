- **WHAT WAS FOUND: the SAME general defect class (a portalled text-entry surface silently not holding the keyboard the way its own code assumes), in a DIFFERENT AnchoredMenu-hosted input.** `AnchoredMenu.jsx` hid its panel before placement with `visibility: pos ? "visible" : "hidden"`. A `visibility:hidden` ancestor is UNFOCUSABLE per spec, and React applies a JSX `autoFocus` prop with one synchronous, never-retried `.focus()` call at the exact render that inserts the node — which on first mount is the render where `pos` is still null. Confirmed live on the project-switcher's `autoFocus`'d "Search projects…" box: `document.activeElement` stayed the trigger `<button>` after opening it (real focus never moved), so a subsequent Arrow key resolved as CHROME scope with `fieldEdit:false` — genuinely allowed — and nudged the selected building (`{x:682.91}→{x:682.77}` on one ArrowLeft). React does **not** set an `autofocus` DOM attribute for the prop (verified by reading the live DOM), so there is no marker to re-focus after the fact; the only fix is making the FIRST `.focus()` call succeed.
