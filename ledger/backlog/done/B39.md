### B39 — PDF.js documents are never `destroy()`'d → growing memory leak across a review session `[Document Review]` (bug) — leak, high
`[x]` 🔧 fixed 2026-06-15 (branch `chore/audit-safe-fixes-b39-b45`): the prior doc is destroyed before swap (DocReview `setPdfDoc` helper) and the Stitcher destroys docs as they leave state via a diff effect, plus an unmount cleanup in both. `loadPdf` returns a `PDFDocumentProxy` (worker + retained ArrayBuffer); every replacement just overwrites `pdfRef.current` / `pdfs[].doc` (openFile, load, resetSingle, resetStitch, loadStitch) with no `.destroy()`, and there's no unmount cleanup. A repo-wide grep for `.destroy()` in doc-review is empty. Heavy construction sets leak MBs per open; the stitcher holds N docs at once. Fix: destroy the prior doc before replacing, destroy each removed/replaced source in the stitcher, and add an unmount effect that destroys the live doc(s).
