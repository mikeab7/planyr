`[x]` **Built + tested + shipped this session.** Re-architected auto-filing (B299) to **"plain code first, AI only as fallback"** so the common case is **free, instant, and needs no cloud or API key** — exactly the owner's point that reading a title block, picking the latest date, and recognizing "ALTA survey" is ordinary code, not an LLM job.
- **Tier 1 — deterministic, in the browser, $0 (the default now):** for any PDF with an embedded text layer (most CAD-exported vector drawings), read the text with the existing `extractPageText` (pdf.js, the same reader B267 uses) and parse the filing fields with pure code:
  - `src/shared/files/titleBlockParse.js` (pure, **17 unit tests**): `classifyDiscipline` (a keyword table — **ALTA** → Survey/ALTA Survey, boundary/topo → Survey, grading/paving/drainage → Civil, fire sprinkler, landscape, environmental, geotech…; sheet-number prefix as the tie-break), `findDates`/`latestDate` ("search all dates, pick the newest" = the issue date, across MM/DD/YYYY, YYYY-MM-DD, "June 30, 2025", "30 June 2025"), `parseSheetNumber` (labelled-first, conservative — returns "" rather than grab a grid ref), `parseRevision`, `readTitleBlockText`.
  - `src/shared/files/matchProject.js` (pure, **8 unit tests**): `matchProjectInText` **searches the sheet text for each named project's identifiers** (name phrase, or exact parcel/account/job number) and reuses the B299 "never auto-guess" decision (confident single → matched; none/ambiguous → needs-filing tray). Mirrors `server/filing/matcher.js`'s thresholds.
  - `src/workspaces/doc-review/lib/localRead.js` glues them to pdf.js (lazy-imported) → a decision in the SAME shape the server returns.
- **Tier 2 — AI fallback, only when Tier 1 finds NO text** (a scanned/image-only sheet) **and** the backend is enabled. So tokens are spent only on the hard minority, not every file. `autofile` (`lib/autofiling.js`) is now local-first with an injectable `localRead`; `capturePlacementFacts` uses a new `forceServer` flag (placement is genuinely an AI/CV step).
- **On by default, safely:** the provider now exposes `autofileReady = true` (Tier 1 always works in the browser — no key, no deploy), so the drawer auto-files dropped drawings out of the box. A **confident match auto-routes**; **anything else falls back to today's behavior** (the active project, or the holding tray) — so the only behavior change is that confident matches now file themselves, and a wrong confident match is still re-filable from the row. `backendReady` stays gated on `VITE_AUTOFILE_ENABLED` (the honest "AI can also read scanned sheets / capture placement" signal).
