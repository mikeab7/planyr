**THE MODEL.** `task.responsibleParty` is now an ARRAY of contact names (was a bare string). `ownerListOf(t)` is the one coercion every reader goes through — a legacy string becomes a one-element list, `null`/`undefined`/`""` become `[]`, a real array is trimmed/de-duped (case-insensitive, first occurrence wins) and passed through. It is naturally idempotent (array in → same array out), so — unlike `normalizeToV6`/`V7`/`V8`, which each gate on their own `_v6`/`_v7`/`_v8` flag already stamped `true` on every real schedule — it needed **no version flag of its own**: folding it into one of those would have silently skipped every already-migrated production document, which is exactly the data this feature has to reach. `normalizeOwnerLists` (new, unconditional) runs in the load pipeline right before `ensureContacts` (which now derives a contact for every name in the list, not just one) at all four call sites (initial load, cloud fetch, seed fallback, `window.__PLANAR_DATA__` fallback) and in `applyLoadedDataRef` (import / version-restore). **No existing task changes meaning** — a plan with single-string owners loads exactly as before, just now representable as a one-person list.

**THE EDITOR.** `ContactPicker` (`public/sequence/index.html`) is rebuilt as a chip picker: `owners` (the existing list, seeded once, never overwritten by a keystroke) + `seedText` (the character that opened a type-to-edit session, if any) replace the old single `value`/`seeded` pair. Typing seeds the NEXT chip, never replaces the list — this closes a real regression class the old design invited (typing one character over an existing single-owner cell used to select-and-replace it; under the array model that would have silently dropped every existing co-owner). Enter or comma commits the typed text as a chip and **keeps the popup open** so several names can be entered in a row; Enter on an already-empty input, Tab, or clicking away all finish editing (Tab and click-away never try to resolve unconfirmed typed text into a new contact — only an EXACT match is folded in, matching the original NEW-1 protection). Backspace on an empty input removes the last chip. Chips are removable (a small × on each) and reorderable by a plain HTML5 drag — the same `draggable`/`dragstart`/`dragover`/`drop` pattern this file already uses for column headers — and **the first chip is the accountable owner, with no separate primary control**: reordering IS how you correct it.

**THE CAP is 6, enforced with a message, never a silent drop.** A task can carry a driver plus a couple of co-owners/reviewers who share responsibility; past that it stops being an ownership list and starts being a mailing list, which is not what this field is for (`OWNER_CAP` in `public/sequence/index.html`, stated in code and here rather than buried).

**DISPLAY.** The Owner cell is unchanged in width (the column must not widen — B443536's grid still has it at 132px, and MasterView's at 100px) and shows `ownerDisplayParts`: first owner alone, or `"First +N"` once there is more than one, with every name on hover via `title=`. Used everywhere the cell renders: the grid's closed cell, the grid's `autoSizeCol` width measurement, MasterView's closed cell, MasterView's `autoSizeMCol`, the Gantt bar-label "owner" option (`barLabelText`), and the review/suggestions-queue panel's Owner column.
