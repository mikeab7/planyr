- **THE IDEA, and it is the only genuinely new thing in this item.** The owner's report contains two facts and this program had used only one. *"cost rises with time in session"* is a DETECTOR. *"if I reload, it's immediately pretty quick"* is an **ELIMINATOR** — a reload destroys the document, the heap, the DOM, every listener, timer and in-memory cache, and destroys **none** of localStorage, IndexedDB, the HTTP cache or the V8 code cache. So **anything that survives a reload cannot be the mechanism**, however perfectly it correlates. That single inference takes the whole durable-storage family off the table — which is where a reasonable person starts, and where **TIER-BY-REBUILDABILITY** (B1427/B1429) had most recently pointed. The caveat is stated in the code rather than left to be rediscovered: a durable store is excluded as the cause of the SLOPE, never as a contributor to a CONSTANT cost, which is B1121 complaint (b).
- **A CURVE, NOT A PAIR — because a pair cannot be asked the question.** Two points fit a step and a line equally well. `classifyCurve` fits FLAT / STEP / SLOPE / SAWTOOTH, reports each model's residual, requires a 35% improvement over the constant null before preferring a richer model, and **refuses to name any shape for a series whose whole range fits inside the measured noise floor**. That refusal is the load-bearing branch: this program has already paid for four shapes fitted to noise.
- **THE ENUMERATION IS PRE-REGISTERED AND COMMITTED** (`GROWTH_CANDIDATES`, 22 candidates in six families), each with a PREDICTION about whether a reload zeroes it, made in advance and **scored afterwards** — so a contradicted prediction is visible rather than invisible. Four are **not observable from outside the app** and are recorded as open questions rather than dropped: `undoDepth`, `gisCacheEntries`, `pendingJournalOps`, `telemetryBuffer`. An unmeasured candidate is an open question, not an exonerated one.
