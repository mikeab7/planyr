- **THE MEASUREMENT.** Five double-clicks on a scratch page with nothing typed: all five were written to storage as `noteAnchor` nodes with x/y/w and no text, and all five survived a reload.
- **⛔ AND THAT LITTER *IS* THE INTERMITTENCY, WHICH IS THE PART WORTH RECORDING.** An empty block draws nothing you can see and **still occupies its box and still takes the press**. So the second attempt at a spot you already tried lands inside the first attempt's invisible leftover and appears to do nothing at all. It fails exactly where somebody already tried once and gave up — which is what *"it works intermittently"* turned out to mean. Two of the reporter's own double-clicks on apparently blank space produced nothing, both inside earlier empty blocks.
- **THE FIX IS THAT AN EMPTY BLOCK IS PROVISIONAL, ENFORCED AT THE STORAGE SEAM RATHER THAN IN THE GESTURE.** The editor removes one the moment the caret leaves it, on blur, and on Escape — that is what you SEE. `writePage` prunes any empty block on the way to the disk — that is what makes it TRUE, and it is what closes the doors a gesture-side fix leaves open: an autosave firing in the half-second before the first keystroke, a closed tab, a crash, a cloud push.
- **⛔ THE BAR FOR "EMPTY" IS A WHITELIST AND REFUSES TO GUESS.** No text at all, and every node inside it a plain paragraph. A picture, an attachment, a sketch, a table, a heading — or **any node type this code has not heard of** — is content and is left alone. Unknown must mean keep.
- **AND AN EMPTY BLOCK IS NEVER INVISIBLE.** It is outlined while it is empty and says "Type here" while the caret is in it, driven by the SAME predicate the storage seam uses — two definitions would mean a block that looks provisional and is kept, or looks real and is thrown away.
- **A ONE-TIME CLEAN-UP** goes through every stored note on load and rewrites only the ones actually carrying empty blocks, through `writePage` so the cleaned copy reaches the cloud too, and says so on screen rather than doing it quietly.
