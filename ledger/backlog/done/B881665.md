- **ROOT CAUSE.** `MapFinder.jsx`'s name-filter predicate (`passName`, built from the "Filter by name…" box) was already applied to the Sites-panel LIST rows and its count (`sites.filter((s) => passName(s))`, two call sites) — but the SEPARATE effect that paints the map's status pins built its marker set straight from the raw `sites` array (`(showSitesLayer ? sites : []).forEach(...)`), never passing it through `passName`. - **THE FIX.** The pin-paint effect now filters through the same predicate (`sites.filter(passName)`) and depends on `nameFilter`, so the map's pin set and the list's row set read one filtered source and can never drift apart again. The comp-marker layer is untouched — comps aren't part of the sites list this filter targets, and the owner's own report already reconciles the pin count that way (29 = 28 sites + 1 comp).
