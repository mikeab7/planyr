`[x]` **DONE — diagnosed to the exact line from the minified production stack, fixed + sandbox-verified same session (Verify: sandbox — the crash is a pure render throw, fully reproducible headless).**
- Verify: sandbox
- Origin: filed 2026-07-07 from the Cowork V229–V231 run report (V231 #18)
- **Diagnosis (from the live stack, confirmed by rebuilding the deployed commit):** the reported minified frames `ym→Hp→Ij` in the `SitePlannerApp` chunk were mapped by building 40884e6 (the deployed build) locally with Supabase env configured — they are **`shoelace` → `siteAcres` → `MapFinder`** (`MapFinder.jsx`). `siteAcres` guarded `site.parcels?.length` but ran `shoelace(p.points)` unguarded — a stored record whose parcels array holds a parcel WITHOUT a `points` array (attr-only / legacy / a malformed row round-tripped verbatim through storage or `site_elements`) throws `undefined.length`, and because the finder's site list + map-marker tooltip call `siteAcres` for every record, ONE bad record crashes the entire Site workspace into its error boundary. (MapFinder's own map-drawing path already skips such parcels — `p.points?.length` — the acreage helpers just never got the same guard.)
- **Fix:** guard the two ring-area helpers at the read boundary — `shoelace` (`MapFinder.jsx`) and the planner's `polyArea` (`SitePlanner.jsx`) return 0 for a missing/empty ring, so a degenerate parcel reads "no boundary" in the list and contributes 0 area on the canvas instead of killing the module. Value-preserving for every real ring.
- **Regression net (the reason this escaped):** every headless smoke seeded a well-formed site, so the fresh-client and bad-record paths were never exercised. `ui-audit/verify-b671-element-sync.mjs` now additionally runs (5) a **NO-SEED cold start** — a truly fresh context must boot the Site module with zero page errors and no error-boundary card — and (6) a **bad-record boot** — a seeded site whose parcel has NO points must list as "no boundary" without crashing. Both new checks pass against the fixed build.
- **Negative control (diagnosis proven, not just plausible):** running check (6)'s seed against the UNFIXED deployed commit (40884e6, rebuilt locally) reproduces the production failure verbatim — the Site error card with "Cannot read properties of undefined (reading 'length')" — while the fixed build lists the record as "no boundary". Also confirmed the React boundary swallows the throw (no `pageerror` fires), which is why the smokes detect the error CARD text, not page errors alone.
- **Note on the live repro's confound:** the crash fired right after the "[Supabase] connected" console line, which made it look auth/boot-order-related — it isn't. That line is just the phase-1 connection test resolving at about the same moment the finder first renders the stored list; the trigger is purely the bad record. Signing in "resolving" it is consistent: the signed-in pull merges/normalizes a different store copy.
