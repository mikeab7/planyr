### B447 — Switching between files is flaky and "forgets which file I was on" `[Doc Review / Markup]` (bug)  *(owner-dropped 2026-06-24 as "NEW-2"; fixed same session)*

Code complete + logged-out paths verified V131; the auth-only switch-determinism check (two saved cloud reviews) logged for a signed-in live pass in VERIFICATION.md V131.** Owner repro: open A, switch to B, switch back to A → A's backdrop/markups/calibration/view/breadcrumb don't reliably return; clicking the file list feels like it drops the doc you were on.
- **Root cause (the clobber):** the debounced autosave's pending cloud write is cancelled the instant a switch changes the persistence `deps` (the effect cleanup clears the timer), so the outgoing review's last edit lived ONLY in the synchronous localStorage mirror. `openReview` then loaded the **stale cloud copy** by id and never reconciled with that mirror — so switching back overwrote the newer local state with the older cloud one.
- **Fix:** `openReview` now (1) `await saveNow()` to **flush the outgoing review's pending write** before the incoming load begins, and (2) loads the incoming via `reconcile(await loadReview(id), readDraft(uid, id))` so it picks up that file's newer local mirror if the cloud is behind — exactly the pattern the resume-on-mount path already uses. The lazy-mount **resume effect was confirmed to already stand down** for an in-workspace switch (its `booted`-once guard + `projectId` early-return + `bootDocIntentRef` mean it never races an explicit `openReview`), matching the cross-workspace docIntent contract the brief asked to mirror.
