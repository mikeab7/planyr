### B1145 — Split the map/geometry vendor libraries into their own chunk `[Infra / Build]` (task) #infra #perf #site-planner  *(owner chat 2026-07-30, provisional NEW-2. Minted **B1145**. DEDUPE-FIRST: **B1064** explicitly says "do NOT reach for `manualChunks`" — the owner overruled that in part, deliberately and with the honest limit stated; B1064 is amended in place rather than duplicated, and this item owns the change itself.)*
`[x]` **SHIPPED 2026-07-30 — with the limit stated first, because the limit is the interesting part.**
- Verify: sandbox
- Origin: filed 2026-07-30 from chat
- **WHAT THIS DOES NOT DO:** it does **not** reduce `siteRouteJsBytes`. The same bytes still download on a Site route — the planner needs leaflet at first paint and clipper at the road-network dissolve. Measured: 2266.3 → 2260.7 KB, which is noise, not a saving. Anyone reading this as "the planner got lighter" has read it wrong.
- **WHAT IT DOES DO, both measured:** `largestChunkBytes` **1702.7 → 1388.8 KB (−313.8 KB)** — that metric measures the biggest INDIVISIBLE unit the browser must parse and compile before anything runs, and splitting a 1.7 MB lump lets that work interleave. And **cache invalidation**: with one chunk, every planner edit re-hashed the file that also holds leaflet + clipper-lib + esri-leaflet + @terraformer, so a returning user re-downloaded ~310 KB of libraries that had not changed. Split out, those bytes keep their hash across a release.
- Deliberately narrow: only the map/geometry closure moves. `react`/`react-dom` stay in the shared entry chunk (on every route, so a separate chunk adds a request without adding cache stability) and nothing app-owned moves at all.
- **⚠ THE TRAP, and it cost a full build cycle to find — written into `vite.config.js` so nobody pays for it twice.** Rollup's CommonJS interop helper (`\0commonjsHelpers.js`) is shared by every chunk that consumes a CJS dependency. Under default chunking it lives in the ENTRY chunk, which every route loads anyway, so it is free. Adding a manual chunk makes that chunk entry-like for rollup's dependent-entry grouping, and because the helper is tiny `experimentalMinChunkSize` then **merges it into the new chunk** — at which point EVERY route statically imports the map vendor bytes to reach a few hundred bytes of interop. Measured on the first attempt: **Review 1248.9 → 1557.1 KB, Library 675.1 → 983.3 KB, Scheduler 553.1 → 861.3 KB.** A straight regression on three routes, invisible unless you look. Pinning the helper to its own `cjs-interop` chunk breaks the merge; final figures are Review +0.3 KB, Library +0.2 KB, Scheduler +0.3 KB — the interop chunk itself and nothing else.
- **A REAL BUG FOUND IN THE MEASURING INSTRUMENT.** `stemOf` stripped `-[A-Za-z0-9_-]{8,}\.js$` — "8 **or more**" hash characters — which silently ate the tail of any HYPHENATED chunk name: `map-vendor-BLBG5Rcw.js` came back as the stem **"map"**, `cjs-interop-…` as **"cjs"**. Both would have gone into the committed allowlist as nonsense names, and `perf-harness.mjs` (which carried its own copy of the same line) reported two expected chunks as phantom intruders. Now matched at exactly 8, and the harness imports the one shared `stemOf` instead of duplicating it.
- **The allowlist guard earned its keep, twice**, failing by NAME on `map-vendor` and again on `teams` before either was admitted. `siteRouteChunks` 4 → 7 and the allowlist +3, each member documented in `perf-budgets.json` with what it contains and why. The sharp guard (fail-by-name) is unchanged; the NEW-9 regression it exists for would still be caught.
- Evidence: `npm test` 6483 green · lint 0 errors · build green · bundle audit green · `node ui-audit/perf-harness.mjs` frame median 16.7 ms / p90 16.7 ms / heap 53.4 MB, all inside budget.
