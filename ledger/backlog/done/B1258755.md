- **THE FIX.** `lib/roadCrossSection.js` gains `bandExtents(xsection)` — the assembly's true, independent reach on each side of the centerline (`{left, right}`, both non-negative; the two always sum to `rowWidth`, which is what keeps the existing averaged-margin arithmetic unchanged for a symmetric section) — and `rowMarginsBySide(xsection)`, the per-side undesignated margin (`designated/2 − extent`, negative when that side overruns). `rowMarginFt` now returns `null` (the existing "invalid, don't draw a ROW line" signal every caller already reads) whenever EITHER side's margin is negative, not just when the bare sum exceeds the designated total — so the canvas correctly refuses to draw a ROW boundary for the invalid asymmetric case, exactly as it already did for the symmetric one.
- **The dialog surfaces which side, by how much.** `RoadCrossSectionDialog.jsx`'s warning now names the overrunning side and the amount when only one side overruns ("...run past the designated 30′ right-of-way on the left side by 2′ — the section isn't centered on the ROW"), falling back to the original "total X′ wider than Y′" wording when BOTH sides overrun (the ordinary symmetric case). The "ROW margin" summary line reports the two margins SEPARATELY ("3′ left · 8′ right") whenever a valid asymmetric section's two sides differ by more than a rounding sliver, rather than one misleading averaged "each side" figure.
- **Live-verified both states on the repro's own numbers:** the invalid case (30' ROW) draws no boundary lines on the canvas and the reopened dialog shows the exact warning above; a valid variant of the same section at a 40' ROW draws both boundary lines + the "40′ R.O.W." label, and the reopened dialog shows "ROW margin 3′ left · 8′ right" with no warning.
