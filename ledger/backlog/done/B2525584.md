`[x]` **✅ DONE — V1966720 PASSED live 2026-10-29 (planyr.io build 73bf936, 15/15).**
- **Cause, MEASURED (not assumed) — reproduced first with a first-character Range rect in a real Chromium:** a TEXT cell whose right-hand neighbour is EMPTY is painted by `SheetView.jsx`'s *spill* span; every other cell is painted inside the cell's own flex box. The two paths positioned the text with their own constants — the spill span at a hard-coded `left: 8·zoom`, always vertically centred, ignoring indent and alignment; the in-cell path at padding `6·zoom + 14·zoom per indent step`, honouring alignment and vertical alignment. So the moment the amount beside a label was cleared, the label jumped **2 px right (170 → 172)**; an INDENTED label lost its whole indent (198 → 172); a top-aligned label dropped to the middle; a centred label snapped to the left. Retyping the amount jumped it back. Not the column width, the row height, auto-fit, or alignment inheritance from the currency format (the candidates the brief listed) — those were ruled out by the same geometry read (every cell box and neighbour box identical before/after).
- **Fix:** ONE definition of where text starts — new `lib/cellTextLayout.js` (`cellPadX`, `canSpill`, `spillSpanWidth`): both paths take their horizontal inset from `cellPadX`; the spill span now also uses the cell's vertical alignment; `canSpill` lets only LEFT-aligned, unwrapped, plain text spill (a centred/right/wrapped label cannot spill without moving its start point, so it clips inside its own column exactly as it does when the neighbour is full). Clearing/refilling a neighbour now changes only how FAR a left-aligned label may run, never WHERE it starts.
- **Behaviour change to flag:** a centred or right-aligned text label longer than its column used to hop to the left and run across empty neighbours when they emptied; it now stays put and ellipsis-clips. (Excel spills those on both sides / leftwards; that is a larger feature, not built — a label that jumps is the bug being fixed.)
- **Sandbox-verified:** new `e2e/model-clear-cell-layout.spec.js` (9 tests: Delete · Backspace · context-menu Clear contents · retype the value back · Ctrl+Z restores the exact original layout · a cell to the LEFT cleared · plain-number and text neighbours · a label longer than its column keeps its start point · indented / centred / top-aligned labels) measures the label's painted first-character rectangle plus every cell box before/after. **RED on the unfixed build: 7 of 9 fail** with the exact 170→172 (and 198→172) shift; the 2 that pass on both builds (undo, left-cell clear) are the known-good control arms. 9/9 green with the fix; the existing `e2e/model-spreadsheet.spec.js` stays green apart from two failures that reproduce identically on main (the breadcrumb self-heal spec, and the Ctrl+wheel zoom spec already filed as B1112834 which passes when run alone). `test/cellTextLayout.test.js` (14 tests; 2 of them fail on the old SheetView).
