### B1656402 — Enter on an empty list item wearing Tab's flat indent attribute skips "give the level back" and ejects it from the list immediately `[Notes]` (bug) #notes #ui #testing  *(found this session during B1656401's sweep, not owner-reported directly. Minted **B1656402**, same reserved block, against `origin/main` 0f17770. DEDUPE-FIRST — searched Open/⏳Verify/Done for "notesEnterInherit", "emptyIndentableAt", "Enter on empty", "B512672": `lib/notesEnterInherit.js`'s Enter handler deliberately DECLINES on every empty block (the "leave the list" case) and is untouched; nothing prior taught the native Enter-on-empty-item handling about the `indent` ATTRIBUTE B512672 added, which is exactly the gap here. Net-new.)*
`[x]` **FIXED AND VERIFIED THIS SESSION.** Repro: a solo top-level bullet, Tab (attribute path, indent=1, no real nesting — nothing to tuck under), Enter (creates a new empty sibling, correctly inheriting `indent=1`), Enter again on that still-empty item. **Before the fix:** the item was removed from the list ENTIRELY and replaced with a bare paragraph below it — skipping the expected "outdent one level, then leave the list on a second Enter" convention this module already gets right for REAL structural nesting (verified as a control case: an empty item nested by real `sinkListItem` correctly becomes a top-level empty bullet on the first Enter, and only leaves the list on the second). Cause: ProseMirror's native Enter-on-empty-item logic decides "nested vs. leave the list" from structural depth alone; an item wearing only the flat `indent` attribute is, structurally, an ordinary top-level item, so the attribute is invisible to it. **Fix:** a new `Enter` binding in `lib/notesListIndent.js`'s `NoteListIndent` extension (same priority-200 rung as Shift+Tab, above the list keymap) — `emptyIndentableAt(state)` finds the caret's own indentable ancestor when it has no text anywhere in it; if it also has `indent > 0`, the press runs the same `shiftIndent(-1)` Shift+Tab already uses instead of falling through to the native handling. Declines (returns false) for every other case — a non-empty item, a range, or an item already at attribute level 0 — so `lib/notesEnterInherit.js`'s and the list keymap's own already-correct behaviour is untouched. A compound case (real nesting depth 1 + attribute level 1, the "Tab again" shape from B1656400) now takes the levels back one visible step at a time: attribute first, then the real structural outdent, then leaving the list — never more than one step per press. **No contradiction with `## Owner product constraints`.** Checked every entry — none apply. - Verify: sandbox — reproduced live in headless Chromium before and after; `npx vitest run` full suite green, no regressions; `node ui-audit/audit-notes-tab.mjs` unchanged (30/30 pinned rows still match); new permanent guard `ui-audit/verify-notes-list-indent-height.mjs` (6/6, red-proofed by stashing the fix — the Enter-outdent check failed exactly as expected, ejecting the item instead of outdenting it). - Files: `src/workspaces/notes/lib/notesListIndent.js`, `ui-audit/verify-notes-list-indent-height.mjs`. - Base: `origin/main` @ `0f17770`.
