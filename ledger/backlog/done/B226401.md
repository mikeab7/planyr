- **THE INVARIANT, one sentence, at the top of `test/mintFatality.test.js` because that is the only place it is enforced rather than described:** *a fatal mint verdict may only ever name an id that is HELD RIGHT NOW — present on origin/main or on a live peer branch — and never an id judged against an AGGREGATE of peer state such as a maximum, a mean, or a high-water mark.*
- **THE LETHAL SHAPE, named as three stacked properties rather than as one bad line** (this is what the guard is really about): the check is **REQUIRED** — an unsatisfied required context offers no merge control to anyone, not even an administrator, so the repo cannot recover from the GitHub side · its verdict depends on **ANOTHER UNMERGED BRANCH**, state no branch controls and that moves without any action by the branch being judged · and **THE ONLY REMEDY WORSENS THE CONDITION FOR EVERY PEER**. Any one alone is survivable; the three together have no fixed point.
- **GUARDED TWO INDEPENDENT WAYS, because either alone can be fooled.** `ui-audit/lib/mintFatality.mjs` is the pure engine. **(1) Behavioural** — drives the real `mintVerdict` through a battery of 21 probes built so every aggregate of peer state (max · mean · min · count · high-water) is wildly out of line with the ids being judged, in **both directions**, and asserts the fatal set is exactly the ids something actually holds. It tests the property, not the spelling, so it catches aggregate predicates nobody thought to name. **(2) Structural** — asserts the decision loops that produce `offenders` (`mintVerdict` **and** `announceVerdict`) mention no aggregate identifier at all, which catches a reintroduced predicate that is dormant on every probe because it sits behind a flag, an env var or a date. Comments are stripped first: `check-mint.mjs` discusses `claimedMax` at length precisely *because* it was removed, and a guard that fired on its own explanation would be uninstallable — that exemption is itself a test case.
- **THE ANTI-ROT HALF IS EXPLICIT.** `missed-collision` fails the guard when an id genuinely present on `origin/main` comes back non-fatal — so a verdict function that has quietly stopped failing on anything cannot pass. Without it this guard would go permanently green the moment the gate broke, which is the failure mode **VIEW-INDEPENDENT-ONCE §6** names.
- **MUTATION-CHECKED BOTH WAYS, the way `test/requiredChecks.test.js` does for the ruleset contract** (`test/mintFatality.test.js`, 17 tests): the real repo passes, and each rejected shape goes red — the reinstated `claimedMax` predicate (naming **B3005**, the exact id whose rejection started the cascade, as *unfounded*) · a **mean** of peer ids · **out-of-block made fatal** (no aggregate in sight, still a prediction — and the reason the invariant is worded as "held right now" rather than "not an aggregate") · a gate that never fails · `ok` disagreeing with its own offender list · a verdict function that throws · source the structural half cannot read (**LOUD-FAILURE**: it refuses rather than reporting a pass).
- **SCOPE STATED SO IT IS NOT MISTAKEN FOR A LOOPHOLE.** The announcement check is fatal and is *not* exempted — it needs no exemption, because it reads only this branch's own working tree, so its verdict is a present self-contained fact with no peer state in it. It is scanned by the structural half alongside `mintVerdict`.
