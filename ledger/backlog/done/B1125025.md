`[x]` **SHIPPED THIS SESSION.** Root cause: `` `Save ${readyRows.length || ""} comp${readyRows.length === 1 ? "" : "s"}`.trim() `` — `.trim()` only strips LEADING/TRAILING whitespace, never a gap in the middle, so whenever `readyRows.length` is `0` (mapped to `""` by the `||`), the template still emits the two literal spaces around the empty interpolation: "Save", space, space, "comps". A freshly pasted row is never "ready" until its Location is picked (paste never sets one), so this is the COMMON case, not an edge case — reproduced at both 3 and 123 rows. Fixed with a new shared `saveButtonLabel(readyCount)` in `compSheetColumns.js` (one place, since the desktop sheet and the mobile transposed sheet both had the identical bug independently, being the exact same template literal copy-pasted into `CompEntryMobileSheet.jsx`): returns `"Save comps"` (no count, correct single space) at 0, `"Save N comp"`/`"Save N comps"` otherwise — matching the report's stated EXPECTED ("keep the button disabled and label it 'Save comps' with one space" being the branch chosen, since the footer status line already states the ready-vs-total breakdown and doubling that count on the button would be redundant per this repo's own PANEL-BREVITY rule).
