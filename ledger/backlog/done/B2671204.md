### B2671204 — Inserting or deleting a parcel corner silently reset the BUILDING setbacks to the project default (per-edge array left at the old length) `[Site Planner / parcels]` (bug) #site-planner #persistence #parcel  *(found 2026-11-09 while building the paving setback, B2671202; owner: "settle it without a headless click")*

`[x]` **SHIPPED (sandbox-verified).** `SitePlanner.jsx` `insertVtx` / `deleteVtx` shifted `roleOverrides`, `roles`, the section breaks/joins (and, since B2671202, `pavingSetbacks`) but NOT `pc.setbacks`. `parcelSetbacks` honours that array only while its length equals the ring's, so after one added or removed corner a parcel with per-edge building setbacks (10/20/30/40) read as the project default on every edge (the ring and chips went back to the faint "defaulted" look, and the buildable envelope changed).
- **Settled by a unit test on the real code path, not a browser:** the parcel branch of both functions was extracted UNCHANGED into `lib/parcelReshape.js` (`parcelAfterInsert` / `parcelAfterDelete`) and the planner now calls it. With that extraction alone, `test/parcelReshape.test.js` was RED on exactly the four building-setback cases (`expected [10,20,30,40] to equal [10,20,20,30,40]`, `… [10,20,30,40,40]`, `… [10,20,40]`, `… [20,30,40]`) while the six control arms (no per-edge setbacks gains none, paving / role vectors / section vertices already followed, point lands on the edge, insert→delete round trip of paving) were green — the red proof.
- **Fix:** the building setback array now follows the ring (insert: both halves keep the parent edge's value; delete: the merged edge keeps the first half's), only while it is the ring's length (a stale-length array is left alone rather than shifted into a wrong alignment); a parcel that never set per-edge setbacks gains none.
- Verify: sandbox. A live browser check was NOT possible — a corner insert could not be made to fire in headless Chromium (five attempts, the instrument not the app); the unit test calls the function the corner tool calls and a source guard asserts the tool still does.
- Guards: repo-root `test/` **parcelReshape** (10, incl. the wiring guard that fails if an inline copy returns), **pavingSetbackWiring**. Files: `lib/parcelReshape.js` (new), `SitePlanner.jsx`.
- Related, not a recurrence: B966627 (a defaulted ring must not look like a set one — that rule is why this reset was visible).
