`[x]` **ROOT CAUSE, found and reproduced deterministically in a real browser (not guessed).** `NoteEditor.jsx`'s `commitPendingPlace` turns an armed placement caret into a real box via `editor.commands.addNoteAnchorAt`, whose `typing` branch ends in Tiptap's own `.focus(at + 2, { scrollIntoView: false })` (`lib/notesAnchorNode.js`). Tiptap's `focus` command (`@tiptap/core`'s `commands/focus.ts`, confirmed by reading the installed package source) never calls the browser's real `view.focus()` synchronously — it defers it to a `requestAnimationFrame` callback ("For React we have to focus asynchronously… otherwise wild things happen"). `commitPendingPlace` immediately follows with `editor.commands.insertContent(text)` for the first character, a direct command that lands regardless of DOM focus — so the first character is never at risk, which is exactly why every report named ONLY the first character as safe. Every character AFTER that is a real keystroke the browser routes to whatever element currently holds DOM focus. On the very first placement gesture of a freshly opened page, nothing has focused the editor yet, so if that `requestAnimationFrame` has not fired before the next keydown arrives, every following character is dispatched to `document.body` and lost in total silence — measured directly: `document.activeElement` reads `BODY` for every keydown after the first. Once real DOM focus lands once, for that open editor, this can never happen again (`view.focus()` on an already-focused element is a no-op) — which is exactly why a second box on the same page, or clicking back into the first one, never reproduces it, and why the owner's own report named specifically the FIRST box on a brand-new page.
`[x]` **CONFIRMED WITH A FORCED, DETERMINISTIC RACE, before writing the fix.** A fast/idle headless run can complete the pending `requestAnimationFrame` well inside the gap between two Playwright-dispatched keystrokes, which is why this shipped and stayed green — reproducing it honestly needed the same kind of deterministic instrument this repo already uses for other async races (the manually-gated fake network `notesPushReentrancy` uses): delaying `window.requestAnimationFrame` by a fixed amount inside the test page, simulating a browser with other work already queued ahead of the next paint (autosave, sync bookkeeping, telemetry — all of which a real, busier, signed-in production tab does on every keystroke and a bare local sandbox does not). Against unmodified `origin/main`, with the delay in place: typing "DELTA" left the box holding `"D"`; without the fix restored, the identical script types the full word correctly.
`[x]` **FIX.** `commitPendingPlace` now calls ProseMirror's own synchronous `editor.view.focus()` (from `prosemirror-view`, confirmed by reading its source: `focusPreventScroll(dom)` + `selectionToDOM(this)`, no `requestAnimationFrame`, no scroll-into-view of its own) immediately after `addNoteAnchorAt`, guarded on `!editor.view.hasFocus()` so it is a no-op once real focus already exists. This is safe to call at this exact point specifically because `addNoteAnchorAt`'s own transaction has ALREADY moved ProseMirror's selection into the new box (at the pressed point, already on screen by construction, per NEW-10's own guarantee) — `selectionToDOM` only re-syncs the browser's selection/caret to that already-correct position; it does not move the selection or scroll anywhere new. Verified with a live transform read before/after commit on a manually panned canvas: the workspace's CSS transform is byte-identical before and after the fix's own focus call, so NEW-10's scroll-jump regression (calling raw `dom.focus()` at ARM time, before any selection existed) does not recur.
`[x]` **TEST — red on unmodified code, green after, wired into the required `build` check.** `ui-audit/verify-notes-in-sheet-placement.mjs` §20 (new) drives the exact repro under the forced-rAF-delay: a brand-new page, one double-click, "DELTA" typed with zero delay between keystrokes, asserting the STORED text (not merely that the placeholder vanished) and that every keydown after the first resolved `document.activeElement` inside the editor — plus a second box on the same page (no regression), a word-then-Enter two-line case, and full-text reload persistence, all under the same forced delay. §1 (existing) is also tightened: it used to check only that the empty-page placeholder disappeared after typing "FIRST," never the box's own text — exactly the gap that let this ship. It now also asserts the stored text equals "FIRST" in full.
