### B2171808 — On-canvas +/− edit handles stayed on the map after their group was hidden: the hover scan ignored the View filter `[site-planner / map canvas]` (bug) #site-planner #ui #selection  *(owner chat block "MAP-HANDLES" NEW-1, 2026-10-06. DEDUPE-FIRST — searched Open/⏳Verify/Done for feature-edit-nodes / hoverElId / hidden+handles: B1253248 (placement-tool guard on grips), B705200 (measurement vertex dots with no selection gate) and B442688 (hide never deletes; selection dropped on hide) are neighbours, none covers a HOVER-armed cluster. Net-new.)*
`[x]` **SHIPPED.** Owner repro (Goose Creek, View = "7 groups hidden"): green/orange "+" and red "−" discs floated over the aerial where hidden buildings/parking had been.
- **Root cause (measured, not assumed):** `onMove`'s hover scan walked the whole `els` model, so hovering the footprint of a HIDDEN element still set `hoverElId` → `featActiveId` → `sideAddNodes` (building dock/employee/bump-out +/−) and `parkingAddNodes` (parking row +/−). B442688 clears `sel` when a group is hidden, but nothing refused the hover. Clickable too: the clusters are real hit targets that grow/shrink a hidden field.
- **Fix — one shared gate:** `contentVisibility.refHidden(hidden, els, ref)` (pure). `SitePlanner.jsx`: the hover scan skips hidden elements; `featActiveId` is nulled for a hidden element; `selHiddenNow` is asked by every selection-driven handle group (`handleNodes`, `parcelHandles`, `elPolyHandles`, `elSelOutline`, `markupHandles`, `calloutHandles`, `measureHandles`, `selParcel` chrome) and by the multi-selection rings; `selKindHidden` now delegates to the same predicate. Re-showing the group brings everything back with no reload (state is not cleared, only gated).
- **Element types affected (hover-armed, were broken):** buildings (dock/employee-side +/−, bump-outs) and car parking (row +/−). **Already correct before this change** (selection is dropped on hide, and they have no hover path): roads, ponds, paving, text/callouts, measurements, parcels/metes-and-bounds chrome, markups — now additionally gated at render time so the one-commit lag of the clearing effect can't paint a grip. Trailer parking and sidewalk/landscape have no on-canvas +/− cluster of their own in this build (trailer row count controls are in the Properties panel, not on the canvas).
- Verify: sandbox — `e2e/hidden-group-handles.spec.js` (real browser, local build, logged out, no DB): draws a building and a parking field, hovers (precondition: handles exist), hides the group → zero `feature-edit-nodes` nodes, shows it → they return. **Red on the pre-fix build for both types, green after.** Unit: `test/contentVisibility.test.js` (`refHidden` + wiring guard).
- Not done here: no signed-in live check (production-DB caution of 2026-10-06); the e2e proves the DOM on the same build.
