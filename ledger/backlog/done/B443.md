### B443 — Shift-click parcel multi-select unreliable / "needs several tries" `[Site Planner]` (bug)  *(owner-reported 2026-06-24 as "NEW-2"; minted **B443**)*
`[x]` **Fixed + shipped (branch `claude/gallant-euler-sk8kwd`). Headless-verified: 4 interior shift-clicks → "4 parcels selected" on the first try (`ui-audit/verify-merge-banner.mjs`).**
- **Repro (owner):** with the Select tool, Shift-clicking parcels to add them to the merge selection often didn't register — it took several clicks.
- **Root cause (confirmed in code — broader than first hypothesized):** **B420** makes a parcel's *interior* click-through — only its ~12px boundary hit-stroke grabs the press. So a Shift-click on the parcel **body** misses the parcel and falls through to the canvas background handler `onBgDown`, whose `tool==="select" && e.shiftKey` branch started a **marquee select** (not a merge-toggle). The pick only registered when the click happened to land on the thin boundary line → the "click a couple times" feel. (Secondary, rarer: when a parcel is *unlocked + selected*, the capture-phase vertex-insert `onCanvasVtxDownCapture` could steal a Shift-click meant to merge a neighbor sharing that edge.)
- **Fix (`SitePlanner.jsx`):**
  - `onBgDown` select+shift branch (~L1990): before starting a marquee, ray-cast (`pointInRing`) the press against the parcels; if it lands inside one, `toggleMerge(hit.id)` + select it and return. Topmost (last-drawn) parcel wins, matching the boundary-stroke path. Gated on `settings.parcelSelect` (respects the "Select parcels: off" browse mode). Marquee still works on genuinely empty canvas.
  - `onCanvasVtxDownCapture` (~L2508): the Shift+edge vertex-insert now yields when the press is inside *another* parcel's body — that's a merge-pick on a neighbor, not an edit of the selected path — letting it fall through to the merge-toggle.
- **Verified after B442** (a residual stuck pointer-capture from the banner bug could have masked this) on a clean canvas.
