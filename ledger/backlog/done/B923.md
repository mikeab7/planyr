### B923 — Clicking inside a text box / callout editor doesn't move the caret to the click point `[Site Planner]` (bug) #site-planner #ui #markup  *(owner-reported 2026-07-21 in chat — "when I'm editing text box, it doesn't seem like clicking with my mouse works to put my cursor where I want it to go." Minted **B923** via `npm run next-id -- --against-main`.)*
`[x]` **FIXED + sandbox-verified this session (build green · 4774 unit tests · headless e2e proven BOTH directions, logged-out).** In the Site Planner, opening a callout/text box (or the inline-label / numeric inline editor) and then clicking with the mouse to reposition the typing cursor did nothing — the caret stayed wherever it was (autoFocus leaves it at the end of the text), so you couldn't click into the middle of what you'd typed to edit it. Root cause: the SVG canvas carries `onMouseDown={(e) => e.preventDefault()}` (it suppresses page text-selection during a canvas drag). The inline editors are `<foreignObject>` children INSIDE that SVG and stop only the POINTER event (`onPointerDown` → `stopPropagation`); **mousedown is a separate event** that still bubbled up to the SVG's handler, whose `preventDefault()` cancels the mousedown's default action — placing the text caret at the click point. Focus landed on the field but the caret never moved.

- **Fix (`SitePlanner.jsx`, the `planner-canvas` `<svg>` `onMouseDown`):** guard the handler so it does NOT `preventDefault()` when the mousedown target is an inline text editor — `if (t.tagName === "TEXTAREA" || t.tagName === "INPUT" || t.isContentEditable) return;`. One central fix covers all three foreignObject editors (callout/text box `<textarea>`, inline-label `<input>`, numeric `<input>`) plus any future one, and canvas drags on everything else still suppress text-selection exactly as before.
