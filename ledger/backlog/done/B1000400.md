`[x]` **The rule, written into `docs/DESIGN.md`** ("Floating notifications" section, new): every floating, app-level notification renders `position:fixed`, `bottom` (Toast's existing `18` — promoted, not reinvented), `left:"50%"`, `translateX(-50%)`, one shared z-index (`6500`, replacing the pre-existing 5999/6500/9000 spread). Multiple simultaneous notifications stack vertically from the bottom, newest nearest the bottom edge, never overlapping. A max-width clamp is mandatory. It must clear an open mobile bottom sheet rather than sit under or over it. **The boundary is stated explicitly, in these exact terms:** an inline message belonging to one panel/row/field stays exactly where it is (named non-examples: `StoragePanel.jsx`'s `msg`, `FolderTree.jsx`'s tree error row, the Notes workspace's inline `role="alert"` blocks) — `role="status"`/`role="alert"` is NEVER the test, floating-and-app-level is.
`[x]` **ONE shared primitive owns the position, per the brief's explicit requirement — `src/shared/ui/FloatingNotice.jsx` (new).** Rather than manual per-caller pixel math for "never overlap," every mounted `<FloatingNotice>` portals its content into ONE lazily-created shared host `<div>` (fixed, bottom-center, flex column, `justifyContent:"flex-end"`) — the browser's OWN layout engine keeps simultaneous notices from landing on the same pixels, by construction, regardless of which component mounted them or when. `FloatingNotice` owns position/stacking/max-width/bottom-sheet-clearance only; each caller keeps its own visual style (border/background/color/content), so an amber warning and a blue info notice still read differently.
`[x]` **Bottom-sheet clearance, the one genuinely new mechanism this item needed.** `src/shared/ui/bottomSheetTracker.js` (new) is a tiny module-scope publish/subscribe signal — deliberately NOT React context, because the sheet (`src/workspaces/food/components/BottomSheet.jsx`, Food-workspace-only) and a floating notice (app-level chrome, mountable from anywhere) share no useful ancestor. `BottomSheet` now publishes its live height on every change (mount/snap/drag, and `0` on unmount); `FloatingNotice` reads it and adds the sheet's height plus a gap to its own bottom offset. The arithmetic is split into a pure, exported `noticeBottomOffset(sheetHeight)` specifically so it is unit-testable without a browser (`test/floatingNotice.test.js`, 7 tests) — the DOM/portal half needs one and is proven live by B1000402's V568016.
