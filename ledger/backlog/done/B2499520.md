### B2499520 — Address / place suggestion lists: Up/Down arrows move a highlight nobody can see — one shared list behaviour, visible solid highlight `[app-wide inputs]` (bug) #ui #keyboard #site-planner #food  *(owner report 2026-10-29: "When adding an address or typing an address, you can't use the up or down keys to pick one of the drop-down suggestions. Or if it does work, I can't see it." Related, not duplicates: B831779 (the combobox itself), B832391 (party names).)*
`[x]` **✅ Done — shipped in #2633 (merge 500ea22); live-verified on planyr.io 2026-10-29.** **Determined first, on live planyr.io (build 3ae16f4, signed in as the test account, geocoder stubbed): the keys WORKED and the highlight was not drawn.** After typing and pressing Down twice, `aria-activedescendant` moved and the row read `aria-selected="true"`, but its computed background was `rgb(255, 255, 255)` — the list's own background (`--surface-raised` on `--surface-overlay`, both white in the light theme; 1.06:1 in the dark theme). Not a key-handling bug; an invisible-highlight bug.
- **Fix:** ONE shared list behaviour — `shared/ui/listboxNav.js` (pure policy: Down enters at row 1, Up at the last row, both WRAP; Enter commits only a highlighted row of an open list; Escape closes and leaves the text; Alt/Ctrl/Meta chords never ours) + `shared/ui/useListboxNav.js` (the hook: highlight state, keydown, `role=combobox`/`listbox`/`option` + `aria-activedescendant`, highlighted row scrolled into view, hover and keyboard share one highlight via mousemove so a list scrolling under a still pointer cannot steal it, caret never jumps because Up/Down are consumed while the list has rows). The highlight is a SOLID `--accent` fill with `--on-accent` ink (Food: `--accent-food` / `--on-accent-food`, its chips inverted on the active row) — the pairs the contrast gate already audits at 4.5:1.
- **Inputs touched (all of them that show a suggestion list):** (1) the Map toolbar's address / place search — `site-planner/components/PlaceSearchField.jsx` (the only geocoder list; Enter with nothing highlighted still runs the raw search, unchanged); (2) the comp form's Landlord/Seller + Tenant/Buyer party fields — `shared/comps/components/PartyNameField.jsx`; (3) Food's restaurant search — `food/components/SearchBox.jsx` (had NO keyboard handling at all; the two action rows under the results stay mouse/Tab). Not touched, by the standing rule: dimension / length / street-label fields; the comp grid's address column and Set-location dialog (no suggestion list — they geocode on commit); Food's dish-name list (a dish list, not an address/place; buttons, own pattern) — left as is.
- **Sandbox-verified:** `e2e/address-suggest-keyboard.spec.js` — 8 cases (light + dark): the highlighted row ≥ 3:1 against the list and ≥ 4.5:1 ink, Down ×2 + Enter picks row 2 exactly as a click, Up wraps to the last row, Escape closes and keeps the typed text, typing resets, the caret does not move on Up/Down, hover and keyboard share one highlight. **RED on main** (the highlight read 1.0:1 light / 1.06:1 dark), green on the fix. `test/listboxNav.test.js` (13: the policy, the key table, the row style, and a source guard that every list uses the hook with no private arrow handling and no surface-token highlight).
