**THE CONTRACT — three editor classes, now a named rule in `CLAUDE.md` (`EDITOR-EXIT-CONTRACT`) so a new editor inherits it instead of re-deriving it:**
- **text** — the value in flight is text the person is still typing. **Enter / Tab / click-away COMMIT; Escape abandons the typed text.** Nothing is drawn as finished, so Escape destroys nothing anyone could mistake for saved. (Task name · Start · Finish · Duration · Predecessor · Cost · % Complete · Budget · Actual · the Notes modal's rows. Measured conforming on all four exits.)
- **select** — a menu. **CHOOSING is the commit**; the arrow-key highlight is in progress, not finished, so an exit taken without choosing correctly leaves the value alone, and **every** exit closes the menu. (Health · Status · the master table's health menu.)
- **tokens** — a chip/token field. **Every token is written through the instant it is added, removed or reordered**; every exit merely closes and none can discard. (Owner — converted by B1341728.)
- **THE INVARIANT THAT BINDS ALL THREE: no exit may remove anything the editor renders in FINISHED form.** A hybrid — a value drawn as finished while held unsaved — is the defect, whichever exit exposes it.

`[x]` **THE ONE OTHER GAP FOUND, and fixed in this PR: Tab did not close the Health or Status menu.** Their capture-phase handler returned early on any key outside `ArrowDown/ArrowUp/Enter/Escape/Space`, so Tab moved focus on and left an open popover floating over the grid. Nothing was lost — the menu commits only on a choice — but an exit gesture that does not exit is a contract gap, so Tab now closes both. (The master table's `HealthDropMenu` already did this and is unchanged.)

`[x]` **Non-conformances found: ZERO in the text class and ZERO in the select class besides the Tab gap above.** Columns hidden by default (% Complete, Budget, Actual) route through the SAME generic `<input>` branch as Cost — asserted structurally in the unit test rather than claimed from a run that never opened them.
