- **What the owner saw:** the "2 · Plot a metes-and-bounds description" drop zone rejected `M&B - POA Parcel 3 (0.6 AC).doc` with "Can't read a .doc here…", and dropping several files only ever read the first.
- **Root cause (AUDIT-FIRST):** `readDeedFile` (`shared/files/docxText.js`) handled only `.docx` (a ZIP of XML) + plain text. A legacy `.doc` is a different binary entirely — an OLE/Compound-File container with the text stored via a *piece table* — so it fell through to the friendly-but-dead-end throw. The drop zone had no `multiple`, and both handlers hard-indexed `files[0]`.
- **Fix:**
  - **Legacy `.doc` reader** — new dependency-free `shared/files/docText.js` (`docToText`): parses the CFB container (FAT/DIFAT + **mini-FAT**, the path a real deed's small Table stream always takes), the Word FIB (guards `wIdent`, **nFib ≥ 193** so Word 6/95 don't slip through and mis-read, `fEncrypted`, `fcClx`/`lcbClx`), and the CLX **piece table** — decoding each piece with the native `TextDecoder("windows-1252")` (compressed) or `"utf-16le"`, clamped to `ccpText`. windows-1252 is load-bearing: surveyors' minute/second marks are 0x92/0x94 (→ U+2019/U+201D), which a naive `String.fromCharCode` turns into control chars the bearing parser drops. Nesting-aware field-code handling; loud, specific errors (very-old/encrypted/corrupt → "Save As .docx or paste"). Same hand-rolled, dependency-free spirit as `docxText.js`.
  - **PDF reader** — new `shared/files/pdfText.js` (`pdfToDeedText`), **lazily imported** so pdf.js stays out of the Site Planner bundle until a PDF is actually dropped (own 1.5 kB chunk). Pulls the embedded text layer via pdf.js (the engine the Review workspace already uses) and **reflows** word-wrapped survey courses back onto one logical line each (`reflowLines`) — without which PDF word-wrap splits "…23 SEC. / EAST, 403.47 FEET" across lines and the bearing loses its quadrant + distance. Scanned/image-only PDFs throw loudly ("looks scanned — paste it or drop the Word file"). Owner's five PDFs: the three written descriptions parse (5/7/10 calls); the two Carlson **exhibit drawings** (plat sheets, title-block only, no prose) honestly report "no calls" — correct.
  - **Dispatch** — `readDeedFile` gains ordered `.doc`/`.pdf` branches (`.pdf` via the lazy import); `accept` + copy widened; input gains `multiple`.
  - **Multi-file intake** (`SitePlanner.jsx`) — `readDeed(file)` → `readDeeds(files)`: reads every file (one batch-guarded commit via `deedReqRef`), builds a `deedQueue` of `{name, calls, exceptions, closes/gap, error}`, auto-loads the first readable into the textarea (single-file drop unchanged). New queue list UI (renders at ≥2) with per-file summaries + red rows for unreadable files; clicking a row loads it; the textarea edits the active row. **"Plot all"** threads a queue through `pobMode` and advances through **one** `advanceDeed` helper (all `anchorEncumbrance` exits routed through it, so no early-return aborts the run); the POB banner is now dynamic ("Deed K of N — name"); the per-deed basis-of-bearings align hint is gated to single plots (skipped mid-run to avoid banner churn + an O(parcels) solve per deed); per-deed notes roll into the final "All N placed — verify: …" summary.
  - **Bearing parser fix (bundled, found via the real deed):** the `BEARING_SRC` degree/minute/second separators matched the single-char class `[°ºo*:d-]` *before* the spelled-out words, so the bare `d` ate the "D" of "DEG" and the stray "E" was mis-read as the East quadrant — every "N/S ## DEG. ## MIN. ## SEC. E/W" bearing lost its minutes/seconds and read West as East. Reordered to match "deg"/"min"/"sec" (optional trailing period) first. `NORTH 02 DEG. 29 MIN. 38 SEC. WEST` now → N 2°29'38" W (az 357.51, not 2°). All 13 existing parser tests still pass; also now reads fully spelled-out "87 degrees 04 minutes 16 seconds".
