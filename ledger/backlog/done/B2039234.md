### B2039234 — Switching project from the breadcrumb while a Word/text file had unsaved edits silently dropped the file and the edits `[doc-review]` (bug, pre-existing) #doc-review #files #data-loss  *(FOUND while shipping B2039232 — measured in `ui-audit/verify-review-close-file.mjs` on the pre-fix tree: dirty .docx open, route changed to another project → editor gone, that project's "Current set" shown, no prompt.)*

`[x]` **Cause:** the project-switch effect in `DocReview.jsx` (B914-era) runs AFTER the route has already changed and either opens the target project's last document or `resetSingle()`s; a dirty Word/text editor was discarded on both branches (PDFs autosave and are unaffected).
`[x]` **Fix:** every branch that would replace the open file goes through `leaveDirtyDoc`, which — only when a Word/text file is open AND dirty — shows the same Save / Discard / Cancel prompt ("…before switching project?"). Save writes then proceeds; Discard proceeds; Cancel navigates back to the previous project/Organization (`prevProjectRef`/`prevOrgRef`), and a FAILED Save also goes back rather than discarding. A clean file and every PDF switch with no prompt, exactly as before.
- **Verified (sandbox, logged out, real Chromium on the built app):** `ui-audit/verify-review-close-file.mjs` — dialog appears with the file still on screen · Cancel returns to the previous project with the edit intact and still unsaved · Discard lands on the other project's "Current set" · Save writes (no download) then switches · a clean file switches with no prompt. (The first three failed on the pre-fix tree.)
