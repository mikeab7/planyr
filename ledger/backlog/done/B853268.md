- **ROOT CAUSE, found by an Explore agent reading `Scheduler.jsx` + `ScheduleToolbar.jsx` + `navState.js`.** The empty state (`showEmptyState`) is gated on `ready` — flipped true either by the embedded scheduler's first real `planar:nav-state` message, or by two REVEAL FALLBACK timers (2.5s after iframe load, 6s absolute backstop) so a slow/broken embed doesn't spin forever. The right-hand toolbar (`ScheduleActions`/`ScheduleCenter`, gated on `toolbar.ready`) and "Link an existing schedule" (gated on the schedules list from `nav-state`) are driven by a SEPARATE `planar:toolbar-state` message with **no fallback of its own**. So on any load where `nav-state` (or a fallback timer) lands before `toolbar-state`, `ready` flips true, the empty state mounts, and the toolbar/link render as their EMPTY defaults — correctly self-healing the moment `toolbar-state` finally arrives and React re-renders, but with nothing forcing that re-render sooner. The owner's "opening/closing the switcher fixed it" was coincidental timing, not a real trigger.
- **THE FIX.** `toolbar.ready` now gets the SAME two fallback timers `ready` already had (`markToolbarReadyFallback`, gated so a REAL `toolbar-state` report always wins and is never clobbered), and `showEmptyState` is gated on `ready && toolbar.ready` (`iframeFullyReported`) instead of `ready` alone — so every signal the empty state depends on resolves on one schedule, and a slow/broken embed reveals no later than it already did.
