### B1354 — Size the cost of the 20 `feDropShadow` filter regions with a real paint profile `[Site Planner / UI]` (task) #site-planner #perf #ui  *(filed 2026-07-31 from the speed program's "RECORDED, NOT FOR THIS PR" list — **filed deliberately, NOT implemented**, and deliberately as a MEASUREMENT task rather than a fix. Minted via `--against-main`. DEDUPE-FIRST — searched Open + ⏳ Verify + Done for `feDropShadow`, `filter`, `shadow`, `raster`: nothing covers it. Net-new.)*
- One filter region per building (four render sites), each forcing an offscreen buffer and a gaussian blur of the group's whole bounding box **every frame**, each wrapping a group with up to ~160 door rects, and each under a **non-integer rotation** straight out of the data (e.g. `rot 178.543241069641`) which defeats raster caching.
- **Do not guess and do not remove the shadow.** This needs a Chrome paint profile with the `filter` attribute A/B'd to size it; the drop shadow is how a building reads as a building and its removal is a drawing-quality downgrade, which the owner's standing constraint forbids.
`[x]` **MEASURED 2026-07-31. RECOMMENDATION: leave the shadows alone. Nothing shipped, which is the correct outcome for a measurement task.**
- **HOW.** `ui-audit/diagnose-zoom-cost.mjs --mutate nofilter` strips the `filter` attribute from every canvas node and re-strips after each React commit (a one-shot strip silently undoes itself on the first frame and would report the baseline as the A/B). Interleaved against an unmutated control, 4 reps each, 4x throttle, the same wheel gesture the harness drives.
- **THE NUMBER.** All 20 filter regions removed: paint/raster residual **1,027 → 819 ms** across the gesture (−20% of the paint half), total task time **6,880 → 6,285 ms** (−8.6%), frame median **166.6 → 158 ms**. So the drop shadows are about **3% of the frame** — real, and nowhere near the 5× the target needs.
- **THE SUB-FINDING THAT SETTLES THE OBVIOUS CHEAPER FIX: the blur is not the cost.** `--mutate noshadowdefs` keeps every filter reference intact (so the region is still established and the offscreen buffer still allocated) and zeroes the `feDropShadow` — residual **1,050 ms vs the 1,027 ms control**, i.e. no change at all. The cost is ESTABLISHING the filter region, not the gaussian. So "soften the shadow" / "reduce `stdDeviation`" buys nothing, and there is no visually-identical alternative at this size of prize.
- **RECOMMENDATION: do not touch them.** Removing or weakening the shadow is a DESIGN change — the shadow is how a building reads as a building — for ~3% of a frame. That is Michael's call and this item does not ask him to make it.
