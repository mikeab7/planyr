### B2156912 — Click-and-drag pans the page from anywhere, including on a table, a picture and an unfocused box's text `[Notes]` (bug) #notes #selection #ui  *(owner report 2026-10-06 (Michael): "click-and-drag should ALWAYS pan the page, from any spot" — a drag that started on a table selected the table instead; asked whether the press itself should select it, "probably shouldn't". `[ ]` **✅ Done — live-verified (V1572160 PASSED 2026-10-06, build 70826a4).** A plain left press on a box's content (table cell / header / border, picture, text) that is not already selected or being edited is now taken in the CAPTURE phase and DEFERRED: nothing happens on the press; past the drag slop it is the same pan as blank paper (followed from the press); with no travel it is a click, replayed unchanged into `focusFromMat`. So a pan selects nothing — no caret, no cell/node selection, no box selected, no focus.
- **Root cause:** the pan (`beginBlankGesture`) is only armed for a press `focusFromMat` calls BLANK. A press on a box/table/picture is CONTENT, claimed first by ProseMirror (caret / CellSelection on `mousedown`), by stage 1 of the select-then-enter model (box selected on `mousedown`) and by the box body's `pointerdown` drag. Measured red on unmodified main: table cell/header/border, box text and picture all moved the workspace 0.0 and left a box selected (+2/+1/+4 cells selected on the table arms).
- **Fix (`NoteEditor.jsx`, the effect above the touch pan):** capture `pointerdown`/`mousedown`/`click` on the mat; `claims()` decides which presses are taken; shared `setMatPanning`; a `click` after a real pan is swallowed once.
- **Keeps its own drag (stated, not eaten):** box grip, resize handles, arrow connect dot, table column-resize handle (`resize-cursor`), page-edge grips, form controls / links / `<summary>`, any press with Shift/Ctrl/Alt/Cmd, middle button, Space-held, click-to-connect mode, touch (own pan).
- **⚠ TWO CALLS FOR THE OWNER TO VETO (stated in the PR):** (1) a drag that starts INSIDE a box that is being edited — or one you have already selected by clicking it once — selects text instead of panning (otherwise mouse text selection is impossible); (2) a drag on an UNSELECTED box's body used to be wired to move the BOX (`notesAnchorNode.js` `beginDrag`) — it now pans; a box is moved by its grip. Not claimed: a bare top-level table/picture with no box (`notesFlowMigration` folds those into boxes on read).
