- **CONFIDENCE IS A DE-RANK SIGNAL, NOT A HARD FLOOR — chosen from data, not vibes, per the brief's own instruction to sample before committing.** Sampled `food_places` directly across every confidence band from 0.50–0.60 (the very bottom — nothing scores lower) through 0.75–0.90: every band is dominated by completely ordinary real restaurants (Starbucks, Waffle House, Subway, Taco Bueno, Whataburger, Don Julios Mexican Restaurant, Doña Martha Comida Nicaragüense…) — there is no cut where "below this = bad" held up under inspection. A hard floor at the report's suggested 0.80 would have silently hidden 11,343 real rows (13.8% of the snapshot) for no measured quality gain. What confidence DOES do reliably: the "fadis" repro's own three exact-name candidates (sim 1.0) needed confidence to tell the clean meta/BrightQuery records (0.95–0.99) from the corrupted Foursquare one (0.77) — so it's used purely as a sort tiebreaker (`rankSearchCandidates` in `lib/searchQuality.js`), never a filter. Reported per the brief's ask: what was sampled (every 0.05-wide band from 0.50 to 0.90, ~20 rows per band eyeballed) and what was chosen (de-rank, not a floor) — with the reasoning above.
- **CONCATENATED ADDRESSES — detected and EXCLUDED (not repaired: the offending row's coordinates are also simply wrong, matching neither embedded address, so there is no safe text-only repair; excluding leaves the two already-clean duplicate records fully findable).** `CONCAT_ADDRESS_PATTERN` (`lib/searchQuality.js`) requires a real 5-digit zip immediately followed by "and" and a second house number — deliberately narrow so it never fires on a real Texas place name containing the word "and" ("Cut and Shoot, TX" and "Town and Country Way" are both common in this snapshot and were the first two false-positive shapes found and excluded while building the pattern). **AUDIT-FIRST discrepancy, recorded rather than silently matched:** the report estimated 37 rows of this shape; measured directly against production this session, only 2 currently match (the reported Fadi's row and one Dallas "Rise" record — confirmed to ALSO have high confidence, 0.985, proving confidence alone would never have caught it). The snapshot reloads periodically per this module's CLAUDE.md, so the counts can genuinely differ between samples; this is not claimed as a correction of the report, only as what THIS session measured. Applied both server-side (the RPC excludes these rows outright) and client-side (defense in depth).
- **REGISTRY-STYLE NAMES ("Fadis Express Binz Llc", "Fadis Signature Katy Inc") — measured 3,371 matching rows in production** (the report's manual count was 3,403 — same drift note as above) via the report's own `/\b(llc|inc|corp|holdings|management)\b/i` pattern (translated to JS). De-ranked, not excluded — some (like the Fadi's Binz St location) are real, otherwise-undocumented locations, so hiding them outright risked losing a real place with no clean-named duplicate; instead they NEVER outrank a non-registry match at any similarity score (`rankSearchCandidates` buckets non-registry names first, THEN by similarity/confidence/distance) — verified against the exact repro: "Fadis Signature Katy Inc" scores a higher raw similarity (1.0, no apostrophe) than the real "Fadi's Mediterranean Grill" (0.667, the apostrophe costs it trigram overlap) and is still correctly ranked below it.
