`[x]` **DONE + headless-verified with B461 (V137 above; rot 0 → 30° on a 30°-rotated parcel). lint 0 · 1517 tests · build green.** The "Align to base edge…" menu entry **reuses the existing building→parcel primitive — no second align written:** it arms `ovAlignBase`, and the next click on a parcel boundary (caught in `startMoveSheetOverlay` / `startMoveParcel` / the background handler, the same three consumption points as the element `alignFor`) runs `alignOverlayToParcelEdge`, which finds the nearest parcel edge via `segDist` and snaps the overlay's rotation parallel to it via `snapParallel` (the very functions the building→parcel "Align rotation…" uses).
- **Edge-snap = rotation only** (translation + rotation, scale unchanged); the **2-point translate+rotate+scale** path is the overlay's existing "Align to map" (`solveSimilarityLSQ`), left in place. Rotation is a persisted real-world angle (degrees on the model) so the alignment survives zoom/pan/reload; the base parcel is never mutated. **Guards:** refuses a **locked** overlay with a visible reason; rejects a **degenerate** (too-short) edge rather than applying a NaN rotation; "no parcel to align to" flashes a clear message; one undo step; re-aligning replaces the prior rotation.
