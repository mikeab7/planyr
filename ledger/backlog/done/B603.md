### B603 — Elevation / hillshade map overlay never painted: wrong 3DEP rasterFunction name `[Site Planner / GIS]` (bug)  *(owner-dropped 2026-07-01 — "debug and fix the elevation layer"; minted **B603** = highest real B# across both files (B602) + 1; branch `claude/elevation-layer-debug-s8xhdx`)*
`[x]` **Fixed + verified this session. *Moves to BACKLOG-DONE on merge.***
- **Root cause:** the `elevation` overlay config (`lib/layers.js`) rendered the USGS 3DEP ImageServer with `rendering: "Elevation Tinted Hillshade"`. That string is the USGS **press-release prose** wording — it is NOT one of the service's published `rasterFunctionInfos[].name`. ArcGIS ImageServer `exportImage` **errors on any rasterFunction it doesn't recognise** (returns an error tile), so the overlay came back **blank / went to the "failed" status dot** with a misleading "service not responding" message (the service was fine; the name was wrong). The cross-section tool was unaffected — it samples via `getSamples`, which takes no rendering rule.
- **Fix (one line + guard comment):** `rendering: "Hillshade Elevation Tinted"` — the exact 3DEP template name. Its siblings on the same service are `Hillshade Gray`, `Hillshade Gray-Stretch`, `Hillshade Multidirectional`, `Slope Map`, `Aspect Map` — all `Hillshade …`/verb-first order; the prose reorders the words for readability. Confirmed verbatim against a **working USGS 3DEP WMS layer config** (`Hillshade%20Elevation%20Tinted`). Added a comment so nobody "corrects" it back to the prose form.
- **Why it wasn't caught earlier:** the value has been wrong since the layer config was first authored (the monorepo-restructure commit); the request-shaping (`imageLayerOptions`), the proxy transport swap, and the esri-leaflet `imageMapLayer` wiring are all correct — only the template name was off, and nothing asserted it.
- **Tests:** new `test/bugHuntGuards.test.js` **B603** source guard (config carries the exact template name, never the prose ordering); the existing `test/layerRequest.test.js` already locks the `rendering → renderingRule:{rasterFunction}` transform. lint 0 · full suite **2148 green** · build green.
