`[x]` **✅ Done — V1626976 passed 2026-10-08.**
- **What it does:** a `paste` listener on the planner (`SitePlanner.jsx`) takes the first `image/*` file off the clipboard and hands it to the SAME `addOverlayFile` the "Add overlay" upload and the canvas drag-drop use — same storage/IndexedDB/cloud backup, same record shape, same panel row, same undo frame, same oversize/decode error messages. Centered in the view, sized by the normal heuristic, NOT scaled (Set scale / Trace a length / Match 2 points all apply), selected with its References row open. Named **Pasted image**, then **Pasted image 2**… (`lib/pasteImage.js` `pastedImageName`, deduped against the plan's overlay names), renameable like any overlay.
- **Never hijacks typing:** ignored when the event target or focus is an input / textarea / select / contenteditable, and unless the same `focusScope` the keyboard uses says the drawing owns the keys. A text-only or empty clipboard is a silent no-op (the listener returns before `preventDefault`).
- **Coexists with element copy/paste (no double-fire):** the Ctrl+V keydown used to run `pasteClip`/`pasteOverlay` synchronously with `preventDefault`, which also suppresses the browser's `paste` event — so an image could never win. It now arms the internal paste on a 0 ms timer WITHOUT `preventDefault`; the `paste` event fires in the same task, and if it carries an image it cancels that timer. No image ⇒ the internal paste runs exactly as before, one tick later.
- **Cross-plan:** nothing new — a pasted overlay is an ordinary overlay record, so B2200992's sibling-plan offering (hidden "added on <plan>", shown on demand) applies unchanged. Owner constraint #11 (no store merge) untouched; no new store.
- **Drag-and-drop** of an image file onto the map already existed (canvas `onDrop` → `addOverlayFile`), so the "optional" half needed no work.
- **Sandbox-verified:** `test/pasteImage.test.js` (clipboard → File, text-only → null, name dedupe); `e2e/paste-image-overlay.spec.js` (synthetic `ClipboardEvent('paste')` with a PNG DataTransfer → exactly one overlay, "Pasted image", 320×200, unscaled; second → "Pasted image 2"; text-only → no overlay and event not consumed; paste with an input focused → nothing; Ctrl+C/Ctrl+V of a building still works with a non-image clipboard; keydown+image-paste in one task → one overlay and NO element paste). **Red-proofed:** against the unmodified `SitePlanner.jsx` the image-paste and wins-over-element specs FAIL (zero overlays).
