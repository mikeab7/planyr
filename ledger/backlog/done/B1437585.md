**WHAT WAS BUILT.** `ui-audit/lib/statewideCoverage.mjs` (new, pure-decision module in the same DI shape as `agolParcelSearch.mjs` — every network-touching function takes an injected `fetchJson` so the logic is unit-testable without a real request):
- **`STATE_BBOX`** — a generous `[south, west, north, east]` reference envelope per state + DC (same convention as `counties.js`'s own `bbox` fields and `siteRegion.js`'s `STATE_ENVELOPES`), and **`STATE_PROBE_POINT`** — a real, on-land, populated coordinate per state (its capital, or a better-placed city where the capital sits awkwardly — Florida uses Orlando, not Panhandle-outlier Tallahassee).
- **`projectExtentToWgs84`** — reprojects a layer's own declared `extent` (free: it already rides the SAME `?f=json` metadata call the probe was already making) to lat/lon via **Esri's own public Geometry Service** (`utility.arcgisonline.com/.../GeometryServer/project`, confirmed reachable from this sandbox — one extra GET request, no bundled CRS library, no guessed reprojection math for the different spatial reference every state's service happens to use — Florida EPSG:3086, Tennessee Web Mercator, California a custom Albers 102962, …). Skips the network call entirely when the layer is already geographic.
- **`extentCoverageCheck`** — pure: compares the projected extent's lat/lon SPAN against the state's reference bbox span **in each dimension separately** (not area — a layer clipped narrow in only one dimension is just as wrong as Nebraska's, which was narrow in both), flagged below a **35% floor** (Nebraska's real defect reads ~6–7% in both dimensions — wide margin either side).
- **`probeEnvelopeTiming`** + **`pointInsideExtent`** — see **B1437586**, the sibling NEW-3 item; same file, same session, distinct finding.

The layer's own declared `extent` (its maintained spatial-index bound) is what a "does this even reach the state" screen should read.
