- **What the owner gets:** draw a building and it now shows its **structural column grid** + **dock doors** automatically, the way spec industrial is actually framed. Off each dock face is a **speed bay** (the staging strip — default **60′**, the one number the owner cares most about). Behind it the interior bays are **UNIFORM, sized within the 50–58′ band toward the typical** (default **56′** along the docks · **50′** deep) so the columns are evenly spaced. **Length and depth typical sizes are independent** (real buildings run e.g. **56′ × 50′**, exactly the owner's case). Cross-dock mirrors a speed bay to **both** long walls and divides the middle uniformly. *(Spacing model: see B590 — the owner caught a too-rigid version that put a skinny/fat odd column in the middle of deep cross-docks; interior bays are now uniform-in-band.)*
- **Geometry (new pure lib `lib/buildingGrid.js`, dependency-free):** `computeBuildingGrid({length, depth, dock, grid})` → building-LOCAL column-line offsets (`lengthLines` / `depthLines`, each tagged `speed` | `flex` | `std`), bay lists, and a panel summary. `divideSpan` sizes UNIFORM interior bays within the band toward the target (the count whose uniform size is nearest the target); only a narrow "gap" span with no in-band uniform division falls back to a module + one flex bay (ends/rear/centre). `resolveGridSettings(el, settings)` resolves the plan defaults under per-building overrides (the existing `…Override` pattern). 33 unit tests (`test/buildingGrid.test.js`): uniform-in-band sizing, deep-cross-dock uniform middle, speed-bay placement, cross-dock symmetry + too-shallow guard, independent length vs depth targets, dock-`none`, degenerate depth, out-of-band-target safety, gap-span fallback, empty footprint.
- **Render (in `renderElPx`):** maps the local offsets onto the element's axis-aligned frame (the existing rot/ppf transform handles rotation) — interior lines **solid 0.5px neutral gray**, the **speed-bay line a stronger solid coral** (a literal drafting hue, deliberately NOT a `--status-*` / `--accent-*` token), flex boundaries **dashed**, the **dock wall the heaviest edge**. Whole grid **zoom-gated** on the rendered footprint px (the `FEAT_BTN_MIN_PX` precedent) so it reveals when legible and never clutters zoomed out. Rectangle footprints only (polygon `el.points` buildings stay out of scope v1, like the docks); never drawn on a dog-ear bump-out.
- **Settings + overrides + readout:** plan-wide **Structural grid** section (showGrid, speed bay, typ bay length/depth, band min/max, door W / o.c.) + a per-building **Column grid** override group in the inspector. The building panel now reads **"Column grid: 56′ × 50′ typ · speed bay 60′ · N × M bays"** and the door line tracks the configured o.c.
- **Door spacing now configurable (was a hardcoded 12′):** `doorOC` / `doorWidth` settings; the count tracks o.c.; the dog-ear skip + dock-side logic are unchanged.
- **Adversarial review (8-agent workflow) found 5 real defects — all fixed this session:** (1, high) an out-of-band per-building bay target drove a NEGATIVE residual bay + off-building column lines — `resolveGridSettings` now clamps the targets into the band and `divideSpan` clamps the effective target; (2) `divideSpan` threw / emitted NaN when called without the band — it now defaults + sanitises the band; (3) the renderer read raw `el.dockSide` while the axes came from the validated `footprintAxes`, so an axis-flipping resize desynced the grid 90° — both now read the validated side from `dockSidesFor`; (4) the grid/readout defaulted a dock-less building to `single` while the rest of the app defaults `cross` — standardised to `cross`; (5) the door-count readout overcounted vs the canvas when a dog-ear sat on the dock face — both now route through one shared `dockDoorRun` helper (dog-ear skip included). +5 regression tests.
