### B1895539 — Font/size/spacing controls: real defaults, no floor, typed sizes, redesigned spacing popover `[Notes]` (feature) #notes #ui  *(Same dispatch as B1895536 — item 4 of 9. Minted **B1895539**. DEDUPE-FIRST — searched for "DEFAULT_SIZE", "SPACING_PRESETS", "size floor": no prior item.)*

`[x]` **The size chip now shows a real, resolved number, never a category label.** Old behaviour: the chip read "15 · std" (a hard-coded body size nobody chose) with a floor of 9 and no way to type an arbitrary value. New: `notesFormatPalette.js`'s `SIZES` ladder is `[8,9,10,11,12,14,16,18,24,30,36,48,72]` (no floor, no leading `null`/"Default" row), a new `SizeMenu` popover carries a `[−] [typed input] [+]` stepper accepting any integer `SIZE_MIN`(4)–`SIZE_MAX`(400) (validated on blur/Enter, clamped, a non-numeric entry simply reverts to the last real value — never applies `NaN`), a hint line ("Type any size from 4 to 400"), then the preset ladder with **11 tagged "Default"**.
`[x]` **The body default moved 15px → 11px** (`NoteEditor.jsx`'s `NOTE_BODY_FONT_PX`), matching `notesFormatPalette.js`'s new `DEFAULT_SIZE = 11` and every reference editor's own fresh-document default (Word, Google Docs). **The page TITLE's default size was deliberately decoupled from this constant** rather than silently shrinking 25% along with the body — `TITLE_DEFAULT_PX` now freezes the title's existing tuned ratio against the OLD 15px body (B1203504's own owner-approved critique-loop numbers), so this change touches only what the brief actually asked for (the body default) and does not retune a separately-tuned surface as an unannounced side effect.
`[x]` **The spacing popover is fully redesigned** (`SpacingPopover`, opened from a dedicated icon+chevron trigger): a "Line spacing" 4-way segmented row (1.0/1.15/1.5/2.0 — `notesSpacing.js`'s new `SPACING_LINE_OPTIONS`), a "Space between paragraphs" Before/After stepper pair (defaults 0/8 — `SPACE_BEFORE_DEFAULT`/`SPACE_AFTER_DEFAULT`), a "Presets" section (Compact 1.0·0after / Standard 1.15·8after / Relaxed 1.5·12after — `SPACING_PRESETS`, each showing its own values and a checkmark on the current match), and footer "Apply to whole page" (a new `setNoteSpacingWholeDoc` command — the selection-scoped `setNoteSpacing` is untouched, used everywhere else) / "Reset" links. The old dropdown's meaningless rows ("Whole note comfortable/compact," "Lines: 1.15" reading as a raw number with no name) are gone from this control; the underlying stored attributes (`lineHeight`/`spaceBefore`/`spaceAfter`, and the whole-note `density` mechanism) are **unchanged**, so an existing note's on-screen appearance does not change on open — only the picker UI changed. `test/notesSpacing.test.js`'s pinned `LINE_SPACINGS`/`BLOCK_SPACES`/`spacingLabel` exports are untouched (the new exports are additive, not a replacement).
`[x]` **`test/notesModule.test.js`'s toolbar `useState`-count cap updated with a full new inventory** (11 → 16, every entry named and justified in the test's own comment) — the redesign's new transient control-chrome state (`SizeMenu`'s open+typed-text, `SpacingPopover`'s open, `InsertMenu`'s open, the new shared tooltip hook, the compact-fold state) accounted for honestly rather than the cap being silently raised or the sharper "never seeded from `editor.`" assertion being weakened. **A real duplication was also caught and fixed in the same pass**: the first draft of the rebuilt toolbar had inlined the pre-existing `usePopoverClampLeft` popover-edge-clamp logic eight separate times (once per popover) instead of reusing the one shared hook the old file already had — refactored back to one shared hook, which is what brought the count from 23 down to 16.
