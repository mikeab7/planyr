1. **Templates are stored records now, not a JS constant.** `lib/notesTemplates.js` is rewritten as the PURE shape (seed content + create/rename/re-body/duplicate/delete, mirroring `notesModel.js`'s own split from `notesStore.js`); the actual read/write (`readNoteTemplates`/`writeNoteTemplates`, one JSON blob at `planyr:notes:templates:v1:<scope>`) lands in `notesStore.js`, the module's one storage seam, scoped by account exactly like the tree. A scope is seeded ONCE, on its first-ever read, with the original **Project Contacts** template plus a new **Asset Information** template (17 labelled fields — address, parcel ID, land area, building size, zoning, dock/drive-in doors, tenants, purchase price, basis, etc.) — and never re-seeded, so an account that deletes every template stays empty rather than having them silently reappear.
2. **The ▾ dropdown lists every template and ends with a separated "Manage templates…" row** (`components/NotesTree.jsx`) — the caret button itself is no longer gated on "at least one template exists" (it always renders now, since Manage Templates — which CREATES the first one — must stay reachable even at zero). `RowMenu` (this file's own small-menu idiom, reused rather than a new import for the same bundle reason B1020931's first round already documented) gained a `{sep:true}` divider row (mirrored from `NoteEditor.jsx`'s own document-menu `SEP` idiom) and a capped, scrollable `maxHeight` — item point 6, since a fixed-height menu with ten-plus templates would run off a short window with no way to reach the rows past the fold.
3. **"Manage templates" is a new full-screen panel** (`components/TemplateManager.jsx`, its own lazy chunk) — create, rename, edit the body, duplicate and delete. **It reuses the exact same rich-text `NoteEditor` a page uses for the body — no second editor was built.** That component gained two small, fully-optional, backward-compatible props, `loadDoc`/`saveDoc` (default to the untouched `readPage`/`writePage(pageId, …)` for every existing page caller); Manage Templates points them at a template record instead. The title field doubles as the RENAME control (the same field a page's title already is), which needed the identical live-typing/blur-commit split `notesModel.js`'s `renameNode`/`commitTitle` already established (`renameTemplateRecord` writes the raw label on every keystroke; `commitTemplateLabel` applies the "Untitled template" default only when the field is left blank) — coercing on every keystroke would have made the field impossible to clear, the exact bug that split exists to prevent. Delete uses the app's normal inline "Delete? ✓ ✕" confirm, mirrored locally (this file is its own lazy chunk; NotesTree.jsx's version is private to that file).
4. **"Save current page as template"** lives on the page's own right-click row menu (`NotesTree.jsx`, "Save as template…", last before Delete) — reads the page's real stored body via `readPage`, builds a new template from it.
5. **Creating a page from a template titles the page after the template** — `createPage`/`addPage` already accepted an explicit `title`; a template pick now passes `tpl.label`, a blank pick keeps passing `undefined` and gets the same "Untitled page" default it always did.
6. **A template is deliberately NOT a page-tree node** — it never appears in search, Quick Open, the task rollup, the duplicate scanner, or the reachability/orphan sweeps, none of which were touched, because none of them ever needs to know templates exist. The one place this needed a real decision: a picture pasted into a template body lives in the SAME image store a page's pictures do, keyed by a synthetic `tpl:<id>`, so `Notes.jsx`'s periodic image-orphan sweep (`sweepImagesOfMissingPages`) now threads current template ids into its "keep" list — a cheap, one-line fix for what would otherwise have been a silent, eventual "the picture I pasted into my template disappeared" bug.
