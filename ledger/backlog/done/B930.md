### B930 — Info "ⓘ" popover flashes rapidly while hovering (Yield "Sources ⓘ" + Layers-panel per-row ⓘ) `[App-wide / UI]` (bug) #ui #site-planner  *(owner-reported 2026-07-21 in chat with a screenshot of the Yield → "Sources ⓘ" legend — "when you hover it flashes a ton", same for the Layers-tab per-row "i". Minted **B930** via `npm run next-id -- --against-main`. Branch `claude/info-icon-hover-flash-2ku7ju`.)*
`[x]` **FIXED + sandbox-verified this session (build green · 4774 unit tests · headless proven on the REAL component, both pre-/post-fix, logged-out).** Resting the pointer on either hover-opened info popover — the Yield panel's "Sources ⓘ" legend (`SourcesLegend`) and every Layers-panel row's ⓘ (`RowInfo`, also the `SourceTag` "Basis" ⓘ) — made the popover strobe open/closed continuously instead of opening once and staying put.
- **Root cause (AUDIT-FIRST):** every one of these popovers renders through the shared `AnchoredMenu`, whose click-away layer is a **full-viewport transparent backdrop** (`position:fixed; inset:0; z-index:4000`, pointer-events default = **auto**) that sits *above* the little ⓘ trigger. On hover-open the backdrop instantly covers the trigger, so the browser fires `mouseleave` on the button → the 160 ms close timer arms → the popover closes → the backdrop unmounts → the trigger is exposed under the still-stationary pointer → `mouseenter` fires → it reopens → the backdrop covers it again → loop. Every micro-movement of a real hand re-armed the cycle, so it flickered many times a second. (Click-opened `AnchoredMenu` consumers never hit this — they have no `mouseleave`-driven auto-close on the trigger.)
- **Fix (`src/shared/ui/AnchoredMenu.jsx` + the two hover consumers):** added an opt-in **`hoverSafe`** mode to `AnchoredMenu`. When set, it renders **no interactive backdrop** (so nothing can steal the pointer off the trigger) and instead dismisses on any document `mousedown` (capture) whose target is outside **both** the anchor (its own click still toggles) and the panel (its content isn't click-away). `RowInfo.jsx` and `SourcesLegend.jsx` now pass `hoverSafe`. Escape-to-close and the pure placement math are untouched; **all click-opened consumers keep the default backdrop unchanged** (AccountControl, ProjectBreadcrumb, AppHeader, ContextMenu, ScheduleToolbar, FloatingPanel, DocReview, SitePlanner), so this is additive and scoped to the two hover popovers.
- Verify: sandbox — CLOSED. A logged-out hover interaction with no auth/GIS/real-data wall → per ATTEMPT-BEFORE-YOU-PARK it was reproduced + driven headless here. Bundled the **real** `RowInfo` (esbuild) and rested the pointer on the ⓘ with tiny real-hand jitter for ~1.5 s: the **pre-fix** build (hoverSafe off) opened the popover **11×** / closed it **10×** in that single hover (the strobe); the **fix** opened it **1×** / closed **0×** and it stayed visible. Click-away outside still closes it; the trigger's own click still toggles it. Not filed for a live pass — the component behaviour is identical wherever the ⓘ renders.
