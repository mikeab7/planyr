**⛔ THE HORIZONTAL HALF'S FIRST DRAFT WAS THE SAME SHAPE — `paddingRight: matPadX + MAT_EXTRA_RIGHT` on `note-mat` — AND IT SILENTLY NARROWED THE SHEET.** `note-sheet` sizes itself with `width: "100%"` when ungrown, resolved against `note-mat`'s own CONTENT box, and `matPadX` (the existing centring gutter) is chosen specifically so that `paneWidth − 2×matPadX ≈ naturalSheetWidth` — a closed-loop equation between the mat's padding and the sheet's percentage width. Adding MORE padding-right to reach further breaks that equation directly: it shrinks the content box `note-sheet`'s `100%` resolves against by the exact amount added. Caught by this repo's own `verify-notes-free-placement.mjs` (a harness this session did not write) going from all-green to two failures with nothing else changed — a naturally-580px sheet rendered at its 260px floor the moment 320px of extra padding-right was tried, on a page with no drag at all. **The shipped fix is a normal-flow SPACER SIBLING instead** (`matReachWidth` state, set to the sheet's own already-computed real rendered width — `totalSheetWidth`, the same number the growth effect already produces for `sheetGrowWidth` — plus `MAT_EXTRA_RIGHT = 320`), rendered as an `aria-hidden`, contentless `<div>` right after `note-sheet` inside the mat: `alignItems: "flex-start"` sizes each flex-column child independently, so a wider SIBLING extends `note-mat`'s own `scrollWidth` without note-sheet's `width: "100%"` ever seeing it. Growing left already had its own mechanism (`sheetGrowLeft` + the existing scroll-compensation layout effect) and was left alone.
