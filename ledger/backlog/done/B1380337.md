**Verify: sandbox** — pure function + a source assertion on the copy; both green.

**The reported symptom was the tail of a real bug.** `relTime()` did `Number(ts) || 0` and returned `""` for anything unparseable — and `cloudCheckDeleted` hands `deletedAt` straight through from Postgres, where `deleted_at` is an **ISO string**. `Number("2026-09-01T…")` is `NaN`, so the deleted-project screen rendered a space followed by an empty string: **"was moved to Recently deleted ."**. The relative time was not merely mis-spaced, it was **missing entirely**, and deleting the space would have hidden that for good (LOUD-FAILURE: it degraded quietly rather than failing).

Why it survived: the "Recently deleted" LIST was never affected — `listDeletedProjects` converts with `toMs()` first — so one correct caller sat beside the broken one.

**Fixed at the source:** `relTime` now parses an ISO string as well as epoch ms (numbers and numeric strings unchanged). The notice's sentence is additionally built in **one expression** rather than by JSX whitespace-condensing, and gates on the RENDERED time rather than on `deletedAt` merely being truthy, so a future unparseable value degrades to "Recently deleted." and can never re-grow the space. Red-proof: the new ISO assertions fail on `origin/main`.
