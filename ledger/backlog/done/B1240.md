**THE ANSWER: setbacks are measured from the PARCEL BOUNDARY AS DRAWN. There is no right-of-way line anywhere in the codebase.**

- `lib/parcelOffset.js` `offsetPolygon(points, setbacks)` insets the parcel ring by the per-edge setback value and nothing else; `setbackRingArea` and the buildable envelope both read that one derivation. The ring's points are whatever geometry was imported or drawn — for an assessor-sourced parcel, the fee polygon exactly as the county publishes it.
- **A repo-wide search for right-of-way handling returns nothing.** No ROW width, no half-width, no dedication, no centerline offset — the strings do not appear in the planner's libraries at all.
- **The nearest thing that exists is NOT this.** `lib/setbackRoles.js` reads real road geometry to decide whether an edge is a Front / Street side / Rear / Side — but a role is a LABEL, and by construction it never writes a setback VALUE. It cannot move the envelope, which is precisely the non-negotiable that item was built under.
- **So the owner's premise holds.** Where a section-line county road runs as a public easement and the fee (and therefore the assessor polygon) reaches the centerline, the buildable envelope is short by roughly half the ROW width along that frontage — 15–25 ft of setback origin error on a typical 30–50 ft county road, in both Texas and Colorado.

**What a fix would involve, and its size (filed, NOT implemented — the owner has judged the acreage effect not worth fixing):**
1. **Getting the ROW line at all is the whole problem, and it is a DATA problem, not a geometry one.** Nothing currently fetched carries it. The candidates are each partial: a county road centerline layer plus a published ROW width per classification (the `thoroughfare/` spine already does exactly this for Houston's MTFP — §42-122 widths by road class — so the pattern exists but only for one jurisdiction); a recorded plat or ROW-dedication instrument (not machine-readable); or the surveyor's line off an imported drawing (already possible today by hand-tracing).
2. **A per-edge ROW offset on the parcel record** — an additive `rowOffsetFt` beside the existing per-edge setback, applied before the setback inset. Small, and it fits the existing model.
3. **The honesty layer is the expensive half.** An inferred ROW line must be visibly labelled as inferred and must never silently move a number the owner is reading — the same provenance discipline as the WSE providers (`SourceTag` / basis popovers), plus a way to say "this frontage's ROW is unknown".
4. **Rough size: one focused session for the per-edge offset + its provenance on ONE jurisdiction's road data; materially more to generalise.** It is NOT a net-vs-gross area feature and must not become one — that was explicitly ruled out.
