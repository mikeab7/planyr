### B894 — A fast "click to select, then double-click to edit" (3 rapid clicks) on a callout/road/markup silently swallowed the edit `[Site Planner]` (bug) #site-planner #selection #ui #markup  *(owner-dropped 2026-07-18 from chat: "Double click on a callout after it's selected should allow you to edit text, three clicks total." Minted **B894** (late-bound against fresh main). Branch `claude/triple-click-callout-edit-fix`.)*
`[x]` **IMPLEMENTED + unit + headless-e2e verified this session.** `isDoubleTap`'s pairing logic used to fully WIPE its tap history the instant a double-tap was detected, so a genuine "select, then IMMEDIATELY double-click" gesture done fast enough that all three presses land inside one ~350ms window (a completely natural way to do this — real users don't pause between a select-click and the edit double-click) lost its third press entirely: presses 1+2 paired (selecting + opening Properties), and press 3 had nothing left to pair with, so it fell through as an unrelated lone click. The callout/road/markup ended up with Properties open but never entered edit mode — confirmed via a live headless repro (all 3 presses ~100ms apart) before touching any code.

- **Fix (`SitePlanner.jsx`):** `isDoubleTap`'s matched branch now RE-ARMS `lastTapRef` to the just-matched press (marked `wasSel:true`, since a matched pair always selects the feature) instead of clearing it to an empty record — so a third press within the window pairs with the second and correctly reads "already selected" → edits.
