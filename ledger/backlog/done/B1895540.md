### B1895540 — Page title's font size (and style/colour/highlight/sub/sup) now editable `[Notes]` (bug) #notes #ui  *(Same dispatch as B1895536 — item 5 of 9, "title size not editable" from the owner-approved mockup's own bug list. Minted **B1895540**. DEDUPE-FIRST — searched for "titleStyle", "note-title" + "font size": no prior item.)*

`[x]` **ROOT CAUSE, confirmed by reading rather than assumed.** The page title is a plain sibling `<input>` in `NoteEditor.jsx` — never a ProseMirror node, entirely outside the `editor` instance the toolbar reads everything else from — so the toolbar's size/style controls had nothing of the title's to read or write; the size chip clicking a title just acted on whatever the document's own selection happened to be (usually nothing, hence "disabled or does nothing").
`[x]` **FIX.** A new `titleStyle` document attribute (`notesExtensions.js` — `{fontSize, bold, italic, underline, strike, color, highlight, sup, sub}`, one object rather than eight attributes, mirroring how `arrows` is already one attribute for the same one-undo-step reason) plus a `setNoteTitleStyle(patch)` command that merges rather than replaces. `NoteEditor.jsx` tracks a `titleActive` boolean (set on the title input's own focus/blur) and hands it to `NoteToolbar`; when true, the toolbar's Size/Superscript/Subscript/Text-colour/Highlight controls read and write `titleStyle` instead of the editor selection, and the Paragraph-style control shows "Title" (a synthetic, non-pickable option — you cannot convert a title into a paragraph). Bold/Italic/Underline/Strikethrough and the Font-family control are deliberately DISABLED while in the title (the title is already rendered at weight 700 by design, and the brief only named size/sub-sup/colour/highlight explicitly) — the same "keep list/indent controls disabled there if the schema forbids them" instruction, extended conservatively to controls not explicitly asked for rather than guessed into working.
`[x]` **Superscript/subscript on a title is honestly a WHOLE-FIELD effect, stated as such in code**, not a silent limitation: a native single-line `<input>` cannot style half its own value, so picking either scales the title down (`0.7×`) and applies `vertical-align`, applied to the entire title text.
