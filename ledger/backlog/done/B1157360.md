- **A SECOND, independently-confirmed defect found while reading the actual rendered CSS cascade (AUDIT-FIRST), not just the source text:** the tab's inline style set `fontSize: 12` (already correct, matching `FONT_SIZE.control`) but then set `font: "inherit"` AFTER it — and `font` is a shorthand that resets EVERY sub-property (including size AND weight) to the inherited value. Since inline-style declarations cascade in the same later-wins order they're serialized in, that LATER `font: "inherit"` silently threw the earlier `fontSize`/`fontWeight` away again, leaving the button at its ambient inherited size/weight — which is almost certainly the real mechanism behind the reported 16px measurement (the source read "12" the whole time; the browser was never applying it). Fixed by reordering `font: "inherit"` FIRST, so it resets only font-family, and the explicit `fontSize`/`fontWeight` after it stand. This is a real, verifiable defect independent of whichever exact deployed asset the owner's 16px reading came from.
