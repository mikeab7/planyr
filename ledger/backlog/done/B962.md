- **Root cause (traced + confirmed per-frame):** the planner SVG is `width:100% viewBox="0 0 size.w size.h"`. When a docked panel opens it steals width from the in-flow canvas, so the SVG **element** shrinks IMMEDIATELY (flex layout). But `size.w` — which drives the **viewBox** width — was fed ONLY by a `ResizeObserver`, which reports the new width a frame LATER. For that one frame the old (wider) viewBox rendered into the freshly-narrowed element → the whole drawing squished sideways (clientWidth/viewBoxW ≈ 0.69), then the RO fired and it snapped back. B933 had already killed the *aerial* half of this flash (same-zoom re-center pans, no tile-wipe/ghost); this is the residual *SVG* half.
- **What changed (`SitePlanner.jsx` only — pure geometry untouched):** the existing `useLayoutEffect` that pan-compensates the canvas left-edge (B837) now ALSO measures the wrap's real width (`getBoundingClientRect`, same triggers) and calls `setSize` synchronously — so the viewBox width lands in the SAME pre-paint commit as the reflow (and as the offX compensation). A functional bail (`s.w===w && s.h===h ? s : …`) keeps steady-state re-runs a no-op; the `ResizeObserver` got the same bail so its now-redundant callback doesn't force an extra render. VIEWPORT-STABLE (a): measure the real edge, fold the delta in the same frame — the panel-open twin of B837's pan.
