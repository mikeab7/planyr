- **Verify:** live — zoom-/viewport-dependent pointer input against the real deployed grid (the signed-in test account on a throwaway project; no real data needed).
- **Reported:** drag-selecting cells only reached rows/columns already on screen; at the edge the selection simply stopped and the grid never scrolled.
- **Root cause (AUDIT-FIRST, read from the code before any change):** `SheetView.jsx` extended the range ONLY through each cell's `onMouseEnter` and ended the drag on the grid's `onMouseLeave`. A virtualised row that is not rendered has no element to fire `mouseenter`, the pointer past the edge is over no cell at all, and leaving the grid element cancelled the drag outright. There was no timer, so a pointer held still could never keep going either. Column-header and row-header drags did not exist (a header was a click-only select), and the fill handle read the pointer only on `mousemove`.
- **Fix:** ONE drag session (`beginRangeDrag` in `SheetView.jsx`) behind every range-extending gesture — cell drag-select, column-header drag (NEW: press selects the column, drag extends across columns), row-header drag (NEW: the row-number gutter now selects a row, drag extends across rows) and the fill handle. Window-level `pointermove`/`pointerup`/`pointercancel`/`blur` listeners (a held-button drag is delivered to the window even outside the page, so releasing outside the grid or the window ends it; `setPointerCapture` was deliberately NOT used — capture retargets the following click and would break double-click-to-edit) plus a `requestAnimationFrame` loop, so the grid keeps scrolling and re-targeting with the mouse held perfectly still. The cell under the pointer is found by COORDINATES against the full row/column offset tables (`lib/dragAutoscroll.js`, pure) — so an un-rendered virtualised row is still reachable, a pointer past the far edge reaches the last visible cell, and a pointer over the sticky header/gutter reaches the first visible cell (or row/column 0 once scrolled home). Speed ramps with the distance past the edge (240 px/s at the edge, +14 px/s per px, capped at 2600 px/s); all four directions and diagonals; frozen rows/columns respected (a pointer over the frozen band reaches that frozen row; scrolling stays in the scrolling pane; the anchor never moves). Release stops it immediately. A merged span still answers as its anchor cell, as the old mouseenter did. **Also fixed (asked to "check, and fix if not"):** Shift+Arrow, Ctrl+Shift+Arrow and Shift+click extending past the visible edge did NOT scroll the moving end into view — the reveal effect only watched the anchor. They now do (`revealCell`). Two small behaviour notes: Shift+click then dragging now extends from the original anchor (it used the clicked cell before), and only the primary button starts a range drag (a right-button drag used to extend it).
