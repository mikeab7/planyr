`[x]` **FIXED — the dock-zone Depth/Length fields now read plain `Depth (ft)` / `Length (ft)`, matching the sidewalk fields immediately below them in the same panel (which already use exactly this un-prefixed convention) and no longer needing the differentiating word at all.**
- **ROOT CAUSE.** `isDockZone(selEl)`'s properties-panel branch built each row's label as `` `${DOCK_ZONES[i].label} depth (ft)` `` / `` `${DOCK_ZONES[i].label} length (ft)` `` — for a truck court, "Truck court depth (ft)" and "Truck court length (ft)". The panel's shared `PropLabel` component renders a label in a fixed 64px gutter (`PROP_GUTTER_W`), clamped to 2 lines with a hover `title` for the full text — deliberately narrow, because the panel's two value columns need the rest of a 268px-wide rail. At that width the identical "Truck court" prefix consumes both wrapped lines (or crowds out the differentiating word) on both rows, so a glance at the panel shows two rows reading the same truncated text with nothing visibly telling them apart without hovering.
- **THE FIX is deletion, not a wider column or a tooltip.** The panel's own selection is already scoped to the one zone the user clicked — restating its name in every field label was pure redundancy, and it's exactly the pattern the sidewalk fields two branches down already avoid (`Field label="Width (ft)"` / `Field label="Length (ft)"`, no "Sidewalk" prefix). Dropping the zone-name prefix for ALL three dock-zone kinds (court/trailer/buffer) removes the truncation collision entirely — "Depth (ft)" and "Length (ft)" both fit the gutter on one line with room to spare — while keeping the existing hover title / "↗ Standards" / "set ↺"/"auto" affordances untouched.
- **Confirmed live** (headless-Chromium render of the real panel, a synthetic 836′×135′ truck court): the panel now shows "Depth (ft)" with its editable `135` input and "Length (ft)" with its (now read-only, see B1749154) `836′` value — both labels fully legible, no truncation, unambiguous at a glance.
