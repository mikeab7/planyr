`[x]` **AUDIT-FIRST finding, stated in the PR per the dispatch's own instruction: the printed CLEAR/SLAB values were already computed by a real tiered rule (`buildingProps.js`, B198) and were already editable — but only from inside the print/export "Compose exhibit" screen (B199's "Options ▾" body), never from the Standards panel where the owner was looking.** He had, correctly, already found the Standards panel's "Buildings — structural grid" section and assumed nothing existed for clear height/slab; the gap was findability, not capability.

**WHAT SHIPPED.**
- A new **"Buildings — program"** section in the Standards panel, directly under "Buildings — structural grid," with a full CRUD tier table for both clear height and slab thickness: add a tier, edit its threshold/value, remove a tier (never below one — every sf must resolve), and reorder rows with ▲/▼.
- `evalTier` (`lib/buildingProps.js`) is now **order-independent** — it resolves the SMALLEST qualifying threshold rather than "the first match walking the array" — so the new reorder control is provably cosmetic and can never change which tier a building resolves to. New pure helpers `addTier`/`removeTier`/`moveTier`/`maxFiniteUpTo`, unit-tested (`test/buildingProps.test.js`).
- **Defaults shipped:** clear height <140k SF → 32′ · [140k,600k) → 36′ · ≥600k → 40′; slab <140k → 6″ · ≥140k → 7″ — unchanged from B198's existing industrial defaults (32′/36′/40′ clear heights and 6″/7″ slabs are standard for small-bay/mid-box/big-box distribution product); no new numbers were invented.
- **Per-building override** is unchanged and already worked exactly as described: select a building, its Properties → Structure group shows Clear height/Slab with an "auto" tag or, once pinned, a "set ↺" revert button — the same visible-override pattern the structural grid's own overrides already use. A resize across a tier boundary re-derives the AUTO value live; an override never jumps.
- **The three Standards footer scopes now cover it, without inventing a fourth verb:** editing a tier commits straight to `settings.buildingRules`, exactly like the sibling structural-grid fields (Speed bay, Bay band, …) already do — so it is "saved for this plan" the instant it's typed, same as its neighbor section. **"Save for all projects"** (the existing footer button, now extended) additionally promotes the whole tier table to the signed-in account (`userPrefs.js`'s new `planStandards.buildingStyle.rules` bag) and clears the plan's own copy so it follows the account default afterward — the identical promote-and-defer-to-account pattern parcelStyle/typeStyles/measureStyle already use. A brand-new project with no `settings.buildingRules` of its own now falls back to that account default.
- **The print compose screen's old "Defaults by building size" tier editor is retired** — it duplicated the new Standards editor byte for byte (both read/wrote the identical `settings.buildingRules`, so never a correctness risk, just a needless second way to make the same edit). It's replaced with a one-line summary ("Clear height N tiers · slab N tiers — edit in Standards → Buildings") plus a link. The **per-building override list stays** — a genuinely print-specific convenience (adjust just the two printed columns right before printing) that doesn't exist anywhere else.
- **NEW-2 (the companion findability fix, same PR, filed as B1631633):** the building Properties panel now ends its Structure/grid groups with one line — "This building's column grid, clear height & slab start from Standards → Buildings ↗" — the same style and mechanism (`jumpToStandards`) the existing per-field "default ↗" links and the generic Colors pointer already use.
