- **Triggering bug (repro → expected):** Schedule → open a task's notes → click an existing note's date (or its text) to change it → the whole panel closed ("takes me out"). Expected + now delivered: clicking a date or text edits it **in place** with the panel staying open; the panel closes only on ✕ or a deliberate backdrop click.
- **Confirmed mechanism (read the real handlers, not guessed):** cause (b) from the spec — an edit-commits-**and-tears-down-on-blur** pattern. Editing a note put its `<textarea>` in `autoFocus` with `onBlur → saveEdit() → setEditId(null)`; moving focus into that row's date `<input>` blurred the textarea, committed, and unmounted the sibling date input mid-click — the `mouseup`/`click` then landed on the backdrop (whose `onClick={onClose}` fired because inner `stopPropagation` can't stop a click on an element the render just removed / a native-picker portal click). Exactly the "native-picker/portal click reaching the backdrop" case. Fixed **by construction**.
- **The rebuild (dated-grid running log; the whole panel replaced):** two-column rows — compact **M/D** date in a fixed left rail (~54px, plain Schedule-purple `#534AB7` text — the AA-safe shade of the module accent `#7F77DD` — click to edit), hairline vertical divider, note body; hairline row dividers, no per-note card fill. **Descending (newest first), no sort toggle.** **Add-at-top** composer prepends, dates to today, focuses the body (honors `initChar` quick-entry). **Inline CRUD that never strands you:** click date → native `<input type=date>` (pops wider than the rail — fine); click body → edit in place; delete reveals on row hover; commit-on-Enter/blur **saves and stays open**. **Guarded dismiss:** closes only on ✕, on Escape (which first backs out an active edit / a composer date-picker), or on a click whose `mousedown` **and** target are the backdrop element itself (`e.target === backdrop` + a press-started-on-backdrop ref) — never a bubbled child / native-picker portal click.
- **Storage contract kept intact:** notes stay `{id, date:"YYYY-MM-DD", text}`; `toShortDate`/`parseFlexDate` untouched; the rail gets a **display-only** `noteShortMD` (M/D) formatter; the native picker reads/writes the stored ISO directly. New sub-components (`NoteRow`, `AddNoteComposer`) defined at **module scope** (B247/B258 focus-loss trap avoided). Every edit maps by note **id** (`notes.map(x => x.id === cur.id ? …)`), so an edit structurally can't scramble the other notes — the modern successor to the removed free-text by-text matching. All CRUD rides the existing `updateTask → setData` autosave/cloudSync path (B210/B212/B566) + the `<script id="planar-data">` self-save — neither bypassed; a failed save surfaces via the existing badge.
