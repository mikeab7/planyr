### B757 — ＋ Add parcel menu: mismatched header font sizes + over-explaining copy `[Site Planner / UI]` (bug) — ✅ SHIPPED 2026-07-11 — `Verify: sandbox`
Origin: filed 2026-07-11 from owner chat (screenshot of the ＋ Add parcel menu). Owner report: "one of the fonts are all different sizes," and the descriptions were over-explaining the obvious ("Add by address" → "Type a street address," "Draw a new boundary" → "of course you're gonna have to click points") rather than adding real information; also asked for "county GIS" to read more like something a real-estate person recognizes.
- **Root cause of the size mismatch:** the "🔍 Identify" and "✏️ Draw" option headers live inside `<button style={menuItem(...)}>`, which sets `fontSize: 12.5` on the button (inherited by its child `<div>`s). The "📍 Add by address" header is a plain `<div>` (not a button, since it also hosts the text input), so it never picked up that font-size and rendered at the browser's ambient size instead — visibly bigger than its neighbors, exactly matching the screenshot. Fixed by giving all three option headers an explicit `fontSize: 13` (and keeping descriptions at the existing `fontSize: 11`), so sizing no longer depends on which wrapper element happens to host each option.
- **Copy pass (all three options), `SitePlanner.jsx` ~L9504–9547:**
  - **"Identify from county GIS" → "🔍 Click a lot on the map"**, description → "Property lines from the county appraisal district light up on the aerial — click one lot or several." (plainer term than the jargon "GIS"; explains what the click does rather than just naming the mechanism).
  - **"📍 Add by address"** header kept (already clear); description trimmed to "We'll look up that address at the county and add the lot." — dropped "Type a street address" since the input field right below it already makes that obvious.
  - **"✏️ Draw a new boundary"** header kept; description replaced "Trace a lot by clicking points on the canvas; close on the first dot" (stating the obvious mechanic) with "For a lot that's not in county records yet" (states *when* to reach for this option instead).
  - Disabled-state copy for both GIS-dependent options (no georeferenced plan yet) unified from two slightly different jargon-y sentences ("Identify needs a georeferenced plan...", "Add-by-address needs a georeferenced plan...") to one consistent plain sentence: "Add a parcel from the map first to turn this on."
  - The one other place this menu's old label was echoed in copy — the "align to deed" empty-state warning (`flashWarn` at ~L8663) — was updated to reference the new "＋ Add → Click a lot on the map" path so the two don't drift.
