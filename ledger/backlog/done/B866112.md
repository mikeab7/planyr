`[x]` **AUDIT-FIRST — owner's "second header copy" theory disproved by direct source reading (as with the switcher round), but the underlying signal was right for the same reason: there is exactly ONE `AppHeader`/`ProjectBreadcrumb` in the codebase (`src/shared/ui/`), confirmed by grep with no second definition anywhere. What Scheduler actually has is its OWN local `goDashboard` handler wired into that ONE shared header's `onDashboard` prop, instead of the Shell's cross-workspace `onGoDashboard` every other workspace uses for that slot — a wiring gap, not a duplicated component.**
- Verify: sandbox
- **ROOT CAUSE.** `Shell.jsx` passes `onGoDashboard={goDashboard}` (→ `navigate({module:"site-planner", projectId:null})`, i.e. leave the workspace entirely and land on the Site Planner map home at hash `"#/"`) generically to every workspace. `Scheduler.jsx` never destructured that prop at all. Its own local `goDashboard` (B1050) does something narrower by design: clear the ROUTED project within Schedule and tell the embedded Gantt iframe to switch to its internal "reports" section — correct behavior for keeping a no-project Schedule state from showing a stale resolution panel, but it never leaves the module. On the global `/schedule` route — already showing that internal reports view with no project routed — calling it changes nothing observable, which is exactly the owner's "no navigation, no menu, no console error" report; the button was live and firing, just doing a no-op in that state.
- **FIX.** `Scheduler.jsx` now destructures `onGoDashboard` from its props, renames the old local handler to `goDashboardWithinModule` (body unchanged — the B1050 behavior is still needed and still runs first), and composes a new `goDashboard = () => { goDashboardWithinModule(); onGoDashboard?.(); }` — the same function name the header's `onDashboard` prop already referenced, so the wiring itself needed no further change. Pressing Dashboard on Schedule now behaves identically to every other workspace: it leaves the module and lands on the map home, on both the project-scoped and the global route.
- **Adjacent controls checked, per the owner's explicit ask ("check the same header's other controls… export, history, people, Automation and settings").** Read `ScheduleToolbar.jsx`'s `ScheduleCenter`/`ScheduleActions` in full: every control (zoom, `ExportMenu`, history/contacts/automation/format/settings) posts its own `planar:*` command to the iframe and is correctly gated on `toolbar.ready` — legitimately workspace-specific (Automation etc. have no equivalent on other workspaces), not a stale copy of anything shared. No defect found; no change made there.
