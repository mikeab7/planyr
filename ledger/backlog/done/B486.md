### B486 — SECURITY: a non-owner team member could RE-HOME a shared project to another team `[Site Planner / Team / RLS]` (bug, security)  *(found 2026-06-27 by an owner-requested Team Workspaces bug audit; minted **B486** = highest real B# (B485) + 1)*
`[x]` **Fix WRITTEN + committed (`db/team_rehome_guard.sql`); ⏳ owner must RUN it in Supabase to activate (like every team migration). lint 0 / build green (SQL-only + docs — no app code).**
- **The bug:** `db/team_sharing.sql`'s `update own or team …` policies enforce sharing via WITH CHECK, whose second branch `(team_id is not null and is_team_member(team_id))` only checks the RESULTING team_id. RLS WITH CHECK can't see the OLD row, so it can't distinguish "kept the same team" from "moved to a different team." A NON-OWNER member who belongs to two teams could therefore UPDATE the owner's shared row and change its `team_id` from team X to team Y (a team the member is on) — re-homing the owner's project and cutting team X (and the owner, if not on Y) out of access. Contradicts the documented owner-only re-home/unshare intent. (Unshare-to-null was already owner-gated — only re-home-to-another-team slipped through.)
- **Why it's not an emergency (but should be run before teams go live):** it requires a member on two teams with the project shared to one — and the team feature isn't actively used yet (no invites sent; B406's signed-in round-trip is still owed, V118). So no real team with overlapping members exists today; the exposure is latent.
- **The fix (`db/team_rehome_guard.sql`):** a BEFORE UPDATE trigger `guard_team_rehome()` on `sites`/`doc_reviews`/`file_facts` that raises `42501` if `team_id` changes and `old.user_id <> auth.uid()` — i.e. only the row OWNER may change `team_id` (share/unshare/re-home); teammates edit CONTENT freely (team_id unchanged → allowed). Idempotent; SECURITY INVOKER (reads OLD/NEW + auth.uid(), no RLS bypass). Audited the rest of the team surface too (teams.js, teams.sql helpers + invite-claim, casUpsert owner-preservation, team_storage.sql) — all sound; this was the one real gap.
