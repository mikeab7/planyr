### B466 — "Opened in another tab" recovery was broken: reload didn't take the lock; no way to take over or force-save `[Site Planner / Persistence]` (bug/feature)  *(owner-dropped 2026-06-25 as "NEW-3"; minted **B466**; depends on B464)*
`[x]` **DONE + headless-verified (branch `claude/exciting-wright-yb6ruz`). V (`ui-audit/verify-readonly-takeover.mjs`, 7/7): two tabs of one browser context share Web Locks → tab B goes read-only, "Take over editing here" makes B active AND hands tab A down to read-only via the cross-tab bus.**
- **`editorLock.takeOver()`** (`src/shared/presence/editorLock.js`): STEALS the Web Lock (`{steal:true}`) so this tab is unambiguously the editor even if the other tab is gone or on an older build, THEN broadcasts a `yield` on a BroadcastChannel so the prior holder steps down to read-only cooperatively. Steal-first-then-broadcast so the prior holder's re-request queues behind the steal. Degrades open where Web Locks is unavailable. (+3 unit tests: steal-makes-active, bus hand-off, degrade-open no-op.)
- **`takeOverEditing()` (SitePlanner):** the banner button calls `takeOver`, then flushes the live canvas to the device mirror AND force-pushes to the cloud (`cloudPushWithWatchdog`) — so the pent-up un-synced work reaches the cloud immediately. The B459 thin-clobber + B314 CAS guards still protect that push (a genuine conflict surfaces the loud BLOCKING banner + reload-merge; never a silent overwrite), so takeover-and-push is safe.
- **Reload-recovery premise CORRECTED (flagged):** "work done before reload is lost on reload" is mitigated by B458 — a read-only tab's edits ARE written to the device mirror immediately, so boot's union-merge restores them; the remaining gap (cloud sync) is what takeover closes. The brief's "manual Save now / force flush" is subsumed by "Take over editing here" (the only SAFE way to push from a read-only tab is to first own the lock; the device mirror already keeps the work, so a user is never stranded).
