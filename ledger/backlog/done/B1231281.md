- **⛔ THE TRADE, STATED PLAINLY PER THE DISPATCH'S OWN INSTRUCTION ("if removing the zoom-stack control would cost [speed], say so and propose how the help control preserves it").** The old button was genuinely ONE press, reachable without opening anything, while the planner canvas already had focus. The help control's own row requires opening the control first — TWO presses, not one. This is a real, accepted cost, not hidden: (a) it is flagged here and in the session reply, not silently absorbed; (b) the SECOND press adds no capture latency — B1231280 already took (and is usually already delivering) the capture from the FIRST press by the time the row is reachable, so the two-press sequence costs one extra tap, not one extra wait; (c) the row is the FIRST thing visible after opening — no typing, no scrolling, no menu depth — so "file a pure performance report with no prose" is still true, just two taps instead of one; (d) the fold is a net INCREASE in reachability overall — the old button existed only inside the Site Planner's open-drawing canvas, while the global control (and therefore this same row) now works from every route, matching the exact "recorder is only showing up in the site planning module" gap B842864/B842865 already closed for the OTHER two menu items.
