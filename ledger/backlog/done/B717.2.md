- AUDIT-FIRST root cause (two sources of truth disagreed): the grid colours a leaf via `computeDisplayHealth` (applies cfRules), but Focus decided visibility from the RAW stored health. In the `flatTasks` memo (index.html ~L6209), `rolledStatus`'s leaf branch read `byId[id].health` directly (gray→"upcoming"), and `hideStatusOf` hides anything not "active" → an overdue leaf displayed red yet was classed "upcoming" and filtered out at the `walk` step. The `hideableUpcoming` count/tooltip was wrong for the same reason (tallied it as not-started). Overdue In-Progress/yellow leaves already mapped to "active", so only the overdue-but-Not-Started → red case vanished.
- Fix (single source of truth — same class as PDF-PARITY: grid status and Focus filter must never diverge): the leaf branch now classifies via `computeDisplayHealth(byId[id], settings)`. `data?.settings` (so cfRules is visible) and `NOW` (so the midnight/focus overdue rollover re-runs Focus) added to the memo deps. Deliberate design choice per the brief: a `dueSoonYellow`-promoted Not-Started leaf now also survives Focus — consistent with the grid showing it "In Progress"; red is ALWAYS kept.
