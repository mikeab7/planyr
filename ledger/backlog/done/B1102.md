### B1102 — Map viewer: the zoom-out floor that made a second state unreachable `[Site Planner / map]` (bug) #ui #gis  *(minted via `--against-main`. Origin: filed 2026-07-29 from chat (NEW-6).)*
`[x]` **Done 2026-07-29 — root cause found, fixed, and verified headless in this session.**
- Verify: live → **verified in sandbox 2026-07-29** (logged-out, no external GIS needed — ATTEMPT-BEFORE-YOU-PARK applies, so it was driven here rather than filed for someone else)
- **Which of the four candidates it turned out to be: none of the three the brief suspected.** It was a single hard `minZoom: 8` on the Leaflet map (`MapFinder.jsx:417`). **Not a bounds clamp** — `setMaxBounds`/`maxBounds` appear nowhere in the codebase. **Not tile coverage** — Esri World Imagery and USGS ImageryOnly both serve from z0; their `maxNative` ceilings (19/16) constrain the deep end, not the shallow end. **Not a projection chosen at init** — the map is one Web Mercator worldwide; the per-site frame (`mapLock`) belongs to the planner canvas, not the finder.
- At z8 the view spans a few counties, so there was no way to pull back and see another state at all — you could only jump by picking a site. Now `minZoom: 3`, which puts the continent on screen.
- **Verified headless** (`e2e/colorado-map-zoom.spec.js`): the real app boots, the zoom-out control is driven the way a user drives it, and the **graphic scale bar reads 300 mi** with the cursor readout over latitude 39.3° — a continental view, structurally impossible at the old floor, asserted in the units the user actually sees. Zero page errors. Also guarded statically in `test/coloradoRegistry.test.js`, which asserts the literal and that no `maxBounds` reappears.
- The landing view is still `COUNTIES_MAP.harris` — deliberately unchanged; where the app opens is a product decision, not a bug fix.
