`[x]` **The page sits on an UNBOUNDED workspace.** `note-mat` is a viewport (`overflow: hidden`); one transform on a `note-workspace` layer places everything — `translate(−x, −y) scale(z)`, `transform-origin: 0 0`, so `screen = workspace × z − view`. `view.x` is `scrollLeft` **without the clamp**: same sign, same units, so every computation that reasoned in scroll terms kept its arithmetic and only the bound disappeared. The page can be pushed clean off all four edges and Ctrl+0 always brings it back (asserted, four directions).
`[x]` **Zoom is ANCHORED AT THE CURSOR**, reusing the site planner's own rule (B1449/PR #952) rather than a second implementation: solve for the view that keeps one workspace point at one viewport position. Asserted at three different anchors × both directions — the point under the pointer moves **0.00px** in all six.
`[x]` **Range: 10%–800%**, chosen against a stated picture rather than copied (a whole page as a small card; a glyph big enough to inspect). Ladder: 10·15·25·33·50·67·80·90·**100**·110·125·150·175·200·250·300·400·600·800.
`[x]` **Gesture map, as shipped:** wheel = zoom at the cursor (Ctrl/⌘) · plain wheel and two-finger swipe = pan, both axes · middle-mouse drag = pan from anywhere, including on top of the page · Space+drag = pan (and Space in the writing is still a space — asserted) · left-drag on blank workspace = pan (unchanged, the mat's existing four-way gesture model) · Shift+drag = marquee (unchanged) · Ctrl+= / Ctrl+− / Ctrl+0 (100%) / **Ctrl+9 (fit the page)**. The browser's own zoom is `preventDefault`ed for all of them.
`[x]` **Text stays crisp**: `transform: scale()` with **no** `will-change: transform` — the promotion hint is what makes Chrome raster once and stretch the bitmap, which is the blurry-text failure this had to avoid. Line breaks never change, which is the point of the Bluebeam model.
`[x]` **The view is a REF, never React state** — a pan writes one `transform` string and re-renders nothing, so VIEW-INDEPENDENT-ONCE holds by construction rather than by a memo key a later edit can poison. `applyView()` is the only writer; a layout effect re-asserts it after every render so no other render can drop it.
`[x]` **Persists per page** (`planyr:notes:view:v1:<scope>:<pageId>`) and survives a reload — zoom AND position, asserted. Per PAGE, not one level for the whole workspace: on a canvas you can pan, the view is a place you left off in a particular document.
`[x]` **Print and export are untouched by the view zoom** — the view is not in the document.
`[x]` **The opening framing follows the page until the first size-stable pass OR the first thing the person does, then latches for good.** Both halves are needed: the first layout pass genuinely reports the sheet at the unpinned 580×145 before the pin and the document have settled, and a page that re-centres itself later is the "the whole page jumped" defect this module has already paid for twice.
