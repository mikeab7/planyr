(2) *"The row got wider"* — every cell got its indent as padding on BOTH sides and a box cannot be narrower than its padding, so enough presses (which is what an owner does when nothing moves) made the cell outgrow its 120-wide column and shoved every cell to its right out of line with the header. - **Fix:** `lib/cellTextLayout.js` `cellPadding({indent, align, zoom, width})` — the indent insets the text on its READING side only (left for left-aligned, right for right-aligned, none for centred; Excel's rule) and is CLAMPED so padding + borders never exceed the column width, so an indent can never change a cell's width or any other cell's position. A deep indent in a narrow column leaves the text no room (clipped) instead of stretching the box. Third bug found while testing the multi-cell case: the toolbar / palette computed the new level from the ACTIVE cell only (`active + 1`) and wrote that to every selected cell; `sheetModel.adjustIndent` now steps each cell from its own level (Excel's rule), capped at Excel's 15, a no-op range returning the same sheet object (no history entry). `increaseIndentPatch` / `decreaseIndentPatch` removed; the ribbon buttons and the palette commands call `ctx.onAdjustIndent(±1)`.
