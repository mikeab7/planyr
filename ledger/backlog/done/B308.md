### B308 — Server-side Mapillary token proxy so the street-level layer works for all users `[Site Planner / functions]` (feature)  *(coworker-chat "NEW-1" 2026-06-20; first filed B303 then renumbered **B308** — concurrent `main` landed a Doc Review batch on B303–B307, so both can't share the number)*
`[x]` **Built + shipped 2026-06-21 (branch `claude/busy-allen-ofgy9l`).** The "Poles & hydrants from street imagery" layer now works for **every visitor with no per-user token**, and the Mapillary access token never reaches the public bundle or any client request URL — it lives only as an encrypted Cloudflare Pages Secret the owner set (`MAPILLARY_TOKEN`, Production). Resolves the audit's *token-in-bundle* + *token-in-URL* LOW findings; honours the KEY DECISION "Mapillary token is a secret."
- **Pages Function** `functions/api/mapillary/[[path]].js` reads the token from the runtime binding `context.env.MAPILLARY_TOKEN` (NOT `import.meta.env`/a `VITE_*` var) and forwards to the Graph API. **Guardrails** (pure helpers in `functions/api/mapillary/_proxy.js`, unit-tested): allow-list ONLY `map_features` + fields `id,object_value,geometry`; **Origin check** (same-origin / `*.planyr.io` / `*.planyr.pages.dev`, foreign Origin → 403); bbox/limit validation; short edge-cache (`max-age=300`) to cut quota. **Dormant-graceful:** no token (e.g. a Preview deploy, which doesn't have the secret) → 503 + empty `data`, the client shows "not available here", never a hard error.
- **Client:** new leaflet-free `lib/mapillaryClient.js` (`mapillaryRequestUrl`/`pickDetections`); `evidenceLayers.fetchMapillary` calls the same-origin `/api/mapillary/map_features` with **NO `access_token`** by default (a pasted token = an optional power-user override straight to Mapillary). Removed the no-token gate in `mapillaryLayer` + `syncOverlayLayers` and the `needsSetup` flag on the layer; the LayerPanel box is now "Works automatically — (Advanced) use your own token". `.env.example` + README document the secret-lives-in-Cloudflare rule.
- **Verified:** lint 0 · **722 tests** (10 new, `test/mapillaryProxy.test.js`: allow-list, Origin, limit-clamp, and the client default carrying no token) · build green; **0 `MLY|` token literals + 0 `VITE_MAPILLARY_TOKEN` in `dist/`**. Headless on the built app (`gis-verify/mapillary-proxy-verify.mjs`): toggling the layer with no token → it loads via **same-origin `/api/mapillary/map_features`**, **0 token leaks** in any request URL, **no** direct `graph.mapillary.com` call, graceful degrade in preview, **0 JS errors**.
- **⏳ LIVE confirm (the one piece the sandbox can't do — a Pages Function needs the Cloudflare runtime):** on planyr.io Production after the next deploy, zoom ≥ 16 over a covered area → pole/hydrant dots render via `/api/mapillary/…`, token nowhere in page source/bundle/URLs. Logged in VERIFICATION. (The owner already set the secret, so this is just the deploy + a coworker eyeball.)
