### B2158064 — `/api/taxrates` dies with Cloudflare error 1102 (Worker exceeded resource limits) on any uncached county/spelling; the old rate fetch then shows "Unexpected token '<'" `[Site Planner / functions]` (bug) #site-planner #gis  *(owner chat block 2026-10-07 NEW-1)*
`[x]` **Repro (measured 2026-10-08 on planyr.io):** `GET /api/taxrates?county=Harris` → 200 JSON (cached). `?county=harris`, `?county=Harris%20County`, `?county=Fort%20Bend` → **503 `error code: 1102`** (a platform kill, not an app error — Cloudflare's error page is HTML to a browser, which `res.json()` then chokes on: "Unexpected token '<'"). `?county=Galveston|Montgomery|Brazoria` → 200 on the same minute. **Root cause:** `functions/api/taxrates.js` parses four statewide Comptroller workbooks (school-district + special-district are the big ones) with the full SheetJS in-memory model on every cache miss; the Worker sits at its memory ceiling, so success is a coin-flip on GC timing, and the cache key is the raw `county` string so each spelling re-rolls it. **Fix:** a streaming minimal XLSX reader (`functions/api/lib/xlsxRows.js`: zip central directory → inflate only `sharedStrings` + `sheet1` via `DecompressionStream`, emit rows incrementally, keep only the wanted county) so memory is O(one county), a normalised cache key (case/space/"County" suffix) and a handler that can only ever answer JSON. Also: the special-district rows all came back named "Harris" (the unit-name column was not found) — fixed in the same pass.
**Stopping rule:** closes when 20 consecutive uncached calls across spellings/counties on planyr.io all return JSON 200 with real unit names.
