- Verify: sandbox — pure client-side rendering logic; self-verified live in this session's headless run (the color of both a refusal toast and a completed-action toast was read via `getComputedStyle`, not assumed).
- **CONFIRMED IN CODE FIRST, per the owner's own caveat.** The one bottom-center toast pill every `flashWarn(...)` call renders through (`SitePlanner.jsx`, near `toastPill`) picks its background from the message TEXT: `overlapWarn.startsWith("⚠") ? "#7f1d1d" (red) : "#15803d" (green, default)`. A call site that refuses a requested action but doesn't happen to prepend `⚠` therefore renders in the SAME green as a genuine success toast, or as the "● Scaled · county GIS" affirmative status chip the owner compared it to (a different component, `rgba(22,101,52,0.92)` — visually the same family of green, confirming the READING even though it's a separate element). This is exactly the shape B742368's own old refusal was in before this item's fix.
- **A SECOND, independent bug in the color rule itself, found while confirming the first.** `.startsWith("⚠")` misses any message that EMBEDS a warning mid-string rather than leading with it — e.g. `"All 3 deeds placed.${bad.length ? " ⚠ Verify: …" : ""}"` — which never starts with `⚠` even when it does carry one, so it also rendered green. Changed to `.includes("⚠")`, which catches both without touching any call site's wording.
- **THE AUDIT — every one of the 130+ `flashWarn(...)` call sites in `SitePlanner.jsx` was read and classified as a genuine blocking refusal/failure (needs `⚠`), a completed action (correctly green, left alone), or a neutral in-flight mode prompt ("Click the far side of the ditch.", left alone — not this report's shape).** ~24 of the clearest, highest-traffic refusals now carry the `⚠` prefix: both `place.mode === "refuse"` (LOUD-FAILURE) sites, the reshape self-intersection revert (B742369), footprint dock-wall-corner guards, "Couldn't delete/copy/duplicate/re-render/reach the hydrant source/sample 3DEP/form a shape/build that easement" failures, "No parcel/county-parcel/building/bearings…" and "Select a pond/plotted deed boundary first" preconditions, "That's already gone", "That drawing is locked", "This tab is read-only", pond-sizing refusals including the one that already says "refusing" outright, and the lock-toggle failure messages. **What was deliberately left green:** every message reporting a COMPLETED action even with a caveat (e.g. "Aligned…", "Pasted…", "Rotated the deed… ⚠ the fit is loose" — the embedded `⚠` there now correctly reddens it via the `.includes` fix, without touching its wording), and neutral step-by-step mode instructions during an armed multi-click flow (those aren't refusals and aren't this report's shape).
- **What was NOT touched, named rather than left silent.** A further ~80–100 lower-traffic `flashWarn` sites were read and judged either already-correct (a completed action) or genuinely borderline ("Already at the front/back", "Nothing to reorder…" — a no-op status rather than a stopped user action) and were left as-is rather than mechanically prefixed; a full char-by-char relabeling of every remaining site was judged disproportionate to this report's shape (a green refusal reading as success) versus the size of the file, and is not filed as a separate item since nothing here rises to a blocking, misleading-as-success defect on the scale of what was fixed.
