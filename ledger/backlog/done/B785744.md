- **THE LANGUAGE.** A rule is `IF (conditions, AND/OR) THEN set status to (color) UNLESS (conditions, AND/OR — optional)`. A condition is `[field] [comparison] [value]`, Smartsheet-style — `RULE_FIELDS` (Finish date, Start date, Status, Owner, % Complete, Cost, Budget, Actual Cost, Predecessor) × `RULE_OPS` (date: is N+ days past due / is within N days / is more than N days away / is today / is blank / is not blank; status: is / is not; text: is blank / is not blank / is / contains; number: is / is more than / is less than / is at least / is at most / is blank / is not blank; predecessor: is late) — collapsing the old seven fixed sentences into ~6 fields × a handful of comparisons, with AND/OR composition and the UNLESS exception clause on top. His exact sentence renders verbatim: `IF Finish date is in the past THEN set Status to Needs Attn. UNLESS Status is Complete`.
- **THE ENGINE** (`public/sequence/index.html`, mirrored verbatim in `ui-audit/stress/scheduler-engine.mjs` per this repo's existing faithful-copy convention): `evalFieldCondition` (one condition, absence-safe — a missing date/text field always fails except the explicit blank tests; a missing number reads as 0, matching the long-standing `percentComplete||0` convention) → `evalConditionGroup` (AND/OR over a condition list; an empty group never matches) → `evalRule` (fires — returns the color — iff `when` matches and `unless` does not) → unchanged `evalHealthRules`/`computeDisplayHealth` call sites and signatures, so every existing caller (grid, Gantt, MasterView, PDF/web export, focus-overdue filtering) inherits the fix with zero changes of its own. `HEALTH_CONDITIONS`/`evalHealthCondition` (the old seven-condition vocabulary) are RETAINED, unused by the live engine, only as `migrateRule`'s frozen translation reference and because the existing test suite pins their exact semantics.
- **BACKWARD COMPATIBILITY, three generations deep.** `getHealthRules(settings)` now migrates ALL THREE stored shapes — the very-old 3-toggle `cfRules`, the v1 ordered-list from #1073, and native v2 — into the v2 `{when,unless}` shape live, purely derived, never persisted (same philosophy the original `migrateCfRulesToHealthRules` already used: nothing repaints until the panel is opened and touched). `migrateRule`'s `LEGACY_RULE_FIELD_MAP` translates each of the seven old condition types onto the new field/op vocabulary with byte-identical semantics (`notStarted` becomes a genuine two-condition AND — start past-due AND %Complete ≤ 0 — proving the new language subsumes the old one, not just replaces it).
- **THE ACTUAL FIX, made structural instead of a hardcode.** Every migrated non-green rule gets an auto-attached, VISIBLE, EDITABLE `unless: Status is Complete OR Status is Paused` — not a special case, just what `migrateRule` does for any rule whose color isn't green.
