`[x]` **ROOT CAUSE.** `SupText`/`SubText` were plain text spans using CSS `vertical-align: super`/`sub`, which shifts the WHOLE inline box — the "X" included — relative to the surrounding line. Superscript's box rides above the line, subscript's rides below it, so the two buttons' "X"s sat at genuinely different heights next to the plain-text B/I/U/S glyphs beside them, exactly as reported, and were text glyphs rather than the inline SVG every other icon on this row uses.
`[x]` **FIX.** Replaced with `SupIcon`/`SubIcon`, two inline SVGs sharing the same 16×16 `Icon` viewBox every other glyph on the bar uses. Both place their "X" (`<text>`, matching the same SVG-text convention `OrderedIcon`'s digits already use on this row) at the IDENTICAL `x`/`y`/`fontSize` — only the small "2"'s own position differs, top-right for superscript, bottom-right for subscript — so the two buttons now read as one glyph family with a single varying mark, matching B/I/U/S.
`[x]` **Checked the rest of the row for the same class of misalignment, per the brief's own instruction — nothing else was found.** Every other icon on the bar is already a centred inline SVG at the same size.
