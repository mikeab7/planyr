### B2061333 — iPhone: the keyboard hides what you are typing, and the chrome eats the screen `[Notes]` (feature) #notes #mobile  *(Claude Code dispatch block "NEW-6," adversarial iPhone review 2026-09-29, sent 2026-10-04)*

`[x]` **Five linked phone-layout problems, all reproduced on current main by `ui-audit/verify-notes-phone-layout.mjs` (14 ⛔ on an untouched-main build), all green here.**
`[x]` **(a) Caret under the keyboard.** Cause as traced: the caret was compared with the mat's own rect, which on iOS still spans the whole screen while the keyboard covers its lower part. Now the band is the mat ∩ the VISUAL viewport (`visibleBand` / `caretRevealDelta`, pure + tested), used by ProseMirror's scroll hook AND by an effect on `visualViewport` resize/scroll and editor focus (never while a placement is armed — the B1960480 trap). **Guard cooperation:** `pageContainmentGuard` still pins the document back, but when the keyboard is up (`keyboardUp`: an editable focused + visual viewport >120 px shorter) it ANNOUNCES the heal (`planyr:viewport-healed`) so the canvas does the revealing, and reports it as its own kind (`page-containment-keyboard-reveal`) so a real stray drag stays distinguishable from the production "(0, 244/264/275/276)" rows. **Proved with a controllable FAKE `visualViewport`** (WebKit headless has no keyboard): the old code let the caret reach 577 against a 400 keyboard line; now typing 10 lines never passes it. The production-rows explanation stays an **inference**, not proof (no real iPhone here).
`[x]` **(b) Toolbar.** Measured on main: Bold at x=449, lists at x=944, one 1290 px sideways row, no scroll cue. **What regressed:** NEW-9's compact fold deliberately removed the phone-specific layout ("narrow no longer selects a different LAYOUT"), so B849633's phone row was gone and nothing replaced it. **Fix:** on a phone the bar is one non-scrolling row of the essentials — ‹ (icon-only back) · undo · redo · B · I · U · bullet · numbered · text colour · More — and **More** drops a panel DOWN from the bar (the keyboard covers the bottom) holding everything else, rendered from the same named pieces as the desktop row (one implementation per control). **Desktop is byte-identical** (harness compares the toolbar's DOM to untouched main). Stated limit: nine controls at 390 px are ~38 px wide × 44 tall — a full 44 wide is not achievable on one row; the height is 44.
`[x]` **(c) Chrome.** While the editor has focus on a phone, `<html data-notes-typing>` hides the module-tab row (row 1 — settings/account/sync — stays); the page actions that lived there (Find and replace, Page setup, Version history, Export, Print) are buttons in the More panel meanwhile; the mat's resulting top-edge move is MEASURED and folded into the view so the page does not jump (VIEWPORT-STABLE; measured sheet top 147.0 → 147.0, canvas gained 40 px). Blur restores the row.
`[x]` **(d) Targets.** Coarse pointers only: box grip, eight resize handles and the connect dot get an invisible 44 px hit area (visible size unchanged); the sheet's EDGE grips are deliberately NOT enlarged (they sit where a page-edge tap places a box; a symmetric 44 px and then an outward-only 36 px version each moved a first letter 5 px off the finger at 200% in `verify-notes-touch-landing`); zoom −/+ 26 → 44 px; header row-1 buttons get a full-row-height hit area (never wider — neighbours are 4 px apart). The help button and the zoom pill leave the writing area while typing. "Double-tap" wording was already shipped by B1960480 (asserted by `verify-notes-touch-place`). **Tradeoffs stated:** the grip outranks the handles' halos (a corner handle's halo is partly shadowed on a very small box; its visible square still hits); row-2 module tab buttons and Notes' own header icon buttons were NOT enlarged (row 2 hides while typing, and it is shared chrome).
`[x]` **(e) Tooltips** never show where `(hover: none)` — the iOS compat `mouseenter` stuck them; desktop hover tooltips unchanged (known-good arm).
`[x]` **Regression caught by the combined run on final main, fixed (follow-up to #1961):** `verify-notes-touch-box-tap` (caret to the tap) and `verify-notes-touch-pan` (wobble) both went red on merged main — the (d) halo was centred, always-on, and sat over a box's first letters, so a tap meant for text/paper hit the grip.
