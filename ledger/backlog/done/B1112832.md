`[x]` **SHIPPED THIS SESSION.** A READ-ONLY walk of the EXISTING per-cell dependency graph in `lib/sheetEngine.js` — no second graph, no new edges. `collectRefHops` mirrors the graph-building AST walk (`collectCellDeps`) one-for-one but groups what it finds into the reference the user actually TYPED (a range, a `[Column]`, a named range) rather than one edge per cell, so a trace can label an arrow "Rate" instead of drawing seven separate lines to C4..C10 — `evaluateWorkbook`'s return now carries a `graph` object (`hopsFor`/`dependentsOf`) alongside the existing per-sheet eval results, at no extra recalc cost (same pass that already built the dependency graph for ordering). **`dependentsOf` is built from the hops, not from the eval-ordering `deps` map** — `deps` only ever records edges INTO a formula cell (a literal needs no ordering), so inverting it would silently break "trace dependents" starting from an ordinary INPUT cell, exactly the classic "who uses this number" case; measured and fixed before shipping. `lib/traceAudit.js` is the pure, UI-agnostic stepping layer: `beginOrStepTrace` decides fresh-start vs. extend-one-level from whether the SAME button was clicked again on the SAME cell (Excel's own behaviour); `stepTrace` expands only the trace's own last frontier, bounded by `TRACE_STEP_CAP` (400) so a cell with a huge fan-out (a shared constant every row of a 1000-row sheet reads) can't lock up the tab — a step that hits the cap reports `truncated: true` rather than silently drawing a partial picture with no explanation. `renderableTrace` turns the accumulated trace into arrows/markers for whichever sheet is CURRENTLY on screen — a hop is only drawn once its own target cell(s) are actually revealed (filtered against `trace.visited`), which is what keeps level-at-a-time stepping honest (an early attempt at this leaked precedents-of-precedents into level 1 before the filter was added; caught by a unit test, not by inspection). Cross-sheet edges never draw as an arrow (the target sheet isn't mounted) — they render as a small clickable marker naming the sheet and the reference (a name, when that's how it was reached), and clicking it switches tabs and selects the target cell. `SheetView.jsx` draws the overlay as an absolutely-positioned SVG (dashed rect + arrow + arrowhead marker, `pointerEvents:"none"` — an audit overlay is read-only, CHROME-NEVER-EATS-A-PRESS) computed from the SAME `colOffsets`/`rowOffsets` every cell already renders from, so it's correct at any zoom. A new "Formula Auditing" ribbon group (Trace Precedents / Trace Dependents / Remove Arrows, plus the Inconsistencies toggle from B1112833) ships alongside; Esc also clears an active trace, scoped to ignore the keypress when a floating menu/panel currently holds focus (see the MoreMenu note below for why that scoping is necessary). **A genuine, unplanned UX fix landed in the same commit:** live-testing at the owner's own stated 729px working width — narrow enough that this whole new ribbon group routinely collapses into the ribbon's "More ▾" overflow — found that picking a PLAIN action from that overflow popover (any of them, not just the new ones) left the popover sitting open afterward, which for Trace Precedents specifically meant it could cover the very arrows just drawn. Fixed at the root: the three dropdown-trigger shapes (`DropdownButton`/`IconDropdownButton`/`ColorSwatchButton`) now carry `aria-haspopup="true"`, and the overflow popover closes itself on any OTHER click inside it — matching Excel/Sheets' own overflow-menu convention (pick a one-shot action, it closes; open a nested picker, it stays). Every other ribbon group benefits from this, not just Formula Auditing.
