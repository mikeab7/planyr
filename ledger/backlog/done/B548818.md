`[x]` **The estimate was `widest line by CHARACTER COUNT × (fontSize × 0.6)` — two compounding errors.** A character count says "1" and "M" are the same width; 0.6 em overstates a face that draws figures at ~0.55 em. A chip full of digits is the worst case, which is why it was the one reported.
- **THE SHARED HELPER IS FIXED AND EVERY CALLER SWEPT, as instructed** — `widthOf` in `labelLayout.js` now takes optional per-line MEASURED widths, and all three passes supply them: the measurement chip, the parcel acreage badge, and the element-label pass. A caller that supplies none keeps the old estimate exactly, so nothing moves by accident. Measured widths join the layout memo key, because they are an input to placement (VIEW-INDEPENDENT-ONCE).
- Each line is measured at the size AND weight it is painted at — headline bold, name/detail at the subordinate size with its 0.02 em tracking. **Letter-spacing is real width and `measureText` does not report it**, so both measurers now add it; a measurer blind to it under-sizes exactly the lines that carry it.
- `test/labelWidthMeasured.test.js` includes the case a character count gets BACKWARDS rather than merely imprecise: six of the narrowest glyphs against three of the widest.
