`[x]` **New named check, `ui-audit/ui-inventory.mjs`'s `siblingMismatches()`, its own count, never folded into `nestingMismatches()`'s.** For every crawled surface: groups the same on-scale rounded-candidate pool `nestingMismatches()` builds by shared **flex-row ancestor** (a bounded upward walk from each candidate's parent, not a bare immediate-parent test — see the measured reason below), sorts left-to-right, and walks **adjacent pairs only**; a pair is flagged when their families differ, their vertical centers roughly agree, and the horizontal gap between them is small (≤12px — this app's own base flex `gap` is 6–8px almost everywhere, so a flush pair trips it and a pair separated by a real divider does not). Findings print in `docs/UI-INVENTORY.md`'s new "Sibling radius mismatches" section.
`[x]` **⛔ THE GROUPING HAD TO BE ANCESTOR-BASED, NOT IMMEDIATE-PARENT, and this was found by the check reporting ZERO on the owner's own exact pair on its first pass — not assumed.** This sandbox's signed-out fallback (`AccountControl.jsx`'s "Cloud off" pill, the only branch reachable with no Supabase configured) wraps its button in an extra `<div style={{position:"relative"}}>` for its own popover anchor; the signed-in pill does not (a bare Fragment). An immediate-parent test sees two different parents for what is visually one row and finds nothing. Walking up to the nearest `display:flex` row ancestor (capped at a few hops) fixed it — real rendered geometry decides adjacency, not incidental DOM nesting depth.
`[x]` **Decided and documented in `docs/DESIGN.md` (new "The sibling clause" section): neither control is reclassified.** The account chip genuinely is a `pill` (a container holding an avatar, a name and a caret — already blessed by the shape rule) and the fullscreen button genuinely is `md` (a standalone icon action, matching `controls.jsx`'s own `IconButton` primitive) — collapsing that distinction to make two unrelated controls match would be worse than the mismatch. **The binding rule instead: two different radius families may sit in one control row only with a visible boundary between them** (a divider, or genuine clear space) — flush adjacency is never acceptable between families, however individually correct each one is. Fixed by inserting the same hairline divider `AppHeader.jsx` already uses between the wordmark and the breadcrumb, between the icon-button cluster (save badge, fullscreen, gear) and the identity pill.
`[x]` **The check found a second, independently pre-existing instance the owner never reported.** The header's plan-name chip (`SitePlanner.jsx`) had drifted to `RADIUS.sm` sitting beside the project-breadcrumb chip (`RADIUS.md`) — its own comment claimed they matched ("Styled to match the breadcrumb crumbs... so the three segments share one hit-target geometry"), a claim that silently went false when a prior session (B942178's design-drift merge) moved the breadcrumb's own `crumbBtn` from `sm`→`md` and never touched this chip.
