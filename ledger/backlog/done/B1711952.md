`[x]` **EVERY NOTICE IN THE FILE THAT NAMES A TASK OR A SCHEDULE NOW SAYS `<Project> / <Schedule>` FOR A ROW OUTSIDE THE SCHEDULE ON SCREEN, AND DROPS THE REDUNDANT PREFIX FOR A ROW ALREADY IN VIEW.** All in `public/sequence/index.html` (the standalone embedded schedule app served at `/sequence/`, iframed by the Schedule tab — none of this is in `src/workspaces/scheduler`).
- **THE MODEL.** Every schedule already carries `linkedSiteId`/`linkedSiteName` (the cross-module link to its owning Planyr project) via the existing `ownerOf()` schedule-ownership function (`SCHEDULE-OWNERSHIP` sync block, unmodified). Three new helpers, deliberately placed OUTSIDE that sync block (they're notice-copy built ON it, not part of the ownership contract `src/shared/schedule/scheduleOwnership.js` mirrors):
  - **`crossScheduleLabel(schedule)`** — `"<Project> / <Schedule>"`. Never degrades to a bare schedule name: org-owned prints the fixed `ORG_OWNER_LABEL` ("Organization"), and a site-owned schedule whose cached `linkedSiteName` hasn't caught up yet gets "an unnamed project" rather than silently falling back to the exact ambiguity this closes.
  - **`scheduleRowPrefix(projects, pid, currentPid)`** — the prefix for a row belonging to schedule `pid`: nothing when `pid` is the schedule already on screen (PANEL-BREVITY — restating "Goose Creek / Master Schedule" next to every row of the table you're already looking at is noise), else `crossScheduleLabel(...)` + a trailing space. Compares `pid`/`currentPid` as strings deliberately — a schedule id arrives as an object key (`Object.keys(d.projects)`, always a string) in some call sites and as the numeric `.id`/`.aPid` field in others; a strict `===` would silently show every row as "elsewhere."
  - **`changedProjectIds(before, after)`** + **`mergeLocationPhrase(projects, changedPids, currentPid)`** — which schedules a `planar:merged` round-trip actually touched, and the toast's "where" phrase: `"in this schedule"` when the only one touched is the one on screen, else `"in <label>[, <label>…]"` built from `crossScheduleLabel` (capped with a `+N more`).
