**WHY NO APPLICATION CODE CHANGE WAS NEEDED — checked, not assumed.** All three sources (`fl_statewide`, `tn_statewide`, `oh_statewide` in `counties.js`) render via the ordinary vector `esri-leaflet` featureLayer path (`mapServer: null`, not the special TxGIO image-only case), which is already covered by `MapFinder.jsx`'s existing `DISPLAY_LOAD_TIMEOUT_MS` (8000ms) hang-guard (`markDown` — the SAME mechanism B1427664 just hardened, which shows an honest "still loading"/outage notice rather than hanging, and falls back to a cached Drive snapshot when one exists) — and the click/ID-lookup path already carries its own independent 8-second `AbortController` cap (`PARCEL_FETCH_TIMEOUT_MS`, `arcgis.js`). So a user selecting a site in Florida, Tennessee, or Ohio today already gets a graceful, honest degradation rather than an indefinite hang; the gap this closes was **visibility**, not runtime safety — nobody had measured that these three sources actually exercise that hang-guard in practice, and nothing would have caught a FOURTH one silently joining them, or one of these three getting worse.

**THE INSTRUMENT (shared code with B1437585 — `ui-audit/lib/statewideCoverage.mjs`).**
- **`ENVELOPE_QUERY_BUDGET_MS = 8000`** — **not invented for this probe.** It is `PARCEL_FETCH_TIMEOUT_MS` from `arcgis.js`, the app's own real click-lookup hang-guard cap, duplicated with a comment (that module can't be imported into a Node script — it transitively pulls in `mapLock.js`, which needs a DOM `window`). Asserting the app's real budget against the app's real query shape, not a number picked for this probe alone.
- **`probeEnvelopeTiming`** runs exactly that query shape, timed via the probe's own `fetchJson`'s `AbortController`, and reports `overBudget` (didn't answer inside the budget) independent of `ms` looking "successful."
- **`pointInsideExtent` + `emptyDespiteCoverage`** — the SECOND, independent signal this item's own evidence demanded: Tennessee's timing varied run to run (sometimes under budget, sometimes not) but was CONSISTENTLY empty at a point its own extent claims to cover, so a timing-only check would miss it on a fast day. A query answering zero at a point inside the layer's own declared coverage is flagged regardless of how fast it answered.
- Both signals are reported per-source in `docs/STATEWIDE-PARCELS.md`'s new `Envelope query (≤8s)` column and the shared `⛔ WIRED SOURCES FLAGGED` section (see B1437585), and printed live to the console as the probe runs (an 8-second-budget check per state costs real wall-clock — an operator shouldn't have to wait for the whole 29-state run to see a hit).
