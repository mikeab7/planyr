- **(1) Parcel fill "Translucence" slider** (`SitePlanner.jsx:~10361`) — a bare `onChange → setSelParcel` (which never pushes history) meant dragging translucence recorded no undo frame, though `fillOpacity` IS in the snapshot; the next Undo then misfired past it. Fixed: spread `{...sliderHistory(...)}` like every other opacity slider (the RC-5/RC-7 house rule). **SANDBOX-VERIFIED end-to-end** — `ui-audit/verify-b828-undo.mjs` (8/8, logged-out): draw parcel → enable fill → drag Translucence 0.12→0.24 → click the Undo BUTTON reverts it in ONE step (parcel+fill survive, no overshoot) → Redo restores.
- **(2) Raster overlay "Width (ft)" input** (`SitePlanner.jsx:~9918`) — typing a new width (patchOverlay `hist=false`) had no `onFocus` checkpoint, so rescaling an image overlay wasn't undoable though `ftPerPx` IS snapshotted. Fixed: `onFocus={() => pushHistory()}`, mirroring the opacity number input directly above it.
- **(3) Stitcher auto-calibrate** (`Stitcher.jsx:~362`) — auto-setting `ftPerUnit` from a grouped set's stated scale had no `pushHistory()`, so one Undo skipped straight past it and DELETED a measurement drawn before the group was added. Fixed: checkpoint before the auto-set.
- **(4) DocReview + Stitcher undo mirror was a passive effect** (`DocReview.jsx:~372`, `Stitcher.jsx:~82`) — the B315 anti-pattern: the `docStateRef`/`editRef` mirror lagged one paint behind the live state, so an undo fired right after an edit compared against a stale snapshot, treated the top frame as a no-op, and did nothing (the button stayed enabled, so it just looked broken). Fixed: assign the ref DURING RENDER, exactly like SitePlanner's `stateRef` (the proven B315 fix).
