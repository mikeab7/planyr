`[x]` The zoom indicator — which used to render only once the view drifted off 100% (a PANEL-BREVITY call that made sense for a toolbar SLOT, and no longer applies to a permanent floating control) — is now an always-on `[−] [level ▾] [+]` pill, floating bottom-right of the notes canvas, in `NoteEditor.jsx`. The dropdown offers 50/75/100/125/150% plus "Fit width". `−`/`+` walk the same named zoom ladder (`stepZoom`, `notesViewport.js`) Ctrl+=/Ctrl+− already use; the level shown resets to 100% correctly, and picking a named level or Fit width calls the exact same `zoomTo`/`resetView`/`fitWidth` functions the keyboard shortcuts always have — zoom itself is unchanged, only where its control lives moved.
`[x]` **⛔ A real collision was caught and fixed, not just built.** The pill's first live pass showed it intercepting no clicks in isolation but SHARING its exact corner with the app-wide Help/Report floating button (`HelpReportControl.jsx`), which (per `shared/ui/cornerClearance.js`'s own documented contract) reads `[data-canvas-corner]` markers elsewhere in the DOM and repositions ITSELF to clear them — `NoteOutline.jsx`'s own floating toggle in this same module already relies on exactly this. The pill was missing that marker, so the Help FAB sat on top of it and ate every click. Fixed by adding `data-canvas-corner="notes-zoom"` to the pill — the established, already-precedented contract, not a new mechanism.
`[x]` The pill's own containing box is scoped to JUST the canvas (a new `position: relative` wrapper around `note-mat` specifically), not the wider row that also holds the Outline/History side panels — so it stays anchored to the canvas's own bottom-right corner regardless of whether either side panel is open.
