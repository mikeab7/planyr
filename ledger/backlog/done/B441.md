### B441 — Parcel selection feels laggy: paint the highlight optimistically on click, confirm via identify in the background `[Site Planner / map]` (bug)  *(owner-reported 2026-06-24 from a ChatGPT thread as "NEW-1"; minted **B441** = highest real B# across both files (B440) + 1)*
`[x]` **Built + shipped (branch `claude/hopeful-brown-q7q4jo`). lint 0 errors · 1421 tests · build green.**
- **Repro (owner):** clicking a lot on the live county map took a variable delay — sometimes a couple seconds — between the click and the parcel highlighting. Root cause (confirmed in code): `MapFinder.handleClick` did `setBusy(true)` then `await identifyParcelEager(...)` — a network identify against the county ArcGIS REST service(s) — and only painted the highlight + pushed the selection AFTER that promise resolved. The variable multi-second lag was county-server round-trip latency, not client compute.
- **Fix — optimistic local highlight, then reconcile (no network on the felt path):**
  - The county parcel outlines are already drawn client-side as esri-leaflet vector `featureLayer`s (`makeParcelLayer`). New `optimisticHitAt(latlng)` hit-tests those already-loaded features (cheap `getBounds().contains` reject → ray-cast on the outer rings) and returns a hit shaped like an identify hit. New pure `geoJsonToEsriFeature` (arcgis.js) converts the display layer's GeoJSON polygon into the same esri-shaped `{geometry:{rings},attributes}` the highlight/select path already consumes — so the on-screen outline feeds the **exact same** `addParcelHit` pipeline (one source of truth, B233/B22 keys intact). Prefers a real county over the statewide TxGIO backup (mirrors identify's source priority), then the tighter parcel when several overlap.
  - `handleClick` now paints the optimistic highlight **synchronously, before** the identify starts → the click feels instant. The `await identifyParcelEager(...)` still runs in the background as the authoritative confirm (still feeds the circuit breaker via `onSettled` → `recordSourceResult`, B244 unchanged). On return it **always rolls back the optimistic outline and rebuilds from the identified geometry** (full-res + real account/address attrs), so the IMPORTED parcel is never the simplified display outline. No flash — the remove+re-add happen in one synchronous turn after the await.
  - **Reconcile cases:** identify confirms the same parcel → seamless real-geometry swap; identify returns a different/refined parcel (multipart per B36c, or a statewide-backup relabel) → optimistic rolled back, authoritative added (multipart still highlights every tract); identify finds nothing / errors → optimistic highlight **visibly rolled back** + the existing "No parcel right there" / "server isn't responding" message (B245 wording preserved).
  - **Instant local toggle-off:** new `selectedHitAt(latlng)` — a click inside an already-highlighted parcel now deselects it with **zero** network round-trip (we already have its geometry).
- **Edge cases handled:** display layer zoom-gated (`PARCEL_MINZOOM` 14) → when nothing's loaded under the click, `optimisticHitAt` returns null and we fall back to the original await-identify-with-busy behavior (never fabricate a highlight from nothing). Optimistic add only fires when the parcel isn't already highlighted, so a rollback can never strip a pre-existing selection. `selectParcelAt` (address-search select, B233) shares the same reconcile pipeline; the optimistic step is click-only (an address select already runs after a `flyTo`, so there's no felt lag there).
- **Tests:** +3 unit tests for `geoJsonToEsriFeature` (Polygon flatten + attrs, MultiPolygon flatten, null/non-polygon) round-tripping through `outerRingsLngLat` (test/arcgis.test.js, 19 in that file). lint 0 errors · full suite 1421 green · build green.
