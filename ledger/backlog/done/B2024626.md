### B2024626 — Chambers lots come in as "Parcel N" with blank owner/name, and the Account/ID shows the row id `[site-planner / parcels]` (bug) #site-planner #gis  *(Owner report 2026-10-03 (NEW-3): lot 15835 → "Parcel 18", owner blank; live row has `Accounts.Owner_Name = BARBERS HILL EDUCATION FOUNDATION`.)*

`[x]` **Cause:** CCAD is a JOINED layer — every field is table-prefixed (`ChambersCADWeb.DBO.Accounts.Owner_Name`). The owner/situs/acreage resolvers and the curated-row regexes match anchored bare column names, so a prefixed key never matched: Owner, legal and acreage came back blank for any Chambers lot (the strip lots only named themselves because they carry a situs), and the "Account / ID" row's `account` regex matched the PREFIX word in `…Accounts.OBJECTID`, showing the row id (2933785) instead of `Accounts.Account`.
`[x]` **Fix:** `lib/appraisal.js` resolvers (`ownerKey`, `situsKey`, `acreageKey`, the curated field map, `findAttr`) now match the LEAF of a key (`leafKey`: text after the last "."), reading the value off the full key; a table-prefixed bare `Name` (the lot number) is never an owner. A lot with no situs is now named by `parcelFallbackName` (owner, else the first line of the legal, capped) before "Parcel N" — in `siteModel.parcelDisplayInfo`, so the plan list, panel and exports agree. Un-prefixed schemas are untouched (existing appraisal/situs/owner/panel suites green).
- **Red-proof:** `test/chambersLotRecord.test.js` uses the live Chambers attribute set for lot 15835 (no situs): owner, Account/ID (`00321-02000-00100-100001`), legal, acreage, and the stored parcel's display name — 5 of 7 fail on the pre-change source. Real browser harness: before, no owner text and the row id shown; after, owner shown and `2933785` absent.
- **Note on existing plans:** any saved parcel with county attributes and no situs now displays its owner/legal as its name instead of "Parcel N" (display only — stored `addr`/`label` untouched; a name the user typed still wins).
