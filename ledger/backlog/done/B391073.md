- **TWO MECHANISMS REMOVED ANYWAY, because "I could not reproduce it" is a finding and not a fix:**
  1. **A PRESS THAT NEVER MOVED NOW WRITES NOTHING AT ALL.** The drag used to commit the box's own coordinates back over themselves on every release — a no-op only for as long as nothing in that round trip is ever wrong. The reported symptom is a box moving on a press with no drag, so the press no longer has a write path to move it through.
  2. **THE DRAG IS SCROLL-PROOF.** It measured a delta between two CLIENT coordinates, and a client coordinate means something different the moment the scroller moves underneath the gesture. It now keeps the grab offset and reads the editor's box FRESH on every move — which also makes "the box must not re-seat under the cursor on grab" true by construction rather than by luck.
- **WHAT I COULD NOT RULE OUT.** His page had ten boxes and an empty-box cleanup running in the same frame; a change in the page's height clamps the scroller, and everything on screen moves together.
