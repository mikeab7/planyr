`[x]` **FIXED THIS SESSION.** The overlay drew one straight `<line>` per arrow from the source rect's near edge to the target cell's own center — for a precedent sharing the target's ROW (the common case, e.g. `A1 -> E1`), that line ran at the row's own vertical center (`cy`), which is exactly where every intervening cell's text sits (`vAlign` defaults to "center", regardless of the cell's own horizontal alignment). `routeArrowPath` (new pure helper, `SheetView.jsx`) now routes a same-row or same-column arrow along a LANE inset from the rect's near edge (16% of the row/column's own height/width — clear of the centered text band regardless of left/right/center alignment), with a short stub at each end connecting to the true source-edge and target-center points, so the dot still marks the source and the arrowhead still lands exactly on the target. A genuinely diagonal precedent (source and target share neither a row nor a column) keeps the original corner-to-corner line — it never ran through a row/column's own center band to begin with. Rendering changed from one `<line>` per arrow to one `<path>` per arrow (`routeArrowPath`'s multi-segment waypoints as an SVG path `d` string via a new `arrowPathD` helper); `marker-end` still orients to the path's own final segment, so the arrowhead direction is unchanged.
