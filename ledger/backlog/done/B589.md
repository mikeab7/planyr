- **HIGH — whole-column aggregation double-counted summary/parent rows.** In a grouped schedule the flattened row list contains a parent (showing the rolled-up sum of its children) AND its children, so `SUM([Cost])` returned ~2× the real total (and a collapsed group's children were omitted entirely). **Fix (host, `computeFormulaValues` in `public/sequence/index.html`):** aggregation now reads the project's **LEAF tasks of the full tree** (`proj.tasks` leaves), independent of expand/collapse — leaves carry the atomic values; a parent's cell is a pure roll-up. The per-row display still uses each row's own values. `previewFormula` mirrors it.
- **HIGH — date-literal criteria never matched.** `COUNTIF`/`SUMIF`/`AVERAGEIF([Dates], ">=2026-03-01")` returned 0 (and the `<>` form a wrong non-zero count) because `parseCriteriaOperand` didn't parse a date string and the numeric-family gate excluded dates. **Fix:** parse date literals → date values; widen the gate to include dates.
- **MED — `[@Column]` (this-row) was ignored by `COUNTIF`/`SUMIF`/`AVERAGEIF`/`MATCH`/`INDEX`/`XLOOKUP`** (`colArray` didn't check `atRow`), so `SUMIF([@Cost],…)` read the whole column. **Fix:** `colArray` returns a single this-row cell when `atRow`.
- **MED — `WEEKNUM`** silently treated every type other than 2 as Sunday-start (so type 11 Monday-start and 21 ISO were wrong) and never returned `#NUM!` for an invalid type. **Fix:** full type table (1/2/11–17/21) + `#NUM!` on unknown.
- **MED — `[@[Column]]`** (Excel's bracketed-inner structured ref) failed to tokenize (`#ERROR!`); the tokenizer stopped at the first `]`. **Fix:** scan to the `]]` for the `@[…]` form.
- **MED — `MIN`/`MAX` over a date column returned a raw serial number** instead of a date (so `MIN([Start])` showed `46388`). **Fix:** return a date when every contributor is a date.
- **LOW-MED — `MATCH` approximate (type ±1) leaked across type families** — a text lookup matched numeric cells (cross-type rank). **Fix:** restrict the ≤/≥ search to the target's type family.
- **LOW — `YEARFRAC`** returned a negative result when end < start (Excel is always non-negative). **Fix:** drop the sign.
- **LOW (latent) — `colArray`** decided "unknown column" from `rows[0]` only, so a ragged table could read a real column as `#REF!`. **Fix:** existence check across the union of rows.
