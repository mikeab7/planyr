`[x]` **ROOT CAUSE.** The font chip's visible text (`FormatMenu`'s `displayLabel` prop) was wired to `notesResolvedValue.js`'s `defaultFontLabel(defaultFamily)`, which deliberately returns `"<name> · standard"` (e.g. `"Inter · standard"`) — correct for a MENU ROW naming which option is the default, wrong for a fixed-width CHIP, where it truncates to `"Inter · st…"`, unreadable, exactly as reported.
`[x]` **FIX.** The chip's own label (`fontLabel` in `NoteToolbar.jsx`) now reads the plain resolved family name only (`defaultFamily || "Standard"` — never the bare word "Default," matching this module's own established rule that "Default" names no real font). The default marker moved into the MENU instead: the palette's default row now shows the real name, a "✓ " prefix when it is the value actually in effect (the same convention `SpacingPopover`'s preset rows already use), and a small "Default" tag beside it (the same visual treatment `SizeMenu`'s own default-size row already uses) — never appended into the name itself.
`[x]` **Checked the size chip and the paragraph-style menu for the same leftover-suffix pattern, per the brief's own instruction — neither has it.** The size chip is a bare number with no suffix; the paragraph-style options are plain "Body text"/"Heading N" labels. `defaultFontLabel` (`notesResolvedValue.js`) is untouched and keeps its existing unit test coverage — it is simply no longer called from the chip.
