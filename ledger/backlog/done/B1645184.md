`[x]` **REPRODUCED, before writing any fix, via a mutation check** (extend `e2e/split-parking-add-aisle.spec.js` with a freestanding fixture, then temporarily disable the new delegation branch and re-run): on unfixed `main`, `growParking`'s wall-bonded guard (`el.attachedTo && el.sideParkSide`) never fires for a freestanding piece, so a "+"/"−" on one piece of an already-split freestanding stack falls straight to the generic single-element resize path — it resizes THAT ONE PIECE in place instead of appending a new row+aisle beyond the stack, exactly the class of defect B1625728's own comment predicted ("resizing ONE piece of a bonded stack in place doesn't move its siblings, so it overlaps them" — the freestanding case has no siblings-by-host to even check against). **ROOT CAUSE (AUDIT-FIRST).** Identical shape to B1625728: `explodeParkingBands` replaces one field with a STACK of independent pieces, and only the wall-bonded case had a way to find "the rest of the stack" (`sideParkPadsOn`, keyed on `attachedTo` + `sideParkSide`). A freestanding field has no host and no side, so there was nothing to group siblings by — B1625728's own words, quoted above.

**THE FIX.** `freeParkStack(el, els)` (new, `lib/parking.js`, pure) finds a freestanding piece's siblings from GEOMETRY instead of a host relation: same width, same rotation, touching end to end along that shared local axis, walked outward from whichever piece was passed in (so it works no matter which piece the user clicked) — mirroring the standing rule right above `sideParkPadsOn` in `SitePlanner.jsx` ("what is on this wall is answered by GEOMETRY, with the tag as a fast path"), applied where there is no wall to test against. `sideParkPiece` (already stamped by the explode) orders the result when present but is never required for membership, so a plan where the tag went missing still degrades to a correctly-ordered geometric read rather than an invisible stack. `growFreeParkStack` (new, `SitePlanner.jsx`) mirrors `addSideParkPieceBeyond`/`growEmployeeSide`'s own ladder: always acts on the stack's OUTERMOST piece (LIFO, same as the wall case), appends an aisle THEN a row unless the outermost piece is already an aisle (the same odd/even-row-count distinction B1625728 fixed for the wall case — a single-loaded freestanding field's reserved aisle must not gain a second one stacked on top), and on shrink removes one outermost piece at a time. `growParking` now checks `!el.attachedTo` and delegates to it whenever `freeParkStack` finds more than one piece, right alongside the existing wall-bonded delegation — a lone, un-split freestanding field (the control case) is untouched and keeps its original in-place row-pairing growth.
