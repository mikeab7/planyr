### B19 — Resume-on-mount re-saves the just-loaded review with a fresh `updatedAt` `[Document Review]` (bug) — correctness, medium
`[x]` 🔧 fixed 2026-06-15 (branch `doc-review/b19-resume-resave`): `useReviewPersistence` exposes `suspendSave(ms)` which parks a suspend window; the autosave effect early-returns while it's active. `loadSingleReview` arms it once (single commit); `loadStitch` arms it at start and re-arms before its async `setPdfs`/`setPlaced` commits, so a programmatic load never re-stamps just-loaded data with a fresh `updatedAt`. `loadSingleReview`/`loadStitch` set state → the debounce deps change → autosave writes the loaded snapshot back with `updatedAt: now`, so a resume can stamp stale data as newest and (multi-tab) clobber a newer cloud edit. Fix: a `suspendSave` ref set during programmatic load, early-returning from the autosave effect for that tick.
