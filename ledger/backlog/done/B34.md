### B34 — Doc Review single-viewer `render()` calls `setScale` internally → re-entrant render race `[Document Review]` (bug) — correctness, medium
`[x]` 🔧 fixed 2026-06-15 (branch `chore/audit-tail-grind`): the fit-to-width scale is computed in its OWN effect (when `scale===0`); `render()` returns early until a concrete scale exists and no longer calls `setScale`, so it's a pure draw and the double-render / `dims` mismatch is gone. In fit-to-width mode `render` calls `setScale(s)` then keeps drawing; the `scale` change re-fires the render effect, so two renders run and `dims`/canvas can briefly mismatch the overlay. Fix: compute fit scale in a separate effect; keep `render` a pure draw at a concrete scale.
