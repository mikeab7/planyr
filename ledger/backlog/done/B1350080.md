`[x]` **FIXED THIS SESSION.** `public/sequence/index.html`, `GridView`. Deleted the old absolutely-positioned `⊞ Columns` pill entirely (it floated over the table regardless of content width, which is exactly why it could cover the last column's name at any width). In its place: a **28px never-scrolling gutter strip**, a true sibling of the grid's horizontally-scrolling region rather than a member of it — `data-grid-scroll`'s own box is now inset `right:GRID_GUTTER_W` from the pane's true right edge, and the gutter strip is a separate absolutely-positioned column pinned to that same edge. Because the scrollable region's own clip boundary stops 28px short of the pane edge, **no column can ever be laid out under the gutter, at rest or mid-scroll** — this is structural (the two regions don't share a scroll body), not a z-index/paint-order trick. The gutter's own border runs the full pane height (drawn once, not per-row), so it reads as one continuous column edge without needing a spacer on every data/filler row (an earlier sticky-flex-item version of this fix DID need a per-row spacer — abandoned once measurement showed the sticky-in-flow approach still let a mid-width column's trailing pixels paint under the gutter at rest; see the verification note below for how that was caught and why the two-region layout doesn't have the same failure mode). The button itself reuses the app's existing house three-dot glyph (the mobile header's overflow-menu SVG, at 14px) rather than inventing a new icon, carries the same `title="Show, hide, add or reorder table columns"`, and its `onClick` is unchanged (`setColMenuOpen`/`setHdrCtx`). `GridColumnsChooser` now takes an optional `anchor` prop (the button's own `getBoundingClientRect()`, read via a new `colBtnRef`) and positions itself just under the button instead of a hardcoded `top:46,right:18`; the header-cell right-click menu's existing "Columns…" entry is untouched and opens the same panel. `GridView` is shared by the plain Grid view, both Split-view layouts (desktop and phone), and the review-suggestions grid, so this fixes all of them in one place — no separate Split-view change was needed.
