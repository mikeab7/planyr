- **ROOT CAUSE, confirmed by reading `src/workspaces/site-planner/lib/keyContract.js` and proven with two independent probes (unit-level pure-function tests AND a live pre-fix/post-fix browser diff), not inferred from the branch's position in the handler.** `SitePlannerApp.jsx` was checked directly and carries **zero** keydown listeners — the "four separate listeners inside SitePlannerApp" lead in a later correction did not hold up; instrumenting every real `window`-level `keydown` listener that observes a `c` keypress (there are four across the app: `SitePlanner.jsx`'s main handler, its Shift-tracker, `AppHeader.jsx`'s fullscreen toggle, and one more from a conditionally-mounted `MapFinder.jsx` menu) showed only ONE of them ever calls `preventDefault()` on a bare `c`, and it is exactly the branch this item fixes. **`KEY_CONTRACT` (the declared-shortcuts table every canvas keyboard shortcut is checked against before it can fire) had an entry for every OTHER bare-letter tool shortcut — Select(v) Pan(h) Marquee(m) Snap(s) Callout(q) Text(t) Line(l) Rect(r) Ellipse(e), ⇧Polygon(p) ⇧Polyline(n) — but NONE for Cloud(c).** `resolveKeyEntry` returns `null` for anything undeclared, and `keyScopeVerdict`'s `if (!entry) return { allow: true, … }` rule — correct for a genuinely unbound key — then let it fall through even while a text field owned the keyboard (FIELD scope), because there was nothing to refuse. Every sibling letter's declared entry gets refused correctly in FIELD scope, which is exactly the asymmetry the owner's own discriminating test found (l r e t q v m h n p x y z landed as text; only c fired).
- **THE FIX:** one new `KEY_CONTRACT` entry — `{ id: "tool-mcloud", label: "Cloud tool", keys: ["c","C"], mod: M.NONE, scope: "canvas", mutates: false }` — routing Cloud through the SAME arbitration every other letter already uses. No change to the SitePlanner.jsx branch that arms the tool, no bespoke "is this an input" check bolted beside it — exactly what the report asked for.
