### B467 — Restore's "can be undone" guarantee was unverified; Restore wasn't lock-gated `[Site Planner / Persistence]` (bug)  *(owner-dropped 2026-06-25 as "NEW-4"; minted **B467**)*
`[x]` **DONE + unit-verified (branch `claude/exciting-wright-yb6ruz`). lint 0 · 1528 tests (storage.test.js +3) · build green.** The Version History dialog promises "your current version is backed up too, so a restore can be undone," but that relied on the autosave's shape-DEDUPED snapshot firing after the restore — which can no-op (same collection shape, different content) → restore overwrites current work with no real undo.
- **Fix (`storage.js` + `restoreVersion`):** `snapshotVersion(model, { force })` now **returns whether it persisted** and `force` bypasses the shape-dedup; new `backupNow(id)` force-snapshots the current stored state and returns true only when a backup actually persisted (or there's genuinely nothing at risk — empty/missing record). `restoreVersion` (a) is **lock-gated** — a read-only tab can't Restore (loud message + the takeover way out); (b) flushes the live canvas, then **verifies `backupNow` before replacing** — if the backup can't be written (device storage full) it CANCELS the restore loudly + emits a `restore-backup-failed` telemetry event, rather than destroying current work on a false promise. Fits the verify-it-persisted / no-silent-success discipline.
