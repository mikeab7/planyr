- **WHY, mechanically — no fix was needed because there is nothing to leave stale.** The handle layer's `onContextMenu` (`SitePlanner.jsx`) recomputes `document.elementsFromPoint` fresh on every press and reads the CURRENT `sel`/`selVtx` React state; there is no cached "last target" anywhere in the dispatch path. `ContextMenu.jsx`'s own Escape listener runs in the CAPTURE phase and calls `stopPropagation()`, which stops `SitePlanner.jsx`'s bubble-phase catch-all Escape handler (the one that clears `sel` and every menu state at once) from ever running while a menu is open — so neither dismissal method touches the selection or leaves DOM in the way of the next press. The live report's own instability (two of three identical-looking tries returning the BUILDING's menu, a fourth returning none) is exactly the signature of a synthetic-input timing artifact, not a state leak: nothing in the resolution path is capable of remembering a prior press at all.
