### B414 — Doc Review (Library) sheet flashes white on zoom-settle — double-buffer the re-raster `[Doc Review / Markup]` (bug)  *(owner-dropped 2026-06-23 as "NEW-1"; first filed as B412, but a concurrent `main` (PR #311) took B412/B413, so **renumbered B414** = the next free ID)*
`[x]` **Filed AND fixed the SAME session per STANDING RULE #1 (branch `claude/confident-edison-lpbco9`). 1273 tests · lint 0 · build green; headless-verified.**
- **Repro:** open a sheet in the Library/Markup canvas, zoom in/out; ~140 ms after the gesture settled the sheet flashed blank/white before the sharp render appeared (Bluebeam never flashes on the same file).
- **Root cause (code-confirmed):** the single visible canvas was re-rastered on every zoom settle; reassigning `canvas.width/height` clears it to transparent, revealing the white page-box `<div>` (`background:"#fff"`) behind it, and the `page.render()` that refills it is async (pdf.js worker) → a visible blank gap each settle.
- **Fix:** `pdf.js` `renderInto` now rasterises into an OFF-SCREEN canvas and blits the finished frame onto the visible canvas (`drawImage`) in one synchronous step — the compositor never sees the cleared canvas. It bails on `isStale()` so a superseded render never blits a stale frame (B40 guard kept; off-screen also sidesteps the same-canvas throw). The biggest contributor in practice is B415's backdrop (the whole-page layer no longer re-rasters on zoom at all), but the double-buffer makes EVERY swap (page change + the detail settle) flash-free.
- **Verified:** `ui-audit/verify-b414-b415-render.mjs` D1 (backdrop backing dims unchanged across a zoom → can't blank) + D3 (detail layer polled through a settle, never caught blank — min opaque centre pixels > 0). Foundation for B415.
