- **THE DEFECT, in the file's own words.** `scripts/perf-ratchet.mjs`'s header has promised since it was written that it "measures the value itself, **from a fresh build**", and that "you cannot ratchet to a number you did not measure". The second half was true. The first half was a **comment**: the code called `loadBuild(join(ROOT, "dist"))` and measured whatever `dist/` was in the tree, produced by whoever last typed `npm run build`, at whatever revision the tree was in at that moment. Note the asymmetry it had lived with — the RUNTIME half of the same script interrogates its input rigorously before writing a byte; the bundle half did none of it.
- **THE FIX, three parts, all loud rather than degrading:** (1) it **builds**, into its own `dist-ratchet`, unless `--dist` names one deliberately; (2) it **refuses a working tree with uncommitted changes** to anything the bundle is a function of (`src/`, `index.html`, `public/`, `vite.config.js`, `package.json`, `package-lock.json`) — a number measured from a tree no commit contains is unreproducible by construction; (3) every entry now records **`commit` + `sourceHash`**, which is what makes a baseline checkable rather than merely recorded.
- **Guarded** in `test/perfBudgetPolicy.test.js`: the mechanism is asserted (it must invoke a build, it must check `--porcelain`, the entry must carry commit + sourceHash), not the comment — the comment is what was wrong for weeks.
