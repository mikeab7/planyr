`[x]` **IMPLEMENTED and verified this session.** A new scheduled workflow, `.github/workflows/build-check-sweep.yml` (every 10 minutes + manual `workflow_dispatch`), lists open PRs into `main` and asks GitHub directly (combined commit status + check-runs, both APIs — a required context can be satisfied by either) whether each PR's current head commit has ANY "build" entry at all. A commit with nothing under that name after a 6-minute grace period (long enough that CLAUDE.md's own measured 3–44s normal case is never raced) and with no repair already queued/in-progress is "stuck"; the sweep re-dispatches `build.yml` against that PR's head ref with a new `pr_number` input. `build.yml` itself gained a small tail step (`if: always() && github.event.inputs.pr_number`) that posts a CLASSIC commit status via the Statuses API for that exact PR's head SHA once the gates finish — necessary because a plain `workflow_dispatch` run's own auto-generated check does NOT satisfy a PR's required status (CLAUDE.md's own "Nudge CI" section: only a real push event or an explicit status post does), so this closes that specific, previously-undocumented gap. Idempotent by construction: once any entry exists for "build" on a commit (including one the sweep itself posted), the next sweep pass sees it and does nothing further.
