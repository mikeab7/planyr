### B744 — "Drop site plan" overlay hint sticks after a drag leaves the window; make it non-obscuring `[Site Planner]` (bug) #site-planner #ui  *(owner-dropped 2026-07-09 as "NEW-1"; provisional **B736**, renumbered **B744**; code/tests/commit keep the provisional **B736** label. Branch `claude/site-planner-overlay-bugs-yzkalh`. → V256.)*
`[x]` **IMPLEMENTED + LIVE-VERIFIED (V256 ✅ PASS 2026-07-18, headless synthetic-drag drive) — folded here per the B877 reconciliation rule.** The full-canvas "Drop site plan to place it on the map" drag hint could stay stuck ON after a file was dragged over the canvas and then back OUT of the browser window without dropping; and its light-theme fill was opaque, hiding existing geometry. The highlight is now driven by a dragenter/dragleave DEPTH COUNTER + a window-level reset, and its fill is a translucent accent wash (both themes) so the site stays visible under it.
- Verify: live → **V256 PASS 2026-07-18** (`ui-audit/verify-overlay-dnd.mjs` re-run 11/11 in the running app this session; the only non-drivable bit is the OS's native file-drag gesture, which is a Playwright platform limit, not one of the three named sandbox walls — recorded as driven-and-passed on the confirmable surface).
- **Part B (the real defect):** the canvas wrapper's `onDragLeave` only cleared when `e.currentTarget === e.target` (false whenever the pointer was over the child `<svg>` at exit), and the window guard listened only for `dragover`/`drop` — NO window `dragleave`/reset. An OS-file drag fires no in-page `dragend`, and its final window-exit `dragleave` can target `document`/`body` (outside the wrapper subtree), so nothing cleared the flag → the tan highlight stuck on with nothing under the cursor.
- **Fix (`SitePlanner.jsx`):** (1) both dropzones (canvas wrapper + References panel) use a per-zone dragenter/dragleave DEPTH COUNTER ref — highlight iff depth>0, force depth=0 on drop — robust against the child-crossing flicker, replacing the fragile `currentTarget===target` guard. (2) The window guard `useEffect` gains a `dragleave` listener that hard-resets ALL drag-hover flags + both counters, but ONLY when the drag truly left the window (`relatedTarget==null` **AND** pointer coords at/past a viewport edge), plus the window `drop` handler now also resets. `preventDefault` on dragover (drop stays allowed) + the panel drop's `stopPropagation` are preserved. (3) Part A spirit: the hint fill is now `color-mix(in srgb, <accent> 18%, transparent)` in both themes so geometry shows through; `pointerEvents:none` kept.
- **DEDUPE-FIRST:** distinct from B445 / V131 (which BUILT this affordance) — a GAP in B445's edge-case reset (leave-window), not a regression.
