### B1312 — Nothing recorded when a note was last touched `[Notes]` (feature) #notes  *(filed 2026-07-31 from an owner review of B1290; minted with B1310. DEDUPE-FIRST: no prior item covers note timestamps or a recent view.)*
`[x]` A page node was literally `{ id, title }` — no timestamp anywhere in the module — so the rail could not show "edited 2h ago", there was no sort by recent, and after a few weeks the only way to find yesterday's note was to remember its name.
- Verify: sandbox
- Origin: filed 2026-07-31 from chat (NEW-3)
- `createdAt` / `updatedAt` on the PAGE node only — the tree is read on every render and rewritten on a 400 ms debounce, so it stays titles-and-numbers; two integers per page is the whole cost, and bodies stay out of it as before.
- **`null` is a real value and means UNKNOWN.** Every page written before this honestly has no time; inventing "just now" at upgrade would be a lie the rail repeats forever and would put the oldest notes at the top of Recent. So a migrated page shows no time and sorts last. The migration is additive in both directions.
- **`updatedAt` is stamped on the write that actually LANDED**, not on a keystroke: the editor's flush calls back only when `writePage` returned true, so a page cannot claim it was edited at a moment storage refused to record it (LOUD-FAILURE's quieter cousin).
- Rendering: a relative time on the page row (in the same slot the hover controls use, so a row is never taller for having one), an "Edited 5h ago" line in the page header with the exact moment on hover, and a new **Recent** view in the rail. `lib/notesTime.js` is the one formatter, so the three surfaces cannot disagree.
