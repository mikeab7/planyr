- **THE SENTENCE MODEL.** Every recurrence rule (a "pattern") is now `{ positions: 'every' | number[] (1..5, -1 last, -2 2nd-to-last), weekday, months: 'all' | number[], anchor: null | {position, weekday} }`, rendered as one inline sentence — "Meets the 2nd and 4th Thursday of every month" / "Meets every Wednesday in Jun, Jul and Aug" / "Meets the 1st Tuesday of Nov, counting from after the 1st Monday" — with the varying words as real, keyboard-operable controls: a POSITION multi-pick popover (Every week · 1st..5th · 2nd-to-last · Last, "Every week" exclusive and replacing the old separate Weekly mode), a plain weekday `<select>`, and a MONTHS multi-pick popover (Every month + Jan–Dec, any subset). An optional "counting from after the [position] [weekday]" checkbox generalizes the old Tuesday-after-Monday-only anchor to ANY weekday pair on both sides — positions are counted among the target weekday's occurrences strictly after the computed anchor date within the same month, and an anchor that doesn't exist that month (a "5th Monday" anchor, most months) resolves to nothing for that month rather than crashing. Patterns repeat with no cap via "+ And also…", exactly like today's uncapped "+ Add cadence rule." A warning line reports how many of the next 12 picked-month instances produce no meeting for a fixed position (e.g. a bare 5th-weekday pick).
- **THE RESOLVER is one new primitive, not a parallel engine.** `occurrencesInMonth`/`pickOrdinal` replace the old `nthWeekday`-based `nthWeekdayOfMonth` (now a one-line call onto them) and the retired `nthWeekdayOnOrAfter` fixed-day-of-month hack; `meetingDatesInRange` computes the anchor date via the SAME `nthWeekdayOfMonth` primitive and filters the target weekday's occurrences to those strictly after it — one code path serves both the anchor and non-anchor cases. `positionMissingReport` (the warning line's data) reuses `meetingDatesInRange` itself rather than a second occurrence-walker, so an anchor's own non-existence in a month is already accounted for.
- **MIGRATION IS LOSSLESS, PROVEN, NOT ASSUMED.** A new version-gated pass (`normalizeMeetingCadence` / `migrateRecurrenceRule`, flag `_mbv2` — deliberately NOT the retired `_v9`, which every real schedule already carries `true` and would have silently skipped this) converts every existing body's rules before the dialog or the resolver ever sees them: `freq:"weekly"` → `positions:"every"`; `setpos` → `positions` array (`-1` unchanged); blank `months` → `"all"`; the old Election-Day checkbox (the ONLY anchor shape the UI could ever produce: `weekday:2, onOrAfter:2`) → `anchor:{position:1, weekday:1}` (the 1st Monday), target weekday Tuesday, `positions:[1]`. `effectiveFrom`/`effectiveTo`/`interval` pass through untouched. Proven against the three real named bodies by pinning what OLD MAIN's engine actually resolved (2026–2032) and asserting the migrated body resolves the byte-identical dates: P&Z (84 dates), City Council (168 dates), and the MUD body's two rules (the exact 14-date sequence, including every Election Day from 2026 through 2032) all match exactly.
