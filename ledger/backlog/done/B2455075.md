- **Confirmed broken on main before the fix (the owner's (a)–(f), measured with `ui-audit/verify-spreadsheet-keyboard.mjs` against ff7daf0):** **(a) CONFIRMED, and worse than "does nothing":** with Excel HTML on the OS clipboard, Ctrl+V pasted the *stale internal copy* ("Item/100/Total/200") instead — silently WRONG data (C3 vals=`Item|200|`; C4/C5 the same); with no earlier internal copy it is a silent no-op. **(b) CONFIRMED:** after Ctrl+C the OS clipboard held nothing at all (C1 `types=` empty). **(c) CONFIRMED:** after a reload Ctrl+V pasted nothing (C10 `got=''`). **(d) CONFIRMED:** paste within the sheet kept values and shifted formulas but lost bold/fill/number format (C2 `bold=400`). **(e) CONFIRMED:** no outline after copy (C1b/C7 `had=0`). **(f) CONFIRMED:** Ctrl+X did nothing (C6 `outline=0`, source untouched, the paste inserted the earlier copy).
- **Fix:** native `copy` / `cut` / `paste` EVENTS on the document (no permission prompt) scoped to "the grid owns focus": not while the cell editor, formula bar, name box, find bar or a dialog field has focus (harness C8: native text paste into the editor still works). `SheetView` no longer `preventDefault`s Ctrl+C/V/X. `lib/clipboardIO.js` (pure): copy writes **text/plain** (TSV of displayed values, Excel quoting) AND **text/html** (a styled table — bold/italic/underline/strike/colours/fill/alignment/borders/`mso-number-format`, `colspan` for merges — carrying a `data-planyr-clip` marker with raw text/formulas/styles/formats/merges/source row+col of every cell). Paste order: Planyr marker (formulas relocate by the same `relocateText` rule as before, tiling kept) → any HTML table (Excel/Sheets/Outlook/web: class and inline CSS, `<b>/<i>/<u>/<font>`, `x:fmla` formulas, `x:num` exact numbers, `mso-number-format`, colspan merges) → plain TSV text. A single value fills the whole selection; a block tiles when the selection is a multiple of it; a paste past the last column adds columns; a line of text with commas stays ONE cell. Hidden rows/columns (Ctrl+9 or AutoFilter) are skipped when copying.
- **Cut = move (`pasteMoveSameSheet`):** Ctrl+X marks the range (dashed animated outline — also for copy — until Escape, a new copy, typing into a cell, or the paste); pasting in the same window empties the source (contents, look, merges), writes the block with its formulas VERBATIM, and re-points every formula in the whole workbook (and named ranges) that referred into the block (`lib/formulaMove.js`). A cut pastes once; a second paste of it is a plain copy. **Limits, said plainly:** a cut pasted onto a *different sheet tab* moves the cells but does NOT re-point formulas elsewhere that pointed at them (a visible notice says so); a cut pasted in *another window* acts as a copy (it cannot clear the source there); formulas from a *foreign* HTML table (Excel has no source address) paste exactly as written, not shifted.
- **Menus:** context-menu Cut / Copy / Paste and the palette use the SAME code (menu copy/cut run the browser's own copy/cut so the same event handler fires; menu Paste uses `navigator.clipboard.read()` and, if the browser refuses, shows "press Ctrl+V instead" — never a silent no-op). The internal copy remains ONLY as the fallback for a browser that gives the event no `clipboardData`; if the system write fails a visible notice says pasting inside Planyr still works. An empty/unusable clipboard shows "Nothing to paste" (C9). One undo step per paste or cut-paste (C6).
- **Updated:** the `lib/sheetOps.js` header no longer claims the internal-only scope call; `shortcutsData.js` lists Copy/Cut/Paste with new evidence.
- **Unverified here:** WebKit/Firefox firing `cut`/`copy` on a non-editable focused element (Chromium does, measured); Windows Chrome with a real Excel on the machine — that is V1898578.
