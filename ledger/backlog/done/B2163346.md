### B2163346 — Map/Comps: releasing a handle drag over the map DISARMED the site plan (handles vanished after every resize/rotate/move) — the release's click reached the map's background-deselect `[Site Planner / map overlays]` (bug) #site-planner #map-notes #selection #ui
`[x]` **✅ Done 2026-10-08 — V1578594 PASSED live (build 1bb362a).** Found while running the parked live check V1578593 (B2163345) on planyr.io: after a real mouse corner-drag the overlay was saved correctly (ft/px 3.000 → 3.506) but "Editing on map" went false and the handles' `<svg>` was `display:none` for the next 45 s — the plan had been de-armed. **Cause:** `MapFinder`'s map-level `click` handler treats any unclaimed click as "background: deselect the armed plan" (only the image's OWN click stops propagation, B848496 NEW-2). A drag that starts on a grip and ends over the map makes the browser dispatch a `click` to the common ancestor — the map — so every handle release disarmed the plan. Not caused by NEW-2 (those lines are untouched); it did defeat NEW-2's own acceptance ("handles stay on the visible region after a resize").
**Fix:** `lib/handleGestureClock.js` — the handles stamp the release (`markGestureEnd`, in `runGesture`'s `onUp`, covering move/scale/rotate); the map's background click ignores a click within 400 ms of it (`gestureJustEnded`). A genuine background click later still deselects. `test/handleGestureClock.test.js` (clock + wiring). RED on main: `ui-audit/verify-map-overlay-crop-handles.mjs` fails its post-drag checks there (handles never re-armed in 45 s; `post-scale diag: editingOnMap:false, svgDisplay:none`).
**Stopping rule:** closes on a dated PASS of V1578594 (the harness's scale + rotate checks pass with no re-arming); a plan that disarms on release re-opens it.
**Live pass 2026-10-08, planyr.io build `1bb362a`:** after a real corner drag and after a real rotate drag the handles were still armed with no re-arming (`post-scale diag: editingOnMap:true, svgDisplay:""`, handles back after 0 s); the same harness on `c0ca458` (before the fix) reported `editingOnMap:false, svgDisplay:none`, handles never back in 45 s. Disposition (STANDING RULE #2 does not apply — found by this session, not owner-reported): reproduced and fixed. Open question left honest: the harness drives the mouse through the browser driver; a real human's release produces the same browser click, so the same disarm is expected on any real drag, but that was not observed on Michael's own machine.
