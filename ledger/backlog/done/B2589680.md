`[ ]` **⏳ merged — V2038736 PENDING (Verify: live — PDF/export parity).** Owner asked why Aerial is an option in the print panel. It was never a print-only setting: the checkbox wrote the plan-level `showAerial`, the same value the map's View menu and the Overlays panel use, so it only duplicated the map control. **Removed the "Aerial" row from "On the plan" entirely** (`components/PrintCompose.jsx`; props `aerialAvailable` / `showAerial` / `onToggleAerial` deleted from the component and from its caller in `SitePlanner.jsx`, along with the `aerialAvailable` const). The exhibit now prints the aerial exactly when the map is showing it when print is opened — same rule as Map layers and Overlay ("exactly as shown"). **Snapshot/restore:** `preCanvasDisplayRef` no longer carries `showAerial` (and `cancelPrint` no longer restores it) — its only reason was undoing the panel's own toggle; the panel can no longer change it, so restoring would only ever revert a deliberate change made on the map, and the dims/areas snapshot keeps working unchanged. `showAerial` stays in the compose preview's `composeKey` (the preview must follow the map's state). **⚠ CORRECTION found by the live check (V2038736, 2026-11-02, build 04665c2): the brief's premise was wrong — the export did NOT follow the map.** `exportSheet.js` deliberately "always included the aerial (even if it's hidden on screen)" and never read `showAerial` (`exportCtx` passed `basemapOn`, not `showAerial`), so on a located plan the old Aerial checkbox — and hiding the aerial on the map — never reached the PDF at all: a plan with `settings.aerialHidden` printed the same photographic sheet as one without (measured: identical PDFs, non-paper share 1.00 both). With the row gone and the export unchanged there would have been NO way to print without the aerial, so the export now follows the map as the brief's rule ("prints the aerial exactly when the map is showing it") and acceptance step ("hidden on the map → the PDF omits it") require: `aerialVisibility.aerialWantedOnSheet(showAerial)` gates BOTH export seams (`exportAerialForFrame` fetches/stitches nothing; `buildExportSvgRaw` draws neither the live capture nor the pinned map snapshot), `exportCtx` passes the live `showAerial` (default shown for any other caller). **This IS a change to what the PDF renders for one map state — aerial hidden on the map now prints without it (it used to print with it)**; aerial showing is unchanged.
