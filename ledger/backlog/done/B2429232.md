### B2429232 — Schedule / project switcher stays open while clicking grid cells: a press inside the embedded Schedule grid now dismisses every shell dropdown `[Schedule · shared menus]` (bug) #scheduler #ui
- Verify: live (V1862176) — PASSED 2026-10-22 on build 9545da8, signed in as the test account, real mouse presses.
- Owner report (chat block NEW-1): open the schedule switcher ("PII ▾"), click Successor / Status / Notes cells — the switcher stays open over the grid. Expected: any outside click closes it AND still selects the cell; Escape closes it; clicking inside the switcher (rows, kebabs, New schedule) does not close it early.
- **Root cause (measured, not the guessed one):** the Schedule grid is the embedded `/sequence/` app in an **iframe**. A press inside a frame never reaches the parent document, so `AnchoredMenu`'s document-level `mousedown` listener (B1106256) could not see it; it is not about cells stopping propagation (the shell's listener is capture-phase and unaffected by that). Escape typed with focus in the frame never reached the shell either.
- **Fix, once, in the shared component:** `src/shared/ui/AnchoredMenu.jsx` closes an open menu on (a) a same-origin `planar-seq` `planar:press` / `planar:escape` notice and (b) the window losing focus to an `<iframe>` (belt-and-braces; Chromium headless never fires it). `public/sequence/index.html` posts the notice from a window-capture `pointerdown` / Escape `keydown` — a notice only, nothing is stopped or swallowed, so the cell still takes its click. Shell-side behaviour unchanged: outside click, Escape, hashchange (tab switch), opening another menu, and presses inside the panel / the kebab's own menu (`pressBelongsToHigherMenu`) all as before.
- **Adjacent cases, reported:** schedule switcher — reproduced (red on current main). Project switcher ("Goose Creek ▾") — same component; the same spec is red for press + Escape on current main, green with the fix. Kebab menu inside the switcher — nested `AnchoredMenu`, covered by the same listener; a press inside it still doesn't close the parent (existing `pressBelongsToHigherMenu`). Site / Review / Library — no iframe, they use the same document listener, which works (not reproduced; fixed by construction for any future iframe too). The grid's own in-frame popovers (status, owner picker, column menus) are bubble-phase `document` listeners inside the frame; only the group fold toggle stops `mousedown` (deliberately, B463922) — not driven individually this session.
- Guard: `e2e/menu-closes-on-iframe-press.spec.js` (6 tests: press + Escape inside the frame, Escape in the shell and press inside the panel, for both switchers) — 4 red on the unfixed build, all 6 green with the fix. The press is dispatched from inside the frame because the shell can cover the frame with its own loader in the sandbox.
- Stopping rule: closes on the dated PASS of V1862176.
