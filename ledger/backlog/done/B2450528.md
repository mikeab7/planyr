- **Root cause (measured, not re-derived):** `model_sheets.data` is jsonb, which re-orders object keys (length, then bytewise); the device copy keeps typing order; `sheetsDiverge` was a raw `JSON.stringify` compare, so IDENTICAL content read as different and the red bar froze every cloud push. Second gap: no record of which cloud version a device copy was BASED ON or whether it held unsynced edits, so "this device is just old" could not be told from "this device has unsaved work".
- **Fix:** (1) `sheetModel.canonicalJson` + `sheetsDiverge` compare with sorted keys (arrays keep their order); (2) the device keeps a sibling record `planyr:model:sheet:meta:v1:<scope>:<id>` = `{ baseVersion, dirty }` (`modelStore.readSyncMeta/writeSyncMeta`) — set clean on every load-adopt and every successful push, dirty on every PERSON'S edit (commit/undo/redo only; a load's `reset` never marks dirty); (3) the one decision `modelSyncBase.decideLoadSync`: equal → in-sync · local clean → adopt the cloud silently · dirty and the cloud has not moved past the base → push local silently · dirty AND the cloud moved → the bar (the only case left) · legacy copy with no record: equal → record base; differs and untouched blank → adopt cloud; otherwise a one-time bar. (4) A never-edited placeholder (`isPlaceholderWorkbook`) can never win or raise the bar, and — new — the push now uploads only real unsynced work AFTER the cloud has answered, so a plain reload no longer bumps the cloud version and a blank placeholder no longer creates a row (constraint 5, lazy creation). All three load paths share it: project sheets, org workbooks (same effect, `storageKey`), and the signed-out → signed-in adoption (`diverges` now also ignores an untouched placeholder). The bar's two buttons record the new base. CAS-conflict guard during saves untouched.
- **Adjacent checks (reported):** `notesStore.js:2098` compares two LOCAL IndexedDB version rows; `storage.js:1088` compares localStorage ring vs IndexedDB; `SitePlanner.jsx:5336` compares a cross-tab localStorage merge — none of the sides is a jsonb column, so no change. Library file mode (`useFileWorkbook.js`) has no cloud-vs-device compare at all (the file's bytes are the one copy; `fileDraft` is a safety copy keyed by the source id). Notes' base-tracking idea is reused in spirit; no second mechanism.
