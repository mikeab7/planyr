### B581 — Print/PDF export: plan line work bakes in too thick (cartoonish) `[Site Planner / export]` (bug)  *(owner-dropped 2026-06-29 — "the line work is all sorts of fucked up, way too thick… makes it look unprofessional"; minted **B581** = highest real B# across both files (B580) + 1; branch `claude/drawing-export-quality-6dl678`)*
`[x]` **DONE + headless-verified the same session (`verify-export-quality.mjs`: building object line = 0.60 pt on paper, thinned from authored 2 px).** Root cause: element strokes are authored in SCREEN pixels for the live canvas (building/parcel/pond weight 2, surfaces 1.25, parking/dock striping 0.5–0.75). When the plan SVG is cloned and nested into the sheet, those pixel weights are scaled by the sheet's "meet" fit transform — a factor that DEPENDS on the zoom the user was at when they hit print — so line work baked in heavy and inconsistent.
- **Fix:** a pure `lib/exportStyle.js` (`printStrokeWidth` + `sheetFitScale`) retargets every stroke to a real PHYSICAL drafting weight (object line → **0.6 pt**, hierarchy preserved, floored at 0.32 pt so striping never disappears, capped at 1.5 pt), **independent of zoom**. Applied at export by `restyleExportClone` (walks the clone, skips the `data-furniture` group, scales stroke-width + inline-style stroke + dasharray). Both PDF and PNG use it (PNG against a notional letter-landscape sheet so it matches the PDF). 9 unit tests in `test/exportStyle.test.js` (zoom-independence, hierarchy, floor, cap).
- **Files:** `src/workspaces/site-planner/lib/exportStyle.js` (new), `src/workspaces/site-planner/SitePlanner.jsx` (`restyleExportClone`, wired into `exportPDF`/`exportPNG`), `test/exportStyle.test.js`.
