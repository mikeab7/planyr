### B242 — On-building "＋ / −" controls for the whole dock stack + uniform panel rows `[Site Planner]` (feature)  *(owner-reported, chat — "bring my plus buttons back to the building… plus and minus next to each other for every one of them, except the bump-outs." `[x]` **Done 2026-06-20 (branch `claude/practical-faraday-9mmfch`).** The owner's model: the building is the hub and every dock-side piece is part of it, so the add/remove controls belong **on the building, on the map** — and he was "missing the plus buttons" because the old on-canvas dock node was a single toggle that flipped to a lone "−" once a court existed (the "＋" to add the *next* zone had moved onto the sub-pieces). **Fix (`SitePlanner.jsx`):**
- **On-canvas "＋ / −" PAIRS on the building** (new `featPair` + `glyphPlus`/`glyphMinus`, replacing the single-toggle `featNode` for these). Each **dock side** gets a pair that walks the zone stack **out/in** (＋ = next outward zone court → trailer parking → buffer; − = remove the outer zone), **per side** (independent — never the old "stuck adding courts" problem). Each **non-dock side** (short ends, and the long side opposite single-load docks) gets a **car-parking ＋ / −**. Each **dock corner** keeps a single **bump-out** toggle — the one exception the owner called out ("you only add one thing there"). The old `courtAddNodes` / `trailerAddNodes` far-edge nodes are removed (folded into the dock-side pair). Still gated by `FEAT_BTN_MIN_PX` (B225) so they never cluster when zoomed out, and shown for the selected/hovered building (B226).
- **Building-level controls are now per-side too:** `addDockZone` / `removeOuterDockZone` grow / shrink **every** dock side by one ring (each side adds/removes its own next/outer zone), so an uneven building is never stuck.
- **Uniform panel rows:** the Dock-features panel now lists **Dock zones / Car parking / Bump-outs**, each a label + a consistent square **＋ / −** pair aligned right (bump-outs: ＋, plus − only when present) — fixes the "different sizes / odd layout."
