- Verify: sandbox
- Origin: filed 2026-07-29 from chat
- **The report.** planyr.io had served `assets/index-iy2BZyRK.js` unchanged since before #852 merged — same hash, same 507,528 bytes, sampled at 19:04, 19:20, 19:42 and 21:24 with `cache:'no-store'` — and that bundle does not contain `p_atomic`. Read as ~2.5 h with no build, i.e. the automation-token hiccup again.
- **AUDIT-FIRST — the deploy had happened. The METHOD was wrong, in two independent ways.** **(a)** Vite content-hashes **every chunk separately**, so the entry chunk's hash is UNCHANGED across a deploy whenever its own bytes didn't change. A stable index hash is evidence of **nothing**. **(b)** `p_atomic` lives in `lib/elementApi.js`, which is part of the **lazy `SitePlannerApp-*.js`** chunk — it was never going to appear in `index-*.js` on any build, deployed or not. Walking the real module graph found it immediately: **`p_atomic` IS SERVED, in `assets/SitePlannerApp-C4rK_NtZ.js`**, alongside `noteLocalAuthority`, `onRowsCanonical` and the "This tab is out of date" copy. `src/` at the verifying HEAD is byte-identical to the deployed `678d58d`.
- **Also worth stating, because it was the proposed remedy:** a GitHub Actions nudge could not have fixed this even if it had been a real stall. Cloudflare Pages deploys through **its own GitHub App connection** (`CLAUDE.md`: "there is no Cloudflare workflow file in this repo"); the `Build` workflow is only the PR status check and publishes nothing. Nudging Actions has no effect on whether Pages builds.
- **Fix — a script, because a markdown warning would rot.** `ui-audit/verify-deploy.mjs [--origin=…] [--json] <marker…>` walks index.html → entry chunk → every hashed chunk the entry names, reports which chunk carries each marker, and exits non-zero if any is absent. It also warns, on a miss, that the marker may simply be **minify-unsafe** — a local function name like `closeAssemblies` is renamed by the build and can never be found, which is the same false negative in a new costume. `VERIFICATION.md`'s self-verification section now carries the procedure and the one-line rule: **a green build check and the served bytes are different claims; only report "deployed" off the bytes.**
- **Evidence.** Run live against production this session: 20 chunks walked, all four markers found, exit 0. The pre-fix hand method (grep the entry chunk for `p_atomic`) returns a false negative on the same, correctly-deployed origin — which is what makes the script a guard rather than a convenience.
