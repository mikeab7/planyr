`[x]` **FIXED THIS SESSION.** **route.js** — bare `"#/"` is now reserved for a real Dashboard destination (`isDashboardRoute`, read straight off the raw hash the same way `isAdminRoute`/`isDesignRoute` already are — never through `route.module`, which can't tell "the Dashboard" apart from "site-planner, no project"). `buildHash` no longer special-cases the default module to the bare `"#/"` home — every project-less module, site-planner included, now gets its own named slug (`"#/site"`), which is what makes the Dashboard a genuinely distinct place rather than an alias. **`navigate()`** (inside `useHashRoute`) now compares the literal HASH STRING it's about to write against the current one, not the parsed route shape — the old `sameRoute`-based check made leaving `#/admin`/`#/design`/the Dashboard for "the same-looking" project-less route a silent no-op (this is the exact mechanism behind the measured `#/design` exit bug fixed in the same commit). **Shell.jsx** — `goDashboard` now sets the hash directly to `"#/"` (bypassing `navigate`'s module-merge shape, which the Dashboard isn't a value of); `active` (which drives every workspace's `isActive` prop) is `null` while on the Dashboard, so no module tab highlights and a fresh Dashboard boot mounts no workspace chunk at all; the Dashboard itself renders as a genuinely conditional block (`{isDashboardHash && ...}`), unmounting the instant you leave rather than staying kept-alive like the six workspaces (fresh data on every visit — see **B1213313**). **`isAdminHash`/`isDesignHash`/`isDashboardHash`** were rewritten from `useState` + a `useEffect` keyed on `[route]` to plain synchronous consts computed straight from `window.location.hash` on every render — the old shape lagged one render pass behind `route` itself (see `test/dashboardHashSync.test.js`'s header for the exact mechanism), and because `active` now depends on `isDashboardHash`, that one-render lag reopened the exact B881664-class bounce this item exists to close: measured live, clicking the wordmark from Schedule produced `#/schedule → #/ → #/site`, 55ms apart, before this fix. **`lastRoute.js`** — `isWorthRestoring` dropped its `DEFAULT_MODULE → true` special case (which relied on the old "bare `#/` is a no-op for site-planner" assumption, no longer true), so a stored "site-planner, no project" pointer no longer force-redirects a fresh Dashboard boot away from the Dashboard. **The one bug this item's own fix required, found live rather than assumed:** neither `SitePlannerApp.jsx` nor `SitePlanner.jsx` had ever wired the Shell's `onGoDashboard` prop into their own `AppHeader`'s wordmark at all (`onDashboard` there was always the workspace's own `goMap`/`onBackToMap`, matching the crumb) — so the wordmark from inside the Site Planner (in or out of a project) still cleared the project and stayed on the map, never reaching the real Dashboard. Fixed the same way **B1128272** already fixed this split for Schedule: `onLogoDashboard={onGoDashboard}` added alongside the existing `onDashboard`, threading a new `onGoDashboard` prop through `SitePlannerApp` → `SitePlanner`. Schedule's own wordmark tooltip ("Leave Schedule — go to the Site Planner map") was reworded to say "go to the Dashboard", since that's what it now does.
