`[x]` **Root cause of the banner defect: `UpdateBanner` (`src/app/Shell.jsx`) held a single non-wrapping flex ROW** — message `<span flex:1 minWidth:0>` beside two `flex:"0 0 auto"` buttons that never shrink. At a ~390px phone width the buttons ate most of the row and left the message a sliver, wrapping "A newer version of Planyr is available…" into as many as 12 lines of one-or-two words each (measured on the actual pre-fix build). **Fix: the banner stacks at narrow widths** — message on its own line, Reload/Dismiss in a row beneath — reusing the SAME 760px `matchMedia` breakpoint (`useNarrow`) `AppHeader.jsx`/`Notes.jsx`/`FoodMap.jsx` already standardize on, as a LOCAL copy rather than an import (importing `AppHeader.jsx` into `Shell.jsx`'s entry chunk would pull in `ProjectBreadcrumb`/`CloudSyncBadge`/`AnchoredMenu`/`BrandMark`/`InterfaceSettings` and more onto every route — `FoodMap.jsx`'s own `useCoarsePointer` documents the identical bundle-weight tradeoff). A first cut only switched `flexDirection` and regressed WORSE (165px-wide, 4-line message — the container shrink-wraps to content unless told to actually fill FloatingNotice's own width budget); the shipped fix additionally sets `width` to the SAME `min(480px, calc(100vw - 16px))` value the `FloatingNotice` wrapper already caps at, which is what actually claims the room (message now wraps to 2 lines at 390px, matching desktop's own 2-line wrap at 344px vs 299px measured width). The deliberate FloatingNotice overlap tradeoff the component's own header comment documents (a bottom-centered card that CAN cover a strip of content, acceptable only because it stays dismissible/actionable) is untouched — this is purely the card's own internal layout.

`[x]` **Added a cheap, baseline-image-free structural gate (`ui-audit/lib/narrowWidthAudit.mjs`) that catches this whole DEFECT CLASS, not just this one banner — this is the check that actually closes the gap, not the pixel baselines above.** At the phone viewport: (a) no visible element whose OWN text reads as a sentence/phrase (`SENTENCE_MIN_CHARS=20` — chosen so short real UI labels like "Select parcels" never qualify, but the shortest real banner/notice sentence in this app, 40+ chars, always does) may render in a content box narrower than `PHONE_MIN_CONTENT_WIDTH=120`px (MEASURED: the broken banner's message box was 56.9px wide/12 lines; the fixed one is 299–344px/2 lines — 120 sits with real margin on both sides of that gap, more than 2× the broken width and comfortably under both correct renderings, at this app's own 11.5–14px UI font sizes enough room for 2-3 short words so a sentence never degenerates into a single-word ladder); elements that never wrap (`white-space: nowrap`/`pre` — the sanctioned single-line-ellipsis truncation pattern, e.g. `MiddleTruncate.jsx`) are excluded, since a narrow box holding a TRUNCATED string is a different, intentional pattern, not this defect.
