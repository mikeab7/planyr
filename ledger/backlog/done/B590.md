- **HIGH — a non-finite numeric value leaked out as a successful result.** `1e309`, `SUM(1e308,1e308)`, `TRUNC(0,1e16)` etc. returned `{ok:true, Infinity/NaN}` (and `1e309 > 5` a silent `TRUE`) instead of `#NUM!` — the `^`/`POWER`/`+−×÷` guards didn't cover literals, aggregations, or the single-arg maths. **Fix (engine):** reject a non-finite number literal at the tokenizer (so an overflow can't even reach a comparison/label), finite-check every numeric function result at the call boundary (`evalCall`), and backstop the contract in `evaluateFormula`.
- **HIGH — `MROUND` rounded the half toward zero (float drift).** `MROUND(6.05,0.1)` showed `6.0` not `6.1` (6.05/0.1 floats to 60.4999…). **Fix:** `Math.round(n/m + 1e-9)·m` — half-away-from-zero with the same epsilon discipline `ROUNDUP`/`ROUNDDOWN` use.
- **MED-HIGH — `FLOOR`/`CEILING` to a fractional step landed a whole step off.** `FLOOR(2.4,0.1)` showed `2.3` (2.4/0.1 floats to 23.999). **Fix:** ±1e-9 on the quotient (`Math.floor(n/sig+1e-9)`, `Math.ceil(n/sig−1e-9)`).
- **MED — a giant operator chain gave a non-deterministic result.** A multi-thousand-term `a+b+c+…` (iterative parse, recursive eval) overflowed the JS stack or not depending on the ambient call depth — the SAME input could return `#ERROR!` or a value. **Fix:** a `MAX_TOKENS = 1000` cap rejects an over-large formula up front (far above any real formula, far below the overflow boundary), so the verdict is input-determined.
- **MED — `TEXT()` mishandled `;`-separated sections** (accounting formats). `TEXT(-1234.5,"#,##0.00;(#,##0.00)")` gave `-1,234.50000000` (8 decimals + a stray `-`) — the decimal count scanned across the `;` boundary and there was no section selection or literal-text emission. **Fix:** split on top-level `;`, pick the section by sign (positive;negative;zero), count placeholders within the chosen section only, and emit the section's literal text (`(`, `)`, `$`, `%`) in place → `(1,234.50)`. Single-section formats unchanged.
- **LOW-MED — a column named with `[` or `]` was unreferenceable** (`Cost [USD]` → a `[Cost [USD]]` reference tokenizes to the truncated `Cost [USD` + a stray `]` → `#ERROR!`). **Fix (host, `FormulaColumnEditor`):** reject `[`/`]` in a column name with an inline "Name can't contain [ or ]".
- **Confirmed clean / deliberate (no change):** within-formula error propagation is correct (`SUM(1,1/0)`→`#DIV/0!`; `AND`/`OR`/`&`/comparisons propagate; `IFERROR`/`IFNA`/`ISERR` trap correctly); `2^3^2 = 64` is Excel's left-assoc `^`; cross-COLUMN aggregation **skips** an errored cell (stored BLANK) rather than propagating — a deliberate host choice (one bad row shouldn't blank a whole roll-up), flagged for the owner as an optional skip-vs-propagate decision, not changed; renaming a referenced column → `#REF!` is a visible-error v1 limitation (rename-propagation deferred).
