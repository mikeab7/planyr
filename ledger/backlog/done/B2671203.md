### B2671203 — The Spreadsheet crashes ("Spreadsheet hit an error and couldn't load") on a project-less route such as `#/spreadsheet` `[Spreadsheet / Model · crash]` (bug) #model #testing
*(found 2026-11-09 by the signed-in live check for B329408 — on UNMODIFIED production build 6c580b3 and on a local build of main. DEDUPE-FIRST: searched Open/Verify/Done for `primeCalcCache`, `reading 'then'`, `Spreadsheet hit an error` — no match.)*
✅ **Done 2026-11-09** — shipped in mikeab7/planyr#2896 (merge 74168be); live-verified signed in on planyr.io build 74168be (V2115868 step 6): a project's Spreadsheet AND the bare `#/spreadsheet` route render with no error card (the same route showed the error card on the pre-merge production build 6c580b3).
- Verify: sandbox (unit test `test/modelNoScopeNoCrash.test.js` + the signed-in live check V2115868 step 6 opens a real project's Spreadsheet; the bare route is asserted by the same test).
- **Symptom.** Opening the bare Spreadsheet URL (`https://planyr.io/#/spreadsheet`, no project) showed the workspace error boundary: *TypeError: Cannot read properties of null (reading 'then') at ModelApp*. Reproduced on production and on a local build of main, signed in and signed out.
- **Cause.** `ModelApp.jsx` ran `primeCalcCache(viewPrefsKey).then(done, done)`; `primeCalcCache(viewKey)` returns `null` when there is no scope key (`if (!viewKey) return null`, `univerCalcCache.js`), so a route with no project/workbook/file scope threw inside an effect and took the whole workspace down.
- **Fix.** `Promise.resolve(primeCalcCache(viewPrefsKey)).then(done, done)` — a null settles at once and the timer path is unchanged. No behaviour change when a scope exists. Shipped in mikeab7/planyr#2896 (found while verifying that PR; kept with it because the live check for the lazy-chunk work has to open the Spreadsheet).
- **Stopping rule:** closes when V2115868 step 6 (a project's Spreadsheet renders) passes on the deployed build and the bare `#/spreadsheet` route renders its "pick a project" state rather than the error card.
