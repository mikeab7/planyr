### B2249169 — A press that starts on a building's label (SF label) did not drag the building — label now hands the press to its element `[Site Planner]` (bug) #site-planner #selection #ui
`[x]` Done 2026-10-11 (branch `claude/great-ritchie-folkxl`; owner chat block, NEW-2). DEDUPE-FIRST: the label's pointer handler is the click-ownership audit's NEW-1 (2026-09-12) — it made EVERY element's label pointer-enabled so a click/double-click resolves to its own element, but it only SELECTED on press and stopped the event, so nothing armed a move. This is the missing half of that item (select + double-click + right-click were covered, drag was not), not a recurrence of a closed report.
- Verify: sandbox — red-proof e2e below. Post-deploy: signed-in drag-from-label check on planyr.io (test account), recorded on the PR.
- **Root cause (read from code, confirmed by red run):** `SitePlanner.jsx` label `<g onPointerDown>` did `stopPropagation` + `setSel` and returned. The label paints above its element and is hit-test-first, so the element body's `startMoveEl` never saw the press.
- **Fix:** the label now calls the element's own `startMoveEl(e, id)` — one handler, so single click selects, drag moves (same history gate, assembly members, group / multi-select / lock / phone-pan rules), double-click opens Properties. Grouped/locked elements keep pairing their double-tap in the label (startMoveEl does not pair one for them), every other element pairs inside `startMoveEl` — never both, so the pair is not eaten.
- **Siblings (audited, the label pass is one generic loop so one fix covers every type that HAS a label):** building · rotated building · building with bump-outs · trailer-parking row · pond — each proven. Parking fields, truck courts and roads have **no on-canvas label** (`NO_LABEL`), so there is nothing to press; road inline labels, easement inline labels and dimension numbers have their own deliberate handlers (the easement label's own press already drags the label; the dimension number is an inline editor) and are NOT this defect. Parcel acreage chip already drags (B1327/NEW-4).
- **Red-proof:** `e2e/label-press-drags-element.spec.js` — each case first drags the BODY (known-good arm; run is VOID if it does not move), then drags from the LABEL unselected, then from the label selected. On main: 5/5 label cases fail ("label drag (unselected) moved nothing") + the bump-wording case; with the fix 6/6 pass. A plain click and a double-click on the label move nothing.
- **Regression:** `ui-audit/audit-doubleclick-properties.mjs --labels` 266/266 and `--labels --locked` 169/169 (double-click on a label still opens Properties; locked still selects only); `labelLayout`/`labelFitLadder`/`viewCull`/`siteMetrics`/`dogEar` unit suites 106/106. `ui-audit/verify-click-ownership.mjs` crashes in a parcel-vertex step (`rectCenter`) identically on untouched main — pre-existing, unrelated, not changed here. Older `e2e/chrome-swallows-press.spec.js` lands on the dashboard (`goto("/")`) and fails identically on main.
- Not zoom-specific by construction (no geometry in the fix); the e2e runs at the plan's fit zoom.
