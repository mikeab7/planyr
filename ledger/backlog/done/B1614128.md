### B1614128 — The Standards → Buildings pointer (and per-building clear-height/slab override) never reached a freehand building `[Site Planner]` (bug) #site-planner #ui  *(owner report, dispatched as "NEW-1": B1631632/B1631633 shipped the BUILDINGS — PROGRAM editor and its Properties-panel pointer line, verified live on production for a DRAGGED-RECTANGLE building — but with a hand-click-drawn (freehand) building selected, the Properties panel's last line was still only "New building elements start from Standards → Colors," with no pointer to Standards → Buildings and no clear-height/slab fields at all. Minted **B1614128** from this branch's reserved block B1614128–B1614143 against freshly-fetched `origin/main` 9574c0a. DEDUPE-FIRST — searched Open/⏳Verify/Done/Done-archive for "Standards → Buildings", "freehand", "Polygon · N points", "footEdit" + "isBuilding": B1631633 shipped and verified the pointer for a rectangle building only (its own harness seeded three plain `{w,h}` buildings, never a `points`-only one) — this is a real, narrower gap that survived that verification, not a duplicate report of the same symptom on the same case. Net-new.)*

`[x]` **AUDIT-FIRST — root cause, found by reading the gate, not by guessing.** `SitePlanner.jsx`'s selected-element Properties panel routes to the whole grouped building inspector (Footprint · Loading · Structure · Column grid · Placement, plus the B1631633 pointer line) behind one outer condition: `(!selEl.points || selEl.footEdit) ? <the grouped inspector, incl. isBuilding(selEl)> : <generic "Polygon · N points" fallback>`. A **freehand** building — drawn by clicking corner points (`closeElPoly`, `SitePlanner.jsx`) — is created as `{ id, type: "building", points, rot: 0 }`: it carries `points` but never `footEdit`, `w`, `h`, or `cx`/`cy` (those belong only to a plain rectangle or a **reshaped** rectangle, `footEdit: points + a dock frame`, B872). So `!selEl.points` is false and `selEl.footEdit` is false — the freehand building never satisfies the gate and falls straight to the generic polygon fallback, which has no Structure fields and no pointer line. The building's SF-driven printed CLEAR/SLAB values were never affected (`buildingSqft`/`buildingRows` already compute real polygon area for any shape via `polyArea(el.points)`), which is exactly why the exhibit and the Properties panel disagreed.
- The ticket's "consider whether the gate is on a building KIND" was the right question, but the actual defect is narrower than a building-kind check: `footprintLength`/`footprintDepth` (needed by the Footprint/Loading/Column-grid sections) index `el.w`/`el.h`, which a freehand building simply doesn't have — extending the WHOLE grouped inspector (dock zones, a wall-based structural grid) to a shape with no wall/axis concept would either need new bounding-box plumbing for every one of those sections or silently break them (`NaN` fields, dock-zone buttons enabled over geometry with nothing to dock to). Scoped the fix to what the ticket actually needs and what already works correctly for any shape: clear height/slab (`effectiveBuildingProps` only needs `sf`, not `w`/`h`) and the pointer line.

`[x]` **THE FIX.** A new block, gated on `isBuilding(selEl) && selEl.points && !selEl.footEdit` (i.e. exactly the freehand case the outer gate excludes), renders right after the generic "Polygon · N points" description: a **Structure** group with Clear height (ft)/Slab (in) fields — auto value + "set ↺" override, identical mechanism (`effectiveBuildingProps`, `clearHeightOverride`/`slabThicknessOverride`) to the rectangle-building path — followed by the pointer line, worded "This building's clear height & slab start from **Standards → Buildings ↗**" (the "column grid" clause is deliberately dropped for this case — a freehand outline has no wall to hang a grid on, and the Column grid section stays out here on purpose, so the pointer never promises a control that isn't on the panel). Column grid + the dock-frame Loading UI are unchanged and still don't apply to a freehand building — not a regression, the same as before this fix; only the Structure fields + pointer were missing.
- **Per-building override reachability, settled (the ticket's second ask):** the fix itself makes it reachable — a freehand building's Clear height/Slab fields now show "auto" or "set ↺" exactly like a rectangle building's, and setting/reverting an override works and persists (checked live below). It was ALREADY reachable on a plain rectangle and a reshaped (`footEdit`) building before this fix — both already satisfied the outer gate and always had the Structure section; only the freehand case was missing it.
- **"Save for all projects" carrying into a brand-new project, settled in code (the ticket's third ask, not tested against the owner's real account, per his own instruction not to touch it from a throwaway test):** `SitePlanner.jsx` resolves `buildingRules = normalizeRules(settings.buildingRules ?? getStandardPref(userPrefs, "buildingStyle", "rules"))` — a plan with no `settings.buildingRules` of its own (a brand-new project) falls back to the account-wide tier table, and `saveStdForAllProjects`'s own comment states the intent verbatim: "whatever this plan currently shows is what a brand-new project starts with." Confirmed **live, headless** (not just read): `ui-audit/verify-building-program-standards.mjs` section H seeds the account mirror + a never-before-seen project and the fresh project's first clear-height tier reads the seeded account value back correctly.

`[x]` **CHECKED live in a real headless Chromium against the built app** (`ui-audit/verify-building-program-standards.mjs`, extended with a fourth seeded building — a genuine 5-point freehand polygon, `points` only, no `w`/`h`/`cx`/`cy`, created exactly the way `closeElPoly` creates one — and a new section F2, 12 checks, all green): the freehand building's Properties panel confirms it's reading a real polygon ("Polygon · 5 points"), shows the correct auto clear height/slab for its actual polygon area (50,000 SF → 32′/6″, same tier as the rectangle case), shows the "Standards → Buildings" pointer line, and the pointer's own jump opens Standards with "Buildings — program" expanded — the same live functional check section F already runs for a rectangle building.
