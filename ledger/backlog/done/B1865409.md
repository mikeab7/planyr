`[x]` **AUDIT-FIRST — found the real defect by reading the component's own layout, since the dispatch gave no repro.** `ConflictNotice.jsx`'s one-line banner (`role="alert"`) interpolates the note's TITLE straight into its message (`"<title>" also changed…`) inside a flex row (`display:flex, flexWrap:"wrap"`). The message `<span>` had `flex: "1 1 220px"` but **no `minWidth: 0`** — a flex item's default `min-width` is `auto`, which floors it at its own content's min-content size, and for a title with no spaces at all (a compound project code, a pasted filename, a long unbroken string) that min-content size is the WHOLE title, since a browser only wraps at whitespace by default. This banner sits ABOVE the two-pane rail/editor layout as a plain child of the outer flex COLUMN (`Notes.jsx`), which has no cross-axis clipping — so a wide-enough unbroken title does not stay contained to the small bar, it widens the whole row and can force the entire workspace to scroll sideways. `flexWrap: "wrap"` alone does not fix this: wrapping moves the span to its own line, it does not shrink it.
`[x]` **FIXED — the span now gets `minWidth: 0` (lets it shrink below its content's natural width) plus `overflowWrap: "break-word"` / `wordBreak: "break-word"` (lets it wrap even a single long word), and the outer alert row also gets `minWidth: 0`** (the same missing floor-override one level up — a flex item in a column still needs it to avoid being held to its content's width by the container's default `align-items: stretch`). This keeps the file's own stated design intent (its header: "wraps onto a second line… rather than truncating — a notice this short can afford two lines; it cannot afford hiding its own message") for a title with NO spaces, not only one with them — nothing is truncated or hidden, the message still names the real title in full.
