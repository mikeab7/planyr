- **Root cause of the wrong value:** `editor.getAttributes()`/`editor.isActive()` answer "what is at ONE position" (the selection's `$from`) — exactly right for a caret, silently wrong for a range that can honestly disagree with itself. A 24/18/9px selection showed "24", the first block's size, presented as the whole selection's; an H2 + two paragraphs read "Body text" the same way.
- **The fix, `lib/notesMixedSelection.js` (PURE, unit-tested):** `selectionFontSizes`/`selectionBlockShapes` walk every text run / textblock the selection touches; `uniformValue` returns the shared value or a `MIXED` sentinel the moment two disagree; `formatDisplayValue` still trusts the caret's own read for a collapsed selection (rule 1 in `NoteToolbar.jsx`'s own header — active state comes from the editor, never a mirrored copy) and only asks the range question for a real range. A mixed selection now shows no value, matching Line spacing's existing convention; a uniform selection still shows its real value (unlike Line spacing, which is always blank — Font size's whole point per B1371 is to be readable at a glance).
- **The dead click, made structurally impossible, not just usually avoided:** blanking the box on mixed fixes the reported repro directly (blank → a real value is always a change, so a native `<select>`'s `change` event fires normally) — but a UNIFORM selection re-picking the value it already shows is a real, separate case the fix has to cover too. A native `<select>` cannot be made to guarantee this (its `change` event provably does not fire on a same-value re-pick, and — checked empirically — headless Chromium cannot even open/click a native select's real popup, so no automated regression guard could ever prove a fix to it). Both `nt-block` and `nt-size` are now a `FormatMenu` **listbox popover** (a `<button>` trigger + real `<button>` options), the same shape this file already uses for `ColorPopover`/`CalloutControl`/`TableGridPicker` — a button's `onClick` fires on every press, full stop, with no "did the value change" state to go stale. `ui-audit/audit-notes-formatting.mjs` (the existing, more general formatting-regression audit) updated for the new control shape and still 46/46 passing.
