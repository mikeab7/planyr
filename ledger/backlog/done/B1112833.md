`[x]` **SHIPPED THIS SESSION.** `lib/formulaConsistency.js`'s `findInconsistencies(sheet)` normalizes every formula cell's AST to an R1C1-style STRUCTURAL shape (`shapeSignature`) — every plain reference becomes a (row-delta, col-delta) pair relative to the cell holding the formula, so `=B2*C2` and `=B3*C3` fingerprint identically; a $-anchored coordinate stays LITERAL on its anchored axis (a shared tax-rate cell every row multiplies by is the SAME pattern down the whole column, not a different one every row); a `[Column]`/named-range reference compares by NAME; embedded number/string/bool literals compare by TYPE only, never value, so two rows growing at legitimately different rates (`=B2*1.05`, `=B3*1.06`) read as the same shape. Runs both axes independently over every maximal contiguous non-blank run (`MIN_RUN_LEN` 3+), asserting a pattern only once a DOMINANT shape covers a real majority of the run's formula cells (`MIN_DOMINANT_COUNT` 3, `MIN_DOMINANT_FRACTION` 0.6) — a short or genuinely mixed run asserts nothing. **Three precision passes, each one measured to remove a real false positive** (not guessed): a formula whose shape merely differs from the dominant one is suppressed at the run's own edge when it's a top-level call to an aggregate function (SUM, SUBTOTAL, …) — the ordinary shape of a subtotal/total row, not an error; a LITERAL is suppressed unconditionally at the edge — the ordinary shape of a growth series's own seed value; and a plain TEXT literal (a row/column LABEL) is excluded from the pattern entirely, never a "hardcoded" candidate and never counted toward edge position — without this, the label column nearly every real sheet has (routine: the label sits immediately before the numeric run on almost every row) pushed the true first NUMBER one position in, defeating the edge check and flagging an ordinary seed value as an overtype. This ties directly into #1385's new blue/black/green colour-by-type convention (input/formula/cross-sheet), landed in the same Stage 3 work: a hardcoded value inside a formula run is now visible TWO ways at once — blue text (already shipped) and this item's own small amber corner-triangle flag — and the two never disagree, since the flag detector reads the same `isFormulaText` predicate the colour classifier does. Persistence for dismissal (`sheet.dismissedInconsistencies`, same `colId:rowIndex` keying and row/column insert-delete relocation/tombstone-delete discipline as `sheet.styles`) lives in `sheetModel.js`; `findInconsistencies` itself stays pure and knows nothing about dismissal — the UI layer filters. `InconsistencyPanel.jsx` (same floating-panel family as Name Manager/Find-Replace, same fixed top-right position since they're mutually exclusive) lists every active flag with Go-to + Dismiss; the ribbon's own Inconsistencies button carries a live count badge. The per-cell marker is deliberately `pointerEvents:"none"` — CHROME-NEVER-EATS-A-PRESS — dismissal only ever happens through the panel's own button, never by clicking the marker.
