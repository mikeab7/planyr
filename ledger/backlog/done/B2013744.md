### B2013744 — A map note's pin completely hides a comp's pin on the same parcel `[site-planner / map]` (bug) #site-planner #comps #map-notes  *(Owner report 2026-10-02 (NEW-1), measured live on build 6246ba3: throwaway comp + note on APN 0481850000004, zoom 17 at 29.62316598,-95.28208917. DEDUPE-FIRST: no prior item on overlapping map markers; nearest is B1372144 (map notes layer) which built the note marker.)*

`[x]` **Cause (AUDIT-FIRST):** a parcel anchor's lat/lon is the parcel's assembly centre, so a parcel-anchored comp, a note on that parcel and the site's own pin all resolve to ONE point. The note marker's 34x46 hit box (anchor = its centre) wholly contains the comp's 14x14 box, and the notes layer is added after the comps layer, so it paints and hit-tests on top: `elementFromPoint` returned the comp at 0 of 49 sample points (reproduced exactly, in the harness's red arm). The site pin has the same 34x46 box and a higher z, so it covers both.
`[x]` **Fix:** pins that genuinely coincide (within ~4 m) are nudged apart in SCREEN pixels (`lib/pinCluster.js`, pure): the site pin (or first pin) keeps its true spot, the rest take fixed slots left/right/above/below, 38 px apart so no two hit boxes overlap, the same gap at every zoom. Applied by shifting the marker's `iconAnchor` — the true lat/lon is never changed. Only painted layers count (checkboxes + name filter); a lone pin never moves.
