- Verify: sandbox
- Origin: found 2026-08-08 in-session
- **THE DEFECT.** `parseBacklog`'s heading pattern was `/^###\s+(B\d+)\b\s*[—-]\s*(.*)$/` — the em-dash had to follow the id immediately. The recurrence rule (**B636**) mandates the opposite shape for a fix that did not stick: `### B1121 (×3) — …`. So every recurrence-marked heading failed to match and its item was **dropped from `BACKLOG_OPEN.md` silently**, because a dropped item is indistinguishable from an item that does not exist. `--check` stayed green throughout: the index was a faithful render of a parse that had already lost the rows.
- **⛔ WHY IT MATTERS MORE THAN ITS SIZE.** `CLAUDE.md` tells every session to **grep `BACKLOG_OPEN.md` for the live open set** rather than read the 250 KB backlog — so this is the file a session actually looks at, and the bug **selected precisely for the items that matter most**: a `(×N)` means a fix has already failed at least once. **Eleven Open / ⏳ Verify items were missing**, among them **B1121 (×3)** — the oldest unexplained bug in the speed program, the one this very session was dispatched on, and the one `CLAUDE.md`'s own perf notes point at. Recovered counts: **140 → 143 open, 306 → 314 awaiting verification.**
- **The fix.** `(?:\(×(\d+)\))?` between the id and the dash, and the count is **carried into the row** (`| B1121 (×3) | …`) rather than merely no longer fatal — a reader scanning for what to pick up should see "this has already failed twice" without opening the backlog.
- **Tests.** `test/backlogIndex.test.js` gains two cases, asserted **from `BACKLOG.md` itself** rather than from a fixture, so they cannot rot into a green that tests nothing: every `### B# (×N) —` heading in the real file that the parser collects must appear in the real index **with its count**, and a plain heading must carry `recurrences: null` and render as the bare id. 4 cases green.
