- **DEDUPE-FIRST:** this EXTENDS the shared B230 Bluebeam vertex engine (`editablePath`/`hitEditPath`/`insertVtx`/`deleteVtx`) — which shipped before the B599 centerline-road model and so excluded roads (its `sel.kind==="el"` branch keyed off `el.points`; roads store `el.pts` + a parallel `el.vtx` treatment list). Predecessors B141/B147 added vertex-edit to measures/markups; B599/B600 built the road model — none added road control-point add/remove. No new number minted for the engine: this is the road slice of the same engine.
- **What shipped:** two pure, unit-tested helpers in `lib/roadGeometry.js` — `insertRoadVertex(pts,vtx,edgeIndex,pt)` (splices the point + a matching `{}` treatment, staying length-matched; the new interior vertex defaults to arc and renders straight until dragged because the projected point is collinear on its sparse segment) and `removeRoadVertex(pts,vtx,index)` (returns null for an endpoint or a 2-point road) + `canRemoveRoadVertex`. `SitePlanner.jsx`: `editablePath()` returns a `{layer:"road", pts:el.pts, closed:false, min:2, edgeTolFt:…, noEndpointDelete:true}` case (checked before the polygon `el.points` case); `hitEditPath()` honors a per-path `edgeTolFt` (≈ strip half-width, so a Shift-/right-click anywhere on a wide road projects onto the centerline); `insertVtx`/`deleteVtx` gain a `road` branch that keeps `pts`+`vtx` in lock-step and re-syncs the strip bbox via `reRoad`; the plain-click + context-menu wiring arms only INTERIOR road vertices for the Delete key (an endpoint/body leaves selVtx null so Delete still removes the whole road — no behavior change there).
- **Also fixed (latent bug this surfaced):** the Shift-insert `onOtherParcel` guard used `pc.id !== (path.layer==="parcel"?path.id:null)`, which was true for EVERY parcel when editing a road/el, so a road inside a parcel (the normal case) could never Shift-insert. Gated it to `path.layer==="parcel"` (also fixes the same latent case for polygon elements).
