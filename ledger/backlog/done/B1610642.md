`[x]` **FIXED THIS SESSION, per the owner's own stated approach (move View/Layers, not the tabs).** On a narrow (phone-width) canvas, the "Panels" edge tab (left screen edge) sat at `top: 10`; the "Tools" edge tab (right screen edge) sat at `top: 53` — pushed 43px lower specifically to duck under the top-right View/Layers row, which shares the Tools tab's same right-edge column (the row sits at `right: 10`, and the Tools tab, flush at `right: 0` with a 40px width, overlapped the row's own rightmost 30px if both were at the same `top`). Since Panels has no such neighbor on the left edge, it never needed the offset — so the two tabs, meant to read as one deliberate top row, visibly didn't.
- **THE FIX.** The View/Layers row's own `right` offset now insets further left on narrow screens — past the Tools tab's 40px column plus an 8px breathing gap (`TOP_RIGHT_ROW_NARROW_RIGHT_PX = 48`, new in `lib/mapChromeStack.js`) — freeing the top-right corner for the Tools tab to sit at the SAME `top` the Panels tab already used (`EDGE_TAB_TOP_PX`, `= MAP_OVERLAY_TOP_PX = 10`, also new). Desktop is untouched: the View/Layers row keeps its original `right: 10` there (the edge tabs never render on desktop at all, so there's nothing to clear). `TOOLS_TAB_RESERVE_PX` (the reserve the bottom-right zoom stack clamps against, on narrow, so it never climbs into the Tools tab's own band) is derived from the SAME `EDGE_TAB_TOP_PX` rather than the old hardcoded `53`, so it shrank in step (145 → 102) with no separate edit — the zoom stack's clearance math didn't need to change shape, only read the corrected input.
