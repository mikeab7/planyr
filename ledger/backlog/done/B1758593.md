- **REUSED THE BUILDING'S MECHANISM, not a parallel one.** A callout is a different data shape from an `els` building (no bonded assembly, width comes from `calloutLayout`'s auto/`boxW` sizing rather than a stored `w`/`h`), so the exact `startRotate`/`assemblyOf` code couldn't be called directly — but every REUSABLE piece is reused verbatim: the same `rot2(x,y,deg)` rotation primitive, the same `drag.current = { mode, pivot, rot0, a0 }` shape and the identical `Math.atan2(...) * 180/Math.PI` + 15°-snap-when-Snap-is-on math (`startCalloutRotate`/the `calloutRotate` onMove branch, modeled directly on `startMarkupRotate`/`mkRotate` — the closer single-object precedent), and the identical rotate-handle visual (`topMid` → a unit vector out → a fixed-px `rotPos` → a connector line + `data-handle="rotate"` grab circle) both the building and rect/ellipse markups already use. `DRAG_OP_KIND.calloutRotate = "rotate"` so undo/the activity feed label it correctly, same as every other rotate mode.
- **THE BOX+TEXT ROTATE AS ONE RIGID UNIT; A LEADER DELIBERATELY DOES NOT.** `c.rot` (degrees, additive field, no migration — `c.rot || 0` everywhere, matching `el.rot || 0`'s own convention) drives a `<g transform="rotate(rot bp.x bp.y)">` wrapped around ONLY the box `<rect>` and its text lines. A callout's leader points at a fixed external target and must never swing with the box — so leaders sit OUTSIDE that group, and every place that finds where a leader touches the box (the render's `origin`, the elbow grip's default position, a never-bent elbow's seed on drag-start) now rotates the target point into the box's own LOCAL (unrotated) frame first, runs the existing axis-aligned `nearestRectPerimeterPoint` unchanged, then rotates the answer back out — the same rotate-into-local-frame idiom `startMarkupResize`/`mkResize` already use for a rotated rect/ellipse markup. `rot === 0` reduces every one of these to the exact byte-identical math every callout ever saved already used.
- **RESIZE AND THE DOUBLE-CLICK HIT-TEST ARE ALSO ROTATION-AWARE**, not left broken under an angle: `startCalloutResize`/the `calloutResize` onMove branch now compute the fixed opposite edge and the live width along the box's OWN rotated local x-axis (mirroring `mkResize`'s rotate-into-local-frame pattern) instead of a bare world-X scalar; `calloutDblAction`'s interior-vs-border hit test rotates the click point into the local frame before testing. Both proven live (below), not just reasoned about.
- **PANEL CONTROL.** The callout Properties panel gained a `Rotation°` field using the exact same shared `RotationStepper` component the markup/element/overlay inspectors already use — not a new control, the one the owner already knows from every other rotatable object.
