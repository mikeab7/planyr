### B511 — Site Planner: pruneMigratedLegacy dropped a NEWER logged-out site by id alone → silent data loss `[Site Planner / Persistence]` (bug) — HIGH  *(bug-hunt round 2, 2026-06-27, adversarially confirmed; fixed same lap)*
`[x]` **DONE + verified. lint 0 · 1716 tests (+3) · build green.** `pruneMigratedLegacy` (runs in `pullCloud` on every sign-in) deleted any on-device legacy site whose id merely EXISTED in the cloud map, with no timestamp check — so: create a site logged-out → sign in + migrate (legacy copy kept) → sign out → edit it logged-out → sign back in → the NEWER local edit was deleted before the migration modal (`pendingLegacyCount`, which keeps a legacy id newer than cloud) could ever surface it. **Fix:** prune only when `cloudMap[id].updatedAt >= legacy[id].updatedAt` (the inverse of `pendingLegacyCount`'s predicate), so B473's duplicate-reclamation still works but a newer local copy survives. Exported the function + 3 unit tests (`test/storage.test.js`: keeps-newer, prunes same/older, keeps cloud-absent). **⏳ Signed-in end-to-end flow → V160.**
