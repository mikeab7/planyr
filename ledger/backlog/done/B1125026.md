### B1125026 — Close silently discards every unsaved comp with no confirmation `[Site Planner / comps]` (bug) #comps #ui  *(second-half adversarial review of the comps module, 2026-09-03, "NEW-8" — measured live on planyr.io build fa427d7: 123 pasted rows, none saved, one click on Close, all 123 gone with no prompt anywhere. Explicitly reconfirmed unaffected by the mid-session NEW-6 retraction ("NEW-7... and NEW-8... are unaffected by this retraction"). Minted **B1125026** from this branch's reserved block. DEDUPE-FIRST — searched Open/⏳Verify/Done for "discard unsaved", "Close confirm" + comps: comp delete already has no confirm/undo by design elsewhere in this module (per the report's own note) but no prior item covers the WHOLE-SHEET close path. Net-new.)*
`[x]` **SHIPPED THIS SESSION.** Root cause: the header ✕ and the footer Close button both called the panel's `onCancel` prop directly — `CompsPanel.jsx`'s `closeGrid` (`setView("list")`), which unmounts `CompEntryGrid` with no prompt; `gridRows` state isn't even explicitly cleared on close (only on the NEXT open), so the discard is silent both ways. Investigated the report's third named path (Escape) before building anything: this module has no whole-panel Escape-to-close handler at all today — the only existing Escape handling is per-cell edit-cancel (`onEditKeyDown`) and the separate `armedRowId` map-pin disarm in `CompsPanel.jsx` — so the header ✕ and footer Close already shared one handler and there was no third path silently bypassing a fix aimed at just those two. Fix: both now route through a new `requestClose` — empty sheet (`rows.length === 0`) closes exactly as before, instant and silent (nothing to lose); a sheet holding rows arms an inline confirmation ("Discard N unsaved comps?" / "Discard 1 unsaved comp?" singular) with **Discard** and **Keep editing**, rendered by a new module-scope `DiscardCloseConfirm` component — no `window.confirm`, this app bans native dialog boxes app-wide (the same "no dialog-box edits" house rule this module's own file header already cites). The desktop version is `position: absolute` scoped to the docked panel's own box (never a full-viewport modal, consistent with this file's own standing rule against covering the map); the mobile version is `position: fixed` covering the whole screen, matching that sheet's own already-full-screen nature. The mobile sheet's own header ✕ / footer Close (`CompEntryMobileSheet.jsx`) got the identical fix — same silent-discard bug, same template, independently confirmed live.
- **FOLLOW-UP, same session, live PR review** — the report's own hedge ("Consider also treating Escape... they may not share a handler") was resolved as "no third path" at the time, correctly — but a live re-check of the merged PR asked for Escape to share the SAME confirm-before-discard behavior as the other two, not merely to be ruled out as a silent-bypass risk. Added: a bubble-phase Escape handler on the whole panel (desktop) and a wrapping `<div>` around the mobile sheet, both routing through the same `requestClose`/`confirmingClose`/`keepEditing` state the buttons already use — guarded off while a cell is mid-edit (`onEditKeyDown`'s own, more specific Escape-cancel takes priority) or a row is armed for a map pin (`CompsPanel.jsx`'s window-level Escape-disarm owns that case). A second Escape while the prompt is already up is treated as "Keep editing," the safe default for a confirm dialog, never a second discard attempt.
- Verify: sandbox — live-driven in the same session (`ui-audit/verify-comp-entry-a11y-close.mjs`): header ✕ with 1 row arms "Discard 1 unsaved comp?", Keep editing leaves the row and the sheet intact, footer Close with 2 rows arms "Discard 2 unsaved comps?", Discard actually closes the panel; an empty sheet closes instantly with no prompt anywhere in the DOM; the mobile sheet's own Close arms and honors the same confirmation; Escape (a real `page.keyboard.press`, not a synthetic dispatch) arms the identical prompt on both desktop and mobile, a second Escape keeps editing, and Discard is still reachable from an Escape-armed prompt. 16 checks, all passing, folded into the same 34/34 harness run as B1125024/B1125025.
