- Verify: sandbox — pure URL-parsing/directory-walk logic and a Node CLI script, fully exercised end-to-end against a fixture reconstructing the real Nevada incident (the exact failed URL, the exact replacement service name, the exact 1,394,188 count) via an injected fetch mock; no live network needed to prove the mechanism finds and confirms the real replacement it was built for.

**`ui-audit/lib/serviceNeighbourWalk.mjs` (new)** — given a failed ArcGIS layer/service URL, parses it into `{restBase, folder, serviceName, serviceType}` (pure), lists the SAME folder's services first (a same-server rename never leaves its folder — confirmed against Nevada's real incident), falls back to every sibling folder at the server root, scores every candidate by NAME-TOKEN SIMILARITY against the failed service's name (so an unrelated service sharing the host is never proposed), and for the survivors resolves a real layer (preferring a polygon layer named "parcel") and MEASURES it — feature count, field names, using the SAME body-checking logic B1461729 fixed (`measureParcelLayer`, shared rather than a second copy). When the caller supplies the last-known-good facts (feature count, field names), `candidateMatchesKnownGood` flags a CONFIRMED match (count within 0.5% tolerance, every known field present) — exactly the count-and-schema match that identified the real Nevada replacement — never auto-applied, always reported for a human to confirm. A same-named candidate that is ITSELF an empty shell is reported as such, never silently dropped (`"service has zero layers"`).

**`ui-audit/parcel-source-health-sweep.mjs` (new)** — the periodic sweep. `collectWiredLayerUrls` reads every DISTINCT `layerUrl` directly out of the real `COUNTIES`/`COUNTIES_MAP` registries in `counties.js` (deduped — several county keys can share one statewide layer, e.g. Waller→TxGIO — and every affected key is named in a failure report, not just the first found), checks each with `measureParcelLayer`, and on a failure (an ArcGIS error body, zero features, or unreachable) runs `walkForReplacement` and includes what it found. `node ui-audit/parcel-source-health-sweep.mjs` exits 0 when every checked source answers with real data, 1 otherwise (`npm run sweep:parcel-health`). Scoped honestly: only `layerUrl`-direct entries are checked this pass (the great majority of wired sources, including every statewide composite) — a `serviceUrl`-only entry (auto-resolved at request time) is out of scope, stated in the script's own header rather than silently skipped. No persisted "last-known-good" baseline exists yet, so a sweep-found candidate is reported by name-similarity + measured facts for a human to confirm, not auto-flagged as confirmed — a real, separate follow-up (see the "What isn't built here" note below).

**"Caught by the build," concretely:** `.github/workflows/parcel-source-health.yml` (new) — a nightly scheduled workflow, same shape as the existing `gis-drift.yml` (the weekly drift check for the OTHER registry): runs the sweep, and on any non-zero exit opens (or bumps) a single `@claude`-labeled GitHub issue naming every broken source and its walked candidate, auto-closing it when the sweep goes green again. GitHub Actions runners have ordinary internet access (unlike this sandbox's blocked-.gov egress policy), so this is expected to reach `arcgis.water.nv.gov` and its peers for real on its first scheduled run.

**PROVEN AGAINST THE REAL INCIDENT, not a synthetic shape.** `test/serviceNeighbourWalk.test.js` (20 tests) reconstructs the exact Nevada directory tree (`BaseLayers/County_Parcels_in_Nevada` failed, `BaseLayers/County_Parcels_In_Nevada_Yellow` the real sibling, plus an unrelated sibling folder and an unrelated same-folder service to prove both are filtered out by name similarity) and confirms `walkForReplacement` finds and CONFIRMS the real replacement against the real feature count and field list, never re-proposes the failed service as its own replacement, and reports (never drops) a same-named-but-empty decoy. `test/parcelSourceHealthSweep.test.js` (6 tests) drives the sweep end-to-end over a mocked Nevada host and confirms it reports the outage, names `NV/nv_statewide`, and surfaces the Yellow candidate — plus confirms the REAL `counties.js` registries (post-B1455632/B1461728's fix) resolve Nevada to the Yellow URL, so this guard would have caught the original incident on the very next scheduled run.

**What isn't built here, stated rather than implied:** a persisted cross-run "last-known-good" baseline (so a genuinely-down-right-now source's replacement gets CONFIRMED rather than merely proposed by name) is real follow-up work, not done in this pass — every sweep run currently proposes candidates by name-similarity + a fresh measurement, which is sufficient for a human to confirm quickly but not fully automatic. Auto-wiring a confirmed replacement into `counties.js` is explicitly NOT done — every fix stays a human decision, per this repo's own settled position against auto-guessing a data source.
