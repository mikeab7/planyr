- **THE READ.** `teeGeometry`'s `fillet()` (`roadGeometry.js`) computes `tMax` — the maximum tangent run a return can carry — from the actual room available along the edge in each direction (`throughAvailPos`/`throughAvailNeg`, fed from `driveJunctionsOf`'s `edgeRunPos`/`edgeRunNeg`, each side's distance to where the pad edge itself ends) and clamps the requested radius down to fit (`Rc = tMax * Math.tan(phi / 2)`) whenever the class radius would overrun that room. This is the extensively documented "REACH-CAP the curb return (B1005/NEW-1 — supersedes B989)" rule, already in the code: "the return reach is ALWAYS ≤ R at ANY angle… Still bounded by the actual road/drive run available (a short drive shrinks the return further)." A return that ignored this would either overshoot past the pad's own corner (pavement floating past the edge it's rounding) or — before B1703665 NEW-2's chamfer fallback for the genuinely-zero-room case — degenerate to an exposed bevel. Clipping the RADIUS while still tracing a true circular arc is the correct, intended behavior, not a bug.
- **MEASURED DIRECTLY against the real pipeline, matching the dispatch's own live numbers in shape (not reproducing Goose Creek's specific geometry, which this item never touched — see DO NOT REPAIR HIS DATA below):** a road landing 23.59 ft from a pad corner produces a near-side return that circle-fits to R≈20.78–23.5 ft (varies slightly with the exact synthetic pad geometry used) against a full R=24 ft far side — both genuine constant-radius arcs (circle-fit RMS residual < 0.05 ft, per-segment turn angle < 10°, comfortably inside the tessellation bound), never a bevel and never an unclamped overshoot.
