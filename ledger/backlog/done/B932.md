- **Behaviour:** Alt+Z clears the callout's explicit `boxW`, returning it to AUTO width (which, post-B931, hugs the real text). Equivalent to the "Fit to text" button — a fixed-width box that the user dragged wide collapses back onto its content; an already-auto box is a no-op (the key is still consumed so nothing else fires, and no empty undo frame is pushed).
- **Fix (`SitePlanner.jsx`):** (a) the main keydown handler — `e.altKey && e.code === "KeyZ"` (physical Z, since Alt+Z emits a dead/other char on some layouts) on a selected callout → `pushHistory()` + clear `boxW`, reading live `selRef`/`stateRef` so a stale keydown closure can't miss a just-dragged width; (b) the inline editor's `<textarea>` `onKeyDown` — same chord clears `boxW` mid-type so the box re-flows to fit on the spot (Bluebeam parity). Discoverability: the "↔ Fit to text" button now shows an `Alt Z` kbd hint, the shortcuts overlay lists it, and the Callout/Text tool hints mention it.
