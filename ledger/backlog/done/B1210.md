**The report + the screenshot.** Zoomed out until the whole 62-acre parcel is a thumbnail against several square miles of county, a full-size **"Front · 25′"** chip is the single largest, loudest thing on screen. *"The setback chip is showing as the only thing I can see when I zoom out — it's kind of pointless at this zoom."*

**Cause.** Both shipped guards are **relative to the parcel**: `CHIP_MIN_EDGE_PX` drops a chip whose anchor edge is too short *on screen*, and `CHIP_MIN_SEP_PX` thins neighbours. On a 62-acre lot the longest run is ~1,700 ft, which clears the edge bar at **any** zoom (at county zoom it is still ~34 px), and separation never applies to a lone survivor. Nothing about the parcel got smaller relative to itself, so no relative guard could ever hide the last chip.

**The fix — an ABSOLUTE floor, and deliberately the one that already exists.** `setbackChipsVisible(ppf, { editing })` gates on `dimCalloutVisible` — the same `DIM_CALLOUT_MIN_PPF` floor every other callout and dimension rides — so the chips leave and return **with** the rest of the annotation instead of standing alone over an empty county. Both relative guards still run after it. The **one exception is deliberate**: a parcel whose setbacks are actively being edited (the user has drilled into *By side* / *Per segment*, or has an inline value editor open) keeps its chips at any zoom, because at that moment they are the edit surface, not annotation.

> **Tests / verification.** `test/setbackChipQuiet.test.js` — hidden at county zoom, shown at working zoom, exactly equal to `dimCalloutVisible` across a zoom sweep, the editing exception, and the arithmetic showing why the relative edge guard alone cannot hide a big parcel's longest chip. Headless: chips are counted at three zooms on the real geometry (plan → overview → back), in both themes, with screenshots.
