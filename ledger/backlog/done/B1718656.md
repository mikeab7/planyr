`[x]` **FIXED AND VERIFIED THIS SESSION.**

**ROOT CAUSE, measured, not assumed.** `MapFinder.jsx`'s Sites-list row (`siteRow`) painted the org/team chip (B885136/B1614656) as a zero-width, absolutely-positioned overlay: a `<span>` with `flex:"none", width:0` sitting right before the "locate" slot, holding a child pill styled `position:"absolute", right:0` — so the pill always grew LEFT from that one fixed x, whatever else occupied it. B1614656 hardened this against exactly ONE sibling (the site name), by shortening the badge to short initials once a wide team name was measured covering the name. It never checked the OTHER sibling that can sit at that same edge: the standing-fact flag group (B845089's "no boundary" / the Locations-card "no location" chip, `rowFlagGroupStyle`), which — like the name — is free to grow right up to the edge of its own flex-1 box whenever the row is squeezed. Reproduced on the owner's own "Untitled site" row (a SHORT name, so B1614656's truncation guard never engaged) at this panel's real fixed 232px width: the "no boundary" chip measured x=96–154, the badge measured x=150–162 — a real 4px overlap, confirmed both by live geometry and by a temporary revert of the fix (see Verify below).

**THE FIX.** The badge slot is now a real (non-zero-width) flex item, laid out IN SEQUENCE after the flag group and before the locate slot, sized to its own content — the chip itself dropped `position:absolute`/`right`/`top`/`transform` and renders as ordinary in-flow content. The browser's own flex-shrink pass — not a hand-picked anchor point — is what now keeps every sibling clear of it. VIEWPORT-STABLE still holds: the slot's DOM presence and size are constant across hover states (only `opacity` toggles, exactly as before), so revealing the badge on hover still never shifts the last-edited date column. The flags' existing `flex:"0 1 auto"`/`minWidth:0` and the name's `NAME_MIN_PX` floor (B1424624) are unchanged — the same shrink order (flags give way first, then the name's own ellipsis) still applies, just against a smaller total available width. B1614656's initials-only bound on the badge's own content is what keeps this slot small even at its widest, so the fix cannot reopen the truncation defect it once caused.
