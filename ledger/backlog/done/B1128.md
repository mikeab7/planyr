- **Why.** Four "computed but never rendered" defects in five dispatches (see **B1126** for the full class analysis). The variable half is statically detectable and this repo simply never enabled the rule: `eslint.config.js` is deliberately minimal and carries **no `no-unused-vars`**, so a local assigned in every branch and read in none compiles, minifies and ships silently — exactly B1110.
- **Why a RATCHET, not a clean gate.** Turning the rule on as an error fails in **136 places (90 in `src/`)**, mostly harmless (unused icon components, destructured setters). So `ui-audit/dead-store-baseline.json` freezes the count **per file** and it may only go DOWN: a new dead store fails immediately, existing ones get paid off whenever a session is in that file anyway. No false-positive tax, and the class stops recurring from today. `--update` **refuses to raise a total** — a new one must be fixed, not blessed.
- **Scoped deliberately to "assigned a value but never used".** Unused imports and unused params are cosmetic and would triple the baseline, burying the signal.
- **⭐ IT CAUGHT A REAL ONE WITHIN MINUTES OF EXISTING, from a concurrent session.** Merging `main` (PR #858, the trailer-court / inspector work) turned this test red immediately: **two NEW dead stores** that landed before the guard existed — an `alongUnit` ALONG-wall helper in `SitePlanner.jsx` that nothing called, whose own comment claimed it kept "screen math and layout math" in agreement (precisely the dead code that reads as load-bearing and is not), and an `nx` in `siteModel.js`'s alongLen heal where only the across component is read. Both fixed here rather than banked — and note the guard **would not let me bank them**: `--update` refuses to raise a total, by design. The `alongUnit` deletion also names where the live derivation is, so a future caller takes the one copy instead of reviving a second that can drift. This is the class going non-recurring in practice, not just in principle.
