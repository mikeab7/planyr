### B1074770 — Two different caret glyphs/structures in the same Map finder toolbar `[Site Planner / Map]` (bug) #site-planner #ui  *(owner chat block 2026-09-02 — "The two split buttons render their caret as the character U+25BE, while the Imagery & layers control in the same toolbar renders U+25BC as a text prefix inside its label. Same toolbar, same affordance, two glyphs and two structures. Pick one caret treatment for the toolbar per docs/DESIGN.md and use it for all three." Minted **B1074770** from this branch's reserved block against `origin/main` a90e0c37. DEDUPE-FIRST — searched Open/⏳Verify/Done for "caret glyph", "▾", "▼", "MenuTrigger caret": no prior item addresses this specific cross-control inconsistency. Net-new.)*
`[x]` **AUDIT-FIRST finding that corrects the repro's framing before fixing it: these are not actually the same affordance, and docs/DESIGN.md already has a canonical answer for the one that is.** `controls.jsx`'s shared `MenuTrigger` primitive — the one control this app already uses for "opens a menu/popover" (the row-1 "File ▾" button, the account chip) — draws its own trailing caret as `<span aria-hidden="true" style={{opacity:0.6, fontSize:11}}>▾</span>` (U+25BE). The two split-button carets this item's repro flags already used the CORRECT, canonical glyph (▾) — matching `MenuTrigger` exactly — they just didn't use its STRUCTURE (a bare button-text child sized off the button's own `fontSize`, no `aria-hidden`, no dedicated opacity). The "Imagery & layers" toggle's ▼ (U+25BC) with a `rotate(-90deg)` transform is a genuinely DIFFERENT affordance — a persistent DISCLOSURE that expands/collapses a docked panel in place — and it is internally consistent with two OTHER disclosure toggles in that exact same rail panel (the Sites-panel header's expand/collapse arrow, each status group's own collapse arrow), all three sharing the identical ▼ + rotate-on-state treatment. Converting it to a static ▾ would break its own established, repeated-3× convention and would misrepresent an in-place expand/collapse as if it were a "click to open a floating menu" trigger (which never rotates on open anywhere else in this app — clicking away, not clicking the trigger again, is how those close).
`[x]` **Fix: converge the two split-button carets onto `MenuTrigger`'s exact structure**, not onto the disclosure toggle's. Both `▾` characters are now wrapped in `<span aria-hidden="true" style={{opacity:0.6, fontSize:FONT_SIZE.micro}}>▾</span>` (the app's raw-literal-fontSize rule means the button-caret span uses the token `FONT_SIZE.micro` (10) rather than `MenuTrigger`'s own raw `11` — `controls.jsx` is exempt from the design-drift check as the token layer itself; `MapFinder.jsx` is not, and `micro`'s documented role, "tiny numerals and decorative glyphs," is exactly this glyph). "Imagery & layers" is deliberately left unchanged, with a comment at the fix site explaining why, so a future session doesn't "converge" it a fourth way without re-reading this reasoning.
