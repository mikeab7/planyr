- **Repro (owner):** Site Planner → open the "Site-plan overlay" panel → its copy says "Drop a site-plan PDF onto the map (or browse)", but dragging a file over the panel gives **zero feedback** and releasing it does nothing (or the browser opens the PDF in a new tab) → reads as broken / "doesn't allow anything to be dropped in."
- **Root cause (confirmed in code):** the canvas wrapper (`wrapRef`, `SitePlanner.jsx`) already HAD a working `onDragOver`/`onDrop` → `addOverlayFile`, but (1) there was **no drag-hover affordance** so the live zone looked dead, and (2) the **left panel itself** (where the cursor goes — the "Add site plan…" button + copy live there) had **no drop handlers**, so a release there hit the browser default. On narrow screens the panel is `position:absolute; zIndex:1100`, outside the `wrapRef` subtree, so its drops could never reach the canvas handler.
- **Fix (`SitePlanner.jsx`), reusing the existing ingestion path (`addOverlayFile` → `openOverlayFile`/`uploadOverlayFile`) + the Doc-Review `FileBrowser` dropzone pattern:**
  1. **Panel is now a real dropzone** — the overlay `Section`'s button + copy are wrapped in a dashed-border `<div>` that highlights on hover (accent border + `PAL.accentSoft` bg, anti-flicker via `e.currentTarget === e.target`), routes drop → `addOverlayFile`, and shows "Drop to add this site plan" while dragging. The button stays the click-to-browse path.
  2. **Canvas "drop to place" hint** — a full-bleed dashed overlay (`pointerEvents:none`, above the SVG's `zIndex:1`) mounts only during an active file drag, with a centered "Drop site plan to place it on the map" pill.
  3. **Window-level guard** — a `useEffect` blocks the browser's default file-drop everywhere (`dragover`/`drop` preventDefault when the drag carries Files), so releasing a few pixels off-target no longer navigates away / opens the PDF (the core "nothing happens / data loss" feeling).
- **Edge cases:** multi-file drop takes the first file + `flashWarn`s ("one overlay placed at a time"); panel `onDrop` `stopPropagation`s so it can't double-fire to the canvas; all new colors use the existing `PAL` theme tokens (no raw hex), keeping WCAG AA.
- **Deduped:** distinct from the Doc-Review file-drop dropzones (`ProjectFilesDrawer`/`FileBrowser`) — this is the Site Planner *site-plan overlay*, a separate surface; the pattern was reused, not the component.
