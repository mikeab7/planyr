`[x]` **FIXED AND VERIFIED THIS SESSION.** `NoteOutline` (`components/NoteOutline.jsx`) used to render unconditionally whenever a note has at least one heading, sitting BESIDE the mat in the same row (`NoteEditor.jsx`'s outer `display:"flex"` row: mat + Outline + History) — the row has no `overflow` of its own, so on a real phone Outline ate real width from the mat regardless of the sheet's own alignment, and once the mat's own available width dropped below the sheet's `minWidth` floor the sheet's words got clipped at whichever edge didn't get the overflow. Below the shared phone breakpoint (`narrow`, the same 760px one the toolbar and the phone drill-in already use) the component now renders NOTHING inline — a `position: fixed` floating toggle costs the row zero width by construction — and opens the same heading rows in a `position: fixed` panel drawn OVER the document instead of beside it; picking a heading auto-closes the panel so the jump is never left covered. `NoteEditor.jsx`'s `outlineOpen` now defaults to CLOSED on a phone (`!narrow`) so opening a note with headings never launches an unasked full-screen takeover. Two real defects caught and fixed by live-driving the change rather than trusting the code read: (1) the floating toggle collided with the global Help/Report FAB at the identical `right:12,bottom:16` corner — fixed by marking it `data-canvas-corner="notes-outline"`, the existing corner-clearance contract (`shared/ui/cornerClearance.js`, B966700) that lets the Help control measure and clear real occupants of that corner without either control needing to know the other's name; also corrected the toggle's own shape from `RADIUS.pill` to `RADIUS.control`, matching the just-established rule (B1176976) that a standalone FAB is never a full circle at this size. (2) the drawer's own `zIndex` (57) sat BELOW `AppHeader.jsx`'s `position:relative;zIndex:60`, so a tap on a heading row under the header's own vertical span was intercepted by a header tab button instead — raised to 65/66.
