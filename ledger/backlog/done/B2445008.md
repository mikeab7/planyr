- **Root cause — TWO defects, both confirmed in a real browser on his real structure (read read-only from production into `ui-audit/lib/grandPortScheduleStructure.mjs`), both red on 3a33571:**
  1. **Grid zoom (hypothesis (c), but the offset is ZOOM, not the iframe or virtualisation).** The grid scales itself with CSS `zoom` (Ctrl+wheel, `gridZoom`, kept per browser in localStorage — not in the DB, so his own value could not be read). `intentAt` divided VISUAL pointer pixels by the UNZOOMED row height, so at any zoom ≠ 100% the drop resolved to a different row from the one under the pointer, by (1 − zoom) × the row's distance from the grid's top. - **Inference CONFIRMED in code (AUDIT-FIRST):** `GridView.startRowDrag` resolved every release to a GAP (above/below a row) via `resolveDropParent`; a row only ever became a parent when the drop landed in the gap between a parent and its FIRST child. A childless row has no such gap, so nesting under it by drag was impossible by construction. (The pure mover `moveSelectionToDestination` already supported nesting — it is what "Move to…" uses.)
- **Fix (`public/sequence/index.html`):** new pure, module-level `rowDropZone` / `rowDropIntent` / `resolveDropParent` (the latter lifted out of the drag closure so tests run the REAL code). A hovered row now has three zones — top 35% = insert above, bottom 35% = insert below (the 2BAND rule, unchanged), **centre 30% = nest under THIS row** (`destParentId = row.id`, `insertAfterId = "end"` → last child). The nest target is a boxed, tinted outline around the whole row with a "Nest inside" chip — visually unlike the insertion line (painted imperatively like the line: zero React state mid-drag, still ONE `moveRows` call on drop → one setData → ONE undo step). The centre of a row that is being dragged, or sits inside a dragged row (collapsed descendants included), paints a red dashed "Not allowed" box and a release there refuses with a toast ("A row can't be moved into itself or its own sub-rows.") — never a silent no-op. No `not-allowed` cursor is set (cursor-convention guard stays green).
- **Decision (amends the 2026-08-25 two-band rule, recorded as constraint 36):** nesting is back, but as the SMALLEST zone (30% vs 35%/35%), never the biggest target — the exact mistake B763472 fixed (the old "into" band was 40%, 8px vs 6px at 20px rows, and caught accidental drops). Asserted per row height by STEP 2 + a NESTBAND mutation in `ui-audit/verify-schedule-row-move.mjs`.
