- Verify: sandbox — pure logic + unit tests (`test/buildSkew.test.js`, +14 new cases, all green), a build-time embed proven by inspecting the emitted `dist/version.json`, and a UI wiring change with no auth/live-GIS/real-data dependency. No live click-through needed for a notice-copy/dismissal-timing change.

**THE MECHANISM.** `buildSkew.js` treated every skew identically — one dismissible notice, dismissal scoped to the served build id — right for a cosmetic fix, wrong for a build whose known defect is destructive on a timer (exactly B1517888's shape). Added a new, additive escalation path rather than changing the existing contract:
- **`src/app/unsafeBuilds.js`** (new) — an append-only, hand-maintained registry of `{ build, reason, date }` records naming past build ids known to carry a still-live problem. **Deliberately empty at ship time**: B1517888's server-side trigger makes the dangerous path impossible regardless of which build issues the delete, so escalating every pre-fix build here would nag users to reload for a risk that no longer exists — the registry is for a FUTURE incident where staying on an old build carries a real, still-live cost nothing server-side can close.
- **`vite.config.js`**'s `buildStamp()` now embeds `supersedes_unsafe: [...build ids...]` into `/version.json` alongside the existing `build` field — a deploy-time data change, never a code change, to declare a build unsafe.
- **`buildSkew.js`** gained `fetchServedMeta` (returns `{build, unsafeBuilds}`; `fetchServedBuild` is now a thin, 100%-backward-compatible wrapper over it), `isLoadedBuildUnsafe(loaded, unsafeBuilds)` and `shouldEscalate({loaded, served, unsafeBuilds})` — all pure, same "silent when it cannot know" discipline as every existing function here (malformed/missing list, dev build, no confirmed skew all answer false). `installBuildSkewWatch` gained an additive, optional `onUnsafeBuilds` callback fired alongside the unchanged `onServed` on every look.
- **`Shell.jsx`** wires it: a new `updateReason` value `"unsafe-build"` wins over the ordinary skew reasons (never over `"chunk-stuck"`, a confirmed CURRENT failure) and gets its own `UpdateBanner` copy ("This tab is running an older build of Planyr with a known problem — please reload now. Your work stays saved either way."). **The re-arm, per the dispatch's own design point (b):** an unsafe dismissal is tracked separately (`unsafeDismissed`) from the ordinary `dismissedFor`, and is cleared every time the watch looks again (poll / focus / visibility change) — so a shrug only lasts until the next look, not forever, while staying non-blocking and never a takeover mid-edit (both existing contracts held per design point (c)).
