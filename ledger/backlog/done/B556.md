### B556 — On a phone, tapping an element auto-opens the properties panel (buries the canvas) `[Site Planner / mobile]` (bug)  *(owner-found 2026-06-28 on iPhone; minted **B556** = highest real B# across both files (B555) + 1; branch `claude/mobile-safari-pinch-menu-3gon8x`)*
`[x]` **DONE + verified. lint 0 · 1782 tests · build green · headless 2/2.** On a phone the left menu is a full overlay (`position:absolute`, ~320px, zIndex 1100) that buries the canvas, so the Bluebeam-style "select → open its inspector" auto-open was the wrong default there — a single tap to select an element/parcel covered the drawing. Two narrow-gated changes (≤760px, the existing `narrow` state; desktop unchanged):
  - **Auto-open gated (the fix).** The selection→panel effect now early-returns `if (narrow && !leftPanel)` — on a phone with the panel closed, tapping just **selects** (handles/rotation/resize controls still appear) and does NOT pop the overlay; the user opens Properties from the **Element** tab when they want it. If a panel is **already** open it still re-syncs to the new selection. One guard covers all selection kinds (`el`/`callout`/`markup`/`parcel`) — verified by the adversarial review (the per-handler `startMoveEl/Markup/Callout/Parcel` paths all route through this one effect).
  - **View-shift reconciliation (review-found, B556 finding #1).** The pan-compensation effect (which offsets the drawing when the desktop panel resizes the canvas) was rewritten to track the **exact** px shift applied in a ref and reconcile to the desired value on `[leftPanel, narrow]` — so the phone overlay never shifts the drawing, and a mid-session **rotation** (crossing the 760px breakpoint with a panel open) can't leave a residual sideways offset. Replaces the old `prevPanelOpen` open/close toggle.
- **NOT changed (deliberate, confirmed by the review):** explicit **create** actions still open their panel — dropping/importing a drawing or duplicating an overlay (`setLeftPanel("overlay")`), finishing an easement/markup draw. Those are deliberate, not incidental taps; the overlay move/scale/rotate tap handlers never opened the panel to begin with.
- **Verify:** `ui-audit/verify-mobile-no-autopanel.mjs` 2/2 — phone keeps the panel CLOSED after selecting a building (handles still show); desktop still OPENS it (unchanged). Adversarial review workflow (6 findings → 3 confirmed; 2 already-handled/no-op, 1 view-shift fix applied; overlay finding dismissed as a wrong-premise false positive). The on-device feel (tap to select, then open Properties manually) is owed as **V170**.
