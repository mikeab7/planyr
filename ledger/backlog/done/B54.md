### B54 — `pullCloud` overwrites the per-user cache with `{}` when a cloud fetch errors `[Site Planner]` (bug) — data-loss-shaped, medium
`[x]` 🔧 fixed 2026-06-15 (branch `site-planner/b54-cloud-pull-guard`): `cloudList` now THROWS on a real fetch error (vs. a genuinely-empty result); `pullCloud` catches it, SKIPS the cache write, and returns `{ ok:false }`, so the cache (the user's last-known sites) is preserved; `applyUser` then shows a dismissible "showing your last synced copy" banner instead of a silent empty library. B18's separate half (merge-by-`updatedAt` + `sendBeacon`-on-pagehide) stays open — it carries a delete-resurrection subtlety, so it's deliberately left under B18. `cloudList` returns `[]` on *error* (cloudSync.js), so `pullCloud` can't tell "no sites" from "fetch failed" and blind-writes an empty map to the per-user cache; signing in while offline/unreachable thus shows "no sites" and wipes the local cloud cache to empty (data safe in Supabase, but a scary empty state that the user might start recreating into). Fix: have `cloudList` throw/return a status on error; `pullCloud` must skip the cache overwrite on error and surface a "couldn't load" state. (Sharpens B18/B37d into a concrete fix.)
