### B510 — Markup: Dimension tool showed "—" instead of its calibrated length `[Shared / Markup]` (bug) — HIGH  *(filed AND fixed the same lap per STANDING RULE #1; surfaced by the 2026-06-27 bug-hunt Workflow — found by two independent hunters, adversarially confirmed)*
`[x]` **DONE + verified. lint 0 · 1691 tests (+1) · build green.** The Dimension tool is declared `measureOutput:"length"` (`tools.matrix.js`) and rendered via `measureLabel` in `MarkupRenderer.jsx`, but `measureValue` (`src/shared/markup/measure.js`) had no `dimension` branch — it fell through to the generic return with no `lengthFt`, so `measureLabel` printed **"—"** for every calibrated Dimension (the tool's whole purpose — a ticked line labelled with its real length — was broken). Verified empirically: pre-fix `measureLabel({kind:"dimension",pts:[{0,0},{10,0}]}, 2)` returned `"—"` while the identical distance returned `"20.0 ft"`. **Fix:** `measureValue`'s distance branch now also handles `dimension`, preserving `m.kind` so it reports the calibrated `lengthFt` while callers still render the ticked variant. Deliberately NOT added to `MIN_MEASURE_PTS`/rollup — a dimension is an annotation, not a takeoff total, so totals are unchanged. New regression test in `test/takeoff.test.js` (`measureLabel` → "20.0 ft" calibrated / "set scale" uncalibrated / no-throw on empty). Pure-function fix; the on-canvas label is the visible win.
