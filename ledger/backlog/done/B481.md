### B481 — Large site-plan overlay didn't re-render after reload (stranded on the "Re-add" placeholder despite the raster being in IndexedDB) `[Site Planner / overlay]` (bug)  *(Cowork signed-in verification 2026-06-26, "NEW-1" — a 7.5 MB overlay showed "Re-add … not synced to this device" after reload though its ~10 MB raster sat in IndexedDB; minted **B481** = highest real B# (B480) + 1)*
`[x]` **DONE + verified (branch `claude/exciting-wright-yb6ruz`). lint 0 · 1597 tests · build green · NEW headless `verify-b480-overlay-large.mjs` 8/8 + `verify-b474-overlay-idb.mjs` 7/7 (no regression).**
- **Repro (Cowork, signed-in):** load a >~5 MB image as a sheet-overlay → it stores in IndexedDB (`raster:<proj>:overlay:<id>`, ~10 MB) with localStorage small → reload → overlay shows the "Re-add … not on this device" placeholder, even though the bytes are in IndexedDB *on this device* and the record carries an `idbKey`. The same large image as the **aerial underlay re-rendered fine** (separate, simpler effect).
- **ROOT CAUSE (not Cowork's guess of "gates on storageKey" — the effect DOES try `idbKey` first, SitePlanner.jsx:3551).** The overlay rehydrate effect had a `cancelled`-flag stranding race: a SLOW `idbGet` of a multi-MB raster was discarded whenever any other setState re-ran the `[sheetOverlays]` effect before the read resolved — the result was dropped AND never re-fetched, so the overlay sat src-less forever. A small raster resolves before any re-render (why the 7/7 small-overlay test always passed); the underlay uses a separate effect (why it worked).
- **FIX:** apply each rehydrate result via a functional patch-by-id guarded on `!x.src` (safe across re-runs — fills only an overlay still present + still src-less), and DROP the `cancelled` guard so a slow `idbGet` is never stranded. Plus the placeholder now reads "Loading drawing…" when an `idbKey` OR `storageKey` exists (recoverable) and only "Re-add … image not on this device" when neither does.
- **Verified:** `verify-b480-overlay-large.mjs` 8/8 — a 2.1 MB overlay (idbKey only, no storageKey, heavy src off the cap) re-renders after reload + view churn, no placeholder. Original 7/7 overlay test unchanged.
