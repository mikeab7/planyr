- **Confirmed in code (AUDIT-FIRST):** the Schedule grid's `selRange` was one rectangle; `cellMouseDown` ignored Ctrl; a drag extended only through per-cell `onMouseEnter`, so it died at the grid's edge. A Notes table's `CellSelection` is one rectangle and prosemirror-tables returns early on a Ctrl/Meta mousedown.
- **ONE selection model, not three.** `lib/selectionModel.js` moved to `src/shared/selection/rangeSelection.js` (the Spreadsheet's import path re-exports it), and the edge-scroll speed (`axisVelocity`) to `src/shared/selection/edgeScroll.js`. The Schedule page cannot `import`, so both are inlined between `RANGE-SELECTION` markers by `scripts/sync-sequence-selection.mjs` (the ownership/formula sync shape); `test/rangeSelectionInlineSync.test.js` fails on drift. The Notes tables import it directly. Added `selRowsOf`, `selEdgesAt`, `selIsRange`.
- **Schedule grid** (`public/sequence/index.html` `GridView`): `selRange` is now `{r1,r2,c1,c2,extra?}` (the Spreadsheet's shape) — every old reader keeps acting on the active range. **Ctrl/Cmd+click** adds the cell as a new range (earlier ranges stay highlighted, the active cell moves) · **Ctrl+click on a selected cell** takes it out (decided on release; no drag) · **Ctrl+click on a row number** adds the whole row · a plain click collapses · **Shift extends only the newest range** (click and Shift+Arrow / Ctrl+Shift+Arrow). **Drag-select edge-scroll:** one coordinate-driven session (`beginCellDrag`: window listeners + a rAF loop, row found from the pointer so an unrendered row is reachable, column read from the painted element, shared `axisVelocity` speed ramp, pinned columns respected) replaces the per-cell `onMouseEnter` extension; nothing extends or scrolls until the pointer has travelled (a press at the edge is a click — the NEW-1 row-drag lesson). Every range paints (tint, outline edges incl. the right-hand filler strip; the active cell keeps its own outline).
- **Commands across ranges, one undo step each:** Delete clears every cell of every range (or deletes the rows when EVERY range is a full row — non-contiguous rows delete together, one "N rows deleted" toast, one Ctrl+Z); bulk fill by typing/Ctrl-commit and the status/health picker take every range; the right-click format bar (bold, italic, fill, colour, size) takes every cell of every range; copy / cut take the rows of every range. **Refused out loud ("This action won’t work on multiple selections.", amber toast, nothing changes):** indent, outdent, "Move to…", drag-reorder of rows, Insert key — they are built on ONE contiguous block (`indentSelection`'s header said a discontiguous selection "cannot occur"; the comment is corrected). A plain press on a row number inside a multi-range selection collapses instead of picking the rows up.
- **Notes tables** (`lib/notesTableMultiSelect.js`): `MultiCellSelection` is a `CellSelection` subclass whose `ranges` hold every selected cell, so bold/italic/colour/size/alignment (they walk `selection.ranges`), the highlight, Delete and cell fill / No fill (`notesTableFill.js` → `multiCellPositions`) reach all of them. Ctrl/Cmd+click adds a cell / takes a selected one out (merged cells by their whole span); a plain click collapses. It claims a Ctrl press ONLY while the editor has focus (an entered box): a Ctrl press on a box that is not entered is still stage 1 of select-then-enter, the border still moves the box, a drag from content still pans — untouched. Copy, cut, paste and the table-structure buttons (row/column insert-delete, merge/split, header row, select/delete table) refuse with the same message.
- **Not built, said plainly:** Ctrl+DRAG of a rectangle and drag edge-scroll inside a Notes table — the Notes page has its own pan/zoom viewport and the browser's text-selection autoscroll is the only drag-select there (the owner's Notes ask was Ctrl+click; Shift+click in a Notes table still collapses to one rectangle). Indent/outdent per contiguous run on a multi-range Schedule selection (refused instead, loudly).
