`[x]` **AUDIT-FIRST — checked how the existing "Dock layout" presets relate to paving/drive elements before writing a line of code, per the ticket's own instruction.** A cross-dock building (`dock:"cross"`) already builds a genuinely SEPARATE truck court / trailer parking / buffer stack per side — real, distinct site elements bonded via `truckCourt.side` (`findCourtIn(arr, b, side)` is already keyed on `side`, and has been since B228). What was NOT independent: every edit path — `setZoneDepthAll`, `setZoneLengthAll`, and the two display readers `zoneDepthShown`/`zoneLengthShown` ("the first dock side that has one") — deliberately forced the SAME value onto both sides ("the stack is mirrored, so depths stay uniform," per the removed code's own comment) and showed one side's value for both. So this needed new WRITE logic (independent per-side setters), not a new association — the association already existed. **Only "adjacent-side" docks (e.g. north AND east on one building) are out of scope**: the product's "Dock layout" presets are Single-load (one side) / Cross-dock (always the two OPPOSITE long walls) / No docks — there is no configuration anywhere in the codebase for docks on two adjacent (non-opposite) sides, and building one would be new geometry/preset work, not a labeling or independence fix. Nothing in this item builds that; flagged here rather than silently assumed out of scope.
`[x]` **Compass labels, derived from the building's own rotation — never hardcoded N/S.** New pure `dockSideCompassLabel(side, rot)` (`lib/dockZones.js`, plus its `dockSideBearing`/`compassLabelForBearing` halves): a dock side's outward-face bearing is its un-rotated bearing (top=0°/N, right=90°/E, bottom=180°/S, left=270°/W) plus the building's `rot`, using the SAME clockwise-rotation convention `sitePlacement.rotPt` and the deed-parsing azimuth code already use (0° = north, clockwise). A 45°-rotated cross-dock building reads NE/SW — the ticket's own worked example — proven by unit test, not eyeballed.
`[x]` **Independent Width/Depth per side, edited separately in the truck court's own properties-panel entry.** New `setZoneDepthOnSide(b, side, i, newDepth)` / `setZoneLengthOnSide(b, side, i, newLen)` (single-side siblings of the removed `setZoneDepthAll`/`setZoneLengthAll`) — the dock-zone element's own panel (opened by clicking that specific court/trailer/buffer) now reads and writes ONLY the selected element's own side, via `zoneDepthOf(selEl, b, side, i)` and the element's own laid-out `w`/`h`, instead of the old "first dock side that has one" readers. The building-level "Zone depths · both dock sides" quick-set section (for setting both sides at once on a symmetric building) is UNCHANGED and still uses the mirrored setters — it is already honestly labeled as applying to both sides, and remains a deliberate convenience alongside the new per-element independence, not a contradiction of it.
`[x]` **Distinguishable wherever the two sides could otherwise look identical.** `dockZoneDisplayLabel(z)` (new, `SitePlanner.jsx`) returns e.g. "Truck court · NE" for a dock-zone element on a multi-sided building (bare "Truck court" on a single-dock building, where there is nothing to tell apart) — wired into both the compact selection header ("Element · Truck court · NE") and the Properties panel's Section title ("Selected · Truck court · NE"), the two places a generic "Paving / Drive" label made two courts read as identical shapes. Also added the same compass suffix to the on-canvas right-click "Dock zones" per-side rows and the docked building panel's "Dock face" readout (both previously said only "Top"/"Bottom", true only at rot=0). This product has no separate persistent "site elements" inventory list (the "Site elements" heading in this codebase names the DRAWING-TOOL rail, not a list of placed instances) — the selection header and Properties title are the actual places two same-type shapes read as identical, and both are now fixed.
`[x]` **Dead code removed, not left half-migrated.** `setZoneLengthAll`, `zoneLengthShown`, `zoneLengthPinned`, and `courtLengthShown` had no remaining call sites once the per-zone panel switched to the per-side reads/writes above (the building-level quick-set section only ever covered Depth, never Length) — deleted rather than left as unused dead functions.
`[x]` **Unit tests for the new pure library function**, `test/dockZones.test.js`: cardinal cases (rot=0 → N/S/E/W, matching `top`'s outward normal being north), the ticket's own 45°→NE/SW example, a 90° quarter turn, negative/>360° wrap, and all 8 compass points.
