### B579 — Document Review robustness batch: stuck detail-popup capture · failed-delete mirror desync · silent PDF-store failure `[Document Review]` (3 bugs)  *(self-found 2026-06-29 by the improve loop's lap-7 hunt; minted **B579** = highest real B# across both files (B578) + 1)*
`[x]` **DONE + verified the same session. lint 0 · 1874 tests (+3 anti-drift) · build green.** Three distinct, hand-verified defects from one lap (the hunt's other lens, GIS/layer plumbing, came back clean):
- **Detail popup kept pointer capture on an interrupt (`Stitcher.jsx`).** The Bluebeam-style detail "cloud" popup set pointer capture on `onPointerDown` and released it on `onPointerUp`, but `onPointerCancel` only cleared the drag state — so a browser interrupt (blur / tab-hide / OS gesture) mid-pan left the popup holding capture, swallowing every click/drag/wheel with a stuck grab cursor until it was closed and reopened. Same class as B551 on the main canvas; fixed by releasing capture in `onPointerCancel` too.
- **A failed review delete desynced the local mirror (`reviewStore.js`).** `clearDraft` ran *before* the cloud `delete`, so a delete that errored (network/auth) left the cloud row alive but the local resume-mirror cleared — the review lingered in the library yet could no longer auto-resume. Now the mirror is cleared **only on a successful delete**, keeping a failed delete in a consistent, retry-able state.
- **A genuine PDF-store failure was silent (`DocReview.jsx`).** When BOTH backends (Drive *and* the Supabase fallback) rejected a dropped PDF — not merely `oversize`, which still saves the work layer and flags "re-drop on load" — the source stayed permanently keyless, so `buildSnapshot` persisted `sources:[]` and the markups reloaded with **no backdrop**, with no warning. The drop path now surfaces an error banner on a real failure, **gated on `cloudReady()`** so logged-out local-only mode (bytes cached, work mirrored locally) stays quiet.
