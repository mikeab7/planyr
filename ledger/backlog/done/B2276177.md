- **Cause (three defects, one symptom), all reproduced with `teeJunctionsOf` before touching code:** (1) `armStraightRun` (`lib/roadJunctions.js`, from B1832210) capped an arm at `leg − T` for the IMMEDIATELY adjacent interior vertex even when nothing is drawn there (a collinear vertex, another road's tee node on a straight trunk) — a run shorter than the side road's half-width puts `nodeJunction`'s corner past the run, `tMax = 0`, that ONE corner SQUARE (measured: stray vertex 6 ft off the node → `R 24.0, 0.0`; both sides → `0.0, 0.0`). (2) A leftover connect vertex that survives load is a MILD bend (> 1.5 ft off the chord, a real arc corner whose tangent run is clamped to a few feet) — less STRAIGHT run than the corner needs. (3) `teeNodeIndicesOf` stored a VIRTUAL tee's index (`teeTargetPointOf`'s splice index, valid only in the local spliced copy) as a sharp-vertex index against the REAL `G.pts` — it named an unrelated bend (measured: a virtual tee beside a 60° bend marked vertex 2 sharp), while `roadJunctionVerticesOf` (vertex-only `teeTargetOf`) never flattens a virtual node, so the two maps disagreed.
- **Fix:** `armStraightRun` walks on through vertices turning the road by under 3° (`STRAIGHT_THROUGH_DEG` — another road's tee node on a straight trunk included) and stops at a real bend at its arc entry exactly as before (the 57° Goose Creek spike guard is a test); it also returns `soft`, the run past MILD bends (≤ 15°, `SOFT_BEND_DEG`). `nodeJunction` falls back to `soft` — tangent capped at 8 ft (`SOFT_TANGENT_FT`) — when a corner's `tMax` would be 0, so the return SHRINKS instead of vanishing (measured 24/8 where it was 24/0). `teeNodeIndicesOf` records real vertices only, and `teeJunctionsOf` shifts that set into the spliced copy's index space when the through road is virtual-spliced.
