- **Repro.** Drag a building, then press Ctrl+Z within ~2 s. `applySnapshot` restores the full pre-move state locally but never calls `flushElems()` — unlike every other gesture end (`onUp`). The undo therefore trails on the engine's ~750 ms debounce while the move's batches are still going out, and the server ends up with a mix of moved and restored members. Ctrl+Z is not the CAUSE of the tear (B1094 is) but it reliably makes it worse.
- **Fix.** An undo/redo is a gesture boundary and commits immediately. `applySnapshot` now flushes — **against the SNAPSHOT, not `stateRef`**: React has not re-rendered when the handler runs, so `stateRef` still holds the state being undone and diffing it would have re-committed the move. `reconcileElems`/`flushElems` take an explicit state override, and a new `syncStateOverride` ref installs that snapshot for the engine's `liveCollections()` read for the duration of the synchronous flush (without it B1094's freshen pass would have re-read the stale `stateRef` and undone the undo). `drainRemote()` is skipped on a snapshot flush — a snapshot already knows what the canvas holds. Covers redo and the Esc mid-drag cancel (`cancelActiveMove`) by construction; no-ops when the plan isn't cloud-synced.
- **Tests.** `test/assemblyTear.test.js` — restoring a snapshot and flushing commits ON THE SPOT (one more commit, **zero pending timers**) and carries the whole assembly at the restored coordinates; plus two anti-drift source guards (that `applySnapshot` flushes with `s`, and that the override reaches the engine's live read). `e2e/ctrlz-undo.spec.js` (5 pre-existing logged-out cases) re-run green, so the local undo path is unregressed.
- **What is still owed (V509).** The signed-in race itself: drag, Ctrl+Z inside ~2 s, and confirm the rows settle to the pre-move geometry with no mixed state.

- **AUDIT-FIRST — the brief's two named fixes were ALREADY IN PLACE, and neither could have prevented this. Recorded rather than silently "fixed", because it changes where the defect is.** (1) `closeAssemblies` already runs for EVERY batch, not only gesture flushes — it is called unconditionally at the top of `flush()`. (2) `freshen` is already unconditional and already reads live canvas bytes at flush time regardless of `syncStateOverride` (that ref only shortens the window during the synchronous snapshot flush). **Both ran, and both were correct.** The straggler was 2 ops precisely BECAUSE closure works: only those two elements genuinely disagreed with the server, so there was nothing else to fold in. And `freshen` faithfully sent what the canvas held. **The canvas itself was wrong** — which is upstream of the write path entirely.
- **ROOT CAUSE — a buffered remote instruction with a FROZEN payload, replayed across the undo.** A `postgres_changes` row that arrives while `busyRef` is true (mid-gesture, and the flag outlives pointer-up by a render) is converted to a canvas instruction **at arrival time** — `const instr = eng.applyRemoteRow(row)` — and parked in `pendingRemoteRef` with its `el` payload frozen (`SitePlanner.jsx`, the B672 mid-gesture buffer). It is applied at the next `drainRemote()`. If an undo lands in between, that drain writes **pre-undo geometry** back onto a canvas the user has just restored, for whichever elements happened to be in the buffer — and the next diff dutifully commits the re-torn canvas as a fresh edit. Two elements were in the buffer; hence 2 ops, hence pre-undo coordinates, hence ~4 s later.
- **Fix — the applied snapshot is the authority, on BOTH the buffered and the live path.**
  - **Buffered (the measured path).** `applySnapshot` now drops every buffered **UPSERT** minted before it — those describe a world the user has explicitly discarded. A buffered **REMOVE is KEPT**: a remote tombstone is not undone by a local undo, and dropping it would resurrect a deleted element (**TOMBSTONE-DELETES**).
  - **Live (the same hole, one beat later).** An echo can also arrive in the window right after the restore, with no buffering involved. `elementSync` now carries a **local-authority epoch**: `noteLocalAuthority()` (called by `applySnapshot`) bumps it, and every serialization this tab puts on the wire is tagged with the epoch it was sent in. In `applyRemoteRow`, a row whose bytes are **ours, sent at an older epoch** adopts the rev into the shadow but is **kept off the canvas** — so it cannot resurrect what the user just undid. The shadow then disagrees with the canvas, which is correct: the next reconcile re-asserts the SNAPSHOT's geometry, **assembly-closed, as one batch**. A foreign row, or an own echo from the current epoch, is completely unaffected (the B672 stale-seed re-true still works).
- **The invariant now enforced, in the owner's words:** no batch may leave with a payload older than the most recently applied snapshot — enforced at the source, by never letting that payload reach the canvas in the first place.
