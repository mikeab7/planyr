### B315713 — Show which project a note belongs to while reading and editing it `[Notes]` (feature) #notes #ui  *(owner chat block, 2026-08-09)*
`[x]` So a wrong stamp is visible at a glance.
- Verify: sandbox
- Origin: filed 2026-08-09 from chat (NEW-2).
- **WHY THERE WAS NOWHERE TO SEE IT.** Inside a project the rail deliberately drops the per-row project badge (everything on screen belongs to where you are standing, B1420), and the Dashboard's grouping is a level up from the page. So a note copied into an unrelated pursuit looked exactly like a note in the right place. The one surface always on screen with the note — the note's own header — said nothing.
- A quiet chip beside the title, derived from the page's ROOT so a subpage answers with its root's project and there is never a second copy of the fact. It is a LABEL, never a control: re-filing stays on the row's menu, one place. **A project id that no longer resolves is NAMED as unresolved** and wears the warning colour, rather than being captioned as "no project" — a failed lookup and a page that genuinely belongs nowhere are different states, and describing the first as the second is what made a mis-filing invisible (B482 ×2's lesson, applied one level down).
- Proven: `ui-audit/verify-notes-project-integrity.mjs` §3 — the chip's project is read back against the TREE, not against what the viewer supplied, in all three states (resolved · unresolved · genuinely no project).
