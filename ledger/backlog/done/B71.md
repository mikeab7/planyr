### B71 — Per-element curb override on trailer parking (6″ → 12″) `[Site Planner]` (feature)
`[x]` Selecting a trailer-parking element exposes a curb selector: default 6″, option 12″ (heavier curb to take trailer-tire/dolly abuse). 12″ = 1.0′ of plan-view width (double the 6″ curb's 0.5′) — real plan width, not a taller face/reveal (height unchanged). Flows through the same three-way rule as B70: drawn in the visual field, included in calculations (a trailer section with a 12″ terminal curb counts the full 1.0′ in area/width math), excluded from the displayed dimension (185′ still reads 185′). Build the property globally underneath (any band could carry it) but surface the control only on trailer parking for now.
> Done 2026-06-15 (branch `claude/nice-wozniak-2k2v9c`). The width is a global per-element field `el.curbW` (`CURB_6 = 0.5` / `CURB_12 = 1.0`) read by `curbWidthOf(el)`, so any band *could* carry it; the **6″ / 12″ control is surfaced only in the selected-trailer panel** (`setCurbW`). It rides the B70 model end-to-end: the drawn band scales to 1.0′ (visibly double), `curbAreaOf` counts the full 1.0′ in the SF/width math, and the displayed dimension is untouched (still face-of-curb). Trailer fields show no on-canvas dimension number today, so there's nothing to wrongly include the curb in; the rule holds the moment one is shown. Verified: a 12″ curb on a 300′ edge = 300 sf vs the 6″ 150 sf; build + tests pass.
