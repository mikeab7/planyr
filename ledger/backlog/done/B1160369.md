`[x]` **SHIPPED THIS SESSION.** `NoteToolbar.jsx`'s `spacingControl` hardcoded its `<select>`'s `value` to `""` on every render, so no state could ever reach the box — confirmed by reading the code, not just the report. Added `selectionLineHeights(doc, from, to)` to `lib/notesMixedSelection.js` (the `lineHeight` analogue of the existing `selectionFontSizes`/`selectionBlockShapes`, walking every textblock — paragraph or heading — since the property lives on both) and wired it through the same `formatDisplayValue`/`MIXED` machinery Font size and Block style already use. The control itself is now a `FormatMenu`, not the native `<select>` it was — a deliberate design change, not merely a data fix, and stated as such: a native select ties its CLOSED box's text to the exact string of whichever option is selected, so making `value` honestly track state would have forced the box to show the full row text ("Lines: Double") the moment anything was set, and this control is deliberately kept narrow (its own file's PANEL-BREVITY note: "one glyph wide… the formatting row is full at a laptop width"). `FormatMenu` gained an optional `displayLabel` prop so the trigger can show a short current-state word (`spacingLabel()`'s own short forms — "Double", "Single", "1.15", "1.5", or "Spacing" for the unset/default case, closing the separately-reported ICON-4 in the same fix) while the open dropdown keeps its full, unabbreviated option text. A mixed selection now shows a blank trigger with the title "Line spacing — mixed", matching Block style/Font size exactly. The RULED-OUT dead-click concern does not apply to the new shape either way: `FormatMenu` dispatches `onPick` on every real click, same as Block style/Font size already do, never a native `change` event that can silently no-op on a re-picked value.
- **VERIFIED (sandbox, live headless, both themes, three viewport widths).** Real double-click + Shift+End selections against a seeded fixture (paragraphs at `lineHeight` 2, 1.15, and unset): the trigger read "Double", "Single", and "Spacing" respectively; a selection spanning the Double and Single paragraphs read blank with title "Line spacing — mixed"; picking a new value from the open menu updated both the trigger and the stored ProseMirror document (`localStorage` read back after the save debounce). The control's width (`88` → tuned to `82`) was measured against real DOM layout at 1024/1280/1400px to find the exact value that shows "Spacing" (the longest label) without ellipsis-truncating it AND without wrapping the toolbar row to a second line — both failure modes were hit and fixed during tuning, not assumed away.
