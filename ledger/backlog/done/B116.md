### B116 — Measurement tools (Length / Polylength / Area) in Site Planner `[Site Planner]` (feature → already implemented)  *(arrived as "NEW-1"; committed provisionally as B115 — renumbered B116 after main's #72 took B115 for "revisit keyboard shortcuts")*
`[x]` Done 2026-06-16 (branch `claude/youthful-heisenberg-9w64n4`). **Dedupe outcome: already implemented — this is the "the app already had them" case the PHASE E spec and this very task anticipated.** Site Planner's `measure` tool already ships all three calibration-aware modes; nothing was rebuilt. Evidence in `SitePlanner.jsx`:
- **All three modes present + surfaced:** the **Measure** rail button + `▾` mode menu (Length / Polylength / Area) — `measureMode` state persisted to `localStorage` (`planarfit:measureMode`); two-click **Length**, running-path **Polylength** (accumulate points), closed-polygon **Area** (click the first dot or double-click to close). Click handling, `finishMeasure`, `selectMeasure`, delete, and the in-progress draft preview all exist and work.
- **Area label already matches the spec exactly:** renders `"<sf> sf · <ac> ac · <perim>′ perim"` (e.g. `12,300 sf · 0.28 ac · 462′ perim`) — perimeter closes the loop; Length/Polylength label the running feet.
- **Calibration-aware, as specced:** labels read from `calibrationState`; when an underlay is `uncalibrated` they render **amber (`#b45309`) with a `⚠`** and the rail shows the **"Underlay isn't calibrated — distances may be wrong"** banner (same behavior as Document Review / PHASE E). A drawn/georef/calibrated plan labels in the normal accent.
- **Own editable layer; export behavior consistent:** measurements live in their own `measures[]` layer (migrated `{a,b}`→`{mode,pts}`), persisted in the Site Model. They export alongside callouts/markups — consistent with the existing annotation architecture (the only `data-export="skip"` users are transient chrome: grid, basemap, scale bar, north arrow, zoom/layers UI, draft previews). Reuse note: the Document Review takeoff math (`takeoff.js`) and the Site Planner helpers (`polyArea`/`centroid`/`pathLen`) compute the same geometry — doc-review in page-units×calibration, the planner natively in feet (the shared EPSG:2278 spine) — so no port was needed.
- **Finish UX:** double-click **or Enter** commits (shared `finishActiveDrawing`, per B103); **Esc cancels** the draft. The task floated "Esc to end" — deliberately **not** adopted, since Esc-cancels-the-draft is the universal convention used by every other multi-point tool in the app; double-click/Enter already satisfy "click points → end".
- **Only change made (label alignment):** the mode display names were **Line / Polyline / Area**; renamed to **Length / Polylength / Area** — Bluebeam's own terms (Planyr is "Bluebeam-style") and the names this task uses, which also **disambiguates the measurement from the markup "Polyline" tool** (`mpolyline`, ⇧N) that shared the word. Label-only via a module-level `MEASURE_MODES`/`measureModeLabel`; the internal `measureMode` values (`line`/`polyline`/`area`) are untouched, so `localStorage` and all logic are unaffected.
