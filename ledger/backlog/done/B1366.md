- **⚠ AUDIT-FIRST, recorded rather than glossed: no Delete-key handler was found anywhere on the Notes route.** `NotesTree.jsx` had no key handling at all, and the Site Planner's window-level Delete listener returns immediately when its workspace is not `active`, so a kept-alive planner cannot eat a key while Notes is on screen (checked, not assumed). What the rows DID have was four destructive-adjacent controls appearing UNDER THE POINTER on hover, the last of them a 🗑 — which is the same defect the report describes from the user's side, and which B1367 removes outright.
- **What shipped:** the row is now a real `treeitem` with focus, and its key handler answers Enter/Space and the context-menu keys and **nothing else**. Delete and Backspace fall through unhandled, on purpose and in writing, at the code and in the file header.
- **The guard is what makes it permanent:** `ui-audit/verify-notes.mjs` §21 hovers a real row in a real browser, presses Delete and then Backspace, and asserts the stored tree is byte-identical afterwards and that no Undo bar was even offered. A behaviour that is currently absent is one commit away from being present; this is what stops it growing back.
