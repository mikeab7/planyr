- **The honesty rule (the actual ask).** A phone's GPS fix is genuinely precise (tens of feet); a laptop with no GPS chip falls back to Wi-Fi/IP-based positioning, reported through the SAME `accuracy` field but potentially miles off. Both must not be drawn the same way. New pure module `src/workspaces/site-planner/lib/locateMe.js`: `shouldShowAccuracyCircle(accuracyMeters)` gates the accuracy-circle draw at **500 m** (above ordinary GPS/Wi-Fi noise, below "this only knows roughly which side of town"); below the threshold, the map draws a "you are here" dot + a proportionally-sized accuracy ring; at or above it, the map still centers on the best guess available (never silence) but shows an honest "Location is approximate (accuracy ±N mi)" toast instead of a ring that would overstate confidence. `formatAccuracyFt`/`locateErrorMessage` are the other two pure leaves (feet-below-a-mile / miles-above formatting per this app's convention; every `GeolocationPositionError.code` → a plain-English sentence, never a raw browser message, never silent).
- **Permission + failure handling.** No `window.prompt`/`confirm`/`alert` (KEY DECISIONS). A press shows a spinning/dimmed pressed state (the existing `spin` keyframe in `index.css`, applied inline — this is a raw Leaflet DOM node, not React) so a press never reads as inert; a 2nd press while one is in flight is a no-op, not a 2nd request. Denied / timed-out / unavailable all surface through the map's existing bottom-left error-toast slot (`setErr`) — reused rather than inventing a second notice mechanism.
- **Theme:** the marker/circle color is `PAL.accent` (`var(--accent)`), matching this file's own existing precedent for Leaflet vector-layer color (the "Selected parcels" highlight at line ~1348 already passes a `var(--...)` string straight to `L.polygon`'s `color` option) — not a raw hex.
