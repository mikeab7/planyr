`[x]` **Shipped this session. *Moves to BACKLOG-DONE on merge.*** New **pure, dependency-free** `lib/roadGeometry.js` + `test/roadGeometry.test.js`, matching the repo's pure-lib pattern (`metesAndBounds.js`, `polygonSplit.js`) — **no JSTS** (B150 avoided it deliberately).
- `roadCenterline(pts, vtx, { defaultRadius })` → a **tessellated dense polyline** (the rendered centerline) that B601 offsets. Per interior vertex `treatment`:
  - **Sharp** — radius 0, hard corner (vertex unchanged). `sharp == input polyline`.
  - **Arc** — circular **fillet tangent to both segments**, radius **feasibility-clamped** so the run-up `T = R·tan(θ/2)` never exceeds half the shorter adjacent segment (θ = deflection angle), emitted as short tessellated segments. **Default treatment.**
  - **Smooth** — vertex is a **through-point of a Catmull-Rom-style interpolating curve** (tangent from neighbours), tessellated — for tracing curves off an aerial.
- Treatment is **per-vertex and convertible after drawing** (pen-tool style): click a road vertex on the canvas to select it, then flip **sharp ↔ arc ↔ smooth** in the Element panel (Arc seeds the class default radius, editable). No global tool mode, no spacing threshold — dense clicks + the clamp produce smoothness naturally. `minRadiusOfCurvature` (circumradius of consecutive triples) backs the B602 civil check, uniformly for arc and traced/smooth runs.
- **Tests (21):** clamp never overruns a segment; arc tangent at both ends; spline passes through its points; sharp == polyline; tessellation density scales with `tessDeg`; min-radius recovers a known circle + finds the tightest along a mixed alignment; + the B602 class-threshold math.
