- **Root cause.** Both panels dock to the map's right edge (`mapChromeStack.js`: Layers at `topright`, Adjust at `bottomright`) and each sizes itself to the room between its own edge and the OTHER edge's furniture clearance — with no awareness of the other panel's actual rendered height. On a short window (both of the owner's reported real sizes) both panels' `panelMaxHeight` resolve to nearly the full map height, so they collide across their whole shared width even though each is individually well-behaved.
- **The fix.** There is no fifth corner to move either panel to (`mapChromeStack.js`'s header already assigns all four), and at a 465px-tall window there is provably no clearance number that lets two independently-sized full-height right-edge panels coexist — so per the dispatch's own second option, the Layers panel now YIELDS. `MapFinder.jsx`'s new `sitePlanAdjustOpen` state (fed by `SitePlansSection.jsx`'s new `onAdjustOpenChange` callback, reporting `open && adjustOpen` so a section that goes inactive can't leave a stale `true`) force-collapses the Layers panel to its header chip the instant the docked Adjust panel opens, and its own toggle refuses to reopen it while Adjust is open (title explains why, matching this repo's "never a control that looks clickable and silently does nothing" convention) — restoring whatever the user had (open, on desktop's default) the moment Adjust closes. This is a temporary yield, not the user's own choice, so it never writes through `toggleLayersPanel`'s `localStorage` persistence. `mapChromeStack.js` gets a new header section recording why a clearance constant can't fix this class and pointing at the yield relationship instead, for the next panel that claims a corner another tall panel can also reach.
