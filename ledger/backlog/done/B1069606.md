`[x]` **SHIPPED THIS SESSION, both leaks.**
- **Standalone period word.** `extractUnlabeledLine`'s rate-claim block (`compParse.js`) already blanks a claimed rate token and any inline NNN/GROSS basis word out of the line's `working` copy — but `detectPeriod(line)` (which SETS `generic.ratePeriod`) reads the ORIGINAL line and never blanked anything, so a period word that wasn't part of the rate token's own compound match (e.g. "annual" following "NNN" rather than glued to the rate as "/mo") was read correctly but never removed, and fell through into Notes as unrecognized leftover text. Fixed the same way the basis word already was: capture the `PERIOD_RE` match before reassigning `working` and blank it too — a consumed token now never survives in Notes, for every branch of `findRateToken`, not just the compound one HARDENING-23 already covered.
- **Comma-stripped double space.** The leftover-notes line replaced `[,;|]+` with a single space but never collapsed the run of whitespace that produced ("Houston," + " TX" → "Houston" + " " + " TX" = two spaces). Added a `.replace(/\s+/g, " ")` pass after the comma strip, before `.trim()`.
- Verify: sandbox — pure parser logic, no LIVE-VERIFY class applies.
- **Self-verified:** two new cases in `test/compParse.test.js` (105→109 tests, all green): `.56/SF NNN annual` and `.../monthly` never leave a stray period word in Notes while still reading rate/period correctly; `6.72/SF/yr NNN Houston, TX 77073` now leaves Notes exactly `"Houston TX 77073"` (single space, asserted with a `not.toMatch(/ {2}/)` guard). `npx vitest run` 688/688 files green.
