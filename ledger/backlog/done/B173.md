### B173 — App pinned to the viewport; map scale bar always visible `[Site Planner / UI + Shell]` (bug)  *(arrived as "NEW-2"; filed provisionally as B168, renumbered **B173** — #152 + #153 collisions; next free after B171.)*
`[x]` Done 2026-06-19 (branch `claude/optimistic-wozniak-4iltkx`). Root cause: nothing guaranteed the app couldn't grow taller than the window, so the page itself could scroll and push the bottom-of-canvas scale bar below the fold (and the header off the top). Fix is structural, not a scale-bar move: `index.css` now sets `overflow:hidden` on `html, body, #root` and pins them to `100dvh` (dynamic viewport height — handles mobile browser chrome) via `@supports`; `Shell.jsx` adds a defensive `overflow:hidden` on the shell column. The in-canvas measurement-grade scale bar (bottom-right, `lib/sheetFurniture.js`, shared with print/export) sits a fixed 40 px above the canvas bottom, so once the page can't scroll it is **always** visible — no need to fork a second portal-mounted overlay (kept export parity; the owner's "bottom-left fixed overlay" was the suggested mechanism, the real need was "always visible," now met). **Self-verified headless at 1440×900 AND 1280×600:** `document.scrollHeight === innerHeight` (no page overflow) at both sizes, and the scale bar + north arrow render at the canvas bottom with both header rows visible simultaneously.
> **Dedup note:** distinct from completed **B144** (scale bar clipping/measurement-grade in print/export) — this was on-screen viewport layout.
