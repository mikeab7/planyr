`[x]` **SHIPPED THIS SESSION.**
- **Root cause, measured, not reasoned from the symptom.** `SheetView.jsx`'s frozen row renders as `position: sticky`, permanently pinned at a constant pixel offset in the viewport once scrolled at all. Every OTHER (scrolling) row renders `position: absolute` at `top: headerH + offsets[r]`, computed from the SAME cumulative row-offset table (`rowLayout.js`) the frozen row itself uses — with no adjustment for the space the now-pinned frozen band occupies. `rowLayout.js`'s `visibleRowRange` clamped the render window's row INDEX to `>= minIdx` (never re-render the frozen row's own index as a scrolling row) but said nothing about where that row's PIXELS land once frozen — so an early scrolling row (e.g. index 3, "Soft cost") could still compute a top a few dozen pixels UNDER the pinned frozen band. z-index (the frozen band paints above, `zIndex: 3`) does not reliably hide this: a cell's own background does not opaquely cover every sub-pixel of its row, so the row underneath visibly bled through — measured live at the exact repro numbers (freeze the top row, `scrollTop: 60`, `~22px` rows): row index 3's computed top was `32px`, 16px INSIDE the frozen band's own `[26,48]` occupied range.
- **Fix:** `visibleRowRange` now computes the first render-eligible row from `scrollTop + offsets[minIdx]` (`offsets[minIdx]` — the frozen band's own total height, in the same cumulative units) rather than raw `scrollTop`, via a new ceiling search `firstRowAtOrAfter` (the smallest row whose own top is `>=` the threshold — the floor-search `rowAtOffset` a plain unfrozen edge correctly uses would still let the chosen row START a few pixels before the boundary, which still overlaps by exactly that sliver; verified this distinction matters with a live math trace before shipping, not assumed). The existing BUF top-of-window headroom (pre-rendering a few extra rows for scroll smoothness) is skipped specifically for the frozen case — those rows would be exactly the hidden-under-the-band ones the bug renders. An unfrozen sheet (`minIdx === 0`) takes the exact old code path, byte-for-byte, and is unaffected — proven by a dedicated regression test.
- **Verified live at the exact repro:** freeze top row alone + scroll → garbled ("Line Item"/"Soft cost" on the same pixels) before, clean after. Freeze top row + first column + scroll → same. Both themes.
