- **Investigation (audit-FIRST, as the brief demanded): a 6-dimension parallel auditor sweep + a two-skeptic adversarial verify pass (refute-the-claim + check-the-fix) over the whole persistence layer.** 18 candidates raised, 15 refuted; **3 survivors all converged on ONE root cause** (a CONFIRMED verdict that I could not refute), correcting the owner-session's initial guess (a missing immediate local mirror — already shipped as B458).
- **Root cause (NOT B134's #3 debounce-flush or #4 silent-error — a sixth, previously-unidentified cause):** drawn-element ids came from a single per-tab module counter `uid() = "e"+_id++` (`SitePlanner.jsx`), and `ensureIdAbove` re-seeded that counter at load from **only `parcels`+`els`** — never `markups`/`measures`/`callouts`/`deletedIds`. So the load-bearing invariant the tombstone system rests on (literally commented "ids are never reused, so tombstoning by id is safe") was **FALSE**: (a) after reopening a plan the counter could sit BELOW a markup id already deleted (its id sitting in `deletedIds`), so a freshly drawn polyline was minted with a **tombstoned** id; (b) two tabs of the same plan re-seeded identically and minted **colliding** ids. When `mergeSiteContent` then ran (cross-tab `storage` sync, take-over reconcile, or boot pull), its tombstone filter (`live()`, `siteModel.js`) **stripped the just-drawn polyline** → it vanished mid-session with no reload, and the thinned model was persisted to device + cloud (a later reload lost it again). The immediate B458 mirror is a sole-tab plain replace that KEEPS the polyline, so the B473 read-back's count check passed — which is exactly why nothing alarmed at draw time (→ B595).
- **Fix (the verifiers explicitly REJECTED the tempting fixes — weakening `mergeSiteContent`'s tombstone filter / a `localOnlyIds` carve-out — as regressing B276/B556/B480; the endorsed fix is unique ids):**
  - **New pure `src/shared/ids.js` (`createIdMinter(salt)` + `randomIdSalt()`).** `uid()` now carries a per-tab **salt** (6 random lowercase letters) appended to every id, so two tabs/sessions can never mint the same id and a fresh add can never equal a retained tombstone. Salt is **letters only**, so `seedAbove`'s `parseInt(replace(/\D/g,""))` still recovers the sequence number for ordering. Legacy short ids ("e5") keep working; no data migration.
  - **`ensureIdAbove` now seeds from EVERY id-bearing collection + tombstones** (markups/measures/callouts/deletedIds, not just parcels+els) at both call sites (restore + import) — defense-in-depth + monotonic ordering.
  - **Comment at the tombstone helper updated** to record WHY reuse is now impossible (the salt), so the invariant can't be silently re-broken.
