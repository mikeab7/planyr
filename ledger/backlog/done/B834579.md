### B834579 — Map-route element strokes are a flat 1px at every zoom 15-21, reading as a mesh of hairlines when zoomed out `[Site Planner / map]` (bug) #site-planner #gis #ui  *(owner chat block 2026-08-28. Minted **B834579** from the same reserved block. DEDUPE-FIRST: no prior item.)*
`[x]` **SHIPPED — element stroke weight now ranges 0.5px (at PLAN_ZOOM=15) to 1.5px (six zoom levels up), linear, clamped**, computed once when the plan layer is (re)built.
- Verify: sandbox
- **⛔ DELIBERATELY NOT a live per-zoom-tick recompute, and this is a real engineering tradeoff, stated rather than silently taken:** the effect that builds this layer explicitly does NOT depend on `zoom` (see its own B64 comment: a rebuild mid-gesture drops the path a press landed on, silently swallowing the click). A per-tick `setStyle` across hundreds of paths on every zoom frame was considered and rejected — it would add live per-tick work to exactly the hot path B834580 was built to protect. So the stroke weight is resolved at the zoom the layer was last (re)built at (crossing PLAN_ZOOM, or any other change to this effect's deps — filtering, selection, the site list); it does not continue thinning/fattening as the user zooms further without a rebuild. This fixes the reported case (hairline mesh at the low end, right where a plan first becomes visible) without adding a new perf risk.
- **Confirmed via a real browser render:** stroke-width read off an element `<path>` — flat `1` at both a low and a high zoom pre-fix; `0.5` at the PLAN_ZOOM crossing and `1.5` after a rebuild forced at zoom ~21 (via a real status-filter toggle, not a synthetic call) post-fix.
