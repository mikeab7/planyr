### B353 — B331 pinch regression: the new pinch handlers clobbered Site Planner vertex editing `[Site Planner / Markup]` (bug)  *(found by owner-requested stress test of B331, 2026-06-21; fixed + verified same session)*
`[x]` **Fixed + verified (2026-06-21), on branch `claude/gifted-heisenberg-a6zlvt`.** Stress-testing the just-shipped B331 pinch (#245) surfaced a **real, live regression**: on the Site Planner SVG the pinch handlers were added as a *second* `onPointerDownCapture`/`onPointerMoveCapture` on the same element, and **JSX silently keeps only the last duplicate** — so the pre-existing vertex-edit capture handlers (`onCanvasVtxDownCapture`/`onCanvasVtxMoveCapture`) were dropped. Net effect: **selecting a parcel/polygon vertex, shift-click-insert-vertex, and the insert-on-edge hover hint all stopped working** — on mouse *and* touch. The build was green and the minimal lint gate has no react plugin, so nothing caught it. **Fix:** merge the two capture lines into one prop each (pinch first; the vertex handler runs only when a pinch is NOT engaged, `if (!pinchRef.current)`) — mouse + single-touch editing restored, pinch still wins when it engages. **Hardening (same pass):** a shared `reseedPinch` re-baselines the gesture to whatever fingers remain on every add/remove, and a 3rd+ finger is absorbed instead of starting a competing pan/draw — a partial lift or extra finger can no longer jump or corrupt the zoom. **Permanent guard:** `test/noDuplicateJsxProps.test.js` AST-scans every `.jsx` (via the already-present `@babel/parser`) and fails if any element repeats an attribute — kills this build-invisible clobber class for good. **Verified (V94):** new `ui-audit/verify-pinch-stress.mjs` 15/15 (adversarial multitouch: 30-cycle storms, clamp saturation, coincident fingers/no-NaN, 3-finger + partial lift, interrupt recovery, mouse-path survival) + verify-pinch 5/5 + all viewport/rail/viewer regressions green; 1015 unit tests; lint 0; build green. Eligible to move to BACKLOG-DONE on merge.
