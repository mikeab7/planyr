### B415 — Doc Review (Library) render is softer than Bluebeam on large sheets — viewport-clipped two-layer rendering `[Doc Review / Markup]` (bug)  *(owner-dropped 2026-06-23 as "NEW-2"; first filed as B413, renumbered past main's B412/B413 (PR #311) to **B415**; depends on B414)*
`[x]` **Filed AND fixed the SAME session per STANDING RULE #1 (branch `claude/confident-edison-lpbco9`). 1273 tests · lint 0 · build green; headless-verified.** Net-new architectural item that **supersedes the whole-page raster path B247/B265/B327/B329** (extends that path, does not fork a second renderer).
- **Repro:** Planyr's linework/text was visibly softer than Bluebeam side-by-side, most pronounced on large (E-size) civil sheets and when zoomed in.
- **Root cause:** the viewer rasterised the ENTIRE page into one canvas at a single density; the ~24 MP backing-store budget (`renderBudget.backingScale`, B327/B247) was spent across the whole sheet, so on a big sheet density dropped below full (even <1×) everywhere to stay under budget — even though only a small window is visible. Bluebeam rasters only the visible region at full resolution.
- **Fix (two-layer, additive over B414; the page-box + SVG-overlay CSS model is byte-for-byte unchanged, so markup/zoom-anchor geometry is untouched):**
  - **Backdrop** — the whole page at a FIXED, zoom-independent density (`backdropDensity`, ~8 MP budget) painted once per page, filling the page box. It never re-rasters on zoom (so it can't flash white) and is always present as a no-white floor.
  - **Detail** — only the visible page-rect (+ a 25% margin) at full device dpr (cap 2), budget-bounded on the REGION not the page (reuses `backingScale` on the region size), re-rastered on pan/zoom settle (double-buffered via B414) and positioned over the backdrop. Because the detail backing store is ~viewport-sized, the budget stops forcing low density → on-screen resolution stays native at any sheet size/zoom.
  - Pure region/density math (`visibleRegion`, `tileCovers`, `backdropDensity`, `BACKDROP_PX_BUDGET`) in `renderBudget.js` (+13 unit tests in `test/renderBudget.test.js`); region render path (`renderInto` with a `transform` offset + canvas-clip) in `pdf.js`; two-canvas viewport + settle-driven `renderBackdrop`/`renderDetail` in `DocReview.jsx`. The B40 race guard + B39 destroy are kept; the imported drawing stays a display-only backdrop.
- **Verified (`ui-audit/verify-b414-b415-render.mjs`, 11/11, E-size sheet @ deviceScaleFactor 2):** zoomed to 2.6×, the **detail layer renders at 2.00× native device density** while the OLD whole-page raster would be **0.95× at the same zoom → 2.11× sharper**; backdrop fills the page box and stays opaque through the zoom; markup overlay still draws. Regression: the B329 viewport harness (`verify-markup-viewport.mjs`) still 13/13 (pan / cursor-anchored zoom / calibration survival / measurement geometry / sheet-switch), plus `verify-docreview-viewer` 13/13 and `verify-delete-markup` 10/10.
