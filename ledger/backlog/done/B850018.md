`[x]` **SHIPPED THIS SESSION.** Split `MapFinder.jsx`'s single `mode` state (B831776, "one piece of state, never two") into two independent state variables: `mode` — what an address search creates, and which toolbar workflow is armed (Select-parcels vs. Place-comp) — and a new `panelTab` — which list the left rail browses. Neither setter touches the other. `setPanelTab` is a plain `useState` setter with no side effects (switching tabs must never cancel an in-flight comp placement or parcel selection the way leaving `mode` does via `setMode`'s existing `setPlacingCompPin(false)`/`setSelectMode(false)` calls).
- **The centre toggle's own copy was corrected to match its narrowed job** — "Browse your sites and start new plans" / "Browse your leasing comps and place new ones" (which implied it also controlled what was browsed) became "Address search creates a new site" / "Address search creates a new leasing comp"; the `role="tablist"` accessible name moved from "Browse sites or comps" to "What an address search creates".
- **Every adjacent case the item asked about, decided deliberately and stated here, not left implicit:**
  - Clicking a comp MARKER on the map, or a freshly-dropped comp pin — **DOES** still flip the panel to the Comps tab (kept, deliberately: selecting a specific comp should surface its detail, matching the item's own suggested distinction) — but this effect used to ALSO force `mode` to "comp" as a side effect of merely viewing an existing comp, which was the identical coupling from the other direction; that forced `mode` write is now gone, so viewing a comp no longer silently rearms what a future address search creates.
  - Dropping a FILE onto the map (creating a site-plan overlay under a comp workflow) — arms `mode` to "comp" (a direct creation action, unchanged) AND now also explicitly sets `panelTab` to "comp" so the result is visible, rather than relying on the coupling that used to do this as a side effect.
  - Clicking a SITE polygon — navigates directly into that site's plan (a full workspace switch via `onOpenSite`), an entirely different thing from either `mode` or `panelTab`; confirmed by reading the call site — no coupling existed here to begin with, nothing to fix.
  - The comp detail's "← All comps" back link (`CompsPanel.jsx`'s `onBack`) — confirmed it only clears CompsPanel's own local detail-vs-list state; it was never wired to `mode`/`panelTab` and stays that way — returns to the comps list, panel stays on the Comps tab, exactly as expected.
