`[x]` **✅ DONE — `planSwitchVerdict` takes a settle sample and gains two verdicts. A one-sample run can no longer produce the word RETAINED.**
- Verify: sandbox
- Origin: found 2026-08-08 in-session
- **THE FALSE POSITIVE, measured.** Re-taken on two real plans, the plans axis reported **RETAINED — `retainedHeapMB +39.1%`, `rendererNodes +38.1%`** after one A→B→A round trip, read after **two forced `HeapProfiler.collectGarbage` calls**. `ui-audit/session-growth.mjs` sampled the same counters across four switch rounds of a long session and saw the identical spike each time — and saw it **gone one ordinary round of work later, every time**, settling BELOW where the session began (detached≈ 185 → 1245 → 203 → 1028 → 168 → 1199 → 168; renderer nodes at rest 2355 → 2230 → 2011 → 2082).
- **WHY THE FORCED COLLECTION DOES NOT HELP, which is the part that makes this a real trap rather than a sloppy read.** V8's **conservative stack scanning** pins objects still referenced from the frames on the stack when the collection runs, so the outgoing tree survives the purge and is collected a moment later. `docs/PERF-PLAN-SWITCH.md` §14 had already recorded exactly this effect — *"a forced purge drains 2,343 → 1, but both natural allocation pressure and a precise cache-neutral `gc({execution:'async'})` do not"* — and the single-sample verdict was built anyway. Collecting twice is not a second sample.
- **The fix:** `planSwitchVerdict({ a0, b, a1, a2 })`. **`RETAINED`** now requires the counter to be elevated at A₁ **and still elevated after a settle**; a spike that decays is **`TRANSIENT`** (*"a single sample here would have reported a leak"*); a spike with no settle sample is **`UNSETTLED`** — explicitly neither verdict, naming conservative stack scanning as the reason. The harness takes A₂ after a `--switch-settle` wait and prints A₂ and its delta **beside** A₁ rather than instead of it, so the transient and its decay are both visible.
- **⛔ THE GENERAL LESSON, and it is the second one this family has produced.** B1439's was *"the instrument's own protocol handles are part of the measured heap."* This one is **"a counter read once, immediately, cannot distinguish a level from a transient — and the collector you called to make it a level does not make it one."** Both were found the same way: by an instrument that samples the same quantity more than once.
- **✅ RE-RUN WITH THE FIX, AND THE VERDICT FLIPS TO `TRANSIENT` WITH EVERY COUNTER COMING HOME.** Same two real plans, same regime: `rendererNodes` **A₀ 2190 → B 3784 → A₁ 3150 (+43.8%) → A₂ 2089 (−4.6%)** — transient. And **four of the six counters return to their EXACT starting value** after the settle: event listeners 1600 → 1600, document elements 1692 → 1692, canvas nodes 600 → 600, layout objects 1391 → 1391. `retainedHeapMB` lands at +0.8%. A plan switch on two real, unrelated, raster-bearing plans releases everything it took.
- **Also fixed in passing: the report header named the WRONG SCENE.** It hard-coded `SCENARIO_ID`, so a `--fixture` run printed *"scenario perf-reference-goose-creek"* over numbers taken on Bain and Sylvestri — which is how a real reading gets filed against the wrong plan, the exact defect B246529 exists to close.
- **Tests.** `test/sessionAxes.test.js` gains four cases including the exact measured numbers as a regression fixture — RETAINED requires the settle sample to agree · the real +39.1%/+38.1% spike with a decaying A₂ must read `TRANSIENT` · a one-sample spike must read `UNSETTLED` and never `RETAINED` · and a clean round trip still reads `RELEASED` with no settle sample, so the change costs nothing when nothing spiked. 34 cases green.
