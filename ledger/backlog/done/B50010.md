### B50010 — A centerline road pops the inline width editor on a double-click instead of opening Properties `[Site Planner / UI]` (bug) #site-planner #selection #ui #road  *(filed 2026-08-06 from the owner chat block as NEW-3; minted with B50008. - Found by the new audit under the **friendliest** conditions — fast machine, unthrottled, two-element plan — so this is a WIRING defect, independent of B50008 and B50009.
- **REPRO:** seed a centerline road, double-click its centre. It selects (endpoint grips appear) and a blue inline `30` width chip opens on the canvas. Properties does not open.
- **CAUSE:** a road's width dimension NUMBER is anchored to the **centreline midpoint** — it is painted ON the pavement — so a double-click aimed at the road cannot miss it, and `onDimNumberDown` routed the pair to `editElDim`.
- **FIXED ONCE IN THE SHARED DISPATCH, NOT SPECIAL-CASED FOR ROAD.** The dispatch now asks the general question for every type: *is the element's own body painted under this point, beneath the dimension chrome?* If yes the press was aimed at the element and the body's action (Properties) wins; if no — the number has been dragged into clear space, which a road's free dimension drag allows — the number is genuinely what was aimed at and keeps its inline editor. Asked through the browser's own hit-test (`pressIsOverElementBody`), with the dimension chrome marked `data-el-dim` so the test can look past it. **A rect element had the same trap waiting** (B592 clamps its number ONTO the footprint) and the audit confirmed it: with the fix reverted, building and paving fail alongside road.
