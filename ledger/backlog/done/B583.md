### B583 — Excel-style Formula column in the scheduling grid `[Scheduler]` (feature)  *(owner-dropped 2026-06-29 — "create a column that is a formula column that basically functions like Excel where you can do math… copy the most-used Excel functions… what would work for ~90% of people"; provisional "NEW-1"; minted **B583** = highest real B# across both files (B582) + 1 — renumbered from a provisional B562 that collided with main's grid-keyboard-nav B562 plus the B564–B582 burst of concurrent mains landed while this branch was open; branch `claude/scheduling-formula-column-anxv35`)*
`[x]` **DONE + verified this session. lint 0 errors · 1850 unit tests green (56 in `test/formula.test.js` + 1 inline-sync guard) · build green · headless E2E `ui-audit/verify-b562-formula-column.mjs` PASS (add column → per-row compute → `#DIV/0!`/`#REF!` surfaced) · a 6-lens adversarial-review Workflow ran and all 6 confirmed bugs were fixed before shipping.** A user can now add a **Formula** column to a project's schedule grid (Columns chooser → "+ Formula column", or right-click a column header → "Add formula column…"), type an Excel-like expression, and it computes a value **per task row** from that row's other columns.
- **Per-row calculated column, structured references (not A1).** One formula evaluates for every row, referencing columns by name — `[Finish] - [Start]`, `IF([% Complete]>=100,"Done", NETWORKDAYS([Start],[Finish]) & " wd")`. Schedule rows are activities that reorder/insert/delete constantly, so absolute cell addresses (A1) would break; column-name refs survive.
- **Engine = a dependency-free pure lib** `src/shared/formula/formula.js` (tokenizer → precedence-climbing parser → tree-walk evaluator; **no `eval`/`new Function`**). The ~90% function set: math `SUM PRODUCT MIN MAX ABS ROUND ROUNDUP ROUNDDOWN INT MOD CEILING FLOOR POWER SQRT`; logical `IF IFS AND OR NOT SWITCH IFERROR ISBLANK`; date `TODAY DATE YEAR MONTH DAY WEEKDAY EDATE EOMONTH DATEDIF DAYS WORKDAY NETWORKDAYS`; text `CONCAT TEXT LEFT RIGHT MID LEN TRIM UPPER LOWER`; operators `+ − * / ^ &`, comparisons, parentheses. Built generic for Cost Estimating reuse later; wired into Schedule first.
- **Dates honor the project working-day calendar.** `WORKDAY`/`NETWORKDAYS` use the SAME weekends + `HOLIDAY_SET` the schedule cascade uses (injected calendar adapter) — not Excel's naive Mon–Fri — so a formula's working-day count agrees with the duration model. Typed inputs documented: Start/Finish = date, Duration = working days (number), % Complete = **0–100**; `date − date → days`, `date + n → date`.
- **Read-only / no feedback loop.** Formula columns are derived display columns (`e:false`) computed in a memo AFTER `cascadeDates`/`rollupParentDates` settle, so they read final dates and can never drive task dates/durations (no circular dependency with the scheduling engine). Inter-formula deps are topologically ordered (`planFormulaColumns`); a reference cycle surfaces **`#CIRC!`**.
- **Errors are visible, never a silent blank** — `#REF!` (bad column), `#DIV/0!`, `#VALUE!`, `#NAME?`, `#NUM!`, `#N/A`, `#CIRC!` render red in the cell with a tooltip.
- **Inline editor (no dialog-box edits — owner rule)** — `FormulaColumnEditor`: a name field + a formula box with **autocomplete** for `[Column]` and `FUNCTION()` names + a **live preview** evaluated against the selected row; validates the name (required/unique/not a built-in name) and the formula (parse error shown live). Edit/delete via the chooser ✎/🗑 or the header context menu.
- **Persistence** — formula defs live on `proj.formulaCols` (additive, rides the existing scheduler cloud-save), visibility/width via the existing `colConfig`. A shared effective column registry (`effectiveColsOf`) merges built-ins + formula cols so `selectedColIdx`/copy/format/keyboard-nav resolve consistently App-wide.
- **Standalone-scheduler delivery:** the scheduler is a self-contained in-browser-Babel HTML file (`public/sequence/index.html`), so the engine is inlined VERBATIM by `scripts/sync-sequence-formula.mjs`; `test/formula-inline-sync.test.js` fails CI on any drift between source and the inlined copy.
- **Adversarial-review Workflow (engine-semantics / parser-security / dates / integration, each finding independently re-verified) found + I fixed 6 real bugs before shipping:** (1) float-noise display (`9999999.99 & ""` → clean, not `9999999.9900000002`); (2) non-finite `+ − * /` now `#NUM!` (was a silent `Infinity`/`NaN` that produced a WRONG TRUE/FALSE in comparisons); (3) `DATEDIF "YD"` across year boundaries (was huge/negative); (4) `TEXT` integer leading-zeros (`"00"`→`"07"`); (5) a parser depth guard + a never-throw-to-host contract (deep nesting returns an error cell instead of a `RangeError` that could blank the grid); (6) a hidden formula column that couldn't be re-shown (`showCol` used the built-ins-only registry). Plus 2 low (CEILING/FLOOR sign mismatch → `#NUM!`, `DATEDIF "MD"` non-negative). All pinned by new tests.
- **Deferred to a follow-up (NOT built, as scoped):** cross-row aggregation (column-wide SUM/COUNT/COUNTIF/SUMIF/AVERAGE), lookups (VLOOKUP/XLOOKUP), and formula columns writing back into dates. Formula columns also don't yet appear in the PDF/Gantt exports or the cross-project MasterView (grid-only in v1).
