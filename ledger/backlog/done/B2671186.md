### B2671186 — Row height can't be changed in a Notes table: drag the line under a row `[Notes]` (bug) #notes #ui  *(owner report 2026-11-05, NEW-3 of the block with B2671184 / B2671185; he did not say how he tried. Deduped: no prior item.)*
`[x]` **✅ Done — V2115856 PASSED live 2026-11-05 on build 44486b2 (the merge commit of #2867), signed in as the test account (`ui-audit/verify-notes-table-size-live.mjs`, 18/18).**

**Measured first: there was NO way to set a row's height at all** — `tableRow` had no attribute, no handle, no cursor (only column widths could be dragged). So the drag was **built**, modelled on Excel / Word (`lib/notesTableRowHeight.js`): the line between two rows (and under the last row) shows the ↕ cursor and drags the row **taller and shorter, live**, one undo step on release; with whole rows selected, dragging one selected row's line sets them ALL; double-clicking the line is AutoFit (clears it); the stored `rowHeight` (CSS px, a MINIMUM) rides the document, sync, print (PDF-PARITY: it is in the schema's own HTML) and copy. **A row never goes shorter than its text needs — dragging back to that point stores NO height, so the row is "auto" again and follows its text** (36 → 9 shrinks it; verified), and a wrapping row stops at its wrapped height (text is never clipped). The column drag is untouched (the handler declines in the column zone). A new row takes the HEIGHT of the row it was added from (NEW-2 tie-in, B2671185).
- **Cause of the first failed build, kept for the next reader:** ProseMirror reads a live `style.height` patch on a `<tr>` as an edit and redraws it from the document, so the preview vanished on the next mouse move; rows now have their own node view whose `ignoreMutation` ignores height (the table's column drag needed the same).
- **Cases run (all green):** taller · shorter · to the text's height (stores null) · reload after each · empty row · first row · last row (its line sits on the table's outer edge — needed its own hit test) · a wrapping row · several selected rows · double-click AutoFit · Ctrl+Z · the column drag still works · an auto row shrinks when its text size is reduced · an Excel-pasted table (`excel.html` fixture) drags like a Planyr-built one. Mouse only: a phone keeps its page pan (the column drag has the same limit) — not built, said plainly.
