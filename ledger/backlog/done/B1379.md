- **The defect.** `bondedHealWatch.flush()` decides whether a load-time repair is worth persisting by measuring how far it MOVED a child (`healMoveFt` → `HEAL_TEAR_TOL_FT`). That is the right question for a torn assembly, where the distance is both the severity and the proof. It is the wrong question for **B1377**'s repair: restoring a bonded pad's `sideParkSide` changes its IDENTITY and not one coordinate, and minting the deleted 5 ft sidewalk back into the void ADDS an element with no previous position to measure against. Both scored **0 ft**, so `wasTorn` came back false, `loadSite`'s `persistHeal` branch never fired, and the plan rendered repaired while the stored record kept its wreckage — the precise failure `loadSite`'s own comment was written about, arrived at from the other direction.
- **The fix.** Severity at this seam is now **structural as well as metric**: `STRUCTURAL_HEAL_KINDS` (`orphan-pad-retagged`, `orphan-pad-strip-restored`) always persist. They are reported on their OWN telemetry event (`assembly-orphan-pad-repaired`) rather than folded into `assembly-tear-detected`, because "N bonded children up to X ft off their host" is simply untrue of a repair that moved nothing, and a message that overstates what happened is how a real signal stops being read.
- **⚠ THE METHOD NOTE WORTH KEEPING — the first version of this item's tests PASSED against the unfixed code.** They seeded the damaged plan through `saveSite`, which **renormalizes on WRITE**, so the record on disk was already repaired and the load path was never exercised at all. It was caught only because a mutation that should have turned them red did not. Tests for a LOAD-path repair must plant the raw bytes straight into the store; the helper now says so in a comment, next to the `plant()` it provides.
- Tests: `test/orphanWallPads.test.js` +3 (24 total) — the damaged plan's restored sidewalks are asserted **on disk** and not merely in memory, re-opening re-mints nothing, and a plan needing no structural repair is not re-written on open (no `updatedAt` churn on every route lookup).
