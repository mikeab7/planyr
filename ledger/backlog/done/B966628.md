`[x]` **B520560, owner decision, is quoted exactly because this item sits right next to it: "Nothing may be discarded silently — if a cut produces a sliver, he gets it as a parcel rather than losing the acreage."** That guarantee is NOT reopened here — every square foot a cut produces still lands somewhere and is never dropped. What changes is what "somewhere" means for a fragment too small to be its own row.
`[x]` **Shipped: SNAP, not refuse, as the default — because snapping conserves the guarantee above and refuse alone would not.** `snapTinyPieces` (new, `lib/polygonSplit.js`) repeatedly fuses the smallest sub-threshold piece into whichever OTHER piece it shares the LONGEST boundary with (two pieces of one cut are faces of the same planar arrangement, so a shared boundary is edge-exact — the identical cancellation `SitePlanner.jsx`'s `mergeRings` uses to undo a merge, specialised here to carry `edgeSrc`/setback provenance through the join). The threshold reused is the EXISTING `SLIVER_FRACTION` (1e-5 of the parent) that already computed the old "tiny, kept" notice — one number, not a second one invented to disagree with it. `performSplit` reports what happened LOUDLY: *"a sliver too small to be its own parcel (N SF) — merged into the piece next to it, acreage kept."*
`[x]` **REFUSE is the fallback, only when snapping would leave fewer than 2 pieces** (the whole cut only ever clipped off a fragment — there is nothing left to call a division). New refusal code `sliver-only`: *"That cut only clips off a sliver too small to be its own parcel — draw it further in so both pieces are real parcels."* Never a silent near-no-op that hands back the parcel almost whole.
`[x]` **Duplicate-name debris (three rows named `2A1A1A`, three named `2A1A1B` on Bain, across separate cut attempts) verified NOT a live defect and not touched.** Names are deterministically derived from parent + birth order, so re-attempting the same cut on the same parent naturally reproduces the same next letters — and the LOUD-FAILURE `nameCollision` check (B520560) is correctly scoped to the LIVE `parcels` array only, so a soft-deleted prior attempt's identically-named debris was never live-visible and never silently collided.
