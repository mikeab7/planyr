- **MECHANISM (AUDIT-FIRST).** `Shell.jsx` has exactly ONE write site for the pointer — `useEffect(() => writeLastRoute(route), [route])` — so every navigation (tab click, breadcrumb pick, programmatic `navigate()`) persists whatever route is currently active, with no per-module opt-out. `lastRoute.js`'s `pickBootRoute` then seeds an empty-hash boot from whatever was last stored, with the only existing exemption being the plain default dashboard (`{module:"site-planner", projectId:null}` → `buildHash` gives `"#/"`, a no-op). Food has no project concept at all (`src/workspaces/food/CLAUDE.md`: *"No projects, no cross-workspace navigation — this module is deliberately outside the Site Planner's project model"*), so any visit to it — even a stray click — writes `{module:"food", projectId:null}` as the pointer, and the very next bare-domain boot restores exactly that.
- **(1) GENERAL RULE — a stored pointer is only seeded when it names somewhere SPECIFIC.** Added `isWorthRestoring()` in `src/app/lastRoute.js`, consulted by `pickBootRoute`: a non-default module with **no active project AND not in a deliberate cross-project view** is refused — it's a generic placeholder (a project picker, an empty canvas, "nothing selected") indistinguishable from just landing on the default workspace, so seeding it never restores anywhere the user was actually working. `cross:true` is explicitly exempted — it's a real, user-toggled destination (Notes' "All Notes" dashboard, a cross-project Library tree), not a dead end, and blocking it would have thrown away a working, designed feature the food bug never touched.
  - **⚠ DISCREPANCY FLAGGED, per AUDIT-FIRST.** The brief's stated premise — *"a module with no project is not a place worth returning to"* — is not literally true for Notes' "All Notes" dashboard, Library's project picker, Doc Review's blank canvas, or Scheduler's dashboard: each is a genuine, designed, reachable destination (see the audit table below), not a broken state. The rule is applied anyway, uniformly, because (a) a generic module-with-no-project landing is still a worse bare-domain default than falling through to the Site Planner (which resumes ITS OWN last plan internally via `resumeAllowed`/`pickResumeTarget` — so "fall back to the last real project" happens for free), and (b) every one of those states stays exactly one click from the header crumb, so nothing becomes unreachable — only what gets auto-restored on a fresh tab changes. Flagging this explicitly rather than silently overriding the brief's stated reasoning.
- **(2) FOOD'S PARTICIPATION — DECIDED: excluded outright, both directions.** Food stays reachable by direct URL (`#/food` still parses and mounts it; nothing in `route.js` changed) but never becomes the restored default, and — going further than "don't restore it" — **a visit to Food no longer even overwrites the stored pointer** (`shouldPersistRoute()` in `lastRoute.js`, checked inside `writeLastRoute`). Reasoning: Food is a private personal side product the owner built for himself (place-tracker, ratings, notes on where he's eaten) that happens to live in the same app shell as the professional tool he sends to brokers, lenders and his team — it has no project model to restore INTO even in principle. Not writing it means a food visit is now transparent to "resume": open a project, check Food, close the tab — you come back to the project, not to a fallback default. This is strictly better than merely refusing to seed it, and was cheap to add.
