### B117 — Draw-tool palette can't scroll to its bottom on desktop → SHAPES group unreachable `[Site Planner]` (bug)
`[x]` Repro: open Site Planner on a normal laptop viewport; the dark draw-tool rail (the **Tools / Site elements / Shapes** palette) is taller than the screen but won't scroll to the end — the SHAPES group and anything below it sits past the fold and is unreachable. Expected: the rail scrolls cleanly to its last row at any viewport height, with the full list reachable. **Confirmed cause:** the rail container in `SitePlanner.jsx` sets `overflowY: narrow ? "auto" : "visible"`, so it only scrolls inside the phone/`narrow` overlay (B113); on the desktop path `overflowY:"visible"` + `flex:none` with no height bound lets the content spill off-screen with no scrollbar. Fix: give the rail `overflow-y:auto` on the desktop path too and bound its height to the viewport — it already sits in a flex row, so add `min-height:0` on the column so it can shrink-and-scroll; confirm the last row is fully visible.
> Not a dup of **B107** (that reworked the *mode-tab* column — Yield/Parcel/Element/Aerial/Overlay/Setup — and found it already fits) or **B113** (that added only the *phone* slide-in overlay, with its own `overflow:auto`; the desktop layout was left byte-identical, so this desktop scroll gap is untouched). Michael described it as the "left" rail; in the current build this palette renders on the **right** (dark chrome) — same element, identified here by its Tools/Site-elements/Shapes content. Pairs with **B118** (shorter rows overflow less often), but this is the underlying bug — even a short rail must stay fully reachable.
