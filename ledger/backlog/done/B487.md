### B487 — Schedule module: input edits silently dropped, mangled, or left stale state `[Schedule / inputs]` (bug batch)  *(owner-dropped 2026-06-27 — "find all the bugs you can as it relates to the inputs for the schedule module and fix them and ship"; branch `claude/schedule-input-bugs-jtfplb`; minted **B487** = highest real B# (B486, the concurrent team-RLS fix) + 1 — the B526 hit in BACKLOG-DONE is a CSS hex, not an id)*
`[x]` **DONE + verified. lint 0 · 1613 tests (+16) · build green · esbuild JSX transform OK · NEW headless `ui-audit/verify-schedule-input-bugs.mjs` 8/8 (real Chromium, logged-out).** A fan-out review of every user-input path in the embedded scheduler (`public/sequence/index.html`) found six places where a reasonable typed value was silently lost, mangled, or left the model inconsistent. All fixed at the input boundary; the engine itself was already hardened (B246–B251).
- **`[x]` Predecessor edits validated (self / unknown / cycle).** New pure `validatePredEdit(tasks, id, parsed)` (in index.html + mirrored to `ui-audit/stress/scheduler-engine.mjs`, 7 unit tests): drops self-references (existing Fix #16), references to task ids that don't exist in the project (were stored + displayed as a live dep but did nothing — `cascadeDates` filtered them), and references that would close a **circular dependency** (A→B→A produced silently-arbitrary dates) — each surfaced with a toast. Wired into `applyUpdate`.
- **`[x]` Grid date input hardened.** A date cell can now be **cleared** (empty → `""`, was silently reverted); an **unreadable** date gives a toast ("Couldn't read that date…") instead of silently reverting; and **Finish before Start** is rejected with a toast instead of silently collapsing the task to a 0-day milestone and discarding the typed date.
- **`[x]` Finish on an unscheduled task.** Setting a Finish on a task with no Start used to set `duration = ""` (rendered a bare "d") and the typed finish was then wiped by the cascade (`calcEnd("",…)===""`). It now anchors a 1-day task on that date (start=end, duration=1). Added a defensive duration-cell render guard so a stray empty duration can never show a bare "d".
- **`[x]` Indent / outdent / paste now recompute roll-ups.** `indentTask`, `outdentTask`, `indentTaskById`, `outdentTaskById`, and `pasteTaskAfter` changed `parentId` but never ran `cascadeDates`/`rollupParentDates`, so the old and new parents kept **stale summary start/end/duration** until the next in-subtree date edit. New shared `recomputeAfterStructureChange` (= `rollupParentDates(cascadeDates(...))`, the same recompute `updateTask` runs) is applied in all five handlers before renumber.
- **`[x]` Master ("All tasks") grid duration clamp.** It lacked the project grid's `Math.min(100000, …)` upper bound, so a fat-fingered duration there could freeze the layout. Clamp added to match.
- **`[x]` Export cover fields escaped.** The PDF/print cover **Date** (`cfg.docDate`) and **Prepared for** (`cfg.preparedFor`) were interpolated raw while their four siblings used `escapeHtml` — a typed `<`/`&`/quote corrupted the cover (and was an injection vector into the generated preview). Both now use `escapeHtml`.
- **Verified here (logged-out headless):** `verify-schedule-input-bugs.mjs` 8/8 — board boots with all fixes in (proves the whole Babel block still parses), and self-ref / nonexistent-id / circular-dependency / Finish-before-Start / unreadable-date each toast with no uncaught errors. Plus `validatePredEdit` units + `rollupParentDates` move-rollup unit + anti-drift string guards in `test/schedulerEngine.test.js`. *(Sandbox quirk: the board's React/Babel CDNs are closed to the browser here, so the harness used locally pre-downloaded copies via `SEQ_VENDOR=<dir>`; in CI/normal envs run it with no env var.)*
- **⏳ Three running-app click-throughs → VERIFICATION.md V148** (indent roll-up widening visible in the grid; Finish-on-blank-task showing "1d"; export-cover escaping in the generated PDF) — not drivable as cleanly headless, covered here by unit + anti-drift + the boot check.
- **Scope note (NOT a bug):** the on-screen Gantt has **no bar drag/resize** (bars are click-to-select only; the only chart drag is whole-canvas pan, and the Snap/Free toggle drives the grid↔Gantt split divider) — so there's no second date-input path that could disagree with the typed/`addBD` path. New/inserted tasks are intentionally born blank (unscheduled until given a date or predecessor). Both confirmed during the review.
