`[x]` **ROOT-CAUSED AND FIXED THIS SESSION.**
- Verify: sandbox — fully reproducible headless (a deterministic DOM-focus defect, no auth/live-GIS/real-data dependency), and DELIBERATELY control-tested: the new e2e spec was run against the pre-fix code first and reproduced the exact repro (selection moves to B15, `model-sheet` never receives focus, the follow-up keystrokes are lost) — then run again against the fix and passed.
- **THE MECHANISM.** A mouse click on a cell gets DOM focus for free as a side effect (`SheetView.jsx`'s own `cellClick` calls `outerRef.current?.focus()`), which is why every subsequent keystroke reaches the grid's one `onKeyDown` handler. The Name Box (`FormulaBar.jsx`) has no such side effect: its Enter handler called `onGoTo(...)` (which only updates the `selRange` React state — the selection) and then `e.currentTarget.blur()`. With nothing else to take focus, that `blur()` leaves `document.activeElement === document.body` — the selection moved, the keyboard did not, and the grid's `onKeyDown` never fires for anything typed next. No error, no marker: the keystrokes are simply gone, exactly the B1287888 fault family (a keystroke arriving with nothing actually focused to receive it), one level up — there the input existed but hadn't taken focus yet; here nothing was focused at all.
- **THE FIX** hands DOM focus to the grid explicitly once a Name Box jump resolves, the same target a mouse click would focus. `SheetView.jsx` now takes a forwarded ref (`forwardRef` + `useImperativeHandle`, the same pattern already used by `FileMenu.jsx`/`TabStrip.jsx` in this module) exposing one method, `focusGrid()`, that calls `.focus()` on the grid's own container. `ModelApp.jsx` holds that ref (`sheetViewRef`) and passes a `focusGrid` callback down to `FormulaBar`, which calls it instead of `blur()` on a successful Enter (and on Escape, which had the identical gap). Scoped deliberately to the Name Box only — Find/Replace and the Name Manager's own "Go" navigation call the same shared `onGoTo`, but both keep focus in their own panel on purpose (repeated Enter/Shift+Enter cycles through Find matches, "Go" buttons let you jump again without reopening the panel), so changing `onGoTo` itself would have broken that UX; the fix lives only in the one caller that hands focus away.
- **Regression guard:** `e2e/model-spreadsheet.spec.js` — new test "Name Box: typing right after a jump lands in the target cell, no intervening click needed" drives the exact repro (click Name Box → type `B15` → Enter → assert `model-sheet` is focused → type `987654` → Enter → assert B15 reads `987654`). Confirmed it fails on unmodified code (times out waiting for `model-sheet` to be focused) and passes with the fix. The two existing Name Box tests (typed-address jump, range/invalid-address refusal) still pass unmodified.
