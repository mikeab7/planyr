### B576 — Scale control: dead "custom…" rebuilt as Bluebeam-style page-distance = real-distance entry `[Site Planner]` (bug + feature)  *(owner-dropped 2026-06-29 as "NEW-3"; minted **B576** — renumbered B562→B566→B574→B576 as concurrent mains kept taking the id)*
`[x]` **DONE + headless-verified. lint 0 · 1808 tests (+18 unit) · build green.** The old scale `<select>` skipped its own `custom` value and only revealed the custom input when the overlay *already* sat at a non-preset size — so picking "custom…" did nothing. It was also a feet-per-inch model with the page side hardcoded to 1″, so only `1″=X′` scales were expressible. **Rebuilt to Bluebeam Revu parity:** a preset dropdown (Engineering `1″=10/20/30/40/50/60/80/100′` + Architectural `1/8″ … 1″=1′-0″`, grouped) where picking a preset populates page=1 + real=preset and **Custom…** reveals editable paired fields **`[page][unit ▾] = [real][unit ▾]`** (page in/ft, real ft/in/m; page side accepts decimals AND fractions — `0.5` or `1/2`). The page→real ratio is the single source of truth: `feetPerInch = realFt / pageIn` feeds the **untouched** `applyOverlayScale`/`ftPerPx` model, so `0.5″=60′ → 1″=120′` is now expressible (was impossible). The custom/preset distinction is driven off **explicit editor state** (`ovEdit`), not the overlay's current size, so Custom always reveals the fields; the dropdown **round-trips** to the matching preset when the size lands on one, else shows Custom with the fields populated. Resolved scale still drives EPSG:2278 sizing and survives reload (only `ftPerPx` changes). **Extended `lib/overlayScale.js`** (not forked): pure `parseDistanceInput` (decimals/fractions/mixed), `feetPerInchFromPair`, `SCALE_PRESETS` + `feetPerInchForPreset`, `matchScalePreset`; **+18 unit tests** (`test/overlayScale.test.js`, 30 total green). Headless: round-trips to eng-30; `1/4″=1′` → `1″=4′`; Custom `0.5″=60′` and `1/2″=60′` both → `1″=120′ · 4320′ wide`. **Review-driven precision guard:** the custom fields default-DISPLAY a rounded value but COMMIT full-precision defaults, and the page/real inputs carry **per-field dirty flags** so an idle focus→blur of an un-edited field never re-commits the rounded display string (which would have quantized e.g. a metric `1″=1m`/3.2808 to 3.3). Headless: idle focus+blur leaves the scale exactly put.
