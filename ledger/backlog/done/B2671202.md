### B2671202 — Paving setback beside the building setback — owner-added, never automatic, limits parking / trailer parking / truck courts / roads, with a dotted line and a conflict mark `[Site Planner]` (feature) #site-planner #ui #persistence

`[x]` **IMPLEMENTED 2026-11-09 (owner-approved mockup, board 1 panel before, board 2 after, board 3 map).** Verify: live — a render / zoom-dependent surface (dotted line, red marks, PDF-PARITY of the line) so it parks in ⏳ Verify with a V# until the signed-in check on planyr.io passes.
- **Storage:** `pc.pavingSetbacks` — a second per-edge array (same shape as `pc.setbacks`). ABSENT = not added; a parcel that never adds it has no key and renders/saves byte-for-byte as before. Adding starts at 0 on every edge and is never copied from the building setback or the default; removing deletes the key. Pure rules in `lib/pavingSetback.js`. Same sections as the building setback (`lib/boundarySections.js`) — no second section system.
- **Panel (`components/SetbackSections.jsx`):** "Setback" row is now "Building [n] ft · all sections"; "+ Add paving setback"; once added a "Paving [n] ft · all sections" row with its own Show line (plan-level `settings.showPaving`, absent = on) and a trash that removes it (Undo toast, building untouched); a Building | Paving switch above the sketch picks which numbers the sketch labels; section rows that differ show BOTH numbers under BUILDING / PAVING headings, each box labelled; "Reset all" zeroes paving and resets building (paving stays added).
- **Map:** dotted blue line (`PAL.paving`, token `--canvas-paving`) inside the parcel beside the dashed building line, screen-pixel weight, same sub-pixel gate; in the plan SVG so the export clone carries it. Legend: the building line has none, so paving has none.
- **What it limits:** car parking, trailer parking, paving / truck courts, roads (drive aisles, on-site roads). NOT sidewalks (owner 2026-11-09), NOT buildings, buffers, landscape, ponds, ramps.
- **Driveway exemption — SAID PLAINLY: the app has NO "this drive connects to a public road" notion** (junction code only knows road↔road and road↔field links; `parcelStreets` is a 60%-outside heuristic). So the rule is geometric: an END of a road that lies outside the site (outside every active parcel, or within 2 ft of this lot's line and not inside another lot) is where it meets the street; the stretch from that end to the first point inside the paving line is the driveway and is never counted. A road that only runs along the band or dead-ends in it is flagged.
- **⚠ BUILDINGS GET NO SETBACK CONFLICT MARKING TODAY (found by reading the code, stated loudly as asked):** the only existing setback-conflict treatments are a text flag on a drive-in ramp ("The ramp crosses the setback.", panel only), the owner-only grading flag, and the "Setbacks exceed parcel" danger-coloured badge. So the paving mark matches the closest on-canvas treatment — danger-coloured text with a halo ("Crosses paving setback") plus a danger outline on the offending footprint — as review chrome (`data-export="skip"`, like the road-radius flags). Buildings were NOT given a mark (out of scope; their line is unchanged).
- **Yield:** no yield figure counts parking/paved area against the setback (`siteMetrics` never reads a setback), so nothing changed there; building area is computed exactly as before.
- **Edge bookkeeping:** corner insert/delete shift the paving array (`shiftPavingOnInsert/Delete`); a split carries it per edge with the cut edge at 0; a duplicated plan copies it (whole-record copy); combine makes a fresh tract with none (originals, with their paving, ride `combined.from`).
- **NO-PER-MOVE-WORK:** the conflict scan costs nothing unless a parcel has paving and is a 120 ms trailing debounce (a drag restarts the timer), view-independent geometry, declared MUST-FILTER in `hiddenContentReads`.
- **Observation, NOT filed as a bug:** reading `insertVtx` / `deleteVtx` shows `pc.setbacks` (the BUILDING array) is not shifted on a corner insert/delete, so `parcelSetbacks` falls back to the default when the length no longer matches. I could not make a corner insert fire in a headless browser to confirm it (the instrument, not the app, is on trial), so it is recorded here as unverified, and building behaviour was deliberately left unchanged.
