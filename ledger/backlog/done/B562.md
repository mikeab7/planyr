`[x]` **DONE + verified the same session. lint 0 · tests green · build green.** B559 made the newer-wins timestamp comparison type-safe with `toMs()` at two sites (the `mergeNewer` in `siteModel.js` and `pruneMigratedLegacy` in `storage.js`) but **missed a third sibling**: `importLegacyIntoCloud` (the login-time copy of on-device sites into the cloud) still used the raw `(existing.updatedAt || 0) >= (local.updatedAt || 0)`.
- **Why it bites:** `createSiteModel` keeps whatever `updatedAt` it's handed (`p.updatedAt || Date.now()`), so a legacy/imported record can carry an **ISO string** while the cloud cache holds a **number**. `number >= "2025-…"` coerces the string to `NaN`, and `anything >= NaN` is always `false` → the "cloud already newer, skip" guard silently fails → an **older** local copy can be pushed over a **newer** cloud copy (cross-device work loss) on the one-time legacy import.
- **Fix:** one line — `toMs(existing.updatedAt) >= toMs(local.updatedAt)`, mirroring the B559 fixes. `toMs` was already imported. Anti-drift guard added in `test/bugHuntGuards.test.js` (B562).
