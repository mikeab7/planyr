### B613 — Fort Bend parcel layer: switch off FBCAD's chronically-down self-hosted server, onto FBCAD's own Esri-hosted (ArcGIS Online) parcel service `[Site Planner / GIS]` (bug — recurring reliability)  *(owner-reported 2026-07-02 — "figure out why Fort Bend Appraisal District [layer] is not working well… I feel like we've had so much trouble with Fort Bend… maybe we just cache it"; minted **B613** = highest real B# across both files (B612) + 1; branch `claude/fort-bend-appraisal-issues-8j5cp3`. Closes the root cause behind the whole FBCAD trouble family — B137/B244/B245/B382/B469.)*
`[x]` **Shipped 2026-07-02.** Diagnosed the recurring Fort Bend flakiness to ONE root cause and fixed it at the source rather than adding another layer of fallback. **Every past Fort Bend incident (B137 "can't click a visible lot", B244/B245 the 45s freeze + statewide fallback, B382 "takes forever then won't click", B469 CORS) traces to the app depending directly on FBCAD's SELF-HOSTED server `gis.fbcad.org/serverarcgis2` — an on-prem ArcGIS server with no CDN/redundancy that repeatedly 503s, times out, and isn't CORS-clean, and has already migrated servers once (the "serverarcgis2" in the path).** Live-probed 2026-07-02: `gis.fbcad.org` resets the TLS connection on every path (~11.5s hang → reset) — the origin server itself, not a proxy denial. Caching alone (the owner's suggestion) would only smooth the DISPLAY tiles; it can't fix click/search when the source's query is down, and the statewide TxGIO fallback's own `/query` was ALSO failing at probe time ("operation not supported"), so both live sources could fail a click simultaneously.
- **The fix — repoint Fort Bend to FBCAD's OWN data on Esri's ArcGIS Online cloud.** Research + independent live-probe found FBCAD publishes its parcels as a hosted feature service on its own AGOL org (`services2.arcgis.com/D4saGHECICkCeoJm/.../FBCAD_Public_Data/FeatureServer/0`, layer 0 "FBCAD Public Parcel Data"). It's the SAME authoritative FBCAD data but Esri-hosted (reliable, CORS-open, no key), holds all ~385k county parcels, is **refreshed daily** (last edit 2026-07-02 at probe time — fresher than the statewide layer or any snapshot), is natively **EPSG:2278** (State Plane feet — our coordinate spine, no reprojection), and carries the full native appraisal schema (OWNERNAME, LANDVALUE/IMPVALUE/TOTALVALUE as real numbers, SITUS, LEGAL, LANDSIZEAC, YEARBUILT, land-use codes, exemptions, deed refs). Verified by direct curl: metadata (capabilities=Query), a Fort Bend point-click query (returns lot R40594 with polygon geometry in feet), and an owner-name search all succeed.
- **Single switch point (`lib/counties.js`):** `COUNTIES.fortbend` (search) and `COUNTIES_MAP.fortbend` (display + click) both repointed at the hosted `FeatureServer/0`; `idField`/`addrField` hints set to `QUICKREFID`/`SITUS` (both auto-detected anyway by `detectField`). `resolveLayerUrl`/`lookupParcels`/`makeParcelLayer`/`queryFeatures` all handle a FeatureServer layer natively — no other code change. The old self-hosted URL is retired as primary (kept in a comment). The statewide TxGIO layer **stays** the automatic outage fallback (`statewideFallbackFor` unchanged) and the display hang-guard + circuit breaker (B244/B382) remain the safety net.
- **`lib/appraisal.js`:** added `land_?size_?ac` to the Acreage matcher (FBCAD `LANDSIZEAC`, acres — not `LANDSIZEFT`) and `land_?state_?code` to Land use (FBCAD `Land_State_Code`) so the curated appraisal panel fully populates from the new schema; the TxGIO/HCAD mappings are untouched (proven by the unchanged `test/appraisal.test.js`).
- **Verification harnesses** `gis-verify/fbcad-outage-fallback-verify.mjs` + `ui-audit/verify-parcel-resilience.mjs` repointed to the new host; new `gis-verify/fbcad-hosted-primary-verify.mjs` added for the happy-path click.
