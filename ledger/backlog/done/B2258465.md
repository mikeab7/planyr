- **Root cause (measured on f20ee5a by the owner, reproduced here against pre-fix main):** every drop zone kept its OWN "a file is over me" flag driven by per-element dragenter/dragleave COUNTING. A drag that ends with no matching dragleave (released outside the window, cancelled, a failed/unhandled drop, an element unmounting under the cursor) leaves the counter above zero and the overlay on. On pre-fix main `dragenter+dragover` survived dragend, Escape, blur, mousemove, pointerdown, silence — only a matching dragleave cleared it — and (see B2258464) the hidden Site workspace's Map handler also reacted to drags over OTHER views, which is how the Library and Map overlays appeared together.
- **Fix:** the one tracker `src/shared/files/fileDrag.js` (`useFileDragActive(visible)`) replaces every per-pane counter: Library `FileBrowser`, Map `MapFinder`, Review `DocReview` read it directly; the Site canvas/deed zones keep only a *where* flag that is forced false the moment the tracker clears. It rises ONLY for a drag whose `dataTransfer.types` includes "Files" (map-feature / text drags never raise it) and clears on: the drag leaving the window (`relatedTarget` null, 120 ms grace so Chromium's in-page null hops don't flicker), a drop anywhere (handled, rejected or unhandled), `dragend`, Escape, window blur, any `mousemove` / `pointerdown` / `pointermove` with no buttons (a real drag fires none), tab hidden / pagehide, `hashchange` / `popstate` (view change), and a 2 s watchdog (a live drag fires `dragover` continuously — silence means no drag). Each overlay also shows only in the visible, active view.
- **Stopping rule:** closes when the signed-in live pass (V1683600) shows every end-of-drag arm clearing on planyr.io AND the owner's own sequence (abandoned Library drag → Map) leaves nothing up. Not closed on a sandbox null: the harness raises a REAL overlay first (VOID otherwise) and its known-good arms stay green.
