- **ROOT CAUSE, confirmed against the real code and the real rows, not reasoned in the abstract.** `pushHistory()` (`SitePlanner.jsx`) is the ONLY call in this codebase that opens an operation (`opTrackerRef.current.beginOperation`, `operationEnvelope.js`) — it is called from ~190 sites and covers every interactive drawing/editing gesture (parcel split, parcel merge, deed promotion, JSON import, version restore, clipboard paste, Standards-apply all correctly call it — verified one by one, not assumed). `envelopeNow()` (read at ENQUEUE time inside `elementSync.js`'s diff) falls back to `"unknown"` whenever nothing is open. The gap is never "the duplicate flow" specifically — it is any code path that changes the canvas's collections OUTSIDE a `pushHistory()`-covered gesture, because that state change still feeds the SAME autosave-diff effect every real edit does. `duplicatePlan`/`newPlanSameParcel`/`newSiteFromMap` (`SitePlannerApp.jsx`) only call `saveSite()`, which (per `cloudSync.js`'s `slimForCloud`) writes the `sites` metadata row and STRIPS every element collection — the parcels/elements they carry forward never touch `site_elements` until the plan is opened and `SitePlanner.jsx`'s `refetchReplace` seeds it from zero (or partial) server rows. THAT reconcile call is the one true funnel every never-synced-local-content path shares (duplicate, same-parcel, new-site-from-map, and a migrated legacy site alike) — confirmed by pulling the 7 "impossible" rows directly: they are HCAD-attributed parcels + a road carried forward by an earlier `newPlanSameParcel`/multi-parcel site seed, not a duplicate at all.
- **THE FULL AUDIT — every write path that can create a `site_elements` row, and which ones open an operation:**
  - Plan duplicate / new plan (same parcel) / new site from map / migrated legacy site (`SitePlannerApp.jsx`, `storage.js`) — write only the `sites` row; the actual `site_elements` seed happens in `refetchReplace` on first mount — **GAP, fixed**.
  - "Take over editing here" (`takeOverEditing`) — a cross-device/cross-session union-merge reconcile with no gesture and no operation open — **GAP, fixed**.
  - Undo / redo (`applySnapshot` via `undo()`/`redo()`) — `endOperation()` is never called anywhere, so an undo/redo rode whichever operation was last begun (often the very edit it reverts) instead of its own — never literally `"unknown"` (some operation is always open by the time anything is undoable) but a real misattribution — **fixed**.
  - The Standards-apply toast's own "Undo" button (`applyAllStd`) — a direct state revert with no fresh operation, and not on the Ctrl+Z stack at all — **fixed**.
  - Parcel split (`performSplit`), parcel merge/combine (`mergeParcels`), deed promotion to parcel (`promoteDeedToParcel`), JSON site import (`importJSONFile`), version-history restore (`restoreVersion`), same-plan and cross-plan clipboard paste — all already call `pushHistory()`/`ctx.pushHistory()` — **already covered, no gap** (split/merge use the generic `"edit"` kind rather than `"split"`/`"merge"` specifically; a labeling-quality gap the vocabulary's own header already calls deliberately-deferred future work, not an `"unknown"` bug).
  - Cross-tab local convergence (the `storage` event handler) — fires only when `!isCloudActive()`, at which point no element-sync engine exists to write through — **not a gap** for this bug.
  - Overlay import (DXF/PDF/DWG) — never touches `els`/`parcels`/etc. at all — **not a `site_elements` write path**.
  - Template / library placement — **no such feature exists** in this codebase.
- **THE FIX**, all in `SitePlanner.jsx`: `refetchReplace`'s seed reconcile and `takeOverEditing`'s union-merge state set now call `opTrackerRef.current.beginOperation("create")` before touching state; `undo`/`redo` and the Standards-toast "Undo" each mint their own fresh operation instead of inheriting whatever was last begun.
