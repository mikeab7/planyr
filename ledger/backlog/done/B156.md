### B156 — Hover highlight on the markup under the cursor (pre-click affordance) `[Document Review + Site Planner / UI]` (feature)  *(arrived as "NEW-2"; minted B156 — next free ID after B155)*
`[ ]` In **Select** mode, highlight the markup currently under the cursor — the element that *would* be selected on click — before the click lands, so you can see what you're about to grab. Subtle outline/glow; never disturbs the immutable PDF/drawing backdrop layer. **Depends on B155's shared `hitTest`** and must use the **same topmost/smaller-area resolution**, so the hover preview always matches what a click selects. Out of scope for B155 (a separate, lower-priority affordance) — minted net-new so B155 can ship without it.

> - **B156 — a subtle pre-click hover glow shows what a click will grab, on both surfaces.** A shared `.mk-hover` CSS class (a two-tone light-under-dark `drop-shadow`, mirroring the selection chrome so it reads on both a light sheet and a dark aerial) glows the markup under the cursor in Select mode — never recolouring it, never touching the immutable backdrop. **Document Review** computes the hovered id on the idle pointer-move path with the SAME `pickMarkup` wrapper the click uses (hover == selection by construction) and wraps ONLY the hovered markup (overlay DOM otherwise unchanged, so existing selectors/exports are untouched). **The Site Planner** sets the hovered id from each markup's own `onPointerEnter`/`onPointerLeave` — the browser's hit-testing, the exact geometry that decides a click — so its hover matches its click by construction; the hovered subtree carries `.mk-hover`. Never shown on the already-selected markup.
