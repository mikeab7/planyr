### B1923744 — Map view: draw a site record's selected parcel boundary at close zoom, alongside the pin `[Site Planner / Map]` (feature) #site-planner #parcel #gis  *(Owner chat dispatch, "NEW-1," 2026-09-27. DEDUPE-FIRST — searched Open/⏳Verify/Done/Done-archive for "parcel boundary … zoom", "selected parcel … map", "map view … parcel": no prior item draws a record's own parcel geometry on the Sites overview map at any zoom — every hit is either the live-GIS parcel-select flow inside an open plan, or the existing PLAN_ZOOM full-detail swap (unrelated: that REPLACES the pin, this joins it). Net-new.)*

`[x]` **Implemented.** `MapFinder.jsx` (the Sites overview map) already swaps a site's pin for its full plan — every element, true colors — once zoomed past `PLAN_ZOOM` (15). Below that, a record showed only its pin, however close you zoomed. New: at a much lighter `PARCEL_ZOOM` (13) — chosen so the pin/plan swap's own existing threshold is untouched — the record's own **active** parcel(s) draw as a boundary outline alongside the pin (pin stays on top; Leaflet's marker pane paints above the overlay pane by default). Self-contained: geometry already on the record (`site.parcels` / the canonical `parcelSummary` rows, same source the full-plan view and the KMZ export already read — never an external/county GIS source), reprojected to lat/long via the SAME shared `feetToLatLng` projection every other map-render path in this file already uses (no new transform). No active, georeferenced parcel → pin only, unchanged, no error — that is the expected case, not a failure.
- **Which parcel counts as "selected."** There is no single-parcel "the chosen one" in this data model — `active` is a per-parcel flag on a record's parcel array/rows, and a multi-parcel assemblage (twelve of the owner's 28 sites are multi-parcel) can have several active at once. All of them draw. Filter: `isLiveActive(p)` (active, not soft-deleted — the same guard `splitIntegrity.js` already provides for a superseded split parent) **and** a real ring (`Array.isArray(p.points) && p.points.length >= 3`) — the exact predicate the KMZ export / thumbnail / rotate call sites already use for "does this parcel count," so this feature can never disagree with them about which parcel is selected.
- **New pure module** `src/workspaces/site-planner/lib/activeParcelBoundary.js` — split out (same pattern as `layerZoomGate.js` / `parcelDisplayZoom.js`) so the zoom gate, the parcel filter, and the reprojection outcome are unit-testable without Leaflet or a DOM: `PARCEL_ZOOM`, `showActiveParcelAt(zoom, showPlans)`, `activeDrawParcels(drawParcels)`, `reprojectParcelRing(points, lat0, lon0, project)`.
- **LOUD-FAILURE.** A parcel that IS selected and georeferenced but whose ring reprojects to a non-finite lat/long (a real defect) reports `map-active-parcel-reproject-failed` via the existing `reportClientEvent` telemetry channel and is skipped — never a silent drop dressed as "no parcel," and never a thrown error that would take down the whole Sites map for every other record in view.
- **Style.** Solid accent-colored stroke + a light accent fill (`PAL.accent`, the same token/opacity family the file's own existing parcel-highlight layer — `hilitesRef` — already uses for "outline this one parcel"), non-interactive (a highlight, not a second click target), class `map-active-parcel-boundary` for test selection (GOTCHA: Leaflet vector layers are SVG with no accessibility node).
- **Edge cases, per the dispatch:** no parcel selected → pin only, no empty overlay (the existing `if (!site.origin) return;` gate plus the active-parcel filter both naturally produce this — no extra code needed). Multiple active parcels → all of them draw. A local/non-georeferenced record → the WHOLE site (pin included) is already skipped upstream (`site.origin` absent) — there is no separate per-parcel frame; every parcel on a record shares its one site-level origin, confirmed in code before building. Rapid zoom in/out → no duplicate/leaked layer (same teardown-and-rebuild lifecycle the existing pin/plan effect already uses; the new `showActiveParcel` boolean is derived outside the effect and added to its dependency array, so — like the existing `showPlans` — the layer only rebuilds when the THRESHOLD is crossed, never on every zoom tick, preserving the existing B64 "don't drop a click in flight" guarantee). Pin and parcel far apart (bad anchor) → both draw where they actually are; the pin is never moved to compensate.
- **Red-proof test.** `test/activeParcelBoundary.test.js` (14 cases) — the module is net-new, so every assertion fails on unmodified `main` (nothing to import); confirmed via `git stash` against this branch's own pre-change tree.
