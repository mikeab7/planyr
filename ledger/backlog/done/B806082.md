- **AUDIT-FIRST found the mechanism was already built and already had the RIGHT documented intent — it just wasn't wired to the one place a natural right-click actually lands.** The leader's own `<g>` already carries `onContextMenu={(e) => onCalloutContext(e, c.id, i)}`, and "Delete Leader" (gated on `mapMenu.leaderIndex >= 0`) already exists in the map menu (B919). But once a callout is SELECTED, `calloutHandles` renders three grip kinds into the always-on-top `data-handle-layer` group: the box's width grips, a per-leader TIP grip (a filled circle sitting EXACTLY at the arrowhead — the single most obvious place to aim a right-click at a leader), and a per-leader ELBOW grip. In SVG, paint order is hit-test order, so any of those wins a press landing on it — and NONE of the three carried an `onContextMenu`. A right-click aimed at a leader's tip therefore fell straight through the leader's own handler (never reached — the grip is topmost) all the way to the empty-canvas map menu, in total silence. The tip grip's own adjacent code comment even already said "a single leader is removed by right-clicking it → 'Delete Leader'" — the intent was documented, the wiring wasn't there. This is a fresh instance of the CHROME-NEVER-EATS-A-PRESS rule: a handle that paints over its own object's body must forward the press to that object, never swallow it.
- **THE FIX.** All three grip kinds now forward a right-click to the SAME handler the object they belong to already uses: the tip and elbow grips call `onCalloutContext(e, c.id, i)` (their own leader's menu, offering Delete Leader); the width grips call `onCalloutContext(e, c.id, -1)` (the box's menu). No new hit targets, no new menu rows — reusing the existing fat leader hit-lines' handler exactly as the item's own "already measured" note directed. A locked callout's width grips already render `pointerEvents:none`, so a right-click there correctly falls through to the box body underneath (which still forwards) rather than needing a separate guard.
- **What is unchanged:** the leader body's own `onContextMenu`, the box body's, the "Delete Leader" row's gating and its undo behavior (already correct per B919) — only the three previously-silent grip nodes gained a handler. Right-clicking empty canvas away from any callout is untouched and still opens the ordinary map menu (Zoom to fit / Paste / Export…).
