`[x]` **Fixed + shipped this session.** After B613 switched Fort Bend to FBCAD's Esri-hosted layer, every Fort Bend click still flashed the amber **"Statewide backup — Fort Bend county's server is unavailable; shown from TxGIO"** notice — a false alarm the B613 change was meant to end.
- **Root cause — the eager RACE, NOT the circuit breaker (the live report's leading hypothesis was close but off).** The click path (`identifyParcelEager`, `arcgis.js`) queries the county CAD and the statewide TxGIO layer **in parallel and takes the first to answer**. Its doc comment assumed "real CADs are listed before the statewide fallback, [so] a healthy county still answers first" — but list order does NOT govern a parallel race. FBCAD's Esri FeatureServer identify is a hair slower than TxGIO's, so **TxGIO kept winning the race**; the winning `hit.county` became the statewide key, and the old flag `viaBackup = STATEWIDE_KEYS.includes(hit.county) && realPrimaries.length > 0` (`MapFinder.jsx`) read "statewide answered" as "the county server is down." The breaker was demonstrably **closed** (the live network capture shows the app calling FBCAD and getting **200 on every click**), and it already correctly ignores "200 + 0 features" (B245) — so the breaker was never the problem.
- **Fix — decouple the "backup" label from the race, key it off real availability.** New pure `isStatewideBackup(hitCounty, { realPrimaries, queried, statewideKeys })` in `lib/sourceHealth.js`: a statewide answer is a genuine "backup" **only when NO real CAD for this point was queryable this click** — i.e. every real primary had its breaker open and was dropped, so TxGIO was the only source left. When a healthy CAD **was** queried (whether or not it won the race), statewide merely being fastest is no longer treated as an outage → no notice. Wired into both the map-click (`handleClick`) and search-select (`selectParcelAt`) paths, replacing the two identical `viaBackup` expressions. A genuine outage (real CAD breaker opens) still surfaces the honest backup notice, and the imported parcel/appraisal data is unchanged.
