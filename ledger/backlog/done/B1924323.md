`[x]` **AUDIT-FIRST correction to the dispatch's own inference — the bug is NOT scoped to Lease comps, and fixing only `validateComp` alone would have left a general, unreported defect live.** `comps.js`'s `emptyDraft()` sets `leaseRatePeriod: ""` (an empty string, never null) for EVERY comp type, by design — the field is deliberately never defaulted or guessed (a real 12x MO/YR error risk, per the file's own NEW-1 2026-09-10 comment). `draftToComp()`'s existing per-field conversions (`num()` for numeric fields, `|| null` for `compDate`/`leaseCommencementDate`) never touched `leaseRatePeriod`, so it passed straight through as the literal `""` into `compToRow()`'s `lease_rate_period: comp.leaseRatePeriod ?? null` — and `??` only substitutes for `null`/`undefined`, never for an empty string. Since Postgres's `lease_rate_period text check (lease_rate_period in ('annual','monthly'))` accepts `NULL` but rejects `''` outright, EVERY comp type's untouched, not-applicable `leaseRatePeriod` field would raise the identical raw constraint error the moment it reached an insert — Land and Building-sale comps simply hadn't hit it yet (production `comps` currently holds only 7 rows, all type Lease, confirmed via direct SQL before writing the fix).
`[x]` **FIX, part 1 — the general defect, at the encoding boundary.** `draftToComp()` now converts `leaseRatePeriod: d.leaseRatePeriod || null`, the identical `|| null` treatment `compDate`/`leaseCommencementDate` already get — so no comp type can ever again send the literal empty string to a Postgres column with a CHECK constraint.
`[x]` **FIX, part 2 — the reported symptom, blocked client-side before any insert.** `validateComp()` gained `if (draft?.compType === "lease" && !draft?.leaseRatePeriod) errors.push("Pick a rent period (MO or YR).")`, mirroring the existing "Pick a comp type." pattern exactly. Since `validateComp` is the SAME gate both the single-comp `CompForm` (`CompsPanel.jsx`) and the batch `CompEntryGrid.jsx`'s row-readiness check (`rowIsReady`/`readyRows`) already call, this closes the actual reported path (the grid) and the single form in one change — a Lease row missing a period is now excluded from "ready" rows and never reaches `insertComp`/`updateComp` at all, with the friendly message rendered by the grid's own pre-existing `ProblemsList` "Row N — …" line (no new UI needed) and by `CompForm`'s existing error banner.
