- **Fix — reconstruct the browser's own double-click test:** `e.detail` is 0 on a `pointerdown` (per the Pointer Events spec — click-count only rides mouse events), so a small `isDoubleTap(e, id)` replays the native rule — a second press on the SAME feature within **350 ms AND within 14 px** of the first (time **and** distance gates). Added to `startMoveCallout` (box part), `startMoveMarkup` (line/polyline/easement), and `startMoveEl` (non-grouped centerline road) → opens the in-place editor instead of starting a move. The **distance gate is what stops a "click here to select, then press over there to drag" gesture from misfiring as an edit** (an adversarial-review finding — fixed before merge). Edits only **UNLOCKED** features (a locked line/road stays select-only — also a review finding). Opens the same editor the old `onDoubleClick` did (`beginEditCallout` / `beginEditInline`), kept as a secondary path. Also restores the promised double-click-to-edit for the B620 inline labels (same root cause), so the tool hints ("double-click to edit") are now true for callouts, text boxes, and labeled lines/roads.
