- **LIBRARY — ExcelJS, pinned exact `4.4.0`.** SheetJS (`xlsx`, already a dependency here for an UNRELATED server-side read of tax-rate data in `functions/api/taxrates.js` — read-only, no conflict) was ruled out: its free "Community Edition" build does not WRITE cell styles on its own round trip (no bold/italic/underline/fill/border survive without the paid Pro tier), which the owner's own spec explicitly requires. ExcelJS writes and reads the full set natively — formulas as live formulas, number formats, fonts, fills, borders, alignment, merged cells, column widths, row heights, freeze panes, and workbook-level named ranges — with nothing paid. **Lazy-loaded**: `lib/xlsxIO.js` is dynamically `import()`ed only when the File menu's Export/Import actions fire (`ModelApp.jsx`'s `loadXlsxIO()`, a single memoized loader so both directions share one fetch) — confirmed in the production build: ExcelJS lands in its OWN chunk (`xlsxIO-*.js`, ~947 KB / 274 KB gzip) that is **absent from the Model route's own eager-chunk list** (`node ui-audit/perf-bundle-audit.mjs`: `route model 674.1 KB across 5 chunk(s): index, ModelApp, AppHeader, serializeWrites, cjs-interop` — no xlsxIO chunk in that list), so opening the Model tab never gets slower for someone who never exports or imports. `csvIO.js` is dependency-free (hand-rolled RFC4180-ish encode/decode) and stays a plain static import — CSV never needs ExcelJS at all.
- **EXPORT (`exportWorkbookToXlsxBlob`)** — every sheet, real Excel sheet names (sanitized: ≤31 chars, none of `: \ / ? * [ ]`, de-duplicated). A formula cell writes as `{formula, result}` (a real formula string PLUS the live-evaluated cached value, so the file shows a correct number even before Excel's own recalculation runs) — never flattened. Number formats (`formatAt`) are ALREADY valid Excel format syntax (this app's own tokens — `#,##0.00`, `0.0%`, `$#,##0.00`, the `[Red]` accounting convention — were designed against the same grammar) and pass straight through with no translation; a date-typed value with no explicit format still gets `yyyy-mm-dd` so it doesn't show as a raw serial number in Excel (matching what this app's own on-screen `formatValue` already shows for an unformatted date). Styles (`styleAt`) map onto ExcelJS's `font`/`fill`/`alignment`/`border`. Horizontal merges (`sheet.merges`) become real Excel merged cells — non-anchor cells inside a merge are explicitly EXCLUDED from the cell-writing pass (Planyr never renders their own content once merged, so writing it would put data into the file that never appeared on screen). Named ranges (`sheet.names`) become real Excel workbook-level defined names, sheet-qualified. Column widths/row heights/freeze panes carry over with the standard px↔Excel-unit / px↔point conversions.
- **IMPORT (`importXlsxToWorkbook`)** — every worksheet, in order, through `migrateSheet`/`migrateWorkbook` (the SAME entry point every other foreign/legacy blob in this module already reads through, so capacity floors and every newer field default correctly with no new migration path). **Formula support test (`checkFormulaSupport`)**: an Excel formula (with any `_xlfn.`/`_xlws.` compatibility prefix real Excel files carry for newer functions stripped first) is kept as a REAL, LIVE formula only if it parses AND every function it calls is one `shared/formula/formula.js` implements (`FUNCTION_NAMES`) — this engine's syntax is already Excel-A1-compatible for cell/range/name/cross-sheet references, so the common case transfers verbatim. **Where the function is NOT supported** (VLOOKUP is the standing example — genuinely common in real Excel files, never implemented here — confirmed absent from `FUNCTION_NAMES` by its own unit test): the cell keeps the FILE'S OWN CACHED VALUE as a plain literal (nothing silently dropped, zeroed, or left to recompute into a confident wrong `#NAME?`), and the original formula text is recorded in a new per-cell `sheet.unsupportedFormulas` map (`sheetModel.js` — cascades on row/column insert/delete exactly like `dismissedInconsistencies`, tombstoned on delete, and CLEARED the moment the user types a real edit over the cell, via `setRaw`/`blankRange`) — one unsupported cell never fails or degrades the rest of the sheet. `SheetView.jsx` paints a small top-left corner marker (`unsupportedFormulaAt`, mirrors the existing top-right inconsistency-flag marker, `pointerEvents:none` per CHROME-NEVER-EATS-A-PRESS) with the original formula text as its tooltip, so the cell is findable without a separate panel. Merge-follower cells are skipped on read (ExcelJS's own `ValueType.Merge`); a vertical/block merge keeps its content but drops the visual merge (this app models horizontal merges only — `sheetModel.js`'s own header, B1007283 tracks the vertical case as separate future work — a stated, not silent, limitation). Workbook `definedNames` import into the target sheet's own `names` table (validated against the same naming rules `namedRanges.js`'s `validateNameText` already enforces — an Excel `_xlnm.`-prefixed internal name like Print_Area is filtered out, it is not a user range).
- **CSV (`lib/csvIO.js`, deliberately the LESSER path, never the default button)** — export is the ACTIVE sheet's DISPLAYED values (`displayFor` — formulas already computed, numbers already formatted), trimmed to the sheet's own used range; import lands as a brand-new APPENDED sheet (`addSheetWithContent`, a new small sheetModel.js workbook helper reusing the existing sheet-naming dedupe rule) — never replacing the open workbook, since a CSV is inherently one flat table, not "the user's whole model." Column headers in a dropped CSV land as ordinary row-1 DATA, never as a column identity (columns stay plain-lettered) — the scope guard's "no real-estate opinion" applies to import shape too.
