- **Menu (`ovMenu`):** a portalled, viewport-clamped floating menu at the cursor (mirrors the element `typeMenu` / B127 portal pattern), opened by `onOverlayContext` from the **canvas overlay `<g>`** (unlocked) AND its **Overlay-panel row** (so a locked overlay — pointer-inert on the map — is still reachable to unlock). Entries: **Copy, Duplicate, Paste** (Paste disabled on an empty clipboard), **Bring to front / Send to back** (disabled at the ends; draw order = array order), **Lock / Unlock**, **Align to base edge…** (disabled when locked or no parcel), **Delete**. Right-click `preventDefault`+`stopPropagation` so the canvas pan/marquee never eats it.
- **Copy/Duplicate/Paste touch only the overlay's transform layer + its source *reference*, never the source bytes:** a copy/dup/paste shares the same `src` + `storageKey` (no re-import). `removeOverlay` is now **ref-counted** — it only deletes the cloud source object when no OTHER overlay still points at that `storageKey`, so deleting one of a duplicated pair can't orphan the sibling's image. Copy → `overlayClip` ref; Paste lands at the cursor (B417 pattern) or offset; `Ctrl/⌘ C/V/D` wired for a selected overlay (separate from the element clipboard; selecting an overlay sets `sel=null`, so no collision).
- **Delete is count-verified (silent-failure rule):** `removeOverlay` refuses if the id isn't present, and a `setTimeout` re-reads `stateRef` to confirm the row actually went — a no-op delete flashes a loud "⚠ Delete didn't take" warning instead of a phantom success.
- **Single-overlay note:** the Site Planner selects one overlay at a time (`selOverlay`), so the menu is single-target (the brief's multi-select-for-Delete/z-order is moot until overlay multi-select exists). Every op is undoable (`pushHistory`). Esc clears the menu + any armed align.
