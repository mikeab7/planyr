- **`convexDeficiency(isPaved, bbox, step)`** — grid-samples the box, takes the convex hull of every PAVED cell, and counts UNPAVED cells that fall INSIDE that hull. A perfectly filled convex shape (a solid rect, a square corner) reads 0. A corner rounded by a real, tangent curb return reads a SMALL, bounded deficiency (the circular segment the fillet itself cuts from the square corner — expected, not a defect). A raw bevel or a dropped return reads a LARGE one (the whole triangular gore) — this is a RATIO/MAGNITUDE measure against a known-good reference, never a bare "must be exactly 0" (a real fillet can never satisfy that).
- **`convexDeficiencySelfTest`/`assertMeasurableConvexDeficiency`** — the mandatory control (DRIVER-SCROLL-IS-NOT-APP-SCROLL §6 / this repo's own established discipline): punch a disc out of an otherwise-paved region and require the SAME scan to report a large, nonzero deficiency; THROWS if it doesn't, so a "0" on real geometry can never be trusted as vacuous.
- **`deficiencyAreaSqFt`** — mirrors `enclosedAreaSqFt`'s own unit convention.
- **Both measures kept, deliberately — neither substitutes for the other.** `floodFillEnclosed` still catches a true enclosed courtyard (which `convexDeficiency` also sees, since the hull spans it too); `convexDeficiency` is the one that catches an OPEN notch, which `floodFillEnclosed` structurally cannot (the fill walks straight through anything reachable from the scan box's own border).
