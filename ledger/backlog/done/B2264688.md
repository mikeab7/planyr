- **Root cause (measured, not inferred):** the canvas and the built sheet agree on paint order (the clone IS the canvas; a full feature-sequence diff over the Goose Creek plan was identical). The PDF export's DEFAULT ("Flatten markups" OFF, B2127664) lifts every markup / callout / measurement OUT of the page and writes it as a native PDF annotation — and a PDF always paints annotations ABOVE the page. So any markup stacked behind a building, court or parking field printed over it, washing it in its fill. No second ordering rule exists; z is untouched.
- **Fix (`lib/annotationExtract.js`):** an annotation is lifted (still editable in Bluebeam) only when it paints AFTER the last piece of page content (non-annotation features, placed drawings, the lifted GIS band). - **Recurrence ×2 (2026-10-19, Michael: "Flatten markups" OFF, rectangles burned into the page in Bluebeam, a measurement on the same sheet editable).** Amends B2127664 (#2057) and this item's #2309 rule.
  - **Root cause (measured, mechanism confirmed in the DOM order of the real clone):** `lastContent` counted ANY non-annotation feature, any placed drawing AND the `[data-gis-front-band]` group as page content and pinned every annotation that preceded the last of them. (1) A reference drawing promoted above the plan is ladder rung 7 — after every default markup (rung 6), before every default callout/measure (rungs 8/9) — so it pinned all the rectangles/lines/clouds/polygons and left callouts and measurements lifted: exactly the report. (2) **The second candidate is REAL too:** `SitePlanner.jsx` renders `<g data-gis-front-band>` whenever the plan has an `origin`, AFTER the markup-above pass (markups render at ~line 24974, the band at ~24995) and whether or not any layer is lifted into it — so on EVERY geolocated plan with no reference drawing at all the empty band pinned every markup. It sits after rung 6 and before the callout/measure passes, i.e. it is not a rung of its own but a host that is always present.
  - **Decision (stated):** the pin rule is now grounded in the ladder, not in "precedes the last content node". An annotation is pinned only when (a) the user sent it BEHIND THE PLAN (`behindEls`, rungs 2–4), or (b) page content that paints after it genuinely overlaps it in plan space (a later element, a later easement/encumbrance line, or an annotation already pinned — the selection-lift case). **A promoted reference drawing and a lifted GIS layer never pin a markup** — the owner's intent for #2309 was "a markup I sent behind the plan must not print on top", not "anything under a transparent overlay is burned in"; an empty front band is not content. Parcel outlines/chips and element labels stay excluded (thin linework; unchanged deviation). Relative order is preserved by a top-down pass: anything earlier than a pinned object that overlaps it is pinned too, so a flattened object is never above a lifted one.
