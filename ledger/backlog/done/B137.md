### B137 — Fort Bend parcels render but aren't clickable (display covers more counties than the click queries) `[Site Planner / map]` (bug) — coupled to B11/B13/B36  *(filed as "B130" in the brief; minted B137 — `main` concurrently took B130–B136, so this is the real next free ID)*
`[x]` Repro: Map view → "✓ Selecting — click lots" → pan to a Fort Bend area (purple parcel outlines visible) → click directly on a lot → nothing selects; "No parcel right there — zoom in and click directly on a lot" fires. Harris parcels select fine at the same zoom. Expected: clicking any displayed parcel selects it, regardless of county.
> **Root cause (confirmed by live endpoint probes, not assumption).** The visible outlines and the click-query had different *coverage*. The `chambers` entry in `COUNTIES_MAP` is actually the **statewide TxGIO** parcel layer (one service covering all 254 Texas counties); its display layer (`makeParcelLayer`) has no county filter, so when zoomed in it **paints parcel outlines everywhere — including Fort Bend.** But on click, `candidateCountiesForPoint` only made TxGIO a query candidate inside the narrow *Chambers* bbox. A Fort Bend click therefore queried only **Harris** (returns nothing — verified 0 features at a Sugar Land point) and **FBCAD** — and FBCAD's host (`gis.fbcad.org/serverarcgis2`) is currently **down (HTTP 503 on every path, even the host root; Harris/TxGIO/Esri all return 200 from the same network)**. So the click had no answerer and fell through to the "no parcel" message, even though the TxGIO layer that drew the outline *does* return that exact Fort Bend lot on a point query (verified: `county:'FORT BEND', prop_id 40594`). This is precisely the brief's hypothesis #1 — display covers more than the queried source. (The brief's other guesses — separate selection service, missed reprojection, click tolerance — were ruled out: display and click share the same resolved per-county URL, `queryAtPoint` already sets `inSR:4326`, and Harris selects fine via the identical code path.)
> **Fix (minimal + structural; branch `claude/magical-ramanujan-v1dnuw`).** Marked the TxGIO source `statewide:true` in `COUNTIES_MAP` and made `candidateCountiesForPoint` (`lib/counties.js`) **always append any statewide source as a universal fallback** — so the click can always select an outline it can see. Appended **LAST**, so a county's own CAD still answers first when reachable (more authoritative, richer fields) and the statewide layer only catches clicks the county CAD didn't; the answering county is then corrected to its true CAD key by the existing **B36(a)** `countyAtPoint` relabel (already keyed on a `chambers`-sourced hit, so no extra wiring). This also makes Fort Bend selection **resilient to FBCAD being down** (TxGIO covers it) and keeps `viewCounty`/Layers-panel jurisdiction unchanged (bbox matches still lead). No change needed in `MapFinder` beyond what already existed. 5 new unit tests in `test/counties.test.js` (Fort Bend routes to fortbend + statewide fallback; fallback ordered last; no dup when in-bbox; Harris still leads; out-of-bbox still gets statewide). lint 0 errors · **180 tests** · build green; lazy chunk split intact.
> **Coupled to B11/B13/B36:** same county-resolution theme. Does NOT close B13-pt1 (true point-in-county polygons vs. the bbox pre-filter) — that's still the deferred, more-accurate routing; this is the resilience/coverage fix that makes "click anywhere selects the parcel you see" hold today.
