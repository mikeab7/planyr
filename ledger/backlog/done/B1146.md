- **The report.** A breach printed one sentence — `2286.3 KB exceeds 2265.6 KB by 20.7 KB` — and stopped. That reads identically for a 20 KB feature and a 20 KB dependency bump, so every red run cost somebody a local checkout, a local build and a manual diff before they could even decide *optimize this* vs *this is a dependency, ratchet it deliberately*.
- **Attribution.** `vite.config.js` gains a `chunk-module-stats` plugin that writes `dist/.vite/chunk-modules.json` — each chunk's per-module size, straight out of rollup's own `chunk.modules`. **No new dependency, no extra parse**, and inert at runtime. The audit folds it into **vendor / app-shared / app-route** buckets per route and prints the heaviest dependencies. Honest limit stated where the numbers are produced: rollup reports `renderedLength` (post-tree-shake, **pre**-minify), so every attributed number is SCALED by `on-disk ÷ summed renderedLength` for its chunk — the buckets sum exactly to the real chunk sizes, and the split is proportionally faithful, but no single module's number is a precise minified size.
- **Base-ref diff.** `scripts/perf-base-stats.mjs` resolves the PR's base (or `HEAD^` on a push to main), checks it out into a throwaway git worktree with `node_modules` symlinked, builds it, and snapshots it; `perf-bundle-audit.mjs --compare` then names **which modules and packages moved and by how much**, biggest mover first, plus the per-route bucket deltas. Wired into `build.yml` ahead of the gate step so a failing run's log alone carries the diagnosis. `fetch-depth: 0` added to the checkout, because a depth-1 clone has no base commit to compare against.
- **DIAGNOSIS, NEVER A GATE — by construction.** `perf-base-stats.mjs` exits 0 on every failure path (shallow clone, unresolvable base, a base that does not build, a base predating the stats plugin) and prints the reason. Module ids are made CWD-relative so the base worktree's different path does not make every module look moved. And when the base snapshot has no per-module data, the module/package/bucket sections are **withheld entirely** rather than diffed against nothing — subtracting from an absent base labels every module in the build as new in this PR, which is worse than saying nothing. A diagnostic that can turn a build red is a diagnostic people delete.
- **It paid for itself immediately:** the 4× overstatement of the analysis stack recorded on B1064 came out of this attribution, and so did the finding that `SitePlanner.jsx` alone is 581.2 KB of a 1378.9 KB chunk.
- Evidence: `npm test` 6483 green · lint 0 errors · build green · verified end-to-end locally against `HEAD^` (headline metrics compared, per-module withheld with its reason, exactly as designed for a base that predates the plugin).
