**THE SORT DECISION, stated rather than silently chosen, per the brief's explicit instruction.** The table now sorts **alphabetically by name, unconditionally** — the same fallback order B1411504 already established for the undated case, kept on as the only sort now that there's no date to sort by first. **Quiet time (real edit recency) is available and real (0–31 days across the owner's rows) and is deliberately NOT the sort.** He explicitly rejected quiet-first ordering when this card was designed — his words: *"I don't know that something that's been quiet the longest should really be the one at the top."* That verdict doesn't change just because the alternative it was weighed against (deal date) is now gone too; making quiet time the sort now would be silently doing the thing he already said no to. The "Quiet for" column itself is untouched — it still shows per pursuit, just never drives order.

**WHAT ELSE WAS REMOVED, and why, beyond the column itself.** `pursuitsList.js`'s `nextContractualDate`/`NEXT_DATE_FIELDS`/`allPursuitsUndated`/`nextLineTone` (and their two threshold constants) are deleted rather than left as dead code, per this repo's own no-dead-code discipline (the same call B1268017 itself made removing the superseded "Pursuits by activity" card). Confirmed, before removing, that nothing else on the Dashboard reads `feasibilityExpiry`/`loiDate`/`closingDate`: `dashboardPipeline.js`'s `groupProjectsByGroupId` carried the three fields through ONLY for `pursuitsList.js`'s `nextContractualDate` to consume — no other card (Pipeline, Jump back in, Going quiet, Locations map, Needs attention, Comps, Schedule health) touches them. So the fields are also dropped from `groupProjectsByGroupId`'s output and from `dashboardSitesFetch.js`'s Supabase select — the dashboard no longer fetches them at all. **Untouched, deliberately:** the three date fields on the site model (`siteModel.js`), the "Deal dates…" editor (`DealDatesForm.jsx`, `MapFinder.jsx`'s site menu, `setSiteDates`) — this is a Dashboard-card-only removal, not a data-model change, and no data was written to or repaired on any of the owner's rows.
