### B2618896 — Schedule grid: the row highlight stopped short of the ID and Task cells (selection tint / cell fill hidden under the frozen columns) `[Scheduler]` (bug) #scheduler #ui  *(owner chat block NEW-1, 2026-11-02, from a screenshot of Goose Creek / PI, Grid view on planyr.io. Related, not a recurrence: B2132256 shipped the frozen ID/Task columns this defect lives in. DEDUPE-FIRST checked Open / Verify / Done: no earlier item for this symptom.)*
`[x]` **✅ DONE 2026-11-02 — live-verified (V2063568 PASSED on served build ec77d2d, test account, throwaway schedule, 13/13; PR #2790).** The highlight now runs edge to edge; ID, Task and date cells paint one colour on every row.
- **Root cause (MEASURED, not the brief's guess as stated).** The brief guessed the frozen cells "paint their own background over the row's". Half right: they DO paint their own opaque background (it must stay solid so sideways-scrolled columns never show through), and for a plain health-coloured row (Complete green / Needs Attn. red / In Progress yellow / Paused) or a user row colour it already matched the row — measured, those rows were never wrong. The defect was the LAYER ORDER of that frozen background. `pinStyle(k, [rowBg, overlay])` built a CSS multi-layer `background-image`, and CSS paints the FIRST layer on TOP, so the row colour was painted OVER the cell's own range-selection tint and per-cell fill. The unfrozen cells (a single `background-color`) showed them; the frozen ID/Task cells did not. Result: a selected range or a filled cell coloured from START rightward and stopped at the frozen columns. Reproduced on the pre-fix page: a green row with a pink fill on ID..DUR painted ID `rgb(214,250,226)` / Task `rgb(214,250,226)` / Start `rgb(251,207,232)`; a Task→Finish range painted the blue tint on Start and Finish but not on Task; a full selected row tinted every cell except ID and Task.
- **Fix, where the colour is decided (`public/sequence/index.html`, `GridView`).** (1) ONE module-scope rule, `pinnedFillLayers(fills)`, lists a frozen cell's fills bottom→top and reverses them for CSS, so the cell's own overlay is on top of the row colour. (2) The cell computes its overlay ONCE (`cellOverlay = tinted ? "#dbeafe" : cfmt?.fill`) and both the unfrozen cell (`backgroundColor`) and the frozen layer stack read that one value, so the left cells and the rest of the row cannot drift apart. (3) The body cell no longer sets the `background` SHORTHAND beside the frozen cell's longhands (a shorthand re-applied on a re-render resets them). Frozen cells stay solid: opaque `--bg` under opaque layers, no opacity anywhere. The row colour (`rowBg`) was already one variable shared by the row and its frozen cells; untouched.
- **Sandbox proof (red/green).** `ui-audit/verify-row-highlight-continuous.mjs` reads the PAINTED colour of the ID, Task and Start cells on every row kind (health colours, row colour, expanded parent, indented child and grandchild, collapsed parent with lock, cell fill, range selection, whole-row selection), with a known-good arm that must report the known health colours, then repeats scrolled sideways + down in a narrow pane and on the grid side of Split. Against the pre-fix source it FAILS (6 failures); on the fix 11/11. CI half: `test/scheduleRowHighlightPinned.test.js` runs the real `pinnedFillLayers` sliced out of the page, asserts frozen == unfrozen paint over every row colour × overlay, and fails at extraction on the pre-fix source (function absent). Neighbouring `test/scheduleGridPinnedColumns.test.js` green.
- **Checked and not changed.** Rows with no highlight look the same (one layer, same colour). Hover and the selected-row outline are `::before` lines drawn on each cell (not a background) and are untouched. The Schedule page has ONE light palette (`:root` is its only token set; no dark variant), so there is no dark-theme state to differ. Print/export: the grid body is not what the Gantt export (`buildGanttSVG`) or the Task Report table reuses; the Task Report rows already paint `rowColor` across a whole `<tr>`, so there is nothing to mirror.
- **No contradiction with `## Owner product constraints`** (checked the list; none concern row paint).
