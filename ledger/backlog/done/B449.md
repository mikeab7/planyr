### B449 — SPA fallback serves index.html for a missing /assets/* chunk (masks a 404 as a text/html MIME error) `[App Shell / Deploy]` (bug)  *(owner-dropped 2026-06-24 as "NEW-1"; shipped same session per STANDING RULE #1)*
`[x]` **DONE (branch `claude/youthful-volta-ns1n75`). lint 0 · 1468 tests · build green. Live-edge 404 confirmation delegated to Cowork (the sandbox's vite-preview can't reproduce Cloudflare's edge — verified it serves index.html for a missing /assets path, which is exactly the masking bug, but only Cloudflare honors `_redirects`).** Repro: requesting a content-hashed chunk a newer deploy deleted (`/assets/SitePlannerApp-<deadhash>.js`) returns 200 + index.html (text/html) instead of a real 404 → the browser tries to parse HTML as a JS module and dies with "Expected a JavaScript module script … MIME type text/html" / "Failed to fetch dynamically imported module".
- **Root cause:** the Cloudflare Pages project answers unmatched paths with index.html (SPA not-found handling), which catches missing `/assets/*` too. There was no in-repo routing file to stop it.
- **Fix:** added **`public/_redirects`** (copied to `dist/` like `public/_headers`) with **NO** `/* /index.html 200` catch-all — Planyr uses HASH routing (`#/…`, `src/app/route.js`), so every real navigation already lands on a static file and no catch-all is needed. A single rule `/assets/*  /404.html  404` forces a missing chunk to a real 404 (Cloudflare serves real static files BEFORE `_redirects` rules, so it can NEVER 404 a live asset — only a deleted one). Added a tiny dependency-free **`public/404.html`**. Confirmed `_redirects`/`_headers`/`404.html` all emit to `dist/`. The brief's prescribed catch-all was the WRONG fix here (it would *cause* the masking); flagged + corrected.
