- **ROOT CAUSE, confirmed in the code (AUDIT-FIRST), not assumed.** The bar's three groups were built at three different times by three different passes and never reconciled onto one shared style: File's button hardcoded its own `borderRadius: 3` (a one-off, from the earlier B727504 "give File a border" pass) while `dGhost` — the shared ghost-button style every other chrome button on this bar already used — carries `borderRadius: 8`; the Undo/Redo pair was wrapped in its own `<div style={{ background: "var(--hover-chrome)", borderRadius: 10, padding: 2 }}>` (a filled pill, unique to that one group); Zoom-to-fit had no wrapper styling at all. `var(--hover-chrome)` is the same token a *hover* state washes any chrome button with, and it sits close enough to the disabled-icon fade (`.tb-icon-btn:disabled { opacity: .38 }`, dimming the SAME `fill="currentColor"` glyph) that a disabled Undo/Redo pair read as one indistinct grey smear rather than two clearly-off controls — exactly defect (2) in the report. The icon SHAPES themselves (`components/icons.jsx`) were already consistent — all four (`UndoIcon`/`RedoIcon`/`ZoomFitIcon`/`LayersIcon`) are `fill="currentColor"` MDI paths from the B727504 pass — so the "heaviest blackest strokes on fullscreen, faintest on undo/redo" read was the CONTAINERS (grey-on-grey pill vs. bare glyph on transparent chrome), not the glyphs; no icon path was touched, per the report's explicit scope note.
- **THE FIX — one chrome system, defined once and applied to all three groups, not one control nudged.** Two new shared constants, `TB_H = dIcon.height` (30) and `TB_R = dGhost.borderRadius` (8) — deliberately reusing the values the icon buttons and the app's default ghost button ALREADY used, rather than inventing new numbers, so the fix is "make File match the app's existing standard," not "invent a fourth number everyone must now match." **(1) File** now sets `height: TB_H, borderRadius: TB_R` instead of its one-off 3px radius / implicit ~29px height, so it sits on the exact same height/radius grid as the icon buttons. **(2)** The Undo/Redo group's filled-pill wrapper (`background`/`borderRadius: 10`/`padding: 2`) is removed entirely — the pair now renders bare, exactly like the Zoom-to-fit button beside it, with no container to ever carry a disabled-adjacent color; grouping is by the bar's existing `vSep` 1px divider only (File | History | View), never a filled tray. **(3)** Optical weight and icon-family consistency fall out of (1)+(2) for free — once all three groups share the same bare/icon-button treatment on the same transparent chrome background, the icons (already identical MDI stroke weight from B1148) read at the same weight; no glyph was redrawn. **(4)** Height/radius/baseline are now identical by construction (30px / 8px / one shared vertical center — proven ±2px in the live check below). **(5)** Icon families — untouched, per the scope note; already correct. **(6)** File's caret is de-emphasized to match the muted-token convention every other disclosure caret in this app already uses (`railHint`'s `PAL.chromeMuted`, the plan-caret at the breadcrumb) — `fontSize: 9` + full ink color → `fontSize: 10.5` + `color: PAL.chromeMuted`, plus the flex `gap` between "File" and the caret widened from 5 to 6 for real spacing — rather than a solid full-weight triangle jammed against the word. The caret stays the same "▾" character used in dozens of other menu/dropdown triggers throughout this app (verified — `railHint`, the plan chip, the Add ▾ row, the rail tool menus all use the identical glyph), so this is "the rest of the app's own convention," not a new one.
- **THE RULE, not a one-off nudge — enforced two ways so a future fourth control inherits the system.** A code comment at the shared `TB_H`/`TB_R` declaration states the rule and points at the guard; `test/toolbarChromeSystem.test.js` (5 tests, source-level) pins that File uses `height: TB_H`/`borderRadius: TB_R` (not a hardcoded `3`), that the Undo/Redo wrapper carries no `background`/`padding` (mutation-checked against the exact pre-fix `background: "var(--hover-chrome)", borderRadius: 10, padding: 2` string), that `.tb-icon-btn:disabled` stays opacity-on-glyph and never gains a `background`, and that the three groups are still separated by exactly two `{vSep}` dividers (no fourth grouping mechanism reintroduced).
