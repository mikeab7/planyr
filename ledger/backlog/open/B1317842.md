- **How it forces the outage:** `page.route()` aborts the three live parcel hosts named in the owner's own repro (`gisdata.pandai.com` [Chambers CCAD], `feature.geographic.texas.gov` [TxGIO statewide — also Waller's only live source], `www.gis.hctx.net` [Harris HCAD]) and serves a canned response for the same-origin `/api/parcel-cache/svc/<county>` endpoint (necessary because `vite preview` serves only the static build, not the Cloudflare Pages Function — this tests the CLIENT's use of a well-formed response; the SERVER's own decompression is separately unit-tested per B1317840). The Esri geocoder is mocked too, used only to fly the map to the test point at a parcel-selectable zoom (mirrors how Michael's own repro used an address search) — manual zoom-button/wheel automation was tried first and proved unreliable headless.
- **Why address-search-then-click, not a bare map click:** the bare `#/site` MapFinder screen lands at a metro-wide ~5 mi view with no other reliable way to reach parcel-selectable zoom. Since the address-search path (`selectParcelAt`) already had a working fallback pre-fix, the harness flies there, DESELECTS the result (an instant local toggle-off, zero network, per B441), then clicks the SAME point again to force a fresh `handleClick` pass — the exact code B1317840 fixed.
- **Three scenarios, 12 assertions:** (1) Chambers outage — outline paints, the fresh click selects the lot, the "Cached copy · as of" badge names the county + date; (2) Waller outage — same three assertions, kept as a regression guard since Waller's path partly worked pre-fix too; (3) Harris control — live "answers" via a canned HCAD hit (no real network reach required), and the cache badge must never appear (Harris has no Drive snapshot — `SNAPSHOT_COUNTIES` excludes it).
