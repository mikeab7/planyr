### B251137 — The fix: a re-raster ladder plus a per-rung cache, so crossing the zoom gate costs one page render instead of one per wheel notch — and zooming back in costs none `[Site Planner]` (bug) #site-planner #perf  *(the fix B251136's measurement produced. Minted **B251137** from the same reserved block. Net-new.)*
`[x]` **Shipped 2026-08-08, measured before and after on both of the owner's real Bain plans.**
- Verify: live (zoom-/data-density-dependent rendering + real-project-data — `V48144`, `Blocker: auth`, `Blocker: real-data`)
- **THE CONSTRAINT WAS THE POND CONSTRAINT: do not reduce what is drawn.** PERCEPTUAL-PARITY's relaxation is for detail the owner cannot see at working zoom; a sheet he has deliberately zoomed into is the opposite case. So the bar taken here is not a perceptual measurement but a **PROOF of non-degradation**: `chooseOverlayRasterScale` now rounds the chosen scale **UP** to an octave rung above the base raster, clamped to the 8192 px cap, and both of those steps can only raise it relative to `min(want, cap)` — the exact scale the old continuous rule picked. The returned scale is therefore `>= ` the old one at every zoom and every page size, pinned by a dense sweep in `test/overlayRerasterCount.test.js`. Sometimes it is finer; it is never coarser. **No resolution cap was taken and no detail was dropped** — option (c) from the brief was available and was not needed.
- **What that buys, and why it is a scheduling fix rather than a cheaper algorithm.** With the scale DISCRETE, a zoom sweep asks for the same rung over and over instead of a slightly different scale at every ×1.12 notch, so the answer can simply be kept. On his ARCH-D sheet the whole band between the gate and the cap collapses to **exactly one rung**.
- **And the second half, which is the bigger one: the zoom-out no longer throws the raster away.** The old effect revoked the hi-res the moment the view dropped below the gate — and a zoom sweep is out AND back by definition, so every return trip paid the whole 179 MB page render again. Rungs now live in an LRU cache (`HIRES_CACHE_PER_OVERLAY` = 3 per overlay) that survives a zoom-out; what is retained is the **encoded PNG blob (~3.5 MB)**, never the decoded texture, which the compositor allocates only for the raster actually on screen. Hiding or removing a reference still drops its rungs, and the cache is the only owner of an object URL, so a displayed raster can never be revoked out from under the `<image>` showing it.
- **A third defect the measurement exposed and this closes: a re-raster that arrived while another was in flight was DROPPED AND NEVER RETRIED.** `hiresBusy` made the effect `continue`, with nothing to re-run it, so a fast zoom could leave the overlay on a rung the view had already left until some unrelated dependency changed. A completion now bumps `hiresTick` — **gated on real work having been done**, because an ungated bump is an infinite loop for an overlay whose bytes cannot be fetched.
- **MEASURED, same harness, same regime, both plans.** The `outback` arm (in, back out below the gate, in again — eighteen notches) is the one that shows the cache, and it did not exist before this work because no single-direction sweep can see a revoke-on-zoom-out:

  | arm | re-rasters before → after | main-thread blocked, total, before → after |
  |---|---|---|
  | bain / across | 2 → **1** | 3,347 → **742 ms** (−78%) |
  | bain / outback | 3.5 → **1** | 3,277 → **1,776 ms** (−46%) |
  | quiddity / across | 2 → **1** | 2,046 → **824 ms** (−60%) |
  | quiddity / outback | 4.5 → **1** | 4,842 → **1,563 ms** (−68%) |

  After: **12 of 12 reps at exactly 1**, across both plans and both sweeps, with the controls unchanged and still at zero (`across-image` 0 re-rasters, 94 ms worst block; `below` 0). `--assert` green.
- **⚠ THE COUNT IS THE CLAIM; THE DURATIONS ARE REPORTED WITH THEIR SPREAD.** The re-raster count is deterministic — 12/12 — and it is what the guard asserts. The worst SINGLE main-thread block is not: the same arm on the same build measured 557 ms in the clean 3-rep pass and 1,808 ms in a 2-rep pass an hour earlier. Long-task TOTAL is the stable signal and is what the table reports; a single-block improvement is not claimed beyond "no worse". This is B1434's rule applied to our own result rather than to someone else's.
- **⚠ AND ONE RUN WAS THROWN AWAY, recorded because the failure mode is invisible.** A post-fix pass reported `quiddity/across` at 2 and `quiddity/outback` at 4 — the pre-fix numbers — on the fixed build. `dist` had been rebuilt from a stashed tree WHILE that harness was running, so its early arms measured one build and its later arms measured another. Nothing in the output says so; only the numbers being exactly the pre-fix ones gave it away. **Never rebuild under a running harness**, and prefer a build fingerprint over a memory of which build is on disk (here: the site-route chunk is 2372.2 KB with the fix, 2371.3 KB without).
- **Bundle cost, attributed rather than assumed:** +0.9 KB on the Site route, measured by building the same tree with and without the `src/` change (2372.2 vs 2371.3 KB). The +2.0 KB above baseline and the +74.2 KB on total JS that `perf:bundle` also reports were **already on main** and are not this item's.
- **THE GUARD IS A COUNT, NOT A DURATION, in the idiom B236592/#947 established** — a time budget passes the moment a re-raster that should not happen merely gets cheaper. Two halves, neither substituting for the other: `test/overlayRerasterCount.test.js` (12) replays the production rule AND the pre-fix rule verbatim as a mutation check, so reinstating the revoke-on-zoom-out or the continuous scale goes red; and `node ui-audit/zoom-reraster-arms.mjs --assert` asserts the per-arm budget (`across` 1, `outback` 1, every control 0) against a real browser driving a real wheel gesture, which is the only place the number the app ACTUALLY produces exists.
- **⚠ ONE THING NOT DONE, AND DELIBERATELY.** Option (b) from the brief — raster only the visible REGION rather than the whole page — is the larger win and is NOT taken here. It changes the overlay from one placed image into a viewport-tracked tile, which makes PAN a re-raster trigger where today it is free (VIEW-INDEPENDENT-ONCE), and it would have to be measured against the pan batteries as well as this one. The ladder plus the cache takes the sweep to one page render, which is the number the count guard now holds; region rastering is worth revisiting only if a measurement says one render is still too many.
