`[ ]` Verify: live (PDF/export parity, timing, concurrency, real-data) — **NOT SHIPPED. Stage 0 only (decision record + measured spike). Flagged loudly: the swap cannot ship in one session — see "Why", below.**
- **Owner decision (2026-10-30):** keep Planyr's Notes canvas; each box's content becomes a BlockNote editor instance (`@blocknote/core` + `@blocknote/react` + `@blocknote/mantine` only; **never `@blocknote/xl-*`, GPL-3.0**). Record + licence rules + extension rules: `docs/notes-editor.md`.
- **Why it did not ship in this session (measured 2026-10-30, details in `docs/notes-editor.md` §3–§4):**
  1. **Architecture.** A box is a `noteAnchor` node *inside one page-wide Tiptap/ProseMirror document* (`content: "block+"`, node view with `contentDOM`). Per-box editor instances change what persistence, version history, cloud merge, redline, search, outline, Markdown, print (PDF-PARITY), arrows, marquee, prune and the toolbar read. **6 required CI gates, ≈60 `ui-audit` harnesses and ≈70 `test/notes*` suites** drive a box's `contentDOM`, so the swap cannot merge until they are rewritten in the same PR.
  2. **Feature gap.** BlockNote's default schema has no font size, font family, sub/superscript, line spacing or callout (only bold/italic/underline/strike/code/textColor/backgroundColor). The brief also requires the in-flight spacing + fill behaviour to survive, so retiring the custom toolbar needs custom BlockNote styles/blocks — or an owner decision to drop a feature.
  3. **Install constraints found by the spike:** `@blocknote/mantine@0.56` pulls Mantine 9 (needs React 19.2; Planyr is React 18.3.1) → pin `@mantine/core`/`@mantine/hooks` `^8.3.11`; BlockNote brings `@tiptap/core` 3.32.x vs Planyr's `^3.29.2` → bump together or two copies ship; bare BlockNote + Mantine ≈ 1.55 MB JS (≈445 KB gzip) + 235 KB CSS vs ≈460 KB for today's engine.
  4. **Sequencing.** The two in-flight Notes sessions edit exactly the code this retires (table fill, paste, spacing) and neither had merged to `main` at 2026-10-30 — nothing absorbed, nothing retired yet.
- **Measured native-paste result (BlockNote `pasteHTML`, no pre-processing):** keeps grid, `colspan` merge, CSS `background:` fill, bold, italic, `color:` text. **Loses** `bgcolor=` attribute fills, `<font color>`, empty `&nbsp;` cells (become a space), and Word bullets (two `·         text` paragraphs). That is the pre-processor's job list.
- **Stages (each mergeable):** 1 engine slice (pinned deps, own lazy chunk + bundle gate, Planyr theme, pure `bn` format + version + legacy→BlockNote converter + "couldn't convert" state, Office-paste pre-processor with committed fixtures and red-proof tests — paste half AFTER the in-flight paste session merges) · 2 the swap (`noteAnchor` content → atom with `bn`/`bnv`, convert on READ never on write, adapters for every consumer, gate/harness rewrite) · 3 parity decisions for each feature BlockNote lacks · 4 retire the custom table/paste/toolbar code (delete, no dead code) · 5 live: signed-in planyr.io throwaway-notebook check (type, Excel paste via clipboard API, fill/un-fill a row, border-move, reload with cache-bust, persisted, delete the throwaway), WebKit phone check, bundle check, V# recorded.
- **Owner decisions needed before Stage 3 (genuine product forks):** for each of font size / font family, line spacing + Comfortable/Compact density, highlight, sub/superscript, callout, toggle, task list, images, attachments, in-box find — keep (build as a BlockNote extension) or drop.
