- **THE MEASURED FACT B1360 FILED, restated so this is read as its answer:** `f2p` was `worldToScreen(view, …)`, so every element's pixel geometry was a function of the live view. A pan changed the rendered output of **every** element, and `ElNode`'s memo missed on **100% of elements during a view gesture, by construction** — which is why B1352 moved the number by less than the noise floor.
- **THE CHANGE.** A pan is a pure translation at constant `ppf`, and a translation composes EXACTLY, so it does not have to be baked into coordinates at all. While a pan is armed the geometry stays pinned at an **anchor** (`renderView`) and the gesture writes **one group transform**. `view` itself is untouched and stays the truth: `p2f`, the cull rect, the basemap registration (`tileRef`) and the `data-view-off*` harness contract all still read it, so the pointer path, the weld and every e2e assertion are unchanged.
- **⛔ THE OWNER'S CONSTRAINT LIFT IS WHAT MADE THIS SAFE, and it is spent here rather than merely noted.** `buildExportSvg` clones the live SVG, so historically anything the screen did to its own representation reached the sheet. An **export pass now bypasses the anchor entirely** (`!exportPass && …`), i.e. the sheet resolves its own render view at export time instead of inheriting whatever transient state the screen is holding. A sheet built mid-gesture is identical to one built at rest **by construction**. This is the same principle B1355 already shipped under — *an export is a document, not a screenshot* — applied to the view rather than to a label gate.
- **MEASURED, on two builds served side by side** (`ui-audit/diagnose-pan-commits.mjs`, reference plan, 60 pointermoves): **101,267 → 2,194 DOM mutation records (46×)**, and the same scripted gesture completed in **2,737 ms vs 4,000 ms**. Commits per pointermove are unchanged at 1.10 — this does not remove a commit, it removes almost everything each commit had to do.
- **THE PIXEL BAR IS FREE HERE AND B1360 SAID SO IN ADVANCE:** *"A translation cannot change any LOD gate or stroke width, so the picture is exact by construction — this is the increment whose pixel bar is free."* Confirmed rather than assumed: the isolated A/B run for **B1350** used these same two builds and came back **byte-identical** at its control rung.
- **⚠ WHAT IS DELIBERATELY NOT ANCHORED.** The drafting grid (outside the group, `data-export="skip"`, only drawn with no basemap) and the print-crop overlay (its dim mask hugs the canvas edges) both stay on the LIVE view via `f2pLive`. Translating either would detach it from the frame it belongs to.
- **Guard.** `test/panAnchor.test.js` (14) — a SOURCE guard by design, because every invariant here draws the identical picture when broken: a pan that silently goes back to baking the view is invisible to every screenshot and behavioural test in the repo, and only a frame counter would notice. It pins the f2p/p2f split, the value-keyed memo (`[view]` instead of `[view.ppf, rvOffX, rvOffY]` would make the whole change a no-op that still looks correct), the export bypass, the `data-view-off*` contract, the mid-gesture panel rebase, and disarm on BOTH gesture-end paths.
