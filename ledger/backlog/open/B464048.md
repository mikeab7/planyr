  **18 → 9 is one press taking Building 1 AND its eight bonded elements** — two 135 ft truck courts, two 55×60 bump-outs, two sidewalks, two side-parking rows. The control is the ONLY state the old guard covered. **This is not an edge case; it is the normal way a person uses the panel.**
- **THE CAUSE.** The planner's keydown listener is on `window` and its guard asked one question — `if (document.activeElement is INPUT/SELECT/TEXTAREA/contentEditable) return;`. That is a guard on the one instant the field literally holds focus, and says nothing about the state a user is in for the rest of an edit. `<body>` is where focus goes after ANY dismissal (a commit, an Escape, a click on inert chrome), and a focused `<button>` was never in the tag list at all — which is why two of the seven leaked while chrome still HELD focus.
- **THE FIX — a declared key contract plus a scope rule, not a patched branch** (the owner asked for exactly this, mirroring B1188 / `elementCapabilities.table.js`):
  - **`src/shared/keyboard/keyScope.js`** — the rule: **THE KEYBOARD FOLLOWS THE LAST SURFACE YOU TOUCHED.** Four scopes (`field` · `slider` · `chrome` · `canvas`) computed from PLAIN FACTS so it is unit-testable without a browser, plus a **three-valued latch** driven by `pointerdown` + `focusin` in the capture phase. ⛔ **No clock** — "did the keystroke arrive soon enough after the blur" is unanswerable and a harness measuring it would measure its own pacing (FOREGROUND-OR-VOID); the latch is an exact fact about which surface was last addressed.
  - **`site-planner/lib/keyContract.js`** — every planner shortcut DECLARED with its scope and whether it mutates, and `test/keyContract.test.js` **SWEEPS the real handler source** and fails the build if a branch tests a key the table does not declare.
  - **`NumInput`'s Enter no longer `blur()`s.** That call is the root: it put focus on `<body>` with the building still selected. Enter now commits IN PLACE and selects the value, so the next digits retype it. Being silently ejected from the box is also half of *"it's not letting me"*.
  - **Doc Review had the identical defect** (its guard read `e.target`, `<body>` after any dismissal) and is closed the same way — a stray Backspace there destroyed the selected MARKUP.
- **⛔ TWO OVER-REACHES WERE SHIPPED AND CAUGHT BY THIS REPO'S OWN TESTS, and both are pinned so they cannot return.** (1) Answering `chrome` for any focused non-text element made **Delete DEAD ON THE CANVAS** — the canvas is not focusable, so pressing the Building tool leaves `activeElement` on that BUTTON for the whole session; eight delete/undo e2e cases went red. **Focus is sticky; the latch is fresher, and the latch wins.** (2) Refusing every mutating key from all chrome broke a legitimate flow this repo tests (panel ＋ → Escape → Delete) and killed the tool letters after any toolbar click. **The line is the VALUE ROW, not chrome-ness**: `[data-field-group]` marks a row (label + input + steppers) as one unit, and only there is a mutating key refused. Both regressions have named test cases.
