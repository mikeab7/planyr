`[ ]` Three sub-features, all deferred out of the PHASE 1 session as explicitly too large to ship alongside the draw/edit/style/metadata/z-order/PDF-parity work:
- Verify: live — PDF/export parity (the CSV/PDF summary table) and zoom-/data-density-dependent rendering (the panel row list) are both mandatory LIVE-VERIFY classes.
- **The Markups List** — a sortable, filterable, groupable panel (type, subject, author, date, colour swatch, comment, status) listing every markup on the plan (not just clouds — Bluebeam's own Markups List covers every annotation type, and this app's shared markup family already spans line/rect/ellipse/polygon/cloud/callout/text/measure). Clicking a row zooms to that markup (reuse the existing "zoom to feature" plumbing measurements/parcels already have). Exports to CSV and to a PDF summary table (reuses `exportSheet.js`'s document-composition path, never a second PDF pipeline). **The Review tab is its natural home** per the brief.
- **Threaded replies** — a markup (starting with Cloud, generalizable to any kind once the Markups List exists to display a thread) carries a reply thread: author + timestamp per reply, same shape as the metadata this session already added (`cloudMetaDefaults`'s author/createdAt pattern generalizes directly). Needs its own small data shape (`replies: [{id, author, text, createdAt}]`) and a compact panel UI — natural to build alongside the Markups List since a reply is what a list row expands into.
- **Tool presets (Bluebeam's Tool Chest)** — save a configured cloud (colour, weight, arc size, subject) as a reusable named tool, plus a recent-tools row. This session's `mkCloudStyle` sticky-style mechanism (kept deliberately separate from every other markup's shared `mkStyle` — see `MK_CLOUD_DEFAULT` in `SitePlanner.jsx`) is the natural seam: a preset is just a NAMED, PERSISTED snapshot of that same shape, plus a small picker UI. Store presets per-account (mirrors `userPrefs.js`'s account-level Standards store) so they follow the user across plans/devices, not just per-device localStorage.
- Depends on nothing PHASE 1 didn't already ship — the shared markup engine, the metadata fields, and the sticky-style seam are all in place; this is new UI + a new small data shape, not a prerequisite refactor.

Worth reconsidering build order when this is picked up, not a reason to renumber or split it.
