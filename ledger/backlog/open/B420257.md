- **THE LIKELY SHAPE, stated as a hypothesis and not as a finding.** `create` is minted for exactly one reason (`reconcile`: the canvas holds an element the SHADOW does not), so a `create` against a row the server already has means the shadow lost an entry the server still holds — a re-seed from a snapshot older than the create, a `shadow.delete(key)` on a `missing`/`deleted` branch that then re-diffs, or a refetch-replace landing between the two. The `exists` branch already recovers correctly (it adopts the row as an update), so **this is not currently known to lose data** — it is an assertion firing that says a state we believe unreachable is being reached, and that belief is load-bearing for other reasoning in this engine.
