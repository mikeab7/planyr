`[x]` **Built as an AGENDA, never a Gantt** — the owner's own reasoning (dates + real recurrence, but no dependencies/roll-ups/critical path) is exactly why. **The scope decision, argued rather than assumed, per the brief's own instruction:** the agenda view is a wholly separate lightweight surface **OUTSIDE** the embedded scheduler (`Scheduler.jsx`'s new `org` branch renders `AgendaView` INSTEAD of the `<iframe>` — `public/sequence/index.html` itself is never touched, imported, or reached on this path). Chosen over extending the embedded app because: (a) the two views share almost no logic (no dependencies/critical-path math to reuse), (b) it keeps a walled, heavily-instrumented module untouched (`Scheduler.jsx`'s own header: "if you find yourself editing the scheduler, stop" — honored by never reaching its code on this branch at all, not by editing it carefully), (c) React's rules of hooks mean every existing hook/effect in `Scheduler.jsx` still runs unconditionally either way, so branching only the RETURN value costs nothing extra and touches nothing load-bearing.
- Verify: sandbox — **revised from the original filing's "Verify: live."** The original note assumed a UI surface "inside the embedded scheduler," which would have been auth/signed-in-dependent; the surface actually built is pure local state (no auth, no GIS, no cloud), so it is fully headlessly testable and WAS headlessly tested this session (18/18 checks: org-scope routing, tab visibility, the iframe genuinely NOT mounted, add/edit/delete, recurring-item roll-forward, one-off completion + Done section, reload persistence, and leaving org scope cleanly restoring the real embedded scheduler).
- **RECURRENCE GRAMMAR, stated per the brief's own requirement:** six fixed presets — Does not repeat / Daily / Weekly / Every 2 weeks / Monthly / Yearly — covering the owner's own two examples ("monthly", and "every other Tuesday" as weekly-interval-2 anchored on whichever weekday the item's date already falls on). **NOT supported, deliberately:** an arbitrary N-day/week/month interval, a "nth weekday of the month" rule, an end date or occurrence count. Checking off a recurring item never marks it done — it advances its own date to the next occurrence and stays open, forever; a one-off item toggles done normally (undoable).

This has a real, narrower precedent already in this codebase — `notesVersions.js`'s version history is device-local for the identical reason ("it needs no schema change and cannot fight the server-owned rev"). The follow-on that adds real cross-device sync is filed separately as **B1023024** (below) rather than left implicit.
