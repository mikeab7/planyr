- **THE `BELOW` RULE IS GONE; `TAKEN` IS UNCHANGED AND STILL FATAL.** A proven, present collision still fails the build, and `test/idUniqueness.test.js` still fails it if two active items share a number. What was removed is a **heuristic that never proved a collision** and whose only remedy starved every other branch. **This makes the 30-minute lag harmless:** an id unclaimed at push time is still unclaimed half an hour later, so the verdict no longer depends on how fast the queue moves.
- **THE BLOCK IS A PURE FUNCTION OF THE BRANCH NAME — there is NO ALLOCATOR.** Nothing is handed out, nothing is stored, no service is consulted. This is the single most important property, because it answers two of the owner's steel-man points structurally rather than by argument: it **cannot become a single point of failure** (there is nothing to be down), and **two sessions cannot be handed the same block by a racing allocator** (there is no hand-out). `scripts/idBlocks.mjs`; 16 ids × 512 blocks anchored just above main's max, so ids stay four digits (main at B1449 → the ring is B1456–B9647) and move up with main instead of inflating.
- **THE STEEL-MAN IS WRITTEN OUT IN FULL, in the header of `scripts/idBlocks.mjs`, arguing against the design at its strongest and CONCEDING where the cost is real.** All eight points the owner listed: block exhaustion mid-session (continues into the next free block; conceded cost — non-contiguous ids) · abandoned sessions leaving holes (conceded, and the cheapest possible cost — B1140 established gaps are free, against 98,000 ids burnt in one day) · a racing allocator (there is none; the residual is a hash collision, which is **detected**, costs one branch one step, and critically **does not propagate**) · a session that renumbers anyway (the incentive is gone — CI now only rejects a genuine collision) · non-adjacent BACKLOG.md conflicts (conceded; but adjacency is what makes two inserts collide in one hunk, so this conflicts *less*) · sortable/contiguous ids (audited — nothing iterates a range or infers "the next one"; sortability survives, only contiguity goes, and gaps had already broken that) · migration for branches holding ad-hoc numbers (**grandfathered** — out-of-block ids are reported, never fatal; forcing seven blocked PRs to renumber would be one more round of the exact tax this ends) · "the gate is weaker" (answered: a false-positive predicate was replaced with a structural invariant).
- **THE REQUIRED PROOF, four ways** (`test/idBlocks.test.js`, 18 tests): all 512 blocks pairwise disjoint, exhaustively · a property test over 2,000 random branch-name pairs asserting **both** outcomes (distinct slots ⇒ disjoint blocks and disjoint id sets; equal slots ⇒ the same block, which is the collision the probe resolves) · **the exact race that broke the repo** — two sessions minting at the same instant off the same freshly-fetched main, which under `next-id --against-main` handed both the same number and here cannot · all seven branches open that day getting seven mutually disjoint id sets. Plus a direct assertion that one branch claiming B25005 **does not move anyone else's block** — the ratchet, proven absent.
- **`next-id --against-main` now prints your block** (`Your block → B6864–B6879 · V6144–V6159`) instead of `max + 1`, which is what handed two concurrent sessions the same number. `--b`/`--v` return the in-block id. `nextB`/`nextV` are preserved for existing callers and remain the honest "highest assigned" report.
- **The gate's failure message now points at YOUR BLOCK, not at a global mark** — moving into your own block invalidates nobody else's ids, which is precisely what stops a rejection cascading.
- **`test/mintGateE2E.test.js`'s "below-the-mark → rejected" case is deliberately INVERTED to "→ allowed", and the inversion is the fix.** The other four outcomes (taken-on-main · taken-on-a-peer · clean mint · recurrence · unreachable remote warns under `--ci`) are unchanged and still green.
