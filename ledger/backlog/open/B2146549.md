### B2146549 — "Delete team" leaves `team_members` and `team_invites` rows behind (UI says invites are removed for everyone) `[Teams]` (bug, low-medium) (×2) #auth  *(AUTH-SWEEP 2, V118)*
Deleting a throwaway team removed the `teams` row only; membership + invite rows remained (cleaned by API). The test account also has a pre-existing orphan membership (team 79fdfc32, no visible team row). Related: a plan created while a profile Organization was set kept a `team_id` pointing at a deleted team and could not be trashed (RLS violation on `deleted_at`) — see B2146552.

- **Recurrence ×2 (2026-10-29, measured live while verifying B2451824/V1895328):** two throwaway teams created by `e2e@planyr.test` and deleted through the app's own client (`teams.delete().in(name, …)`, RLS "admins delete team") — the `teams` rows went (`list_my_teams` and the `teams` table read empty) but **their `team_invites` (2) and `team_members` (3) rows stayed**, still readable by the admin, and `list_team_members(<deleted team id>)` still answered. So production has no working `ON DELETE CASCADE` from `team_members`/`team_invites` to `teams`, contrary to `db/teams.sql`. Cleaned by id. **Why it matters now:** an orphan OPEN invite for a deleted team is still returned by `list_my_invites()` (it joins `teams`, so it is HIDDEN there — checked in the SQL, an inner join) but `claim_team_invites()` / the signup trigger would insert a membership into a team that no longer exists. **NOT FIXED in this item's session — hard blocker, said plainly:** the fix is a production DDL change (re-add the foreign keys with cascade after deleting existing orphans, or a `delete_team` RPC), and the Supabase tool's confirmation prompt was unanswered when this was found; the constraint state itself (`pg_constraint`) was not read. **Stopping rule:** closes when `select conname, confdeltype from pg_constraint where conrelid in ('public.team_members'::regclass,'public.team_invites'::regclass)` shows cascade on both team FKs, orphans are gone, and a throwaway team delete leaves nothing behind.
