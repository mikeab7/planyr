- **THE MEASUREMENT.** `@anthropic-ai/sdk` is **144.4 KB** of the built bundle — the fourth-heaviest dependency, behind `pdfjs-dist`, `pdf-lib` and `leaflet`. It is reached from exactly one place (`lib/titleReader.js`, itself dynamic-imported) and makes exactly one call. It also drags a `node:fs` externalisation warning into every build.
- **TWO REASONS, and the second is the stronger one.** (1) It is most of the 167.7 KB `totalJsBytes` is over. (2) It runs `new Anthropic({ dangerouslyAllowBrowser: true })` with a key the user pastes and this app stores — `lib/titleKey.js`. It is the USER's own key rather than ours, so it is not a breach of the "server-side only" KEY DECISION, but it is the same shape, and the repo already has the right pattern next door: **B299** does the Tier-2 filing read server-side behind a Function.
- **THE SHAPE TO BUILD:** a same-origin Pages Function that makes the call with the SDK server-side, so the browser ships neither the SDK nor the key. **⛔ Do NOT "fix" this by swapping the SDK for a raw `fetch` in the browser** — the `claude-api` skill forbids that substitution by name, and it would keep the key in the page anyway. That option was considered and rejected during B393171; do not re-derive it.
