`[x]` **SHIPPED — the two asks that don't require the full MapFinder.jsx conversion to be meaningful; the third (a structural "is this a KNOWN component" check, as opposed to "is this a legal value") is NOT built, and is named here as the honest reason why.**
- Verify: sandbox
- **Headline metric changed, as asked:** `docs/UI-INVENTORY.md` now leads with **"Distinct control signatures per surface"** — DISTINCT `(radius, height, padding, fontSize)` combinations actually painted per surface (deliberately excluding color/weight/background/border, which are legitimate per-role differences, not drift) — instead of "N deviations from the allowed list" (which the brief correctly named as never having been the real health metric: two individually-on-scale values sitting next to each other, wrong together, is invisible to a deviation count). The old metric is KEPT as a named backstop, not deleted — a value that's off the scale entirely is still worth flagging, just no longer the lead.
- **Ratcheted the same way `design-drift-ceiling.json` is:** `ui-audit/control-signature-ceiling.json` (new) records each surface's current count; `--write-signature-ceiling` updates it; `--check` now fails if ANY surface's count grows past its recorded ceiling, in addition to the pre-existing stale-doc diff check. Verified both directions live: it correctly failed when clean-main's (higher) Map-landing-page count was checked against this branch's (lower) ceiling, and passes clean against the committed ceiling.
- **Height and padding added to the sibling/row check, as asked** ("they were never governed at all... seven heights in one screen is a worse defect than three radii") — via a NEW function, `siblingSizeMismatches()`, not a modification of the existing `siblingMismatches()`: the existing radius check's candidate pool deliberately EXCLUDES 0px-radius elements (a nav tab is invisible to it by construction — `if (!radius || …) continue`), which is correct for a check about CURVE families but wrong for a check about height, where a 0-radius tab sitting flush at the wrong height beside an 8-radius chip is exactly the defect to catch. So the new check's pool is every interactive control (`INTERACTIVE_SEL`, matching `readSurface()`'s own definition), not just the rounded subset. Same shared-flex-row grouping and the same B972097 divider-in-span escape as the radius check (a real divider still legitimises two different SIZES sitting apart; never an excuse for two sizes sitting flush). Found **32 real findings** on the current app (e.g. "Switch project" 26px vs "Switch or rename plan" 24px — exactly the App-header debt B989105 named as unconverted; "Cloud sync: Saved on this device" 24px vs "Full screen" 30px — the CloudSyncBadge, also not touched this session) — sanity-checked by hand, all genuine, none noisy.
- **NOT built: "is this an instance of a known component" as the primary gate, replacing "is this a legal value."** That check needs a real component-identity signal at the DOM level (a `data-` attribute every locked primitive stamps, or a source-map-level check) that does not exist yet — `ui-inventory.mjs` reads `getComputedStyle`, which cannot see which React component rendered a node. Building that stamp is real, scoped work (add a `data-locked-primitive="Tab"`/`"MenuTrigger"` attribute to both primitives in `controls.jsx`, teach the crawler to read it) — left as the honest remainder rather than faked with a heuristic. The existing token/value checks (design-drift-audit.mjs, the RADIUS/FONT_SIZE scale checks already in `ui-inventory.mjs`) remain the backstop in the meantime, exactly as before.
