- Verify: sandbox
- **THE GAP, stated as the weaker truth, not the comfortable one.** `ui-audit/verify-successor-complete.mjs` — Sections A/B/C (the original 27 checks) and Section D (the seven-width sweep + 2 mutation proofs added in B605840, 102 checks total) — is **not invoked anywhere in `.github/workflows/build.yml`**. Neither is the pre-existing A3 pixel-equality check. The dialog EXISTS in a permanently-checkable state, but the check is **not enforced** — it only runs when a person, or a future Claude session, types `npm run verify:successorcomplete`. A regression here (buttons going unequal, the footer overflowing at a narrow width, the interaction silently breaking) would ship, deploy, and stay broken indefinitely with every other CI check green, until someone happens to run this script by hand.
- **THE ONLY CI-GATED ARTIFACT touching this dialog at all** is the source-regex anchor in `test/schedulerEngine.test.js` (`REVERT: Skip and Update Successors share one style object...`), which runs under `npm test` in CI. It checks that both buttons still spread the literal `FOOTER_BTN_STYLE` object in the source text. **It measures zero pixels and knows nothing about width** — it would stay green through a regression this harness would catch, and stay green through one it wouldn't.
- **⚠ NOT SCOPED TO THIS ONE FILE — NAMED HERE SO THE NEXT READER DOESN'T MISTAKE IT FOR A ONE-OFF OVERSIGHT.** Every `ui-audit/verify-*.mjs` harness in this repo shares this same non-enforcement — `build.yml` runs lint, the drift/mint guards, `npm test` (vitest), `npm run build`, and the perf-bundle audit; it does not invoke any `verify-*.mjs` script, by design (per `CLAUDE.md`'s "🤖 Self-verification" convention, these are meant to be run by the session shipping the change, and by whoever later works `VERIFICATION.md`). This item is filed narrowly against the one harness just extended, not as a mandate to wire the whole suite into CI — that would be a real headless-Chromium-in-CI infrastructure decision (cost, runtime, flakiness surface) worth its own item if picked up, not an incidental fix.
- **What "closing" this would mean, so it's actionable rather than just documented:** either add a CI job that runs `verify-successor-complete.mjs` (accepting the real-Chromium-in-CI cost for this one dialog), or accept the gap explicitly and say so in this file rather than let a "permanent check" read as a "permanent guarantee."
