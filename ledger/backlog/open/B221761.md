- **THE DEFECT.** `interiorFitter(ring).spots(w, h, want)` rasterises a pond's polygon at 96 cells across its long axis and enumerates every maximal inscribed rectangle — thousands. The RASTER was cached per ring (a WeakMap); **the SCAN over those rectangles was not**, and `layoutLabels` runs in the render body, so it re-ran up to nine times per pond per frame. **And none of it depends on the pan:** `spots` is asked in FEET (`layoutLabels` divides the screen size by `ppf` first) and a pan is a pure translation at constant scale (B1440), so the ring, the ppf, the lines and the type metrics are bit-for-bit identical frame to frame. Every frame re-asked an identical question and got an identical answer; only the screen ORIGIN moved, and the caller applies that with one multiply-add afterwards.
- **THE FIX, and it is BYTE-IDENTICAL BY CONSTRUCTION** — same pure function, same arguments, same outputs, moved from *once per frame* to *once per distinct question*. No threshold, no approximation, no level-of-detail decision, so **PERCEPTUAL-PARITY has nothing to measure and no pixel argument is made**: byte-identical is the stronger claim and it is the true one. (1) `spots` is memoised on a bounded LRU inside the fitter, whose lifetime IS the ring's — `fitterCache` is a WeakMap keyed on the ring array, so an edited pond arrives as a NEW array and gets a new fitter. **It can never serve a stale interior**, which is the failure that would matter: a label placed against the wrong interior is a wrong drawing, and a wrong drawing is worse than a slow one. (2) An early-out: no rectangle can exceed `maxW`/`maxH`, so a request past either bound was already guaranteed to scan everything and return nothing — turning the WORST case (a label that fits nowhere, exactly the case the outside rung exists for) from a full scan into a comparison.
- **PROVEN ON THE SAME PROBE.** Seeded pond ladder, same regime: per-pond **10.26 → 4.94 ms** of main-thread work per gesture; the 16-pond penalty **+30.5% → +14.1%**. Re-profiled, the phase it was aimed at moves as predicted: Label layout & collision across 0 → 16 ponds **+76.7 ms → +20.0 ms (−74%)**, and `labelFitLadder` is no longer the hottest application function.
