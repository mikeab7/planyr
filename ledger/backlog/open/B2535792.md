### B2535792 — Spreadsheet: Ctrl+Z while typing in a cell undid OTHER sheet edits instead of the typing `[Spreadsheet]` (bug) #model #keyboard #ui  *(owner chat block NEW-1, Windows, 2026-10-29: "start typing into a cell, press Ctrl+Z to remove what I just typed — instead the sheet-level undo fires and starts undoing OTHER, earlier changes". Minted **B2535792** from this branch's reserved block against `origin/main` 50b2d2b. DEDUPE-FIRST — searched Open/⏳Verify/Done for ctrl+z × spreadsheet/SheetView/cell editor: only Notes/Schedule items; nothing for the Spreadsheet's editor. Net-new. Another session ("Excel keyboard shortcuts in Spreadsheet") edits SheetView keyboard handling; this change is confined to the `if (edit)` branch, `startEdit`, and ModelApp's undo branch.)*
`[ ]` **ROOT CAUSE (AUDIT-FIRST, measured not inferred):** `ModelApp.jsx` binds ONE `window` keydown listener for sheet undo/redo and never asked where the key came from. Ctrl+Z from the in-cell `<input>` bubbled to it, ran the SHEET `undo()` (reverting earlier committed cells) and its `preventDefault()` also killed the field's native undo. Red-proof on pre-fix code: type `abc` → Ctrl+Z left the editor at `abc`; in the formula-bar arm a committed A2=300 was actually erased.
- **Fix (one rule, applied at both ends):** (1) `lib/undoKeyScope.js` — `undoKeyOwner({textControl, cellEditorOpen})`: undo/redo belong to the TEXT whenever a text control has the key OR the sheet reports an open cell editor (`data-cell-editing` on the grid, covering the B1287888 not-yet-focused window); ModelApp's window listener returns before touching the stack. This also covers the formula bar, Name Box, column-rename box, Find/Replace bar and command palette (native undo is no longer preventDefault'ed). (2) `lib/cellEditHistory.js` + SheetView's `if (edit)` branch — the editor has its own tiny history: Ctrl+Z steps the typing back, Ctrl+Y / Ctrl+Shift+Z steps forward, and with nothing left to undo Ctrl+Z abandons the edit back to the cell's original value (Excel). After Enter/Tab/click-away the committed edit is still ONE sheet frame (unchanged).
- **Adjacent grids audited:** Schedule grid (`typing` guard on INPUT/TEXTAREA/SELECT, `public/sequence/index.html`) — NOT affected. Comp entry grid (`if (editing || !selection) return` before its undo) — NOT affected. Notes (only forwards undo when a box selection holds focus on `<body>`; typing is ProseMirror's own) — NOT affected. Only the Spreadsheet was.
