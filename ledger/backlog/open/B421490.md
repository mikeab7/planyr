### B421490 (×3) — A box could hang off the page, where its controls were unreachable `[Notes]` (bug) #notes #ui  *(found 2026-08-13 by `sweep-notes` at a narrow window. See B421488's provenance.)*
`[ ]` **⛔ SHIPPED — and the fix was WRONG TWICE before it was right, both times caught by an existing guard.**
- Verify: sandbox
- `placeAnchor` spends the WIDTH to keep the LEFT EDGE, but only at PLACEMENT. Narrow the window afterwards and a box placed toward the right hangs past the sheet, under the outline panel, which paints later and takes its presses.
- **⛔ ATTEMPT 1 MOVED THE LEFT EDGE past the width floor, on the strength of a sentence in `placeAnchor`'s own header. `verify-notes-anchor-zoom` — the owner's acceptance test for B350000 — went red inside the hour: a click at x=760 stored 751.** Reading the CODE rather than the prose settles it: the edge only ever moves away from the LEFT margin. The prose was wrong and the fit followed it. **A clamping band is a clamping band whatever justifies it.**
- **⛔ ATTEMPT 2 FOUGHT THE RESIZE DRAG IN REAL TIME**: the fit re-derives the rendered width from `data-anchor-w` on a ResizeObserver, so while the handler wrote only the STYLE, every frame of a drag was immediately overwritten with the old stored width and the handle appeared dead. Caught by `verify-notes-box-drag` the same hour. The attribute is the live truth during a gesture now.
- **The shipped answer:** spend the width, never move the edge, and keep an overhanging box REACHABLE by stacking instead — which is where that problem belonged all along.
