### B6865 — A required status check that can never report is a repo-wide outage that looks like nothing is wrong — so assert the contract in the build `[Infra / CI]` (task) #infra #testing  *(filed 2026-08-06 from the owner chat block as NEW-2. See B6864 for the mint provenance and the shared DEDUPE-FIRST search.)*
`[ ]` The ruleset lives on GitHub and the workflows live here; the two drift independently with nothing watching. Now checked in the ordinary required build.
- Verify: sandbox
- Origin: filed 2026-08-06 from chat
- **PROTECTION KEPT, as the owner required.** Nothing was loosened: the ruleset is untouched, `build` is still the required context, and no check was dropped. What changed is that a breach of the contract now goes **red in CI before it can wedge a merge**, instead of manifesting as silence on seven pull requests at once.
- **`.github/required-checks.json`** is the committed copy of the "Protect Main" contract (`requiredStatusChecks: ["build"]`, ruleset 17661176). **`ui-audit/required-check-audit.mjs`** runs as a build step and asserts two properties: **(1) name agreement** — every required context is actually produced by a job that runs on `pull_request` into main (a one-word job rename otherwise arms exactly this outage); **(2) docs-only reachability** — every required context still reports when a PR changes only documentation. The second is the owner's leading hypothesis promoted to a permanent guard: it was **not** the cause this time, but a backlog renumber is docs-only by construction and a `paths:` filter is one edit away from making it the cause.
- **The failure message names the standard remedy rather than the easy one:** keep the filter on the expensive job and add a companion job with the **SAME check name** that runs when the filter excludes everything and reports success immediately. It explicitly says not to drop the required check and not to remove the ruleset.
- **No YAML parser is added to the lockfile for a CI guard.** `ui-audit/lib/workflowContract.mjs` reads the small, highly-regular subset of workflow syntax it needs and **REFUSES (LOUD-FAILURE) on anything it cannot parse** — a contract checker that silently skips the file it cannot read is worse than none, because it reads as a pass. That refusal is itself tested.
- **Mutation-checked both ways** (`test/requiredChecks.test.js`, 16 tests): the real repo passes, and each deliberately broken copy goes red — job renamed (`build` → `Build & Test`), `paths: [src/**]` filter added, `push`-only trigger, `pull_request` targeting a different base. The companion-job pattern is asserted to bring it back to green, so the remedy the message recommends is proven to work rather than merely described.
- **What is NOT fixed, stated plainly:** the ~30-minute delay between a push and its workflow run is GitHub-side and nothing here can shorten it. B6866 is what makes it harmless — the gate's verdict is now stable over time, so waiting out the lag produces the same answer as being fast.
