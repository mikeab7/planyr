`[ ]` **Open — swept, counted and sized. The cheap half of the guard SHIPPED as B1128; this item is the expensive half plus the paydown.**
- Verify: sandbox
- **Why it was swept.** Three "computed on render, never reaches the DOM" defects surfaced in five dispatches: the invisible Buildability panel rows, the ParcelDrawing swatch row reported missing though B567 records it shipped, and **B1110**'s `detVerdict`/`detTone`/`detSub`. A fourth was found during this sweep and fixed as **B1127** (the verdict strip rendering every Colorado site as a permanent "checking flood data" spinner). Four in five dispatches is a class, not a run of bad luck.
- **THE CLASS SPLITS IN TWO, and conflating them is why it kept recurring.**
  - **(a) The VARIABLE half** — a local written and never read. Statically detectable. **Guard SHIPPED (B1128):** `ui-audit/dead-store-audit.mjs` + `test/deadStores.test.js`, a per-file ratchet over ESLint's `no-unused-vars` (assigned-but-never-used only). A new one now fails CI.
  - **(b) The REACHABILITY half** — a variable that IS read, feeding JSX that never mounts, renders zero-height, or sits behind a condition that is never true. **This is the Buildability-rows and swatch-row shape and it has NO guard.** No static rule can see it: the value is used, the element exists in the tree, and every unit test passes. It needs a headless assertion that the node is present **AND** has a non-zero box **AND** its text is non-empty — which is the point the dispatch made: *a passing test asserting an element EXISTS is not a test that it is REACHABLE.*
- **INVENTORY for (a), measured, so the paydown is scoped rather than vague.** 90 across 29 files (`node ui-audit/dead-store-audit.mjs`): **28** look like unused components/constants (cosmetic dead code — unused icon components, `LINE`, `Badge`), **62** look like unused VALUES (the B1110 risk shape). **`SitePlanner.jsx` holds 46 of the 90**, 37 of them value-shaped: `measureModeLabel`, `lookupBusy`, `lookupErr`, `lookupRes`, `setSearchMode`, `setSearchVal`, `setLotW`, `setLotD`, `addRectParcel`, `overlayCenter`, `onCountyChange`, `runLookup`, `importFeature`, `courtOnSide`, `addCourtTrailer`, `drainCityCount`, `pondTailwaterFt`, `buildingRules`, `calibrated`, `hdrTab`, `curHint`, `otherSites`, `drainRecomputing`, three `fill`/`stroke`/`fillOpacity` triples, and others.
- **⚠ Sizing, and the honest risk note.** The paydown is NOT a mechanical sweep and should not be done as one PR. Each of the 62 value-shaped ones is a fork: **either** the value was meant to render and does not (a real bug worth its own item — `drainRecomputing` and `pondTailwaterFt` in particular sound like they were meant to be seen), **or** it is a leftover whose surface moved (delete it). Only reading each one tells you which, and the second reading is what B1110 got right. Estimate: **~1 session for `SitePlanner.jsx`'s 37** (the only file worth a dedicated pass), ~1 session for the remaining 28 files, and any genuine "was meant to render" finding spawns its own item.
- **Scope for (b), the part with no guard yet.** A shared helper — `visibleText(page, selector)` / `assertRendered(...)` — asserting presence **+** a non-zero bounding box **+** non-empty text, adopted by the `ui-audit/verify-*.mjs` harnesses. `ui-audit/verify-b1105-mhfd-panel.mjs` (shipped with B1105) is the worked example: it reads `innerText` off the `data-surface="planner"` host, so a `display:none` or zero-height node fails. Retrofitting it across the existing harnesses is ~1 session; it is the only thing that would have caught the Buildability rows.
