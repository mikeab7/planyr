### B2671297 — Map flashes on zoom: MapLibre 6 worker never loads, road names fall back to the raster layer [site-planner] (bug)
- Reported by owner 2026-11-23 on Goose Creek › Phase II - Base Case: "the map is flashing a ton when I zoom in or out".
- Measured live on planyr.io (build 6a7ebb0, owner's signed-in Chrome): no `.leaflet-gl-layer`, the `planyrVectorLabels` pane empty, console `vectorLabelLayer: vector roads/labels unavailable … Error: Worker failed to load`. The raster fallback (Esri World_Transportation, 0.85) was drawing instead: it appears ~1.4 s after each zoom with a fresh tile set (66→171→105→72 tiles) and is dropped/added across zoom gates. The aerial itself never went blank (coverage probe 0 blank frames).
- Cause: #2993 (maplibre-gl 5.24 → 6.19) — v6 finds its worker via `new URL('./maplibre-gl-worker.mjs', import.meta.url)` relative to its bundled chunk; the build emits no such file, so the request returns the SPA index.html. Every vector label layer (planner + Map + Food hybrid) silently fell back to raster.
- Fix: `vectorLabelLayer.js` imports `maplibre-gl/dist/maplibre-gl-worker.mjs?url` and calls `setWorkerUrl` before building the layer. Proven in a real browser harness: without it "Worker failed to load", with it the worker loads (only the sandbox's blocked network remains). Guard: test/maplibreWorkerUrl.test.js.
- Verify: live — after deploy, on a plan at working zoom `.leaflet-gl-layer` canvas present, no console "Worker failed", road names stay on screen through wheel / button zoom. Stopping rule: owner confirms the flashing is gone on his machine.
