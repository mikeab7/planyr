`[ ]` **`ui-audit/diagnose-edit-listener-leak.mjs`.**
- Wraps `EventTarget.prototype.addEventListener` / `removeEventListener` before any app code runs, keyed by the **(target, type, listener, capture)** tuple the DOM itself uses, stamps each with its capture stack, and reports **net-live count per call site**. Frames are resolved through the build's sourcemaps (`lib/sourceMapIndex.mjs`) so the output is a path, not a minified offset.
- **It found the B1121 mechanism on its first run** — `el:img/load` and `el:img/error` at +272 per edit each, attributed to Leaflet — which a class histogram had reported only as `Object +226,488 nodes`.
- **⛔ IT HAS A REFUSAL PATH AND THAT IS THE POINT.** The verdict is `CONCENTRATED` only when the top site holds ≥50% of net growth (or the top three ≥80%); otherwise it prints **`INCONCLUSIVE — net-live listener growth does not concentrate in a small number of call sites`** rather than promoting row 1 to a culprit. B1121 has killed five plausible stories; an instrument that always names a suspect would have produced a sixth.
- **⚠ ONE LIMIT, stated because it changes how the number is read.** The registry cannot observe a listener dying with a garbage-collected target, so its "live" count is an **upper bound on gross subscriptions**, not a retention figure. Retention is read from CDP's own `JSEventListeners` counter in B519904 (+≈1 per edit). **The two answer different questions and are never reported as one number.**
