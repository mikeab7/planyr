`[ ]` `cursorLL` is memoised on `[cursor, origin]`, and `cursor` is only written by a pointer MOVE — so a wheel zoom with the mouse still leaves the lat/lng chip reporting the **pre-zoom** point until you jiggle the mouse. The same screen pixel is over a different place in the world after a zoom.
- Verify: sandbox
- **This is the OPPOSITE edit to VIEW-INDEPENDENT-ONCE** — a value that is genuinely view-derived, memoised so hard it fails to move when the view legitimately changes. Reported by `inverseFindings`, never "fixed" by the perf pass.
- The fix recomputes `cursor` from the last screen pointer position when `ppf` changes, which touches the pointer path — out of scope for a performance dispatch, and the pointer path has a quarter-pixel accuracy harness (`diagnose-pointer-accuracy`) that any change here must clear.
