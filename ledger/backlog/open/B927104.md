`[~]` **HALF SHIPPED THIS SESSION — the CI-side asymmetry is fixed; the "a local run cannot predict CI" half is NOT, and is flagged loudly here rather than silently closed.**
- Verify: live — the fix is a GitHub Actions workflow change; only a real CI run can show the corrected attribution line.
- **THE DEFECT, measured.** `.github/workflows/build.yml` sets `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` on the **Build** step (the head build) and on nothing else. The **Base-ref bundle snapshot** step (`scripts/perf-base-stats.mjs`) therefore builds the base ref with those variables ABSENT, and `import.meta.env.VITE_SUPABASE_URL` / `..._ANON_KEY` are inlined as string literals at build time (`src/workspaces/site-planner/lib/supabase.js`, `src/workspaces/food/lib/supabaseClient.js`, both statically reachable from `src/main.jsx` → the shared entry chunk on EVERY route). So base and head are not two measurements of the same thing: head carries the literals, base does not.
- **THE SIZE OF THE LIE, derived from the two failing runs plus local builds of the same commits.** Local (no secrets): `a85cd402` notes route **705,351 B**, `b4d65330` **706,504 B**, `9a5d54f3` **706,439 B**. CI's base builds reported **+30.7 KB** and **+31.8 KB** above the 673,962 B baseline — i.e. **705,351** and **706,504**, byte-for-byte identical to the local builds, confirming CI's base build is also secret-free. CI's HEAD builds of the same trees came out **~300 B larger** (bounded to 291–321 B by CI's own rounded output). A control build with a full-length dummy JWT + project URL moved the same metric **+619 B**, confirming the mechanism directly.
- **WHY IT MATTERS: it inverts the sign of a real reduction.** PR #1263 REMOVED code, and CI's attribution line still read `this branch +0.2 KB`. The true branch delta was **−65 B**; the reported figure was the removal swamped by ~300 B of literals present in head and missing from base.
- **SHIPPED HERE:** the same `env:` block added to the Base-ref bundle snapshot step, so the two builds are built alike. This does NOT change any push-to-main verdict (main is judged absolutely on the head build), only the honesty of the attribution.
- **⛔ NOT SHIPPED, AND THIS IS THE HALF THAT ACTUALLY BURNED TWO SESSIONS.** A LOCAL pre-flight has no secrets at all, so it under-measures the head build by that same ~300 B and reports a margin CI will not honour. That is exactly how PR #1263 was validated locally at "0.3 KB under the ceiling" and then failed on main by 0.0 KB. Until this half lands, **treat any local `--as-main` margin under ~1 KB as UNPROVEN.** A fix needs a way for a local run to state, in the report, that it was built without the production env — noted in `docs/perf/PERF-BUDGETS.md` in this commit as a stop-gap.
- **STOPPING RULE:** closes when a local `perf-bundle-audit` run either (a) reports the env-provenance of the build it measured, or (b) refuses to print a margin it cannot vouch for. Not before.
