- **WHAT SHIPPED — `ui-audit/interaction-degradation.mjs`** (+ `ui-audit/lib/interactionAxis.mjs`, `lib/heapSnapshot.mjs`, `lib/fakeTile.mjs`; 40 unit tests in `test/interactionAxis.test.js`, `test/heapSnapshot.test.js`, `test/fakeTile.test.js`; `npm run perf:interaction`). ONE identical, **viewport-neutral** probe — a fixed pan out-and-back plus a fixed wheel zoom in-and-out — at **N = 0 · 50 · 150 · 400 · 1000** gestures, in a **headed** Chromium under Xvfb (honouring `frameSamplingFault`; no number the guard would reject is ever printed), against an **`idle` control arm** that waits the same wall clock and takes the same probes.
- **TWO GUARDS PULL IN OPPOSITE DIRECTIONS AND BOTH ARE ASSERTED EVERY CHECKPOINT** — the probe must MOVE the view (or it samples an idle page, the B1344 trap) and must RETURN it exactly (or checkpoint N is looking at a different amount of scene, which silently collapses this back into the "how much is drawn" axis). Plus a hard CONTROL assertion on `elementsDrawn` / `canvasNodes`.
- **⚠ THE FIRST FULL RUN WAS INVALID AND THE HARNESS CAUGHT IT ITSELF — recorded because it is the whole argument for building the guard.** The workload's wheel direction never alternated (a parity bug: `done` advances by TWO per iteration, so `done % 2` never changed), so every notch zoomed the same way, the view walked into the ppf clamp, and by N=150 the plan was off screen — `elementsDrawn` **66 → 0**, `canvasNodes` **976 → 227**. The neutrality guard **SUPPRESSED every affected checkpoint** rather than reporting the resulting frame numbers as a trend. Without it this item would have shipped a confident, false degradation curve. Each workload gesture is now individually neutral, with a view restore and the control assertion on top.
- **THE RESULT — THE IDENTICAL PROBE DOES NOT GET SLOWER, ACROSS THREE REGIMES.** Drift **0.000** and `elementsDrawn` **66** / `canvasNodes` **976** pinned flat at every checkpoint of every run, so the content genuinely was constant.

  | regime | probe median 0 → 1000 | probe p90 0 → 1000 | verdict |
  | --- | --- | --- | --- |
  | dpr 1, no tiles decode | 33.3 → 16.8 ms | 166.6 → 166.7 ms | INCONCLUSIVE (floor ±50.1%) |
  | dpr 1, **tiles decoding** | 50 → 50 ms | 166.6 → 149.9 ms | INCONCLUSIVE (floor ±33.3%) |
  | **dpr 2**, tiles decoding | 16.7 → 16.7 ms | 116.6 → 100.1 ms | INCONCLUSIVE (floor ±99.8%) |

- **THE CONTROL ARM MAKES IT STRONGER, NOT WEAKER.** In the two-armed run the `idle` arm — same wall clock, same probes, zero gestures — drifted **worse** (p90 166.7 → 249.9 ms) than the arm that did a thousand gestures. Whatever wander is in these numbers is the machine, not the interactions.
- **SO, IN WRITING, AS THE ITEM DEMANDED: the owner is NOT confirmed right on this axis in this environment, and the r=0.93 finding is NOT refuted.** That is the honest reading and it is stated plainly rather than softened.
