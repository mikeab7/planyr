- **The case.** A first pass at the repeat-gesture table put a **900 ms read between the two presses**. That is past `DBLTAP_MS`, so it is two clicks and not a double-click, and it "reproduced" a failure that meant nothing. The runs that produced B280400 have no read between presses and log the measured gap for each (70–144 ms).
- **The rule, beside FOREGROUND-OR-VOID in `/CLAUDE.md`:** take the reading only at the END of the gesture, or **measure the press-to-press interval from the events' own `timeStamp`s and assert it is inside the budget** — never assume it. The deliberate exception is the TWO-PRESS INVARIANT, which is a single press followed by a question and does not claim to be a double-click.
- **⛔ AND THE ASSERTION IMMEDIATELY FAILED ON ITSELF, which is the whole argument for measuring.** The first implementation carried its running gap across the reset and so measured **deselect→press-1 (852 ms)** instead of **press-1→press-2 (34 ms)**, reporting every gesture in the suite as too slow. It now records raw timestamps per gesture window. An instrument that cannot catch its own defect is not measuring anything.
