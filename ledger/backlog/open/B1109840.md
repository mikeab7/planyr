`[x]` **SHIPPED.** A workbook is now an ordered list of named sheets (`lib/sheetModel.js`'s `createWorkbook`/`migrateWorkbook`), each holding its own independent grid — add / rename (inline, double-click, never `window.prompt`) / duplicate / delete (right-click menu; refuses on the last remaining sheet) / reorder (drag) — via a new `TabStrip.jsx`, pinned OUTSIDE the grid's own scroller (a sibling of `SheetView`, never a child of it) so it never scrolls away with the columns, with its own horizontal overflow handling for many sheets and the "+ Add sheet" button always reachable at the strip's trailing edge.
- **Storage — the cheapest correct shape, argued rather than defaulted:** `public.model_sheets` stays ONE ROW PER WORKBOOK — the `data jsonb` column simply now holds `{version, nextSheetId, sheets:[{id,name,sheet}], activeSheetId}` instead of one bare sheet's fields. No SQL migration was needed (a jsonb column has no fixed shape to migrate); `migrateWorkbook` reads either shape and always returns a valid workbook, wrapping a pre-existing single-sheet blob into a one-sheet workbook named "Sheet1" with zero data loss. A row-per-sheet schema was considered and rejected: nothing in this app ever needs to read/write one sheet of a workbook independently of the rest, so a second table would only add its own CAS/RLS/trigger set and a join for no benefit over the existing guarded whole-row write.
- **Cross-sheet formula references — `SheetName!A1` / `'Sheet With Spaces'!A1`, engine-side in `src/shared/formula/formula.js`** (synced to `public/sequence/index.html` via `scripts/sync-sequence-formula.mjs`; the concurrent named-ranges session was told to expect this and to say in its own PR exactly what it additionally changed there). Tokenizer: `!` as a new operator, single-quoted sheet-name literals (`''` escaping, mirroring the existing `"..."` string handling). Parser: a leading `id`/quoted-name token immediately followed by `!` qualifies the ref/range node that follows (`node.sheet`), checked ahead of the ordinary identifier dispatch so it can never collide with a function call (which needs `(`, not `!`). Evaluator: `ctx.grids` (an optional map of lowercased sheet name → that sheet's own `grid[][]`, wired only by the new multi-sheet workbook evaluator) resolves a qualified reference; an unresolvable sheet name is `#REF!`, never a silent blank — matching the engine's existing never-a-crash contract. `sheetEngine.js`'s `evaluateWorkbook` generalizes the existing per-sheet `evaluateSheet` (kept, now a thin one-sheet wrapper over it) into ONE combined dependency graph across every sheet's cells, so a formula on one sheet reading another sheet's (possibly itself formula-computed) cell resolves correctly regardless of which tab is currently visible, and a circular reference THROUGH another sheet is caught as `#CIRC!` exactly like one that never leaves a sheet — every sheet evaluates always, hidden ones included.
- **Renaming a sheet rewrites every formula that references it, across the whole workbook** (`rewriteFormulaForSheetRename`, formula.js — token-level, only the qualifier's own span changes, quoting the new name only when it doesn't lex as a bare identifier). **Deleting a referenced sheet turns every cross-sheet reference to it into `#REF!`** (`dropFormulaSheetRefs`) rather than blocking the delete — a deliberate choice, stated rather than defaulted: blocking would mean hunting down every reference across every other sheet before a delete is even possible, a worse workflow than Excel's own (delete a referenced sheet, formulas pointing at it show `#REF!`, nothing else breaks). Row/column insert-delete (`rewriteFormulaForStructuralShift`) is now sheet-scoped too — a structural edit on one sheet shifts only the references whose EFFECTIVE target (its own qualifier, or the owning formula's sheet when unqualified) is that sheet, sweeping every OTHER sheet's cross-sheet formulas via new `workbookInsertRowAt`/`workbookDeleteRowAt`/`workbookInsertColumnAt`/`workbookDeleteColumn` wrapper functions in `sheetModel.js`; passing no sheet names preserves the exact original single-sheet behavior byte-for-byte (the Schedule module's mirrored copy, which never sets these, is unaffected).
- **Two real layout bugs found and fixed via live-browser screenshots before shipping** (not sandbox-only): (1) the tab rename input was a fixed 110px box — typing a real name ("Assumptions") scrolled its own start out of view, rendering as "\ssumptions"; widened to the tab's own true available width (172px). (2) `SheetView.jsx`'s `position:fixed` zoom control (bottom-right corner) sits relative to the whole viewport, not this card, so it had no way to "see" the new tab strip below it and sat ON TOP of the "+ Add sheet" button — measured live, same pixels. Fixed by lifting the zoom control's `bottom` offset by the tab strip's own exported height constant.
