- **HIS MEASUREMENT, WHICH IS THE WHOLE ITEM IN ONE FACT.** After a press, the element carried the class `planyr-anchor` and **nothing else** — no selected, active or focused state anywhere on the box, before or after clicking. There was no such thing as a selected box, so Delete had nothing to act on and every affordance had to hang off the pointer happening to be over it.
- **THE MODEL, OneNote's, in four steps.** Press 1 on an unselected box **selects** it — the caret does not enter, so the BOX is the thing you have hold of and Delete removes it in one undoable step. Press 2 **enters** it and it is an ordinary text box again. Escape backs out to selected; Escape again deselects. Arrow keys nudge a selected box; click-away clears it. A press on empty page still places a new box, unchanged.
- **TWO DEFECTS FOUND BY THE ADVERSARIAL PASS ITSELF, both invisible to a confirming test.** (a) The selection ring is an attribute on an element the EDITOR owns, and blurring the editor rebuilt the node view and dropped it — so "Escape backs out to the box being selected" silently did not happen. It is repainted on every transaction now. (b) The rule was bound in TWO places, so one Escape ran it twice and left editing *and* cleared the selection in the same keystroke, which made the two-stage model unusable. One binding now.
