- **THE MEASUREMENT, from the incident that produced this.** #974 was pushed with a green build. Five PRs merged while it sat — **#969, #970, #971, #973, #976, #977** — and it went `mergeable_state: dirty`. Resolving it by hand required inspecting **4 conflict hunks across 3 files** and regenerating 2 more. **Every hunk was "both sides prepended a new item to the top of the same section", with ZERO id overlap on either side.** There was no disagreement to resolve. There was nothing to decide. It was pure arrival-order collision, twice in one session (an earlier merge against `f797f8c` had the identical shape).
- **⛔ WHY THIS IS THE B6864 FAMILY AND NOT A HOUSEKEEPING GRUMBLE.** B6864–B6867 diagnosed a livelock where seven PRs were open and none was mergeable, and the fix was to make the contended resource a **pure function of the branch name** so two sessions cannot contend at all. That fixed the *numbers*. **The TEXT those numbers live in was left as one shared append target**, so the same shape survived one level up: the ids no longer collide and the paragraphs still do. A concurrency defect fixed for the identifier and not for the record it identifies is fixed for the easy half.
- **THE ASYMMETRY THAT POINTS AT THE ANSWER, and it is a measurement rather than a preference.** Of the five files, **two are GENERATED** (`BACKLOG_OPEN.md` from `BACKLOG.md`, `MAP.md` from `src/`) and **three are hand-maintained**. The generated pair conflicted just as violently — and resolving them cost **nothing and required no judgement**: take either side, run the generator, done. The three hand-maintained files are where all the reading, checking and risk was. **The files that are a function of data were free; the files that ARE the data were not.**

**THE THREE FIXES, and what each actually costs.**
- **(a) PER-SESSION APPEND FILES reconciled by the generator** — each branch writes `backlog.d/<branch>.md`; the generator concatenates. Kills the conflict outright (different files never conflict) and is the smallest conceptual change. **⛔ But it breaks on the two operations this repo performs most.** The lifecycle is a **MOVE** (🔲 Open → ⏳ Verify → ✅ Done, and Done means moving the block to another file) — that is not an append. And the **recurrence rule** re-opens the ORIGINAL `B#`, which by definition lives in some *other* session's append file: the edit is cross-file again, and now it is a conflict in a file whose owner never expected one. It solves the case we have and fails the cases we rely on.
- **(b) A UNION MERGE DRIVER on the append-only sections** — `.gitattributes` marking these files `merge=union`, which git concatenates both sides of. **By far the cheapest: one line, no per-clone configuration (union is a built-in low-level driver), and it would have landed #974 with no human step at all.** ⛔ Its hazard is exactly proportional to its convenience: union **cannot tell an append from an edit**, so two sessions amending the SAME item — which happened twice in this very session (#976 amended B1349; this branch corrected its own B287057 cross-reference *because* of #976) — are silently DUPLICATED instead of stopping anyone. In the file that is the single source of truth for what is open, a silent duplicate is a correctness failure, not an untidiness. Good bridge, wrong destination.
- **(c) ENTRIES AS DATA THE GENERATOR ASSEMBLES** — one file per item (`backlog/items/B287056.md`, front-matter for status / `Verify:` / tags / module, prose for the body), with `BACKLOG.md`, `BACKLOG_OPEN.md` and `BACKLOG-DONE.md` all becoming GENERATED VIEWS. Two sessions filing two items touch two different files → **no conflict**. A lifecycle move is a one-field edit in one file → **no conflict**. A recurrence is an edit to one existing item → conflicts **only** with another session editing that same item, which is a genuine disagreement that SHOULD stop you.
- **⛔ I WOULD PICK (c), AND SHIP (b′) AS THE BRIDGE. The reason is the property, not the tidiness: (c) is the only option where the conflict rate tracks REAL DISAGREEMENT instead of ARRIVAL TIME** — which is precisely the property B6864 established for ids, applied one level up to the text. Three things make it the cheap choice rather than the grand one: the repo **already runs this pattern** (`BACKLOG_OPEN.md` and `MAP.md` are generated, `--check` already fails CI on drift, and both were free to resolve in this incident — that is evidence, not analogy); prose cross-references (*"see B1349"*) are plain text and keep working untouched; and the archives are already declared **write-only**, so turning them into generated views costs nothing anybody reads.
- **THE PRICE OF (c), NAMED RATHER THAN GLOSSED.** It is a one-time migration of ~1,400 items across two files, `BACKLOG.md` stops being hand-editable and every session's habit changes with it, and **the generator becomes load-bearing** — if it is wrong the entire ledger is wrong, so it needs the same mutation-proven treatment as any guard here. That is a real cost and it is why the bridge matters.
- **(b′) THE BRIDGE TO SHIP FIRST, and it is small: `scripts/resolve-ledgers.mjs`,** encoding exactly the resolution performed by hand in this incident — union the conflicting append sections, **but FIRST assert that no `B#`/`V#` appears on both sides**, refuse loudly and leave the conflict for a human if one does, then regenerate the two derived files. It gets (b)'s automation with none of its silent-duplication hazard, because it checks the property that makes union safe instead of assuming it. It is also the honest way to prove (c) is worth doing: if the "ids overlap on both sides" branch never fires in a month of merges, the conflicts really are 100% arrival-order and (c)'s migration is justified by data.
