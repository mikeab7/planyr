- **THE MISS, and it is the same shape as the raster one.** Every plan this program has measured reads **0 / 0 / 0 / 0** on markups, measures, callouts and cross-sections. Goose Creek does; Bain does. So every null result about annotation cost was structurally guaranteed before the first gesture — the admission `docs/perf/PERF-BAIN.md` §0 makes about rasters, on the other tier.
- **WHY SYLVESTRI IS A CLEAN CONTROL and not merely the available plan.** It has **NO SHEET OVERLAY AT ALL.** Nothing it shows can be charged to a raster, to blending, or to texture memory — the three hypotheses the sixty-run Bain battery was about. Its only raster is the `fromMap` underlay the app never paints on a plan with an origin.
- **(a) THE TIER SEPARATES.** `no-annotations` vs baseline: **6/6 paired reps cheaper, p = 0.031, median −12.6%** render, and it also clears the unpaired range floor (−13.8% against ±8.9%). 5 arms × 6 reps, 30 runs, 0 suppressed, interleaved.
- **(b) NO SINGLE KIND SEPARATES, AND THAT IS A RESULT.** Callouts 5/6 (p = 0.219) · markups 5/6 (p = 0.219) · measures 2/6 (p = 0.688). The whole tier clears the bar and none of its parts does — consistent with the cost being DISTRIBUTED across callouts and markups at roughly half the tier's magnitude each, below what six paired reps can resolve individually, with measures contributing nothing. Six reps is the arithmetic minimum at which a sign test can reach p ≤ 0.05 at all (6/6 → 0.031). ⛔ **Do not read this as "callouts are free."**
- **(c) `no-measures` CAME BACK DEARER (+3.2%), which is how you know the floor is honest.** Two measurements cannot cost negative work. That arm has one rep at 2372 ms against a 1300 ms median — visible because every rep is printed — and the verdict correctly reports INCONCLUSIVE rather than a finding in either direction.
- **(d) MAIN-THREAD WORK DOES NOT SEPARATE HERE EITHER** — −8.1%, inside the ±16.6% floor, 5/6 (p = 0.219). The same pattern as `PERF-BAIN.md` §5: the difference lives in paint and raster, and `Script + Layout + RecalcStyle` is blind to both.
- **(e) THE NODE CENSUS, which needs no statistics.** The 24 annotations are **159 canvas nodes and 33 text nodes**: callouts 122 nodes / 30 text · markups 27 / 3 · measures 10 / 0. Callouts are ~77% of the tier's DOM by node count.
- **⛔ THE GUARD, and it earned its keep on the first run.** An arm whose annotations never rendered looks exactly like an arm that is fast — the `decodeFault` principle on a new axis. `annotationFault` proves each arm's callouts, markups and measures reached the canvas, counted from the DOM, before it will report a number. On run one every arm read **0 of 24 annotations on a page rendering all of them**: the census read was written as a template-literal string, and **Playwright evaluates a string as an EXPRESSION and does not call it with the argument, unlike Puppeteer** — the same subtlety that wrote nothing to IndexedDB in B209568, arriving by a different door. Nothing but the guard would have caught it.
- **ONE APP CHANGE, inert.** Markups were the only drawn object with **no id in the DOM at all** (elements have `data-el-id`, measurements `data-measure`, callouts `data-testid="callout-<id>"`), so nothing outside React could tell whether one had rendered. All ten of `renderMarkupNode`'s return paths now carry `data-markup={m.id}` — an attribute with no behaviour attached. A kind that quietly did not carry it would read as "this markup costs nothing".
