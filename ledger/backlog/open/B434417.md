- **WHY IT IS WORSE THAN "IT DOES NOT WORK".** The box goes on RENDERING at the size you dragged it to, so the gesture looks like it worked; the size evaporates on the next reload. You do the work, you watch it happen, and it is gone.
- **THE MECHANISM.** `endSize` committed `parseFloat(dom.style.width)` — and the DOM is not the gesture's memory. Anything that re-renders the node view between the last pointermove and the release rewrites that style from the node's CURRENT attrs, after which `num(w, ANCHOR_WIDTH)` falls back to the 180px default. On a signed-in account a sync tick does exactly that. **The commit now reads the gesture's own record**, and the MOVE drag — which had the identical `parseFloat(dom.style.left)` hazard and would have been the next report — was fixed in the same pass.
- **⛔ AND THE REASON THE HARNESS THAT SHIPPED THIS WAS GREEN, which is the lesson rather than the excuse.** It read storage AND reloaded, so it looked like a document-level check. It passed because a signed-out sandbox has nothing that re-renders a node view mid-gesture: the check was correct and the CONDITIONS were unreachable. Reproduced here by forcing one interfering re-render mid-drag — which now runs on every pass, at three window sizes, at a zoom other than 100%, on a box that was moved first, and on the last box of a crowded page.
