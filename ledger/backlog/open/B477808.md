- Verify: sandbox — both cases driven on the owner's real FM 359 plan in a browser, with the MODEL read back out of storage.
- **TWO DIFFERENT FACTS, and the first guess about the second one was WRONG — which is why they are stated apart.**
  - **CLAMP (a real alteration).** `clampNum` floors at `min` and ceils at `MAX_DIM` (100,000 ft). Typing `200000` into Depth committed **100,000** and said nothing. The stored dimension genuinely was not the one typed.
  - **DISPLAY ROUNDING (not an alteration).** Every dimension call site passes `value={Math.round(...)}`, so typing `613.7` shows **614** afterwards — and it looked like the field silently rounds. **It does not: the model stores 613.7 exactly** (verified by reading it back out of the saved plan). What is rounded is the DISPLAY, so the number on screen stops being the number in the drawing. A smaller problem than a swapped dimension, and a real one.
- **LOUD-FAILURE:** both now report in the moment, in their own words and with their own icon — *"✎ Using 100000"* for a clamp, *"✎ Showing 614"* for a display that disagrees with the model — and neither is dressed as a rejection (`aria-invalid` stays keyed on a genuine refusal alone). **Nothing was prevented and no rounding was removed**: the clamp and the round are both correct behaviour; they were merely silent. The display half is detected by watching what the CALLER hands back, so no call site changed.
- **⛔ AND THE DEFECT THIS WORK ITSELF INTRODUCED, caught by the browser and pinned by a test.** The first cut rendered the message by returning a bare row when there was nothing to say and a wrapped column when there was — so the moment a message appeared React saw a different tree shape, **REMOUNTED the `<input>`, and the field lost focus mid-keystroke**: typing `-5` left `-` in the box and dropped the `5`. A control that stops accepting input the instant it has something to tell you is a crueller version of the complaint this whole strand began with. The wrapper is unconditional now; the MESSAGE changes, never the tree. Invisible to every unit test (MODULE-SCOPE-COMPONENTS' family).
