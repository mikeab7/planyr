**The report.** V17005 passed live on both features the owner double-clicked, and the same pass found a DETENTION POND on the Bain plan dead to a double-click AND to a single click — while `ui-audit/audit-doubleclick-properties.mjs` seeded a pond and passed it 19/19 in all three modes.

**AUDIT-FIRST — three holes, found by attacking the harness rather than the pond. Each is independently sufficient to green a dead element, which is why the fixture-data theory alone was never going to explain it.**

1. **AN UNANSWERED PROBE POINT WAS PRESSED ANYWAY.** `probePoint` falls back to its first candidate when NO point resolves to the feature. The loop then clicked it, the press landed on whatever lay beneath, *some* panel opened, and `panelOpen()` — which only ever asked "is a panel up", never "is it THIS feature's panel" — reported a pass. **Measured, not argued: with the pond's own group forced to `pointer-events: none` — a pond provably unclickable — the suite still reported 50/50.** An unanswered probe is now a FAILURE with its own message: if nothing under a feature claims it, the user cannot reach it either, and that IS the bug being hunted.
2. **SELECTION WAS NEVER ASSERTED AT ALL.** The owner's symptom was "no panel, **no selection**", and the suite had no check for the second half — a feature that silently refuses selection was indistinguishable from one that selects fine. Now every feature must select on a single click, in every mode (locked is select-only per B922; grouped selects its group per B261, so "something is selected" is the common floor). The deselect is a PRECONDITION, not politeness: Escape alone was measured leaving 45 handle nodes up, and without proving zero first the assertion would pass for every feature whether or not the press did anything.
3. **A CENTRES-MODE PROBE COULD LAND ON TEXT.** `pointer-events` is inherited but a CHILD may override it, so a pointer-dead pond still had live chrome: its map label. The probe found the label, NEW-3 forwarded the press from text to the body's action, and the row passed over a body nobody can press. Centres mode now requires a GEOMETRY hit (text / tspan / `[data-el-dim]` / `[data-label-for]` rejected) — `--labels`, whose entire purpose is probing the label, is the deliberate exception. Interior off-centre candidates were added in the same change, because a filled feature carries its label AT its centre and rejecting text without them would report a perfectly clickable pond as unreachable.

**Two source changes, both inert, both required — selection had no DOM signal to read.** An element (unlike a markup) carries no per-feature "selected" stamp, and a multi/group selection paints only chrome that renders OUTSIDE the handle layer. `SelectionChrome.jsx` and the multi-selection footprint ring now stamp `data-testid="selection-chrome"` / `data-testid="selection-ring"`. One attribute each on already pointer-transparent groups; no visual change. **Bundle cost: +0.2 KB on `bundle.siteRouteJsBytes` (2369.3 → 2369.6 KB), inside the headroom band and stated rather than absorbed silently.** It stays: the two attributes ARE the fix for an unobservable selection, and there is no cheaper way to make selection readable from the DOM than naming the node that paints it.

**Fixture gap closed too — a type name in a fixture is not a class.** The pond row was a bare rect with a label. A real pond carries a detention record, is often an irregular POLYGON (a different branch of `renderElPx` entirely), and may carry an expansion BASELINE painting a second fill over the basin. Added: polygon · rect+detention · polygon+detention · polygon+expansion-baseline · a GROUPED pair. The grouped rows assert **B261 drill-in** in the direction it actually holds (selects, Properties deliberately stays shut), so the one element class whose double-click is *supposed* not to open the panel is PINNED rather than left looking like a pass.

**Verification.** 50/50 `centres` · 50/50 `--labels` · 48/48 `--locked` on merged main. **Negative control, proven RED first:** with the pond group `pointer-events: none`, the pre-fix suite reported **50/50** and the post-fix suite fails **all 12 pond rows** naming the reason. One reported gap is logged, never silently skipped (CLAUDE.md "no silent caps"): a **locked + grouped** element paints no DOM-observable selection at all — locked suppresses handles, grouped paints no per-feature stamp — so `sel` moves with no observable consequence. Reported rather than asserted, because asserting either direction would pin behaviour nobody has decided on.
