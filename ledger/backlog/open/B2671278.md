### B2671278 — Each Notes page keeps its own undo history when you switch pages `[Notes]` (feature) #notes #keyboard #persistence  *(owner chat block 2026-11-13, "NEW-1": Ctrl+Z should keep working "even if I go to an old page or a page I wasn't on in a minute", "if it doesn't cause much bloat".)*
`[ ]` **IN PROGRESS — see the lifecycle line when it moves.**
- Verify: sandbox + live (the signed-in check on the test account records the dated PASS)
- **Confirmed live-reproducible before the change** (the harness against unmodified behaviour: 15 of 33 checks red): `Notes.jsx` keys `<NoteEditor key={pageId:bodyEpoch}>`, so a page switch unmounts the editor and the next page's editor starts with an EMPTY history — Ctrl+Z after A → B → A found nothing.
- **What shipped:** `lib/notesUndoCarry.js` — when a page's editor goes away its undo AND redo stacks are packed (step JSON text, step maps, selection bookmarks) into a small in-memory table keyed account|page; when the page is opened again they are revived against the NEW editor's schema and handed to the history plugin by a meta-only transaction (`historyKey` meta, no step — no plugin sees an edit, nothing is saved). `NoteEditor.jsx` has one effect doing both ends. The keyed remount and the autosave flush are UNCHANGED.
- **⛔ WHY STEPS TRAVEL AS JSON, not as the old history object (measured):** every Tiptap editor builds its own ProseMirror schema; handing the old history to the new editor looks carried (`undoDepth` matches) but an undo whose step holds nodes (a deleted box) silently restores NOTHING. `Step.fromJSON(newSchema, …)` fixes it. A plain typing step happens to work either way, which is how this could have shipped half-working.
- **⛔ STALE GUARD:** the entry carries a fingerprint of the document it was saved against and is replayed only when the reopened page is byte-for-byte the same document. Another tab / computer, a version restore, a conflict choice, a sync adoption, or a legacy page the read-time migrations rewrite → fingerprints differ → the saved history is DISCARDED (nothing to undo), never replayed. Mutation-proven (guard off → the "changed elsewhere" rows go red).
- **Caps (the "no bloat" decision, all constants in the lib):** 5 other pages remembered (least-recently-parked dropped first) · 50 undo steps per page, each of undo and redo (oldest dropped first; ProseMirror's own default is 100) · 200 KB of step JSON per page (oldest steps dropped until under; a single step over the cap drops that page's history). In memory in this tab only; no new dependency; the file rides the editor's own lazy chunk.
- **Left out, on purpose:** surviving a RELOAD (it would need the history in storage — new bytes in the small tier (TIER-BY-REBUILDABILITY) and a cross-version risk for a convenience; stated, not an oversight) · never synced between computers · a picture's bytes are not part of undo (a pasted picture deleted and undone relies on the existing image store, unchanged).
