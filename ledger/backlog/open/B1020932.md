- **The migration, exact SQL, worked out this session so it doesn't need re-deriving:**
  ```sql
  alter table public.doc_reviews    add column if not exists org_scope boolean not null default false;
  alter table public.file_facts     add column if not exists org_scope boolean not null default false;
  alter table public.project_folders alter column project_id drop not null;
  alter table public.project_folders add column if not exists org_scope boolean not null default false;
  alter table public.project_folders add constraint project_folders_scope_ck
    check ((project_id is not null and org_scope = false) or (project_id is null and org_scope = true));
  drop index if exists project_folders_sibling_unique;
  create unique index project_folders_sibling_unique
    on public.project_folders (user_id, org_scope, coalesce(project_id, ''),
         coalesce(parent_id, '00000000-0000-0000-0000-000000000000'::uuid), lower(name))
    where trashed = false;
  ```
  **The `coalesce(project_id,'')` rewrite of the sibling-uniqueness index is not optional** — a plain unique index treats every NULL as a distinct value, so once `project_id` is nullable for org rows the EXISTING index would silently stop deduping org folder names (two folders both named "Drawings" could coexist). This is the one correctness trap in the whole migration; get it right the first time.
