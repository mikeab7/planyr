### B2597360 — Univer grid: formula results get an auto-applied number format that reads wrong (¥ on PMT) and prints raw codes in the CSV (`_)`, `;@`) `[Spreadsheet]` (bug) #ui #testing  *(found by the first live V2034432 run on planyr.io, build 320336a, 2026-10-31, while verifying B2585376; DEDUPE-FIRST: no existing item — B2585376 is the formula engine, this is display formatting)*
`[ ]` **🔲 Open — Verify: live (the Univer grid is owner-gated; sandbox reproduces it too).**
- **Measured, not guessed:** in the Univer grid a plain `=PMT(0.06/12,360,-250000)` shows as **`¥1,498.88`** (a YEN sign, on a US account) — Univer's number-format plugin attaches a currency pattern to the results of financial functions, and `yyyy/mm/dd;@` to date-returning ones (`=DATE(…)`, `=EDATE(…)`). The bridge then SAVES those patterns as the cell's own format (they look like a user's choice), so they travel: the **CSV export printed `"¥1,498.88_)"` and `2026/01/15;@`** — Excel pattern fragments (`_)` = pad for a bracket, `;@` = text section) that Planyr's formatter (`formula.js` `formatValue`) does not understand and prints literally. The Excel FILE is unaffected (V2034432 confirmed the numbers and formulas; the pattern rides as the cell format, which Excel reads correctly).
- **What a person sees:** a mortgage payment with a yen sign; a CSV with stray `_)` and `;@`. Not a wrong NUMBER — a wrong LABEL.
- **Directions (pick with a measurement, do not guess):** (a) stop Univer attaching the pattern on its own (its sheets-numfmt plugin: configure the auto-format off for formula results, or strip patterns the user did not choose in the bridge — the bridge already has the `synth` mechanism for patterns it synthesised); (b) teach the CSV/display path to read `_x` padding and the text section — but `formatValue` also serves the Schedule (inlined in `public/sequence/index.html`), so (a) is the safer first move. The currency symbol should follow the account's locale, never a hard-coded yen.
- **Stopping rule:** closes when, on planyr.io as the test account, `=PMT(…)` shows no yen sign, the CSV carries clean numbers and dates, and a date-returning formula still displays as a date.
