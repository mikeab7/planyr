- **WHAT WAS WRONG.** `renderElPx` recomputed, per building, **on every frame of every pan and zoom**: the validated dock sides, the resolved grid settings, `computeBuildingGrid` (a bay-count SEARCH over the footprint), the footprint axes, and `dockDoorRun` per dock side (the door-placement solver). **Not one of them takes the view.** And `settings.showDocks` / `settings.showGrid` **both default to `true`** (`SitePlanner.jsx:1740`, `:1745`), so a default plan paid the whole lot for every building on every frame. Because the number of buildings is one of the axes that rises through a session, this is an AMPLIFICATION cost, not a fixed one.
- **THE FIX.** `resolveDockPlan(el, settings, dogEars)` is precomputed into B1352's existing per-element neighbour record (`resolveElNeighbors`, now keyed `[els, settings]` — the same key `teeJunctions` / `driveJunctions` already use). `renderElPx` reads `nb.dockPlan`, with an inline fallback that is the identical computation so the two branches cannot draw different pictures.
- **⛔ BYTE-IDENTICAL BY CONSTRUCTION, which is why it clears the B1345 pixel bar without a diff to argue about.** Same pure functions, same arguments, same outputs — moved from "once per frame per building" to "once per model-or-settings change per building". No approximation, no threshold, no new geometry, and nothing about WHAT is drawn changes — which is what keeps it inside the owner's standing constraint that drawing quality and quantity may never be traded.
- **⚠ WHAT IS DELIBERATELY NOT CACHED:** the `buildingChrome` path for a footprint under live reshape (`el.footEdit`) still recomputes from the LIVE `frameBBox` every frame, ON PURPOSE, so the grid tracks the drag. Do not "unify" it in.

- **⚠ THE HONEST CAVEAT, stated rather than left for a reader to find.** Rung 0 is the control — with every drawn layer off, `showDocks || showGrid` is false and the changed code never executes — and it returns within **0.4%**, which is what makes the rest of the column the fix rather than the weather. But the per-rung deltas at rungs 1–3 (−3.5 / −4.9 / −10.1%) are each **inside the ±11–13% floor on their own**, and rung 4's *before* value was the highest single reading in that ladder. The defensible claim is the one the harness itself makes: **the axis went from a sustained upward trend to no trend at all.** It is NOT that every individual rung improved by a measurable amount.
