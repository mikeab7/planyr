- Verify: sandbox
- **THE SHAPE OF THE RISK, not just the gap.** During B646272 (shipped), the drag-and-drop row-move feature's first implementation gave its grip handle `inset:0` over the FULL id cell with `pointer-events` gated on CSS `:hover` — and because `:hover` is true for the entire duration of a mousedown (the cursor must already be over an element to press it), that silently ate every ordinary mousedown in the ID column, breaking the pre-existing row-range-select drag outright. It was caught and fixed in the same session (final geometry: an 8px permanently-interactive strip at the cell's left edge, `pointer-events` never gated) — but **the only reason it was caught is that a developer happened to build an ad hoc diagnostic script to chase down an unrelated multi-row-move test failure.** Nothing in the shipped, checked-in test suite would have caught it on its own.
- **WHAT EXISTS TODAY, PRECISELY.** `ui-audit/verify-schedule-row-move.mjs` check D (and its mutation) both call a `selectRowRange` helper that depends on the ID-column drag-select gesture working correctly — so if range-select broke again, check D would very likely fail too, as a SIDE EFFECT. But there is no check under its own name asserting "a real mouse drag across two ID cells produces a genuine multi-row `selRange`" — the property is only ever exercised as a precondition of a check about something else. A future refactor of check D (or a rewrite that stops using `selectRowRange`) would quietly stop covering this at all, with nothing to notice.
- **WHAT "CLOSING" THIS MEANS.** Add a small, standalone, named check (and its own mutation — e.g. temporarily reintroducing a `pointer-events:auto` full-cell overlay, or reverting the grip to `inset:0`) that asserts the range badge and the selected-range background color appear after a real two-row ID-column drag, independent of anything else in the file. The diagnostic technique already exists and worked (`document.body.innerText` for the "N × M" badge text, `getComputedStyle(...).backgroundColor` on the ID cells for the `rgb(219, 234, 254)` selected-range color) — it just was never turned into a permanent, named assertion.
