### B2522753 — NEW-2: breadcrumb spacing is uneven for short vs long names `[shell / header breadcrumb]` (bug) #ui #site-planner  *(owner chat block 2026-10-29. DEDUPE-FIRST: related to the NAVIGATION-WINS floors in `shared/CLAUDE.md` (NEW-2, B371361) which introduced `CRUMB_MIN_W` — this item changes how that floor is applied, not the rule that navigation wins.)*
`[ ]` Verify: sandbox (+ a signed-in live look on planyr.io after the deploy).
- **Measured cause (confirmed, not inferred):** both name crumbs carried a flat `min-width: 92px`, so a short name was padded out to it. On the real render the gap from the project caret to the next "/" was **62.7 / 53.6 / 16.7 / 14 px** for a 1-char / 2-char / 7-char / 40+-char project name — a spread of ~49 px (red on main).
- **Fix:** `crumbScope.crumbFloor(label, CRUMB_MIN_W)` — the floor is now `min(92px, <0.4ch per character> + chrome)`: still a squeeze limit for long names (capped at the same shared 92), but an UNDER-estimate of the name, so a short name hugs its text. Used by the project crumb (`ProjectBreadcrumb.jsx`) and the plan crumb (`SitePlanner.jsx`) — one rule, not two copies. Long names keep `max-width` + ellipsis and now carry a hover `title` with the full name (project and plan); the ▾ stays attached to the name; the hidden measuring twin no longer carries a floor.
- **Acceptance (measured):** `e2e/header-crumb-scope.spec.js` renders 16 project-name × plan-name combinations (A / GC / Academy / 56-char) on the Site tab at 1280 and 900 wide and asserts the four crumb↔"/" gaps are equal within 1 px, there is no dead space inside either crumb, hover titles equal the full names and nothing is pushed past the viewport. Fails on main (spread 48.7 px), passes now.
