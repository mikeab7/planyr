### B2458960 — Notes: a box that has shrunk to its words jumps wide on the FIRST MOVE of an east-handle drag, instead of tracking the pointer `[Notes]` (bug) #notes #ui  *(found 2026-10-27 while building the B2426788 live pass; PRE-EXISTING — identical on the pre-change build. Minted **B2458960**; DEDUPE-FIRST: no open/verify item names it — B2248944 (done) is the shrink-to-words feature it lives beside.)*
`[ ]` **Measured, not reasoned.** A box placed by a real double-click and typed into shrinks to its words on click-out (`fit`, B2248944 — e.g. 96 wide). Select it, press its east handle and drag 50 right, reading the box's rendered width at the press and after each of six moves: **press 96 → first move 168 → 177 → 185 → 193 → 202 → 210 → release 210** (a tracking drag reads ~104 on the first move, ~146 at the end). So the box jumps to ~160 (the start width a new box gets) before following the pointer, and the stored width ends at ~160 + the pull. Reproduced on **planyr.io signed in (build 3a727d1)**, on the PR preview, on a local build, and on the **pre-change build** (`DBL=1 BODYSEL=1 node ui-audit/verify-notes-box-edge.mjs http://localhost:4182` against a main build) — so it is NOT B2426788. It is invisible to a seeded fixture because seeded boxes never shrink (local seeded run: 160 → 210, tracks correctly).
- **Where to look first (a lead, not a diagnosis):** something re-widens a `fit` box when the resize paints its first frame — candidates are `NoteEditor.jsx`'s `fitAnchorBox` ResizeObserver re-deriving the rendered width from `data-anchor-w`, and the `growWidthFor` "grow back to the start width" effect (the box was shrunk, so `cur < start`), neither of which should run during a handle drag. `notesAnchorNode.js` `beginSize`/`moveSize`/`paint` read the live width correctly (96 at the press).
- **Instrument:** `ui-audit/verify-notes-box-edge.mjs` row 6 prints the rendered-width trail and a "KNOWN DEFECT B2458960 (not scored)" note on any run that builds boxes by real presses (signed in, or `DBL=1` locally). When fixed, score the first-move reading (`trail[1]`) in that row.
- **Stopping rule:** closes when a press-built (shrunk) box tracks the pointer from its own width on an east/west handle drag, in the harness above on the signed-in build. Verify: live.
