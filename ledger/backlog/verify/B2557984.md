- **Cause (measured by pasting a Word-shaped clipboard through a real editor, red on main):** Word has no list element on the clipboard. A bullet is `<p style="mso-list:l0 level2">` whose first child draws the bullet as TEXT — `o` in Courier New, `§` in Wingdings, a private-use square — inside `<span style="mso-list:Ignore">`. The parser kept the span as text and has no idea what `mso-list` is, so no level survived either. Level 1's `·` happens to look like a bullet, which is why only levels 2-4 read as wrong.
- **Fix:** `lib/notesOfficeLists.js` (new). `convertOfficeLists` runs in `transformPastedHTML` before the parse: drops the marker spans, rebuilds real nested `<ul>/<ol>` by level (`planOutline`, pure — a blank paragraph between items does not break the run), reads bullet vs numbered from the marker text or the `@list` definition (`1.` / `a.` / `iv.` → ordered, start number kept), and handles hanging-indent glyph markers with no `mso-list` (the OneNote shapes). Planyr draws the bullet glyphs; nothing from the source survives as text. **Also fixed, found on the way:** a Word list's `text/plain` ("1.⇥Entitlements") is a clean two-column grid and the tab-separated-text rule turned a pasted Word NUMBERED list into a marker+text TABLE on main — `isMarkerColumn` stops that and the text fallback now stands down whenever the html already produced a list.
- **Not changed:** the three paste options (Keep source / Merge / Text only) and Excel/Sheets ranges — `verify-notes-paste-options`, `verify-notes-table-paste`, `verify-notes-table-copy-paste` re-run green; Google Docs lists unchanged (known-good arm); plain-text paste unchanged. No Word checklist shape exists (Word has no checkbox list in its clipboard HTML), so the editor's task lists are untouched.
- **Sandbox-verified:** repo-root `test/notesOfficeLists.test.js` (33 tests: parsers, planner, tab rows, the Word-list-text-is-not-a-table guard, wiring guards); `ui-audit/verify-notes-list-paste.mjs` against the committed fixtures in `test/fixtures/clipboard-lists` — **19 of 38 checks RED on unmodified main, 38/38 green on the fix** (OneNote's real `<ul>` outlines already passed on main, which is itself a finding: the defect is Word-shaped markup).
