### B2671293 — Notes: Ctrl+A with the caret inside a box selects only that box's text, like PowerPoint; with no caret in a box it selects every box as boxes `[Notes]` (feature) #notes #paste #ui

*(Owner, 2026-11-15, Claude Code dispatch block "[FEAT] Notes: Ctrl+A inside a box selects only that box", NEW-1: "approved PowerPoint behaviour". DEDUPE-FIRST: B2671288 (Excel-style box copy, merged #2974/#2978) left Ctrl+A selecting the whole page's text — its carry-forward item 7 named it "a separate call he has not made"; this is that call. No open item covered it. Constraint 59 in `/CLAUDE.md`.)*

- Verify: live — **V?** (signed in on planyr.io, `ui-audit/verify-notes-select-all-live.mjs`)
- **THE RULE (one sentence):** Ctrl+A belongs to the thing you are in — the caret's box's text, else every box as boxes.
- **Caret inside a box:** selects that box's text ONLY (never another box). Ctrl+C then copies TEXT (constraint 58: no box payload, no outline, a plain-text paste); typing replaces only that box's words; ONE Ctrl+Z restores them. A second Ctrl+A changes nothing (the key is still consumed so it cannot escape into the page). `lib/notesSelectAll.js`: pure `selectAllTarget` + the `NoteSelectAll` keymap at priority 200 — **the engine's own `Mod-a` is a core keymap that wins an equal-priority race**, so a default-priority keymap would have changed nothing.
- **Table cell (owner: "follow the editor's normal cell/table behaviour first, then the box; don't let it escape"):** 1st press the cell's own text → 2nd the whole table (`CellSelection`) → 3rd the box's text (intro lines + table) → 4th stays. Never another box.
- **No caret in any box — THE CALL, stated in the PR (the brief asked for it): a box selected by its outline, OR blank paper (a single click, or a double-click's armed caret) → Ctrl+A selects EVERY box on the page as boxes (PowerPoint).** Multi-box copy IS supported (`boxesForCopy` takes a set; `pasteBoxCopy` pastes up to 40), so Ctrl+C then copies them as boxes with the moving outline and Ctrl+V makes the same number of new boxes (one Ctrl+Z removes all); Delete removes them all in one step. Clears an armed blank-paper caret and blurs the editor like every other box-selected state. A page with no box, and a focused form field (title, search), keep the browser's own Ctrl+A. `NoteEditor.jsx`: one window capture handler decided by the pure `selectAllScope`; it stops propagation so the keymap and the handler can never both act.
- **Unchanged (asserted):** undo, the paste-options tab, the text-copy path of constraint 58, every other Notes behaviour — `verify-notes-box-copy` 67/67 and `verify-notes-no-overlap` 123/123 run UNCHANGED against this build.
- **Guards:** repo-root `test/` **notesSelectAll** (9: scope decision table, in-box target, table steps); **verify-notes-select-all** under ui-audit/ (a required `build` step in `.github/ci-gates.yml`; real keys + mouse + the system clipboard, judged on the stored document; 42 checks, **19 ✗ on pre-feature main**, 0 on this build).
- **Two traps found building it (carry-forward file):** `formFieldOwnsTheKey` takes a DOCUMENT, not an element — `formFieldOwnsTheKey(document.activeElement)` silently returns false, so the first cut selected all boxes while the title input had focus; and `Selection.between` does not exist (`TextSelection.between`).
