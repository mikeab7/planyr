### B2416496 — NEW-1: Select parcels drew ONE lot outline in Tennessee (Rutherford) — every held lot collapsed onto the key `undefined` `[Site Planner / Map: Select parcels]` (bug) #site-planner #parcels #gis  *(owner chat block 2026-10-22, planyr.io build ff7be38, Epps Mill Rd / I-24, Christiana TN: only the clicked lot 156-026.00-000 outlined, every neighbour blank; Harris TX and Dougherty GA drew everything at the same scale.)*
`[ ]` **⏳ merged — V1849440 PENDING (Verify: live — GIS endpoint behaviour, signed-in test account on planyr.io after deploy).**
- **Root cause (measured in a real browser, not the brief's hypothesis):** the TN source WAS wired with an outline layer and the outline /query DID fire (12 requests, all HTTP 200 with lots). The outline layer keys every held lot by `feature.id` (`layer._layers[gj.id]`). Rutherford's hosted FeatureServer answers `f=geojson` with features that carry NO top-level `id` (only `properties`), so every lot in the view landed on the key `undefined` and overwrote the one before it: the layer held exactly ONE lot (`__mapParcelDisplay().held === 1`). Click-to-identify never reads that key, which is why clicking worked. Not a zoom gate, not a missing source, not CORS, not paging (2 lots per 512-px tile at this density, far under the 2,000 cap).
- **Fix:** `lib/parcelQueryWire.js` `ensureFeatureIds` (+ `geometryKey`) is applied to EVERY answer the worker returns (`parcelQueryWorker.js`, both the geojson path and the esri-json path through `esriResponseToFeatures`): a feature with no id gets its OBJECTID-like property, else a stable geometry hash; a server-supplied id is never touched. One choke point, so every source that answers id-less is fixed at once, not just Rutherford.
- **Audit of the rest (the brief's second bullet):** all 999 non-statewide entries in `COUNTIES_MAP` resolve to an outline source in Select parcels at their own ground (`displaySourcesForView`), so no jurisdiction was missing an outline source; the only defect in this family was the id collapse, now closed for all.
- **Sandbox-verified:** repo-root `test/parcelQueryWire.test.js` (4 new cases: OBJECTID adopted, server id untouched, geometry-hash fallback stable/distinct, 50 id-less lots distinct); ui-audit `verify-select-outlines-tn.mjs` against the dev build: TN Rutherford held **1 -> 74**, TX Harris 481 (known-good arm, unchanged), GA Dougherty 640. Existing esri-leaflet parity suite still green.
