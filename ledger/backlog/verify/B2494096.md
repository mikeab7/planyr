### B2494096 — Notes paste options look and work like Word / Excel's own Paste Options: a bordered "(Ctrl)" tab, a square flyout with our own drawings, and Excel's table set (Values · Values and Source Formatting · Keep Source Column Widths · Transpose · Formatting only · Picture) `[Notes]` (feature) #notes #ui  *(owner chat block 2026-10-29, NEW-1 — "Office-style" approved from a mockup; one correction applied: the clipboard runs full height under every mark)*

**Shipped (one PR).** After a paste that carried formatting a small bordered tab (clipboard · "(Ctrl)" · ▾) sits at the END of the pasted range, where Word puts it; a click or Ctrl opens a square-cornered flyout (thin grey border, small shadow) headed "Paste Options:" with one square icon button per option, Word's exact name + key as a tooltip on hover AND focus, the applied option shown light-blue pressed, the key letter picking it while open, Esc / outside press closing it. **Text paste** → Keep Source Formatting (K) · Merge Formatting (M) · Keep Text Only (T), unchanged behaviour. **A paste that landed a table** → Excel's set under small bold headings: **Paste** K · M · Keep Source Column Widths (W) · Transpose (T) · **Paste Values** Values (V) · Values and Source Formatting (E) · **Other Paste Options** Formatting only (R) · Picture (U). Every pick is ONE undo step and may be made again — each starts from the paste as it first landed (`baseDoc`; `revertToBase` is the smallest exact replace, verified over every pair of documents), so Keep Text Only → Merge → Keep Source never compounds a loss. The right-click Paste ▸ rows carry the same drawings and names. The approved SVG art is used as drawn (`components/PasteIcons.jsx`), with a dark-theme twin for the few ink marks and a halo that follows the surface (`--paste-halo`).

**What each table option means in a Notes table (it has text marks, header cells, a per-cell fill and per-column widths — no formulas / links to a workbook / number formats):** *Values* = the text of every cell, grid + spans + header cells kept, no marks/links/fills/nested blocks. *Values and Source Formatting* = values + text styling + the SOURCE's cell shading, no links. *Keep Source Column Widths* = the source's column widths (px, raised to the table floor). *Transpose* = rows↔columns, merged cells swap spans, a header row becomes a header column. *Formatting only* = on a new table, the grid with the source's shading and no text; on cells pasted into an existing table, the destination cells' OWN text kept and only the source look applied. *Picture* = a non-editable PNG of the table (drawn on paper-white, theme-independent, with the source's header shading) in a box — a box that held only the table becomes a picture box sized to it. A grid pasted INTO an existing table's cells offers K · M · V · E · R; a table that grew keeps K · M. The source's shading and widths are CAPTURED from the clipboard HTML at paste time (`readSourceTables`) — ⛔ **Excel names a cell's fill by CLASS** (`.xl65{background:#DBE5F1}` in the head), not inline, so reading only `style=` missed every real spreadsheet fill; found by driving the committed Excel fixture. The DEFAULT paste (Ctrl+V) is unchanged and still imports neither.

**Scope notes, said loudly.** (1) A table's chip no longer offers **Keep Text Only** (it is not in the approved table set; T is Transpose there) — plain text of a table is still Ctrl+Shift+V and the right-click menu. (2) Merge Formatting on a table with no font/size/colour to merge (Excel's) changes nothing and writes no undo step, as in Word. (3) Undo is an edit, so it retires the offer (an option on a range that changed under it would act on the wrong text) — re-paste to see the chip again. (4) Keep Source Column Widths is offered only when widths were captured (not for tab-separated text).
