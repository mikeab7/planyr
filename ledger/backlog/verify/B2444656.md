- **Report (verbatim symptoms):** past NOTES the leftover width showed dashed lines on every row, the row tints (yellow In Progress / green Complete / red Needs Attn.) and borders stopped at the last column, a click there selected nothing, and a multi-row selection's highlight/outline stopped at the last column.
- **Root cause (measured, not assumed — `ui-audit/verify-grid-strip.mjs`, red on main):** a data row is a flex of fixed-width cells inside a full-width `.drow`; nothing was drawn or hit-testable AFTER the last cell. So the strip showed only the row's own background + its own 1px bottom line, never a cell: no range fill (the `#dbeafe` fill and the `#2563eb` outline are painted per cell), no outline end, no press handler (a press landed on the row div, which has none), and no per-cell line, so the strip's lines were not the same pixels as the cells'. (The "dashed" look is that mismatch — the row's own hairline against cells that each draw their own bottom/right line; on main the strip's range pixels measured `255,223,223` / `248,250,252` against the cells' `219,234,254`.)
- **Fix (`public/sequence/index.html`):** every row type — data rows, review-proposal rows and the empty / "+ New task" rows — now ends with a `[data-grid-strip]` filler: `flex:1 1 0; min-width:0`, so it is the row's exact leftover width, ZERO-width when the columns already fill the pane (no new scroll width, no horizontal scrollbar), and draws the ONE `GRID_LINE` bottom line like every cell. On a data row it also takes the range fill + range line colour, the outline's top/bottom edges, and the outline's RIGHT edge moves from the last cell to the strip's far end when the range reaches the last visible column; it carries the same hover / selected-row outline as the cells (CSS). **A press, drag-enter and right-click on the strip are the SAME three functions the cells use** (`cellMouseDown` / `cellMouseEnter` / `cellContextMenu`, extracted from the cell's inline handlers — one implementation, never a copy), called with the row's last visible column, so a press there selects the row exactly as a press on its last cell does (shift-extend, drag-extend, right-click inside a selection included). The header already continues (its surface and the amber rule span the full width) so it needed nothing; the drop-indicator line already spans the container. Nothing is stored; nothing writes.
- **Adjacent cases checked in the harness:** a column resized (strip re-derives), a group collapsed, the drag-row indicator line to the pane's right edge, Split view's grid pane, a narrow window (strip zero-width, scroll width = the columns' own) and scrolled fully right (the last cell meets the pane edge, nothing blank beyond it). Pinned columns: the strip sits after the pinned-right cells and the sticky behaviour is untouched (`verify-grid-full-lines` 229/229, `verify-grid-row-outline` 158/158).
