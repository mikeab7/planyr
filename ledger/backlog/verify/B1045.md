- `lib/layerSchedule.js` (new, pure) owns the ORDER: what kills a deal first (flood, pipelines), then boundaries, then feature services, then client-computed terrain, then the crowd sources (Overpass, Mapillary) last. Stable — equal-priority layers keep the registry's own order, so the sequence doesn't shuffle between sessions.
- `syncOverlayLayers` gained an `admit` gate that stages only the ADD path. A layer turned OFF is still torn down immediately and a live layer still gets its opacity/width updates, whatever the gate says.
- `SitePlanner` runs pass 0 with nothing admitted (removals + updates only), then widens the admitted set four layers at a time on `requestIdleCallback` — so the map draws and is draggable first and overlays fill in behind it. Staging applies to the RESTORE burst only: once the first pass has admitted everything, a layer the user toggles on by hand is admitted immediately (waiting an idle tick for a chip you just clicked would read as lag).
- Each chip keeps its own honest loading dot (B790), so a not-yet-arrived overlay reads as coming, never broken. No modal, no spinner, no blocked gesture at any point. A layer that lands after a pan requests the view it is ADDED to, not the one it was queued against — every layer derives its bbox from the live map at add time, and the view-driven ones re-request on the next `moveend`.
