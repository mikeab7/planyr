- **Every status group header carries a drag handle**, native HTML5 drag-and-drop, **quiet at rest and shown only on hover/focus** so the header stays uncluttered. **Keyboard-accessible independent of drag**: the handle is a real focusable `<button>`, and ArrowUp/ArrowDown swap it with its neighbor — a drag-only control was explicitly ruled out as not shippable.
- **Default order is untouched** (Pursuit → Active → On Hold → Complete → Dead, today's order) **until the user drags or arrow-keys something** — the stored order is a sparse override (empty = default), so nobody's panel reorders itself on this ship.
- **⛔ Deliberately NOT a settings screen.** Order, collapse (B859504) and pins (B859505) are ONE account-scope preference bag (`lib/userPrefs.js`'s new `sitesPanel` key — `{order, collapsed, pinned, sort}`), following the SAME load-then-commit shape `SitePlanner.jsx`'s Standards feature already uses for its account-scope store (`loadUserPrefs`/`saveUserPrefs`/`commitUserPrefs`), not a new mechanism. **Why one bag and not `lib/layerPrefs.js`'s pattern** (the nearest per-user-preference precedent in this workspace, per the brief's own instruction to check first): `layerPrefs.js` is per-SITE, device-agnostic-by-construction storage on the site model itself — it has no notion of "this account, on any device," which is exactly what pins/order/sort need ("pin a site on my laptop, see it pinned on my phone"). `userPrefs.js`'s account-scope Postgres row (`profiles.prefs` jsonb, RLS-scoped) is the right store and was picked deliberately, not the nearest-looking one.
- **A failed cloud write is LOUD, but only when it's a real failure.** Signed OUT, every arrangement action still applies locally (instant, via the same localStorage mirror `userPrefs.js` already keeps) with no nag — the header's own "Cloud off" chip already says so, and warning on every single click while signed out would be pure noise. Signed IN, a genuinely failed write shows a dismissing "Saved on this computer only — couldn't reach your account" toast (LOUD-FAILURE), same wording pattern as the existing Standards feature's own warning.
