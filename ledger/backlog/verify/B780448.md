- **THE MECHANISM, confirmed via source before writing a line of the fix, exactly as instructed.** `computeDisplayHealth` had no special-case for "this task is marked Complete" — Complete IS `task.health === "green"`, the same field the status pill/dropdown writes (there is no separate flag). The single-task edit path (`updateTask`, `public/sequence/index.html` ~L6316) writes `health` alone; **only the bulk "recolor this whole branch" cascade** (`~L6367`, and its `SuggestionsView.approve()` twin at `~L4814`) also sets `percentComplete:100` as a side effect, and ONLY when descendants exist. So an ordinary single-task "mark Complete" click — the overwhelmingly common case — leaves `percentComplete` exactly where it was. The rule engine's `finishPastDays`/`finishWithinDays` conditions exempt a task via `percentComplete >= 100`, never via `health === "green"` — so once B752848 made the rule list unconditional, any Complete task whose `percentComplete` hadn't independently reached 100 fell straight through to the overdue rule and rendered red.
