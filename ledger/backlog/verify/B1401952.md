The placement RULE is pure and unit-tested (`test/labelCollide.test.js`, 10 tests: active-beats-pursuit regardless of array order, a lost label frees room for a third label with no collision, the padding budget, the owner's own named pair as a fixture) — the Leaflet/canvas glue around it is not unit-testable and is exactly the LIVE-VERIFY gap above.

**THREE — the basemap.** The quiet Esri Gray Canvas basemap was this session's OWN instruction on B1359904, and per this brief it is now treated as wrong, not preserved: `LocationsMapCard.jsx` imports `BASEMAPS.esri` straight from `site-planner/lib/basemaps.js` (Esri World Imagery, `World_Imagery/MapServer`, the Site Planner's own "Aerial" source, native to z19) rather than writing a second literal — so there is exactly one imagery provider in the app, named here for the record. Satellite imagery has no light/dark variant, so the two-tile-layer light/dark swap this card used to do is gone; one tile layer, unconditionally. **Legibility over real photography, not just the old flat basemap:** the blurred text-shadow halo the labels used to carry can't hold contrast against a frame that ranges from near-black water to bright new concrete, so every label is now a solid, opaque `--surface-raised` PLATE (the same "chip over the drawing" shape the Site Planner canvas already uses for setback/dimension chips) that fully occludes whatever imagery is under it — `--text-primary`/`--text-secondary` on `--surface-raised` are already AA-audited in both themes (`src/index.css`'s contrast gate), so this is provably legible in both themes independent of the ground under any given pin. Both dots get the matching halo treatment (a `--surface-raised` ring/fill around the accent color) and comps get a thin `--surface-raised` stroke, all three previously bare against whatever color sat behind them. The four fixed-black drop shadows (never a theme token — a shadow has to read the same regardless of the app's light/dark setting, the same reasoning `MapFinder.jsx`'s own on-map chips already give) are centralized as named constants with `// design-exempt:` comments rather than left inline, both to avoid four drifting copies and because a template-literal HTML line has nowhere to attach an exemption comment without corrupting the rendered markup.
