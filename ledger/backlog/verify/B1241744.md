- **Root cause, and why it read as "doesn't work" rather than "renders oddly":** the header's view-switcher pill (`data.view`) and the render switch that reads it disagreed below 768px width — the pill kept writing and displaying the tapped selection, the body silently kept showing Grid. - **The fix, WIDTH-drives-LAYOUT / POINTER-drives-SIZING throughout (`public/sequence/index.html`):** (1) a `coarsePointer` state (`matchMedia('(pointer: coarse)')`, live-updated) added beside the existing `isMobile` (width<768) state — the two are now genuinely independent axes, matching the governing phone decision's own rule and the B1223120 precedent's `isPhoneSheetMode({narrow, coarsePointer})` shape (replicated inline; this static HTML file cannot `import` the Site Planner's module). (2) The render switch now respects `data.view` at every width — Grid and Gantt render exactly what the user picked, with `data.view` itself never written (still a pure render-time read, the property `test/schedulerEngine.test.js`'s own #4 guards). (3) The Gantt zoom −/+ buttons gained a phone-branch duplicate (the desktop pair lives inside the `!isMobile` ternary and never reaches a phone at all) and BOTH the phone and desktop copies now size on `coarsePointer` (44px) rather than `isMobile` — so the landscape-phone case gets touch-sized controls even though it clears the 768px width threshold, while a standard fine-pointer desktop measures `coarsePointer:false` and renders byte-identical to before (21px, confirmed below).
