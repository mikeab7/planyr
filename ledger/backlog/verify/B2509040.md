- **One source of truth (the design decision, stated plainly).** The Library file IS the document: opening reads the file's latest stored bytes, saving writes the edited workbook back as a NEW stored version of the SAME Library file (`doc_reviews` record + Drive object, the mechanism Word/text files already use — `docVersions.js`), and the upload stays version 1 byte-for-byte. There is no second copy of the workbook in `model_sheets`/`org_model_sheets` for the file to drift from, no migration, no new table. "Open it a second time" therefore reads the saved bytes. Alternatives rejected: importing into the project's one `model_sheets` workbook (a project holds ONE; a second import would replace it) and a per-file workbook table (two copies = the stale-copy class the SINGLE-SOURCE rule bans).
- **Which files save in place:** only a real `.xlsx`. `.xls` / `.xlsm` / `.csv` would lose formatting, macros or formulas if overwritten, so the FIRST save writes a NEW `.xlsx` Library file in the same project/folder (named `<name>.xlsx`), records `spreadsheetCopyId` on the original (metadata only — its bytes and versions are untouched), and every later open of the original lands on the copy with a one-line note. Same precedent as Word's `.doc → .docx`.
- **Autosave coalescing:** the first save of an editing session adds a version (the upload moves into history); later saves in the same session REPLACE that session's own version and delete its now-unreferenced Drive object — the original and every earlier session's final stay. "Download original" in the file bar hands back the untouched first upload.
- **Parsing off the main thread:** a Web Worker (`lib/spreadsheetWorker.js`) now does ALL xlsx work — read, write, old `.xls` — so ExcelJS lives in one lazy bundle (it was the Spreadsheet's main-thread lazy chunk before; this moved it, did not duplicate it) and the existing File ▸ Import/Export also run off the main thread. SheetJS (`xlsx`, already a dependency, used server-side in `functions/api/taxrates.js`) is added to that worker for `.xls` only — no new dependency (CLAUDE.md "Dependency notes").
- **Real bugs found by running real files through it (not by reasoning):** (1) ExcelJS 4.4.0 THROWS on any workbook containing a chart (`Cannot read properties of undefined (reading 'anchors')`) — a good file would have read as "not a valid Excel file". Fixed with a parse-only retry on a copy stripped of drawing/chart/pivot parts (`xlsxInspect.stripNonCellParts`); the saved original is never rewritten from it. (2) A date cell showed its ISO text and ignored its own `m/d/yyyy` format (`sheetEngine.displayFor` only formatted numbers) — fixed, so imported dates read like Excel's. (3) A cell format of "General" (written by SheetJS, so every converted `.xls`) printed the word "General" instead of the value — now treated as no format. (4) SheetJS's xlsx writer emits ISO `t="d"` cells that ExcelJS misreads as the number 2024 — the converter writes serial numbers instead.
- **Never silent:** a banner lists what the file holds that Spreadsheet can't show or keep (charts, pivot tables, pictures, macros, data validation, conditional formatting, cell notes, links to other workbooks, slicers, Excel tables, sparklines, hyperlinks, drawings, multi-row merges, hidden sheets, formulas kept as values) — dismissible per open. A password-protected file, a text file renamed `.xlsx`, a PDF, an empty file, a 0-sheet package, a file over the open ceiling (the Library's own 50 MB `MAX_BYTES`, no new limit), a worker that crashes or never answers — each gets a plain message naming the file and what to do (`FileProblem` panel, never a blank grid or an endless spinner).
- **Entry points:** (a) a Library row click / right-click ▸ "Open in Spreadsheet" (the Shell routes it; `FileBrowser` no longer offers a download-only dead end for spreadsheets); (b) File ▸ "Open Excel or CSV file…" inside the Spreadsheet, which FILES the upload into the Library under the open project/Organization first and then opens it from there — both land in the same place. The open file is remembered per project/Organization (`lib/activeFile.js`) so a reload lands on it; "Close file" returns to the project's own workbook.
- **Safety copy:** unsaved edits are mirrored to an on-device draft (`lib/fileDraft.js`) recording WHICH stored version they sit on; applied only when that version is still the latest, otherwise set aside, never deleted. A very large workbook is not mirrored into the small localStorage tier (TIER-BY-REBUILDABILITY).
