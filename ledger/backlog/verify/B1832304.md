Net-new. **Interpretation, stated:** since B1420 there is no notebook species — the project IS the notebook and "a notebook" in the rail is a page with pages under it — so "copy a notebook" is implemented as copying a page's WHOLE SUBTREE, available on every row at every depth, not as a new notebook concept, per `src/workspaces/notes/CLAUDE.md`'s "do not reintroduce the distinction by the back door".)*

`[x]` **FIX / BUILD.** New row right-click entry **"Make a copy"** (`NotesTree.jsx`, between Move… and Belongs to…) → `Notes.jsx` `handleCopyPage` → `notesStore.js` `duplicatePageTree`. Placement is `notesModel.js`'s new pure `copyPageTree`, which routes the TOP of the copy through `copyPageWithin` so it inherits that op's whole contract unchanged: next sibling, the SOURCE root's project (never the viewer's — "A COPY NEVER CHANGES PROJECT"), "(copy)" suffix, unknown source refused by name. Subpages keep their own titles, carry no project of their own, and every node gets a fresh id. The copy opens, and a notice names what was copied ("Copied the page and its 2 subpages.").
`[x]` **Pictures and files are COPIED, never shared.** `notesMarkdown.js` gains `remapAssetIds` (the write-side twin of `assetIdsInDoc`) and `notesStore.js` gains `copyNoteAssets`, which reads each source blob's IndexedDB record (falling through to the cloud cache path when absent locally), writes it under a NEW id owned by the copied page, and uploads it when signed in. **Why:** `purgePages` clears every asset its body references and `sweepImagesOfMissingPages` clears an asset whose owning page is gone — a copy that shared ids with its source would silently lose its pictures the day the source is deleted forever. The per-notebook picture ceiling (`MAX_NOTEBOOK_IMAGE_BYTES`) is honoured for a subpage copy landing inside an existing notebook. A picture already missing from the source is counted and re-keyed (the copy shows the same broken state) rather than failing the copy.
`[x]` **All-or-nothing (LOUD-FAILURE, B1405008's ordering).** Every byte the copy needs is written BEFORE the tree is handed back to persist; any refused write rolls back the bodies and bytes this call already wrote and names the failure — the rail can never show a copied row with nothing behind it. A source page with no stored body still gets a blank body in the copy.
`[x]` **Unit coverage**, `test/notesCopyNotebook.test.js` (new, 9 cases): placement at the top level and for a subpage, id freshness, purity, refusal; `remapAssetIds` (pictures, files, nested in a box, unmapped ids untouched, never in place); every body copied incl. body-less sources; the copy's picture surviving a forever-purge of the original AND the load-time orphan sweep; missing-picture handling; unknown source; and the all-or-nothing rollback under a real storage refusal. **Red-proven:** writing bodies without `remapAssetIds` turns 2 cases red (the purge case and the re-key case); the MUTATION case pins the defect directly (a shared id is destroyed by purging the source).
