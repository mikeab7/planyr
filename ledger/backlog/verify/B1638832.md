`[x]` **FOUND AND NAMED, per the dispatch's own request, THEN FIXED AND VERIFIED THIS SESSION.** The state that silently chooses a project is `Scheduler.jsx`'s carry-out effect (`shouldAdoptLinkedSiteIntoRoute`, `src/workspaces/scheduler/lib/navState.js`): whenever the route names no project, it reads the embedded scheduler iframe's own persisted, **account-wide** `aPid`/`section` fields — "what schedule was last open," possibly from a different tab, device, or session entirely — and writes that project straight into the URL, on every arrival at a project-less Schedule route, not only the app's genuine boot. `userLeftProjectRef` (the mechanism the dispatch flagged) is real but unrelated — it governs `SitePlannerApp.jsx`'s own resume logic and was not touched.
- **The fix.** `shouldAdoptLinkedSiteIntoRoute` now requires a new, explicit `bootCarryOutAllowed` gate — the SAME boot-resume privilege `SitePlannerApp.jsx`'s `mayResumeLastSite` already grants (Shell's `resumeAllowed` prop, passed uniformly to every workspace with zero new Shell.jsx plumbing) — never assumed true. `Scheduler.jsx` **freezes** that privilege at its own first render (`bootCarryOutRef = useRef(resumeAllowed)`) rather than re-reading Shell's live prop on every render: `mayResumeLastSite` only compares the CURRENT routed projectId against the app's boot-time one, so reading it live would reopen the exact bug whenever the boot itself resolved project-less and the live projectId later cycled back to null — precisely "arrive at a project-less Schedule route later in the session," the case being closed. The privilege is **spent** the instant it's actually used (`bootCarryOutRef.current = false` right after a successful adoption), matching this file's own `userLeftProjectRef` idiom ("the intent is spent once it has been written") — so even a legitimate boot-time adoption never re-fires on a later revisit. A new counterpart, `shouldNeutralizeToReports`, closes the resulting crumb/grid mismatch: when the boot privilege is refused and the iframe is still showing a stale project's grid, the iframe is told to switch to its own neutral, cross-project Dashboard (reports) view (`post({type:"planar:nav-dashboard"})`) instead of silently leaving that project on screen under an honestly-empty breadcrumb.
