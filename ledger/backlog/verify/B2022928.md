### B2022928 — Word and text files open in Review as editable documents, working like Word `[doc-review]` (feature) #doc-review #files #mobile  *(Owner request 2026-10-03 (NEW-1): .docx/.doc/.txt "should also let me interact the same ways as word, like marking editing, txt editing, formatting, review, comments, etc." No measure/calibrate/takeoff wanted. The earlier plan to render Word/txt as flat PDF pages was RETRACTED — not built.)*

`[x]` **What shipped:** opening a `.docx`, `.doc` or `.txt` from the Library row, a dashboard card, Open…/Upload/drop, or a direct `#/markup` link shows a **document editor** (lazy chunk `DocEditor`) in place of the drawing canvas — no measure, calibrate, area, count or takeoff tools on these files.
- **Editing / formatting (Word):** type/delete/cut/copy/paste, undo/redo, find & replace; paragraph styles (Body/Title/Heading 1–3), bold/italic/underline/strike, font + size, text colour + highlight, alignment, bulleted/numbered lists + indent/outdent, tables (edit, add/remove rows + columns, insert), images stay in place.
- **Review:** Track Changes on/off (insertions/deletions shown with author + time; accept/reject one or all), comments (add on a selection, reply, resolve, delete, author + time). **Track Changes shipped in full — there is NO separate follow-up item for it.**
- **Round trip:** Save writes a real `.docx` back to the same Library file — tracked changes as Word's own `<w:ins>`/`<w:del>`, comments as `comments.xml` + `commentsExtended.xml` (replies, resolved). A change/comment made in Word shows on open here. Only `word/document.xml` + the comment parts are rewritten; styles, theme, numbering, media, headers/footers/footnotes pass through untouched, and anything the editor can't model (drawings, fields, bookmarks, equations, page breaks) is carried as an opaque XML atom and written back verbatim.
- **Versions:** every Save stores the new bytes under a NEW source id / Drive key and keeps the previous source in the review record (`sources[1..]`) — bytes are never overwritten, and `purgeReview` already cleans every source. (There is no browse/restore UI for them yet — B2022929.)
- **.doc (97–2003):** opens (text only — the existing `docText.js` reader), a one-line note says Save creates a new `.docx` next to it and the original is kept; Save files a NEW Library record and opens it.
- **.txt:** plain-text editor (undo, find/replace), formatting controls hidden; saves back byte-faithfully (BOM, UTF-16, CRLF/LF, trailing newline kept). "Save as Word document" files a `.docx` copy and opens it.
- **Never downloads:** nothing in the editor creates an anchor/`createObjectURL`/download (source sweep in the open/save suite + a real-browser `download` listener = 0). Saving goes to the Library. Signed out, a Save is held on this device and says so in one line.
- **Phone:** the toolbar wraps and the Review pane stacks under the page; at a 390-wide window `scrollWidth <= innerWidth` for both the Word and text editors.
- **Route + bundle (the "reuse before you build" survey):** the Notes editor is a 5,200-line component welded to Notes' own cloud/anchor/arrow model, so it was NOT reused whole; what IS reused is its Tiptap package set (starter-kit, text-style, table, highlight, text-align, sub/superscript — already shipped, shared vendor chunk). Tiptap has no free tracked-changes/comments extension, so those are three small marks (`trackIns`, `trackDel`, `comment`) + a transaction fix-up (`trackChanges.js`). The docx layer is hand-written on `fflate` (already in the tree via jspdf; now a direct dependency) + a small XML reader — no `mammoth`/`docx` library (neither round-trips tracked changes + comments). Cost: lazy `DocEditor` chunk **67 kB / 23 kB gzip**, loaded only when a Word/text file opens; drawing review's own chunks are not touched by it (CI's bundle snapshot gate reports the exact delta).
- **Adjacent cases (PR table):** PDF opens on the canvas exactly as before (known-good arm of the browser run) · empty `.docx` (valid, no body) opens as one empty paragraph and saves · 0-byte `.docx`/`.doc` is refused with a plain message · empty `.txt` opens as one empty line, saves back to 0 bytes · very large file: the existing 50 MB `MAX_BYTES` cap, plain message, no crash · corrupt `.docx` → plain error, not a crash · file with no project → stored under `project-unfiled` exactly like an unfiled PDF · reopening after save: the source now points at the saved bytes (and `getSourceBytes` serves them), and the saved XML re-parses to the same text/changes/comments (unit test).
