### B2109728 — BACKLOG.md and VERIFICATION.md conflicted on nearly every PR, so finished fixes sat unmerged for days: ledger is now ONE FILE PER ENTRY `[infra / repo]` (task) #infra #persistence  *(Owner chat block NEW-1 2026-10-05, "approved 2026-10-05"; follow-up to B1102688's `.gitattributes` union fix, not a duplicate. DEDUPE-FIRST: B1102688 (union for the GENERATED files), NEW-1/B<PENDING> 2026-09-08 (generated-doc touch guard), B1592848 (`safe-merge`) all treat the symptom per file; none changes the layout.)*

`[x]` **Measured first (not assumed), 2026-10-05, throwaway PRs #2022/#2023/#2024 (closed, never merged):** GitHub's SERVER-side mergeability does **not** honour `merge=union`. Two PRs prepending a different line at the same spot of `docs/archive/BACKLOG-DONE.md` (which has `merge=union` on main) read `mergeable_state: dirty` — and a local `git merge` of the same pair is clean. The control (same shape in `BACKLOG.md`, no rule) was `dirty` too; two PRs adding different FILES read `unstable` (mergeable, checks pending). So a union rule only ever helped local rebases; the only fix that works is a layout where two entries never share a file.
`[x]` **Chosen design — (a), one file per entry, and why:** (b) union-on-the-two-files is refuted above; (c) an append-only per-PR "fragment" file would still need a merge step into the big file. (a) makes the conflict impossible BY CONSTRUCTION: `ledger/backlog/<open|bug-audit|verify|later|done>/B<id>.md`, `ledger/verification/<pending|checklist|done>/V<id>.md`, plus `ledger/<kind>/_frame.md` (the prose/legend/section headings, with one `<!-- ledger:entries <state> -->` marker per section). A lifecycle move is a rename of ONE file. `BACKLOG.md` / `VERIFICATION.md` become GENERATED views (nightly `regen-derived-docs.yml`, never edited by a branch); `docs/archive/*-DONE.md` are gone (served as virtual text for old consumers). Readable by a person: each file is exactly the old block.
`[x]` **Migrated, nothing lost, nothing renumbered:** `node scripts/ledger.mjs migrate` — 1271 live + 1681 archived backlog entries, 927 live + 407 archived verification entries = 4286 files; it re-assembles every old file in its original order from frame + entries and aborts unless it equals the source modulo blank/`---` separator lines, and a post-hoc check re-parsed the rendered views: the SET of (state, block text) is byte-identical to the originals and the frames equal. The 58 legacy cross-file duplicate ids keep their ids (a dup inside one folder is `B<id>.2.md`). Only lost: the archives' batch labels ("## Archived 2026-06-21 …") and the cosmetic `---` separators.
`[x]` **Tooling:** `scripts/lib/ledger.mjs` (the one reader/writer; serves `BACKLOG.md` / `docs/archive/*-DONE.md` as virtual text so `next-id`, `check-mint`, `build-backlog-index`, `verification-queue-audit` and the id-uniqueness tests keep working; ref reads and peer-branch claims read `ledger/` with one `ls-tree` + one `cat-file --batch`), `scripts/ledger.mjs` (`check` · `render` · `move` · `list` · `migrate` · `import-legacy <base> <tip>` for branches opened against the old files).
