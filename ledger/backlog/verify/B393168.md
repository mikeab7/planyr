- **WHAT SHIPPED.** The class travels with the feature from the registry to the badge: `limitClassField` / `limitClassMap` on the registry row → `normalizeFeature` stamps `limitClass` → `cityLimitClass.js` is the one reader (`full` / `limited` / `strip` / `unknown`, never a boolean) → the badge gives limited-purpose and strip their own SLOT and their own noun (`Baytown limited-purpose annexation`), with `City of X` reserved for full-purpose limits. The plain-English gloss is in the popover copy, not the badge (PANEL-BREVITY rule 3).
- **⛔ AND THE BACK DOOR IT CLOSES:** Baytown's layer names all three classes "Baytown", so the city NAME UNION — the set that decides `unincorporated` and feeds the floodplain administrator — is now filtered to full-purpose hits. Without that, the overstatement simply arrives from the other direction.
- **THE GENERALISATION, which is the half that outlives Baytown.** Every city-limits registry row must declare either the field that separates the classes or `fullPurposeOnly: true`. A row that declares neither answers `unknown` and **fails its own fixture** — `test/cityLimitClass.test.js` sweeps `GIS_SOURCES`. It found one immediately: Colorado's `cityCo` row was undeclared, and is now declared with its basis measured (its only class-shaped column, `type`, is `A` ×1637 / null ×273 / `S` ×1 — not a jurisdiction class).
