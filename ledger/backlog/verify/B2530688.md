`[x]` **Fixed and shipped this session; parks in ⏳ Verify only for the signed-in live pass (`V1971824`).**
- **Cause (code reality, AUDIT-FIRST).** `SheetView.jsx` extended a drag from each cell's own `onMouseEnter` — which fires only for cells the pointer actually crosses — and ended the drag on the grid's `onMouseLeave`. So the selection could never grow past the last rendered row, the grid never scrolled, and leaving the grid ended the drag. (The grid is row-virtualised, so even a hit-test on the DOM could never have named an unrendered row.)
- **Fix — one gesture engine** (`SheetView.jsx` `startGesture` / `gestureMove` / `gestureTick` / `gestureEnd`, pure maths in the new `lib/dragSelect.js`): the pointer is mapped to a row/column from **scroll offset + the row/column offset tables** (`cellAtPoint`, frozen-pane aware — never `elementFromPoint`), listeners live on `window`, and a `requestAnimationFrame` loop keeps scrolling while the pointer sits at or beyond ANY edge **even when the mouse is held perfectly still** — down, up, left, right and both axes at once. Speed ramps with how far past the edge the pointer is (`edgeVelocity`: slow just outside, fast far out, capped). The scrollable pane excludes the sticky header band, the row-number gutter and any frozen rows/columns, so a pointer over those counts as past the edge and the anchor never moves. Once the pointer leaves the grid the pointer is **captured** (`setPointerCapture`), so a release outside the browser window still ends the drag and the selection holds. Release ends the loop at once; a `pointermove` with no button held ends it too (no runaway). The same engine drives the **column-header drag** (sideways only), the **row-header drag** (vertical only — row headers did not select at all before; a press now selects the row, like Excel) and the **fill handle** (vertical only). Shift+click now keeps the ORIGINAL anchor for a drag that follows it.
- **Shift+Arrow past the visible area** (the brief asked to check): the scroll-into-view effect only ever tracked the anchor, so Shift+Arrow grew the selection off-screen without following it. Fixed — `revealCell` (the lifted scroll logic) is called for the moving end on Shift+Arrow and Ctrl+Shift+Arrow.
- **Other grids (the brief asked to check, not assume):** the Schedule grid (`public/sequence/index.html` `GridView`) does NOT share this selection code — its mechanism was lifted from there once, then diverged — and has the same per-cell `mouseenter` drag with no edge scroll; Notes tables are ProseMirror `CellSelection`s with their own handlers. Neither is touched here; filed as **B2530690** so it is owned, not forgotten.
