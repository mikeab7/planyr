- **Finding.** `leftPanel` starts at `null` — no panel is docked on first paint. The panels' JSX is correctly gated, but the derivation feeding them was not: the pond stage models, the storage reconciliation, the drawdown, the mitigation band ledger, the administrator, the apron, the cut/fill balance and the `drainage` object literal itself all ran on **every** render, including every frame of a drag, for surfaces nobody had open.
- **The fix is GATING, not memoising — and it is demand-driven rather than a hand-written list of open panels.** `drainFacts()` builds the bundle fresh, **once per render**, the first time a consumer reads it, and caches nothing across renders (a plain `let` in the render body). So a gated value is either computed from this render's inputs or not rendered at all: it is structurally incapable of holding a stale engineering number, which is the only failure mode that would matter here.
- **Why demand-driven and not `leftPanel === "yield" || …`:** a hand-written gate can forget a consumer, and the two non-obvious ones are exactly the kind that get forgotten. `exportCtx()` closes over `drainage` and is called at Download time, BEFORE `exportPass` is set — so a panel-open gate would have silently stripped the stormwater content out of an exported sheet (a PDF-PARITY break with no error anywhere). The pond inspector's `drainage?.floodFailed` is on a selection-driven surface, not a panel at all. Reading the value is what triggers the work, so neither can be missed.
- **All five consumers audited and converted:** `exportCtx()` · `printMetricPairs` · `printStormwaterBars` (PDF-PARITY, both) · the Yield panel prop · the pond inspector. A source guard in `test/renderBudgetMemos.test.js` fails if any bare `drainage` binding reappears at a call site.
