- **THE REPORT.** On Goose Creek "Plan 1 (copy)": double-click a measurement so its Properties menu opens, then single-click empty canvas with no drag. Expected deselect + panel close with the map still. Actual: the map jumps.
- **AUDIT-FIRST — the report's own "what it is NOT" is CONFIRMED.** B1157 (#869, the pointer-move coalescing) is not involved: `3e2370b` never touched the pan path, the pan branch is a direct uncoalesced `setView`, and the only coalesced keys are `cursor` and `geom`. Nothing was changed there.
- **AUDIT-FIRST — the diagnosis is CONFIRMED, and its one stated caveat is now RESOLVED BY MEASUREMENT rather than reasoning.** Three pieces collide: pointerdown on empty canvas fired `setSel(null)` immediately; the very next line captured `ox: view.offX` from the RENDER CLOSURE (correct only while the panel was still open); and the B837 layout effect then correctly rewrote `offX` by −delta as the inspector relinquished the dock and the left column unmounted. The first pointermove — even a sub-pixel one — then wrote `offX = d.ox + travel` absolutely, discarding the whole correction, and the effect never re-runs because the left edge is now unchanged. The load-bearing assumption was that React flushes the discrete `setSel(null)` and its two chained layout effects BEFORE the first pointermove; the brief flagged that as reasoned, not observed. **It is now observed.** `e2e/canvas-click-pan-jump.spec.js` instruments the transform seam across pointerdown → 1 px move → pointerup: pre-fix the canvas's left edge had ALREADY moved (380 → 54) at the moment of the press and `offX` had already been corrected (−266 → +60), and the one-pixel move then put it back to −265 — **a 325 px jump from a gesture that travelled one pixel**, which is what the owner saw and far more than pointer jitter can explain.
- **AUDIT-FIRST — the second finding is CONFIRMED too:** there was no movement threshold before a pan started. `PARCEL_CLICK_SLOP_PX` was used only RETROACTIVELY at release to reclassify a finished gesture as a tap; nothing gated the `setView` write.
- **ALL THREE PARTS SHIPPED, and the honest limit of each is stated:**
  - **(a) THE REAL FIX — rebase a live pan onto the compensated frame.** When the B837 effect folds in its −delta it now subtracts the same delta from any in-flight pan's captured origin, so the gesture and the compensation stay in one frame of reference. This also fixes the GENERAL case the report names — a panel opening/closing or the rail being resized MID-DRAG — not just this click, and it is correct regardless of which way the flush ordering falls.
  - **(b) DEFENCE IN DEPTH — a real dead-zone before the first `setView` write**, reusing `PARCEL_CLICK_SLOP_PX` so the arm threshold and the tap classifier finally agree. Once armed the pan keeps computing from the ORIGINAL grab point, so the drawing stays welded to the pointer rather than lagging it by the threshold. **Stated plainly, as required: this MASKS the instance and does not fix it** — a genuine pan started right after a deselect would still jump by the panel width on the first move past the threshold. It ships alongside (a), never instead of it.
  - **(c) THE DESELECT MOVED FROM PRESS TO RELEASE**, into the tap branch in `onUp` that already carries the slop + duration test — the same reasoning B310 and B735 already apply to their own release-time decisions. Two consequences, both wanted: dragging the map no longer wipes the selection or closes the inspector out from under a live gesture, and the panel reflow is kept out of the gesture entirely, which removes the trigger for (a) in this instance. The panel CLOSING on a genuine background click is intended and is unchanged — only its timing moved, and the spec asserts it still happens.
- **REGRESSION TEST, and why the existing one missed it.** `e2e/panel-toggle-viewport.spec.js` reads this exact seam but toggles panels via the RAIL, so the reflow never overlaps a live pointer gesture. The new spec drives the pointer sequence the report describes and asserts the B837 invariant across it, plus a second case proving a real drag still pans AND keeps the inspector.
