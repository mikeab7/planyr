- **THREE DEFECTS, one report.** (a) A range input does nothing at all with Delete or Backspace, and a closed `<select>` does not either — so the keys went nowhere and the object stayed on the drawing. (b) The dropdown's refusal named *"the box you're typing in"* about a control with no text in it. (c) **The second press was silent**, because the hint is keyed once per episode — so a user who did not catch the first toast experiences a key that does nothing, repeatedly, without explanation. That is the LOUD-FAILURE violation the hint was added to close, surviving inside the hint's own de-duplication, and it is exactly what *"I was pressing delete"* — plural — describes.
- **THE FIX INVERTS THE DEFAULT.** The old rule was "refuse everything, with an allow-list of exceptions" (`allowOnSlider`, added by B746 for undo/redo alone) — the wrong default, because every key a control cannot use has to be added by hand, one bug report at a time. Now each control scope declares the SHORT list it genuinely consumes (`CONTROL_CONSUMES`: a slider takes the arrows; a dropdown takes arrows, Enter, Space, Escape and the type-ahead letters) and everything else passes. **B746/V258's carve-out is not lost — it stops being a carve-out**, because a slider does not consume ⌘Z under this rule either. `<select>` became its own `SCOPE.PICKER` and left `TEXT_ENTRY_TAGS`. A destructive key now explains itself on **every** press; everything else keeps the once-per-episode rule.
- **AND THE LATCH, which is why the fix holds after focus moves on.** The `FIELD` latch outlives the field's focus by design (that is B464048's whole insight) but it was keyed on the ROW — and `data-field-group` marks every value row, including rows whose only control is a slider or a dropdown. Touching one latched *"the user is typing a number"* about a control with no digits in it. A row is a typing row only if it holds something you can type in; the Depth row does, and is unchanged.
- **⛔ THE CONTROLS ARE THE POINT, and they are in the same run.** Narrowing a guard built to stop a Backspace destroying the owner's building is only safe if that defect is re-proven dead: **Enter-, Escape- and Tab-out-of the real Depth (ft) row, each followed by Backspace, all leave the building and its bonded elements untouched (43 → 43 features).** Nothing in this change reaches the text-field scope.
