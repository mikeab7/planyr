- **Root cause (measured, `ui-audit/perf-grading-freeze.mjs` on the owner's Chehaw cross-dock at his screen size, long-frame observer + animation-frame gaps + screenshot latency, known-good 250 ms arm):** **a yield is not a frame.** `runChunked` split the surface build into ~10 ms slices and resumed each through a MessageChannel message — but back-to-back message tasks starve rendering, so the browser drew nothing between them: one mode switch was a **667 ms** frame made of ~60 short `MessagePort.onmessage` slices, zoom steps 100–241 ms; on the owner's larger round-8 build (pit-fill drain lattice) that scales to the reported freeze. No single task was long, which is exactly why every long-task reader — perfcap included — saw nothing. Second, smaller cause: the round-8 drain lattice yielded only every 8 columns (each column ~300 cone searches), so one generator step ran past 100 ms.
- **Fixed:** (1) `runChunked` now waits for a real animation frame whenever the last one is older than `FRAME_GAP_MS` (30 ms) — the slices still run back to back inside a frame's budget, but the page paints at least every ~30 ms; one clock is shared by every concurrent job; a hidden tab never waits on a frame (it would never come). (2) Finer checkpoints in `limitGridSteps` (the drain lattice per 16 nodes, its seed loop, the flood every 2,048 pops, the limit-edge sampling, the earthwork cells) and `contourLatticeSteps` — a checkpoint costs nothing when the slice has time left. (3) `polylineClip` rejects ring edges by bounding box before the crossing math (same answer — the existing-contour clip runs on the main thread). Previous picture stays on screen throughout (unchanged: `useGradeSurface` publishes only a finished surface).
