`[x]` **⏳ merged — V482 PENDING (Verify: live — `Blocker: live-GIS`).** Measured, and narrower than originally filed: toggling all 23 overlays off correctly released **780 of 782 svg elements** and 1,249 of 1,492 DOM nodes — **the vector/feature teardown is already correct and was deliberately NOT touched.** The defect is the raster half: **0 of 51 overlay tiles released**, lingering until an unrelated later pan happened to prune them (497 → 365).
- `lib/tileLifecycle.js` (new) provides `releaseLayer`, now called on toggle-off instead of a bare `map.removeLayer`: it tombstones the layer FIRST, aborts what the layer can cancel, walks a group's children, drops esri-leaflet's painted `_currentImage` (and its DOM node), empties a grid layer's `_tiles` and level containers, and blocks `onAdd`/`_renderImage` so **a request landing after removal cannot resurrect the layer** — which is what left the images behind.
- **The teardown assertion deliberately does not depend on a later gesture.** Per the owner's caveat, `test/tileLifecycle.test.js` asserts `_tiles` is empty and the image is gone IMMEDIATELY after `releaseLayer`, with no pan involved.
- **Pan supersession now genuinely aborts.** The audit the item asked for found the gap: both evidence layers constructed an `AbortController`, but a `busy`/`pending` queue meant a superseded request ran to COMPLETION before the view the user is actually looking at was even requested. Both now abort on supersession. The old note claiming an abort would "poison the shared SWR cache" is wrong and is corrected in place — `gisCache.swr` writes only on success, so an aborted attempt leaves the last-good copy untouched. Both layers also expose `abortPending` so `releaseLayer` can cancel them.
- **Dedupe:** `gisFetch.coalesceRequest` shares one in-flight request between callers asking for the same thing, and reuses a just-finished result for a few seconds so panning back to a bbox you just left is free. Deliberately seconds, not minutes — the long-lived SWR cache is a separate tier and this must not become a shadow copy of it. Failures are never cached; an injected `fetchImpl`, a request with a body, or one carrying its own signal is never shared.
