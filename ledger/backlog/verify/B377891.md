- **THE REPORT.** A second tab of the owner's own account produced ~5 banners naming a collaborator who was never there.
- **⛔ THE MECHANISM WAS NOT THE UID COMPARISON, which is why reading the report literally would have found nothing.** `createNameResolver` already answered *"you (another window)"* for `uid === selfUid`. `selfUid` was **SNAPSHOTTED** from `activeUid()` when the sync engine was built — and that is null until the auth session resolves, so on any load where the planner mounted first it stayed null for the WHOLE plan session. Every row then fell past the comparison to the final fallback, **"a teammate"**, which invented a person out of a missing value.
- **Two changes, and both are needed — fixing either alone still leaves a way to invent a person.** `selfUid` is now a GETTER, read at resolve time, so a late sign-in is picked up. And the fallback is no longer a person: an actor we cannot PROVE is a different account resolves as this account in another tab. A roster MISS on a real team site still resolves as *a teammate* — that one IS a proven different account, and staying silent about it would be the opposite error.
- **The wording is a MODEL fact, not a string.** The resolver returns `{ name, self }` and `toastForSyncEvent` takes `self`, so every attributing row of the matrix has a sentence that names a TAB — *"…was deleted in another tab of yours"* — with no name in it. `self` defaults to TRUE, so a caller that forgets it gets the unattributed wording: wrong in the harmless direction.
- **The same snapshot bug was in `elementSync`'s own `selfUid`**, where it silently disabled B1116's and B1099's foreign-author gates for the session. Fixed in the same commit; it fails open exactly as before when there is genuinely no id to compare.
- **Sandbox evidence.** `test/editorNames.test.js` +3 (incl. the pre-fix construction asserted directly), `test/conflictMatrix.test.js` +3 (every attributing row × both directions, plus the forgotten-`self` default). Full suite green.
