- **⚠ AUDIT-FIRST — THE BRIEF'S DIAGNOSIS WAS WRONG AGAINST THE CODE, and recording that changed what got built.** The dispatch said *"Notes.jsx never reads the current project and renders one global notebook list."* It does read it: `Notes.jsx` has taken `projectId` from the shell since B1290, `NotesTree` has filtered through `visibleNotebooks` since B1290, and a notebook created inside a project has bound to it since B1290. Had that diagnosis been taken at face value, the fix would have been to re-add machinery that already existed.
- **WHAT WAS ACTUALLY WRONG, established against the owner's OWN data before a line was written.** Querying `notes_trees` in production: **2 notebooks, 2 bound, 0 loose** — bound to two DIFFERENT project ids (`smqfy2r7pdec`, `sms7v3ua7ksy`). So walking into any third project showed a correctly-filtered, entirely empty rail that said "No notebooks yet" — which is why he concluded his notes were gone. And **`setNotebookProject` had NO CALLER ANYWHERE** (the B1316 class): a notebook could be bound only by being born inside a project, and once bound could never be re-bound or set loose. There was also nothing on screen naming the scope, so an empty rail was indistinguishable from an empty account.
- **THE RULE IS NOW WRITTEN DOWN, in the store header, because the owner asked for it to be decided rather than inferred.** A LOOSE notebook is visible **everywhere**, from the Dashboard and from inside every project — a scratch notebook you cannot reach from where you are working is one you stop using. A BOUND notebook is visible from its own project and from the ALL scope. Creating inside a project binds by default; creating from the Dashboard is loose. **Every pre-existing notebook keeps exactly the binding it had** — nothing is re-bound, nothing is orphaned, and an absent `projectId` reads as loose.
- **NOTHING CAN BECOME UNREACHABLE, and that is a property rather than a hope.** The rail carries a scope switch — *this project* / *All notebooks* — whenever a project is selected, so a notebook bound to a project you are not in, to a project that was deleted, or to an id that resolves to nothing at all, is **one click from every screen**. `test/notesModel.test.js` states it as a property: for every project (and for none), the union of the two scopes is the entire tree. The empty rail also explains itself now — "your other notebooks are still here, they belong to a different project" with a **Show all notebooks** button — instead of implying the notes are gone, which is the exact screen this item came from.
- **The binding is now VISIBLE and CHANGEABLE.** A notebook row shows where it lives — "Loose", or the project's name when that is news rather than a repeat of the header (PANEL-BREVITY) — and the row's context menu (B1367) gains **"Belongs to…"**, an inline panel in the row's own style listing Loose / this project / every project, with the current one marked. No dialog box (house rule). The project you are standing in is offered even when the project list has not resolved it, so filing a note here never depends on a lookup succeeding. A binding whose project no longer resolves is shown AS ITSELF rather than dropped — you cannot change a state you cannot see.
- **Scope is never sticky:** entering a project resets to that project, which is the literal ask. Search obeys the same scope as the rail (widen it and a mis-filed note is findable; narrow it and it answers the question you asked). Binding a notebook AWAY from the project you are looking at widens the scope automatically, so the move reads as a move and not as a disappearance.
- **NO SCHEMA CHANGE, AND THE ROUND TRIP IS ASSERTED RATHER THAN ASSUMED.** The binding rides in the tree blob, which is already what syncs. `test/notesSync.test.js` (+4) pins `mergeTrees` carrying it: bindings on both sides survive, a loose notebook stays loose, the LOCAL binding wins for a notebook on both sides (rule 3, same as its title), and re-binding here while the other device adds a page keeps **both**. The headless run additionally reloads the app and re-reads the binding out of storage.
