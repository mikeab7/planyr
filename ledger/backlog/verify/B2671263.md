### B2671263 — A map image layer's request failing AFTER the layer lost its map throws "removeLayer of null" (cross-user, recurring) `[site-planner / layers]` (bug) #site-planner #gis #layers #testing  *(weekly "where people are working" sweep, 2026-11-12; `public.client_errors`, read-only: 2 users in the week to 10-30, again 2026-11-06 19:07 UTC, stack `_overlayOnError → fire → i.P` in `map-vendor`)*

`[x]` **ROOT CAUSE REPRODUCED in a real browser, not read off the source.** esri-leaflet 3.0.19 `RasterLayer._renderImage` wires `onOverlayError = function () { this._map.removeLayer(image); this.fire("error"); … }` with NO `this._map` guard (its sibling `onOverlayLoad` has `if (this._map)`). Any dynamic / image-export layer whose `<img>` request fails after the layer lost its map throws inside Leaflet's event loop. TWO doors lead there, both reproduced: (1) the row is switched off (or the plan switched) while the /export is in flight; (2) the likelier production path — a failing image on a layer routed through the same-origin cache relay makes `wireRasterStatus` swap it for a direct-to-agency layer, which REMOVES the proxied layer under its pending image (the row never moved). e2e on 2b1e4b7: both arms threw `Cannot read properties of null (reading 'removeLayer')` ×2.
- **Fix (vendor untouched, `lib/parcelOpacityGuard.js` — the existing `_renderImage` seam, NOT a second wrapper):** one shared `install()` owns the single `_renderImage` wrapper per layer; right after the stock call it finds the Overlay that call added (a `layeradd` listener held for exactly that call, O(1), no scan of the map's layers), drops esri's unguarded "error" listener and registers an equivalent that removes the image only if it is still on a map, fires the layer's "error" (status wiring still hears it) and drops the pending load listener. `guardRasterOpacity` (parcel layer) now includes it; new `guardRasterErrors` is the error-only entry that `layers.js` applies at all three raster constructors (`EL.dynamicMapLayer` ×2, `EL.imageMapLayer`).
- **Guards:** repo-root `test/` **rasterErrorGuard** (8 — a stock-faithful fake incl. the unguarded line; control arm shows the stock handler throws; `_map = null` + error → no throw, "error" still fired; one wrapper per layer) · **rasterTrackerTeardownGuards** (every `EL.dynamicMapLayer(`/`imageMapLayer(` in `src/` sits inside a guard — a new constructor cannot skip it); e2e **raster-error-after-off** (both doors, held-then-500 `/export`, VOID unless the request was in flight; red on 2b1e4b7, green now).
