- **THE RULE, recorded in `docs/perf/PERF-BUDGETS.md`:** *a feature that breaches a budget ships with a matching optimization, or it does not ship.*
- **Ceiling vs target (the honest answer to "commit today's numbers or the aspiration?").** Every metric carries BOTH. `ceiling` = today's measurement + headroom → green on day one, red on a real regression, attributable to the PR. `target` = where it should be → reported as `⚠ ABOVE TARGET` on **every** run, naming the backlog item that owns closing it. A single budget set to today's number is unbreachable and meaningless; set to the aspiration it is red from day one and gets ignored. Currently above target and reported as such: `frameMedianMs` (20 vs 16.7), `frameP90Ms` (80 vs 33), `aerialTileRequests` (221 vs 120), `siteRouteJsBytes`, `largestChunkBytes`.
- **Deliberate scope call — only the DETERMINISTIC half gates CI, and this is stated loudly rather than quietly dropped.** Bundle weight falls out of the build with no browser, network or CPU contention, so a breach is unambiguously the PR's fault. Frame time and heap on a shared `ubuntu-latest` runner are dominated by co-tenant load; gating merges on them yields flaky reds, and flaky reds train people to re-run until green — worse than no budget. The aerial metrics additionally need live tile hosts the sandbox blocks. So `perf-bundle-audit.mjs` is a required build step; the runtime harness runs on demand and before shipping render/load work. `docs/perf/PERF-BUDGETS.md` records that the honest way to gate the runtime half later is a pinned self-hosted runner.
- **All three measurement blockers designed around, and documented so nobody re-learns them:** (1) the 250-entry resource-timing buffer fills during load and then **silently** drops entries — the harness calls `performance.setResourceTimingBufferSize(3000)` in an init script, the only place early enough; (2) cross-origin tiles carry no `Timing-Allow-Origin` so `transferSize` reads 0 — the tile budget counts **requests issued**, never summed bytes, which also keeps it meaningful where tile hosts are blocked; (3) `measureUserAgentSpecificMemory()` is unavailable (no cross-origin isolation) so tab memory is **not measurable** — `peakHeapMB` is JS heap only and says so in the budget note, the docs, and the harness header (the owner's ~555 MB tab vs 134.6 MB JS heap means ~420 MB is invisible here). Chrome also quantises `performance.memory` without `--enable-precise-memory-info`, which the harness passes.
- **TTFD defined here, as instructed — 328 ms was NOT treated as TTFD.** Definition: navigation start → the canvas exists **and** has demonstrably serviced a pointerdown/move/up with a committed frame, i.e. the first instant real work is possible. It is recorded as `measured: null` with a `localFloor`, **not** given a fabricated production number.
- **Reference scenario is a documented STAND-IN.** Sylvestri / Concept C is signed-in real data the sandbox cannot reach. `e2e/fixtures/sites/dense-testfit` was tried first and is the wrong source — it carries the pure-engine `x`/`y` geometry schema and crashes the live render path. The committed stand-in is deterministic and fixed-origin but **lighter** than Sylvestri, so its numbers are a floor — which is exactly why ceilings are seeded from the owner's production figures, not from a local run. (Trap found and documented: element types resolve through `dockZones.js`, so an invented type id crashes the workspace on `ZONE[e.type].label` — there is no `truckCourt` type; a truck court is `paving`.)
- **Load timings are refused, not faked.** `index.html` pulls the Inter webfont via a render-blocking `<link rel=stylesheet>`; where egress is restricted that hangs and drags FCP from ~330 ms to ~13 s. The harness detects failed cross-origin requests and reports load-sensitive metrics as **MEASURED BUT NOT JUDGED** instead of as a breach — a budget that cries wolf is ignored as fast as one that never fires.
