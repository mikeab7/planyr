- **(a) THE SURFACE.** `shared/storage/StoragePanel.jsx` reports `navigator.storage.estimate()` (with `usageDetails` and `persisted`) plus a localStorage byte census, **by class with sizes** — Saved plans · Version history · Map data · Drawings & notes · Settings — each with a meter, and a **Clear map data** action for the classes that re-fetch. It opens from the **plan menu, beside Save now and Version history** — the two things it explains when a save fails — and it is reachable **signed out**.
- **(b) THE TELEMETRY.** Every storage-failure event (`save-verify-failed`, `save-both-failed`, and the new `device-save-still-full`) now carries the same figures, so the NEXT occurrence reports usage vs quota **per tier** instead of only that a write failed.
- **⛔ BOTH TIERS ARE REPORTED SEPARATELY AND NEVER SUMMED**, in the UI and in the telemetry keys (`local_*` / `idb_*`). They have wildly different ceilings (~5 MB vs ~10 GB) and conflating them is exactly the error the first diagnosis made: a combined "4 MB of 10 GB" reads as 0.04% full while the store that matters is at 78% and about to throw. `storageSnapshot()` returns two objects and there is deliberately no combined total anywhere — asserted directly (`expect(Object.keys(snap)).toEqual(["local","idb"])`).
- **⛔ WHERE THIS CODE LIVES IS A BUNDLE DECISION, AND IT COST FOUR BUDGET BREACHES TO GET RIGHT.** Two separate traps, both worth knowing:
  - **(i) A module shared between chrome and the planner's boot path is HOISTED into a chunk every route downloads.** Importing `gisCache` from the panel put **11.3 KB on a plain Site load** and broke the site-route allowlist, the route chunk count AND the Notes route; splitting it out left a **100-byte** registry shim that STILL showed up as an unexpected route chunk. `shared/storage/` therefore imports **nothing** from a workspace — `originStore.js` is a dependency-free IndexedDB accessor, the map cache is cleared by NAMESPACE, and the live cache hears about it through a window event. `SitePlanner` reaches the reclaim tier by **dynamic** import for the same reason.
  - **(ii) EVEN A LAZY STUB IS NOT FREE IF IT SITS IN THE ENTRY CHUNK.** The panel was first mounted in `AuthPanel` (account → Settings) and the signed-out ⚙ `SettingsMenu`. Both land in the shared entry chunk, so those two `lazy()` stubs cost **+0.8 KB on all four routes** — and CI measured `bundle.notesRouteJsBytes` at **620.2 KB against a 620.0 KB ceiling: a real breach, 0.2 KB over**, on a route this feature has nothing to do with. **Paid back with an optimization, not a raised baseline** (the repo rule, and the owner's "do not raise a ceiling"): the panel moved to the **plan menu on the Site route**, which costs the other three routes nothing, keeps it reachable signed-out (the account panel is not), and puts it beside the Save now / Version history it explains.
- **Bundle cost after the relocation, measured against this branch's own base build:** **Notes route +0.0 KB** (619.1 KB, exactly the base) · Site route **+5.2 KB** (15 KB of band left) · total JS **+19.3 KB** · largest chunk **+3.9 KB**. Audit green. The Notes route's 31.1 KB of above-baseline growth predates this change entirely and is untouched by it — someone should ratchet that metric deliberately, with the item that caused it.
