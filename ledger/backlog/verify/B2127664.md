- **Mapping.** text box → FreeText · callout → FreeText callout (`/IT /FreeTextCallout /CL [tip knee box-edge] /LE /ClosedArrow`) · line → Line · polyline → PolyLine · rect → Square (rotated → 4-vertex Polygon) · ellipse → Circle (rotated → 72-gon Polygon) · polygon → Polygon · revision cloud → Polygon + `/BE /S /C` with its real vertex ring · measurement: 2-pt → Line, path → PolyLine, area → Polygon (number kept in `/Contents` AND drawn in the appearance), **count → Stamp** (no native subtype).
- **How parity is made structural (PDF-PARITY).** The geometry comes from the exported SVG clone itself (`annotationExtract.js` lifts the annotation nodes out AFTER `restyleExportClone`, so print stroke weights, label sizes and hidden groups are exactly what the flattened sheet draws), and `pdfAnnotations.js` re-draws those primitives as the appearance stream — no second render path. Coordinates: clone units → page points through the same "meet" fit `sheetFitScale` uses (works for Fit-to-frame pages). `/Rect` and the appearance `/BBox` are clipped to the plan window, like the flattened clip; a markup wholly outside it is reported (not drawn, as before).
- **STATED DEVIATIONS (read before assuming more).** (1) **Fonts are the base-14 Helvetica family, NOT embedded/subset** — the planner has no TrueType file to subset (only woff2) and the PDF writer is dependency-free; viewers carry Helvetica natively so nothing substitutes, and each line is `Tz`-squeezed to the width the browser measured for the on-screen face, so extents match; glyph SHAPES differ from the on-screen face by design. (2) Prime marks `′ ″` are written as `' "`; characters with no stand-in become `?` and are reported. (3) A callout with several leaders carries ONE native leader (`/CL`), the rest are drawn in the appearance only (reported). (4) A rotated callout keeps its rotation in the appearance, not in `/Rotate`. (5) Hatched fills are a tiling pattern in the appearance only. (6) Markups sent BEHIND plan content (`behindEls`) paint above it in the editable file (annotations always sit above page content; spec: "markups sit above all base content"). (7) Easements, encumbrances and utility routes live in the `markups` array but are SITE DATA — they stay page content, like parcels. Every degraded item is surfaced in a banner (LOUD-FAILURE), never dropped.
