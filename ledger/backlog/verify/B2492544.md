### B2492544 — KML/KMZ import: the comp title is always the placemark's name, never words from its description `[comps / KML import]` (bug) #comps #model  *(Reported by the session that shipped B2345504/B2345505: one test import came out titled "Lease". Owner decision 2026-10-29: the KML `<name>` is the one reliable field in the format, so it always wins. DEDUPE-FIRST: sibling of B2010355 (paste-line lead-title), not a recurrence — that fix is about the paste grid.)*

`[x]` **Cause (reproduced on main, not guessed):** `placemarkToDraftRow` set `title = parsed.draft.title || placemark.name`, so any title the description parse derived beat the name. A one-line description opening with a bare deal word segment — `Lease, 50,000 SF …`, `Sale, 3.2 AC, $850k` — hands that first fragment to `extractUnlabeledLine`'s lead-title path ("Lease"/"Sale"), and an address-looking line (`123 Main St, Houston`) did the same. Multi-line `Type: Lease<br>…` descriptions never hit it, which is why the 2026-10-16 34-placemark import was clean.
`[x]` **Fix:** one rule, `compDrafts.resolveImportTitle(name, derived)` — the decoded, trimmed `<name>` when non-empty; else the description-derived property/address title unless it is a lone deal-type word (`isLoneDealWord`: Lease, Sale, Land Sale, For Lease, Sold …); else blank. `kmlImport.placemarkToDraftRow` uses it (KML and KMZ share the path). `draftTitleFor(draft)` re-applies it from the draft's own `rawName`, and the import-review card now seeds its fields from it and shows a **Title** field, so the title is visible in review and is what promote saves — a draft staged before this fix with `proposed.title = "Lease"` reads and promotes right too. Description text is still read for deal terms exactly as before. No existing comp is touched (drafts only).
