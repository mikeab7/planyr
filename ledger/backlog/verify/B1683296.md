- **THE RACE, measured directly.** A box that is open but never typed into (created either by the sketch's own "+Box" button/an empty-canvas double-click, uncommitted, OR by the note toolbar's "Box" command, which commits an empty box immediately and just opens an editor on it — Michael's own report used this second path) is DISCARDED the instant the label field loses focus, on the very FIRST press of any subsequent click — this is unconditional. Its replacement, before this fix, existed ONLY inside `onDoubleClick`, gated entirely on the browser recognising a native `dblclick`. Two real, separately-dispatched presses 900ms apart (`page.mouse.down()`/`.up()`, twice, with a 900ms gap) never raise a native `dblclick` at all (confirmed via a `window.addEventListener("dblclick", ..., true)` counter reading exactly 0) — so the box vanished on press 1 and nothing ever replaced it on press 2, reproducing the report's own "1 → 0, no new box, nothing focused" symptom exactly, on a REAL browser with REAL trusted input, not a synthetic artifact.
- **THE FIX (`beginBox`, `notesSketchEditor.js`):** an untouched box already open (empty label AND body, committed or not) is RELOCATED to wherever the next press on the bare canvas lands, instead of being discarded and waiting for a `dblclick` that might not come. A committed box's move writes straight through `handle.commit` (it is already real, in the document); an uncommitted box's move stays a local preview, exactly as before. This closes the race structurally: a SINGLE press is now already enough, with no dependence on the browser's own double-click timing window at all. `onPointerDown` routes a press on the bare canvas through the same `beginBox` the moment an untouched box is open, ahead of the generic "close what's open" branch that used to discard it unconditionally.
- **WHICH OF THE TWO PRODUCT CHOICES THE TICKET LEFT OPEN, AND WHY:** the untouched box is KEPT (relocated), never discarded, on a subsequent press — this is what makes the fix depend on nothing but the press itself, and it costs nothing: it is still uncommitted-until-typed for the never-committed case, and a committed-but-empty box already had a real remove-on-close path (`closeEditor`) untouched by this fix for every OTHER way of abandoning it (clicking away into the note body, Escape, a different box).
