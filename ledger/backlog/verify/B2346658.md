### B2346658 — Editing a lease comp wiped its OpEx: `lease_opex` was never selected back `[comps]` (bug) #comps #persistence  *(Owner block 2026-10-19 NEW-3; V630992's "lease detail card does not list OpEx row" was this bug being observed. Minted from the reserved block. DEDUPE-FIRST: net-new; B1629617 is the unrelated no-concurrency-guard item.)*

`[x]` **Cause:** `compToRow` wrote `lease_opex` but `SELECT_COLS` (and the trash list) never read it, so `rowToComp` always yielded `leaseOpex: null`; opening any lease comp and pressing Save wrote that null over the stored value. **Fix:** `lease_opex` selected beside `lease_ti` (so insert / update / insert-many `.select(SELECT_COLS)` return it too); `SELECT_COLS` exported; `test/compsStoreColumns.test.js` asserts the select list contains **every column `compToRow` writes** (red when `lease_opex` is removed — proven — and so a column added later cannot recur this) plus the row → comp → draft → comp → row round trip.
`[x]` **Damage report (read-only query against production, 2026-10-19):** 41 live lease comps, 40 with a null `lease_opex`; **39** of those were edited after they were created (`updated_at` > `created_at` + 1 minute), and only 1 live lease holds an OpEx at all. That 39 is an UPPER BOUND on comps whose OpEx the bug may have erased — a comp edited for another reason that never had an OpEx is in it too. Nothing was restored (not attempted, per the block).
