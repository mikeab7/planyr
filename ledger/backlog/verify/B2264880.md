### B2264880 — No way to open or edit a parcel's properties; setbacks unreachable (double-click inside a lot did nothing, every menu landed on the list) `[Site Planner › Land › Parcels]` (bug) #site-planner #parcel
- **Owner report 2026-10-14 (verbatim gist):** "I don't have a way to edit my parcels' properties right now. I don't even know how to set the setbacks. If I double-click the parcel it doesn't really do anything. Same from the Parcels menu. This is a big issue."
- **AUDIT-FIRST — what the code actually did (measured in a real browser on the pre-fix build, all four e2e tests red):** the parcel's own page (`components/ParcelPage.jsx`: record · setbacks · style) existed since the Parcels rework (B2179968), but nothing on the map led to it. (1) A lot's INTERIOR is click-through by design (B420 — only its line grabs), so a double-click inside a lot resolved to NOTHING. (2) Every entry point that did reach the parcel called the pre-rework `openParcelPanel`, which docks the Land panel on the parcel LIST: a double-click on the line, the Parcel tools "Setbacks and settings" row, and a click with the list open. (3) The right-click parcel menu had no way in at all. (4) On a phone with nothing docked, a double-tap returned early and did nothing (B556 guard applied to a deliberate open).
- **Fix:** ONE `openParcelPage(id)` in `SitePlanner.jsx` (selects, opens the page, docks Land — phone included; never arms a boundary edit). Callers: `featureDoubleAction` (parcel), the list row (`onOpenPage`), Parcel tools row (renamed **Properties** — "Setbacks, style and record"), right-click menu (new first row **Properties**), and a click on a lot's line while the Land panel is showing (the page follows the selection). New pure `lib/parcelAtPoint.js` (smallest live lot containing the point) is the fallback for a double-click/double-tap on empty land inside a lot — at the canvas root (`onBgDouble`) and as a touch double-tap in `onBgDown`. A SINGLE click with the Land panel closed still only selects (B750 — the rail never swings open on a click). `openParcelPanel` is deleted.
- **Adjacent cases, each driven in `e2e/parcel-properties-reachable.spec.js`:** map dblclick inside / on the line · single click with Land open (from the list and from another page) · single click with Land closed (selects only) · list row · Parcel tools · right-click · locked (opens AND the setback edits) · not active · inside Edit parcels · combined tract (shows "Made from", never "Drawn by hand") · phone width with a real touch double-tap · opening never lets the lot be dragged. Persistence: one section's setback → reload → value and the drawn setback line still there.
- **Guards:** e2e **parcel-properties-reachable** (4 tests; red-proven: all 4 fail on the pre-fix build); repo-root `test/` **parcelPropertiesReach** (pure rule + source guards that every entry point goes through `openParcelPage`); **setbackSketch** gains the owner's real Grand Port ring (`test/fixtures/grandPortParcel.json`, boundary only) — distinct value per section, no two labels overlap; `parcelActions` + e2e `parcel-tools-menu` updated (both encoded the list-not-page behaviour).
- **Not changed, on purpose:** the page's line style stays an on/off "Dashed" switch — owner constraint #23 says "dashed on/off" and rules out a dash-pattern picker, which beats the dispatch brief's "plain dropdown".
