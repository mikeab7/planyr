- **THE DEFECT.** The app's only real hydrology + hydraulics derivation — `screeningBfe.js` + `screeningBfeSite.js` + `upstreamArea.js` + `channelSection.js` — runs in exactly ONE place: `checkDrainage`'s async block, gated on an unstudied Zone A site with no published or manual 1% surface. Every byte of it was nevertheless on the Site route's critical path, downloaded on every load of every site, because a handful of CONSTANTS and three pure COPY functions were exported from the same modules and are read by the RENDER BODY. **A static import of one export pulls the whole module** — tree-shaking drops unused exports, never an export a sibling still uses — so the render body's need for `screeningBfeHeadline` was enough to hoist the entire engine.
- **THE FIX** is the `terrainGate.js` / `terrainLazy.js` shape already used twice in this folder: a dependency-free LEAF (`screeningBfeCopy.js`) holding the words, the constants and the acres/lots threshold test, with `screeningBfe.js` / `screeningBfeSite.js` re-exporting all of it so **no importer changed**. `SitePlanner.jsx` keeps the leaf statically and reaches the MATH through `import("./lib/screeningBfeSite.js")` inside `checkDrainage`.
- **MEASURED, before → after:** `siteRouteJsBytes` 2471.0 → 2457.7 KB · `largestChunkBytes` 1554.3 → 1541.0 KB (**−13.3 KB each**) · 43.6 KB of source moved into its own lazy chunk · `totalJsBytes` 4969.9 → 4970.7 KB (**+0.8 KB of chunk overhead — splitting moves bytes, it does not delete them**).
- **NO WALL-CLOCK COST on the branch that uses it:** the engine's `import()` is started BEFORE the `await` on the three data pulls it needs and awaited only at first use, so the module download overlaps network round-trips that were already happening. A failed chunk fetch rejects at that await and lands in the existing `catch`, reporting the named LOUD-FAILURE "could not run" state like any other outage.
- **THREE THINGS NOT TO UNDO** (all three re-open the defect while lint, tests and build stay green): the leaf may never import the engine or anything that does; the constants in `screeningBfe.js` are IMPORTED-then-re-exported rather than forwarded with a bare `export … from`, because its own functions reference them in scope (the trap `titleReader.js` documents); and `floodplainMitigation.js` — also on the boot path — takes its two constants from the LEAF, never from the engine.
