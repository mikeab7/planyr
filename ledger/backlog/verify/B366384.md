- **THE REPORT, verbatim.** *"when I tried to share 8 South it gave me this pop up at the bottom left, which is obviously not true because it's been in cloud for weeks, if not a month already."* The popup: *"This project isn't in the cloud yet — open it once to sync, then share."*
- **GROUND TRUTH (read from production, not assumed).** `8 South` = group `smqiljx5fngg`, **version 587**, `team_id` already `454aa114…` (team **HIP Houston**, 3 members). Exactly **2 of 34** projects carry a team: 8 South and RICHEY (`smraxmrwiyzk`). So the project was both unambiguously in the cloud AND unambiguously already shared.
- **THE MECHANISM.** `set_project_team`'s UPDATE carries `and team_id is distinct from p_team_id`, so re-sharing to the team it ALREADY has legitimately writes **0 rows** and returns 0. `MapFinder.doShare` read that as `if (teamId && r.sites === 0) → "isn't in the cloud yet"`. **"0 rows changed" is not "0 rows exist"** — and the message therefore fired precisely in the case where it was most wrong.
- **AND IT WAS WORSE THAN REPORTED: on this database that string was UNREACHABLE-WHEN-TRUE.** The genuine not-in-cloud case never got as far as the `return` — the RPC raises `No project of yours with that id.` first. So post-migration a 0 could only ever mean *already in that state*, and the sentence was false **100% of the time it was shown**.
- **THE CODEBASE ALREADY KNEW THIS IDIOM BITES.** `storage.js` documents that `cloudDelete` returning `removed:0` means **RLS REFUSED**, not "nothing was there". The share path never got the same care; it does now.
- **THE FIX — three answers at the source, no integer for the caller to interpret.** New RPC `set_project_team_state` (`db/team_share_state.sql`, **applied to production 2026-08-11**) returns `{outcome: not-found|changed|already, matched, changed, already, plans, foreign, mismatched}`. `lib/sharing.js` normalises all three tiers (state RPC → the older integer RPC, which RAISES for not-found so a 0 from it can only mean `already` → the pre-migration direct UPDATE, the one tier where 0 really does mean none exist). `doShare` branches on `outcome`; **only `not-found` may show that message.**
- **VERIFIED ON HIS REAL ROWS**, impersonating the owner, writing nothing (all three answered `changed:0`): re-sharing 8 South to its current team → `outcome:"already", matched:1, mismatched:0` (was: the false popup) · a non-existent group → `outcome:"not-found", matched:0` · Goose Creek (4 plans) private→private → `outcome:"already", matched:4, plans:4`.
- Guards: repo-root `test/` suite **shareMirror** (18 — incl. a mutation check that `r.sites === 0` is gone from `doShare`, and that the message's nearest enclosing condition is the `outcome` test).
