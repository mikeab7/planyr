- **TWO DEFECTS, FIXED AS TWO. (a) DEFAULT.** Dock doors are now an `opts` flag, `includeDockDoors`, **default OFF**, on the `includeDimensions` precedent sitting three lines below it — which has been default-off since B684 with the comment *"they clutter a 3D walkthrough"*. Same judgement, now applied consistently. There is no UI for it, exactly as `includeDimensions` has none; both KMZ call sites (the planner's File menu and the map viewer's multi-site export) state `includeDimensions: false, includeDockDoors: false` explicitly rather than defaulting into it.
- **(b) THE COUPLING, WHICH IS THE PART WORTH KEEPING.** The gate was `settings.showDocks !== false` — the **View ▾ canvas checkbox**. A drawing-legibility preference was deciding the contents of a file built for a different audience, so turning dock doors on to check a layout silently changed what an exported KMZ contained. Worse in the map viewer: that export reads each SAVED site's own settings, so a multi-site file varied with what someone happened to have shown on screen when they last saved plan #3. `kmzExport.js` now reads `settings` only for MODEL facts (door o.c. / width, building rules) that determine where a thing physically IS.
- **REPRESENTATION: ONE RUN PER DOCK SIDE**, as the owner suggested — a line from the outer face of the first door to the outer face of the last, named `Dock doors — 12 @ 12′ o.c.`, so the count and the spacing survive without the pins. A side carrying a single door still gets a real line (one door wide), never a degenerate zero-length one.
- **⛔ THE CLASS AUDIT THE OWNER ASKED FOR — "check whether any other export feature reads a canvas display setting the same way."** Every export path in the workspace was swept for the six View ▾ toggles (`showDocks` · `showGrid` · `showDims` · `showAreas` · `showSetback` · `parcelSelect`) plus the two drafting aids (`snap` · `gridSize`). **The dock doors were the ONLY instance.** `printSheet.js` · `imagePdf.js` · `overlayVectorSvg.js` · `sheetFurnitureLayout.js` · `exportStyle.js` · `exportLabelScale.js` · `measureSheet.js` are all clean and are now PINNED clean by a source sweep, so the next model-built export cannot reintroduce the coupling quietly.
- **THE ONE DELIBERATE EXCEPTION, stated rather than left to be rediscovered:** `exportSheet.js`'s PDF/PNG path CLONES the live `<svg>`, so it inherits every display toggle by construction. That is **not** the same defect — the sheet is the drawing on paper for the SAME audience, and the user sets those toggles while looking at the very drawing they are printing. (`measureSheet.js` holds that path's own rule: an export is a document, not a screenshot, so ZOOM gates are lifted on the sheet while display toggles are honoured.) `exportJSON` writes `settings` wholesale because it is a save file that round-trips — also not a content decision.
