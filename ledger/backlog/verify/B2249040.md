`[ ]` **⏳ merged — V1676224 PENDING (Verify: live — zoom-dependent rendering / registration; sandbox half done, signed-in half runs after deploy).**
- **Root cause:** `SitePlanner.jsx` built only the two AERIAL tile layers (coarse + detail); nothing ever mounted a label layer, and `LayerPanel`'s `placeNames` prop was never passed, so the Road names row did not exist on the canvas.
- **Fix:** the planner's slaved Leaflet basemap now mounts the SAME `addVectorLabels(L, map, { mode: "site", includePois: false })` helper the finder uses (lazy `import()`, so MapLibre never rides the planner boot chunk), gated by the SAME `siteStack(zoom, { roads }).includes("roadNames")` on the committed backdrop zoom. The pane (`planyrVectorLabels`, z 250, pointer-events none) lives INSIDE the Leaflet map pane, so it rides the basemap's own transform through panBy / setView / panel re-centre, sits above the aerial and under the plan SVG (every element, markup and overlay paints over it). Aerial Off ⇒ no labels. `LayerPanel` gets `placeNames={{ value, onChange, opacity, onOpacityChange }}` so the Road names row + opacity slider appear under the aerial source; default ON at the finder's opacity.
- **Persistence decision:** DEVICE-LEVEL pref (`lib/roadNamesPref.js`, key `planyr:roadNames`), NOT per-site `layerOverrides` — that map is booleans only and read by undo/merge/cloud code, and a numeric opacity for a reference label would be a new site-model field for a presentation taste. Per-viewer convenience, guarded, defaults when blocked.
- **VIEW-INDEPENDENT-ONCE:** the layer is created once per (gate, origin) change — `roadsOn` is a boolean off the committed zoom, nothing runs per pan frame. `viewIndependentRegistry` + `layerZoomGate` + `siteStackParity` unit tests stay green.
- **PDF-PARITY decision:** exports do NOT include road names. The export path does not carry the planner's live Leaflet layers (the aerial included — it is rasterised separately), and road names are a live layer on that same map; matching the aerial's path means screen-only. Stated here so it is a decision, not an omission.
- **Sandbox-verified:** `e2e/planner-road-names.spec.js` — RED on main (pane never exists), green with the fix: pane + canvas present at street zoom, pointer-events none, pane inside the Leaflet map (plan SVG outside it); after a wheel-zoom and a pan the label map and the aerial agree on centre to 0 px and keep one constant zoom offset (read in a foreground tab, `visibilityState` asserted); Road names off removes the pane, on restores it; aerial Off removes it; opacity and on/off survive a reload. Uses the synthetic OpenMapTiles fixture (`ui-audit/lib/fakeVectorTiles.mjs`) because the sandbox cannot reach openfreemap — it proves wiring and registration, not what the live OSM data looks like. `test/roadNamesPref.test.js` for the pref.
