### B2039233 — A Word/text/PDF file saved in Review with no project said "Saved to the Library." but appeared nowhere in the Library `[doc-review / library]` (bug) #doc-review #library #files  *(Owner block NEW-2, 2026-10-03; owner's test file `planyr-test-delete-me.docx` — do not delete it.)*

`[x]` **Cause (AUDIT-FIRST):** a project-less review is stored fine (a `doc_reviews` row + bytes) but belongs to no project's view; the Library Home lists only Pinned / Recent / Projects, Word files were never recorded in Recent (B686's "can't be shown" exclusion), and the banner was a fixed string. **No-project PDFs share the exact path** (same `storeSource` + review row, same invisible Home) and are fixed together. A second cause surfaced while tracing it: **a blank Review standing in a project's "Current set" filed its upload to NO project** (the blank review's meta had no project, the route did) — so "Upload file" inside a project went to nowhere too.
`[x]` **Design chosen — an "Unfiled" section on the Library Home, not a project question at Save time.** Reasons: Save must never block on a question (it is the same button for every file, and a prompt on every Save is exactly the friction the editor avoids); a Save-time picker would not rescue files already saved, files whose project was deleted (`unfileReviewsForDeletedProject` writes the same state), or PDFs; and "nothing auto-guesses a project" is kept — the file waits, visibly, until a human files it. **Unfiled** lists every review with no project and no Organization scope (`lib/unfiled.js`), each row = Open + a **Move to project…** picker. Moving runs `fileReviewIntoProject` — the single implementation extracted from FileBrowser's Needs-filing row (which now calls it too: re-point the review, mirror the file index, move the Drive copy; each failure is a loud notice).
`[x]` **The banner tells the truth:** no project → "Saved to the Library under Unfiled — open the Library to move it into a project."; a project → "Saved to the Library in <name>."; Organization → "…under Organization." Review's "Upload a file without a project" now says "It will be kept under Unfiled in the Library." and a blank Review inside a project files the upload into that project. A save files where the open review is filed (its own meta), never where the URL happens to point.
- **Red-proof:** `test/reviewCloseFile.test.js` — the filter (project / org / id-less rows excluded, newest first), the banner text per scope, the Unfiled card + picker render, the shared filing function's sequencing (a failed re-point writes nothing else; a Drive-move failure is loud), and a guard that FileBrowser has no second `refileReview` implementation. Browser: the local mirror of a file uploaded from a project's index carries that project's id.
- **Adjacent cases:** no project selected ✓ (unit + banner) · file inside a project ✓ (filed to the project, banner names it) · Organization scope ✓ (banner). The Unfiled listing itself needs the signed-in cloud — **V1464321**.
- **Constraint check (DoD #4):** auto-filing still never guesses a project; nothing contradicts an `## Owner product constraints` entry.
