- **ROOT CAUSE, traced through Leaflet's own `Map.js` `_animateZoom`, not assumed from the doc comment alone:** the overlay only repositioned on Leaflet's `"move"`/`"zoom"`/`"viewreset"` events. Per the installed source, `_animateZoom(center, zoom, startAnim)` fires `"zoomanim"` first, then calls `this._move(this._animateToCenter, this._animateToZoom, undefined, true)` **synchronously, at the START of the ~250ms animated transition** — and `_move` is what actually flips the map's internal zoom/center state and fires `"move"`/`"zoom"`/`"viewreset"`. So `rotatedImageLayer.js`'s own `update()` (bound to those three events) was computing and writing the CORRECT, FINAL, post-animation transform the INSTANT the gesture began — on a plain DOM element with no CSS transition to ease into it, that write paints as an immediate jump. The owner's own description — "the map imagery moving while the plan stays fixed… it snaps to its new position at the end" — has the SNAP'S timing inverted from how it reads (it snaps at the START; the tiles then spend ~250ms visually catching up to a position the plan had already silently reached), which is exactly consistent with this mechanism and is why it read as "lag" rather than "jump."
- **THE FIX, the sanctioned Leaflet technique — the SAME one `L.ImageOverlay._animateZoom` uses internally, confirmed by reading it, not inferred:** (a) the `<img>` element now carries the `leaflet-zoom-animated` class, which opts it into `leaflet.css`'s `.leaflet-zoom-anim .leaflet-zoom-animated { transition: transform 0.25s … }` rule — Leaflet flags `_mapPane` (an ancestor of every custom pane, including this module's own `sitePlanOverlayPane`, since `createPane()` with no container argument appends under `_mapPane`) with `leaflet-zoom-anim` for the duration of a zoom gesture. (b) a new `zoomanim` handler writes the TARGET-view transform directly, via Leaflet's own private `_latLngToNewLayerPoint(latlng, zoom, center)` — the identical helper `ImageOverlay`/`Marker`/the vector renderer all use for exactly this — refactored the existing corner-to-matrix math (`update()`) into a shared `matrixFor(project)` so the resting and animated cases can't drift apart. Fires per Leaflet's own doc contract ("at least once per zoom animation… once per frame for a continuous pinch"), so a pinch zoom tracks smoothly too, not just a discrete zoom step.
