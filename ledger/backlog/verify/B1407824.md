**PART 1 — the dangling-comma truncation.** No component here duplicated its own ad hoc cutting logic — `LocationsMapCard.jsx`'s pin label and `SinceLastHereCard.jsx`'s feed sentence had **no length limit at all** (a long name would run the pin's label plate off the map, or push the feed row's own age chip out of the layout), while `PursuitsCard.jsx`/`RecentPlansCard.jsx` relied only on a CSS `text-overflow: ellipsis` clamp, which truncates on pixel width with no idea where a comma, period or hyphen sits — it can land the cut immediately after one, and shows no ellipsis at all when the clamp never actually engages (the CSS half only fires once the rendered text overflows its box; a short string, like the 16-character reported name, never trips it at all). **DO NOT REPAIR HIS DATA** — nothing here reads or writes `sites.site`/`sites.name`; every fix is at the RENDER layer only, per the brief's own instruction.
- **The shared place:** `shortenDisplayName(name, maxLen)`, new in `src/shared/projects/projectModel.js` (the existing pure, dependency-free home for project/plan name helpers, already reused across workspaces with no storage/DOM dependency). It does two different things, because the reported case is NOT a length problem: **(1)** a name **over** `maxLen` is cut, trimmed back past any trailing run of comma/period/hyphen/whitespace, then marked with one trailing "…" — a shortened name is always both clean and visibly identifiable as shortened; a cut landing MID-WORD (nothing separator-like to trim) is left exactly as cut, which reads as an ordinary shortened name, not as broken text. **(2)** a name **at or under** `maxLen` — nothing to cut for space — still has a trailing comma/period/hyphen stripped, with **no** "…" mark (nothing was hidden, so nothing is "shortened"), because a name that just stops on a bare comma with nothing ever following it reads as broken regardless of how it got that way, and there is no more text this function could ever append to make it whole. A trailing plain SPACE on a fitting name is left alone in this branch — whitespace isn't "broken text" the way dangling punctuation is.
- **Wired into all five call sites, once each, no duplicated cutting logic:**
  1. `dashboard/lib/dashboardMapMarkers.js` — `mapMarkers()` shortens `p.name` (22 chars) before it ever reaches the pin label; `LocationsMapCard.jsx` itself is unchanged.
  2. `dashboard/lib/pursuitsList.js` — `pursuitsTable()` shortens `p.name` (26 chars) at the pure table-model layer; `PursuitsCard.jsx`'s existing CSS clamp stays as a backstop for an unusually wide font, no longer the thing deciding where the name breaks.
  3. `dashboard/components/RecentPlansCard.jsx` — the tile caption (22 chars) and the separate "cannot render a thumbnail" fallback text (60 chars, it's line-clamped to two lines and has more room) both shorten `plan.name`; the tile button's own `title=` attribute keeps the FULL name, so hovering always shows the real thing.
  4. `dashboard/lib/sinceLastHereFeed.js` — `buildPlanEvents()` shortens the name (36 chars) embedded in a "New plan …"/"Renamed to …" row's `parts`; the FULL name is kept in the plan snapshot and in `open.groupId` (nothing that resolves navigation or a future diff is touched, only the sentence).

**PART 2 — lower-case county names in the feed.** `site.county` is a lower-case ROUTING KEY (`"bowie"`, `"harris"`, `"fort_bend"` — see `shared/CLAUDE.md`'s County ROUTING KEYS note), never a display string; `sinceLastHereFeed.js`'s `planContextLine` built its sentence with `` `${site.county} County` `` verbatim, printing "bowie County"/"harris County". `dashboard/lib/compsCardModel.js`'s `countyLabel` already turns the identical routing key into a properly title-cased name for the Comps card ("Harris County, TX") — its word-capitalization step is now split out as its own exported `countyNameWords(countyKey)` (returns `{ words, isColorado }`, no "County"/state suffix baked in), so `countyLabel` composes it into "County, TX/CO" and `planContextLine` composes the SAME words into "County" — one capitalization rule, two sentences, instead of a second regex reimplementing it. `countyLabel`'s existing behavior (and its test coverage in `test/compsCardModel.test.js`) is unchanged — confirmed by the full suite below.
