### B2671288 — Notes: copying a BOX works like copying a cell in Excel (moving dashed outline, Ctrl+V makes a new box); copying TEXT never copies the box `[Notes]` (feature) #notes #paste #ui

*(Owner, 2026-11-15, Claude Code dispatch block "[FEAT] Notes: Excel-style box copy, PowerPoint-style overlap", NEW-1: "it must be obvious when he is copying a BOX as opposed to TEXT, the way Excel shows a copied cell." DEDUPE-FIRST: B2155520 (a table on the page copies / cuts / pastes) is the ancestor and is kept — a selected box's content still goes to the clipboard as HTML + tab-separated text; this adds the box itself, its outline and its paste. - Verify: live — **V2671276** (signed in on planyr.io, `ui-audit/verify-notes-box-copy-live.mjs`)
- **THE RULE (one sentence):** a box copy is "boxes are selected AND there is no text selection and no caret in an entered box"; anything else is a text copy.
- **Box copy:** click a box's outline, Ctrl+C → Excel's moving dashed outline (`data-copied`, an animated `::after`; static but dashed under reduced motion) on the copied box(es) until Esc, a new copy or an edit (a PASTE is not an edit — Excel keeps the outline so the same copy can be pasted again). The clipboard carries the boxes as stored (position, width, formatting, table, picture reference) in a `data-planyr-boxes` attribute of the HTML (`lib/notesBoxClipboard.js`), AND the content as ordinary HTML + plain text, so Word / Excel / an email paste it like any copy. Ctrl+V — blank paper, an armed spot, another page, or with the caret inside another box's text — makes NEW box(es) with all the text and formatting, claimed by one handler (`pasteBoxCopy`) that the loose-paste and armed-paste routes stand down for (`carriesBoxCopy`); one transaction (`pasteNoteAnchors`), one Ctrl+Z; the new box ends up selected.
- **Design calls (stated in the PR, not asked):** (1) **Ctrl+X** cuts: the box leaves, one Ctrl+Z restores it exactly (focus returns to the document so the undo is reachable — the same fix as a group Delete), the clipboard still holds it so Ctrl+V brings it back as a new box; no outline (nothing is left to outline). (2) **Placement:** at the armed spot when he double-clicked blank paper first; else offset down-right from the source on the same page, one step further each time the same copy is pasted again; else in place on another page. (3) **Caret inside another box's text:** still its own new box, never poured into the text; the paste-options tab appears with **Keep Source Formatting** (the box) and **Keep Text Only** (the same words inserted at the caret, the box taken back out — one undo step, switchable both ways; no hover preview for this kind). (4) **Across pages:** the box pastes onto another page; a picture / attachment inside gets bytes of its own under the new page (a copy sharing the source's id would break when the source is purged). (5) **System clipboard:** plain text (the content), no markup.
- **Text copy never copies the box:** MEASURED on main first (2026-11-15): a partial text copy put `data-pm-slice="1 1 [&quot;noteAnchor&quot;,{aid,x,y,w,fit,h}]"` on the clipboard, and **Ctrl+A put every box as a `.planyr-anchor` div with `data-anchor-x/y/w` on it** (pasted into another box it poured every box's words in; the parse could re-create boxes). Fix: ProseMirror's own `transformCopied` (`copyScopePlugin`, `unwrapCopiedSlice`) takes the box frame out of every copied or cut slice, so a text copy carries words, marks, tables and pictures — never a box. Ctrl+A still selects the whole page's text (unchanged; scoping it to one box is a separate call).
