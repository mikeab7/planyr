- **Repro (measured on production, signed in).** Open a plan in a browser profile whose local cache holds an older copy of the same elements. The load itself issues ZERO commits — then, seconds later, `site_elements` takes **FOUR separate transactions over six seconds** (16:38:14.693 · :18.637 · :20.627 · :20.630) writing the CACHED geometry for a SUBSET of one twelve-member assembly: `e26duuwgj` (899.44, −559.55), `e27duuwgj` (899.44, −652.05), `e63sascnh` (1312.94, 47.95), `e64cglxqv` (485.94, −522.05) against canonical 1117.20/−336.35, 1117.20/−428.85, 1530.70/271.15, 703.70/−298.85. **The stale delta is exactly (−218, −223)** — a drag made in the previous verification round and then undone. The live canvas afterwards held `e26`/`e27` stale and everything else correct: the tear was **ON THE CANVAS**, not only in the rows.
- **Root cause (AUDIT-FIRST) — the rev guard structurally cannot catch this.** After `seed(rows)` the shadow holds the server's **current rev**. A stale canvas copy therefore commits **CLEANLY**: the CAS sees the rev it expects, because the client legitimately holds it. Nothing in the write path is wrong — `closeAssemblies` folded in nothing because the other eight members genuinely agreed with the server, which is the correct behaviour for a diff committer. The bug is that the divergence was ever read as an edit. And the copy survived the rows-canonical replace because of the **pending-edit journal**: a stale tab hot-looping rejected commits (B1115) keeps adopting the freshest rev, so its journal's `baseRev` tracks the current row and its entries sail through `foldJournal`'s `row.rev <= baseRev` test carrying geometry undone long ago.
- **Fix — the rule is now WRITTEN DOWN (`CLAUDE.md` → **ROWS-CANONICAL-ON-SEED**), because the ambiguity is what cost the plan.** For an element the server ALREADY HAS, rows win at seed time unless a pending local op explains the difference; for an element the server has NEVER seen, local wins (that is the whole of the B124/B756 guarantee). Mechanically: `reconcile(collections, { afterSeed: true })` — **opt-in on purpose**, since only the seeder knows which diff is its own, and an ordinary later diff carries genuine edits that must never be silently reverted — adopts the rows through a new `onRowsCanonical` callback instead of enqueueing. Result: **zero commits**, not a four-op one.
- **Second half — heal AFTER the folds.** `rowsToModel` healed the ROWS, but the journal / never-synced folds run afterwards and can substitute a local copy back over a healed row. `refetchReplace` now re-runs `normalizeBondedChildren` on the FINAL merged canvas, so no fold can put a geometrically impossible assembly on screen (and then commit it). Identity-preserving on a coherent plan, so a healthy load still churns nothing.
- **Tests.** `test/assemblyTear.test.js` — the case the brief specified: seed from rows, inject a divergent cached copy of **4 of 12** assembly members, assert **zero commits** and that all four rows are adopted onto the canvas; plus "never a 4-op commit" stated as an invariant, a pending local edit still committing (not silently reverted), and a never-synced element still winning locally.
