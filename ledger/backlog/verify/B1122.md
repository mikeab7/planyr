- **ROOT CAUSE (AUDIT-FIRST) — and it is narrower than hypothesis (B) supposed.** Both surfaces were ALREADY driven from the same value (`view`). They never disagreed about WHERE to be — only about **WHEN** each got there. The SVG renders from `view` in the React commit and paints immediately; the basemap wrapper's transform is computed from the same `view` but was written in a **passive `useEffect`**, which runs **AFTER paint**. So every pan frame painted the drawing at the new offset with the aerial still at the previous one: **one frame of separation per frame, proportional to the per-frame delta** — which is exactly why a fast SLING shows it and a slow drag barely does. The debounced re-base then lands and they line up: *"slings back into position."*
- **FIX — DIRECTION 1, reachable in one line, structurally rather than by narrowing.** The transform write is now a **`useLayoutEffect`**: applied before the browser paints, in the SAME frame as the SVG that shares its source value. There is no instant at which the two hold different values, so the disagreement is impossible by construction rather than merely brief. **Explicitly NOT a shortened debounce** — the owner named that trap, and it would have narrowed the snap-back while leaving the per-frame lag untouched, reading as fixed on a slow drag and still slinging on a flick. The commit delay is unchanged and a test pins it that way.
- **This is `CLAUDE.md` → VIEWPORT-STABLE, which already said it in as many words** — fold the delta in a layout effect, *"never a passive (after-paint) `useEffect` (that skips the content sideways for one-plus frames)."* This effect predates the rule and violated it. Nothing about the projection or the origin-anchored scale changed.
- **VERIFICATION UNBLOCKED by changing the ASSERTION, not the instrument (the owner's correction).** A pixel-offset probe against real imagery is unrunnable here (no tile host) and unrunnable for him (hidden tab, rAF suspended — the B1086 trap); both of us hit the same wall. `test/panLockInvariant.test.js` asserts the STRUCTURE instead — needs no imagery, no visible tab, no rAF, runs in CI on every commit: the effect owning the basemap transform write is a LAYOUT effect (located by the write itself, not a line number); both surfaces read the same `view.offX/offY/ppf` source; the debounce is unchanged so a future "perf tweak" can't substitute one for the other; and NO other `wrap.style.transform` write sits in a passive effect. **TEETH: two of the four cases go RED on the pre-fix model** (verified by restoring `useEffect` on that block) — the B1062 standard. `ui-audit/verify-pan-lock.mjs` stays as the nice-to-have pixel check on top, no longer the gate.
