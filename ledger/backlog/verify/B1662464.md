`[x]` **IMPLEMENTED AND SANDBOX-VERIFIED — the report's own first question, answered and closed: yes, the app writes on open, unconditionally, and that is now fixed.** Tiptap's own mount-time schema settle — missing node attrs filled to their schema defaults, and the `TrailingNode` extension inserting a blank paragraph so the cursor has somewhere to land after a table/list — is a REAL, doc-changed ProseMirror transaction that fires with **zero keystrokes**. `NoteEditor.jsx`'s `onUpdate` could not tell that transaction apart from a real edit, so opening ANY note: (a) queued a write that landed 600ms later via the normal save path, (b) stamped the page's `updatedAt` to "now" (`Notes.jsx`'s `handleSaved` → `touchPage`) — so "Edited just now" showed on a note nobody touched, and (c) via `docTick` (which bumps on `selectionUpdate` too, not just real doc changes) could mint a version-history row 1500ms later carrying the DEFAULT reason label, **"While you were typing"** — exactly the exhibit in the report — or, on leaving the page, a forced "When you left the page" row, both from a session with no keystrokes at all.
- **MEASURED DIRECTLY, not inferred**: a throwaway-note harness (`ui-audit/verify-notes-write-on-open.mjs`) seeds six documents (identical-mark runs, differing `textStyle` between two adjacent runs, one bold/one plain, an autolink-shaped email mark, a real Tab-sunk nested list item, and an item wearing Tab's flat `indent` attribute) and opens each with **zero interaction** — no click, no keystroke, only navigation + reload. Before the fix: all six changed the stored document's shape and stamped `updatedAt` on the very first open (0/6 passed — red-proved against the pre-fix code, same commit range, `git stash` round-trip). After the fix: none does (6/6).
- **THE FIX, and why it closes the whole class rather than this one shape.** `hasUserInputRef` (`NoteEditor.jsx`) starts `false` and is set `true` ONLY by a genuine, browser-`isTrusted` DOM event (`pointerdown`/`keydown`/`paste`/`drop`/`cut`, listened on `window` for the component's lifetime so a toolbar click counts too) — never by a command, an effect, or anything the app's own code dispatches. `onUpdate` still tracks the live document on every transaction (a real edit right after the settle is never missing context), but it does not queue a write, flip the status to "unsaved", or arm the save timer until this flips; the periodic `docTick`-driven version snapshot and the forced "closed" snapshot on unmount are gated the same way. A real edit is unaffected end to end (verified: a real click + real keystrokes still saves, stamps `updatedAt`, and reads back correctly after a reload) — the fix only ever *withholds* a write nobody asked for, never delays or drops one a person made. This is deliberately not a special case for the settle's specific shape (attrs, TrailingNode) — it refuses to call ANY load-time transaction an edit until a person has done something, which is what the report itself asked for: *"whether the write-on-open can be made a no-op when nothing actually changed."* Full regression pass: `verify-notes-box-selection.mjs` (131/131, exercises real select/type/delete/undo/resize through the same save path) and `verify-notes-list-indent-height.mjs` (6/6, today's PR #1725) both green against the fixed build; `verify-notes-anchor-soak.mjs`'s pre-existing red (documented in `docs/NOTES-CARRY-FORWARD.md` §7) reproduces byte-for-byte identically with the fix stashed out, confirmed not a regression.
