- Verify: live
- **Root cause.** `sinceLastHereFeed.js` carried its own hand-rolled `compRateLine`/`compSizeText` — "A small, local re-implementation of `shared/comps/lib/comps.js`'s `compHeadline`," by its own comment — kept separate from the Comps card's model for a real, measured bundle-size reason (importing `shared/comps/lib/comps.js`'s `rowToComp` from a Dashboard-eager module once pulled a whole extra chunk onto the Site Planner route). That reimplementation rendered a lease rate in the comp's OWN entered period always, never the account's chosen display period (`dashboard/lib/compsCardModel.js`'s `compHeadlineRate` + Michael's own "per year / per month" toggle, B1395568) — so the same comp could disagree with itself by exactly the stored period's ratio (12x for a monthly-vs-annual lease), on the same screen, depending which card you read.
- **The fix.** Deleted the duplicate calculation and formatter. `sinceLastHereFeed.js` now imports `compHeadlineRate`/`formatRateValue`/`DEFAULT_LEASE_PERIOD` directly from `dashboard/lib/compsCardModel.js` — the SAME dashboard-workspace-local module `Dashboard.jsx` already imports for the Comps card, so this adds no new cross-route bundle edge (confirmed by `npm run perf:bundle`: no new chunk, budgets unchanged from before this item). `formatRateValue` itself was ALSO a local duplicate (`CompsCard.jsx`'s un-exported `fmtRateValue`) — moved into `compsCardModel.js` and exported, so the card and the feed now literally call the same formatting function, not just the same math. The new `compAddedSubline(comp, compsRatePeriod)` (exported) composes both, given the SAME period value threaded from `Dashboard.jsx`'s `compsPeriod` state (the same state `buildCompsCardData` already reads) — and it is recomputed at RENDER time in `SinceLastHereCard.jsx`'s `FeedRow`, not baked in once when the feed was built, so flipping the toggle updates both cards in the same click rather than leaving the feed on whichever period was current at page load.
- **Red-proofed.** `test/sinceLastHereFeed.test.js`'s "FEED-3: a monthly-quoted lease comp reads the SAME figure the Comps card would show" test computes its expected string independently, off the real `compHeadlineRate`/`formatRateValue` the card calls, then asserts the feed's subline contains it — confirmed failing against the pre-fix module (feed printed "$0.65/SF/mo," card figure is "$7.80/SF/yr") via the same before/after scratch harness used for B1405456, and passing after the fix.
