`[x]` **FIXED THIS SESSION.** `projectId`, as fed into `buildProjectNames`/`siteEntries` (`src/workspaces/model/lib/projectRefs.js`), is the route's **Site-GROUP id** (`Shell.jsx`: "active Site-group id"), never a specific plan/concept id — a project with several concepts/schemes is several `sites` rows sharing one `groupId`, and a brand-new project's FIRST plan is always minted with `id === groupId` (`storage.js`'s `saveSite` call sites). `siteEntries` called `loadSite(projectId)` directly, which therefore always resolved to the row whose own id equals the group id — the ORIGINAL concept — no matter which scheme the user actually had open, including after a full page reload (the reference never consulted which plan was active in the first place; "switching schemes changes nothing in the model" was exactly this).
