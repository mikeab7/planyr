### B2308848 — Browser saved-entry dropdown pops up on Site Planner and Schedule text fields `[site-planner, schedule]` (bug) #site-planner #scheduler #ui
`[~]` **⏳ Verify — fix merged, V1739376 pending (his Chrome).** Owner repro 2026-10-16, Chrome on Windows: Site › Land › Parcels › an unnamed Harris CAD lot › "YOUR NAME FOR IT" — Chrome's own dropdown offered "1502 FELLOWS", "10", "15", "23", "22", "20" (values typed into other boxes), covering the panel; same in Schedule. Expected: no browser autofill / saved-entry list on ANY input in Site Planner or Schedule; Planyr's own pickers (contact picker, place search) unchanged; login/sign-up/profile keep autofill; no name is prefilled.
**Root cause (measured, red-proofed on main):** B2088384's app-wide stamp (`shared/ui/phoneTyping.js`) gave every non-contact field the NON-STANDARD token `x-planyr` (iOS ignores `off`) AND the same `name="planyr-field"`. Chrome reads an unknown token as "no opinion", so its saved-entry (form-history) list stayed on, and because every field shared one `name`, every field drew from ONE pooled history bucket — which is why a number typed in one box was offered in another. The Schedule grid's inline `NO_AUTOFILL` bag carried the same token.
**Fix:** off iOS the token is a genuine `autocomplete="off"` — the value Chrome honours for the saved-entry list — and no shared `name` is stamped; iOS keeps `x-planyr` + neutral name (it ignores `off`). ONE decision point: `autofillToken()`/`isIosLike()` in `shared/ui/noAutofill.js` (feeds `NO_AUTOFILL` and `phoneTyping.autofillStamp`); the iframe's byte-for-byte inline copy mirrors it. Fields with a REAL contact token (sign-in email/password, profile name, organization) and Food's own `x-food-*` are left alone. Applied app-wide through the one stamp on focus/press, so new fields inherit it.
**Verified here:** `test/phoneTyping.test.js` + `test/noAutofill.test.js` (token per platform, drift guard for the iframe copy); `ui-audit/verify-no-browser-autofill.mjs` focuses every input in the Site panels (Land incl. "Your name for it", Analysis, Drainage, Yield, Overlays, Standards, Properties, plan-name) and every Schedule grid cell editor in a real Chromium: 36/36 on the fix, **14/36 on current main** (the reported field reads `x-planyr`, 16 grid fields share `planyr-field`). Known-answer arms (bare→off, email stays email) make a blind run VOID. **Chrome's popup itself is browser chrome — not in the DOM, not reproducible headlessly; this is NOT claimed as a live check.**
**Not touched / follow-up:** Food keeps `x-food-*` (out of scope; same Chrome-history caveat if the owner sees it there). Stopping rule: closes when V1739376 passes on his Chrome, or he says the list is gone.
