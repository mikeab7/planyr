- **THE AUDIT, DONE FIRST, AS INSTRUCTED — the pointer→world transform (`p2f` → `screenToWorld` in `shared/viewport/viewportTransform.js`) carries NO `devicePixelRatio` or `visualViewport` term anywhere in the chain.** It is `world = (screen − t) / scale`, fed by `e.clientX/clientY` (browser-reported) and `svgRef.current.getBoundingClientRect()` — both defined by the DOM spec in the SAME "visual CSS pixel" space at any browser zoom level, so their difference is invariant under a uniform page zoom by construction (both move together). A repo-wide grep for `devicePixelRatio`/`movementX`/`movementY` in the drag path found none — the one `devicePixelRatio` use in this file is for basemap tile retina selection, unrelated to pointer math. The drag-vs-click gate (`lib/dragGate.js`) measures travel in CSS px and rebases in world feet, also with no zoom term. **So the hypothesis handed in — browser page zoom as the direct cause — is NOT confirmed by this audit, and is not asserted as the cause; it is also not refuted with certainty, since this sandbox cannot drive Chrome's real Ctrl+/Ctrl− page zoom (which changes `window.devicePixelRatio`) the way a real browser session can — `document.body.style.zoom` was tried as a proxy and found NOT equivalent (it changes `getBoundingClientRect()` numbers but leaves `devicePixelRatio`/`visualViewport.scale` at 1, unlike real page zoom).** That specific question is parked below as V408192 for a live re-test at ~160% zoom on the deployed build.
- **THE FIX SHIPPED REGARDLESS OF ROOT CAUSE, because the DAMAGE — an invalid polygon reaching storage — is a defect independent of what triggers an oversized pointer delta.** The self-crossing/degenerate guard (`points.length < 3 || polyArea < 1 || polySelfIntersects`) used to run ONLY at pointer-up (release). It now ALSO runs on every `onMove` frame for a `footEdit` vertex drag, against the CANDIDATE points before they are ever written to state: if the candidate would cross or degenerate, the frame writes NOTHING — the vertex holds at its last valid position instead of following the cursor past the crossing — and a throttled (once-per-gesture) toast fires. The existing release-time guard is kept as a backstop for any other write path (a typed coordinate, say) and is now unreachable via a normal drag. Because a self-intersecting ring can no longer be CONSTRUCTED in local state at all, there is nothing invalid left to race a debounced flush against — closing the reported "canvas showed the old rectangle while the database held a bow-tie" split by construction, not by making the race narrower.
- **User notification, per part (c) of the report.** The per-frame guard flashes `"⚠ Reshape held — that move would cross the outline over itself."`; the release-time backstop's message also now carries the `⚠` prefix (see B742371) so a refusal can never again render in the same green pill as a completed action.
