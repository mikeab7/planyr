- **AUDIT-FIRST — root cause: a stale refetch that OMITS a just-committed element evicts it from the shadow, so its own echoes look foreign.** A resize re-commits a building's bonded children (sidewalk/paving/parking) several times fast. On a socket reconnect / tab-wake, `refetchReplace`'s fetch snapshot can OMIT a just-committed child (read-replica lag / the fetch predating the commit burst). `reconcileSeedRows` (B811) can only substitute into rows the fetch still CONTAINS — it cannot re-insert a dropped row — so `eng.seed()` evicts the child from the shadow. The child's own realtime echoes of earlier revs then arrive with no shadow entry (the rev guard can't catch them), no pending entry, and the single-slot `recentSent` held only the latest version → `sentMatches` missed the intermediate revs → a false `remote-upsert(authoredRecently)` per pre-final commit = the burst. B759×2 (data-match suppression) and B811 (present-but-stale reconcile) both left the OMITTED-element path open.
- **The fix (client-only, `lib/elementSync.js` + `lib/elementRows.js`), four layers, each closing a residual a red-team confirmed:**
  1. **`ownRevs` + `maxOwnRev` high-water (own-echo-by-rev).** Record EVERY server rev this tab's commits produce (ok / restore-self-dup / conflict-self-dup), plus a NEVER-time-pruned per-key high-water. `applyRemoteRow` ignores any non-tombstone echo where `isOwnRev(rev)` OR `rev <= maxOwnRev[key]`, before the pending branch — so it kills the `remote-upsert` AND `remote-while-dirty` variants. Server revs are monotonic per element, so anything at/below our high-water is definitively ours (or a foreign write we already superseded); a live foreign edit always lands strictly ABOVE it → still surfaces. The high-water (never pruned) closes the round-2 Angle-4 edge where a >15s-old own echo outlived the 15s `ownRevs`/`recentSent` windows.
  2. **`recentSent` → all-versions** (`Map<key,Map<json,at>>`): covers the pre-RPC / transport-failure window where no rev was learned, for every version put on the wire.
  3. **`stableStringify` → exact JSON wire semantics** (drop undefined-valued keys / functions / symbols, holes+undefined → `null`, Date via toJSON): the old `undefined` token made any element with an undefined property serialize DIFFERENTLY from its post-jsonb echo, permanently defeating every self-echo byte-compare AND producing phantom no-op diffs (red-team Angle 2). Floats were confirmed byte-stable — not a source of drift.
  4. **`reconcileSeedRows` tombstone-aware** (new 3rd arg `tombstonedSnapshot()`): a delete clears the shadow entry, so a stale-alive refetch would adopt the row verbatim and RESURRECT a just-deleted element (a TOMBSTONE-DELETES violation) + later mis-fire "was deleted by you (another window)" (red-team Angle 1). A fetched-alive row whose (kind,id) this tab tombstoned within the window at a rev ≤ our delete is kept deleted; a genuine re-create ABOVE the delete rev passes through alive.
