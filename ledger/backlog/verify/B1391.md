- **THE TRIGGER, stated honestly because it changes what the bug IS:** the same account was open in more than one window. The owner's own tab was open while this cohort opened `planyr.io/#/notes` in extra tabs on his machines and hard-reloaded them. Two clients of ONE account raced. Nobody else has access — notes are own-row and private by default — so the app was not merely rude, it was **wrong about who**.
- **AUDIT-FIRST — three distinct defects, all three fixed, and the third is the real bug:**
  1. **A NO-OP RAISED A PROMPT.** The revision guard answers "did the row move?", and that was being reported as "the two copies disagree" **without anyone comparing the documents**. A sibling window's push, or a hard reload landing between a push and the ledger write, leaves a stale base rev — so the next push is refused over content the server ALREADY HAS. The user was asked to choose between two identical documents.
  2. **THE WORDING NAMED A PERSON.** "Keep the other computer's copy" / "also changed on another device" implied a second human on a private, own-row note.
  3. **⛔ THE ACTUAL BUG: A SINGLE ACCOUNT COULD SILENTLY OVERWRITE ITSELF.** The editor reads its document ONCE at mount (deliberately — B1290's crash fix). When a page's body is replaced underneath it — by a sibling window, or by the cloud seed adopting the account's row — it kept the STALE copy, and the next keystroke wrote that whole stale document back. Guarded on a revision this window legitimately held, so it committed **cleanly**: no conflict, no banner, the other window's paragraph simply gone. That is the B1113 / ROWS-CANONICAL-ON-SEED trap, in Notes. **Reproduced and then killed in a real browser** — see the mutation result below.
- **What shipped:**
  - **`judgeConflict` + `sameDoc` + `isEmptyDoc` (pure, `notesCloud.js`)** — every path that loses the guard now compares the two documents first. **Identical** → adopt the server's revision in silence. **Nothing here to lose** (no body, or an empty one, against real text) → take the row. **Diverged** → and only then, name it. `sameDoc` compares CANONICALLY, so key order, a `null` attribute written where one was omitted, an empty `marks` array or a re-ordered mark set — all the noise a round trip through jsonb adds — cannot masquerade as an edit. The asymmetry is deliberate: **the silent path may only ever ADD text back, never remove it**, so text-here against blank-there is still a real conflict.
  - **`mergeSyncState` (pure)** — the sync ledger now MERGES with what is on disk instead of overwriting it. Two windows share this browser's storage but not its memory, so a blind write flattened whatever the sibling had learned and manufactured the stale bases that caused the refusals. **A dirty page keeps its OWN base rev** even when the disk holds a fresher one — adopting it would let a stale body commit cleanly past a guard doing its job.
  - **A `storage` listener, for EVERY scope** — signed in or out, a window now learns immediately what its sibling did: merge the ledger, re-read the tree, and announce a changed page body.
  - **`onNotesPagesChanged` → a body EPOCH in the editor key** — an open editor re-reads a page whose body changed underneath it. It is a **REMOUNT, not an effect**: NoteEditor must never grow a "sync content" effect (its header says why, and the guard in `test/notesModule.test.js` now asserts both halves of the key). The store only announces a page this window has no unflushed edit on, and the outgoing instance flushes on unmount — so a remount can never discard work in progress.
  - **The copy, in ONE pure function (`notesConflictLine`)** — “…also changed in another of your windows. Nothing was overwritten — pick which to keep.” with **Keep this one** / **Use the other**. It may say WINDOW or COMPUTER; it may never say a someone. A unit test holds it to that, and a source scan fails the build if any user-facing string in the module implies a second person. The footer line moved with it.
- **Guards, and the two-window one was PROVEN RED FIRST.** `ui-audit/verify-notes.mjs` §23 opens a SECOND browser window on the same storage with the same note open in both, types in window two, and asserts window one re-reads it and that window one's next keystroke does not wipe it. With `attachSiblingListener()` commented out the run goes **167/169 — both checks fail, and the failure text shows window two's sentence gone**. With the fix: **169/169**. `test/notesSync.test.js` adds 30 unit cases over `sameDoc` / `isEmptyDoc` / `judgeConflict` / `mergeSyncState` / the conflict copy.
- **What `V680` still has to confirm (needs a real sign-in, which the sandbox proxy CORS-blocks):** that two SIGNED-IN windows on the same account never raise the bar for identical text, that a genuine divergence still does and still names nobody, and that the parked "(this window's copy)" page appears when "Use the other" is chosen.
