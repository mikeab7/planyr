- **NEW-1 — the popover is gone; a click vs. a drag is inferred per-gesture, never picked in advance.** Deleted entirely: the `cloudMenu`/`cloudAnchor` split-button popover, the `cloudMode` state (`polygon`/`rect`/`freehand`) and its `lsGet`-backed persistence, the "Drag a box" (rectangle) mode and its `commitMkRect` branch, and the standalone `commitMkCloudFreehand` commit path. In their place, one unified gesture (`onDown`/`onMove`/`onUp`'s `mkCloudGesture`): press-down arms nothing yet; if the pointer travels past `DRAG_SLOP_PX` (the app's one existing click-vs-drag threshold, `dragGate.js` — not a new constant) it accumulates a freehand run exactly like the old dedicated Freehand mode did; if it never clears that threshold, the press contributes its single point instead, exactly like the old Polygon mode's click-to-add-vertex. **Both write into the SAME in-progress ring** (`mkPoly`), so a click and a drag freely MIX within one cloud — click two corners, drag a curved run, click two more corners, close — which no prior mode could do, because they were mutually exclusive. Closing is unchanged in spirit but now fires from either gesture: clicking back near the first dot still closes (checked pre-arm in `onDown`, as before), AND a drag that loops back near the ring's own first point closes immediately on release too, so a single continuous drag still produces a whole cloud in one motion — the old Freehand mode's exact UX, now reached with nothing to pick first. `finishMkPoly` (already the ONE shared commit path every polygon/polyline markup used) gained one optional parameter (`ptsOverride`) so the gesture's `onUp` can close a ring it just computed without round-tripping through React's async `setMkPoly` first — the only new plumbing this required, and it made the two other cloud-only commit functions (below) unnecessary rather than adding a third.
- **Arc size moved into Properties, permanently — nothing about a cloud configures before it exists.** The toolbar's Draw-mode radios AND its Arc-size presets/custom-field are both gone; Cloud is now a single plain button in the Draw rail, identical in shape to every other markup tool (`MARKUP_TOOLS.map(...)`, no more special-cased split button). Arc size is now purely `mkCloudStyle.arcFt` — folded into `MK_CLOUD_DEFAULT` alongside stroke/weight/dash/fill, so it rides the EXACT SAME sticky-default mechanism every other cloud style field already used (edit it on a selected cloud in Properties → `setSelMarkupCloud`/`liveMarkupCloud` merge the patch into `mkCloudStyle` → the next NEW cloud inherits it). The separate `cloudArcFt` state (and the localStorage keys `planarfit:cloudMode`/`planarfit:cloudArcFt`) is deleted outright rather than kept as a second, now-redundant remembered-default mechanism — one sticky bucket, not two. The Properties panel's Arc size field (presets + custom NumInput, gated `isCloud`) was ALREADY there from B758544 (verified by reading it, not assumed) — this item's job was removing the toolbar's competing copy, not adding a panel copy that didn't exist.
