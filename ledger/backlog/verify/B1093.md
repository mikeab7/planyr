- **Repro (owner, confirmed live before filing).** `sites.data.settings.parcelSelect` was `false` on the owner's plan `smrjdgmlinea` — it had been `true` earlier the same day, so it was flipped at some point without being noticed. Every press on a lot then fell through to a background pan: no selection, no movement, no message.
- **Root cause (AUDIT-FIRST) — the code is behaving exactly as designed; the DESIGN is the trap.** `startMoveParcel` (`SitePlanner.jsx`) carries B311's `if (!settings.parcelSelect) return;` — a deliberate click-through so a lot's edge doesn't swallow clicks during building work. Three properties turn that into a dead end: the flag is **persisted per plan**, so one flip follows the owner across sessions and devices; the only indication was a header pill that, styled as a borderless ghost with muted text in its OFF state, **read as a passive status label**; and the failure itself was **silent at the point of interaction** — nothing where the click happened said why nothing happened.
- **The click-through behaviour is UNCHANGED.** B311 is the point of the mode; this item adds feedback, a discoverable control, and an announcement — it does not make parcels grab clicks again.
- **(1) The readout IS the control.** The pill was already a `<button>`; it now looks and behaves like one — a real pill border and full-contrast chrome text in BOTH states (no muted-text OFF state, per the theming rule), the state spelled out either way (`Select parcels: on` / `Select parcels: off`), `aria-pressed` + an explicit `aria-label`, a "click to turn it on or off" tooltip, and the native `:focus-visible` ring, so Tab-then-Enter operates it. `data-testid="parcel-select-toggle"`.
- **(2) Feedback at the point of failure.** A press that provably lands on a parcel's boundary or setback hit-stroke while selection is off raises a short non-blocking hint on the SAME bottom-center toast surface the canvas already uses — *"Parcel selection is off — that click panned the map."* — with an inline **Turn it on** action and a Dismiss. It rides one notch higher when the existing pill is occupied, so neither message can swallow the other. The decision is a pure, unit-tested module (`lib/parcelSelectHint.js`): never when selection is on, **never on empty canvas**, at most one per press gesture (keyed on the event's `timeStamp`, deliberately NOT `pointerId` — Chromium reuses id 1 for every mouse press, which would suppress the hint forever after the first), and rate-limited so a pan across a subdivision can never become a stream.
- **(3) The keyboard-shortcut question — ANSWERED: there is none, and this is the reported finding.** A full sweep of the planner's keydown handler and the whole repo for `parcelSelect` shows **no shortcut of any kind, modified or bare, that flips it**; the toggle button is the only writer in the codebase. So the owner's flip came from clicking the pill, not from a stray keypress. The mitigation is therefore the other half of the brief: **the toggle now announces itself when flipped** — turning it off flashes *"Select parcels is OFF — clicks pan the map instead of selecting a lot."* — so an accidental flip is visible at the moment it happens instead of surfacing days later as "the app stopped letting me click my parcels". Both the header pill and the hint's inline action route through one `setParcelSelect` helper, so the two can never drift.
- **Guards.** `test/parcelSelectHint.test.js` (17): the decision matrix; a replayed gesture stream proving exactly one hint per press, one hint for a pan across ten lots, one per cooldown window under impatient repeat-clicking, and zero for 25 empty-canvas presses; plus `settings.parcelSelect` round-tripping per plan through the REAL `saveSite`/`loadSite` path (the cross-session trap itself). `e2e/parcel-select-toggle.spec.js` drives the real render path logged out on a drawn parcel at **desktop and narrow width in both light and dark theme**: with selection off a boundary press raises the hint, does NOT select and does NOT move the lot; an empty-canvas press stays silent; repeat presses don't stack; **Turn it on** restores selection and the SAME boundary point then selects; and the pill is keyboard-operable. Press targets are projected through the live SVG screen matrix and then confirmed via `elementsFromPoint`, so the spec can't pass by pressing thin air.
- **Sandbox evidence.** `npm run lint` 0 errors · `npm test` 6056 green (365 files) · `npm run build` green · `node ui-audit/perf-bundle-audit.mjs` green · `MAP.md` + `BACKLOG_OPEN.md` regenerated · `npx playwright test e2e/parcel-select-toggle.spec.js` **5/5** against the branch's own build, plus `clipboard-standards-swatches` / `click-behavior` / `smoke` (17) green over the surfaces the perf fix touched. **Teeth proven:** with the one-line `noteParcelSelectBlocked(e.timeStamp)` call removed and rebuilt, the spec goes RED on the hint assertion — it is a guard, not a decoration.
