### B2019264 — A plotted deed hides its own misclosure: every course draws as written and the gap is its own red dashed line `[site-planner / deed]` (bug) #site-planner #export  *(Owner report 2026-10-02 (NEW-1), verbatim: "The whole purpose is to … draw it exactly like it's written. So if there's an error in the meets and bounds, it gets caught." Real data: Grand Port `smqfy2r7pdec`, "Tract 1 – 94.53 Acres".)*

`[x]` **Cause (AUDIT-FIRST, confirmed against the live rows):** `buildEncumbranceMarkup` dropped the final as-written endpoint whenever `pathCloses` (tolerance up to 50 ft on a ~9,800 ft perimeter) said "closed", so the polygon's implied last→first edge silently absorbed the miss. Dead-reckoning the stored 13 calls gives **31.39 ft** (the surveyor's exhibit shows it); the tract drew as a clean closed shape. Every deed already stores the full as-written path as `centerline`, so no migration is needed. Checked the Align concern against production: `centerline[0]` == `pts[0]` on every Grand Port deed row (incl. the rotated 1.9 copy), and every move/rotate/Align path maps both arrays together — not stale. `deedGap.js` still re-seats a centerline rigidly onto its ring if one ever is.
`[x]` **Fix:** new pure `lib/deedGap.js` (`deedTrace` / `deedGapText`) is the one answer to "what does this deed look like as written". Plot (`buildEncumbranceMarkup`) and render both use it: the ring keeps the last course's true endpoint; the courses stroke as an open polyline; a misclosure above the noise floor draws as its own red dashed `deed-gap` segment (hover title + the panel say "This description does not close — it misses by N ft. The red dashed line is the gap. Precision 1:N"); the fill still closes over the gap so acreage computes. Existing saved deeds render the new way on load from `centerline` — no rewrite. **Noise floor `DEED_GAP_NOISE_FT = 0.05` ft:** distances are stated to 0.01 ft and one second of bearing on a 2,500 ft course is 0.012 ft, so a surveyed-closed tract of a dozen calls can miss by a few hundredths; the ~0.01 ft save-and-except hole draws no gap. `pathCloses` is untouched for promotability ("Use as parcel boundary" still refuses an open traverse, still promotes a sub-tolerance miss and carries `deedMisclosureFt`) and for OCR culprit flagging.
- **Adjacent cases:** exact-closing deed → no gap line, "This description closes." · save-and-except hole missing by 0.01 ft → no gap line (harness known-good arm) · curve as last course → ends at its chord endpoint, gap to POB · rotated/moved (Align) → same gap length (rigid) · open traverse beyond tolerance → all vertices kept, gap shown, promotion refusal unchanged · PDF/PNG export → the sheet clone carries the `deed-gap` line (asserted on the real built sheet). **Easement plotted from a description:** the boundary easement now keeps the last course's endpoint (so the miss is its closing edge, not absorbed) and flashes the miss in words; it does NOT get a separate red line — the easement renderer is a different model and a styled gap there is not built (stated, not claimed).
