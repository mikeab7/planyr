`[x]` **Item 19 — the premise doesn't currently apply, verified by reading the actual export code, not assumed.** Comps and site-plan overlays live in MapFinder, which has NO PDF/print export at all — grepped `exportSheet.js`/`printSheet.js` (the Site Planner's OWN drawing-canvas export — a DIFFERENT workspace, different data: parcels/elements/measurements) for any reference to `site_plan_overlay`: zero matches. MapFinder's only export is KMZ (Google Earth), and `siteToFeatures`/`kmzExport.js` don't include comps either. So there is no existing "printed plan omits the overlay" gap to close — nothing shows the plan without the overlay, because nothing shows the plan in exported form at all yet. Building real PDF/print or comp-aware KMZ support for MapFinder is a NEW CAPABILITY, not a bug fix — genuinely bigger than this session, flagged loudly here per standing instruction rather than either skipped silently or bolted on hastily.
- **Item 20 — the LOW-zoom bound is already correctly implemented (`SITE_PLAN_MIN_ZOOM = 15` in `MapFinder.jsx`, confirmed in code — overlays are filtered out entirely below it, never drawn as an invisible speck).** The HIGH-zoom "blurry wall" concern was investigated and found NOT to be a real defect: `rotatedImageLayer.js` positions a plain `<img>` (confirmed by reading the module), so extreme zoom is the browser's own native image scaling — no re-rasterization, no memory/performance risk — identical, expected behavior to the base aerial imagery or any other raster layer at max zoom. An arbitrary max-zoom cutoff would remove a legitimate use (zooming in close to align a plan precisely with a parcel corner), so none was added.
- **Item 21 — DECIDED, deliberately: hiding an overlay never hides the comps pinned to it.** A comp's lat/lon is real, independent, kept-in-sync data (B978272) — as meaningful as a plain pin or parcel anchor regardless of whether its plan image happens to be showing; hiding it too would destroy information a person might specifically want. What "no context" would actually mean is fixed instead: the comp detail view's "Open source brochure" link is always available (keyed off the FULL overlay list, not the zoom/visibility-filtered one), and now shows an explicit "This plan is currently hidden on the map" note when relevant.
