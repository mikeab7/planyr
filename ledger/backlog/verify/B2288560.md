- **Root cause (measured, not inferred):** the banner is raised only by an outline layer's own health guard in `MapFinder.jsx` (`markDown`, 8 s hang timer; the statewide `onFail`; the 2.5 s "still loading" timer). Turning Select parcels OFF (Cancel, Drop a pin, Draw, flipping to a project) runs `clearDisplays`, which removes the layers **but never cancelled their timers**, and `layerInDrawRange` reads a layer with no `_map` as **in range** ("unknown reads as IN") — so a timer armed seconds before the user left the tool fired later and put the banner up on a map with the tool off. Nothing retracted it either: it outlived the tool until the view left the named county, which at metro zoom is never. The three hypotheses in the brief: (a) a background pre-warm/health probe — **no such probe exists** (displays are built only in select mode); (b) a parcel layer on by default/persisted — **no** (`selectMode` starts false and resets on every map↔plan flip); (c) a sticky state — **yes**, this is it (stale timers + an un-retracted banner).
- **Fix:** `lib/parcelOutageGate.js` is the ONE rule — a parcel banner may be raised only while Select parcels is ON **and** the reporting layer is still a live display **and** it is inside its draw range (`parcelNoticeMayRaise`). Every banner site in `MapFinder.jsx` (county `markDown`, statewide `onFail`, both slow timers) asks it **when it fires**; `clearDisplays` now retracts a banner the tool raised (`retractSourceNotice`, exact-text match, so an unrelated message is untouched). Wording: the generic county text names "statewide outlines" only where a statewide composite exists for that state (`countyOutageMessage`); the B629 cached-copy case is already its own message (`cacheFallbackNotice`, fixed earlier). No new background request, no new probe.
