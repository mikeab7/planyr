- **THE MULTI-STEP MECHANICS — new `undoN`/`redoN`/`recentUndoSteps`/`recentRedoSteps` in `history.js` (not "call `undo()` in a loop").** A component cannot safely call the existing single-step `undo()` N times in a row: `stateRef.current` only refreshes on React's next render, so a synchronous loop would pass the SAME stale `current` to every call, corrupting the redo chain (each call would re-push the pre-run `current` instead of the true intermediate state — verified in a dedicated unit test that reproduces the correct threaded-pivot result and would fail on that naive shape). `undoN`/`redoN` thread the evolving pivot internally and return only the FINAL target snapshot, so the caller applies exactly ONE `applySnapshot`/flush for the whole run — matching how a paste or a multi-object delete already push exactly one frame for the whole action. `recentUndoSteps`/`recentRedoSteps` are the non-destructive peek the dropdown reads from, using the identical `keyOf` no-op dedup `undo()` itself uses (B32), so the rows shown are guaranteed to match what a click actually consumes. 15 new unit tests in `test/history.test.js`, including the exact-pivot proof against a hand-rolled reference implementation.
