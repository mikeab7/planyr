- **The structural change, which is the point.** The surface now renders **instead of** the iframe, not over it. `Scheduler.jsx` hides the embedded Gantt (`visibility: hidden` + `pointer-events: none` + `aria-hidden`) while the empty state applies. `visibility` rather than `display` deliberately: it keeps the iframe's layout box, so the embedded Gantt's width measurements survive and it needs no re-layout on return, and it stays **mounted**, so the ~2 s boot and its nav/toolbar/save bridges are never lost (the keep-alive guarantee). That one change kills three problems at once — no scrim, nothing to dismiss (so **B1065's strand is impossible by construction**), and no "panel covering the dashboard" case, because pressing Dashboard already clears the routed project and the iframe comes straight back.
- **The `section` guard re-derived under the new model.** When the OUTER route points at a project with no linked schedule, the Schedule tab shows the empty state **regardless** of what section the embedded iframe reports — the iframe has nothing useful to show in that state anyway, and gating on it is exactly the second strand diagnosed in B1065. The `ready` and `routedSiteName` gates are kept **exactly** as they were, so nothing flashes before the site list is warm and the raw group id is never surfaced (**B560**).
- **The visual design — restrained, not a form.** No scrim, no raised card, no drop shadow, no border: the empty state sits on the page surface, vertically and horizontally centred, content column capped, generous vertical rhythm. A small muted calendar glyph (thin stroke, no fill, secondary text colour) sits above the text — it reads calm, so it was kept. Headline `No schedule for “{name}”` (the trailing "yet" dropped as filler) at normal weight/size, **not** the previous heaviest weight. One muted subline: `A linked schedule follows this project across tabs.` Then ONE primary action — a filled scheduler-accent **Create schedule** button sized to its content and centred, replacing B1051's full-bleed 100%-width slab.
- **Progressive disclosure instead of dead controls.** The old surface permanently showed an empty `<select>` beside a disabled `Link` button — two dead controls on a first-run screen. Now a quiet borderless text button, `Link an existing schedule`, **reveals the picker in place** (replacing its own trigger, so no dead trigger is left behind) and moves focus into it. When a `suggestedMatch` exists it is promoted to the secondary line as `Link “{name}”`, and the generic link demotes to a smaller tertiary below it. The "Looks like a match" label and the 🔗 emoji are gone — **no emoji anywhere on this surface**, no uppercase eyebrow, no bold section labels. The affordance only renders when there is actually something to link.
- **Accessibility + theming.** No longer a modal, so `role="dialog"` is dropped for a labelled `role="region"` (`No schedule for {name}`). Keyboard order is **Create → Link an existing schedule → (revealed) picker → Link**, asserted in e2e. Theme tokens throughout with light/dark parity (owner rule **B318**); the scheduler accent is spent on the primary action only. **B560's defence is kept verbatim** — `label` still falls back to "this project" and Create stays disabled when `siteName` is missing.
- **Sandbox-verified 2026-07-29, headless Chromium:** screenshots in **light and dark**, at **desktop and narrow** width, across all three content states (no suggested match · with a suggested match · picker revealed), plus a deliberately long project name — no clipping, no overflow, nothing outside the viewport.
