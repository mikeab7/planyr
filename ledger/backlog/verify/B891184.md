**⛔ FOLLOW-UP (2026-08-31, same session-day, owner-driven live production testing on planyr.io) — THE SHIPPED v1's WHOLE DATA MODEL WAS WRONG, AND IT IS FIXED.** A real Excel user drove the shipped build on Goose Creek and reported it plainly: *"its quite awful."* Thirteen defects, in two passes, all fixed this session — none deferred:
1. **THE CORE BUG — formulas were per COLUMN, not per CELL.** Typing `=SUM(A1:A2)` into ONE cell converted the ENTIRE column to that one formula, repeated for every row; the two real numbers already in A1/A2 vanished from view. Root cause: the shipped v1's own justification ("the engine has no A1/cell-reference syntax") went stale mid-session — a **concurrent session shipped real A1 cell references to the same engine** (commit `0d2d1b3e`, "Formula engine: add A1 cell references", merged the same day) — exactly what a pro-forma needs. `lib/sheetModel.js` and `lib/sheetEngine.js` were rewritten: `cells[key]` stores raw text uniformly (a value or a formula, leading `=`), no column-level `formula` field exists any more, and `evaluateSheet` walks a genuine per-CELL dependency graph (topological order + cycle detection across cells, not columns), wiring the engine's new `ctx.grid` from the sheet's own values.
2. **THE SILENT-ZERO REGRESSION — narrowed by the reporter's second pass to its real mechanism: a reference to a REAL, POPULATED cell (`=A1` with A1=500) rendered COMPLETELY BLANK, and inside `SUM` that blank was coerced to 0.** Root cause, confirmed by reading the engine: with no `ctx.grid` ever wired, `readGridCell` returns `undefined` for every A1 reference (its own contract: never a crash, reads as blank) — wiring the grid (fix #1) resolves this AS AN EMERGENT PROPERTY, not a band-aid; verified live (`=A1` → `500`, `=SUM(B1:B2)` with 100/200 → `300`). A SEPARATE real bug found by this session's OWN test suite while proving the fix: a formula referencing ITSELF (`=A1+1` typed into A1) was excluded from its own dependency set by an over-defensive `dk !== key` filter, so it silently computed a plausible wrong number instead of `#CIRC!` — fixed, and a genuinely unresolvable/out-of-bounds token now reports the engine's own real error code (`#NAME?`) instead of a flattened generic `#ERROR!`.
3. **Number format was ALSO per column** — formatting one "Yield on cost" cell as a percent silently repainted every dollar amount already sitting above it in the same column (`250000000.00%`), found building this session's own verification pro-forma. `formats[key]` (sheetModel.js) is now per-CELL, same shape as `cells`; `setNumberFormat` takes a rectangular range, and `NumberFormatPicker`/`ModelApp.jsx` read/write the ACTIVE cell's own format.
4. **Long text hard-clipped** instead of spilling across an empty neighbour (SheetView.jsx: a left-aligned, non-empty cell now extends its display span across consecutive empty cells to its right, `pointer-events:none` so the covered cells stay their own click targets — numbers never spill, matching Excel).
5. **Numbers rendered flush-left like text.** `displayKindFor` (sheetEngine.js) classifies a resolved value's kind; SheetView right-aligns number/date, centers boolean, left-aligns everything else.
6. **Typed dates were plain strings**, so date arithmetic silently failed. `literalTypedValue` now recognizes a typed date (`parseLooseDate`) and returns the engine's DATE typed value; storage still keeps the raw text verbatim for round-tripping.
7. **Copy/paste did nothing.** A new `lib/sheetOps.js` (`copyRange`/`pasteRange`) — an INTERNAL clipboard (not the OS one, a deliberate scope call stated in the file's own header) that shifts a pasted formula's relative A1 references via the engine's own `rewriteFormulaForCopy`, tiles onto a whole-multiple selection (Excel's own paste-tiling rule), and extends the sheet's column count when the paste lands past the last column.
8. **Ctrl+D did nothing.** `fillDown` (sheetOps.js) — same relative-reference shift, applied per row down a selection.
9. **Ctrl+Home / Ctrl+End / Ctrl+Arrow did nothing.** `usedRangeEnd` (sheetModel.js) answers Ctrl+End; `ctrlArrowTarget` (sheetOps.js) is Excel's real 3-branch block-jump rule (blank start → next occupied cell; occupied start + occupied neighbour → last cell of the run; occupied start + blank neighbour → same as blank start), wired into `SheetView.jsx`'s keydown handler.
10. **The toolbar was unreachable at the owner's real 729px browser width** — the number-format picker's own box sat 22.7px past the viewport edge (measured). AppHeader's shared "narrow" mode (≤760px) already turns the toolbar into a horizontal-scroll strip, but with no visible scrollbar and no drag affordance for a MOUSE on a resized desktop window (as opposed to a touch phone) — undiscoverable. Model's own toolbar now shrinks itself at the same breakpoint instead: icon-only Undo/Redo, a `compact` mode on `NumberFormatPicker` (shorter option labels, a narrower fixed width), and "Delete column" (the one rare, borderline-destructive action) moved behind a small "⋯" popover. Measured after: the picker's box is fully inside a 729px viewport, and a REAL pointer click (not a scripted `selectOption`) reaches both it and the "⋯" menu.
11. **Reported "8-column / 200-row hard limits"** — measured: rows already grow past 200 on typing past the end (unchanged, pre-existing `setRaw` behaviour); columns already grow via "Add column" (confirmed live: 5 clicks → 13 headers) and now ALSO grow automatically on a paste that lands past the last column (`ensureColumnCount`). No artificial ceiling found or introduced.
12. **The reported "renderer freeze" (four 30-second screenshot timeouts right after a formula commit) was investigated and PROFILED, not fixed blind, per the explicit instruction not to take the report on faith.** Measured with real CDP timing on a 200-row sheet, one formula commit: **26–27ms** wall time from Enter-press to committed, rendered result — no freeze reproduces under the rewritten architecture. (The old per-column engine's `SUM([Rent])`-style whole-column recompute on every keystroke is also gone by construction now that formulas are per-cell.)
13. **Minor: the Undo button rendered enabled on a fresh page load with existing local data.** Investigated directly (`useUndoableState`'s `past: []` on `reset()` is already correct) and could not be reproduced under the rewritten build — a live-browser regression test now pins "disabled right after a reload with existing data" so a future regression would be caught either way.
