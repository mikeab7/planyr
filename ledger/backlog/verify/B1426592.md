**ROOT CAUSE, traced through the actual code.** `MapFinder.jsx`'s "Select parcels" mode mounts an outline layer for every one of the ~70 configured counties/statewide composites AT ONCE (`Object.keys(layerUrlsRef.current).forEach(addDisplay)`), regardless of where the map is currently looking — there is no per-county gate on relevance, only a zoom gate (parcel-selectable zoom or above). When a county's own live CAD host hangs or errors, `addDisplay`'s hang-guard (`markDown`) fires and calls `setErr(cacheFallbackNotice(key))` (or a generic "that county's server is slow" message) — attributing the banner to whichever county's layer happened to fail, with **no check that the county is anywhere near the current viewport**, and **no mechanism anywhere that re-evaluates the banner as the map is subsequently panned**. So a county whose CAD host is genuinely down can plant a banner naming it at whatever location the user happened to be looking at the moment select mode was turned on (or the moment a stale, still-mounted layer's periodic re-query finally times out) — and that banner then sits there, unconditionally, until the user's next parcel click resets it. Reproduced deterministically (see RED-PROOF): flying to Chambers's own area, then forcing Chambers's CCAD down, correctly shows the Chambers banner (it's genuinely relevant there) — but flying away afterward to Texarkana, 300 miles off, with no other interaction, the SAME banner stays on screen, verbatim, exactly as the owner reported.

**THE FIX — a plausibility gate at both ends, not a suppression of the notice class.** `counties.js` gains one new pure function, `countyBboxIntersectsView(key, bounds)`: an axis-aligned overlap test between the current viewport bounds and the named county's own (already-padded) `bbox` — the same coarse screen `candidateCountiesForPoint` already uses for click routing, asked from the other side. `MapFinder.jsx` wires this at both ends of the notice's life: **(1)** before showing a county-outage banner (`setSourceNotice`, the one place all three county-outage messages now go through), it checks plausibility and simply doesn't show the banner if the county named is nowhere near the current view — never a corrected-but-still-wrong location, never a generic substitute, matching the brief's own EXPECTED behavior; **(2)** on every map `moveend` (`onMove`, the same handler that already re-derives the Layers-panel jurisdiction on every pan), it re-checks whatever notice is currently on screen and retracts it the instant the view no longer plausibly contains the county it names — gated on the visible text still being EXACTLY what was last set (`sourceNoticeRef`), so an unrelated message set by anything else in between (an address-search failure, a share error, a locate error…) is never touched by this mechanism. The statewide composite's own "Statewide parcel outlines are slow" banner (unnamed, but scoped to one STATE) gets the same treatment at the state level, using the existing TX/CO `siteState` envelope check — a Texas-statewide banner no longer survives a pan into Colorado or vice versa.
