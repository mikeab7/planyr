- **ROOT CAUSE, traced into Leaflet's own vendored source (`node_modules/leaflet/dist/leaflet-src.js`), then MEASURED — never stopped at the theory, per the brief's own explicit instruction to verify before fixing.** `CircleMarker.setRadius()` — what B707841's per-frame compensation loop called every animation frame to counteract Leaflet's own ambient CSS zoom transform — is NOT radius-only: `Path.prototype.redraw()` → `Canvas.prototype._updatePath()` unconditionally calls `layer._project()` (line 12746 of the vendored source), which RECOMPUTES the marker's screen position from the map's current (already-jumped-to-final, confirmed via `Map.prototype._animateZoom`/`_move`) zoom, before repainting. That freshly-correct position then gets Leaflet's OWN ambient transform applied on top a SECOND time — `Renderer.prototype._onAnimZoom` re-applies `_updateTransform` on every `'zoomanim'` frame too (line 12513), computed from the renderer's own last-settled `_zoom`/`_center`. A genuine double transform, not a guess.
- **CONFIRMED WITH REAL, GROUND-TRUTH PIXEL MEASUREMENT, exactly as instructed ("instrument it... report the measured deltas").** `.scratch-repro/verify-marker-position.mjs` (this session): a real headless Chromium build, real Leaflet, the real `FoodMap` component, synthetic markers at the owner's ACTUAL Austin-area cluster (queried live against production: 11 places, lat 30.2627–30.2957, lon -97.7419/-97.7497) plus Dallas and San Antonio test points at different distances/directions from Houston (his `DEFAULT_CENTER` and where his selected place sits). Measured each tracked marker's drawn canvas pixel position against `map.latLngToContainerPoint()` for the same lat/lon, sampled DURING real animated zooms (both the +/- control buttons — clean single-step animated zooms — and a real multi-touch pinch via raw CDP `Input.dispatchTouchEvent`, matching his actual mobile gesture). **Mid-animation deltas of 100–300px+** while the container's live `getComputedStyle().transform` was measurably non-identity; the **distance signature the owner's own hypothesis named held up**: the farther test point (Dallas) consistently showed a larger error than the closer one (San Antonio) at matching sample times, across multiple independent samples. **After the gesture fully settles, the same markers measured within ~0.7px of correct** — so this is a mid-animation-only artifact, not a resting-state one (the owner's own retraction/correction was right), but a real one: a tap during that window could open the wrong place's panel.
- **THE FIX, per the owner's own explicit instruction ("Michael would rather have a pin that pops than a pin that lies"): REVERT to transform-then-settle, not a clever in-place repair.** A "reproject every frame AND neutralise the stale ambient transform on the frames that do" fix was considered — it would have preserved the smooth continuous sizing — but its correctness depends on getting the interaction with B707841's own skip-frame/bail perf-degrade tiers exactly right in every case, which could not be fully verified in the time available; the risk of shipping a new, subtler position bug outweighed the sizing polish this session. Markers are no longer touched at all during the animation — Leaflet's own ambient CSS transform alone carries them, visually correct by construction, settling to true position/radius in one step at `zoomend`/`_reset()`, exactly Leaflet's stock, unmodified `CircleMarker` behaviour. The pre-B707841 "pop" is back; a wrong resting position never existed and a wrong mid-animation SIZE is a correctness-neutral cosmetic regression, not a new defect.
