`[ ]` **Implemented — see V1829360 for the live check (Verify: live — panel-width-dependent layout, measured on the deployed build).**
- **Cause.** `PairedField` / `PairedFieldHead` laid the value columns out as `64px 1fr 1fr`, so each half grew with the panel; the measurement panel's weight box was the older non-boxed `NumInput` (an `<input>` with `width: 100%` and its ▲▼ as a separate pair), so the box stretched and its stepper rode the far edge of the (now huge) cell.
- **Fix, in the shared primitives only (not per call site).** One constant `PROP_VALUE_W` (92) → `PROP_PAIR_COLS` = `64px repeat(2, minmax(0, 92px))`, read by `PairedField`, `PairedFieldHead` and the dock-layer panel's own grid; `minmax(0, W)` means a narrow panel still shrinks the columns instead of overflowing. `Field` caps its value cell to the same width when its only child is a `NumInput` / `PercentField` / `<select>` (`isCompactControl`; only the default gutter — the road and dock panels size their own boxes). `RotationField`'s number box is capped too. Extra panel width is now empty space on the right; a number box and its ▲▼ are one frame (`NumberBox`) and stay touching. The phone bottom sheet raises the ceiling through `--prop-value-w` (136) because its steppers are touch-sized, so the sheet still fits.
