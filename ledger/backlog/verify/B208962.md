`[ ]` **⏳ Shipped this session; V10609 PENDING.** `planyr.io/#/markup` opened full screen with no logo, no Dashboard or project breadcrumb and none of the Site / Schedule / Review / Library / Notes tabs. The only exit was a "‹ Single sheet" link, which does not read as "get me out of here".
- Verify: live
- Origin: filed 2026-08-06 from chat
- **Cause.** `DocReview.jsx` had `if (mode === "stitch") return <Stitcher/>` ABOVE its `<AppHeader>`. Resuming a saved stitch — which is what that URL does when the last document reviewed was one (`resolveResume`, B667) — therefore dropped you into a component that renders its own toolbar and nothing else.
- **THE FIX.** Stitch is now a BODY inside the same shell every other module renders: same header, same breadcrumb, same module tabs, same Library door, plus an explicitly labelled **‹ Exit Stitch** in the tool row (the Stitcher's own back-link is dropped when `chromed`, so there is one exit, not two). `saveState` is deliberately omitted from that header — the stitch's save state belongs to the Stitcher's own persistence hook, which renders its own badge; a header badge there would report the SINGLE-SHEET review's state over a stitch, which is worse than showing none.
- **Guards.** e2e **stitch-row-adds-a-sheet**: the module tabs are visible from inside Stitch; ‹ Exit Stitch is visible AND pressing it leaves stitch mode into the single-sheet view; and a module tab actually navigates out of Review entirely (`aria-current="page"` on the Site tab). Mutation-checked: all three fail on the old build. Live: V10609 — the owner's own resumed-stitch landing.
