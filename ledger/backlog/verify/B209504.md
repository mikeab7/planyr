- **femaEbfe — the 400 is the PROBE, not the layer.** It is a `raster-identify` row: a `/query` against a MapServer raster layer 400s by design, which is what a generic probe issues. The app reads it via `/identify` on sublayers 20/24 (B882's own note records live values 154.8 / 156.0 ft at Tsakiris). Its host `txgeo.usgs.gov` is egress-blocked from this build, so the app path could not be re-confirmed here → **V17705**.

Totals: 47,358 substations · 19,559 airports · 302,771 rail segments, all nationally complete. **The reported zeros came from a uniform small envelope, not from dead layers** — each of these is a proximity source with its own buffer, and a 1 km box is smaller than every one of them.
- **epaCleanups — honestly absent, and the fixture set was the real bug.** 64,000 features; answers in Dallas (19), El Paso (13), Denver (6), Chicago (8), Atlanta (14), Newark (8). "Absent within 1 mi" was the correct answer — but one Pasadena fixture could never have distinguished that from a dead layer, which is exactly the owner's point and is fixed in **B209505**.
- **pipelines — alive** (492,329 segments; 7·0·2·11·0·24 at 1 km, 469·64·236·90·282·469 at 5 km). It is a "crosses the site" intersect, not a proximity buffer, so a zero means no permitted route crosses that footprint.
