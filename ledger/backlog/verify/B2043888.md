### B2043888 — Module tab-strip chevrons: page by an absolute clamped target, snap flush to each end, stay truthful after smooth scroll / rubber-band `[nav / app shell]` (bug) #mobile #ui  *(Owner chat block NAV-ARROWS 2026-10-03, iPhone Safari, planyr.io Map with no project)*

`[x]` **Report:** the phone's module tab strip (Site, Schedule, …) has a ">" chevron; after scrolling, tapping the LEFT arrow "took him too far over" — Site sitting in from the left with empty space beside it and the left arrow gone.
`[x]` **AUDIT-FIRST / WRONG-CASE — said plainly: NOT reproducible in the sandbox, in either engine.** The old code (`el.scrollBy({left: dir*0.72*clientWidth, behavior:"smooth"})`) landed at exactly 0 / max in Chromium AND WebKit at 390 and 430 wide (the new harness is green on the unfixed tree; no red-first was possible). Measured: the strips only overflow by 29–100 CSS px, so any tap crosses the whole overflow. The owner's screenshot (arrow gone while the first tab sits inset from the edge) matches an **iOS elastic overscroll** — scrollLeft < 0 during a rubber-band, which the old `scrollLeft > 1` test counts as "at the start" — plus a relative `scrollBy` that stacks deltas when taps land inside one smooth animation. Neither is observable headless; **this is a hardening of the plausible mechanisms, not a proven fix**, and it is parked ⏳ with a live phone check rather than closed (STANDING RULE #2: not closed on a null).
`[x]` **Fix (one shared helper, `src/shared/ui/scrollStrip.js`):** `pageTarget` — an ABSOLUTE target clamped to [0, max], one screenful minus a tab, snapped flush to the edge when under half a page would remain; `pageStrip` chains rapid taps from the in-flight target; `edgeState` clamps scrollLeft into [0, max] before deciding (rubber-band reads as the end); `observeStripEdges` re-reads on scroll, `scrollend`, a 140 ms settle after the last scroll event (Safari without `scrollend`), resize of the strip/children, and tab-set changes (MutationObserver). `AppHeader.jsx` row 1 and row 2 both use it (they are the only strips with prev/next chevrons — audited: `model/TabStrip`, schedule tabs, site sub-tabs and pill rows have none). `.no-hscrollbar` gains `overscroll-behavior-x: contain`.
`[x]` **Tests:** `test/scrollStrip.test.js` (6) · `test/headerScrollAffordance.test.js` re-aimed (no `scrollBy`) · `ui-audit/verify-nav-arrows.mjs` (390 + 430 phone, 1280 desktop known-good arm = zero chevrons; taps to the end and back, asserts scrollLeft == max / 0 and first/last tab unclipped, stacked taps, arrows truthful after settle; `ENGINE=webkit` selects WebKit) — 31/31 on both engines.
