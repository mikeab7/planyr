- **THE BANNER WAS A SELF-INFLICTED FALSE ALARM.** Because `co_larimer.layerUrl` was byte-identical to `co_statewide.layerUrl`, `MapFinder.addDisplay` — which keys its display map by COUNTY — added **two identical Leaflet layers over the same ground**, doubling every request to the slowest host in the app. And `STATEWIDE_KEYS` is derived from the `statewide: true` flag on the KEY, so `co_statewide` was exempt from the 8 s hang-guard while `co_larimer` — the same URL — was not. The guard fired on the county-keyed copy, `markDown` pulled the layer, `recordSourceResult` opened the breaker, and the banner told the owner his county server was slow **while pointing him at the exact host it had just declared dead**. Two health policies on one endpoint.
- **FIXED STRUCTURALLY, TWICE, AND NEITHER FIX MENTIONS LARIMER:**
  - **(a) Displays dedupe by RESOLVED URL, not by county key.** A key that resolves to an endpoint already on the map becomes an ALIAS of the layer that is there. `displaySrcRef` records `{url, owner}` per key; an alias drops only its own reference on removal, removing the OWNER drops every alias pointing at it, `clearDisplays` removes each shared layer once, and `optimisticHitAt` walks each layer's features once instead of twice.
  - **(b) The hang-guard exemption keys off the URL.** `isStatewideLayerUrl(url)` replaces `STATEWIDE_KEYS.includes(key)`: if the endpoint IS the universal fallback it gets the universal fallback's policy, whichever key asked for it. `optimisticHitAt`'s "is this a REAL county CAD hit" answer moved to the same test — a county drawing COMPOSITE features scores as a statewide-backup hit however its key is spelled, so a genuine neighbouring CAD hit correctly wins over it.
- **THIS WAS NEVER LARIMER-ONLY, WHICH IS WHY IT SHIPS ANYWAY.** **Waller** has carried the identical shape in Texas since B629 (its primary IS the TxGIO composite), and the four Colorado counties above still do. Waller was masked only while its Drive snapshot happened to be loaded; with no snapshot it fell straight through to a second TxGIO image layer WITH a hang-guard on it.
- **AND THE NEXT ONE IS BLOCKED.** `sharedLayerUrlConflicts()` is a pure assertion that no two `COUNTIES_MAP` entries share a **non-statewide** layer URL — sharing a COMPOSITE is the sanctioned parking pattern and stays legal, because after (a) and (b) it is genuinely harmless. It runs as a named `console.error` in dev (LOUD-FAILURE) and as a CI test, so a county parked on a composite in future cannot reintroduce this.
