`[ ]` **⏳ Shipped this session; V10608 PENDING.** The status bar showed "Rendering…" permanently, unchanged after 20+ seconds, with an empty canvas and nothing ever appearing.
- Verify: live
- Origin: filed 2026-08-06 from chat
- **Cause.** The bar rendered `{err || "Rendering…"}` off a bare `busy` boolean. One string, no phase, no count, no name — so it could not move, and it could not distinguish "working" from "wedged". Because `loadStitch` committed nothing until the end (B208960), the canvas behind it was empty for the same window, which is what made it read as a hang.
- **THE FIX.** One honest status model: `prog = { phase, done, total, name }` and `loadStatusLine` (pure, unit-locked) — "Fetching saved drawings 2 of 3… (E2E SET.pdf)", "Drawing the saved set — sheet 4 of 8…", "Adding A227…". It counts, so a long job visibly moves; and it is ABSENT when nothing is happening, so it can never outlive the work it names. The bar carries `data-phase` for assertion.
- **Guards.** Unit: `test/stitchLoadState.test.js` — including the old bug in one assertion (the line at done=0 and done=3 must DIFFER). e2e: **stitch-row-adds-a-sheet** asserts the bar settles to gone/idle/error after a real add and that the literal string "Rendering…" is nowhere on the page.
