- **What was wrong.** Visibility was `dimCalloutVisible(labelPpf)` — ONE global zoom floor, no per-object and no user control. A survey-scale note and a headline site area therefore revealed and vanished together, at a threshold nobody could reach.
- **THE CONTROL IS A CAPTURE, NOT A NUMBER (the owner rule that shaped it).** A px-per-foot figure means nothing to a reader, so it is never typed and never shown. You zoom to where you want the label to start appearing and click **Set at current zoom** once; the panel reads the pinned value back as a NAMED band — *"Shows from Working zoom in"* — plus **Reset to default**. Bands (`zoomBandLabel`): Region · Whole site · Site overview · Working zoom · Close in · Detail.
- **Two levels, the same one-click control.** Per-measurement in its Properties, and a project-wide default in **Standards → Measurements**, which a new measurement is stamped with and which the footer's one Apply pushes onto measurements already drawn. The ladder is built-in floor < account default < project default < the measurement's own pin.
- **The existing global floor stays the default**, so a plan that pins nothing renders exactly as it did — the B939/B942 declutter is untouched.
- **A SELECTED measurement always shows its label**, whatever the threshold says. That is what the code already did and it is right: you must be able to read what you are editing (the same exception B149 / B121 / B225–B226 make).
- **Code.** `lib/measureStyle.js` (`measureLabelThreshold` / `measureLabelVisible` / `hasLabelThreshold` / `zoomBandLabel` / `labelRevealNote`, all pure); the render gate in `SitePlanner.jsx`; `labelPpf` travels with the style keys so it is stamped, defaulted and retroactively applied by the same machinery.
