- **The fix, at the root rather than as two symptom patches.** ONE pure rule — `lib/dogEar.js` `sideParkAlongRun` — shared by the canvas refit and the load-time heal, so they cannot answer *"is this run user intent?"* differently: **a run LONGER than the wall it hugs is never intent, it is staleness** (every gesture that can set one clamps it to the wall, so an over-length run can only have come from a longer host), and only a gesture aimed AT THAT FIELD (`pinAllowed`, B1123's `userResize` by another name) may pin one. A host refit, a duplicate, a relayout and the heal all pass false and are structurally incapable of stamping.
- **The load-time heal, so his existing plan corrects itself on open.** `siteModel.normalizeHostRuns` (new, in `normalizeBondedChildren`, so BOTH read paths run it — the blob and the `site_elements` rows) re-lays any dock-zone chain member or side-parking row whose along-wall run outruns its host, through the same pure `layoutZoneByKind` / `wallKidBox` the canvas uses, and drops an `alongLen` or a `sideParkFit` that names an impossible length. A run that FITS is left completely alone, so the owner's hand-positioned fields (B1039's fire-lane curb return) still survive every load. The repairs ride the existing B1118 `exempt` set, so they diff and COMMIT rather than being adopted straight back over by the torn rows.
