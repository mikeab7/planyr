`[x]` **FIXED THIS SESSION — three distinct reflow mechanisms, one per surface, none of them a widened grace window or a suppressed event (the brief's explicit non-goal).**
  - **Dashboard** (`src/workspaces/dashboard/Dashboard.jsx` + `components/DashboardCards.jsx`): each of the four cards used to reveal its own real content the moment its own data source resolved, independently — a fast card (e.g. "Pursuits by activity") showed its final rows first, then a slower card (e.g. "Schedule health") swapped from its short placeholder to several real rows a beat later and pushed every card in a later grid row down the page, out from under an already-pressed row. Fix: a new `dataReady` flag gates ALL four card renderers behind a single `Promise.allSettled` over every source; until every source has answered, every card shows the same fixed-height skeleton (new `CardSkeleton`), then all six cards swap to real content in one synchronized paint. Nothing can grow later out from under an already-rendered row.
  - **Site Planner header — the project/plan crumb** (`src/app/Shell.jsx` + `src/app/AccountControl.jsx`): the header's account pill starts every load not knowing whether the visitor is signed in (`user` is `null` until Supabase's auth listener reports back, which always costs one paint and, whenever the cached session needs a token refresh, a real network round trip) — that null state rendered the narrow "Sign in" pill, which then swapped to the wider, real named pill the moment auth resolved. Row 1's right-anchored account zone growing squeezed the shrinkable project-crumb zone next to it via plain flexbox, moving a crumb the owner may already be pressing. Fix: a new `authKnown` flag holds a neutral placeholder — deliberately forced wide enough to hit `MenuTrigger`'s own hard 220px ceiling from the very first paint — until auth is known, so the eventual real pill (also capped at 220) can only ever shrink that zone or leave it unchanged, never grow it.
  - **Scheduler's lifted toolbar** (`src/workspaces/scheduler/components/ScheduleToolbar.jsx` + `Scheduler.jsx`): the embedded Gantt app reports its state to the shared header over `postMessage`, and two pieces of the toolbar used to mount conditionally as fields resolved at different times — the unread-review-count badge only mounted once a count arrived a beat after the rest of the toolbar, widening a centered group and re-centering everything in it (sliding "Grid" sideways); the zoom control block only mounted once a ~2.5s fallback timer's incomplete first report was superseded by the real one confirming the view was zoomable, inserting a whole new control in front of "Version history" and pushing it sideways. A third, smaller cause — the row's minimum height was set below one control's actual rendered height, so the row itself grew a couple of pixels the first time that control mounted, nudging everything vertically. Fix: the badge's box is always reserved (visibility, never mount/unmount) since it can grow at any time in a live session; the zoom block is reserved only until the first *real* toolbar report lands (a new `toolbar.settled` flag, distinct from the bare fallback); the row's own minimum height was raised to match the tallest control it ever holds.
  - **Explicitly did NOT do:** widen clickDiag's 900ms grace window, or suppress/filter the `event:click-swallowed` report — per the brief, both would hide the symptom rather than fix the reflow.
