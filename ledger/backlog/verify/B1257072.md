- **THE GENERAL LESSON, carried here so it isn't repeated:** when a brief asks for "a way to do X," check whether the app already has one before building a second. A duplicated control is worse than the bug it was added to solve, because now there are two things to keep in sync and the user has to guess which one is real.
- **The fix (`public/sequence/index.html`):** `PhonePaneSwitcher` (the component, its render call site, and its explanatory comments) deleted outright. The header's existing Grid/Split/Gantt pill's `onClick` and active-tab highlight are now phone-Split-aware: computed once as `inPhoneSplit = isMobile && data.view === "split"`. While `inPhoneSplit`, tapping Grid or Gantt calls `setPhonePane(v)` (the SAME state B1241745 already introduced, kept verbatim) INSTEAD of writing `data.view` — so Split is never actually left, and a session that later widens past 768px (or a desktop teammate on the same project) still opens on the real two-pane Split with nothing forgotten. Tapping Split itself, or any tap outside `inPhoneSplit` (desktop width, or already on plain Grid/Gantt), is the pill's ORIGINAL, untouched behavior: a direct `setData(d=>({...d,view:v}))`. The active/highlighted tab always matches what's actually on screen — while `inPhoneSplit`, "Split" itself never highlights (the screen is showing Grid or Gantt full-width, not a two-pane split; highlighting "Split" would misdescribe the content), Grid/Gantt highlight by matching `phonePane`.
- **A DISCLOSED PRODUCT QUESTION, not papered over, per the brief's own instruction:** with the second pill gone, Split at phone width is now visually and functionally INDISTINGUISHABLE from picking Grid or Gantt directly — same content, same highlighted tab — differing only in what `data.view` remembers for a wider screen. Tapping "Split" while already viewing its default (Grid) pane is now a genuine no-op on screen (nothing visibly changes), which is arguably a softer echo of the ORIGINAL "the Split button doesn't do anything" complaint. Michael may decide Split shouldn't even appear as a pill option on a phone at all — that product call is his, not made here.
