`[ ]` **⏳ merged — V1549536 PENDING (Verify: live).** The grid now keeps its identity and its controls on screen at any width.
- **MEASURED FIRST (as the test account, PR-less baseline = production `93f7114` + the same page served locally), not assumed.** With the owner's column set (ID Task Start Finish Dur Predecessor Successor ●) and user-widened columns at a 960-wide window the ● column sat at 1098–1134 — **off screen** — and after scrolling right ID/Task scrolled away (id.l = −172). **The horizontal scrollbar he saw belongs to the GRID, not the page**: `document.scrollWidth == clientWidth` at every width, before and after (pageContainmentGuard holds; nothing escapes the layout). So "sideways scrolling happens inside the grid only" was already true — what was missing was any frozen column. **Frozen-column support: none existed** (checked `GridView` — no sticky cells).
- **Fix (inside `GridView`, `public/sequence/index.html`).** ID + Task (the leading run) are `position:sticky` left; a trailing ●/Status run is sticky right; pinned cells paint an opaque layered background (row colour, then range/cell fill, over `--bg`) with a subtle inside edge that appears only while content is actually scrolled under it. The pane's own width comes from a `ResizeObserver` on the grid box (÷ grid zoom), so **Split's pane at any divider position** sizes by itself, never by the window. The **Task column's DISPLAY width is capped at ~half the pane** (min 100); the saved/resized width, `onColWidths` and the Split-divider snap still use the real width, so widening the window gives the user's width back. Pins switch off when they would eat >80% of a tiny pane. The "⋯" columns button steps left of the pinned-right group instead of sitting on the ● header. Keyboard navigation's horizontal reveal now scrolls a cell out from under the pins (in display widths; also corrects a pre-existing 2 px offset from the row's left border). Task name has a tooltip. Header cells carry `data-hdr-col`.
- **Where ● is NOT pinned (by design, said plainly).** The ●/Status columns pin only while they are the TRAILING run of columns (the owner's set, and the shape he screenshotted). In the stock twelve-column order they sit mid-table, so they scroll like any column and the contract there is "the last column can be scrolled fully into view" — forcing them to the far right would move every user's columns.
