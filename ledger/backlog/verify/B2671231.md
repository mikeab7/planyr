- **ROOT CAUSE (code-read, AUDIT-FIRST; the exact production trigger was NOT reproduced — the sandbox cannot make the owner's token refresh fail on demand — so the fix is built on the mechanism, and the live check below is what confirms it):** `cloudSync.cloudCheckDeleted` answered `exists:false` ("This project doesn't exist") on the FIRST empty read. supabase-js sends the ANONYMOUS key whenever it cannot hand back a usable session (a token refresh that failed on a slow / dropped connection, a tab that just regained focus with an expired token — `_getAccessToken` falls back to `supabaseKey`), and row-level security answers an anonymous read with ZERO rows and NO error, byte-for-byte what a really-deleted project returns. `Shell.jsx` re-asks the gate on every tab focus / visibility change (B1953796), so the card appeared and, on the next good read, went away "on its own". Second gap: the gate effect did not depend on the session, so a check asked before sign-in (fails open, no uid) was not asked again until the tab next regained focus.
- **THE FIX:** an empty answer is believed ONLY when (1) the client's own session is the caller's and not about to lapse (`sessionProves`) and (2) a second read taken after that proof is empty too; otherwise `ok:false` (inconclusive) → `projectGateStatus` fails OPEN → the workspace stays mounted, no card. A read that errors, times out, 403s, or returns no rows array is inconclusive by the same path. A positive answer (rows came back) costs no extra round trip. The Shell gate effect now also depends on `authKnown` + the signed-in user id, so it re-asks once the session settles. A genuinely unknown / hard-deleted id (proven session, two empty reads) still shows the card; a locally-minted id (B1202176) and a soft-deleted project (Restore) are unchanged. Every other caller of `cloudCheckDeleted` (30-day purge, folder purge, delete confirm) already treats `ok:false` as "keep".
