- **Report.** *"I don't even have the option to bring it to the front. I think it makes sense to be able to bring the overlay to the front."*
- **THE DEFAULT IS UNCHANGED, deliberately.** A reference still draws BELOW the plan unless you say otherwise. The audit did not show the default to be wrong: the ordinary job is tracing over a scanned plan or a survey, where your own property line and massing have to stay legible on top of it — which is exactly why this is a control rather than a new fixed default, as the item instructed. The uncommon case (a finished land-plan exhibit you are working ON, where the parcel line across it is what's in the way) is the opt-in.
- **The model — two BANDS, not a free interleave.** New pure `lib/overlayOrder.js`: every reference is either `below` the plan (default) or explicitly `above` it (`aboveParcel: true` on the record). The array IS the draw order, bottom → top, and every mutator keeps it band-grouped, so a legacy plan with no `aboveParcel` anywhere is trivially grouped and byte-unchanged. Two bands rather than arbitrary interleaving because the plan's own internal stacking (roads → pads → buildings → markups) is a separate, already-solved ordering: a reference only ever needs to be behind all of it or in front of all of it.
- **Bring to front / Send to back now move within the reference's OWN band**, and are greyed at the ends of it. Crossing the plan is only ever the explicit toggle — otherwise "bring to front" would silently lift a backdrop over the property line, which is the thing the default exists to prevent. A promoted reference lands at the front of its new band (you promoted it to see it).
- **Surfaced twice, from one engine:** a **"Draw above the plan"** checkbox in the References panel's per-reference controls, and a **Draw above / below the plan** entry in the overlay right-click menu. Persisted on the reference record, so it rides the same save/sync path as every other overlay field, survives a reload, and syncs cross-device; it is in the undo signature, so promoting a reference is its own undo frame (as `visible` already was).
- **The stacking order is now visible without opening a menu:** the References list is ordered **front-most first** (the way every layers panel reads), with one short line saying so when there is more than one reference. Ordering is stable and predictable with several stacked — the panel order is derived from the same array the canvas paints.
- **Verified here.** `test/overlayOrder.test.js` (33 cases): the default and the "only a literal `true` promotes" rule, band splitting and the grouped-array invariant, identity-return on an already-grouped list and on every no-op mutation (so a no-op costs no undo frame), front/back confined to a band, promote/demote landing at the band front, no mutation of the moved record, and never inventing / dropping / duplicating one. The e2e spec drives the real thing: default UNDER the parcel (asserted by document position, not by eye), the checkbox lifts it OVER, the grips still win the hit test from the promoted band, and the flag is in the saved plan. lint 0 · 6,820 tests · build green.
