`[x]` **IMPLEMENTED THIS SESSION.** The Dashboard's card grid (`src/workspaces/dashboard/Dashboard.jsx`) now runs on **react-grid-layout 1.5.4** (MIT license; pulls `react-draggable` + `react-resizable`, also MIT) instead of hand-rolled native drag-and-drop:
- **Drag by the header only.** Each card's title row carries a `dashboard-card-drag-handle` class, and `draggableHandle=".dashboard-card-drag-handle"` scopes react-grid-layout's drag detection to it — the remove (×) button is a sibling outside that class so it never gets swallowed by a drag-start. The card BODY is a separate `overflow: auto` region (`DashboardCard.jsx`), so a long list (Needs attention, Pursuits) stays scrollable in Customize mode instead of the whole card panning.
- **Resize from the bottom-right corner only** (`resizeHandles={["se"]}`), free-form (not the old binary toggle) — width and height both drag independently in grid units. Each card type carries its own `minW`/`minH` in `CARD_DEFS` (`dashboardLayout.js`) so it can never be crushed to unreadable (e.g. the Pursuits table's four columns need real width: `minW: 5`; a compact stat card needs much less: `minW: 3`). React-grid-layout enforces the minimum live during the drag.
- **Remove** (header ×, Customize mode only) drops the card from the layout array — never destroyed, it reappears in the **Add a card** picker (the existing inline chip list, kept — every catalog card not currently placed, always visible while customizing).
- **Reset layout** (new control, next to Customize/Done) restores the shipped default arrangement (`resetLayout()`), computed once from a pure row-major pack over each card's own default size — not hand-typed coordinates.
- **Responsive, without react-grid-layout's own multi-breakpoint machinery:** the Dashboard measures its own grid container width (a `ResizeObserver`, same pattern `NeedsAttentionCard.jsx` already used for its own bar-drop breakpoint) and below 640px CSS pixels **does not mount react-grid-layout at all** — it renders a plain flex column stack instead, ordered top-to-bottom/left-to-right by the desktop grid's own x/y (`narrowOrder()`, never by array storage order, which stopped carrying meaning once cards have real positions). "Do not let a phone drag-resize a grid it cannot see" is satisfied structurally: there is no grid there to drag. Remove/Add/Reset stay live at any width — only the drag/resize gesture is width-gated (`showDragHandle={!isNarrow}` on every card; no `dashboard-card-drag-handle` class exists in the DOM at all below the breakpoint, confirmed live below).

- **Data model rework, not just the UI:** `dashboardLayout.js`'s stored shape changed from an ORDERED array of `{key, size: "normal"|"wide"}` (array position = screen position; one binary size) to an array of `{key, x, y, w, h}` (real grid-unit position/size, react-grid-layout's own onLayoutChange shape, round-tripped with no translation via `applyGridChange`/`toRglItem`). **A saved layout in the OLD shape is migrated automatically, transparently, the first time it's read** — `normalizeLayout()` detects "no entry carries numeric x/y/w/h" and re-packs the saved CARD ORDER through the same row-major packer the default layout uses, so an old save keeps its arrangement's intent rather than silently resetting to default. Per the brief: **a card type that no longer exists is dropped silently** (unknown keys filtered before anything else runs, both shapes) and **card sizes/minimums live in code (`CARD_DEFS`), never in the saved data** — adding a ninth card type tomorrow needs no migration of anyone's stored layout, it just doesn't appear in an old save until added from the picker. `dashboardPrefs.js` (the Supabase `profiles.prefs.dashboardLayout` read-modify-write + localStorage mirror) needed **zero changes** — it already called `normalizeLayout()` generically on every read/write, so the migration is transparent to it.
- **Never a blank grid.** `normalizeLayout(null | undefined | [] | garbage)` always falls back to the full default catalog (`resetLayout()`), same guarantee the original release made, now re-proven for the new shape.
