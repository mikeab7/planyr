### B1976336 — Map "Select parcels" outlines query every parcel source in the country for every tile `[map-finder]` (bug) #site-planner #gis #parcel #perf *(Owner report 2026-09-29, Bartow County GA / Cartersville: outlines vanish / half-draw on zoom, grey imagery. Measured live on build 6df9a60: 408 `/query` requests in ~8 s for one zoom step, 65 services, 6 per service. **DEDUPE-FIRST:** this is the display-path twin of **B1457152** (archived) — that item's fix narrowed only the CLICK/identify path (`candidateCountiesForPoint`); the display path `Object.keys(layerUrlsRef.current).forEach(addDisplay)` was never touched, so this is NOT a regression of it, it is the half it did not cover. B1457152 amended in place below.)*

`[x]` **Root cause:** select mode called `addDisplay` for every resolved source in `COUNTIES_MAP` (175 keys), with no viewport test, and never removed any on pan/zoom; every layer also contributes its attribution string (hence Harris/TxGIO credits on a Georgia map).
`[x]` **Fix:** new pure `displaySourcesForView(bounds)` in `lib/counties.js` — per-county sources qualify only if their registered bbox intersects the view (`countyBboxIntersectsView`); statewide composites only for a state actually in view (sample grid through `candidateCountiesForPoint`, same nationwide geometry as clicks). `MapFinder.jsx` `syncDisplaysToView` runs on entering select mode, on each source's URL resolving, and on debounced `moveend`; layers that left the view are `removeDisplay`ed (drops their tile work and attribution) and `addDisplay` refuses any source outside the wanted set. B137 preserved: display now uses the same state narrowing as the click path.
`[x]` **Adjacent cases (asserted):** Texas/Harris view → TX sources only incl. TxGIO · Colorado view → CO only · Augusta GA/SC state-line view → GA+SC only · open ocean → `[]` (never "everything") · a zoom-out step from Bartow stays GA-only. Georgia has no statewide composite, so a GA county with no wired source draws nothing (correct — the click path says "no parcel data wired here yet").
`[x]` **Measured before/after (`test/parcelDisplaySourcesForView.test.js`, real county-polygon asset):** distinct services queried for the Bartow view, at 6 display tiles per service: before ≈ 846 requests, after ≈ 12 (`ga_bartow` + `ga_fulton`, whose padded bbox touches the view edge).
`[x]` **Abort in flight:** dead layers are now removed instead of left running, so a zoom no longer queues behind other states' requests. A per-request abort inside esri-leaflet was not added; the only in-flight requests that remain are for sources actually in view.
`[x]` **Missing header / grey band:** NOT reproduced. `AppHeader.jsx` documents that fullscreen (`F`) keeps both header rows byte-identical (B1156/B1173), so the app's own fullscreen toggle cannot hide the header; his screenshot most likely shows browser-level fullscreen or a paint stall while the renderer was unresponsive under the request flood (two screenshots timed out). `[x]` **Second source = Fulton County** (`services1.arcgis.com/AQDHTHDrZzfsFsB5/…/Tax_Parcels/FeatureServer/0` is `ga_fulton`). My first cut chose sources by each county's padded bbox RECTANGLE, and Fulton's rectangle reaches Bartow's ground (its true boundary is ~0.3° south there). `displaySourcesForView` now asks the same nationwide county GEOMETRY the click path uses (`candidateCountiesForPoint`, which narrows a confidently-resolved point to its own county) at a 9×9 sample grid; the bbox test survives only while the geometry asset is not resident. **One source per area:** a statewide composite now draws only where no county source covers a point; when a county's own layer is declared down (8 s hang-guard) `markDown` calls `syncDisplaysToView`, which brings in the state's statewide backup (`statewideKeysForState`). Trade-off, stated: in a county whose server is hung the backup now arrives after the guard fires instead of drawing underneath from the start.
`[x]` **Why 17k features: esri-leaflet 3.0.19 never releases a feature it fetched.** `cellLeave` removes layers only when `!_activeCells[key]`, but `_removeCell` sets `_activeCells[key]` (for reuse) immediately before calling it, so the test can never pass — measured: `cacheLayers:false` changes nothing, and held features stayed at 3,901 through a full zoom cycle in the harness. Tiles were not returning more than their envelope and features were not duplicated (esri-leaflet keys by id). Fix: `lib/parcelPrune.js` `pruneToLiveCells` (run on `moveend`/`zoomend`) drops every feature only non-current cells hold and forgets those cells so returning re-requests instead of re-adding nothing; **and** the outline layer now paints on ONE canvas renderer instead of a `<path>` per lot (removed with the layer). Click-to-select unchanged (B137): the hit test reads the held features' geometry, not DOM nodes.
