`[x]` **Two entry points, both shipped and both driven live.** (1) **Meeting calendars window → "Import from another schedule…"** — lists every meeting body on every OTHER schedule on the account, grouped by schedule name (and its linked Site Planner project, where one is set), each row showing its cadence sentence + next dates; multi-select, then Import. (2) **Task right-click → bind-to-meeting flyout → "From other schedules"** — a new group beneath the schedule's own bodies (and, when the schedule has ZERO bodies of its own, the flyout now opens at all instead of only offering the flat "Add a meeting calendar…" row) that imports the picked body AND binds the task to it in one click.
`[x]` **Copy, not link — and de-duplicated.** `copyMeetingBodyWithNewId` (extracted from `buildDuplicateProject`'s own per-body re-id mapper — Duplicate schedule already had this logic; this item reuses it rather than growing a second copy) mints a fresh, globally-unique `mb_…` id so editing the copy can never move the source's hearings and vice versa. `importMeetingBody`/`importMeetingBodies` (new) check `mbBodiesSameCadence` (same name + an order-independent signature of the recurrence rules — deliberately ignoring agendaLead/blackoutDates/jurisdiction, per the item's own spec) before minting a copy: an identical body already on the target schedule is REUSED, never duplicated; a same-name-but-different-cadence body imports as a genuine second entry, and the picker shows both cadences so they're distinguishable. A batch import (the modal's multi-select) dedupes sequentially, so picking the same source body twice in one Import click still yields exactly one copy.
`[x]` **Nothing about the source schedule changes.** Every source-schedule read is one-way; no code path here ever writes back into the schedule a body was imported FROM. Proven both at the unit level (`copyMeetingBodyWithNewId` independence tests) and live (Section A8 of the live harness below re-opens the flyout after an import and confirms the source's body is still listed, untouched).
`[x]` **Account-wide source list.** `otherScheduleMeetingBodies(data, excludePid)` — every OTHER schedule with at least one body, grouped, sorted by schedule name; used by both entry points so there is one implementation of "what bodies exist elsewhere," not two.
