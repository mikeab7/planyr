None of them owns the export INHERITING a declutter decision as policy. Net-new.)*
`[x]` *(implemented 2026-07-31; parked for the signed-in pass on the owner's own Sylvestri plan — see **V666**.)* The owner's exported sheet showed each length measurement as TWO large filled orange discs joined by a short stub, twice on the plan, and NO value label anywhere. A measurement printed without its number is worthless on an exhibit — the number is the one thing the measurement exists to communicate.

- Origin: filed 2026-07-31 from chat (NEW-1)

**AUDIT-FIRST — the reported root cause was traced against the code before anything was patched, and it holds on every point.** `exportSheet.js`'s `buildExportSvgRaw` CLONES the live `<svg>` and strips only `clone.querySelectorAll('[data-export="skip"]')`, so an export is **by construction exactly what was on screen at that instant**. Two independent things then collided on a sheet printed from a whole-site zoom:
1. **The VALUE was zoom-gated.** The summary chip renders only if `measureLabelVisible` passes, and B1152 had just made that threshold settable per measurement. The owner was zoomed out to see his whole multi-parcel site — the normal thing to do before printing — so the labels were below the gate and simply **were not in the DOM to clone**.
2. **The ENDPOINT MARKERS had no gate at all** and were sized in constant screen px (`<circle r={3}>`), so they kept their size against a drawing that had shrunk to fit several hundred acres. Geometry survived, the number did not, and the marker did not scale.

**⚠ ONE CORRECTION TO THE DIAGNOSIS, because it changes what the fix had to be — and it is why this is NOT a B1085 recurrence.** B1085 already gave the label tier its own frame: on an export pass every gate reads the SHEET's own px-per-foot (`exportLabelScale.js`), not the live zoom. That fix works exactly as specified and still holds — two exports of one plan at different zooms make identical label decisions, which this item's second e2e case now asserts directly. But re-framing a gate is not the same as lifting it: on a several-hundred-acre site the **sheet's own** scale is *also* below the floor, so the label was correctly-but-fatally decluttered off the paper. B1085 closed "the sheet inherits the SCREEN's scale"; this closes "the sheet applies a DECLUTTER POLICY at all". Different decision, same line of code, so it takes its own number.

**THE PRINCIPLE, now written into the code and the folder pointer: AN EXPORT IS A DOCUMENT, NOT A SCREENSHOT.** Level-of-detail gating exists so the canvas stays readable while you work; none of that reasoning survives onto a sheet that will be read at full size on paper.

**(1) THE VALUE ALWAYS PRINTS.** `measureLabelVisible(m, ppf, { …, sheet })` returns true on an export pass regardless of the shared floor, the Standards default, or B1152's per-measurement pin — that pin governs the **canvas only**, and says so in its own docstring. The renderer passes `sheet: labelFrame.sheet`, the flag B1085's own frame already computes, so there is no second notion of "are we exporting".

**THE AUDIT OF EVERY OTHER ZOOM-GATED ANNOTATION THAT CAN REACH THE SHEET, with the line drawn and the reason stated.** The useful distinction is what the gate is ASKING:
- **A PURE ZOOM FLOOR** — a bare px-per-foot threshold with no geometry term — asks *"is the user zoomed in enough?"* That is screen decluttering and has no meaning on paper. **Lifted.**
- **A PHYSICAL-ROOM TEST** — `detailLabelVisible(featureFt, ppf)`, `pondParamLabelVisible(bandFt, ppf)`, the chip's minimum-edge guard — asks *"is there room for this number on the thing it labels?"* Since B1085 that question is already re-asked at the **sheet's** own scale, which is the right question for a document. **Kept.**

| Annotation | Gate | Verdict |
|---|---|---|
| **Measurement value chip** | pure floor + B1152's per-measurement pin | **CHANGED — lifted on the sheet.** The number IS the object: strip it and nothing meaningful is left, which is the whole bug. |
| Measurement per-edge segment lengths | `detailLabelVisible(segFt, ppf)` | **Kept.** Physical-room, re-asked at sheet scale. An edge with no room for type cannot carry a number without overprinting, and the headline value is separately guaranteed. |
| Element dimension callouts (buildings) | `dimCalloutVisible(ppf)` — a pure floor | **Kept, deliberately.** Unlike a measurement, a building still prints its own centred name/area label, so geometry-without-a-dimension is a labelled footprint, not an anonymous mark. They also ride the collision pool (`suppressedDimIds`), so forcing them on a whole-site sheet buys illegible overprint, not information. |
| Road / paving width callouts | `detailLabelVisible(dimW, ppf)` | **Kept.** Physical-room, as above; the road still prints as pavement. |
| Pond parameter labels (berm tag, floor/WS elevations) | `pondParamLabelVisible(bandFt, ppf)` | **Kept.** The label is drawn INSIDE a band — a band thinner than the type cannot hold it. The pond's own name/area label is `mustLabel` and always prints (B1147). |
| Setback chips | `setbackChipsVisible(ppf)` | **No change possible — they already never print.** They live in the `data-export="skip"` handle layer, because a chip is an editing affordance. The setback still prints as its dashed inset ring. |
| Parcel acreage chips | **no gate at all** | **No change needed.** They always draw and always print (restyled to haloed exhibit text by `restyleExportClone`). Checked because the brief asked; nothing to do. |
| Easement centroid labels | `dimCalloutVisible(ppf)` — a pure floor | **Kept, flagged.** Same reasoning as the building dimension: the hatched fill and the centerline geometry always print, so the easement is never anonymous. If the owner wants these on paper too, that is a one-line follow-on and the seam is now in place. |

**(2) THE ENDPOINT MARKERS ARE AN EDITING AFFORDANCE, AND ON PAPER THEY BECOME DRAFTING TERMINATORS.** The vertex discs now carry `data-export="skip"` — belt-and-braces, so they are gone from the sheet even in the fallback where no export pass runs — and on the export pass a **length or polylength** is terminated by the architectural 45° tick at each end of the run (`terminatorTicks`, sized through `labelK` so it holds one physical size on paper), which is what a length annotation looks like on a real exhibit. An **area** is a closed outline and gets neither discs nor ticks; a **COUNT's numbered markers ARE content** — they say which items were counted and in what order — so they print untouched, exactly as the brief requires. Nothing is blanket-skipped.

**(3) THE INVARIANT, ASSERTED IN CODE.** *A measurement must never print its geometry without its value.* `enforceMeasureValueOnSheet` runs on the clone immediately after the chrome strip: any measurement group carrying no value text is **removed from the sheet entirely** rather than printed as anonymous marks, and **LOUD-FAILURE** — the drop returns its ids and raises an owner-facing warning, never a silent trim. It is a removal, not a repair, on purpose: by the time the clone exists a number could only be fabricated, and a wrong figure on an exhibit is worse than a missing annotation. This is the backstop for the case (1) is meant to make impossible — a layout hiccup, or a `flushSync` that cannot run mid-lifecycle, which is precisely how the label re-frame can fall through.

**(4) THE WIDER CONSTANT-SCREEN-PIXEL AUDIT — everything found, and what was done with it.** The markers were one instance; there were five more that reach the sheet.
- **Measurement vertex discs** (`r={3}`) — the reported bug. **Fixed** (skip + terminators).
- **Measurement grab layers** — the fat transparent hit polygon/polyline (`strokeWidth 14`) and the count's transparent hit circles (`r 12`). Invisible, so not a visual defect, but constant screen px and pure editing affordance. **Now `data-export="skip"`.**
- **Semantic markup labels** — `utilRoute`'s fitting glyph and route label, `traced`/`infwater`'s label, `encumbrance`'s per-call bearing/distance and its centroid label. All authored as literal `fontSize="8"…"11"` with no `labelK`, so on a wide-zoom sheet they printed several times their intended size — the same defect as the discs, one layer out. **Fixed:** every one now rides `labelK`, which is exactly 1 on screen, so nothing on the canvas moves.
- **`traced` / `infwater` vertex marks** (`r={3}`, `4×4` rect) — same class. **Fixed** (scaled by `labelK`; they are authored marks, so they scale rather than disappear).
- **In-progress tool drafts** — the measure draft (both branches), the draft polygon and the draft rect all render constant-px dots and type and were NOT export-skipped. A half-drawn shape is never document content and the Export menu is reachable mid-draw. **Now `data-export="skip"`.**
- **NOT changed, recorded for the next reader:** the building poché hatch is a `<pattern>` in user space and therefore scales with the drawing, so it is not in this class — it merely LOOKS wrong on a synthetic 8,000-ft test building. The sheet furniture group is deliberately exempt from the stroke-thinning pass and carries its own hairlines (pre-existing, correct).

**PROOF, and it is mutation-checked both ways.** `test/measureSheet.test.js` (23 cases) covers the pure halves — the sheet override against the floor, the Standards default and a per-measurement pin; terminator geometry at four orientations plus every degenerate input; the invariant's verdict and its DOM enforcement; and source guards on the wiring. `e2e/measure-export-lod.spec.js` is the guard the brief asked for and it drives the **real built sheet**: the defect exists only in the clone, so a new `window.__plannerExportSvg` hook (behind the same `window.__PLANYR_E2E` gate the road-network and geo-map hooks use, never present in production) hands the spec the actual export markup. It draws a genuinely large site — zoomed out BEFORE drawing, because a toy plan exports above the floor and hides the defect entirely — puts a Length, a Polylength and a Count on it, zooms past the gate, exports, and asserts every measurement carries its value, that **zero** endpoint discs survive, that each open run carries exactly two terminators, and that the count's numbered markers ARE present. A second case exports the same plan from a wide and a close zoom and asserts the sheet says the same thing (B1085's property, now guarded). **Proven RED on the pre-fix code both ways:** restoring the discs fails on *"editing discs reached the sheet"*; restoring the inherited label gate fails on *"a measurement was withheld from the sheet"* — which is the invariant firing, i.e. the owner's exact sheet minus the anonymous dots.
