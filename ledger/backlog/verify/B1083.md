- **PREMISE CORRECTION (AUDIT-FIRST): road Free draw was NOT a polygon tool, it was a rectangle DRAG.** With `roadWidth === "free"` the Road tool dropped into the shared `draftRect` path and a drag committed a **rotated-rectangle** road (`cx/cy/w/h/rot`, `travelW = min(w,h) − 2·curb`). It could *also* make a polygon, but only via a different gesture: a press with **no drag** falls through to `setDraftElPoly`, the click-points polygon path shared by paving / parking / trailer / pond. So the owner's "it's basically a polygon tool" was half right — and the distinction matters for the two must-not-break checks below.
- **The shared polygon path was NOT removed.** `draftElPoly` / `closeElPoly` are the general click-points-to-close area path used by **Paving, Car Parking, Trailer Parking and Detention Pond**. Only the Road **menu entry** was deleted; not one line of the shared drawing code was touched, so polygon drawing everywhere else is untouched. Car Parking keeps its own "Free draw (any size)" row — the owner's instruction was scoped to Road.
- **Roads already drawn with Free draw keep working — verified, not assumed.** Both legacy shapes were seeded into a saved plan and driven through the real canvas (`ui-audit/verify-road-width-menu.mjs`): a legacy **rectangle** road renders, selects and edits (it is auto-migrated to a 2-point centerline on read by `migrateRoads` — B596 — at its original 24′ width), and a legacy **polygon** road reads back unchanged, renders, and keeps its four draggable corners. Nothing is orphaned and nothing was migrated destructively. **Both read paths carry the migration** — `createSiteModel` for the local/model path and `elementRows.js:111` for the signed-in element-synced path — so this does not repeat the **B1012** trap where a road cleanup ran on only one of the two.
- **A stored `"free"` can't strand an existing browser.** `roadWidth` persists in `localStorage`; the default was literally `"free"`, so every existing browser carries it. The state initializer now coerces any non-numeric stored value to the first preset, so nobody boots into a mode the menu no longer offers. Asserted headlessly by seeding `planarfit:roadWidth = "free"` before boot.
- **Two headless test hooks added** (both consistent with the existing `data-el-id` convention): `data-el-id` on the centerline-road and polygon-element groups, and an optional `ariaLabel` on `NumInput` (which also names the otherwise-unlabelled Custom width field for a screen reader).
