`[x]` **SHIPPED THIS SESSION — refusal, not cascade, per this app's own standing rule.** `/CLAUDE.md`'s KEY DECISIONS is explicit: *"sharing is always a deliberate, explicit act — never automatic."* Auto-sharing the overlay as a side effect of sharing the comp pinned to it would violate that outright — a plan's OWNER (who may not be the comp's sharer, on a `site_plan` anchor a teammate pinned to someone else's plan) never asked for their plan to go out to a new team. So the fix is a REFUSAL: `anchorTeamConflict(comp, overlaysById)` (new, pure, `comps.js`) returns a plain-language message whenever a comp's `teamId` is set, its anchor is `site_plan`, and the pinned overlay's own `teamId` doesn't match — `null` (no conflict) for every other case, including a pin/parcel-anchored comp, an unshared comp, or an overlay this client hasn't loaded (never guesses from missing information). Wired into `CompsPanel.jsx`'s single-comp `save()` (blocks with the message, same `errors` array every other validation failure uses) and the paste-grid's `saveGridRows()` (holds back only the conflicting rows — any other ready row in the same batch still saves normally, with a clear count in the reported error).
