- **Report.** Owner, on the same Weld County parcel: the panel's setback list runs *"Edge 18, Edge 19 … Edge 32 as separate 25 rows"*. A run row that edits every edge in the run at once is far more usable than 32 identical inputs.
- **The fix.** In **By side** mode the list is now **one row per run** — the same `setbackChipRuns` grouping the canvas chips use, so the panel and the canvas can never disagree about what a side is — and a row writes every edge in its run at once through the existing canonical `setRunSetback` (no parallel store; `offsetPolygon` still miters the joints into one continuous line). A row that spans more than one segment says so in three characters (`Side 2 · 15 seg`); a run whose segments disagree shows a `· mixed` tag whose hover explains that typing a value sets them all. **Per segment** mode is unchanged and still lists every edge, for a notch or a jog.
- **The mode toggle now appears when it is actually needed.** It was gated on a GEOMETRIC side having more than one segment — but on a curved boundary every geometric side IS a single segment, so the toggle hid on exactly the parcel that needed it most. It is gated on the chip runs now.
- **Copy budget.** This REMOVES lines rather than adding them: on the owner's parcel the list goes from **32 rows to 4**, and the only new text is a three-character `· N seg` suffix on multi-segment rows plus a `· mixed` tag that renders only in the disagreement case. The section heading swaps between "Setbacks per edge" and "Setbacks by side" instead of gaining one.
