**THE ACTUAL DEFECT, finally: the MECHANISM itself, not the pill.** Every fix so far (this item's original, B1257072, B1263824) kept Split showing exactly ONE pane at phone width, switched via the header's Grid/Split/Gantt pill. A single pane behind the "Split" tab is visually and functionally IDENTICAL to just tapping Grid or Gantt directly — same content, same full-height layout — so no amount of correcting which tab highlights could ever make it feel like Split does something distinct. This is the "disclosed product question" B1257072 raised and B1263824 left open, now answered by the owner's own repeated rejection: one-pane-at-a-time is not an acceptable shape for phone Split, and the owner separately confirmed Split must stay available on phones (removing it is not on the table).

**THE FIX — STRUCTURAL, not another highlight tweak: Split now renders BOTH panes at once at phone width, stacked vertically.** `SplitView` (`public/sequence/index.html`) is now a thin dispatcher: `DesktopSplitView` (the original resizable side-by-side layout, byte-for-byte unchanged, still gated on `!isMobile`) or the new `PhoneSplitView` when `isMobile`. `PhoneSplitView` renders `GridView` in a fixed-height top pane and `GanttView` in the remaining bottom pane, column-flex-stacked, with a visible divider between them (a thin bar with a center grip mark — deliberately NOT draggable/resizable, since a touch-drag divider risks fighting the page's own vertical scroll and the brief did not ask for resize). Neither pane is passed a shared `scrollRef`/`onScroll`, so — unlike the desktop layout's cross-pane scroll sync — each pane scrolls independently via its own internal ref, exactly like the standalone Grid/Gantt views already do; verified live (below) that scrolling one pane leaves the other's scroll position untouched. The split ratio reuses the existing Settings › "default split" percentage (`settings.defaultSplit`, clamped 30–70) rather than inventing a second "how much space" control. The `phonePane` state and every `inPhoneSplit` branch (the header pill's onClick/highlight special-casing, the toolbar-bridge `view` calc, the body render switch, the phone Gantt-zoom-button visibility check) are DELETED outright — `data.view` is now simply the effective view at every width, and the header pill needs no phone-width special case at all, since tapping Grid/Gantt/Split always just sets `data.view` and Split always shows both panes.

**Grid and Gantt picked directly are UNCHANGED at any width** — still full-height, single-pane; verified live (below) that the plain-Grid and plain-Gantt phone scenarios render byte-identically to before.

**Desktop is UNCHANGED.** `DesktopSplitView` is the exact prior `SplitView` body, untouched; a standard 1600×900 mouse viewport still shows both panes resizable side by side, the zoom button still measures 21px, and the pill's fontWeight-600 "Split" highlight is unchanged — verified live (below).

**The B1241746 row-height parity fix still holds inside the stacked layout**, even though the two panes are no longer positioned side by side — both panes read the same module-scope `ROW_H`, and a grid row's rendered height now carries a `data-gantt-row` marker (new, mirroring the existing `data-task-row`) so this can be measured directly rather than assumed; verified live (below) at 24.00px on both sides.
