- **What it does.** In the schedule grid, **Alt+F** flips the same `task.focused` flag the summary row's Focus chip flips, through the same `updateTask` call, so it is one undo step exactly like a chip click (Ctrl+Z / Ctrl+Y verified). The Focus FILTER rules are not touched.
- **Which group (documented choice).** The anchor is the TOP selected row (a multi-row selection acts on the group of its top row; the range is collapsed afterwards because the toggle changes which rows exist). A summary row → its own Focus. A plain task → its parent group's Focus. A top-level plain task with no parent → nothing happens, no error. Nothing selected or the "+ New task" row → nothing. Pure rule: `focusToggleTarget` in `public/sequence/index.html`.
- **Selection after the toggle.** If the selected row is hidden by Focus, selection moves to the nearest visible ancestor (the parent summary row; higher if that is hidden too) — `focusReselectTarget`, applied in a layout effect keyed on the Focus signature so it runs only for a toggle the key made (not a chip click, not an undo; those keep the existing lost-selection arrow-key re-anchor). The arrow keys continue from the parent.
- **Guards.** Never fires while a cell is being edited (an input/textarea/select has focus, `isContentEditable`, or the live edit state is open) — then the key is left entirely alone, no preventDefault. Modal/overlay guard unchanged. Key-repeat ignored. Matched on `e.code === "KeyF"` (a Mac reports "ƒ" for Alt+F).
- **Chrome's menu.** Chrome on Windows uses Alt+F for its File menu. The handler calls `preventDefault()` on the keydown on every Alt+F outside editing — **even when there is no group to toggle**, so the key is consistently ours on the grid (verified `defaultPrevented === true` on every press, and `false` while editing). What the sandbox CANNOT show: this container's Chromium is headless Linux with no browser menu bar, so "Windows Chrome's menu did not open" is established by `defaultPrevented` plus the precedent that web apps (Google Docs' Alt+F) rely on exactly this — not observed on a Windows Chrome. V1898704 step 7 asks the Cowork chat to confirm it on Michael's real Chrome; if it somehow still opens, the alternative to propose is Alt+G (not silently swapped).
- **Shortcut list.** The schedule has no shortcut/help list; the only place to list it is the Focus chip's tooltip, which now ends "(Alt+F)" (prefixes `Focus: hide` / `Show all tasks` kept — other harnesses key on them). A toast ("Focus on/off for X — expand the group to see it / nothing to hide in it yet") appears only when the chip is NOT drawn (collapsed group or nothing hideable), so the key never looks dead.
