`[x]` **FIX.** `dissolveRings` (`roadNetwork.js`) gains `opts.subtract`: after the cluster's own pavement rings are unioned, every drive-junction target pad in that cluster is cut out of the result via a Clipper `ctDifference` pass, so the road's painted region ends exactly at the court face regardless of z-order. `regionEdgeSegments` (new) walks the subtracted region's outline and drops the segment that runs along the cutter's own boundary (the "mouth" between the two curb-return tangent points), so no curb line strokes straight across the entrance; curb stripes get the same pad rings appended to their own clip set. The un-subtracted ("full") dissolve is kept alongside the painted one purely to interrupt the pad's own outline across the mouth (`outlineCuts`), which needs the road's true footprint, not the clipped one.
`[x]` **MEASURED, paint-order-independent.** `ui-audit/verify-road-ends-at-court-face.mjs` (new) draws a pad and a road in both draw orders (pad-then-road and road-then-pad) and asks the rendered `road-network-surface` SVG path itself, via `isPointInFill`, whether it fills any sampled point inside the pad — never relying on element/z-order, which is exactly the assumption that broke. On unmodified `main`: 1,064 (perpendicular, deep endpoint) and 220 (oblique) filled sample points inside the pad, both draw orders. With this fix: 0, both draw orders, with a control point on the road (just outside the face) confirmed in the fill so the scan isn't void.
