- **FIX.** `stepGridRow` (new pure module `src/workspaces/scheduler/lib/gridRowNav.js`, mirrored byte-identically as module-level `stepGridRow` in `public/sequence/index.html`) now drives both arrows. A selection in the list moves one row (unchanged). A LOST selection is re-anchored at the gap it left and moves one row from there: hidden → after the last visible row that precedes it in visual order (↓ lands below the folded group, ↑ on the group row); deleted → the slot it last held (`lastSelIdxRef`, written by a layout effect only while the selection is in the list), so ↓ lands on the row that slid up and ↑ on the row above; no known position → the row at the top of the viewport. An empty list does nothing (no "+ New task" from an empty list). `flatTasksRef` is now synced in a layout effect instead of a passive one. B463922's selection-chase / anchor / scroll-memory effects are untouched. Test hook: the "+ New task" row carries `data-new-task-row` (`"sel"` when the cursor is on it).
