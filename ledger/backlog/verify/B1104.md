- **The constraint this exists to satisfy:** Colorado ships LIVE rather than behind a flag, so any capability not yet wired must render a hard, unmistakable "not available in Colorado yet" state — never a number, never a silent fallback to a Texas rule, never a blank that reads as zero. A wrong-but-plausible number on a Colorado plan is the single worst outcome of this work.
- **Three deliberate placement decisions in `computeRequiredDetention`.** (1) The guard is the **first statement in the function** — above the `acres > 0` check, because "no site area" is a Texas-shaped answer too. (2) It sits **above the authority lookup**, so even a user who overrides the reviewing agency to a Texas authority on a Colorado site gets no Texas rate — tested against **every** rule in `DETENTION_RULES`. (3) It fires only on a **positive** Colorado answer: `siteState: null` (every legacy plan without coordinates) behaves byte-identically to before.
- **The state is resolved geometrically and WITHOUT a network call** (`coloradoRegions.siteState`), because the guard has to hold when every GIS endpoint is down — which is exactly when a site is most likely to fall through to a default. A guard that depends on a fetch is not a guard.
- **Render (corrected after checking the SHIPPED bundle, not the source — see B1110):** what reaches the screen is the **`N/A · CO` chip** in warn tone plus the explicit line *"…Planyr does not yet carry Colorado detention criteria."*. The neighbouring `detVerdict` / `detTone` / `detSub` locals are computed by every branch in that block and read by NONE — a pre-existing dead store, filed as **B1110** — so the chip and the line ARE the guard's visible output. `N/A · CO` is deliberately not "UNKNOWN", which would read as *we could not look it up* and invite the reader to wait for a number that is never coming. In Colorado `detReq` is computed **regardless of whether an authority resolved**, because the normal precondition would otherwise leave the group rendering nothing at all.
- **The four Colorado regimes are NAMED even though detention is not priced** (`CO_DRAINAGE_REGIMES`): **MHFD** (Adams, Arapahoe, Boulder, Broomfield, Denver, Jefferson — 6 of 9), **Larimer**, **Weld**, **El Paso**. Each carries its criteria manual and a `detentionMethod` saying what would have to be built, so the gap reads as legible rather than mysterious. Larimer/Weld/El Paso each state outright that they are **not** MHFD members.
- **Capabilities ending this session NOT wired for Colorado**, each with its own copy in the `CAPABILITIES` matrix: detention volume · compensating storage / floodplain mitigation · tax units and rates · utility easement widths · thoroughfare plan / ROW · **partial**: required FFE (CWCB floor only, no local ordinance) and drainage authority (named, not priced) · **not applicable** (distinct from not-built, so it never implies work that will never happen): subsidence districts.
- **PANEL-BREVITY measured before/after** (`node ui-audit/panel-copy-budget.mjs`): `yield-detention-detail` 11→**12** lines / 500→**557** chars; `yield-stormwater-notes` 146→**150** / 12576→**12779**. Justified in full in `ui-audit/panel-copy-budget.json`: the added literals are **mutually exclusive** with the Texas copy beside them — a Colorado site shows the Colorado line and never the rate badge, band note or outfall note — so **no single site's default view grows by a line**; the static audit counts every literal in the file. All the substance (both statutory tests, the presumption, the notification, the optimism caveat, the regime's manual, the WQCV+EURV explanation) rides the exempt info argument.
