The first fix (browser PUTs bytes DIRECTLY to Google) is **CORS-dead by design and could never pass its live gate**: Fetch-over-CORS hides the `Location` header of the session-init response, and Google's upload endpoint answers preflights with no `Access-Control-Allow-Origin`. - **Rework (all same-origin, so CORS never applies; owner decision: Drive + chunked-through-the-Worker, not R2/Supabase):** the browser slices the file (`File.slice`, never a whole-file read) into 16 MiB chunks (64 × Google's 256 KiB granule) → `PUT /api/uploads/<id>/chunk` → the Worker relays each chunk to the Drive resumable session it minted in `POST /api/uploads/start`. The capability session URI persists in new **`public.upload_sessions`** (`server/storage/db/upload_sessions.sql`, own-rows RLS, **migrated to production this session via MCP**) and is never returned to the browser. `GET …/status` probes Drive (`bytes */total`) for resume-from-offset; `POST …/complete` records the `drive_files` mapping (keeps the NEW-4 rollback: mapping-write failure deletes the Drive file + fails honestly — the V191 guard moved here). No single request is ever large → the Worker's ~100 MB body cap, its 128 MB memory, and Supabase's 50 MB cap all stop mattering, at any total size. Client loop (`src/shared/files/chunkedUpload.js`): sequential chunks, 5× exponential backoff, resume via /status after a drop, `storageQuotaExceeded` → plain-English "Drive is full" without futile retries; Library tray shows an honest per-file **progress bar** (server-confirmed bytes).
- **Download half (this is what "the big file won't open" was): `GET /api/files` now STREAMS** — the Drive body passes through as a ReadableStream (the old handler buffered `arrayBuffer()` in the Worker, blowing the 128 MB memory cap on a 125 MB PDF) — **and forwards the client's `Range` → 206 Partial Content** (`adapter.fetchStream` / `driveBackend.getStream` / `driveClient.mediaStream`). Drive-stored PDFs > 50 MB open BY URL (`driveStreamSource` + URL-source `loadPdf`), so pdf.js range-streams them progressively; the buffered path stays the fallback and for everything else.
