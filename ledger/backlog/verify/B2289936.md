### B2289936 — A lot's number is STAMPED: "Parcel 4" stays "Parcel 4" when another lot is deleted; the list reads an unnamed drawn / other lot by that number, never "Unnamed" `[Site Planner / parcels]` (feature) #site-planner #parcel #ui #persistence  *(owner direction, Cowork chat 2026-10-16, item 2; amends constraint #19; sibling of B2243424)*
`[ ]` **⏳ merged — V1721552 PENDING (Verify: live — signed-in test-account arm is runnable and is recorded below; `Blocker: real-data` for the owner's own plans).**
- **Owner direction (verbatim in substance):** drawn and other parcels with no name keep a number again — "Parcel 4", "Parcel 5" — stable per parcel, NOT renumbered when one is deleted, instead of a row of identical "Unnamed" labels; county lots still read "Acct …" when unnamed; nothing derived from address, owner or legal description.
- **Root cause of "renumbered":** a root parcel's number was its POSITION in the array (`parcelDisplayInfo`'s `rootNum`), so removing one renumbered every lot after it — on the canvas label AND in the list.
- **Fix:** `siteModel.parcelNumbers(parcels)` is the ONE answer (id → number): a stamped `parcelNo` is kept (unless an earlier root already holds it — a pasted copy carries its source's number — then it is treated as unstamped), every other root takes the next number above the highest held, in array order. **On an unstamped plan that is 1..n by array order — exactly what the positional rule showed — so no existing plan changes what it reads.** `stampParcelNumbers` writes it into the records (identity-preserving once stamped, additive, no migration; an older build ignores the field); applied by `READ_NORMALIZE.parcels` (every read of a stored plan, and the rows seed — which commits what it changed once and is skipped where this tab may not write the plan) and by an effect in `SitePlanner.jsx` for lots created this session (skipped read-only; cannot loop). `parcelDisplayInfo` reads `parcelNumbers`, so the canvas label, the toasts and the list agree. List: `rowText` returns `row.name` for every non-"Acct" row; the word "Unnamed" no longer appears in `ParcelsPanel.jsx`. The parcel's own PAGE still shows its empty name field with the grey "Unnamed" placeholder (constraint #19).
- **Cost / risk, stated:** the first open of a legacy plan by someone who may write it stamps `parcelNo` on every root parcel and commits those rows once (the same mechanism and cost shape as `lockSem`); a read-only viewer never writes. Stored copies of an old plan on another device converge on the next read.
