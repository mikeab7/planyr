- **Owner report.** Grid view on a schedule long enough to scroll: the grid body stops well short of the bottom; a blank band roughly two to three rows tall sits under the last visible row (with a small gray pill he took for the Split divider). Expected: rows use every pixel of height, no dead band, no splitter handle in Grid.
- **ROOT CAUSE (measured, AUDIT-FIRST — the brief's Split-divider lead was NOT the cause).** `public/sequence/index.html` ended the WHOLE embedded page `--fab-dock` (48px, 64px coarse) above the window bottom — `#root` and the app wrapper were `height:calc(100vh - var(--fab-dock))` — so the shell's floating Help "?" would never sit on a cell (B1336528 ×2 / NEW-3, 2026-10-05). That strip is plain `<body>` under EVERY view. Measured live on build 6000483, test account, 2000×1000 window: grid bottom 871 vs iframe viewport 919 = the 48px band; standalone (no iframe) the grid already filled to 520/520. The Split desktop divider is a 1px column, not a horizontal pill, and `[data-split-divider]` exists only in phone-width Split — Grid mounts neither. **The gray pill could not be reproduced here**; see "Pill" below.
- **Fix.** The page now fills the window (`100vh`). Each SCROLL surface — the grid scroller, the Gantt scroller, the Task Report card — carries `--fab-dock` as END-of-scroll padding instead, so the last row still scrolls clear of the "?" but every pixel of height is used (`paddingBottom` divided by the surface's own zoom). The embedded page marks its root `data-corner-free`, and `src/shared/ui/cornerClearance.js` no longer lifts the "?" for such a page (otherwise the hit-test would have lifted it the 160px safety cap over the grid). **Trade-off, stated:** mid-scroll, rows pass under the small round "?" in the bottom-right, like any floating button; the earlier all-the-time clearance is kept only at the end of the list. It also sits over the right end of the horizontal scrollbar.
- **Not changed (checked in the same pass).** Task Report keeps its deliberate 14px page margin (same as its sides — not a reserved strip); Spreadsheet is not iframe-hosted and has no such strip (its bottom clearance is its own, from B1336528 ×2).
- **Proof.** NEW `ui-audit/verify-schedule-fill-height.mjs` — real page in a same-origin host iframe, Grid/Split/Gantt/Task Report × 1280/2000 wide × 520/760/1080 tall: scroller bottom within 2px of the window bottom, no splitter handle in Grid, Split keeps its divider, vacuity guard (the surface really overflows), and scrolled to the end the content ends ≥ one dock above the bottom. **Known-bad arm: `origin/main`'s page is caught (bottom 936 vs 984) — the run is VOID if not.** 72/72 pass. `ui-audit/verify-grid-help-clearance.mjs` re-pointed at the new contract (measured at scroll end) — 84/84, its own known-bad arm still caught. `test/scheduleGridPinnedColumns.test.js` pins the new markup; `test/cornerClearance.test.js` +1 (opt-out).
