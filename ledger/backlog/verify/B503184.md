- **THE DEFECT, measured on a two-layer PDF.** `renderDetail` opens with `if (tileCovers(detailTileRef.current, reg.visible, v.scale)) return` — a cache check that asks *"does the tile I already have cover this view at this scale"* and knows nothing about the drawing's CONTENT changing underneath it. Toggling a layer off re-entered it and it returned immediately. **The detail tile paints ON TOP of the backdrop, so the layer the user just switched off was still what they were looking at — at rest, not only on zoom.** The backdrop correctly dropped to **0** blue pixels while the tile above it held **579,121**, which is 12.2% of the tile and exactly the hidden square's share of the page.

Visibility was the one mutation that did not. `toggleLayer` now drops the retained tile; `tileCovers(null, …)` is false, so the next render is forced.
