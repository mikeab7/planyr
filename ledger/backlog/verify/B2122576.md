`[x]` **SHIPPED 2026-10-05.**
- **Found while verifying, and the headline:** with a real signed-in session, a cold load of `#/admin` showed the admin page and then, ~2.5 s later, the URL rewrote itself to `#/site` and the page vanished. Cause: under `#/admin` the Site Planner underneath still counted as the *active* workspace, and its URL writer (SitePlannerApp effect 2) rewrote the hash once its boot resolved. Fix: Shell keeps no workspace active while the admin page is actually *shown* (`adminShown`, reported by `AdminGate.onShownChange`, reset on unmount) — keyed on "shown", not on the hash, so a non-admin typing `#/admin` keeps the ordinary active workspace and the 404-equivalence is unchanged. `route.js` untouched.
- **One answer per sign-in:** `lib/adminStatus.js` (one store, keyed by user id) + `lib/useIsAdmin.js`; AccountControl and AdminGate no longer each call `is_admin()` per mount. A definite yes/no is remembered for THAT user only (an account switch or sign-out can never inherit the other's answer — tested in both directions); an ERROR is never remembered: the Admin row stays hidden, retried every time the account menu opens, and AdminGate retries twice on a cold load.
- **Every surface:** the row was driven on dashboard, Site, a project open, Review, Library, Notes, Schedule, Food, and phone width (`ui-audit/verify-admin-surfaces.mjs`, real e2e session + mocked admin RPCs, 39/39) with a known-good arm (mocked non-admin → no row, no page).
- Adjacent cases: signed out → no row, no RPC; signed in non-allowlisted (e2e) → no row, normal dashboard at `#/admin`; a `team_members.role = 'admin'` account is not allowlisted → no access (the gate reads `admin_users` only; the e2e account is one and was checked). Server side: every new RPC run as the e2e uid raises `not authorized`.
- Verify: live → V1542176 (non-admin half is checkable by any session as the e2e account; the admin half is the owner's)
