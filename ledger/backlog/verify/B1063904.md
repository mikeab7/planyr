`[x]` **Shipped this session.** Root cause: `parseSingleRecord` (the merge path for a multi-line paste `detectPasteShape` calls "single") resolves `compType` ONCE from the whole JOINED text, so a lease word on ANY line can flip the resolved type away from what an EARLIER line's own size unit assumed — and `genericToDraft` only ever writes a size into the field the FINAL type owns (`leaseSizeSf` has no unit at all, it's always SF), so an acre-unit size captured under a different type has nowhere safe to land. The fix is not a smarter merge — it's knowing when NOT to merge.
- **MERGE SAFETY (`compParse.js`): every line of a would-be single record is now parsed fully independently FIRST** (`buildLineGeneric`, extracted from `parseProseLine`'s own logic so both paths read a line identically; `respectLabels: true` reads a `TT:`/`LL:`/`Rate:`-prefixed line the same way `parseSingleRecord`'s own loop does, so the collision check can never flag a line the merge itself would have read differently). `detectFieldCollisions` compares every line's independent read across Type, Unit, Size, Rate, Price, Rate period, Basis, TI, NOI, Cap rate, and Escalation. **The moment two lines disagree on ANY of these, the merge is refused** — `parsePaste` falls back to one row per line (`mode: "split"`) instead of `mode: "single"`. **Type and Unit are the two the rule names as never mergeable, full stop** — they change the meaning of every other number on the row — and lead the comparison list for that reason, though every field currently gets the identical treatment. Complementary lines (disjoint fields — an address on one line, a rate on the next, the actual shape the merge exists for) are unaffected and still merge exactly as before — verified this is NOT over-corrected (acceptance case (c)).
- **The panel says why**, per the task's explicit requirement: `lastCommitSummary` shows the parser's own sentence, e.g. *"2 lines disagreed on Type — split into 2 comps."* (`CompEntryGrid.jsx`, driven by `parsePaste`'s new `splitReason`). **"Merge into one comp" is the reversible inverse** — a new link beside the existing "Split one row per line" (the pre-existing single→multi override), reachable only after a collision-forced split, re-running the SAME raw pasted text through `parseSingleRecord` (bypassing the collision check) on demand — the choice is reversible in both directions, exactly as specified.
