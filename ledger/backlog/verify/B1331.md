**WHAT WAS SHIPPED, PLAINLY: one instrument with a definitive reading, one cap that the reading justified, and one cap deliberately NOT taken.**

**SUSPECT (i) — THE UNDO STACK. INSTRUMENTED, MEASURED, AND EXONERATED. NO CAP.** `ui-audit/retention-probe.mjs` (`node --expose-gc`) builds a plan-shaped model carrying the two payload classes the item names — markup image `src` and deed rasters, 6 × 512 KB — runs `LIMIT + 40` ordinary edits through the REAL `createHistoryStack` doing exactly what the planner does (`setEls(a => a.map(...))`), and compares the retained stack against 80 INDEPENDENT models under forced GC. **Reading: the full 80-deep stack retains 0.4 MB — 5.1 KB per generation — against 6.21 MB for 80 independent copies, a ratio of 0.065.** So the payloads are **structurally shared**: an edit replaces the array and the one changed element, and every untouched element, every other collection and every image/raster STRING keeps its identity across generations. The undo stack is kilobytes per generation, it is not the 278 MB, and **there is no memory case for lowering the limit** — which is what the item required before touching a number it correctly calls a product decision. Left alone.

**SUSPECT (ii) — THE PDF PROXIES. CAPPED, WITH RE-OPEN MADE TRANSPARENT FIRST.** `overlayDocs` held a live `PDFDocumentProxy` per sheet overlay for the WHOLE session — set on load, destroyed only on removal or unmount — pinning JS-side page objects AND a worker-side document for a reference placed once and never touched again. That is squarely "shorter lifetimes", which is authorised. The trap the item names is real and was closed **first**: the References panel gated the page picker's enabled state on `overlayDocs.current.has(o.id)`, so a naive teardown would silently degrade a working control to *"re-add to change page"*. So the gate now asks a different question — `overlayPageReady(o)`: **live OR re-openable** — and `setOverlayPage` routes through the existing `ensureOverlayPdf`, which already downloads the stored bytes and reloads. A proxy is released only when it can be brought back: an overlay with no stored PDF key is never touched, because there the loss would be real. Idle window 5 minutes on an LRU clock stamped by every genuine use; the knockout control reads the same one helper. LOUD-FAILURE: `setOverlayPage` used to `return` silently on a miss and now says so.

**WHAT COULD NOT BE MEASURED HERE, SAID PLAINLY.** `performance.measureUserAgentSpecificMemory()` needs cross-origin isolation, which planyr.io does not set, and most of a map-heavy tab is decoded tile bitmaps plus GPU copies no JS-heap number can see. **The per-proxy byte figure and the tab attribution are a DevTools heap snapshot WITH RETAINER PATHS on a real signed-in session after a long editing run — logged as V652 and not guessed at here.** No cap was sized off an estimate.

**CONSTRAINTS HELD.** Everything above is eviction / teardown / shorter lifetimes. No retina downgrade, no cap on how much can be drawn, no spinner gating overlays, no geometry decimation, and the B65 anti-flash ghost buffer is untouched. No guard was weakened and no ceiling was raised — the bundle audit reports three metrics above baseline inside their headroom band and **no baseline was re-recorded**, because B1178 is still open and unexplained.
