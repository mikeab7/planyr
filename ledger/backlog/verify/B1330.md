**(a) THE LABEL PASS NOW SEES THE SAME SET THE GEOMETRY PASS DRAWS.** `labelCands` and the `dimItems` collision loop both iterated the FULL `els` while the geometry pass had been culled for releases, and `layoutLabels` then ran twice over that pool. Both now iterate `drawEls`. **This is not a cap and not decimation** — it aligns two passes that were always meant to see the same elements. `cullToView` force-keeps the selection and anything mid-drag, and `CULL_MARGIN` already covers a label hanging outside its element's bounds. **PDF-PARITY is asserted, not assumed:** on an export pass `cullRect` is null, so `drawEls` is IDENTITY with `els` (the same array reference, not a copy) — `test/viewCull.test.js` now pins that identity AND source-guards that both loops read `drawEls`, next to the element-count assertion that was already there. The `cullKeep`/`drawEls` memos moved earlier in the component body so the label pass can read them; nothing else about them changed.
**Deliberately NOT done, per the item:** memoising the label/collision block. `labelCands` carries screen coordinates by design, so its identity changes on every zoom step and there is no key that is both correct and stable. The lever is (a) plus B1329.

**(b) `computeBuildingGrid` IS MEMOISED, WITH A PROVABLY COMPLETE KEY.** It ran once per building per render — twice, in fact, for the column-grid and dock-door passes — with `clipSegmentToRing` then running per grid line, and its inputs contain **no view term at all**, so a pan or zoom recomputed an identical answer for every building on the plan every frame. The function is pure, closes over nothing, and reads exactly `length`, `depth`, `dock` and five numbers off `grid`; the key folds in the other two `grid` fields as well, so an over-broad key can only cost a miss and never return a wrong answer. **This is categorically different from the flood/detention memos we refused** — those had dep sets nobody could enumerate. Bounded at 256 entries with insertion-order eviction (B1162's rule), and the cached value is documented as read-only since it is now shared between callers.

**(c) TWO ZOOM-KEYED DISPATCHES THAT USUALLY WROTE null OVER null.** `setGisHit(null)` and `setGisHover(null)` fire on every `view.ppf` change. Per this file's own B1189 note, a same-value dispatch is still a DISPATCH and React only skips scheduling it when the fiber has no other pending work — which during a zoom it always has. Both now read a plain ref mirror first and skip.

**(d) THE UNDO LOOP STRINGIFIED THE WHOLE MODEL ONCE PER ITERATION.** `lib/history.js`'s `undo` recomputed `keyOf(current)` inside the while loop; `keyOf` is `histKey`, a `JSON.stringify` of every parcel, element, measurement, callout and markup. An undo that skipped ten deduped no-op frames stringified the model eleven times instead of once, on a path the owner hits constantly. Hoisted — behaviour-identical, `current` cannot change inside the loop.

**(e) THE LAST UNBOUNDED CACHE IS BOUNDED — and the answer to "do it or say why not" is DONE.** `lib/layers.js`'s `_probeCache` was one entry per distinct service URL probed, never evicted, for the whole session. The payoff is genuinely small (the entries are tiny), but an unbounded Map keyed on strings arriving from a registry and from user-toggled layers is a leak by SHAPE, and "small" is not an invariant anyone maintains. Capped at 400 through a single write helper, so the cap cannot be bypassed by a second `set` — an evicted probe simply re-probes, which the 40-second TTL already does anyway.
