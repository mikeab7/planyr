- **What's deleted, not hidden, per house style.** `lib/notesSketchNode.js` (the `noteSketch` schema node + node view + the `boxSelection` command behind the toolbar's old Box button), `lib/notesSketchEditor.js` (the interactive double-click/drag/connect canvas), `lib/notesSketchRender.js` (its SVG drawing) — all three files removed outright. The schema no longer declares a `noteSketch` node at all (`lib/notesExtensions.js`). Every call site that referenced them (`NoteToolbar.jsx`'s Box button → the new `+ Arrow` button, `notesSlashMenu.js`'s "Sketch" catalogue entry, `notesOutline.js`'s `LEAF_NODES`) is fixed, not left dangling.
- **What's kept, trimmed to exactly what one caller still needs.** `lib/notesSketchModel.js` survives, cut down to `normalizeSketch` (incl. its legacy `outline`+`positions` migration), `layoutSketch`, `boxSize`, `wrapText`, `edgePoint` — the geometry `lib/notesFlowMigration.js`'s new `migrateSketchesToBoxes` needs to read an OLD page's stored sketch JSON and convert it, on read, to real boxes. Every EDIT function the interactive canvas used (`addBox`/`updateBox`/`moveBox`/`removeBox`/`addLink`/`removeLink`/`boxAt`/`nextSpot`/`outlineFromSketch`) is deleted with it — migration only ever reads a sketch, once, never authors or arranges one.
- **ONE box model, ONE free canvas.** Every placed thing is now a `noteAnchor` (the same box NEW-1 above already made the page's only placement surface) — a picture, an attachment, or arbitrary rich text, exactly as before this item. Nothing new was invented for "the box"; this item is purely about retiring the SECOND canvas that used to live inside a sketch node.
- **Arrows are a DOCUMENT ATTRIBUTE, not a node's own private list.** New `lib/notesArrows.js`: `doc.attrs.arrows` is a `{from,to}` list, the same mechanism `density`/`pageWidth` already use, so an arrow persists, syncs, prints and exports through plumbing that already exists rather than a second store. `normalizeArrows` is the one defensive reader (drops a dangling/self/duplicate arrow); `addArrow` REFUSES WITH A REASON (LOUD-FAILURE) rather than a silent no-op; `cascadeRemoveArrows` is TOMBSTONE-DELETES for arrows, wired into every one of `lib/notesAnchorNode.js`'s box-delete paths (`dropEmptyAnchors`/`removeNoteAnchor`/`removeNoteAnchors`) so no caller can delete a box around it. `edgePoint` (where an arrow crosses a box's border) is RE-EXPORTED from `notesSketchModel.js` rather than reimplemented — the geometry is identical for a sketch's own box and a `noteAnchor`.
- **Two ways to connect two boxes, both carried over from the sketch canvas's own UX rather than reinvented.** Drag from a selected box's own connect dot onto another box (`lib/notesAnchorNode.js`'s node view — a direct command dispatch, no React round trip, local to two DOM elements) — same shape the sketch canvas's own drag-to-connect used. Click-to-connect (`NoteToolbar.jsx`'s `+ Arrow` button, testid `nt-arrow`, replacing the old Box button) — click the source box, click the destination, arrow created, mode exits; Escape or a press on bare canvas cancels — this is **B1834032's own UX carried over verbatim**, just pointed at `noteAnchor` boxes directly instead of boxes living inside a sketch.
- **Markdown export gained a section it never needed before, because an arrow has no drawing surface in text.** `lib/notesMarkdown.js`'s new `arrowsMd` writes a "Connected boxes:" list, referencing each box by its own flattened text (truncated), for the same "content never vanishes" reason the old sketch export's "Also connected:" section existed. A document with no arrows exports exactly as it always did (empty string, filtered out) — the byte-identical guarantee NEW-1's migration fixture depends on is unaffected.
- **⛔ A REAL BUG THIS ITEM'S OWN HARNESS CAUGHT BEFORE IT SHIPPED (CHROME-NEVER-EATS-A-PRESS): the connect dot and the box's own EAST resize handle occupied the IDENTICAL screen position** (`right:-6px; top:50%`, both), and since handles paint after the dot, a text box's east handle silently won every press meant for the dot — the drag-from-the-dot gesture was unreachable by any pointer on a text box. Found only by DRIVING the drag (asserting the element existed was not enough — `getBoundingClientRect()` returns geometry regardless of `pointer-events:none`). Fixed by parking the dot past the SE corner (`right:-16px; bottom:-16px`), clear of all eight resize-handle positions for a text OR a picture box.
- **⛔ A SECOND REAL BUG, ALSO CAUGHT ONLY BY DRIVING THE GESTURE: `removeNoteAnchors` (plural — the multi-select/marquee delete path) passed a `Set` straight to `cascadeRemoveArrows`, which calls `.map()` on it** — `Set` has no `.map`, so every multi-box delete through this path threw, committed NOTHING (the transaction never reached `dispatch`), and left a live page error. The single-box delete path (`removeNoteAnchor`) was unaffected — it already passed a plain array. Fixed by spreading the Set into an array at the one call site that had it wrong.
- **Non-destructive migration, in-memory only, same contract NEW-1's flow migration already established.** `migrateSketchesToBoxes` (new, in `lib/notesFlowMigration.js`) converts every top-level `noteSketch` into real `noteAnchor` boxes at the sketch's own relative layout (`layoutSketch`'s geometry), same text, placed clear of the flow-migration bundle and stacked vertically for more than one sketch; sketch links become `{from,to}` arrows on the same converted, deterministically-minted ids (`mig_<sketch-box-id>` — needs to be deterministic since arrows must reference real ids before any later `ensureNoteAnchorIds` backfill runs). **Composed BEFORE `migrateFlowBody`, order load-bearing** — converting sketches to ordinary anchors first means the flow-body bundler never mistakes a freshly-converted box for content to sweep away. The trailing structural filler paragraph is kept LAST through the conversion (a bug caught by this item's own unit tests, not by hand-reasoning: a naive append put converted boxes after it, which would have made `migrateFlowBody`'s "is this really the trailing filler" check — which requires it be the LAST child — silently misfire on any page holding both an old sketch and old flow content). Nothing is rewritten in storage until the user edits (`hasUserInputRef`, unchanged).
