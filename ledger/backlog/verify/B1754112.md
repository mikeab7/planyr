`[x]` **REPRO ESTABLISHED FIRST, AS INSTRUCTED, then fixed — the honest finding is nuanced: a MOUSE click already recovered the typed text via the browser's own native focus-shift, but the flush was racing the reload on the network call, and the fix closes both.**
- **THE REPRO, run in a real browser (Playwright, mocked backend, no auth needed — `ui-audit/verify-merge-toast.mjs` Case 7):** open a schedule, double-click a task name cell, type new text, and — WITHOUT pressing Enter/Tab/clicking away — force the stale banner and click Reload. **Measured on the pre-fix build:** the typed text WAS captured and saved (a mouse click on the Reload button natively blurs the previously-focused input before React's own onClick handler runs, and this grid's cells already commit-on-blur reading `e.target.value` directly off the DOM — EDITOR-EXIT-CONTRACT's existing "text" contract), so the specific data loss the dispatch worried about did not reproduce for a plain mouse click. **What DID reproduce:** a `Supabase set error: TypeError: Failed to fetch` in the console — the page's OWN existing autosave-on-data-change effect (triggered by that same native blur) fires an independent save that had not yet settled when `window.location.reload()` fired, so its in-flight request was aborted by the navigation. Not silent data loss, but a genuine loose end: an aborted write, logged as an error, on every such Reload.
- **THE FIX (`public/sequence/index.html`, the `staleNotice` banner's Reload `onClick`):** before flushing, blur `document.activeElement` (a safe no-op if nothing is open; sufficient because every text-class cell already commits on blur reading the DOM input's live value, never a stale React closure) and wait one tick for that commit's `setData` to land in `data` — then read `latestData.current` (now current) and flush, THEN reload. This makes the fix robust beyond the mouse-click case it happened to already survive (a keyboard-driven Reload, or a future editor whose native-blur timing differs), and the wait gives any independently-triggered autosave from the same edit time to settle before the page navigates away, closing the aborted-fetch error observed in the repro.
