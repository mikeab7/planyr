- **Recurrence (2026-10-08, owner chat block NEW-2):** *"the shake itself seems better but is only there now if you're paying attention."* Same plan (Goose Creek / Phase II), Land → Parcels docked, Windows Chrome; his window reports devicePixelRatio ≈ 2.15 (innerWidth 1191 on a 2560 panel).
- **Why the first fix's harness passed while he could still see it (instrument on trial).** It read `getBoundingClientRect()` at a 0.5 px tolerance. A rect is a LAYOUT position; the browser then snaps each painted box to whole pixels and re-rasterises anything whose snap changed. Measured on main with device-pixel screenshots: rects 0.00 everywhere, while at 2.15× ~700,000 aerial pixels (every tile seam) and every hatch changed on every drag step, and the drawing shifted ±0.45 device px in a repeating cycle.
- **Three measured causes.** (1) **The owner's display had no step.** `cssStepForDpr` searched only up to 20 CSS px with a 1e-6 tolerance; Chrome reports 2.15 as 2.1500000953674316, so it fell back to 1 CSS px (= 2.15 device px) and the canvas edge changed device-pixel phase every step. (2) **The basemap box followed the panel edge**, so every step resized and panned Leaflet (whole-CSS-px pans only) and re-requested FEMA's picture, whose "Zone AE" labels re-flow with the extent (FEMA's own stripes are ground-anchored — verified by exporting two shifted extents and diffing). (3) **The SVG canvas needs its edge whole in CSS px AND device px:** on a device-aligned edge the drawing shifted with the CSS fraction (its box is pixel-snapped in CSS px); on a CSS-aligned edge the crisp building edges and corner markers jumped a device pixel. Ruled out, measured: a sub-pixel "hold" translate on the map wrap (it changed how the browser rasterised the whole aerial — ~700k px per step); GPU raster (identical with `--disable-gpu`); compositing hints (`will-change`, `isolation`).
- **Fix.** (a) `geoDockX` + `mapLock.mapBoxInset`/`mapBoxCenterX`: the map container (and both GIS band hosts) reaches left under the docked column, so its left edge and width are constant during a docked-panel drag/open/close; overscan is sized off the same fixed width; a pan that rounds to zero is not issued (it would fire `moveend` and re-request every raster overlay); lot-number insets take the per-side box (`parcelLotLabelLayer`). (b) `lib/panelWidth.js`: the panel PAINTS at whole CSS px (`snapPanelWidth`, follows the pointer) but RESERVES `panelFlowWidth` — a notch whole in CSS and device px (1/4/2 px at 100/125/150 %, 20 px at 215 %, float32-tolerant, up to 40) — the leftover overlaps the canvas edge, so the canvas edge never lands between grids. (c) hatches: B2202960.
- **Result (`ui-audit/verify-panel-resize-steady.mjs`, new PIXEL phase, owner's plan, FEMA on, 100/125/150/215 %):** aerial alone and FEMA alone **0 changed pixels on every step** at every scale; drawing **0.00 device px displacement** at every scale. On unfixed main: **44 failing checks across 33 recordings** — a repeating hop of **0.63–0.67 px** (excursion 0.36–0.63) in all seven left-rail panels, wider AND narrower, at 1×, 1.25× and 1.5× display scale. Drawing and aerial moved together (relative drift 0.00): the shake is in the shared frame, not a layer disagreement. The panel open/close toggle, release hop and idle (known-good arm) were already steady. Scale was already guarded by #2119 (ppf and viewBox unchanged).
- **Root cause (measured per frame, not inferred).** The drag wrote the panel width as `startW + (clientX − startX)`. On a Windows display scaled 125%/150% the pointer reports FRACTIONAL CSS px, so the panel — and the canvas's left edge — landed on a different fraction of a pixel every frame (probe: wrap left 363.33 / 366.66 / 370 …). Leaflet snaps its tile lattice to whole device pixels relative to that container, so the aerial re-snapped through a repeating three-phase cycle (+0.33, −0.67, +0.33 px), and the drawing, welded to the tile lattice on purpose (B1141 `registrationShift`), followed. A second, smaller contributor: the pan compensation measured the edge as `Math.round(el.offsetLeft)`, so even with a perfect weld it corrected by a whole pixel for a fractional move.
- **Fix.** New pure `lib/panelWidth.js`: the width is snapped to a multiple of the smallest whole CSS-px count that is also whole DEVICE px (1 px at 100%/200%, 2 px at 150%, 4 px at 125%/175%), then clamped to the grip's 240–620 range — the canvas edge has the same sub-pixel phase on every frame, so nothing re-snaps mid-drag. `startLeftResize` uses it. `lib/canvasBox.js` `canvasEdgeLeft` + `EDGE_EPS`: the pan compensation now reads the exact fractional edge (`getBoundingClientRect` relative to the offset parent), still self-gating for overlay/portaled panels (zero delta). VIEWPORT-STABLE (a) holds: measured edge, layout effect, same frame.
- **Result.** Same harness, fixed build: **0 failing across 33 recordings** — every panel (Land, Analysis, Drainage, Yield, Properties, References, Standards), wider and narrower, open/close, release; windows 1920×1080, 1440×900 (1×, 1.25×, 1.5×), 1191×640; max frame jump and excursion ≤ 0.5 px, drawing-vs-aerial relative drift 0.00, no size change, no hop on release. #2119's `verify-panel-resize-scale.mjs` re-run: PASS, 36 readings.
