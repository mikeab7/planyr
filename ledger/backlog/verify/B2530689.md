- **Confirmed (AUDIT-FIRST, not assumed):** the selection WAS a single `{r1,r2,c1,c2}` rectangle (`ModelApp.jsx` `useState`, `SheetView.jsx` `cellClick` ignored every modifier but Shift). Ctrl+click was a plain click.
- **ONE selection model for both items** (`lib/selectionModel.js`, pure, DOM-free): `{ r1, r2, c1, c2, extra? }` — the four existing fields are the ACTIVE (most recent) range with `r1,c1` the active cell, so every existing reader (Name box, formula bar, fill handle, trace, named ranges) keeps working untouched; `extra` holds the earlier ranges. Excel-for-Windows rules: **Ctrl+click** adds the cell (the whole span of a merged cell) as a new range and the active cell moves to it · **Ctrl+drag** adds a rectangle · **Ctrl+click on a row/column header** adds the whole row/column · **Ctrl+click on an already-selected cell removes that cell** (Excel 365; a range is split into the pieces left, and the ONLY selected cell is never removable) · **Shift+click / Shift+Arrows extend only the newest range** · a plain click / arrow collapses to one range · a tab switch or an insert/delete row/column keeps the active range only (extra ranges are stored by index and would point at the wrong cells).
- **Commands that apply to EVERY range, each ONE undo step** (`ModelApp.jsx` `applyActiveRanges` → one `commit` that threads the sheet through `applyToRanges`): Delete / Clear contents, bold · italic · underline · fill · font colour · borders · alignment (every ribbon style), number formats, clear formatting, Format Painter, Ctrl+D (each range filled down), and **Ctrl+Enter** — commits the typed value into every selected cell (`sheetOps.fillTextToCells`; a formula is relocated per cell like a fill). Typing / F2 on a multi-range selection keeps it so Ctrl+Enter has something to fill.
- **Commands Excel refuses** (copy, paste, insert/delete row/column, freeze, sort, merge) show a visible message — "This action won’t work on multiple selections." in the header notice, role=status — never a silent no-op (right-click menu items AND ribbon buttons AND Ctrl+C/V).
- **Rendering:** a cell/row-number/column-header is tinted if ANY range holds it; computed from state at render time, so a range scrolled out of the virtualised window is still highlighted when scrolled back.
- **Adjacent surfaces checked, not assumed:** the **Schedule grid** (`GridView`) treats Ctrl+click as a plain click, and its row operations (indent/outdent/move/delete, tree reparenting) are built on one contiguous rectangle — its own header comment says discontiguous selection "cannot occur"; **Notes tables** are ProseMirror `CellSelection`s (one rectangle by construction). Neither is changed here — plain reasons on **B2530690**, with the live observation recorded on `V1971825`.
- **Not built, said plainly:** the formula-reference-picking nice-to-have (`=SUM(A1,C3)` by Ctrl+click while typing) — there is no click-to-pick mode in this sheet at all (a click while editing just commits), so there is nothing to extend; and a status-bar sum/count — the Spreadsheet has no status bar. Copy/paste of aligned multi-ranges (Excel allows some) refuses instead of guessing.
