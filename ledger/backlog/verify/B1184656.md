- **Fix A — read tolerance.** `CompsPanel.jsx`'s new `useOwningSiteBinStatus` hook checks a comp's `projectId` against the live `projects`/`trackedSites` lists it already has; when the id is absent from both (the exact "No project" trap #1430 fixed for tracked sites, one hop further), it makes one targeted live check (`storage.checkProjectDeletionStatus`, the same call Shell.jsx's route gate already uses) rather than assuming. A binned-but-not-purged site now renders as its real name (`"<name> (in Recently deleted)"`) in the edit form's Project `<select>`, with a plain-language notice ("restore it … within 30 days to keep this link") in both the edit form and the detail view — restoring the site needs no further action, since `project_id` was never touched.
- **Fix B — the purge is no longer a silent FK side effect.** `cloudSync.cloudHardDelete` (the real row DELETE behind the 30-day lazy purge and "Delete forever" — both funnel through this one function) now takes a best-effort count of live comps still pointing at the row being purged BEFORE the delete, and reports it via `reportClientEvent("comp-project-detached-by-purge", …)` after a successful one — LOUD-FAILURE, per the report's own "that is an event worth surfacing or recording, not a side effect of an FK." The detach itself is unprevented (a purge is genuinely permanent) and still guaranteed by the existing `ON DELETE SET NULL` FK regardless of what the best-effort RLS-scoped count sees.
