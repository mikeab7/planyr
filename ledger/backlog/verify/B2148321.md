### B2148321 — EIA pipeline lines drew in Leaflet's default blue (#3388ff, weight 3) — root cause fixed + deliberate commodity style (follow-up to B1994512)
- Module: site-planner · Tags: #gis #pipelines #layers · Verify: live (V1565601)
- **Root cause (measured on the built app: with only the gas layer on, 5 paths #c2410c/2.2 and 11 paths #3388ff/3/opacity 0.8 in one pane):** the flat esriFeature opacity setter restyled with a bare `{ opacity }`; esri-leaflet keeps the last style for every feature fetched afterwards, so every line loaded after the first opacity write got Leaflet's default stroke. Fixed at the source: `layerRequest.featureBaseStyle` is the one flat style (construction AND setter) — this also repairs every other styleFn-less esriFeature line row (rail, faults, truck routes…).
- **Style:** the four EIA rows use the Texas RRC commodity classes (`pipelineCommodity.js`): gas amber, petroleum green dashed, crude violet, gas liquids red; weight capped at the layer-hierarchy constraint ceiling (3), opacity 0.85 = the Texas layer's; per-feature `styleFn` so an opacity change re-derives the whole style. No hydrography/flood blue. Those palette colours are the Texas layer's deliberate fixed hazard symbology (not theme tokens — see that file's header), reused for one-colour-per-product across states; it also removes four raw hexes from layers.js.
- Guards: `test/eiaPipelineStyle.test.js` (11 of 13 red on main), `ui-audit/verify-eia-pipelines.mjs` E arm (rendered stroke per layer = commodity colour, zero #3388ff), layerHierarchy.
