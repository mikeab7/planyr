`[ ]` **⏳ merged — V2068208 PENDING (Verify: live, signed in as the test account — a throwaway schedule, never a real project).** Hovering or resting on a blank filler row, or on "+ New task", now draws the marker across the whole row, ID and Task included.
- **What he saw (reproduced first, on build ec77d2d — #2790 had not fixed it).** On a blank row below "+ New task" the two lines started at the left edge of START and ran right; the frozen ID and Task cells showed nothing. Measured on the real page: task rows were ALREADY correct (see below); only the blank rows and the "+ New task" row were wrong.
- **Root cause (MEASURED).** The marker is a `::before` drawn INSIDE each cell, selected by `[data-col-key]` / `[data-grid-strip]`. Blank / "+ New task" / review-proposal rows have no `data-col-key` (it carries press behaviour, so it was not added), so their cells matched no rule, and the row's trailing strip (`data-grid-strip`) was NOT `position: relative`, so its `::before` was boxed by the WHOLE ROW (`.drow` is the nearest positioned ancestor): a full-width line painted over the ordinary cells and UNDER the opaque, sticky (z-index 5) ID and Task cells. Hence "starts at START, nothing on ID/Task". On task rows the strip is positioned and every cell is matched, which is why B2279024's fix held there.
- **Fix (`public/sequence/index.html`).** (1) One new hook, `data-row-line`, on the cells of the blank / "+ New task" / review rows, added to the same hover and selected rules the task cells use (plus the focused "+ New task" row, which now shows the selected marker too); (2) every row's filler strip and every such cell is `position: relative` (a frozen cell stays sticky: the later `pinStyle` spread wins), so each line is boxed by its own cell and the frozen cells draw their own segment; (3) the comment at the rule records why. #2790's change (the cell-fill layering) is kept; it is a real, separate fix.
- **Sandbox proof (red/green).** `ui-audit/verify-grid-filler-row-marker.mjs` samples PAINTED pixels (a computed style cannot see paint order) for the top and bottom edge under ID, Task and the visible date cells: blank row hovered and after a click, "+ New task" hovered, sideways scroll 300, scrolled down under the sticky header and sideways, task rows of every kind (summary, indented plain, indented needs-attn, plain, complete) hovered and selected, multi-select with a blank row hovered, the grid side of Split, and a `data-theme="dark"` pass. Known-good arm (a hovered task row paints the marker everywhere; an idle row paints none) makes the run VOID if the instrument cannot see it.
