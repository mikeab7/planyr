### B2347456 — Site record panel V1: the single-record view (Records › click a comp) becomes a sectioned spec sheet — no Site dropdown, no "Recently deleted", no zoom warning, Deal / Building / Parties / Documents `[site / comps]` (feature) #comps #ui #site-planner  *(owner chat block NEW-1, 2026-10-19 — layout approved from a mockup, "build it as specified, do not reinterpret"; DEDUPE-FIRST checked: no open B# touches the comps record view / its Site dropdown — B2154056 (focus blank), B1156865 (site holds plans+deals), B1156867/68 are adjacent, not duplicates)*
**Stopping rule:** closed when a signed-in pass on planyr.io (build hash read in the same call as the assertions) shows the record exactly as specified for a full lease, a sparse comp, a comp with no document, and a sale/land comp where one exists, and the comps list still has Recently deleted — V1777984.
**What shipped.** `CompDetail` (`shared/comps/components/CompsPanel.jsx`) rebuilt on the new `shared/ui/RecordSection.jsx` primitives: "← All comps" (brand green) + a deal-type badge (green diamond + LEASE / SALE / LAND, `compBadgeLabel`) · name (semibold, body size) with the location under it, muted · a 32 px bordered ⋮ (Edit / Delete, delete confirm unchanged) · a 2 px dark rule · then DEAL / BUILDING / PARTIES / DOCUMENTS. One body size (14/20) everywhere; the section header (12 px, bold, 0.1em, uppercase, over a 1 px dark rule) is the only other size; a faint `--border-hairline` (new token, both themes) under every row but the last of its section; no gray fills, no opacity. Rows come from `compRecordSections` (`lib/comps.js`), which only SORTS `compFieldRows` into sections — one derivation, so the list / KMZ balloon / record cannot disagree; a field with no value has no row, a section with none has no header; a key the model grows later falls into Deal, so nothing is dropped. Dates in the record are ISO (`compFieldRows(…, { isoDates: true })`); the list and KMZ keep mm/dd/yy. Land's acreage is a Deal fact; a lease's / sale's size is a Building fact; Parties = Owner/Developer·Seller, Tenant·Buyer, and a clickable **Source** (flyer name · date) when the comp is pinned on a stored plan (replaces the old "Open source brochure" link). **Documents** (`SitePlansSection.jsx`): the embedded card is now the Documents section — "Add" on the dark rule, one row per document (thumbnail · filename · "YYYY-MM-DD · p.N · Zoom to" · borderless ⋮ with the existing Adjust / Change page / Pin comp here / Delete menu), and it is PORTALED into the comps panel's own scroll area (`docsSlotRef` → `docsSlot`) so the whole record is one panel that scrolls together (it used to sit below the scroller and clip Building / Parties on a short window). **Removed from the record:** the Site dropdown (and `siteOptions`), "Recently deleted", the "Zoomed out too far…" sentence (Zoom to replaces it; it flies to the plan at any zoom). A site can now show several documents (Add always works); the Adjust panel follows the map-selected / last-⋮-pressed one.
**Two things the owner should know (decisions made, both in the PR text).** (1) Binned SITE PLANS (the soft-deleted flyers) had their only "Recently deleted" inside the record; with it gone they would have been unrecoverable in the UI, so the plan trash now shows as "Recently deleted site plans" on the comps LIST under the comps one (`showPlanTrash` ← `CompsPanel.onViewChange`). (2) The edit form's Project dropdown stays (the spec removes the Site dropdown from the *record*; to change a comp's site you use Edit — the auto-attach notice now says "reassign it in Edit"). Also: the only warning lines a document row can show are genuine failures (image failed to load, interrupted upload, duplicate page) — a healthy row has none.
