IT WAS, AND HERE IS THE REASON, BEFORE IT IS REVERSED.** B1156 made `f` a real browser fullscreen and hid this header so the workspace filled the screen edge to edge; the ×1 pass then judged that the canvas keeping the WHOLE viewport was worth protecting, and paid for navigation with a **top-edge hover reveal** — arm within 3 px of the very top after 220 ms of dwell, hold it open while a header dropdown is up, slide away 400 ms after the pointer leaves. It was built carefully and it worked; ten source guards and half a headless harness certified it.
- **WHY IT IS REVERSED ANYWAY, and the judgement that was wrong.** The ×1 pass treated header height as the scarce resource. It is not: what fullscreen reclaims is the BROWSER's chrome — tab strip, address bar, OS taskbar — and that is most of what is won. Our two rows are ~80 px, and against them sits a PRIMARY action during a plan review: switching plan or project. A hover-to-reveal charges a deliberate, aimed gesture for it every single time, which is why the owner still experienced the mode as one he had to leave. **If screen area must be reclaimed somewhere it is not from the navigation** — his words, and the rule this item now encodes.
- **WHAT SHIPPED (×2).** The header renders **byte-identically in and out of fullscreen**: in flow, `position: relative`, both rows, no transform, no transition, no pointer listener. `data-fullscreen="on"` is stamped so a check can still prove exactly ONE header claims the mode; everything else about the mode is now invisible to the layout.
- **WHAT WAS DELETED WITH IT, so nothing half-lives.** The four reveal constants, the `fsReveal` state and its `pointermove` effect, the `translateY(-100%)` / `position: fixed` branch — and the **floating "✕ Exit fullscreen" button**, which existed for exactly one reason: a hidden header has no exit control. The header no longer hides, so it became a second control for a job the row-1 ⤢ toggle already does, painted over the drawing. `data-testid="toggle-fullscreen"` with `aria-pressed` is now the one exit affordance, and the three harnesses that reached for `exit-fullscreen` were re-aimed in the same commit.

With the header staying put it would now do **nothing at all** — a keypress that silently changes nothing. A refusal therefore says so, in a short self-clearing notice. Escape loses its last branch with it: in the one mode that remains the browser owns Esc outright, and acting on it here would be a second toggle over the top of `fullscreenchange`.

The `ResizeObserver` adopts the document's truth on the way in and relinquishes on the way out, and with no fallback mode left the document is now the WHOLE answer (the `nativeFsRef` half of the old condition is gone).

- **── The ×1 pass (the top-edge reveal), kept as the record of what was tried and why it did not stick ──**
- **THE REPORT.** Press `f` on a plan, then try to switch to another plan or another module: impossible. `AppHeader.jsx`'s `if (fullscreen)` early return replaced the ENTIRE header with a single floating exit button, so the breadcrumb, the project/plan switcher and the module tabs were all gone. That was tolerable while `f` was a chrome-hide; **B1156** made it a real mode people stay in, and a mode you cannot navigate from is a dead end.
- **AUDIT-FIRST — the diagnosis was checked against the code and is correct as written.** The early return is the whole defect and there is nothing else in the path.
- **THE SHAPE IS THE OWNER'S, chosen explicitly and not substituted.** The header **slides in at the top edge**: the real header, entire — breadcrumb, project switcher, plan switcher, module tabs, toolbar — not a reduced version. The canvas stays edge-to-edge while working because the header is **out of flow the whole time** (`position: fixed` + `translateY(-100%)`), so revealing it never resizes the canvas and can never disturb the B1122/B1141 weld between the drawing and the aerial.
- **The five stated requirements, each with its mechanism:**
  - **(a) arms on REACHING the edge, with intent.** `FS_EDGE_PX` is a genuine edge band, not an upper region (guarded: a test fails if anyone widens it past 8), and `FS_ARM_MS` of dwell is required — a cursor flicking across the top on its way somewhere else does not flash it open (asserted headless).
  - **(b) never hides while you are reaching for it.** Three holds: the pointer being on the header or in the band just under it (where the exit button lives); **a dropdown opened FROM the header still being on screen**; and keyboard focus living inside it. The holds are re-checked when the hide timer FIRES, not only when it is set, so opening a menu during the grace period cancels the hide rather than racing it. The dropdown hold needed a small generic addition, because `AnchoredMenu` **portals its panel to `<body>`** and so leaves the header's subtree entirely: the header marks itself `data-menu-scope="app-header"` and `AnchoredMenu` stamps the matching `data-menu-owner` onto whatever it portals. Menus opened from an unmarked tree stamp nothing and are byte-identical to before.
  - **(c) steals no canvas pointer events when hidden.** `pointerEvents: "none"` while parked, in addition to being translated off-screen — belt to the transform's braces, so even mid-transition it cannot swallow a click. Asserted directly: `elementFromPoint` at the top edge returns the canvas.
  - **(d) the exit button stays reachable.** It is now a CHILD of the header, absolutely positioned at `top: 100%`, so it rides the same transform: while the header is parked it lands at exactly the top-right corner it has always occupied, and when the header slides in it rides down to sit under it. No measurement of the header's height, and nothing to keep in sync.
  - **(e) keyboard access does not regress, and the keep-alive gate is respected — this is the strand that needed the most care.** The gate that stops a hidden workspace's header answering `f` or `fullscreenchange` used to read `offsetParent === null`, with a `!fullscreen` exception bolted on because `offsetParent` is null for ANY `position: fixed` element. The header is now fixed for the whole fullscreen session, so that exception would have swallowed `f` and left no way back out. The probe is `getClientRects().length` instead — a `display:none` ancestor generates no boxes, a fixed header parked off-screen still has one — which needs **no exception at all** and is applied unconditionally to both listeners. A test pins the probe, because reverting it to `offsetParent` would silently disable every gate depending on it.
- **A CASE THIS FIX CREATES, found and closed in the same pass — worth reading before touching this again.** Making the module tabs reachable creates a situation that could not arise before, because you could not switch workspaces at all: every workspace owns its OWN `AppHeader`, and the incoming one was `display:none` when `f` was pressed, so the keep-alive gate correctly kept it out of the `fullscreenchange`. It would therefore have arrived as an ordinary in-flow header inside a still-fullscreen document, **with no exit button and `f` DEAD** (requesting fullscreen on an already-fullscreen document resolves without firing another event, so nothing would answer the key) — a worse dead end than the one this item set out to remove. The outgoing header has the mirror problem: left claiming fullscreen it renders a second, invisible exit button, which is the exact "two stacked" defect #869's harness exists to catch. Both are fixed by a hand-over: a `ResizeObserver` on the header (becoming visible changes no prop and fires no event, but it does take the element from no box at all to a real one) adopts the document's truth on the way in and relinquishes on the way out. Four headless checks cover it.
