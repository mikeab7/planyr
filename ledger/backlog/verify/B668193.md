- Verify: live (no `Blocker:` — extensively verified headless with real Playwright touch/coarse-pointer emulation against the exact shipped algorithm, below; parked per house convention because a real finger on a real phone against the real Montrose cluster hasn't been checked)
- **WHY A TOLERANCE BUMP ALONE WAS REJECTED.** Leaflet's own canvas hit-test (`Canvas._onClick`) resolves overlapping candidates by DRAW ORDER — the topmost/last-added layer wins, never proximity — confirmed against a local repro of `_fireDOMEvent`'s `canvasTargets` filtering. Simply raising the renderer's `tolerance` option would make the WRONG pin win more often in a dense cluster, not less, which fails the report's own explicit requirement ("if two targets overlap, the nearest centre wins").
- **THE FIX.** On a coarse pointer (`matchMedia("(pointer: coarse)")`, reactive — mirrors `AppHeader.jsx`'s `useNarrow` pattern) — desktop mice are completely untouched, so precision there is byte-identical — circleMarkers skip their per-marker `click` listener (confirmed via a local repro that an `interactive:true` canvas layer with no listener attached does not consume the click; `map`'s own `click` event still fires normally) and instead get recorded into `pinIndexRef` with their real screen radius. ONE `map.on("click", …)` handler resolves the tap by picking whichever candidate's centre is CLOSEST to the tap point, among those within `Math.max(radius, TOUCH_MIN_TAP_RADIUS)` (22px, giving a 44px-diameter floor — the common minimum touch-target guideline). `TOUCH_MIN_TAP_RADIUS` only widens the invisible HIT area; the drawn circle's own radius is completely untouched, so the map's visual density at any zoom is unaffected ("must not turn to mush," satisfied by construction, not by tuning). The resolver stands down while "Drop a pin" mode is active, so a tap on an existing pin can't also drop a phantom manual pin at the same spot.
