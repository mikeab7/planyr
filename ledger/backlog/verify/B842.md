- Origin: surfaced 2026-07-15 by the B838 completeness sweep; implemented 2026-07-22 from the owner "find them and fix them" chat (the app-wide flash audit that followed B962).
- **What shipped:** the on-reveal `map.invalidateSize` — fired only on the SHOW/mount trigger (map↔plan `visible` flip + keep-alive tab-return `isActive`/`active`), never on a panel toggle — was a **passive `useEffect` + `setTimeout(…, 60)`**, so the map painted once at its stale / 0×0 hidden size and snapped to the real size ~60 ms later. Converted to a **`useLayoutEffect`** that calls `invalidateSize(false)` synchronously before paint (no pan animation; `invalidateSize` fires only Leaflet `resize`/`move`, never a tile-wiping `viewreset`, so the re-sync itself costs no flash), keeping the 60 ms call as a safety-net fallback for the origin-first-land case (map not built yet at layout-effect time). Deps unchanged (`MapFinder.jsx` `[visible, isActive]`; `SitePlanner.jsx` `[active, origin]`, deliberately NOT `size`) so it still can never fire on a panel toggle. Chose the synchronous re-sync over the B65 ghost the original note suggested because a pure reveal has no tile-wipe to mask — only a reposition-lag, which lands correct in-frame once the sync is synchronous.
- **Verified (sandbox/headless, logged out — ATTEMPT-BEFORE-YOU-PARK):** MapFinder smoke — the finder Leaflet map renders on load AND survives a workspace tab round-trip (Library→Site, exercising the `isActive` reveal) with **zero page errors**.
