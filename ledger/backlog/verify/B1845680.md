`[x]` **Root cause, confirmed by reading the code, not guessed.** `cascadeDates`/`meetingBoundInfo` already resolve a bound body correctly regardless of which schedule it lives on — `MEETING_BODY_INDEX` is built from every project's `meetingBodies` (B816: ids are globally unique), so date math and `meetingBodyMissing` were never wrong (confirmed `meetingBodyMissing: false` for task 49). Only the surfaces that NAME the body were local-array-only: `TaskContextMenu`'s `meetingBody`/`curBodyName` read solely from the `meetingBodies` prop (this schedule's own array), and the grid's `case "meetingBody"` cell read solely from `proj?.meetingBodies`. A foreign id matches neither, so both fell through to the literal fallback string `"Meeting body"` (context menu) or the "set up…" empty-state / a blank native `<select>` (grid cell) — an ACTUALLY-BOUND task reading as unbound.
`[x]` **A second, related gap found and fixed in the same pass:** the Meeting column's auto-show gate (`readGridCfg`) only appeared once the project DEFINED ≥1 body of its own — so a schedule like "MUD v PID" (zero bodies, five bound tasks) never showed the Meeting column at all by default, hiding the fix's own surface. Now OR's in "any task actually bound", matching the existing Float/Cost columns' own gate one line below it.
`[x]` **Fix — resolve through the account-wide index everywhere a bound body is NAMED, not just where it's used for date math:**
- New pure `findMeetingBodyElsewhere(data, excludePid, bodyId)` — walks every OTHER project's `meetingBodies`, returning `{body, schedName, pid}`; null only when the id belongs to nowhere on the account (the genuinely-missing case, `meetingBodyMissing`).
- `TaskContextMenu`: `curBodyName` now checks the local list, then `otherBodies` (already schedule-tagged, already passed as a prop for the import flyout) before falling back to a plain `"⚠ calendar missing"` string. The parent label reads `Meeting: TCEQ MUD Creation — from Master Schedule`. The "From other schedules" flyout list now checks (✓) whichever entry is the task's CURRENT foreign binding and labels it "— copy into this schedule", making B1824576's existing import action discoverable as the deliberate next step, never fired automatically.
- Grid `case "meetingBody"`: when the bound id isn't in this schedule's own `meetingBodies`, resolves via `findMeetingBodyElsewhere` and renders `"<Body name> · <Schedule name>"` (read-only, right-click to change/import) instead of the old empty-state/blank-select paths; a genuinely-missing body renders `"⚠ calendar missing"`.
- `Cell` now receives `data` (GridView already had it in scope) so the cross-schedule search is reachable from the grid cell.
