- **Repro.** Tsakiris, "Contour lines (1 ft)" on, z17+. Pan, then zoom again before the DEM decode + contour trace finishes. A label rendered as **"150 ft ft"** — resolved at 8× magnification into **two separate "150 ft" divIcon labels stacked ~3 characters apart**, not a string double-append — and labels from the previous view lingered at stale screen positions, so a "155 ft" label sat on ground the live view traces as 150 ft.
- **Root cause (AUDIT-FIRST).** `terrainLayers.js` got only B36(e)'s post-await `if (!map) return` MOUNT guard (V333, 2026-07-15). It never got the stronger `mySeq = ++seq` SUPERSESSION token that `vectorOverlay.js` uses — B36(e)'s own class audit called that "the model pattern" and recorded `terrainLayers` as mount-guard-only. A superseded compute is still MOUNTED, so it passes `!map` and paints its lines and labels into the live group after the newer compute already cleared and painted.
- **Fix.** (1) `mySeq = ++paintSeq` at the top of the refresh, bail after the await when `mySeq !== paintSeq`, `paintSeq++` in `onRemove` **and** at the zoom gate — exact parity with `vectorOverlay.js`, no forked pattern; the `!map` guard stays behind it. The fetch keeps riding `gisCache.swr` **uncancelled** (aborting would poison the shared cache — B36(e)'s decision); a superseded result is simply never painted. (2) The label sublayer and the polyline sublayer are built in ONE synchronous pass into a just-cleared group, so a label can never outlive the geometry it names. (3) Labels dedupe on **(level, tileKey, anchor)** in `pickLabels`, so one contour cannot stamp twice even if a race slips through. (4) The unit is appended **once, at format time only** — `contourLabelText` is the sole formatter and the render path receives pre-formatted text, so there is no code path that can concatenate a second "ft".
- **A subtler deadlock fixed alongside it.** `busy` was reset by the resolving generation; a remove→re-add mid-job could leave `pendingMove` set with nobody to drain it. `onRemove` now owns the reset (`busy = false`, `pendingMove = false`, `paintSeq++`), so the B56d trailing edge cannot wedge.
- **LIVE-VERIFIED against the real USGS 3DEP service** (`ui-audit/verify-terrain-lattice.mjs`, committed — real service, not a fixture): 35 labels painted over real Katy ground, **0 with a doubled unit**; injecting a duplicate (superseded) artifact into the paint pass yields **35 labels, not 70**. `test/terrainLattice.test.js` covers the same end-to-end over the captured 3DEP tile, plus source-text pins on the token that FAIL against the pre-fix file.
