**ROOT CAUSE.** `SitePlanner.jsx`'s Site canvas has two independently-anchored controls sharing the right edge: the View + Layers row (top-right, fixed `top` offset) and the zoom stack (`+`/`−`/`⤢`, bottom-right, fixed `bottom` offset tuned to clear the scale bar underneath it). Both offsets assume the canvas is comfortably tall enough that their own opposite edge is nowhere near — true on desktop and on portrait phones. Landscape roughly halves the available height while the header/toolbar keep their fixed share, so on the narrowest current landscape phone (iPhone SE, 568×320 → a ~263px-tall canvas, measured live) the zoom stack's fixed bottom clearance pushes its own TOP edge up past the Layers row's bottom edge: the "Zoom in" button rendered fully inside the "Layers" button's box (100% of the smaller control's area), reproducing the harness finding exactly. A second, independent bug hid the fix on the first attempt: the natural place to read "how much room is actually left" is the component's own `size.h`, but that value is deliberately floored at 360px for the drawing's coordinate math (so `size.h` read 360 on a real 263px canvas) — clamping against it was a silent no-op. The file already carries the fix for exactly this shape on WIDTH (`size.rawW`, B881); it had no height twin.

**THE FIX, holds continuously as the canvas shrinks — no per-device nudge.**
1. `size` (`SitePlanner.jsx`) gains `rawH`, the TRUE unclamped pane height, mirroring the existing `rawW` at all three `setSize` call sites.
2. `lib/mapChromeStack.js` gains `TOP_RIGHT_ROW_RESERVE_PX` (the room the top-right row needs: its own top offset + its measured collapsed height + a clearance gap, rounded up the way `SCALE_BAR_CLEARANCE_PX` already is) and a pure `zoomStackBottomPx({ desired, paneH, stackH, floor })` — the zoom stack's `bottom` is now `Math.max(floor, Math.min(desired, paneH - stackH - TOP_RIGHT_ROW_RESERVE_PX))`, read against `size.rawH`. On any canvas tall enough that the clamp doesn't bind (every desktop size, and most phones) this returns the original constant unchanged — desktop is pixel-identical by construction, not by a separate check.
3. `floor` (`FURNITURE_ROW`, already in the file) keeps the stack from being pushed low enough to march into the scale bar's own reserve instead of the row above it.
