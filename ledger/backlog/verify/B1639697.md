**THE BUG, exactly as reported.** Searching "1200 McKinney St, Houston, TX" fired TWO parcel queries — one to HCAD (`www.gis.hctx.net`), one to the statewide fallback — even though HCAD alone always answers correctly for a confidently-resolved Harris County point. Harmless while the statewide endpoint was the dead third-party mirror (the second query just errored and was ignored); once B1639584 (×2) restores a WORKING statewide layer behind it, the two race for real on every click in every one of the 8 dialed-in counties.

**ROOT CAUSE.** `candidateCountiesForPoint`'s NEW-6 "confident narrow" rule (counties.js) already collapses every OTHER real-CAD candidate to just the resolved county when the geometry answer is unambiguous — but it deliberately never narrows the STATEWIDE tier, which is appended unconditionally as the trailing candidate for every Texas point regardless of how confidently a real CAD already answers. That is correct architecture for OUTAGE resilience (a healthy-looking primary that then fails mid-click still has a fallback in flight — the B130/B634 grace-race design, `identifyParcelEager`), but it means a permanently-healthy primary pays for a redundant parallel request forever.

**THE FIX, in `MapFinder.jsx`'s `resolveCandidates` and `SitePlanner.jsx`'s `candidatesAtPoint` (the two independent places a click's candidate list is built — the Map-search flow and the in-planner double-click-to-import flow).** New pure `suppressRedundantStatewide(candidates, realPrimaries, statewideKeys)` (`sourceHealth.js`, beside `filterHealthyCandidates`/`isStatewideBackup`): drops the statewide candidate(s) from the query list ONLY when there is exactly ONE real (non-statewide) primary for the point AND it is currently healthy (survived the breaker filter) — every other shape (a straddle with 2+ real primaries, an unhealthy primary whose breaker already dropped it, or a derived/parked-on-composite Texas county with no real CAD at all) keeps its existing behavior byte-for-byte, so the B130/B634 outage backstop is unweakened for exactly the cases it exists for. The one accepted tradeoff, named rather than hidden: the FIRST click during a fresh outage (before the breaker has tripped) now queries the primary alone and can take up to its full timeout before falling back to the honest "server isn't responding" message with a manual fallback offer, instead of being silently rescued by the parallel statewide race within ~2-3s — every SUBSEQUENT click during the same outage recovers automatically once the breaker opens (at which point the statewide candidate is the only one left, unchanged from today). This mirrors the sequential primary-then-fallback shape `lookupParcels`/`queryOneLayer` (text search) has used for a long time; this is the same shape, deliberately, for the parallel identify path.
