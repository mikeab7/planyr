- **⛔ THE POND RULE APPLIED — a contour number, so which side was right was settled with EVIDENCE before either was touched. THE CODE IS RIGHT.** The assertion was `worst line-vs-readout disagreement ≤ 2.5 ft`; it failed at **`2.8000000000000114` on four consecutive runs — bit for bit**, so it was never flake.
- **THE EVIDENCE.** Probing the raw ground around the one offending sample shows it sits **in the bottom of a drainage channel**: 140.2 ft at the cursor, rising to ~147 ft within eight pixels on **both** sides — 11.3 ft of relief across a sixteen-pixel box. The 143-ft line the hover named **genuinely passes ~3 px from that cursor** (the raw grid crosses 143 ft between +2 px and +4 px), i.e. well inside the 6 px `HOVER_TOL_PX`. The trace is in the right place and the readout is right; they answer **different questions** — "the level of the nearest line within the tolerance" versus "the ground under the cursor". **59 of the 60 samples were within 1.7 ft** (median 0.6, p90 1.4): one channel bottom moved the MAX, nothing moved the distribution. No code in either grid has changed since the spec was written — the only commit to touch `terrainLayers.js` since (`609b0304`) is a z-order/pane change.
- **WHY IT WAS REPLACED RATHER THAN NUDGED.** A fixed FOOT ceiling on the max was never well-posed: the honest bound is `HOVER_TOL_PX × local relief per pixel`, which is **unbounded in a channel**. Moving 2.5 → 3.0 is precisely what the pond rule forbids, and it would re-break on the next sweep that clips a steeper bank.
- **WHAT REPLACES IT IS STRICTLY STRONGER.** Two guards, each with one job: **(a)** median disagreement ≤ **one contour interval** — the systematic-mismatch guard, since a units/datum/wrong-tile error shifts *every* sample while terrain shifts only the tail; **(b)** **the hovered line's level must be ATTAINED by the raw ground within the hover tolerance of the cursor**, checked on the three worst-disagreeing samples. (b) is what the max was reaching for, stated directly — and it catches a line traced in the wrong **PLACE**, which a foot ceiling never could. Measured: all reachable, **zero slack needed**. `HOVER_TOL_PX` is imported from `lib/contours.js` so the guard moves with the constant instead of silently going stale.
- **A REJECTED APPROACH, recorded because it looked right.** A per-sample derived ceiling (`tolerance × relief estimated from the neighbouring sweep steps`) was tried first and **refuted on its own evidence**: it cannot see relief PERPENDICULAR to the sweep, so it mis-fired on samples running along a contour (8 violations at 0.5 ft slack, still 1 at 1.0 ft). Discarded rather than tuned.
