`[x]` **Implemented as part of the same `elPaintItems` unified paint stack (B1788912).** `SitePlanner.jsx`'s new `liftedElIds` memo (keyed on `sel`/`multi` ONLY — never a view term, so a pan or a zoom can never recompute it, per VIEW-INDEPENDENT-ONCE) marks every currently-selected element id; `elPaintItems` partitions the unified stack into `normal` (creation-order z) and `lifted` (selected — rendered in a second pass, after every unselected item, itself z-sorted so a multi-selection's members keep their relative order among themselves). A road-network composite lifts too when ANY of its cluster's member roads is selected (`roadItems`' own `lifted` flag checks `r.ids.some((id) => liftedElIds.has(id))`) — otherwise selecting a road would show its handles floating over whatever covers its cluster's actual ink, the same "where did it go" defect one level down.
`[x]` **Purely a render-order choice — no `z` is ever written by selecting or deselecting something.** Deselecting simply removes the id from `liftedElIds`, and the element's next render places it back in `normal` at its ordinary creation-order position — this was true before B1788912 too (selection never touched `z`), and stays true here.
