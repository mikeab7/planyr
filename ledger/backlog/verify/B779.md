- **THE ROOT CAUSE, reproduced (`(a)` answered — and the answer is NOT "sessions mint early").** Two clones, both branched from the same main, both `git fetch origin main`, both `next-id --against-main` as the last step before push — **both are handed the identical number**, same `provenance.sha`, both "fetched 0s ago". The late-bind rule was being followed *exactly* and still collided, because `--against-main` reads **one ref** and is structurally blind to the other branch. B1140's own note is the field evidence: its mint WAS late-bound with `--against-main`, and main took B1130/B1131 (#860) and B1132 (#862) while the PR was in flight. **The window that matters is `push → merge`** — PR open, CI nudge (often two), build, auto-merge — not `mint → push`. So this item's "collapses the collision window from a whole session to a few seconds" was **false as written**: minting later cannot close a window that opens after the mint. Corrected in place above and in CLAUDE.md.
- **`(b)` STALE `origin/main` — confirmed, and worse than suspected.** `git show origin/main:…` reads the local remote-tracking ref, and nothing verified a fetch had happened. Measured in a real session clone on 2026-07-30: `origin/main` sat **7 days / 169 ids behind** (maxB 974 vs 1143) while the banner still printed `[incl. origin/main]`. A stale `--against-main` is indistinguishable from a correct one.
- **`(c)` MORE SILENT DEGRADATION of the B898 shape — confirmed.** B898 fixed only the ENOBUFS path. A missing `origin/main` ref and a git-not-found both still hit `catch { return null }` with **no warning at all**, and `maxAgainstMain` folded the null into a local-only max that printed as success. `--json` carried no provenance whatsoever, so the degradation was invisible to any caller.
- **`(d)` The uniqueness guard is INNOCENT — it fires exactly as designed.** It went RED pre-merge on both B1140 renumbers (GitHub runs the required build on the PR's *test-merge* ref, so it sees the merged tree). B779's live guard and B780's cross-file guard are **deliberately untouched**: they are the backstop, and they work.
- **THE FIX — enforce the existing design; no new id scheme, no bot.**
  1. **Peer visibility (`scripts/next-id.mjs`).** `--against-main` now also folds in the ids **other in-flight branches have already claimed** — they are sitting on the remote and readable *now*, no merge required. `fetchPeers` mirrors remote heads into `refs/remotes/planyr-peers/*`; `peerClaims` reads them, deduped by blob sha and skipping any file a peer never touched (≈14 s fetch + ≈2 s scan over 499 branches / 35 in-window). This is what finally makes the "few seconds" claim TRUE: two sessions now collide only if both mint before either **pushes**.
  2. **Freshness is PROVEN, not assumed.** `--against-main` **REFUSES (exit 2)** on a missing, never-fetched, or stale `origin/main` (`--max-age`, default 300 s) instead of returning a plausible number, and reports the exact commit + fetch age it read (`[origin/main d5476d0, fetched 0s ago · 35 in-flight branches]`), in `--json` too.
  3. **No silent fallbacks left (LOUD-FAILURE).** `readOriginMain`'s null-on-anything is gone: `readRefFile` tolerates exactly ONE empty — "the ref is fine, the file isn't in it" — and reports every other failure, so no caller can mistake "couldn't read" for "nothing there". `GIT_MAX_BUFFER` is exported so the B898 regression test asserts the real value instead of scraping source.
  4. **Mechanically enforced, not a convention (`scripts/check-mint.mjs` + `.githooks/pre-push` + a required-build step).** The gate checks the **property** ("this id is unclaimed on main and on every in-flight branch"), never the ceremony ("was it minted late?") — a timestamp receipt would just be one more thing to drift. "Added" is measured against the **merge base**, not main's tip, which is what catches the B1140 case (main took the number mid-flight). A RECURRENCE mints nothing, so DEDUPE-FIRST never trips it. `npm run hooks:install`; `--ci` fails on a proven collision but only warns on an infrastructure problem, so a git hiccup can't wedge merges.

- **THE HONEST COST of the six collisions** (asked for explicitly, and it is lower than the "full CI re-run" framing): B780 established ids appear in code only as **comments**, so a renumber is a **few-line text edit of heading lines** — code, tests and commits keep their provisional `NEW-#` labels through any renumber. The real cost was the **extra push/CI cycle per renumber** (~2 min each) plus, on the worst one (B1140–B1143), a **merge-conflict redo** after a blanket resolution duplicated blocks. Roughly **eight wasted cycles and one manual conflict redo across six dispatches** — an ongoing tax and a genuine irritant, not rebuilt work. The guard never let a collision reach `main`.
- **The gate caught a bug in ITSELF, on its own PR — recorded because it is the failure mode that matters most.** The first CI run of the new step went RED with `V532 is ALREADY TAKEN on planyr-peers/claude/backlog-id-collision-recurrence-2z85n2` — **our own branch.** Cause: `actions/checkout` lands on the PR's test-merge commit in **detached HEAD**, so `git rev-parse --abbrev-ref HEAD` returns the literal string `"HEAD"`, the self-exclusion missed, and the branch read as its own rival. It passed locally (where the branch name resolves) and only failed in CI. Fixed two ways, belt and braces: `selfBranchNames()` also consults `GITHUB_HEAD_REF` / `GITHUB_REF_NAME`, and `dropContainedRefs()` drops any peer whose tip is an **ancestor of HEAD** — name-independent, so it holds even with no env vars. Pinned by a regression case in `test/mintGuard.test.js`. **A gate that cries wolf gets bypassed with `--no-verify`, so a false red is not a lesser bug than a missed collision.**
- **A second self-inflicted defect, found while fixing the first: the peer fetch was DAMAGING the clone it ran in.** `--depth=1` grafts every tip it mirrors into `.git/shallow` — including **our own branch**, which made git treat our own HEAD as parentless: `git merge-base` failed, `git log` went one commit deep, and the gate silently lost the merge base it needs for the B1140 case (falling back to main's tip, strictly weaker). Fixed with negative refspecs (`^refs/heads/main`, `^refs/heads/<self>`) so neither is ever mirrored, **plus a snapshot/restore of `.git/shallow`** so the file is byte-identical after a run — verified. Our own ancestry is now also resolved **before** any peer fetch touches the object store. A tool that inspects the repo must not modify it.
- **Residual, stated plainly:** the gate cannot see a branch that has minted but **not yet pushed**. That window is now seconds wide (mint immediately precedes push) instead of hours, and the B779/B780 uniqueness guards still catch anything that slips. Field behaviour across other sessions' dispatches → **V532**.
