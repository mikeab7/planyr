- **CAUSE.** `SitePlannerApp.jsx` mounts `SitePlanner` with `key={`${activeSiteId}:${loadEpoch}`}`. Every plan of a site is its own record with its own id (plans of one site share a `groupId`; `activeSiteId` is the PLAN id), so a plan switch changes the key, React remounts `SitePlanner`, and `const clip = useRef(null)` inside it — the payload — is destroyed. `overlayClip` died the same way. The right-click menu then showed Paste disabled with "Copy a shape or drawing first", which is what the owner saw.
- **FIX.** The payload moved to **`lib/planClipboardStore.js`, at MODULE scope.** Deliberately not `SitePlannerApp` state: module scope is above EVERY remount boundary in the app at once — the plan-switch key, the `loadEpoch` bump, a workspace switch, a project switch, an error-boundary reset — rather than above the one that happened to be found. Reads are plain calls with no subscription, exactly like the `useRef` reads they replace, so nothing about React's render behaviour changes. Lifetime is the browser tab. **The overlay clipboard moved WITH it**, because leaving one behind is how the two Ctrl+V paths diverge again.
- **THE COORDINATE DECISION, stated: RE-PROJECT, and refuse loudly when re-projection would be a lie.** Clipboard geometry is feet in the SOURCE plan's frame, and `origin` is per-record — siblings usually share one (`New plan (same parcel)` copies it) but are not guaranteed to. So a cross-plan paste takes the payload out of the source frame to lat/lon and back into the destination frame through the SAME `mapLock` projection the planner is welded to (`resolveClipFrame`, `lib/planClipboard.js`), and **lands on the same GROUND POSITION it occupied on the plan it was copied from** — which is what "copy it over" means for two concepts of one parcel. **Real-world SIZE is deliberately NOT rescaled:** each plan's feet are ground-true at its own origin, so a 1,000 ft building is 1,000 real feet in either plan, and applying the Mercator grid-scale ratio between the two origin latitudes would shrink a copied building for no physical reason. That ignored scale term is therefore **measured, not assumed** — it appears as a positional smear across the copied set, and a paste whose smear would exceed `CLIP_FRAME_MAX_SMEAR_FT` (one foot, across the whole set) is **REFUSED by name** rather than landed in the wrong place. Two plans of one parcel never reach it; two plans in different cities do. The other refusal is `no-origin`: exactly one of the two plans is on the map, so the frames cannot be related at all. Both refusals carry owner-facing copy pointing at the cursor, and both are LOUD (LOUD-FAILURE). Two plans that BOTH have no origin are two abstract feet frames with nothing to reconcile — a clean no-op.
- **`lastPtrFt` — CHECKED, and the answer is that it stopped mattering.** It is a per-mount ref, so right after a plan switch there genuinely is no pointer history and the old fixed-nudge fallback would have fired. A cross-plan paste **never consults the cursor** — placement comes from the frame relation — so the fresh mount's empty pointer state is now irrelevant, and the paste is deterministic. It was left per-mount on purpose: a pointer position carried across a remount is stale by construction. A SAME-plan paste is untouched and still lands at the cursor (B417), nudge fallback and all. The cross-plan paste also takes NO nudge (there is no original here to sit on top of), and if the set lands outside the window the view pans to it (`revealPasted`) — "I pressed paste and nothing appeared" is the bug being fixed and must not become the cure's symptom.
- **Known and accepted:** a cross-plan overlay paste shares the source plan's `storageKey`, exactly as `⧉ Duplicate plan` already does — the reference points at the same stored file rather than re-uploading it.
- **ONE placement decision, not two.** The brief warned the two Ctrl+V paths would diverge the first time someone touched one, so `clipPlacement` (pure, in `planClipboard.js`) is the single decision both use: cross-plan-in-place → cursor → same-plan nudge → refuse. The drawn-object and reference-drawing paths now differ only in the wording of their toast.
