`[x]` **FIXED THIS SESSION, verified live headless with a red-proof both ways.** In `GanttView` (`public/sequence/index.html`), the bars are windowed — `tasks.slice(startIdx, endIdx)` — but the dependency-arrow SVG mapped the FULL `depLines` array with no window filter at all, so a link whose source or target row fell outside the current scroll buffer still drew a complete bezier + arrowhead, landing on a row with no mounted bar. Reproduced by both a mid-list scroll (the owner's report) and independently by a short viewport against a 39-row fixture (this session's own headless harness): pre-fix, 5 of 32 arrows terminated on rows with no rendered bar; post-fix, 0 of 25.
- **Fix:** each computed `depLines` entry now also carries `srcIdx`/`tgtIdx` (the same row index `idxOf` already resolved for its geometry). The render site filters to `l.srcIdx >= startIdx && l.srcIdx < endIdx && l.tgtIdx >= startIdx && l.tgtIdx < endIdx` — **exactly** the same `[startIdx, endIdx)` window the bar slice uses, so the two layers structurally cannot disagree. `depLines` itself stays scroll-independent (unchanged deps: `[tasks, minD, ppd, childParentIds, settings]`) so it isn't recomputed on every scroll tick — only the cheap render-time filter runs per frame.
