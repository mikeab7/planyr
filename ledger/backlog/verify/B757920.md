- **THE AUDIT, done first, as the report demanded.** Read every vertex-editable element type's `deleteVtx`/`editablePath` branch (`SitePlanner.jsx`): parcel boundaries, buildings/paving/sidewalk/parking/pond (all `layer:"el"`, closed rings, min 3), measurements (`layer:"measure"`, min 1/2/3 by mode), markups (`layer:"markup"`, polyline min 2 / polygon min 3), and easements (`layer:"ease"`, centerline/strip min 2 / boundary ring min 3) ALL already computed deletability as the generic `path.pts.length > path.min` — no endpoint singled out, INCLUDING for their own endpoints on open paths. **Only the road layer set `noEndpointDelete: true` and routed through `canRemoveRoadVertex`, which explicitly forbade `index === 0` and `index === pts.length - 1` regardless of point count** — that is the one and only place the false "min reached" label could ever fire above the true floor. Encumbrances (`markup.kind === "encumbrance"`) and 2-point `line`-kind markups are moved as one piece and are not vertex-edited at all (no control-point model, so no bug is possible there). Building footprints were explicitly left alone — their loaded-dock-wall-corner exclusion (`x.footEdit && dockLineAt(...)`) is a real, honest, unrelated rule and was not touched.
- **A SECOND removal path exists (Shift-click), and it was measured rather than assumed, per the report's instruction.** Reading `onCanvasVtxDownCapture`/every per-type vertex "start-drag" handler (`startVertex`/`startElVertex`/`startMeasureVertex`/`startMarkupVertex`/`startEaseVertex`) found NO branch anywhere that deletes on a Shift-click of a vertex — only Shift-click on an EDGE (away from a corner) inserts a point; the code's own comment at `startEaseVertex` confirms the design: "Shift-click … an edge to add; right-click a vertex or press Delete to remove." So the two paths did not disagree about endpoints specifically — one of them (Shift-click-to-remove) simply doesn't exist and never has; a Shift-click on a vertex just starts an ordinary drag. Three panel hint strings (the easement panel, the generic markup panel, and the pond inspector) nonetheless claimed "Shift-click removes one" / "click + on an edge to add a point; Shift-click to delete one" — false copy describing a feature that isn't there, the same class of lie STANDING RULE (c) asked to be audited for. Fixed to state the true mechanism (Shift-click an edge to add; right-click a dot to remove).
- **THE FIX.** `lib/roadGeometry.js`: `canRemoveRoadVertex`/`removeRoadVertex` now allow ANY control point — endpoint included — above the 2-point floor, matching the rule every other element type already used; deleting an endpoint on a 3+ point road SHORTENS the road (the adjacent vertex becomes the new endpoint), exactly as the report's EXPECTED (a) specified, and exactly what every CAD/GIS polyline editor does. Endpoints hold no curve treatment (`treatmentAt` only reasons about interior vertices 1..N-2), so removing one is pure geometry with nothing to migrate; road junctions/welds (`teeTargetOf`) are re-derived from live COORDINATES every render, not a stored index, so a shortened road simply stops matching a tee it used to weld to, with no dangling reference. `SitePlanner.jsx`: dropped the road-only `noEndpointDelete` special case from `editablePath`/`onCanvasVtxDownCapture`/`onCanvasVtxContextCapture` so every layer shares ONE `canDelete` rule (`path.pts.length > path.min`). At an OPEN path's TRUE minimum (2 points for road/easement-line/markup-polyline; mode-dependent for measurements), per EXPECTED (b), the context menu now offers **"Delete road" / "Delete easement" / "Delete measurement" / "Delete markup"** in place of the old dead disabled row — routed through the existing unconditional `deleteSel` (DELETE-PLAN's single decision point, so undo/redo + a real `op_kind` come for free, per EXPECTED (d) / B727936). CLOSED rings (parcel/building-shaped elements/polygon markups/easement boundaries) at THEIR true minimum keep the plain disabled "(min reached)" row unchanged — that message was never false there (a ring genuinely cannot go below 3 points), so nothing needed fixing on that side.
