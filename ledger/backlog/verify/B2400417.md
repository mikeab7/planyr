- **What shipped.** The CROP heading carries an on/off **switch** at its right end (`role="switch"`, `aria-checked`, `aria-label "Crop"`, test id `overlay-crop-switch-<id>`; Site green on, neutral grey off). **Off = the heading alone.** **On** = a picture of the sheet (the overlay's own image) with the area outside the crop dimmed and the kept area outlined in a dashed Site-green line — rect or polygon, drawn from the stored crop — as a button ("Adjust the crop") that opens the crop editor, plus an **Adjust** button beside it (`overlay-crop-open` kept on Adjust). The **Reset button and the shape text are gone**; clearing the shape in the editor ("Reset to full page" → Done) is the one reset.
- **Switching off does NOT throw the shape away.** The flag lives ON the crop in the shared engine (`shared/overlay/overlayCrop.js`): `crop.off === true` keeps `kind`/`x,y,w,h`/`pts` untouched and every consumer treats the overlay as uncropped — `hasCrop` / `activeCrop` (one gate), `effectiveCropRect` (so the handles and the frame fit see the whole sheet), `cropClipShapeScreen` (the Site-tab SVG `<clipPath>`, and therefore the **print/PDF clone**, which copies the live SVG), `clipPathValueForCrop` (the Map/Comps CSS clip), `cropOutlinePath`, and the cross-plan copy (`siblingOverlays.makeForeignCopy` copies the record, so a copy of an off crop shows the whole sheet and keeps the shape). `normalizeCropShape` (the one write normalizer) carries `off`; `isValidCropShape` accepts it, so the Map/Comps row mappers and both DB CHECKs (which allow extra keys) need **no change** — no storage / RLS change. An old record with no flag behaves exactly as before; switching ON drops the key, so an enabled crop is byte-identical to one never switched.
- **Switch ON with no saved shape opens the editor straight away; closing it without a crop leaves the switch OFF** (the switch is derived from `hasCrop`, so it cannot desync). Switching on/off is **one undo step** (one `setOverlayCrop` write; an unchanged null→null commit no longer pushes an empty frame). `cropEditBlock` reasons still disable the switch and Adjust with the same title text; a **locked overlay can still be cropped** (constraint #24).
