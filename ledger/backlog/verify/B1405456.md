- Verify: live
- **Root cause.** `buildScheduleEvents` (`sinceLastHereFeed.js`) reported a "tasks completed" row whenever a leaf task's raw `.health` field flipped to the literal string `"green"` between two visits. That field is the `HealthPicker`'s color status (public/sequence/index.html) — a label a person clicks, with no completion event and no timestamp behind it. It is not even guaranteed to mean "done" on every account: `healthLabelOverrides` lets an account relabel what "green" displays as anything, and nothing downstream ever read that label back. The more objective-sounding alternative, `percentComplete`, is demonstrably worse — B785744's own history on this repo is that marking a task Complete never touches it, so it drifts from the true status on real data (212 of 557 leaf tasks measured live). There is no field anywhere in `public.planar_data`, and no timestamp anywhere in `public.planar_history`, that records a genuine per-task completion EVENT. Reporting "Closed N tasks" off a mutable status label is worse than not reporting it: it can announce a batch closed when nobody finished anything.
- **The fix.** Per the review's own stated remedy — derive the row from real completions with real timestamps, or drop it rather than infer one — deriving is not honestly possible here (confirmed above), so the `"tasks-completed"` event kind is REMOVED outright: `buildScheduleEvents` no longer tracks `.health` at all, `KIND_META["tasks-completed"]` is gone, and the row can never appear again. `schedule-slip` (a milestone's `end` date changing) is untouched — that is an objective, unambiguous fact recorded directly in the document, not a status label, and its only honesty gap (the B1373536 timing defect) was already fixed.
- **Red-proofed.** `test/sinceLastHereFeed.test.js`'s "FEED-2: never reports a health-field flip as a 'tasks completed' event" test reproduces the exact scenario above — confirmed failing (a "tasks-completed" row present) against the pre-fix module via a scratch harness importing the old file verbatim, and passing (zero rows) against the fix. `KIND_META["tasks-completed"]` is separately asserted undefined. The month-away fixture (`ui-audit/review-2026-09-08/probe-feed-month-away.mjs`, left untouched as a frozen review artifact) now derives one fewer event and shows one fewer schedule row than its original run — expected, and the surrounding cap/ordering tests were updated to match rather than pinning the old count.
