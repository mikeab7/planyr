`[x]` **Symptom:** 101 long tasks / 25.3 s in a 129 s session; the 24 worst all 283–307 ms, clustered on his zoom gestures, 15 of 16 attributed to a function the minifier called `U` — a name that had survived four builds because nobody had ever resolved it.
`[x]` **Step 1 — `U`, `t`, `Lv` de-minified (rebuilt 49a80ab with sourcemaps, walked every function with those names across all 131 chunks):** `U` = **React's scheduler loop `performWorkUntilDeadline`** (the MessageChannel `onmessage` handler that runs every scheduled React render — `scheduler.production.min.js`), `Lv` = **react-dom's `dispatchContinuousEvent`** (wheel/pointermove dispatch). So the ~300 ms blocks are React render+commit work scheduled by the zoom gesture, not a Leaflet callback. (Reusable: written up in `docs/perf/CAPTURE-PIPE.md` → "Reading a minified attribution".) `t` is anonymous and unresolved (14 candidates; never the top frame).
`[x]` **Step 2 — reproduced on his REAL plan:** `ui-audit/diagnose-silvestri-zoom-freeze.mjs` — the committed verbatim Silvestri pull (`sylvestri-concept-d-full.json`, 2026-08-07) **plus every markup/callout added to the live plan since** (6 markups + 6 callouts transcribed verbatim from today's rows, 2 deleted callouts dropped; counts now match live: 12 markups / 20 callouts / 3 parcels / 2 measures; elements 98 vs 97 live — one unreconciled, element rows not re-pulled), dpr 2.125, viewport 904×416, his four layers mounted, start ppf 0.375, FOREGROUND-OR-VOID asserted. `[x]` **Cause (a temporary one-line log in the effect, removed):** after the very first commit, all 97 later commits were `sizeChanged` for ONE reason — `cachedStale` was `true` while the container size (922×575) never changed. B846384 caches that verdict in `geoLayoutInputsRef` and reuses it while `size`/`geoOverscan` are unchanged; taken true once (the first commit) it was never cleared, so every view commit re-entered the resize branch: clear the gesture transform → `invalidateSize` (forced synchronous layout) → `commit(..., false)` → `setView` — the heavy path, once per wheel event, instead of the cheap CSS-transform tracking the zoom gesture is built around (B65/B183/B933). With his four GIS layers mounted each `setView` also resets every esri FeatureGrid (`_resetView → _requestFeatures` in the profile).
`[x]` **Fix:** the resize branch now retires the verdict it just acted on — `geoLayoutInputsRef.current = resolvedLayoutInputs(geoLayoutInputsRef.current)` (new pure helper `mapLock.js` `resolvedLayoutInputs`: same measured inputs, `cachedStale:false`); a moved `size`/`geoOverscan` still re-measures, so B846384's saving and the first-commit/panel-toggle resync both stand.
