- **Repro A's mechanism, found by reading and then locked as a pure decision.** supabase-js emits `INITIAL_SESSION` with a **NULL user** while it is still restoring a stored session. `applyUser(null, …)` runs to completion and releases `bootResolved` — so the URL sync fires with the cloud sites still absent, `effGroup` is null, and that null is written straight over `#/project/<id>/site`. The deep link is gone before the real `SIGNED_IN` arrives, and the resume it would have driven now reads a route with no project in it. Worse: if the order is `INITIAL_SESSION(null)` → `TOKEN_REFRESHED(user)`, the handler ignores `TOKEN_REFRESHED` entirely, so the resume never runs at all.
- **Chasing the auth timing would close one sequence at a time, so the WRITER is honest instead.** `mayWriteRouteProject` refuses to clear a route-named project unless the user **deliberately left it**, and that intent cannot be inferred from state — "the project's data hasn't loaded" and "the user closed the project" both look like `effGroup === null`, and treating the first as the second IS the bug. Every deliberate exit (the Map crumb, Back to map, a sign-out, a discarded staging site) goes through one `leaveProject` / `goMap` seam that records it.
- **Repro B was two faults compounding.** `openProjectGroup` returned **silently** when a group had no plans on this device, so a hash edited to a not-yet-pulled project left the PREVIOUS project rendered under a URL claiming the new one — and because the effect only depended on `projectId`, the cloud pull landing a moment later never re-ran it, so it never self-corrected either. `routeProjectAvailability` replaces the silent return with three real states — **open / waiting / missing** — the effect now also depends on the site list and on `bootResolved`, and a genuinely missing project gets a named banner instead of someone else's plan.
- **On the duplicate panel:** driven headless, the invariant that actually matters holds — exactly ONE planner surface and at most one VISIBLE Layers panel, before and after a switch, with no duplicated rows. Counting raw checkboxes cannot distinguish a leaked second planner from the hidden keep-alive copy that is there **by design** (the inactive mode stays mounted so its Leaflet map is not rebuilt), which is why the original "64 vs 29" was hard to act on. `e2e/route-project-binding.spec.js` (4) asserts the real property, including that the fix did not make the URL un-leavable.
