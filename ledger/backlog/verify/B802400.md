- **ROUND 4, Q1 RE-ASKED AND CONFIRMED HARDER: which client-side store survives a full page reload, and it is IndexedDB — NOT a service worker, NOT the browser HTTP cache.** The owner asked this be confirmed because it "matters for the fix." Traced it to source: `terrainLayers.js`'s `refresh()` reads every tile through `gisCache.swr(\`terrain:${tile.key}\`, ..., { ttl: TERRAIN_TTL })` (`TERRAIN_TTL = 7 days`). `gisCache.js`'s `swr()`, on a cold in-memory (L1) miss — exactly what a fresh page load is — awaits `readAsync(key)`, which reads the persistent tier straight off `localDb.js`'s `indexedDB.open("planyr", 1)` key/value store; if that entry exists and is younger than 7 days, `swr()` returns it directly and **never calls the fetcher at all** — zero network, by construction, not by luck. Confirmed there is no service worker in the loop: `registerGisSw.js` exists ONLY to actively `unregister()` a legacy GIS-imagery service worker from an old design (B438, superseded by B445's server-side Drive cache) — it is a retirement shim, not something live. So the mechanism is exactly what the owner suspected but couldn't confirm: a genuine client-side persistent store, this app's own IndexedDB tile cache, not an HTTP-cache artifact.
