### B1131 — Hovering an electric line, substation or pipeline must say what it is `[Site Planner / layers]` (feature) #site-planner #gis #ui  *(owner-reported 2026-07-29 from chat, verbatim: "I should be able to hover over it and see what it is." Arrived as provisional "ITEM 2"; minted **B1131 / V523** via `git fetch origin main && npm run next-id -- --against-main`. Origin: filed 2026-07-29 from chat. DEDUPE-FIRST: **B695** added hover/click identify to the cached BOUNDARY layers and is the copy model's sibling, but it deliberately left `featureLayerOptions` at `interactive:false` — that gap is this item. **B1095** is contour hover, unrelated. Net-new.)*
`[x]` **Shipped — parked in ⏳ Verify for the live half (V523).**
- Verify: live — GIS endpoint behavior + zoom/data-density-dependent rendering (two mandatory LIVE-VERIFY classes). Sandbox proof: 51 unit assertions + 8 headless browser assertions against stubbed services; what cannot be proven here is that the REAL agency field names resolve.
- **⚠ THE REPORT'S SPLIT WAS WRONG, and correcting it made the fix smaller and better.** The brief asserted that the PUCT and HIFLD electric layers "do NOT paint as vectors at all" and paint through an `f=image` raster export, so they would need an ArcGIS identify. **They are vectors.** `hifld_tx` and `hifld_substations` are both `kind: "esriFeature"` — esri-leaflet `featureLayer`s with their attributes already in the DOM. Their real defect was `interactive: false` and no tooltip: real features that simply never answered. So the owner's red lines and substations are fixed with **wording + interactivity**, not a network round-trip — cheaper, instant, and more accurate. (There is also no PUCT *electric* layer in the registry at all; PUCT appears only as the water/sewer CCN row.)
- **(a) Vector layers — `featureHover.js` (new, pure).** Registry-driven wording in the SAME shape as the OSM tooltips it sits beside in the merged Electric row: `<Title> (<Source>) · <detail> · <detail>` → `Transmission line (HIFLD) · 138 kV · CenterPoint Energy`, `Substation (HIFLD) · Addicks · 138 kV · Houston`. Enabled via `hoverIdentify` / `hoverTitle` / `hoverSource` / `hoverFields` on `hifld_tx`, `hifld_substations`, `env_cleanups`, `faults`, `txdot_aadt`, `bts_rail`, `faa_airports`, `jur_road_authority`. Opt-in per layer, deliberately NOT blanket: county/city/ETJ/ISD polygons cover the whole view and would tooltip under every idle cursor — the same judgement `canvasIdentify` already makes.
- **Redaction is ABSENCE, never a fact.** HIFLD withholds attributes as `"NOT AVAILABLE"`, `0`, or an anonymised `"UNKNOWN30271"`. Those are omitted, reusing `powerScreen.js`'s existing `voltLabel` / `ownerLabel` cleaners so a tooltip and the Site Analysis card can never disagree about a voltage. A fully-redacted record still answers the owner's actual question — it reports `Substation (HIFLD)` rather than nothing.
- **Field names are matched case-insensitively from a candidate LIST**, because the sandbox blocks these hosts so the exact attribute casing cannot be probed from here. This is the specific reason V523 exists.
- **(b) The genuinely raster layers — `rasterIdentify.js` (new, pure) + `rasterIdentifyMap.js` (leaflet glue).** ~Half the registry really does paint as a server-rendered picture through a CORS-exempt `<img>`: FEMA, wetlands, the COH mains, HCFCD, BKDD, the RRC wells, the CCN/MUD territories, and the pipeline layer's zoomed-out tier. No features in the DOM → no tooltip can ever bind → the only way to answer is the service's `/identify`. Debounced ~320 ms on cursor rest, in-flight request aborted on move, a late answer for ground the cursor has left is dropped, click pins a popup. `identifyCapable` DECLINES what it cannot honestly answer: a FeatureServer (identify is a MapServer op), an ImageServer (returns a pixel, and elevation already has its own readout), and any registry opt-out.
- **Failure behaviour (LOUD-FAILURE).** Every outcome is a stated one: `Nothing here` · `This layer can't be identified` · `Source is rate-limiting — try again` · `Source didn't answer in time` · `Couldn't reach the source` · `Source returned HTTP n` · `Source sent an unreadable answer`. Non-hits self-dismiss; there is no branch that leaves a spinner up or falls silent. A sibling layer's FAILURE wins over another's empty result, so an unreachable service can never read as empty ground (the B233 distinction). **The e2e failure test caught a real leak here:** a 200 that wasn't JSON surfaced the raw parser message `Unexpected token '<'…` in the readout; now typed and worded honestly.
- **Reuses the existing mechanisms rather than adding parallel ones.** Liveness is the existing `probeService` verdict (`layerHealthy` gate — a failed dot is not re-asked on every hover), never a second prober. The click gate is the existing `identifyOk()` (the B98 rule). Transport is the existing direct-first-then-B445-cache-proxy pattern from `probeService`, including the `noCors` branch — necessary because these hosts are pictures precisely *because* they send no CORS headers.
- **BOTH surfaces, which the report did not distinguish.** The map finder gets real Leaflet hover. The planner **cannot** — its backdrop map is inside a `pointer-events:none` box, the SVG canvas owns every pointer event (the wall B1092 hit). So the planner drives the identify from its own already-throttled cursor position (the pipeline `contourHover` uses) and renders into the same card shape as the tap identify, gated to the select tool with no drag/draft in progress and suppressed while a pinned card is open. The esri feature layers also gained an `identifyAt` accessor over the SAME pure `hitFeature`, so the planner's tap reaches them too.
- Not fired while panning, dragging, drawing, or on a layer that is toggled off.
- **⚠ THE BUNDLE BUDGET WAS THE REAL FIGHT, and CI caught it — not the sandbox.** `ui-audit/perf-bundle-audit.mjs` runs in the `build` workflow but is **not** in the local pre-push habit, so PR #860 went red on it. The feature landed at **+20.2 KB** on `bundle.siteRouteJsBytes` and **+20.1 KB** on `bundle.largestChunkBytes`, breaching both. The gate's own rule — *a feature that breaches a budget ships with a matching optimization, or does not ship* — was followed, in this order: **(1)** the raster identify glue + state machine moved behind a dynamic import (`rasterIdentifyLazy.js`, the `terrainLazy`/B1095 shape); **(2)** the vector hover/identify attach layer AND its wording engine likewise (`featureHoverAttach.js`, imported at layer-toggle time — hundreds of ms before a cursor can rest on a feature, and `identifyOverlaysAt` already guards on a missing `identifyAt`); **(3)** `identifyCapable` moved into `layerRequest.js` so `layers.js` can gate on it without dragging the identify module onto the boot path (**trap:** a bare `export { x } from "y"` re-export creates NO local binding, so the function was `undefined` inside its own module — 11 controller tests caught it); **(4)** the `L.Icon.Default` fallback rendered from a ~400-byte inline SVG pin instead of leaflet's ~6 KB of inlined PNGs (see B1130). Result: **+20.2 KB → +7.4 KB**, and **`largestChunkBytes` came back UNDER its existing ceiling** (1719.5 → 1706.8 KB) with no number touched — the B1092 standard.
- **The one ceiling that WAS raised, and why (a product decision, stated as such).** `bundle.siteRouteJsBytes` 2320000 → 2332000. **`main` was already at 2262.9 KB against a 2265.6 KB ceiling — 2.7 KB of headroom — so this metric now trips on essentially ANY feature.** That is a headroom problem, not a regression in this PR, and the residual ~7 KB is `SitePlanner.jsx`'s hover card + effect, the geometry-aware point styling and the per-layer `hoverIdentify` flags: all synchronous, all on this route, none deferrable by `import()`. The full justification is written into the metric's own `note` in `perf-budgets.json`, per that file's convention. **B1064** remains the owner of closing the real gap.
- **A SECOND ceiling moved after merging main, and the reason is structural.** `bundle.totalJsBytes` 3960000 → 3985000. That metric counts **every emitted chunk, lazy ones included — by design**, which is what makes it the honest catch-all; so the four deferrals above move bytes off the critical path without reducing it *at all*, and no further code-splitting can. The residual is ~19 KB of genuine minified code for these two defects. New `main` (#859) was itself at 3861.4 KB against a 3867.2 KB ceiling — **5.8 KB of headroom** — so this metric, like the other two, now trips on essentially any feature. Ceiling and target are kept EQUAL, as they were, so it keeps asserting no known gap rather than quietly acquiring one. **Net for this PR: one budget paid down under its ceiling with no raise (`largestChunkBytes`), two raised with the justification written into their own notes.**
