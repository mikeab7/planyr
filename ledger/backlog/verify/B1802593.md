`[x]` **LOUD-FAILURE, applied to the app's single most visible behaviour.**
- **Three named events, exactly as the item asks**, through the existing `reportClientEvent` channel: `boundary-recovery-attempted` · `boundary-recovery-succeeded` · `boundary-budget-exhausted`. Each carries the classified `reason` (the nested-update breaker vs anything else), the `attempt` index, the `budgetLeft` against `MAX_AUTO_RECOVERIES`, the `module` slug (the active route), `crashedIn` + `component` (the subtree that actually threw — B1802592), and `stackHead`.
- **Plus the field that turns the next occurrence from an investigation into a read:** `loop` — the render-loop probe's own verdict at the moment of the crash (`src/app/renderLoopProbe.js`, e.g. `app-header:breadcrumb-fit x51 planSlot=51i`), naming the effect that was running hot and the dependency feeding it. This is the STANDING RULE #2 disposition for B1225296, taken by name: *instrument it so it captures itself when he hits it.*
- **⛔ A SUCCESS IS ONLY CLAIMED ONCE THE REMOUNT HELD.** `boundary-recovery-succeeded` fires on a 3 s settle timer that `componentDidCatch` cancels, because a remount that re-enters the same loop throws again within a frame or two — a success declared in the same tick would be a lie on the one case that matters.
- **The user-side half.** A silent full remount of the workspace reads as the app reloading itself for no reason, which is exactly what he described. The boundary now renders a brief, NON-BLOCKING notice — *"This view redrew itself after a display hiccup. Your work is saved."* — beside the children rather than instead of them (`position: fixed`, `pointerEvents: "none"`, auto-clearing after 6 s), so it can never sit between him and the drawing that just came back. It is the one style block in this file built from theme tokens rather than raw hex, deliberately: the error CARD is raw hex because it must render when the stylesheet may be what broke, while this appears over a working app and must match its theme (a hardcoded near-white pill would be a flashbang in dark mode).
- **The probe is ALWAYS ON, and that is the decision to know.** `diagArm.js` exists because an instrument gated at mount is unreachable on the machine where the defect lives (B280403); this goes one further — the crash it explains is rare, unpredictable, and has only ever been seen on the owner's own device mid-gesture, so an instrument he would have to arm BEFORE it happened would never have caught any of the recorded incidents. The cost is kept low enough to need no gate: a `Map` lookup and a few comparisons per effect RUN (not per render), with the per-dependency classification skipped entirely until a site is already running hot. **2.6 KB minified / 1.3 KB gzipped**, measured.
