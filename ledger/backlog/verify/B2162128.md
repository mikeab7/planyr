### B2162128 — Adding a note to a site on the map: the thing you clicked disappears and you can't tell where the note is going `[Site Planner / map notes]` (bug) #site-planner #notes #mobile #ui  *(owner report 2026-10-08, iPhone Safari, production, account Map. Branch `claude/compassionate-mendel-v6maoq`.)*
Reported: tap a site (a parcel selection / a dropped pin on the decide bar) → Record info → Add a note; the moment the NEW NOTE composer opened, what he had clicked visually went away (the selection highlight and the decide bar cleared, the toolbar fell back to "Select parcels / Draw / Drop a pin"), the card sat low over the map saying only "On a parcel", and the only trace of the site was a sliver of dashed outline behind it.
**Root cause (AUDIT-FIRST, read from the code, then reproduced in WebKit):** the note verb in `MapFinder.jsx`'s `DECIDE_VERBS` called `finishGroundAction()` (clears the selection + exits select mode) / `clearDecidePin()` the instant it opened the composer — B1892544-era "Add a note doesn't dismiss the parcel selection bar" fix had made the verb DISMISS the ground; nothing then held the target for the composer's lifetime. `MapNoteEditor`'s header said only `"On a parcel"` / `"Dropped pin"`. Nothing guarded the map against a stray tap while the composer was open, and a new note autofocuses its text box, so on a phone the keyboard is up immediately and the 300-px card left no room to show the target.
**Fix:** (1) the verb HOLDS the ground (selection / dropped pin) while the composer is open; Cancel returns to the decide bar exactly as it was, Save releases it through the shared `finishGroundAction` and rings the new note's marker for 6 s ("land on the new note"). (2) the composer NAMES its target — `shared/mapNotes/lib/noteTarget.js` `noteTargetLabel`: saved site's name (parcel contains its origin / pin within 100 m, nearest wins) → parcel address / account → "dropped pin (lat, lon)". (3) the target is outlined / ringed in the notes colour while open (`map-note-target-outline` / `map-note-target-pin`). (4) `panToFitRect` pans (never zooms) the smallest amount that puts the target above the card, re-run on card resize and keyboard change; `keyboardInset` reads the visual viewport; `composerBox` rides the card above the keyboard and caps its height; with the keyboard up the editor goes `compact` (Cancel/Save beside the target name, 2-row text) and the address bar hides, so card AND target both fit. (5) while the composer is open the map click handler, site / comp / note markers, identify popups, `markDecidePin`, `addParcelHit`, Enter-key verbs and the decide / at-rest toolbar rows all yield — a stray tap neither retargets nor discards.
Entry points checked: the decide bar's note verb on a parcel selection and on a dropped pin are the ONLY two paths that open the NEW NOTE composer (`beginNoteAt`); an existing note's marker opens the same editor (parcel notes now outline their parcel and name their account). A comp / record has no add-note path (none exists); a saved site is reached through its parcel or pin. Colorado/Texas: nothing region-specific. Owner constraints checked (none contradicted: #15 test artifacts cleared, #5 lazy project creation untouched — a note still never creates a site).
