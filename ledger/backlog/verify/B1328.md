**CONFIRMED, AND IT WAS STRUCTURAL RATHER THAN A MISSING MENU ITEM.** Measurements live in their own `measures` collection, so they never entered the `zOrder` / `byZ` system (which reasons over `els`), and they painted in ONE unconditional pass after `drawElsZ.above` — a hard top layer. The context menu offered Properties / Lock / Copy / Delete and nothing else, while overlays and markups have had front/back for ages.

**BUILT ON THE MARKUP MODEL, REUSED RATHER THAN REINVENTED**, exactly as the item asked: an explicit `z` from `lib/zOrder.js` (`nextZ` / `Z_GAP` / `byZAsc` — the same helpers elements and markups use, no second scheme) orders measurements against each other, and a `behindEls` flag picks the band. The render was extracted from the inline `measures.map(...)` into `renderMeasureNode(m, i)` and is now called from TWO passes — one beside the behind-the-plan markups, one where it always drew.

**THE DEFAULT DOES NOT MOVE, BY CONSTRUCTION.** `behindEls` is undefined on every measurement ever saved and on every newly drawn one, and only `=== true` sends one down — so no stored plan changes on load, and a freshly drawn measurement still lands on top. `siteModel.js` has been running `ensureZ` over `measures` since B671, so legacy z order already equals array order and the sort is a no-op on an existing plan. Asserted in `test/measureWiring.test.js`.

**THE INDEX IS THE IDENTITY, AND THAT IS WHY THE SORT TOUCHES THE DOM ONLY.** A measurement's selection is `{ kind: "measure", i }` — an INDEX into `measures`, not an id. So the bands carry `{ m, i }` pairs holding each measurement's ORIGINAL index; the z-sort reorders what is painted and never the model array. Getting this wrong would have re-pointed every selection, every drag and every delete at the wrong measurement.

**CONTROLS, IN THE WORDING THAT ALREADY EXISTS.** Right-click gains *Bring to front* / *Send to back* (within the band, shown only when there is a stack to reorder) and *Send behind the plan* / *Bring above the plan*; the Properties panel gains the same three under a **Layer** sub-label; and ⌘/Ctrl+`[`/`]` now answer for a measurement the way they do for an element or a markup. Crossing the plan re-stacks the measurement on top of the band it arrives in, so it is never dropped underneath whatever was already there. Undo rides `pushHistory` + the setter like every other edit, `histKey` already stringifies `measures` so a layer change is its own frame, and `z`/`behindEls` are plain additive fields that persist through save, copy/paste and the element-sync path with no schema work.

**EXPORT PARITY HOLDS BY CONSTRUCTION, AND IS ASSERTED, BUT IS STILL THE LIVE HALF.** `buildExportSvg` CLONES the live `<svg>`, so both passes ride into the sheet in the DOM order the screen has; the source guard pins that order (below pass before `drawElsZ.above`, above pass after). PDF-PARITY is a mandatory live class and the sheet/PDF confirmation is **V649** — the half that silently breaks is exactly the half a source guard cannot see.
