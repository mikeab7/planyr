**ROOT CAUSE.** `az_pinal`'s bbox (`counties.js`) is Pinal County's own measured data extent (32.51–33.48 lat, -112.21–-110.45 lon) — a legitimate, accurate bbox for Pinal — but no `az_maricopa` entry had ever been configured, so every click-routing pre-filter that fell inside that rectangle (which includes all of Phoenix, since a bbox is a coarse rectangle around an irregular county) had exactly one AZ candidate to try: Pinal's. Pinal's real service naturally has no Phoenix parcels, so the click silently returned "no parcel here."

**THE FIX.** Added `az_maricopa` (`counties.js` + `countiesProvenance.js`), wired to the county's own authoritative host: `https://gis.maricopa.gov/arcgis/rest/services/IndividualService/Parcel/MapServer/1` (layer 1, "Parcel" — layer 0, "Subdivision", is a different layer and is NOT wired). `idField: APN`, `addrField: PropertyFullStreetAddress`. Bbox/center read directly from the bundled `public/geo/county-polygons.json` (the same asset `resolveCounty` uses), never hand-typed: `[32.51, -113.33, 34.05, -111.04]`, center `[33.2803, -112.1870]`. `az_pinal` itself is UNTOUCHED — its bbox and service stay exactly as measured and verified in B1551617/B1551616; Casa Grande and Apache Junction still route to it (proven below). Pinal was already registered as its own tier-1 county from B1551617 — this item changes nothing about it beyond adding its neighbor, per the dispatch's own instruction that Pinal is "a valid Pinal source and a tier-1 Phoenix-metro county."

**WHY OVERLAPPING BBOXES ARE SAFE HERE, not just "less wrong."** `az_pinal`'s bbox still legitimately overlaps the southern edge of `az_maricopa`'s (the SAME accepted overlap shape `candidateCountiesForPoint` already documents for Sugar Land/harris+fortbend) — a Mesa-area click now queries both services in parallel, and whichever one actually holds the parcel answers; Pinal's own service returning zero for a Maricopa-County point is the correct, harmless outcome the existing "straddle click queries both neighbours" design already expects. Verified with the app's OWN nearest-county-center tie-break (`countyForView`, used for the header jurisdiction pill): Phoenix's nearest center is now `az_maricopa` (distance ≈0.20° vs Pinal's ≈0.87°), while Casa Grande (≈0.14° vs ≈0.29°) and Apache Junction (≈0.21° vs ≈0.30°) both still resolve nearest to `az_pinal` — computed by hand and confirmed by the new tests below, with NO geometry asset needed (this is the bbox-only fallback path every existing county test in this file already exercises).
