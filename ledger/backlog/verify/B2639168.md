### B2639168 — Duplicate plan dead-ends: the copy is never written on the device, the app still navigates into it, and a reload says "This project doesn't exist" `[Site Planner / Persistence]` (bug) #persistence #site-planner  *(owner report 2026-11-03 — Michael, watching a teammate on Goose Creek `smqfy48tlk9j` (user 74515a27): duplicated a plan, got "saved on this device but couldn't sync", reloaded on advice, landed on "This project doesn't exist". Production `client_errors`: 8× `cloud-push-failed … {"error":"missing"}` over 2026-10-29 and 2026-11-03, only this user, every one on build 879a557 or earlier. Minted B2639168 / V2083840. Branch `claude/wonderful-noether-uz10om`.)*
**Cause (code-traced; the storage-full part is the one inference — the new telemetry confirms it on his next attempt):** the device's storage refused the new plan's entry twice (the slimmed retry too); `planStore.writeEntry` / `blobWrite` returned `false` with ZERO telemetry; `saveSite` returned it; `duplicatePlan` ignored it, ran `pushLoud` (→ `pushSiteToCloud` answers `{ok:false, error:"missing"}` because `loadSite(id)` is null), said "saved on this device", and `goPlan(id)` navigated into an id with no record, which the URL writer published as the PROJECT id; the reload gate asked the cloud about it, `wasProjectFreshlyMinted` was false, so "This project doesn't exist". Retry looped on the same non-existent record. Ruled out: the `saveSite` resurrection guard, a throw inside `saveSite`, RLS / cloud.
**Shipped (all of it):** (1) `planStore.writeEntry`/`blobWrite` report a refused write — `plan-store-write-refused` `{reason, id, mode, fragChars, rawChars, usedChars, capChars, shortBy, plans, …inventory}` — and the FIRST refusal of a page load asks `cfg.makeRoom` once (`requestRoom`, shared/cached; history ring → IndexedDB, rebuildable caches; events `plan-store-write-room` / `-retried`) and re-attempts a refused EDIT of an existing plan once (never a brand-new record: a mint's caller decides, so no ghost plan can appear later). (2) `storage.saveSite` fires `site-save-refused` on a refused write and still returns false; new `lastSaveRefusal(id)` / `requestPlanStoreRoom({force})`. (3) the three mint sites — `duplicatePlan`, `newPlanSameParcel`, `newSiteFromMap` — go through the pure leaf `lib/planMint.js` `runMint` (save → make room once → retry the SAME id once): a refusal raises the existing cloud-write failure banner with honest words ("Couldn't make the copy. This browser's storage for Planyr is full, so nothing was saved. Free up space, or try on another device."), Retry = forced make-room then redo the whole create (fresh id); no `pushLoud`, no `refreshSites`, no navigation; telemetry `site-mint-refused {what, id, reason}`, never `cloud-push-failed`. ✕ vs Retry semantics unchanged (constraint #6). (4) `pushSiteToCloud`'s `"missing"` string is kept; `pushLoud` branches on it via `describePushFailure`: "…is not on this device, so there is nothing to sync", no cloud Retry, not recorded for replay, event `push-missing-local`; old durable-log entries whose error is exactly `missing` are pruned at boot (`write-failure-pruned-missing`) so a device that logged them under the old build does not re-raise a banner forever. (5) `goPlanChecked(id)` refuses an id with no local record (`goplan-refused-missing`) and is the only navigation the three mints use; `newBlankSite` keeps plain `goPlan` (a lazy blank has no record by design — constraint #5). **Decision on `markProjectFreshlyMinted`:** NOT added to `duplicatePlan` / `newPlanSameParcel` — the fresh list is keyed by PROJECT id, a plan copy inside an existing project is not a new project, and with the ghost navigation gone no route can ever name the copy's id; `newSiteFromMap` already calls it (unchanged). (6) Audit of every `saveSite(` caller on a user-watched path: autosave (`SitePlanner.jsx` writeMirror) already raised `save-verify-failed` + the local-save-failed state off the boolean and the `readBackSite` membership check (B473/B592) — confirmed visible, now with the store's own refusal event beside it; `renamePlan`, `setSiteStatus`, `setSiteDates` ignored the boolean and pushed "saved on this device" — fixed (honest banner, no push claim). `saveLive` / placement commands already read the boolean; the boot union-merge write and the parcelDrawings patch are background mirrors covered by `site-save-refused`.
