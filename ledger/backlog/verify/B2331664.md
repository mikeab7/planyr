### B2331664 — Select-parcel tool: outlines never painted for a far-out view (a phone's view of a big site) and the panel said nothing; no loading / empty state `[Site Planner / parcels]` (bug) #site-planner #parcel #gis *(owner chat block "NEW-1", 2026-10-19; minted from this branch's reserved block against origin/main c11d397. DEDUPE-FIRST — searched Open / Verify / Done for select-parcel / Add parcels / outline-paint items: B2024624, B1976336 and B1317841 touch the outline set but none covers a silent no-paint state — net-new.)*
`[x]` **Shipped; ⏳ Verify live (V1762192).**
- Verify: live — real county servers + a real phone; sandbox harness `ui-audit/verify-select-parcel-first-paint.mjs` (36 checks) green, and red on main.
- **THE REAL REASON, measured (not the guessed ones).** The two suspected causes are both REFUTED: outline load is NOT pointer-driven (the `identifyMode` effect builds the outline set and syncs it on activation) and the canvas DOES repaint without a tap — at a drawable zoom the outlines draw with no tap on desktop and an iPhone-class touch context, cold, warm (Done → re-arm) and against a slow server (2.5 s), and a pan refreshes them. **What actually fails:** a MapServer CAD (Chambers…) draws vectors only from `PARCEL_VECTOR_MINZOOM` (16) up (owner decision 2026-10-04, `maxRecordCount`). A phone fits a big site at a lower zoom, so the layer is mounted, is below its own draw floor, asks for NOTHING and draws nothing — and the only hint compared against `PARCEL_MINZOOM` (14), so between 14 and 16 the panel was silent. A tap still selected a lot because a click is a live point query, never what is drawn (B137). Reproduced: 3000-ft-half-width site, 390-wide touch viewport → `chambers` mounted, zero lot requests, zero lots, no message.
- **Fix.** `lib/parcelOutlineSet.js` gains `status()` (`loading | drawn | empty | zoom | none`, plus lot count and the layers' true draw floor) and an `onChange` fired by layer start/finish and every view sync — no pointer involved; `SitePlanner.jsx` shows ONE short status line under the armed "Click lit-up lots" button: "Loading parcels…", "No parcels here", or the zoom hint (now driven by the layers' real floor, REPLACING the old PARCEL_MINZOOM-only hint — same sentence, one place). Gone once lots are drawn. The diag hook `__plannerParcelOutlines` reports the status. One activation path: the same effect serves desktop and touch.
- **⛔ FLAGGED FOR THE OWNER — one expectation cannot be met as written.** "Activating the tool is itself what makes outlines appear; no zoom needed" is impossible while the view is below the vector floor: drawing every lot of a county from that far out is the very thing the 2026-10-04 decision (Planyr-owned vectors, no county picture) and the record cap forbid. So in that band the panel now SAYS why instead of staying silent. Options for him: (a) accept the hint, (b) auto-zoom the plan to the floor on activation (a view jump), (c) re-introduce a Planyr-coloured, label-free server picture in the 14–16 band (needs `dynamicLayers` support per county, unmeasured).
