### B2039232 — Review: once a file is open there was no way back to the sheet index `[doc-review]` (bug) #doc-review #ui #mobile  *(Owner block NEW-1, 2026-10-03, measured live on build e5f51c9.)*

`[x]` **Cause (AUDIT-FIRST):** the toolbar had Open… / Compare… / Stitch / Reviews ▾ and the file name as a bare `<span>` — no Close, no back, Escape unbound — and the app resumes the last file on every visit, so the "Pick a project" / "Current set" index (B2022448) was unreachable for anyone who had opened a file.
`[x]` **Fix:** the file name in the Review toolbar is now a Close (×) button (`review-close-file`); at phone width the toolbar is a sideways-scrolling strip with the name off screen, so phone gets its own always-visible 44-tall "‹ Close" bar under the header. Close → flush the review (`saveNow`) → `resetSingle()` (a fresh blank review id, which the last-doc pointer effect records, so a reload finds nothing to resume and **stays on the index**) → the index for the current project, or "Pick a project" when none. A Word/text file with unsaved edits asks **Save / Discard / Cancel** first (`CloseFileDialog`; Escape = Cancel; Save waits on the editor's own Save, which now resolves true/false via a `saveRef`, and a failed save keeps the file open). PDFs autosave, so they close without a prompt. Word/text files are now also recorded as recents and as the resume target (they open in the editor — the old "can't be shown" exclusion no longer applies).
- **Red-proof:** `ui-audit/verify-review-close-file.mjs` (25 checks, real Chromium on the built app, desktop + 390-wide touch) — against current `main`'s build it fails at "a Close control sits on the file name" with both known-good arms (empty index shows no Close; PDF reaches the canvas) green, so it can see the thing. `test/reviewCloseFile.test.js` fails to load on `main` (no `unfiled.js`).
- **Adjacent cases (measured):** PDF open→close ✓ (no project → "Pick a project"; in a project → that project's "Current set") · Word clean→close, no prompt ✓ · Word dirty → Cancel keeps the edit still unsaved ✓ / Discard drops it (reopen shows the original) ✓ / Save writes (no download) then closes ✓ · Escape on the prompt = Cancel ✓ · .txt dirty prompts ✓ · reload after Close stays on the index for PDF and Word ✓ · phone: control on screen, hit-testable, nothing scrolls sideways, the prompt fits ✓.
- **Adjacent bug found and fixed in the same PR — B2039234:** switching project from the breadcrumb while a Word/text file had unsaved edits dropped the file and the edits with no prompt (measured before the fix). It now asks the same Save / Discard / Cancel; Cancel (or a failed Save) navigates back to the project you were in.
