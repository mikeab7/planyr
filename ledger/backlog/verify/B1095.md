- **The ask.** "I'd like to be able to hover over any contour and it show me the elevation … probably just similar to how it shows the five foot ones." At Tsakiris ~30 index contours carry a permanent label; the other four-in-five 1-ft lines carried none and could not be interrogated at all.
- **Why they were unhoverable (AUDIT-FIRST).** The polylines render into an `L.canvas` with `interactive:false` — B704's deliberate perf decision, since thousands of 1-ft lines with Leaflet hit areas is the perf cliff. Making them interactive to answer this would undo that decision.
- **Fix — hit-test in JS, never make a line interactive.** `contours.js` gains the pure pair `buildContourIndex` / `hitContour`: a flat spatial bucket over the SAME composed geometry `composeContourPaint` paints (one composition, one index — no second geometry model), probed in longitude-scaled degrees so the tolerance is a constant number of SCREEN pixels at every zoom. Ties resolve by LEVEL, so the answer under a resting cursor cannot depend on which tile resolved first (the B1087 determinism rule).
- **One transient label, in its own sublayer.** `terrainLayers.js` paints exactly ONE marker into a dedicated `hoverGroup`, using the same white-halo divIcon, size and colour as the permanent index labels. It is cleared on every move, re-parented empty on every repaint (a label can never outlive the lines it named), and dropped on `onRemove`. It carries `.planyr-contour-hover` so a harness can tell the transient one from the permanent set. NO DOUBLE-STAMP: a hit whose level already has a permanent label within ~40 px paints nothing. Same z16 gate as the contours.
- **No second listener.** `setContourHover(map, ll)` is fed from the cursor position each surface ALREADY computes for the ground readout (the map finder's rAF-throttled `onCoordMove`; the planner's `cursorLL` memo). The `map` argument means the inactive-but-mounted surface's layer clears instead of painting for a cursor that isn't over it.
- **Sandbox + headless evidence.** `test/contourHoverReadout.test.js` (37 green) pins the hit-test: an unlabelled 1-ft line answers, intermediate values read 152/153/154/155, the returned point lies ON the line, a cursor between lines answers NOTHING (no nearest-line fallback), the result is order-independent, ties resolve by level, a segment longer than a bucket is still found, and the tolerance scales. `e2e/contour-hover-elevation.spec.js` drives the REAL planner logged out at the Tsakiris coordinates against REAL 3DEP LiDAR (the sandbox's browser egress can't reach the USGS host, so the spec relays that ONE request through Node — a transport detail only; the app's own fetch, decode, worker trace and paint all run for real). Measured: **30 permanent index labels · a 110-point sweep landed on a line 71 times, naming 149/150/152/153/154/156/157/158 ft — intermediate 1-ft values, not only multiples of five · never more than ONE transient label · agreement with the bottom-left ground readout median 0.30 ft, p90 1.00 ft · leaving the lines cleared it (0) with the permanent set unchanged (30 → 30) · zero duplicate stamps · zero page errors.**
- **The matching optimization (the perf-budget rule).** The two features added real bytes and tripped `bundle.largestChunkBytes` in CI (1715.5 KB vs a 1709.0 KB ceiling). Per `docs/perf/PERF-BUDGETS.md` a breach ships with an optimization or does not ship, so the terrain pipeline now **loads on demand**: `terrainLazy.js` is the ONE entry point (`loadTerrain()` cached import + a SYNCHRONOUS `terrainNow()` so the per-move cursor sample stays a plain function call once the chunk has landed), `terrainGate.js` carries the zoom gate so the layer registry can read it without dragging the pipeline back in, and `contourTrace.js` splits the worker-only marching-squares tracer (the sole `d3-contour` consumer) out of `contours.js` — the `lercGrid.js` (B1042) precedent, one module over. `layers.js` imports the layer constructors at the first terrain toggle and refuses to resurrect a layer the user switched off while the chunk was in flight. Result: **1704.1 KB, 4.9 KB UNDER the ceiling — below where the chunk sat before these features.** `test/contourHoverReadout.test.js` pins it (only `terrainLazy.js` may reach `terrainLayers.js`, the gate module imports nothing, and the tracer may not come back), because this is precisely the kind of split a later change undoes by accident.
