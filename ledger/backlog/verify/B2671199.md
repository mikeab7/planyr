- Verify: live (timing/race class: a second real tab on the bare domain).
- **Repro (measured live, build `caf2020`, `ui-audit`-style driver, the project opened by clicking its row in the Sites rail so it is a REAL open project, `#/project/e2e-fixture/site`):** click the header wordmark (`title="Dashboard: all projects"`) → URL becomes `#/`, but `localStorage["planyr:lastRoute:v1"]` still reads `{"module":"site-planner","projectId":"e2e-fixture",…}`; a second tab opened on `https://planyr.io/` lands on `#/project/e2e-fixture/site`. (An earlier run that set the hash by hand to an id the app never opened gave the same answer, which is why it was re-run through a real click before being believed.)
- **Root cause.** `Shell.goDashboard` (the wordmark and the Dashboard crumb) just sets the bare hash "#/". Shell's single pointer writer was `if (!isAdminHash && !isDesignHash && !isDashboardHash) writeLastRoute(route)` — it deliberately SKIPPED the Dashboard (B711904 excluded `/admin` and `/design`; the Dashboard rode along when B1213312 made bare "#/" the Dashboard), so nothing cleared the pointer. `leaveProject`/`goMap` (NEW-2(b)) only run when the Site Planner itself initiates the exit.
- **Fix.** `lastRoute.js` `pointerForRoute(route, {admin, design, dashboard})` — admin/design → no write (unchanged); Dashboard → the NEUTRAL no-project pointer; anything else → the route. Shell's one writer effect goes through it. `seedBootRoute` runs at module scope before the first render, so a bare-domain boot that has a pointer is seeded before the Dashboard effect can run (no boot race). Guards: `test/lastRouteDashboardClears.test.js` (pure rule, red-proof against the old skip rule, source guard on Shell).
