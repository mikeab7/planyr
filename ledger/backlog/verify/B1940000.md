`[x]` **SHIPPED THIS SESSION — the whole redesign, both data and UI halves.**
- **Score precision — 1 to 10 in QUARTER steps, not half.** `food_dishes.score` widened `numeric(3,1)` → `numeric(4,2)`; `food_dishes_score_check` loosened from `(score * 2) = round(score * 2)` to `(score * 4) = round(score * 4)`, same 1.0–10.0 bounds, nullable unchanged. **Applied live to production (`lyeqzkuiwngunutlkkmi`) and verified non-destructive**: an md5 checksum over all 5 existing `food_dishes` rows (`id` + `trim_scale(score)`) and all 185 `food_visits` rows (`id` + `trim_scale(rating)` — untouched by this migration) matched EXACTLY before and after the `ALTER`. Boundary-tested live against production too: 8.25/8.5/8.0/10.00/1.0 accepted, 8.3/8.125/0.75/10.25 rejected — matching the brief's own acceptance table exactly. `numeric(4,2)`, never the brief's `numeric(3,2)` (which overflows at exactly 10.00 — the same trap this table's own `numeric(3,1)`→`numeric(4,2)` precedent, and `food_visits.rating`'s, already named). Display trims trailing zeros (8.00 → "8", 8.50 → "8.5", 8.25 → "8.25") via a new `formatScore()` — `Number()` coercion does this for free since 0.25/0.5/0.75 are all exact in IEEE754.
- **The score control — same native slider, the "Not rated over a filled track" bug killed at the root.** `ScoreMeter.jsx` rebuilt: step 0.5 → 0.25; a large right-aligned numeral (with "/ 10") above the track, next to a "SCORE" label and a caption that reads "quarter steps" while set and a plain unset statement while not — never silent; real minus/plus `<button>` nudge controls (own `nudgeScore`/`clampScore` pure functions, exported and unit-tested) stepping exactly 0.25 and clamping at 1/10; tick labels 1/3/5/7/9/10 under the track only. **The shipped defect**: the unset state showed the thumb at a fixed mid-scale rest position (visually filled) UNDER the words "Not rated" — two contradictory claims. Fixed by showing the thumb at the scale's own floor (nothing filled) with a flat neutral track colour whenever unset, so nothing on screen implies a value that was never set.
- **The editor's field hierarchy, rebuilt top to bottom**, per the mockup: a "New dish"/"Edit dish" label + close ✕ · the dish name as the ONE hero field (large, transparent, no box, a 2px accent underline — it shipped as a plain grey box identical to Note, so the most important field had no visual priority) · Course + Price sharing a row (Course flexes, Price fixed-narrow) · the Score block · an Order-again block that now carries its own "Order it again?" label (it shipped with three buttons and nothing saying what they answered) and gives EVERY selected state the same accent fill (previously only "yes" got the real fill — "maybe"/"no" read as lesser answers) · Note last, least visually prominent. Every field label: small-caps, 10px (`FONT_SIZE.micro`), letter-spaced, secondary-text token.
- **Buttons — an owner decision, not a guess (asked mid-session rather than assumed).** Adding a NEW dish: "Save & add another" (full-width solid, the real action when logging a meal) + a bordered "Save & close" + a plain-text Cancel, with the Enter/Esc hint. Editing an EXISTING dish: **exactly one primary "Save" + plain-text Cancel** — no "Save & close", no "Save & add another" (those exist only where there are genuinely two different next steps; editing has one).
- **Dish rows, redesigned**: the SCORE CHIP moved to the far left (the list sorts by score, so the column reads at a glance) — a three-tier ramp, deliberately NOT `ratingColor.js`'s 10-step place-pin ramp (`dishAggregates.js`'s new `dishScoreTier`): high (≥8) solid accent fill, mid (≥5) a tinted accent chip with a hairline border, low a plain neutral gray — never red, which this app reserves for genuine danger. Then the name + a compact `course · price (+ had N× / a short note)` line. Then a small round order-again badge (glyph only, conditional on an answer existing). Then a kebab menu at the right edge. **The bare delete ✕ is gone** — it sat immediately beside the score chip, which is how a dish got deleted by mistake; Delete now lives inside the kebab, behind its own two-tap inline confirm (never `window.confirm`). **The standalone pencil is gone too** — clicking the row now opens the editor directly, which the pencil was redundant with. A dish with no score renders as a dashed row: an em-dash chip, "Not scored yet" in accent text, and a small solid "Score it" button.
- **⛔ OWNER DECISION, recorded so it is not relitigated: the per-dish HISTORY view (score-over-time + past notes) is KEPT, not cut.** Row-click now opens the editor (per the brief), which left history homeless — asked rather than silently dropped or silently kept. Owner, verbatim: history "is the whole point of the feature," keep it, move it into the kebab menu as a third item beside Edit/Delete, shown only when the dish has more than one rating (`row.history.length > 0` — nothing to show for a first-time dish).
- **Phone width**: nudge buttons 50px square, the range input's own height 40, order-again buttons 54px tall, the save row pinned to the editor's own bottom edge with a narrow "Done" (add flow) / "Cancel" (edit flow) on the left and the wide solid primary on the right. Every interactive control clears a 44px effective tap area — the app's own `tap-target` CSS class (hit-area-without-growing-the-box) is applied to every control whose visible box reads smaller than that (the kebab trigger, the nudge buttons, the close ✕, "Score it").
- **Kebab menu** — the shared `AnchoredMenu`/`MenuItem` primitives (`shared/ui/`), the same portal-flyout shape every other per-row kebab in this app already uses (e.g. `ScheduleOwnerList.jsx`) — not a new mechanism invented at the call site.
