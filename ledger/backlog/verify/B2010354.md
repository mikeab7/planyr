### B2010354 — KMZ export: parcel outlines must read correctly whether they live on the site record, the comp, or both `[comps / KML export]` (bug) #comps #export  *(Owner report 2026-10-01 (NEW-3): the export put a parcel-anchored comp's outline under Comps in the comp colour with no name context, while the site balloon read "Acreage: No boundary drawn yet". **Direction CORRECTED mid-session by the owner via the Cowork chat:** the first reading ("the outline belongs to the site record; seed the boundary onto the record at comp-log time") was the brief-writer's inference, retracted — and the "Sites stayed 41 / Records 7→8" evidence was retracted with it (the Sites list may simply omit tracked-only records). Michael's actual rule: it must work for BOTH. Logging a comp on a parcel does NOT change how site records are created or updated — a first cut that did was built and fully backed out before merge.)*

`[x]` **Cause:** the balloon builder drew a parcel-anchored comp's `parcelGeom` under Comps with no naming, and the site balloon read acreage only from the site's own drawn parcels, so a record whose only ground was its comp's parcel read "No boundary drawn yet" while the file held an outline.
`[x]` **Fix (`siteRecordKml.js`, pure):** **site has a boundary** → Parcel folder, site style, its acreage in the site balloon. **Comp is parcel-anchored** → outline exported with the comp (Comps folder, comp colour), named "<comp> — comp parcel" (one pin per comp, no second pin from the outline). **Both, same parcel** (shared APN with the site parcel's `acct`, or same lot by geometry: comp centroid inside the site ring and areas within ~18%) → drawn once, the site's. **Both, different parcels** → both drawn. The site balloon never says "No boundary drawn yet" while the file holds an outline for the record: comp-only reads "Comp parcel: 22.48 AC"; a pin-only comp on a boundary-less site still says "No boundary drawn yet" (nothing in the file to claim).
`[x]` **Map notes (owner addition):** BEFORE this item, notes were NOT in the KMZ as map features — only notes linked by `project_id` appeared, as plain text lines inside the site balloon (and a note anchored on the record's parcel but not linked was omitted entirely). NOW the record's notes — linked by project, OR anchored inside an exported outline / carrying its APN; deleted ones never — are pins in a **Notes** folder with title + body in the balloon, escaped the same way as comp balloons (`balloonHtml`). The site balloon no longer repeats them.
