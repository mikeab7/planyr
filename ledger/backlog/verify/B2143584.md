### B2143584 — NEW-1: editable PDF markups keep their look when a recipient EDITS them (callout goes dark, fills go solid, cloud shrinks, measurement number vanishes) `[Site Planner / export]` (bug) #site-planner #export #markup  *(owner chat block 2026-10-06 — amends B2127664 / V1544944, PR #2057 d9fd8c5; measured by Cowork 2026-10-05 evening with PyMuPDF `annot.update()`)*
`[ ]` **⏳ merged — V1560864 PENDING (Verify: live — `Blocker: real-data`, Michael's own Bluebeam/Acrobat).** As-written pages were always right (MuPDF + Poppler matched the screen). The defect shows only when a viewer REGENERATES the appearance from the annotation dictionary — which Bluebeam/Acrobat do the moment a recipient edits a markup's text or properties — because several keys disagreed with the appearance stream (`/AP`).
- **Root causes → fixes (`lib/pdfAnnotations.js`, `lib/imagePdf.js`).** (1) FreeText `/C` was the BORDER colour; it is the box FILL → now `/C` = the box fill (omitted when the box has none, K2), border colour in `/DA` (`RG`) + `/BS`; `/IC` no longer written on FreeText (MuPDF reads it as the box background — measured: the box went dark again) or on Line/PolyLine/Stamp. (2) Translucent fills regenerated opaque because the fill opacity lived only in `/AP` → `/CA` = the FILL opacity when the fill is translucent (`/CA` paints fill AND stroke in a regenerating viewer, so the border is faint there — judged far less bad than an opaque slab). (3) Cloud `/BE /I` was a hint-based 1 or 2 → derived from the scallop pitch the AP really draws (`cloudPitch` → `cloudIntensity`, ≈6.2 pt per unit `/I` on MuPDF, clamped to the spec's 0–2, so a very large Planyr scallop caps at ~12 pt). (4) A two-point measurement's number lived only in the AP → `/Cap true /CP /Top` + `/Contents` = the number in WinAnsi stand-ins (`142' 6"` — a regenerated caption cannot set ′ ″), with a typed note appended after it. (5) FreeText `/DA` now names the real face (`Helv`/`HeBo`/`HeOb`/`HeBO`) and the AcroForm `/DR` defines each.
- **Measured (PyMuPDF 1.28, regenerate every annotation, 60 dpi, 13-annotation fixture):** page mean abs drift **5.28 → 0.65**; Square/Polygon fills 100%/66% of their box differing → 6.7%/4.3%; callout 51% → 6.7% of its box; every as-written render byte-identical before vs after in BOTH MuPDF and Poppler (max pixel diff 0). Flatten ON path untouched (no annotations ⇒ same bytes, still asserted).
- **Known, stated limits (not hidden):** a Polygon (area) or multi-vertex PolyLine measurement has NO native caption in the spec, so its on-sheet number still lives only in the appearance (it is in `/Contents`, so it shows in the comments list) and a regeneration drops it — a companion FreeText was rejected because moving/deleting the shape would strand the label and Acrobat's handling of a grouped (`/IRT /RT /Group`) annotation could not be checked here. A regenerated callout's arrow head is hollow (the only way to fill it is `/IC`, which MuPDF turns into a dark box). A regenerated text box is regular weight, square-cornered and top-aligned in MuPDF. Cloud scallop PHASE is the viewer's. "⚠" still falls to "!" (WinAnsi).
