- **PRODUCTION STATE AT THE TIME OF THE CHANGE, measured:** 65 sites across 5 owners, 1 team, 3 members, **1** shared site, 0 shared reviews, 0 shared files. After the migration: **identical** — 65 / 1 / 0 / 0, 0 locked.
- **WHAT SHIPS.** A new project created by a user who is on a team is born with `team_id` set, so their teammates see it and can **fully edit** it. A new PLAN inside an existing project inherits **that project's** sharing and never consults the account default. Notes, Library, Review and Schedule are untouched.
- **⛔ THE SCOPE GUARANTEE IS ENFORCED IN THE DATABASE, NOT IN THE CLIENT — see B326419.** This is the highest-risk part of the item and it is not left to client discipline.
- **WHAT IS AND IS NOT SHARED, verified against the schema rather than assumed:** Notes (`notes_pages` / `notes_trees` / `notes_images`), Schedule (`planar_*`), Library folders (`project_folders`) and `pins` have **no team column at all** and are own-row RLS, so they were never in scope. `doc_reviews` and `file_facts` DO have one; `set_project_team` deliberately leaves both alone, so Review and the Library file index stay with their owner.
