`[x]` **⏳ merged — V483 PENDING (Verify: live — `Blocker: live-GIS`).** The 4x claim is CONFIRMED and then some: the Leaflet container measured **2018 x 1025 px = 2.07 Mpx against ~0.53 Mpx visible — 3.9x the pixel area** before retina; at dpr 2.15 the working zoom pulled **105 tiles where a bare viewport needs ~12–15 (7–8x)**; one scenario load fetched **221 tiles ≈ 3.5 MB** (avg 16.6 KB, sampled from the real URLs) across FIVE zoom levels — z11=21, z12=56, z13=24, z15=15, z18=105 — of which **~116 (53%) are transitional levels the user never lingers on**. Since ~420 MB of the reported 555 MB is decoded-bitmap/GPU rather than JS heap, **this is the memory fix**.
- **Retina is NOT switched off** — a soft aerial is a core-credibility regression for a tool people eyeball sites in. `tileBudget.retinaForZoom` keeps full density at the working zooms and clamps only at the wide context zooms, extending the B182/B218 `maxNative-1` clamp rather than replacing it. **Named limitation, stated rather than buried:** Leaflet bakes `detectRetina` into the tile grid at construction, so the band is evaluated when the layer is BUILT (basemap on/off, source switch, origin change) — re-deciding it mid-gesture would mean rebuilding the layer and refetching every tile, a worse trade than the one it saves.
- **Adaptive overscan + keepBuffer.** `tileBudget.overscanPx` / `keepBufferFor` step both down on a heavy plan, a device reporting little memory, or a small window — the measured viewport was only 465 px tall, where a fixed 320 px per side is most of the container. `keepBuffer: 4` is revisited alongside it, since it multiplies on top. A real margin always survives, so the B65 pan-reveal never vanishes.
- **The biggest single lever: tiles are reused across a commit.** Leaflet's `Map._resetView` fires `viewprereset` on EVERY `setView`, and GridLayer's handler wipes every tile and level unconditionally — then immediately asks for most of them back. But tiles are keyed by NATIVE tile zoom, and the planner drives the basemap at fractional zoom, so a commit that moves the fractional zoom without moving the rounded one needs no new tiles at all. `preserveTilesAcrossSetView` skips the wipe exactly then (the caller announces the target zoom, since Leaflet hasn't applied it yet at `viewprereset` time) and falls straight through to stock behaviour when the native zoom genuinely changes. A `setView` from anywhere we did not announce always takes the stock wipe — no stale tiles behind our back.
- **Bounded cache.** `boundTileCache` / `tileCacheLimit` put an explicit ceiling on retained tiles, sized from what the container genuinely needs plus headroom. Only non-current tiles are ever shed, so it can never punch a hole in the visible aerial.
- **Gate:** `ui-audit/diagnose-flash.mjs` re-run — no flash regression detectable, but honestly, **it cannot discriminate in this sandbox**: external tile hosts are egress-blocked so the loaded-tile count is 0 for every frame either way. Tile COUNT held flat across the zoom (45 before, 45 after), which is the half this change affects. The flash check itself is genuinely live-only and is what V483 exists for.
