**THE NEW TRAP, caught before it shipped: `/identify` mangles `GIS_AREA`, the OPPOSITE of the 2026-09-12 item's own finding for the dead mirror's `/query` responses.** Sampled live via `/identify`: `GIS_AREA` comes back as a TRUNCATED string in scientific notation ("5.0968505128e-", an incomplete exponent — invalid number syntax, not just an unusual one), while `LEGAL_AREA` comes back clean ("53.803"). `acreageKey` (kept from the 2026-09-12 item — it is a genuine improvement independent of which layer is live) now verifies a GIS-column value actually parses as a number (`Number.isFinite(Number(v))`) before preferring it over `LEGAL_AREA`; a value that fails (this truncation, or an empty string) falls through exactly as if the GIS column were absent. This is general, not `/identify`-specific — it also protects any other source that ever ships a genuinely garbled GIS-area column.
