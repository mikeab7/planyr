- **He was right, and it was measurable: eighteen of twenty-two layers shipped their default opacity inside a single 0.10 band** (0.85–0.95), each value picked in isolation months apart. There was no model, so there was nothing to be inconsistent WITH. `lib/layerWeight.js` is that model, and it is about **decision impact** rather than geometry — role already decides ORDER (`mapStack.js`), this decides VOLUME: **constraint** (it can stop you building or takes land — floodplain, easements, pipelines, faults, wetlands) ≤ 0.85 · **reference** (a fact you look up) ≤ 0.55 · **context** (orientation furniture) ≤ 0.40, with matching stroke-weight ceilings because a 3 px reference centreline reads louder than a 1.5 px constraint line at any opacity.
- **The ceilings are ENFORCED, not suggested** (`test/layerHierarchy.test.js`, 16). A layer with no declared tier fails the build — adding a layer is exactly when deciding its volume is cheapest — and each failure mode is shown red. Two judgment calls are named on the item rather than left implicit: **road authority** and **NHD flowlines** look like context and are not (who maintains the frontage decides who permits the access; whether there is a channel at all is a drainage fact, and it is the universal fallback where no district publishes GIS).
- **AGENCY-DRAWN LABELS: every server-rendered layer now PINS its sublayers.** `layers: null` sends no `layers=show:` at all, which tells the agency to render every default-visible sublayer — and agency services routinely publish a LABEL sublayer beside the data one (the RRC's layer 0 is literally "Well Number", drawn at parcel zoom). Two rows were unpinned. The one that cannot be pinned — Fort Bend's contour service, whose host sends no CORS headers so its catalog is unreadable from here — takes an **acknowledged, in-words exception** rather than a guess, the same discipline as the registry's `monitored-exception` tier.
- **The way out is one click.** "Turn all N layers off" clears every overlay and leaves the plan and the basemap, because the basemap is its own control and not a member of the overlay registry. The button carries the count and disappears when there is nothing to clear, so it is never dead chrome. **Exempt-from-the-ceilings and exempt-from-the-sweep are different questions** — the first cut conflated them and skipped terrain in the sweep, which is wrong: the owner turned contours on the same way he turned everything else on.
