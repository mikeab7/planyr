### B2671321 — Bulk-edit properties across a same-type multi-selection `[Site Planner]` (feature) #site-planner #ui #undo
`[ ]` Owner (2026-11-24): "if I select multiple elements of the same thing I should be able to edit their properties all at once." DEDUPE-FIRST: searched Open/Verify/Done for multi-select / shared properties; only B740 (shared STYLE across a selection, shipped) is adjacent. Built on top of it.
- Verify: live
- Panel: `components/MultiPropsInspector.jsx` over the pure registry `lib/multiProps.js`, shown above the existing shared-style panel. A field every member agrees on shows the value, a field they disagree on shows "Mixed" (an unset override reads "auto"). One typed value goes to every UNLOCKED member (locked ones are counted and left alone).
- Fields: building Length / Depth / Rotation / Clear height / Slab / Pad elevation; road width; car parking Width / Stall depth / Drive aisle / Rotation; trailer parking Stall depth / Stall width / Drive lane / Label shown (tri-state tick) / Rotation; paving, sidewalk, landscape Width / Depth / Rotation; a mixed-type selection shows Rotation only. Colours, opacity, line weight, pattern already covered by B740's panel (also for markups).
- No parallel form logic: every write is the planner's own by-element writer (`resizeElToValue`, `rotateAssemblyTo`, `setRoadTravel`, `setParkCfg`, `setTrailerSpec`, `toggleElLabel`), so bonded courts, trailer rows, buffers, stalls and labels follow exactly as in a single edit. ONE undo step: `bulkHistRef` in `pushHistory` records only the first frame of a bulk run.
- Not covered, said plainly: ponds and drive-in ramps (bespoke panels, no bulk fields yet); loading / dock-wall pickers and per-wall layer rows on buildings (those handlers read the plan state directly and would overwrite each other if looped).
- Sandbox done: `test/multiProps.test.js` (10), `e2e/multi-props-bulk-edit.spec.js` (3 buildings, Mixed → typed 420 → all three; one Undo restores all; Redo re-applies; survives reload), full vitest green.
