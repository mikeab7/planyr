### B2382272 — NEW-1: Ctrl+C on a selected element copies nothing visible; Ctrl+V pastes the OS clipboard screenshot instead `[Site Planner]` (bug) #site-planner #clipboard  *(owner chat block 2026-10-22, live planyr.io, Windows Chrome, Goose Creek / Concept: selected a cloud, Ctrl+C, Ctrl+V → the old Windows screenshot pasted as an image. Related, NOT a duplicate: B2207872 (Ctrl+V image = overlay) is the rule that made the image win; B-NEW-1/NEW-6 planClipboard already covered every kind in memory.)*
`[ ]` **⏳ merged — V1810656 PENDING (Verify: live — signed-in test account on planyr.io).** Root cause (reproduced in the sandbox, red on main): the element clipboard was in-memory only, and the window `paste` listener gives any clipboard IMAGE priority over it — so with a stale screenshot on the OS clipboard the elements never pasted. Candidate (a) (no handler / focus gating) was REFUTED: Ctrl+C already worked for el · markup · measure · callout · parcel and mixed selections.
- **Fix:** `lib/clipBridge.js` — every copy (Ctrl+C, Ctrl+X, menu Copy) also writes a Planyr-marked JSON payload to the SYSTEM clipboard (replacing any screenshot), and the `paste` handler parses it first (before images), re-seeds the store and runs the one `pasteClip` (fresh ids, cursor/in-place placement, selected, one undo step; works into another plan or project, and across tabs). Anything else on the clipboard behaves exactly as before. A refused system write shows a visible warning + `copy-clipboard-write-failed` telemetry and the in-app copy then beats a stale image. Text fields / panels are untouched (focus-scope gate unchanged).
- **Before the fix:** worked — all kinds with NO image on the OS clipboard; broken — every kind (building + its assembly, all markup types, measurements, callouts, parcels, multi-select) whenever an image was on the OS clipboard. Reference overlays (Site tab) keep their separate internal copy path (constraint #11) and are NOT covered by the bridge.
- **Sandbox-verified:** repo-root `test/` **clipBridge** (round-trip per kind, foreign text rejected, write failure loud); e2e **copy-paste-system-clipboard** (real keystrokes + real clipboard: stale image then Ctrl+C/V on a building and a polygon markup; plain image still an overlay; text-field copy/paste untouched) — RED on the pre-fix SitePlanner, green after; existing **paste-image-overlay** green.
