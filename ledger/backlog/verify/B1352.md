- There is currently **ZERO `React.memo` anywhere in `src/`**, so React sees a flat array of host elements with fresh props and diffs all of them — 100% reconciliation for the ~2 of 194 states that change during a pan. Corroborated by measurement: `ui-audit/diagnose-pan-commits.mjs` records **193,303 DOM mutation records across 60 pointermoves** even after B1345 cut the node count by 63%.
- **Two preconditions, both load-bearing:** (1) `useCallback` on its four handlers — they are fresh arrows per render, so a memo without this is a no-op; (2) replace the whole-`allEls` argument with **resolved neighbours**, because an element's render genuinely depends on its neighbours through `curbEdgesOf` / `bumpsAlongLength` / `dockSidesFor`. A naive memo on `el` alone produces **STALE CURBS** when an adjacent element moves. Model that dependency explicitly.
`[x]` **SHIPPED 2026-07-31 — and it does NOT move the wheel-zoom number. Both halves of that sentence are measured.**
- **BUILT.** `renderElPx` now renders through `ElNode`, a module-scope `React.memo` component (the first `React.memo` in `src/`). Both preconditions are in: the five element handlers are bundled behind an identity-stable latest-ref indirection (`useCallback` was rejected — these close over a large shifting slice of a 25k-line component, and a missed dependency is a STALE HANDLER, which is worse than a slow render), and the whole-`allEls` argument is replaced by `resolveElNeighbors`, a per-element resolved record of the four things an element's drawing genuinely reads from its neighbours (curb edges, dog-ear bumps, the dimension slide range, and a bump-out's host style). `sel` and the suppressed-dimension Set are likewise passed as pre-resolved booleans, so a selection change re-renders two elements instead of all of them. **No element type was excluded** — the neighbour dependency is modelled exactly, so none had to be.
- **PIXEL PARITY: byte-identical.** `ui-audit/verify-stall-lod-parity.mjs` across five zoom rungs plus the exported sheet — IDENTICAL at every rung, same node counts, same stall counts, zero segment drift on the PDF path. B1345's bar, met with nothing spent against it.
- **⛔ IT MOVES THE TARGET GESTURE BY LESS THAN THE NOISE FLOOR, and the reason is structural, not a shortfall.** Interleaved A/B, 5 pairs at 4x throttle: wheel median **166.6 (base) vs 166.6 (new)**, script mean 4,883 vs 4,794 ms — against a within-arm spread of 149.9–200 ms and 4,021–6,055 ms. The floor is roughly ±20%. **Why:** `f2p` changes identity whenever the view changes and every element's pixel geometry genuinely changes with it, so the memo misses on 100% of elements during a pan or a zoom **by construction**. That is now written at the top of `ElNode` so nobody re-derives it. **B1360** owns what would actually move it.
- **THE WORK IS GENUINELY GONE, even though the frame cannot see it.** CPU profile, same gesture, before vs after: `edgeAbutsPaving` + `curbEdgesOf` **4.8% → 2.1%** of script self-time.
