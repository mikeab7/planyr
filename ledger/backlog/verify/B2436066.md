Follow-up to B2391216 (×2). DEDUPE-FIRST: B1091 / B1091(×2/×3) (flood-row relevance by county) is the mechanism that failed open here — this item replaces its input with a location rule, it does not re-open them.)*
**THE REAL DIFFERENCE (measured, so it is not rediscovered).** The brief's inference was right in kind and incomplete. (1) The planner scopes the district rows by `floodCounty`, computed in `LayerPanel` as: the site IDENTIFY county if it names exactly ONE, else **`null` when it names more than one** (a Baytown site straddles Harris and Chambers), else `siteCounty` (`restored?.county`, null until the identify/heal lands). **A null county fails OPEN** — `floodRowRelevance` / `districtReaches` / `areaCounties` all return "relevant" for an unknown county — so every Houston source is listed. The finder reasons over `countyForView`, which returns a real county for ANY point (polygon, else bbox, else nearest centre) and is never null; so it hid them. Pinned in `test/layerServiceAreas.test.js` ("the planner's null county no longer lets the Houston rows through"). (2) `REGION_ZONES.houston` was a 65-mile circle round downtown Houston that contains Chambers, Galveston and Brazoria, and its comment claimed HCFCD / BKDD / City of Houston data reach them — false. The circle is what the nine Houston-area rows used as their location rule, so it could not have saved a null-county planner. **Not reproduced on a throwaway:** a fresh located plan at Grand Port on the OLD production build (c574b64) healed its county to Chambers and listed the correct two rows on both surfaces; the owner's plan carries the multi-county / unresolved state. (Disposition per STANDING RULE #2: the fix removes the dependency on that input rather than relying on a repro.)
Shipped — **the location rule no longer reads any county the host identified.** Each source declares the real boundary it serves; both hosts and the map's draw filter ask the SAME pure function (`layerPanelModel.layerAvailableHere` → `inRegion` → `serviceAreas.areaContains`) with the SAME inputs (plan origin / finder view centre + state): `hcfcd_row` → **`harris`** (Harris County, from the same bundled county polygons `countyForView` uses — one definition of "Harris"); `coh_storm`, `coh_ww`, `coh_water`, `coh_hydrants` → **`houston`** = the **City of Houston limits ∪ its ETJ** (TxGIO City_Boundaries full-purpose + H-GAC `HGAC_City_ETJ_Boundaries` CITY='HOUSTON'; the real boundary WAS available, so the "Harris County" fallback was not used); `bkdd_drainage`, `bkdd_easements`, `bkdd_dmp` → **`bkdd`** (the Brookshire–Katy Drainage District boundary, Waller County GIS layer 54). The growth-fault row keeps a circle, renamed `houston_metro` — it is a metro-scale USGS study extent, which is what a circle is honest about. Data: `lib/serviceAreaData.js`, GENERATED by `scripts/build-service-areas.mjs` (committed; re-run to refresh), loaded by dynamic import (own chunk, nothing on the boot path) via `lib/serviceAreas.js` + `lib/useServiceAreas.js`. **Fails open** on: no location, geometry not loaded yet / failed to load (loud `console.error`), unknown area name (a unit test fails the build on a typo). The simplified boundaries are approximate (≈0.4 km), so a point counts as inside when ANY of five probes (the point and four ≈0.3 mi offsets) is — an approximation can only err toward SHOWING a layer. A layer left ON where its source does not serve is kept in saved state and simply not drawn (unchanged rule).
**Consequences owners should know:** downtown Houston no longer lists the three BKDD rows (it is outside that district — it used to list them because Harris is one of BKDD's counties); a Harris site outside Houston's limits+ETJ (Baytown's Harris side) lists HCFCD Channels & ROW but not the City of Houston Storm Sewer / Water & Sewer / Fire-hydrant sources; a Fort Bend site lists none of the Houston-area rows (Sugar Land used to list the BKDD ones).
Adjacent cases, each asserted (unit `layerServiceAreas`, ui-audit `verify-imagery-layers-panel`, and on the real app by `verify-layers-areas-live`): Harris inside Houston (Channels & ROW + Storm Sewer show) · Harris outside Houston (HCFCD shows, Storm Sewer does not) · inside BKDD (the three BKDD rows show, nothing else) · Fort Bend · Chambers (Grand Port AND Mont Belvieu — exactly FEMA + Streams) · Galveston · and the planner and the finder list the SAME rows at the same point, with NO county identified.
