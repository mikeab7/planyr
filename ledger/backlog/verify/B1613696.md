**THE FIX.** A new `sites_stamp_rename_on_insert()` BEFORE INSERT trigger — the same shape `sites_normalize_county`'s BEFORE INSERT OR UPDATE trigger already uses — seeds `data.siteRenamedAt` on any row arriving with no valid `rename_stamp`, from that row's own `updated_at` in epoch ms (falls back to `now()` if that is somehow absent — it never is; the client always sends it explicitly, and the column itself defaults to `now()`). This is the SAME Tier-2 convention `rename_stamp_backfill_20260912.sql` used for the 87 rows it could not transcribe from a sibling — one convention, not a second one, per the dispatch's own instruction. It runs unconditionally on every INSERT into `public.sites`, whatever wrote it (the client's own `upsert`, a future migration, a psql session) — structural, not a call site anyone has to remember. The one pre-existing unstamped row (`smu1z3h60nbu`) was repaired in the same migration by a one-line, self-scoping `UPDATE … WHERE rename_stamp(...) IS NULL` (the identical Tier-2 rule, never a hardcoded id) — an INSERT trigger cannot reach a row that already exists.

**CHECKED BEFORE SHIPPING — nothing reads the stamp as proof a real rename happened (the dispatch's own design point).** The one place `siteRenamedAt` is rendered to the owner as evidence of a rename EVENT is the dashboard's "Since you were last here" feed (`dashboard/lib/sinceLastHereFeed.js`'s `buildPlanEvents`), and it already resolves "created" before "renamed" for the same plan in one visit window, off the row's own real `created_at` COLUMN — a genuine, independent server timestamp this trigger never touches. A birth-stamped row therefore still reports "New plan X," never "Renamed to X," the first time it's seen. `projectName.nameAuthority` is the other consumer, and it already treats "carries a valid stamp" as "this copy is current" regardless of how the stamp was set — exactly what the 2026-09-12 backfill's own Tier-2 rows already do, so this introduces no new category of stamp, only closes the window before a row gets one.
