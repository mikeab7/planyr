- **Cause, confirmed against the code (AUDIT-FIRST).** The pure helpers were already correct (`lib/dogEar.js` `sidewalkSpanForBumps` / `bumpSidewalkSide`, applied by `sidewalkFullRunPatch` + `relayoutBumpSidewalks`). They were called on bump-out add, bump-out delete, zone delete and the bump-out-RESIZED branch of `refitChildren` — but the **BUILDING-RESIZED branch only called `relayoutAllSides`** (dock zones) and never re-laid the wall strips. So on a host resize the strips fell through to `fitKid`, whose `alongDim = 2 * k.alongHalf * ratio` **RESCALES the stored run proportionally** instead of recomputing it from the span rule. Growing 160 → 200 took 220 → 275 where the rule says 260; repeated resizes are what accumulated the 224 / 221.
- **Fix — the span rule is the ONE derivation, at every host geometry change.** Wall strips are now routed OUT of `fitKid`'s proportional path entirely (`refitChildren` skips them) and re-derived by a new `relayoutWallKids` from the pure `wallStripBox` — run, along-wall centre AND the flush perpendicular offset, so a strip can neither be scaled nor left hanging off the wall. Wired into the building-resize branch (the branch that was missing), the wall-strip-resize branch, `setSidewalkWidth`, `addSidewalkSide` and `removeFeature`, alongside the bump-out paths that already had it. The relayout is **identity-preserving** when nothing moved, so a correct plan cannot churn a dirty flag or a cloud re-save.
- **The pure tier is new and shared.** `lib/dogEar.js` gains `wallKidPerp` / `wallKidBox` / `wallStripBox` / `hostAxisExtents` / `ownExtents` / `wallKidAlong` / `sideOfBondedBox` / `dogEarDesc` / `bumpsOfHost` / `localToWorld` — framework-free, so `SitePlanner` and `siteModel` both derive from the same functions and can never disagree.
- **The stored record self-heals on LOAD**, not only on the next resize: `siteModel.normalizeWallKids` re-flushes wall strips to the host's current footprint on every read, the same shape and the same idempotency contract as the existing dog-ear pass. Without it the owner's plan would have kept rendering the drift until he happened to resize something. Verified idempotent on the real fixture: Building 2's never-drifted strips come back byte-identical (object identity preserved), a second load changes nothing.
- **The bump-out anchor drift is a DIFFERENT cause — noted, per the brief.** The bumps sit at cy 250.70 where `dogEarGeom` gives 250.19, but that is a stale-ON-DISK value only: `normalizeDogEarPositions` (B487/B498) already re-derives every bump's whole box on load, so the RENDER is correct today.
