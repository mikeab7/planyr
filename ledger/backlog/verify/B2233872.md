### B2233872 — Signing out copied the plan on screen into the SIGNED-OUT device store `[Site Planner / data]` (bug) #site-planner #persistence #security  *(found 2026-10-09 by the B2233521 write-safety harness, on the build before the fix — not owner-reported)*
`[ ]` **⏳ merged — V1652976 PENDING (Verify: live).**
- **Defect (measured, `ui-audit/verify-plan-switch-writes.mjs` on main 0ade8dd):** ~200–270 ms after the Sign out click, `planarfit:sites:v1:p:<planId>` — the logged-out device store — was written with the account's plan (name, elements, layers). Cause: the device store a save lands in is chosen at WRITE time by whoever is signed in, and the planner's persist-on-leave runs as it unmounts AFTER the sign-out has switched the store. Anyone using that browser signed out afterwards would find the plan.
- **Fix:** `lib/saveDedupe.js` `mayWriteForAccount` — a planner opened under an account writes only while that account is signed in; gates `saveLive` (switch flush, persist-on-leave, page-hide flush) and the autosave mirror + settle tick, reported as `save-refused-account-changed`. A planner opened with no account (signed out / before sign-in resolves at boot) is deliberately not gated. Nothing is lost by refusing: every edit was already written to the right store when made. DATA.md invariant 18.
- **Sandbox proof:** the harness PASSES on the fix and FAILS on main and with the gate forced open (same build otherwise); CI half `test/planSwitchSaves.test.js`.
- **Not done here:** an account plan already copied into a device's signed-out store before this fix is not cleaned up (needs a decision on how to recognise it safely — the signed-out store also holds genuine signed-out work).
