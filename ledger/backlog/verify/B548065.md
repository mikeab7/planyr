- **THE SYMPTOM, measured.** After sending a markup behind the plan, right-clicking it anywhere it overlaps a building opens the **BUILDING's** menu, which mentions the markup nowhere. Paint order is hit-test order in SVG, so the element on top answers every press across the whole overlap. The markup is grabbable only on a sliver no element covers — and on one drawn to COVER a building, on nothing at all. **B548064 makes this worse rather than better on its own**, because it makes crossing the band the ordinary thing to do; the two had to ship together.
- **THE FIX — two mechanisms, because the two states need different answers.**
  1. **A SELECTED annotation in the behind band keeps the right-click wherever it paints.** The selection survives the send, so the way back is available in the very next gesture. Narrow on purpose: it fires only for an annotation that is BOTH already selected AND actually painted under this point, so nothing changes for an element that merely overlaps something. Sibling of `gestureAnchorTarget` — same idea (what the user is working on wins the hit test), different trigger.
  2. **The covering element's menu NAMES what is underneath, with one row to reverse it and one to select it.** `Behind this ▸ Bring the markup back in front` · `Select the markup underneath`. This is the answer for the DESELECTED state, which is the one the owner was stuck in, and it needs no uncovered geometry at all — right-click anywhere over the overlap.
- **⛔ THE STACK IS READ AT MENU-OPEN TIME, not at render.** The menu is about to paint over the very point the user aimed at, so asking again during render would hit the menu instead of the plan.
- **Scoping that keeps an ordinary menu ordinary:** only annotations in the BEHIND band are listed. An element under another element has always been reachable through its own uncovered geometry, and listing everything would turn a right-click menu into a scene graph. A control building with nothing underneath renders no extra rows — asserted.
- **Reuse rather than a fifth copy:** `featureTarget.js` gains `featureStack` / `featuresBeneath` / `stackHoldsFeature` (pure, same skip-the-chrome rule the double-click resolver already uses), and the reversal calls the three existing band setters.
- **GUARDS.** `test/markupBehindReach.test.js` (20 — the pure stack reader plus source guards on both mechanisms, incl. that the priority check runs BEFORE the element claims the selection). Live half is the same `ui-audit/verify-markup-over-building.mjs`, whose NEW-2 arms are mutation-proven red on the pre-fix build — including its own precondition that, deselected, an ordinary press at that point really does reach the building rather than the markup, so the arm cannot rot green if the overlap ever stops being real.
