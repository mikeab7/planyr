- **AUDIT-FIRST (profiled in the harness, unminified names):** per response (~1,200 lots, six per z14 view) esri-leaflet ran `_addFeatures → createLayers → ParcelGhost.initialize → prepareParcel` (ring projection + a typed array per ring) for the whole response inside ONE rAF callback — six responses landed in the same frame — then marked the tiles dirty and every touched tile repainted in one callback. - **Fix:** (1) `lib/parcelIngest.js` `IngestQueue` — a response is queued and drained under a 5 ms/frame budget (clock read every 8 lots); a job whose cell left the view while queued is dropped at drain time (prune deletes the cell's cache entry); a hidden tab drains at once. (2) `parcelDisplay.js`: `_addFeatures` enqueues instead of calling `createLayers`; esri's `_postProcessFeatures` (which fires `load`) is HELD until the queue is empty, because MapFinder reads `load` as "outlines for this view are drawn"; layer removal clears the queue and releases held loads so esri's request counter stays honest. (3) `ParcelTiles._flush` repaints a queue of tile keys under a 4 ms/frame budget and waits (≤100 ms) while ingestion is still running, so a tile paints once per batch, not once per slice. (4) `prepareParcel` packs a lot's rings into ONE `Float64Array` (views per ring) — fewer allocations. **B137 holds:** a lot enters `_layers` (the only thing hit-test/hover/export read) in the same step that puts it in the tile index, so it is selectable exactly when drawable; a click on ground whose lots are still queued falls to the live point query, exactly as before outlines arrived. z13 hint, one-source-per-area and 6-queries-per-zoom untouched (no query/cell change).

- **Fix (×3), five parts:** (1) **warm a county's saved copy only when the VIEW needs that county** (`syncDisplaysToView`, once per select session) — Georgia never touches the Texas copies. (2) **In the browser the saved copy lives in a WORKER, never on the main thread** (`lib/parcelSnapshotWorker.js`): it reads the CHUNKED IndexedDB copy, checks Drive's vintage, downloads + parses + stores; the main thread keeps only the vintage (`getSnapshot` → `{generatedAt,count,bbox,inWorker:true}`) and asks for the lots in a view (`snapshotFeaturesInView`, 200-lot batches) or under a click (`snapshotHitAt`). Node/tests keep the in-memory path. **Storage is CHUNKED** (`lib/parcelSnapshotStore.js`: 1,500 lots per value + a meta written LAST as the commit marker; a half-written or mixed copy is discarded and re-fetched — it is rebuildable cache, TIER-BY-REBUILDABILITY; the v1 single-value key is deleted, never read). (3) **The saved-copy layer uses the live layer's machinery** (`makeSnapshotLayer`: ParcelGhost + budgeted IngestQueue + per-tile canvases) instead of an `L.geoJSON` that built a Path per lot in one task — and it now HAS `eachFeature`, which `optimisticHitAt` and the diag hook always assumed it had (the `L.geoJSON` did not, so neither could see its lots). (4) **Lot-number placement is a sliced job** (`parcelLotLabelLayer.paintLotNumbers`: lots prepared under a 6 ms/slice budget with the clock read after every lot, yielding via MessageChannel; the solve + draw run once; old numbers stay up until the new ones draw; positions use the job's own zoom/origin via `map.unproject`) — on real rural lots (Waller at Katy) it was ~100 ms of one task. `parcelLotNumbers` split into `lotNumberItem` + `solveLotNumberItems` (`layoutLotNumbers` unchanged in behaviour). (5) **The parcel-outline /query runs in a worker** (`lib/parcelQueryTransport.js` + `parcelQueryWorker.js` + pure `parcelQueryWire.js`): fetch, `JSON.parse` and ArcGIS→GeoJSON leave the main thread (the 15–35 ms task ×2 said only a worker could split); the query is still built by esri-leaflet's own `_buildQuery`, the service still fires `requeststart`/`requestsuccess`/`requesterror`/`requestend` through its own `_createServiceCallback` (hang-guards and retries unchanged), and esri's own `request` is the fallback. Kill switch `VITE_PARCEL_QUERY_WORKER=0`. Also: `displaySourcesForView` asks "are the county shapes loaded" ONCE instead of a full resolve per sample point (half its cost; ~35 ms at Katy's three-county corner). Ring helpers moved unchanged to `lib/esriRings.js` and the saved-copy geometry to `lib/parcelSnapshotGeom.js` so the workers carry no county registry. Either worker failing reports `parcel-snapshot-worker-failed` / `parcel-query-worker-crashed` and falls back (LOUD-FAILURE).
