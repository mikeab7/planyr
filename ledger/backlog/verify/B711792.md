- **THE ACTUAL HOLE, one line.** `SitePlanner.jsx`'s real `isDirectEdit` — `kind !== "el" || !el || el.attachedTo == null || isDirectTouched(kind, id)` — reads `el.attachedTo` to tell a bonded child (derived) from anything else (direct). A delete op carries **no element** (`elementSync.js` enqueues `{ cls: "delete", el: null, … }`), so `!el` short-circuited **every** delete, including every cascaded child's tombstone, to `direct: true`. `recent.set(...)` is gated on `direct !== false`, so every deleted child stamped its own authorship and answered `authoredRecently: true` for the whole ~15s window — the exact shape of the report: delete one building, and its bonded truck court / paving / parking field each individually claim "you just edited me" the moment any later activity touches them. **Fixed at the mechanism**, not at a new detection site: `elementSync.js`'s delete-enqueue now reconstructs the pre-delete element from the shadow's last-known json before calling `directTag`, so a delete is classified by the IDENTICAL rule an edit already was. Proven with a mutation check (the regression test fails red against the pre-fix source, green after).
- **THE SEPARATE HOLE `foreignAuthor` closes, defense-in-depth.** Independent of the above: `elementSync.js`'s no-pending `remote-upsert` emit (~1493 pre-fix) was the one B673 site that skipped `foreignAuthor(row)` — its sibling at ~1418 already had it (B1116).
