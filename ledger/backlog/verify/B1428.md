- **THE DEFECT.** `SitePlanner.jsx` wired the amber banner's Retry button to `onClick={saveNow}`. `saveNow` re-ran the same write **with nothing freed in between**, so while the store was full it failed every single time — an action offered for a condition it could not affect.
- **THE FIX.** `retryDeviceSave` now (1) frees the provably re-fetchable tier — oldest-first — (2) retries the identical verified write, and (3) reports **what it freed AND whether the save landed**, naming three distinct outcomes rather than one: `saved` ("cleared N of map data to make room"), `still-full` ("cleared N, but this plan still won't fit on this device — your work is safe in your account"), and `nothing-to-free`. The still-full case is the one the old button could not distinguish from "try again", and it is the one the owner most needs told. The decision layer is pure (`shared/storage/storageReclaim.js` — `reclaimThenRetry`), so all four outcomes are unit-tested with no DOM.
- **The explicit `Save now` does the same thing** before settling for the cloud-only story: one click should exhaust the safe options. The reclaim is awaited rather than raced against the cloud push, so the two can't contend over the banner state — it is a handful of `removeItem` calls plus an in-memory index clear, and it only runs when the device write has already failed.
- **⛔ THE HARD CONSTRAINT — no eviction may ever cost data that cannot be rebuilt.** Every reclaimable class must **declare a rehydration source** before anything is removed (`storageCensus.js`); a class that cannot name one for EVERY member is not reclaimable at any pressure, and the reclaim **refuses the whole pass** if any class claims to be reclaimable with no way back. B474 recorded the precedent — "a raster whose src had been dropped (idbKey set) was then unrecoverable" — so **reference images declare `rebuild: null` and are never bulk-cleared**: a raster with a `storageKey` has a cloud copy, one with only an `idbKey` is the user's ONLY copy, and the key alone cannot tell you which. Asserted directly in `test/storageReclaim.test.js` with exactly that record, under maximum pressure.
