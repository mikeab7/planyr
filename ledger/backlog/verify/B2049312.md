### B2049312 — Team invites now actually send an email, on Invite and on Resend `[Settings › Team]` (feature) #site-planner  *(Owner chat block NEW-1 2026-10-04; decision verbatim 2026-10-03: "It should send both emails.")*
`[x]` **Audit (measured, not assumed):** before this, `team_invites` had no triggers and nothing sent mail — "Invite sent" and "Invite resent" were untrue. Resend re-POSTed the same row (ON CONFLICT DO NOTHING).
`[x]` **Send path — Cloudflare Pages Function `functions/api/team/invite-email.js`** (core in `functions/api/lib/inviteEmail.js`, network injected). Chosen over a Supabase Edge Function because the repo already ships server-side secrets + user-JWT verification this way (`/api/folders`, `/api/files`), it auto-deploys with the build with no second deploy surface, and it is unit-testable. **Provider (changed 2026-10-04 on owner direction: no new accounts): the Gmail API as a planyr.io Google Workspace user** — `lib/gmailSend.js` signs a service-account JWT (WebCrypto), exchanges it with domain-wide delegation (`sub` = `INVITE_SENDER`), and POSTs the MIME message to `gmail.users.messages.send`. Resend (first PR) was dropped. Apps Script was weighed as the shorter route and passed over: a web-app URL guarded only by a shared secret is a weaker door than a scoped service account, and the account setup is similar length. Supabase Auth's invite email was rejected: it creates an auth user up front and doesn't carry the team name / inviter / role or the "activates when they sign in" row flow.
`[x]` **Server-side throttle + `last_sent_at`:** `db/team_invite_email.sql` (adds `team_invites.last_sent_at`, SECURITY DEFINER `claim_invite_send` — admin-only, row-locked, refuses inside 60 s — and `release_invite_send`, so a provider failure hands the slot back). Existing pending invites stay NULL: the migration emails nobody (rollout rule 6; only new invites and explicit Resend clicks send).
`[x]` **Client:** Invite → row insert, then exactly one send; toast "Invite sent to <email>" or "Invite saved, but the email didn't send. Try Resend." (row kept). Resend → one send, **no row written**, toast "Invite email sent again"; button disabled for a minute after any send (from `last_sent_at` + this tab). Invite-row layout untouched (behaviour + toast wording only).
