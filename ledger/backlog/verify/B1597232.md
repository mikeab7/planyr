**ROOT CAUSE — one cause, reached by two paths that look unrelated.** `geometryCountyAnswer` flattened two genuinely different outcomes to the same `null`: "no county resolved" and "a real county resolved, and Planyr has NO source for it." `candidateCountiesForPoint` reads that null as licence to fall back, so:
- **Taylor** matched no county bbox at all → the blind per-state fallback ("return every source in Michigan") → Michigan's only county source is Oakland's.
- **Livonia** DID match a bbox: Oakland's padded box reaches down to 42.35°N and Livonia sits at 42.396°N, so `within` was `[mi_oakland]`. The geometry knew the point was in Wayne, but Wayne has no configured key, so `truth` came back null — and with no truth there is nothing to hoist and nothing for B1338896's confident-narrow to narrow to. The wrong county was the only candidate.
Neither path is reachable from the other, which is why a fix at either alone would have closed half of a two-line report. `countyIdentity` has always distinguished the two — it is what already powers the honest "Wayne County — no parcel data wired here yet" message the callers show — and reading it here is the whole fix.

**THE FIX (`counties.js`).** (a) `geometryCountyAnswer` is now DERIVED from `countyIdentity` rather than a second copy of its three steps — one answer function, per `docs/DATA.md`; the duplication is what allowed the divergence. (b) A confident `no-source` identity returns **no real-CAD candidates at all** — only that state's statewide composite, which is genuinely coverage for every county in it. `nearEdge` gates it exactly as it gates B1338896: within ~150 m of the line the polygon is only picking a side, so a wired neighbour may legitimately own the point and the old multi-candidate behaviour is kept. (c) B1338896's confident-narrow is extended to the no-bbox-match branch, which never got it: one Huntsville, TX point (Walker County, resolved confidently) was returning TEN candidates — nine neighbouring counties' CADs plus TxGIO — and now returns `["txgio_statewide"]` alone (Walker is a statewide-derived county, so its key and the composite resolve to the same endpoint; the composite key is the one kept, being the key the circuit breaker never drops and the one `isStatewideBackup` reasons about).

**⛔ THE HALF THAT WOULD HAVE BEEN EASY TO GET WRONG.** "No source of its own" is not "no coverage." A state with a statewide composite covers every county in it — TxGIO paints all 254 Texas counties, `nv_statewide` is the only parcel source Nevada has at all — so a composite is never narrowed away by a county-level answer; only a RIVAL COUNTY's CAD is dropped, because that is the one thing that provably cannot answer for a lot outside its own lines. Dropping composites too would have taken Nevada, Ohio and every other statewide-only state offline to fix Michigan. Las Vegas still returns `["nv_statewide"]` and Columbus `["oh_statewide"]`, both asserted.

**THE DOWNSTREAM HONESTY, which is half the work and is why this is not a one-line change.** Returning nothing changed what an empty candidate list MEANS — it used to mean only "nothing has resolved yet"; it now also means "there is permanently nothing to ask here." MapFinder's two empty-list branches were both written for the first meaning and said so out loud: the click path said *"Parcel services are still loading — give it a second and click again"*, and the address search — **the exact surface the owner reported through** — raised the `unavailable` card, *"the county parcel service couldn't be reached for this area right now… Give it a moment."* Both are false in both halves for a county that was never wired, and left alone the fix would have replaced a wrong query with a wrong sentence, inviting him to retry something that can never come back. Both branches now consult `countyIdentity` first, and `ParcelInfoCard` gained a fourth state, `no-source`, carrying `noParcelSourceNote`'s own sentence so the wording cannot drift from the verdict. Per NEW-4's existing rule it deliberately does NOT offer "start the plan here anyway" — that fallback belongs to an OUTAGE; the way forward here is the aerial trace the copy names.
