### B978286 — A one-finger drag on a corner scale handle plus an incidental second finger could start Leaflet's own pinch-zoom at the same time `[Site Planner / comps]` (bug) #comps #site-planner  *(owner "HARDENING PASS" item 18 — verbatim: "There is already an open bug in this codebase about markers displacing during pinch. Establish which gesture owns the touch." Minted **B978286 / V550030**. DEDUPE-FIRST — net-new; related to but distinct from the existing marker-pinch-displacement item.)*
`[x]` **CONFIRMED REAL, by reading both the handle code and the map's own init options: `MapFinder`'s `L.map(...)` passes neither `dragging` nor `touchZoom`, so both default TRUE, and `overlayPlacementHandles.js`'s gesture handlers never disabled either — unlike the Site Planner's OWN reference-image handles this mirrors, which live on a plain canvas with no competing Leaflet gesture system to fight.** So a one-finger drag on a corner handle (starting this module's own scale gesture) plus a second finger landing anywhere else on the map could start Leaflet's TouchZoom pinch-zoom AT THE SAME TIME — both driving the overlay's apparent size from two uncoordinated inputs, the same species of bug as the open marker-pinch-displacement item elsewhere in this codebase. Fixed the standard Leaflet way: `map.dragging`/`map.touchZoom` are explicitly disabled for the duration of a handle gesture and restored on release (with a safety net if the controller is torn down mid-gesture).
