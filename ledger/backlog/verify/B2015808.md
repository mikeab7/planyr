### B2015808 — Schedule "Focus" toggles reset every time you come back to the page `[scheduler]` (bug) #scheduler #persistence  *(Owner report 2026-10-02 (NEW-1): "the focus button on the schedule module doesn't hold ... It should just hold whatever the last status was.")*

`[x]` **Cause (AUDIT-FIRST, matches the brief):** the 2026-09-17 fix (`TASK_VIEW_FIELDS` / `stripViewState`) removed `focused` from every cloud write to stop false-conflict `__rev` bumps, and its design note said view-only state should move "per-tab/local" — the strip shipped, the local store never did. `focused` therefore lived only in memory.
`[x]` **Fix:** `focused` stays OUT of the versioned document (unchanged strip). It is now kept per browser in localStorage `planar:taskFocus:v1` = `{ [scheduleId]: [focusedTaskId…] }` (`public/sequence/index.html`: `loadTaskFocus` / `saveTaskFocus` / `applyTaskFocus` / `persistTaskFocus`). `persistViewState` (already run on every data change) writes every explicit `focused` true/false — so the pill AND every flow that clears it (re-parent, indent, paste, dashboard "Open row" ancestor-expand) are remembered with no per-call-site edits; it skips all work when the projects tree is unchanged. `resolveViewState` re-applies it on load / import / restore before first render (no expanded flash) and the sibling-tab merge handler re-applies it after `mergeCloudDoc`. `focused === undefined` means "unknown" (came off the cloud) and is filled from storage; an explicit local true/false always wins, so a remote doc can never wipe local Focus. Missing task ids / projects are ignored and pruned; all storage access is try/catch.
