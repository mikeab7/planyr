I don't know. It doesn't even necessarily need to be a text box, but maybe it's just like an outline." Offered the design fork — free placement vs structure-generated-from-an-outline vs both — and CHOSE **"type first, then rearrange."** DEDUPE-FIRST — searched Open / ⏳ Verify / Done across `sketch`, `chart`, `diagram`, `flowchart`, `mindmap`, `outline`, `notes`: **B973** is the pond cross-section diagram (a generated engineering schematic in the Site Planner, no shared surface); **B1290 / B1310–B1318 / B1291 / B1365–B1374 / B1391–B1393** are the Notes module and its four prior rounds, none of which touches a canvas. Net-new.)*

**Recurrence (×2) — 2026-08-04, owner used what shipped and REJECTED it.** Verbatim: *"The sketch feature kinda sucks. Like, if I could just double click anywhere, even if I'm already writing text, that'd be better. And then, like, maybe there's a button where I can just put a box around it. Like, that would be just as good."* DEDUPE-FIRST: this re-opens **B1400** rather than taking a new number — same feature, same surface, the first shipping of it was wrong. **What went wrong is worth recording, because the code was fine and the DESIGN was not:** his original request was already the spec — *"I can click something, type three words, and then put a box around it, and then draw an arrow to another box"* — which is DIRECT MANIPULATION. He was then offered a design fork whose framing pushed him to *"type first, then rearrange"*, and what he got was a two-pane block in which he had to learn an **indent-and-caret syntax in a textarea** before a single box appeared. **The syntax was the defect.** Nobody sketches by writing a structured list first.

**⛔ THE RULE IS REPLACED, and the old one is marked superseded rather than deleted.**
- **DEAD:** *"the OUTLINE owns content, the CANVAS owns only position"* (project doc `claude/decision-2026-08-03-notes-sketch-mode-outline-owns-content-canvas-owns-position.md`). It is dead because the outline is no longer an authoring surface at all.
- **LIVE: THE CANVAS OWNS EVERYTHING.** Each box owns its own **text** AND its own **position**; the arrows are an explicit list of `{from,to}` box references. **There is no second representation, so there is nothing to keep in sync and nothing to arbitrate.** Written down in all four file headers, in the folder pointer (`src/workspaces/notes/CLAUDE.md`) and here — each of them naming the superseded rule.

**WHAT IT DOES NOW — his two sentences, and they were the whole spec.**
1. **DOUBLE-CLICK ANY EMPTY SPOT** on the canvas → a box appears **right there** with the caret already in it; you type immediately. No pane, no syntax, no button first. *"even if I'm already writing text"* is honoured literally: the press takes focus from wherever the caret was (the node view stops every event reaching the document), and the sentence you were mid-way through is untouched — **asserted headless, both halves**.
2. **THE BOX BUTTON** (toolbar, replacing the old "insert a sketch" button — a REPLACEMENT, not an addition, per PANEL-BREVITY). With words selected, or the caret in a paragraph, one click turns them into a box. **DECISION, stated because it was a real fork: boxing CONVERTS the text into a real sketch box; it does NOT draw a border in place.** A border in place would be a dead end — you could not drag it and you could not draw an arrow from it, and *"then draw an arrow to another box"* was his very next clause. A box you cannot connect is a decoration; he asked for a chart. (Boxing your only paragraph leaves a fresh line to keep writing on — an atom last in the document would otherwise swallow the next keystroke.)
3. **DRAG FROM ONE BOX ONTO ANOTHER** → an arrow. Direct, off a dot on the box's own edge, with **no mode to turn on first**. An explicit **↗ Arrow** button is the keyboard route (select a box, press it, click the target), so nothing here is mouse-only — every box is a real focus stop with an accessible name.
4. **BOXES STAY DRAGGABLE.** A drag previews locally and commits once, so it is one undo step; it leaves every word **byte-identical** (asserted headless).
5. **A BOX IS A SHORT LABEL PLUS AN OPTIONAL LONGER BODY** — *"some more detailed information"* — authored **in the box** (two plain fields laid over it; no dialog, house rule), never via a `>` prefix in a textarea.
6. **DELETE** removes the selected box **and every arrow that named it, at either end** (**TOMBSTONE-DELETES**) and says how many it took. `removeBox` is the ONE place a box is destroyed and it returns the arrows it removed, so no caller can skip the cascade; `normalizeSketch` drops a dangler on read as a second line of defence.

**⛔ THE OUTLINE TEXTAREA IS REMOVED, not kept "just in case."** Two authoring paths is exactly the accumulation **PANEL-BREVITY** forbids, and the outline half is the one he disliked. A read-only outline VIEW was considered and dropped: it costs a disclosure and a line of chrome for something nobody asked for. An ordering is still **derived** from the arrows (`outlineFromSketch`) for the Markdown export and the accessible name — derived, on demand, owned by nobody, with no way back into the model. Net chrome change: three buttons before (Outline · ＋ Arrow · Tidy up) and three now (＋ Box · ↗ Arrow · Delete), minus the textarea and its permanent hint line — the one hint that remains **hides itself after the first box**.

**⛔ NOBODY'S EXISTING SKETCH BREAKS.** A sketch saved under the old shape (`outline` + `positions`, no `boxes`) is **migrated on READ**: its lines become boxes carrying their own text at exactly the coordinates the old automatic layout put them at, the indentation's implied parent→child arrows become **real explicit arrows**, and a box he had dragged stays where he dragged it. Opening one does **not** rewrite it (asserted headless — the stored document still has its `outline` after being opened); the new shape is written the first time it is genuinely edited. The two superseded attributes stay declared, defaulting to `null`, and the schema guard asserts exactly that.

**WHAT WAS KEPT, deliberately and unchanged — the spine that was already verified live.** `noteSketch` is still a **NODE IN THE PROSEMIRROR SCHEMA** (`lib/notesExtensions.js`), so it still persists through the one storage seam (**no sketch key anywhere in `localStorage` — re-asserted headless**), still round-trips through cloud sync (B1291) with **no schema change, no new table, no migration — nothing database-related lands on the owner**, and still prints. The **single render builder** still feeds both the screen and the print sheet, and the interactive half is still a **cached dynamic import**.

**PDF-PARITY GOT STRICTLY BETTER.** The old design had a real screen/paper divergence to manage (a chevron on screen, a detail list on paper). Now the canvas owns the text, so a box simply draws its own body — **the same content on both surfaces, with no flag to keep in step**. The only remaining difference carries no content at all: the grip you drag an arrow out of is not drawn on paper, because nothing on a sheet can be dragged. Print sheet asserted headless: same boxes, same arrows, every label and body present, **zero grips**, box drawn on `rgb(255,255,255)`.

**MARKDOWN STAYS HONEST.** Boxes export as a **readable nested list** (nesting derived from the arrows), bodies attached to their own box as `>` continuation lines. An arrow the nesting cannot express — a second arrow into the same box, a link back — is **written out** under `Also connected:`. Where the boxes SIT is the one thing a list cannot say, and it joins `docToMarkdown`'s named lossy list ("where a sketch's boxes sit on the canvas") — reported only when there is more than one box, since a single box has no arrangement to lose. A sketch's words still feed `docToText`, so a note whose whole content is a sketch is still findable — for the new shape **and** the superseded one.

**BUNDLE.** The interactive chunk `notesSketchEditor-*.js` grows **6.2 KB → 9.4 KB** (direct manipulation is more code than a textarea); it is still fetched only when a sketch is genuinely on screen — asserted live, twenty-two harness sections run with nothing sketch-shaped requested. The static Notes path is unchanged (the exporter still imports nothing).
