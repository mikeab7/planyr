- **The split button.** `MapFinder.jsx`'s comp-mode resting toolbar now renders ONE two-segment button, `COMP_ACCENT`-filled to match "Select parcels"'s existing primary-split-button treatment: a primary segment (label "Place comp", or "Place comp on the map"/"on a parcel"/"on a site plan" once an anchor kind has been used this session) and a caret opening a 3-item menu — **On the map** / **On a parcel** / **On a site plan** — each a prepositional phrase completing "Place comp / …" (never rewritten as verbs, per the brief). The primary click arms the LAST-USED anchor kind, defaulting to **On the map** on a fresh session (`lastCompAnchorKind`, `sessionStorage` — "sticky for the session", not permanent); choosing any anchor (primary click or a menu pick) updates the sticky choice and the button's own label immediately, so reopening the caret shows which anchor is armed without opening the menu (owner acceptance step 3). The two former resting buttons ("Drop a pin"/"Comp from parcel") and their shared logic are gone from the RESTING state; the mid-flow "switch to the other anchor while already armed" buttons (unrelated duplication — they only appear once placement is already in progress) are UNCHANGED, on purpose, to keep the diff minimal and the well-tested `CompsPanel.jsx` banner copy that names them ("...click Comp from parcel on the map toolbar...") accurate.
- **"On a site plan" always renders, never omitted.** Reachability = `sitePlanOverlays.length > 0` (has ANY site-plan overlay been uploaded on this site — deliberately not the zoom-gated `visibleSitePlanOverlays`, a different question). Unreachable → the item renders visually dimmed with `aria-disabled="true"` (not the native `disabled` attribute, which some browsers suppress the hover tooltip on) and a `title` explaining why + how to get it ("Upload a site plan first..."). Reachable → picks the currently-ACTIVE overlay if one is armed, else the first uploaded one, and arms the SAME `startPinOnOverlay` flow the Site plans panel's own per-overlay "pin a comp here" button already used — no second implementation. That flow (`clickableOverlayId` → `placeCompOnOverlay`, kind `"site_plan"`) already existed (B986096-HARDENING-7); this item is its first TOOLBAR entry point.

So it is not "only there to arm placement" and the brief's removal branch does not apply — it stays.
