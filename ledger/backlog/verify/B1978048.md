### B1978048 — City names + state lines behave badly during zoom: labels snap ahead of the imagery, line hairlines fatten then re-thin `[site-planner / map]` (bug) #site-planner #gis #perf *(Owner report 2026-09-29, NEW-1, amends B1973921 / B1973920: "the cities follow weirdly when you zoom, make it more like google maps.")*

`[x]` **Root cause (read in Leaflet 1.9.4 `Map._animateZoom`, then measured):** on a zoom Leaflet fires `zoomanim` and moves its state to the FINAL view in the same tick, while the imagery slides there by CSS transition over 0.25 s. The city-name canvas redrew from map state, so every name snapped to its end position on frame one and sat there while the ground slid under it (mutant-measured 100–450 px off the ground point mid-zoom), then re-collided from scratch. The state-line canvas took the opposite failure: Leaflet's stock canvas renderer CSS-scales its bitmap (**measured: matrix scale 1 → 2 over the zoom, then snap back to 1**), so both hairlines and casing visibly fattened and re-thinned on every zoom. The owner's "drift, stretch, jump" was both, in different layers.
`[x]` **Fix — one shared mechanism (`lib/zoomTracker.js`):** both layers draw their own canvas (never CSS-transformed) and re-project every vertex/place each frame as `lerp(start-view position, end-view position, progress)` — exact, because CSS interpolates a translate+scale linearly in eased time. Progress is NOT a clock: a hidden `leaflet-zoom-animated` sentinel is moved in the `zoomanim` handler so the browser runs Leaflet's own transition on it, and its computed transform is read each frame (a clock started in the handler measured a frame late — `zoomanim` can fire inside Leaflet's rAF; that skew showed up as a 25-unit intermittent miss before the sentinel). Chosen over per-label DOM elements: 1 canvas, no node churn, identical pan path, cheaper on a laptop; chosen over counter-transforming the pane: the lerp is exact for wheel/dblclick/buttons/fractional zoom alike, a counter-transform needs Leaflet's private pane maths.
`[x]` **Google-Maps behaviours:** text keeps its on-screen size (canvas never scaled — asserted every frame); names **fade** in/out (160 ms, `stepFade`) instead of popping, and the whole layer fades across the 13→14 hand-off; **stable priority** — `layoutLabels` now sorts by tier, then already-showing, then name/coordinates, so a collision never depends on array order; **hysteresis** — a label already showing is boxed with a smaller pad so it survives the edge of a collision a newcomer would lose (importance still wins: a held small town yields to a bigger city). The datasets carry no population, so tier (Natural Earth `minZoom`) is the importance signal and name is the tie-break — a population column would be the next refinement. Pan is unchanged (redraw per `move` frame).
`[x]` **State lines (asked to check):** same stretch, so rewritten the same way — own canvas, unit-mercator vertices projected once, ring bounding-box cull, `data-levels`/`data-detail` stamps kept, `L.canvas` renderer dropped. Levels/style follow the END zoom during an animation.
`[x]` **Adjacent surfaces:** Locations card / food map don't share this code path (own Leaflet maps) — untouched. Lazy/boot discipline unchanged (both layers + tracker are dynamic-import only; Layers-panel row untouched).
- **Guards + red-proofs:** `test/placeNames.test.js` +11 (priority order-independence over every permutation, hysteresis ×4, easing, fade). **Red-proof:** the order-independence test FAILS on current-main `layoutLabels` (it was input-order dependent — it relied on the caller's pre-sort); the 8 new tests all failed before the change. Browser: `ui-audit/verify-place-names.mjs` (31/31, 3 consecutive runs) samples each frame of 5 zoom gestures (buttons in/out, wheel in/out, double-click) with real Leaflet markers as an independent oracle, asserting every label sits on its ground point (≤ 2 units), type size constant, canvas unscaled, and that names fade rather than pop. **Mutation proof:** with the `zoomanim` handler disabled the same harness goes red on all 5 gestures (100–450 units off). `ui-audit/verify-admin-boundaries.mjs` (31/31) adds the same oracle for the lines (worst deviation 0.78, canvas never scaled, never blank mid-zoom).
