- **Repro (owner).** "Sometimes it shows an elevation, like the existing elevation, but sometimes it doesn't."
- **Root cause (AUDIT-FIRST).** `useGroundElevation` (B706) had two paths: LOCAL bilinear sampling of a cached terrain grid (instant, rock solid) and ONE debounced `getSamples` call after ~300 ms of cursor REST. With the layer off or the map below the z16 gate, path 2 was the only one running — and B706's shipped rule rendered no-data, void, in-flight and failure ALL AS ABSENCE. So a cursor that never rested (the common case while dragging around) produced nothing at all, which reads as a glitch and is indistinguishable from a real "nothing here". The no-fabrication rule was right; the vanishing was not.
- **(a) Always render the field, with an explicit state.** `useGroundElevation` now returns a STATE, and `lib/groundReadout.js` (pure, new) is the ONE composition both surfaces paint: `Exist 152.6 ft` · `Exist …` · `Exist — (no data here)` · `Exist — (unavailable)`. Reason detail rides the chip's existing `title`. No new chrome, no fabricated numbers, and no state can render as the empty string.
- **(b) The fast path is now the NORMAL case.** `warmCursorGrid` pulls the ONE lattice tile under the cursor REGARDLESS of layer toggles and REGARDLESS of the z16 gate — that gate is a cartography judgement about 1-ft LINES on a coarse cell, never a reason to refuse to sample a POINT; a coarse sample is instead MARKED (`≈`) and explained. It asks for the same `latticeTile` the contour layer asks for at that zoom, so with contours on it is a plain cache hit. It deliberately calls `computeTile` directly rather than through `gisCache.swr`: **swr serves the cached contour artifact without ever running the fetch, so a view painted from cache left the grid registry EMPTY — which is why the fast path went missing after a reload even with contours on.** A failed tile is not retried for 30 s, so a dead endpoint can't be hammered per cursor move.
- **(c) PROPOSED, from the ledger's own surface.** `proposedSurface.surfaceGrid` now publishes `owners` — the very ownership array it priced its lattice from — and the new pure `sampleProposedAt` walks it through the SAME precedence (pad → dock stack → the rest), the same pond exclusion and the same B833 transition taper. So the readout and the B826 earthwork rows read ONE surface by construction, not by care. It NEVER extrapolates a plane past its own element: outside every footprint and its daylight wedge the answer is `Prop —` with an honest reason (no FFE set / no graded element here / pond interior = borrow / no ground data).
- **(d) The delta is the point.** Signed and labelled `Fill 2.4` / `Cut 1.8` on the B809/B826 cut/fill ramp (clamped to the readable end of each ramp for the dark chip — same warm-fill / cool-cut families as the exhibit), `On grade` inside the zero band, and SUPPRESSED whenever either side is unknown.
- **(f) One line, at its existing size.** `components/CursorChip.jsx` is the ONE chip both surfaces render. The old chip truncated from the right, which ate the ELEVATION first; the elevation group is now flex-fixed and the COORDINATE pair is what gives way.
- **Bug found by driving it, fixed here (LOUD-FAILURE).** A caller-supplied `AbortSignal` used to REPLACE `samplePoint`'s own controller, silently disabling its timeout with it — so a socket that accepted and never answered NEVER SETTLED, and the readout sat in-flight forever with no way to ever report the failure. `samplePoint` now always owns the controller, chains the caller's signal onto it, and distinguishes the two aborts: a timeout throws as a real failure, a caller abort stays an `AbortError` the hook ignores.
