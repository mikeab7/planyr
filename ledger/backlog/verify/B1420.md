- **THE MODEL, in one sentence: two concepts, a PROJECT and PAGES THAT CAN HOLD SUBPAGES.** There is no notebook layer to pick and no separate species called a "section" — "Entitlements" stops being a different KIND of thing and becomes simply a page that has pages under it. **Anything can have children, at any depth.** That is precisely what OneNote structurally cannot do (its sections and pages are different types and a page cannot nest under a page), so the distinction is not allowed back by the back door: no `kind` field, no depth ceiling, no "container" flag. `addNotebook` / `addSection` / `moveSection` / `moveNotebook` / `setNotebookProject` / `visibleNotebooks` / `notebooksInScope` / `notebookToMarkdown` are all **deleted**.
- **`projectId` LIVES ON THE ROOT PAGE AND NOWHERE ELSE.** A subpage's project is its root's, DERIVED (`projectOfPage`), never stored. Storing it per node would make one fact writable in N places — the redundancy that cost the Site Planner eight PRs to remove (B1340). `movePage` strips it on nest and restores it on lift, so the invariant is maintained by the one op rather than by discipline.
- **⛔ MIGRATION WAS THE RISK, AND IT IS PROVEN ON HIS OWN DATA.** Every SECTION becomes a top-level page **keeping its own id** (which is what lets a binned page whose `parentId` names its old section restore to exactly the right place); its pages become that page's subpages; **two notebooks bound to the same project MERGE by construction**, because `projectId` is the only grouping key there is — so no id can collide and nothing needs reconciling. A generic "Section 1" does not survive as a page name: a single-section notebook lends its own title instead, and where both titles are noise and there is one page, that page becomes the top level (`Untitled notebook › Section 1 › Load Study` → **`Load Study`**). A loose notebook lands in the named **"Not in a project"** home, same shape. The **bin comes with it**: a binned notebook or section converts to one page carrying its former contents, so a restore returns the branch whole, and every `pageIds` cascade set is copied verbatim.
- **It is IDEMPOTENT and it is PERSISTED.** The conversion only runs on a tree that has `notebooks` and no `pages`, so `migrate(migrate(x)) === migrate(x)` for every input — asserted by deep equality on the owner's data, three times over, and through a JSON round trip (which IS the sync path). It is also **written back on the first load that sees the old shape**, so the new shape rides the cloud tree blob to the other machine instead of being re-derived forever. **No schema change and no SQL — nothing lands on the owner.**
- **WHAT THE RAIL LOOKS LIKE NOW.** Inside a project: only that project's pages, nested, and **no project badge on any row** — everything on screen belongs to where you are standing, so a badge has nothing to say. From the Dashboard: **grouped by project name**, with a "Not in a project" group last, and that heading is the ONE place a project label belongs. A project id that no longer resolves still gets its own flagged group rather than being folded away.
- **⛔ B1374'S GUARANTEE IS UNCHANGED, by a different route.** Its in-rail scope switch is gone as duplicate chrome, because the DASHBOARD is now the all-projects view and its crumb sits at the top of every screen. - **Markdown export is nesting as HEADING DEPTH, and lossless for content.** `pageToMarkdown` writes a top-level page as `#`, its subpages `##`, and so on. Markdown runs out at six levels and a note tree does not — past that the heading clamps and the page's place is carried by a **trail line**, which the exporter REPORTS as the one thing it could not spell. Not a page, title or byte of body is ever dropped.
- **PDF-PARITY.** There is no section heading to print any more, so paper carries each page's **trail** — the same "where does this sit?" the rail shows by indentation, which is what keeps a printed branch readable once the sheets are separated. Screen and paper were changed in the same commit.
- **A page may NEVER be moved into its own subtree.** That single move would detach a whole branch from the tree — every page under it still in the object graph and reachable from nowhere, which is the "renders in zero scopes" bug in its purest form. The model REFUSES it (returns the tree unchanged), the drop target does not light up for it, and both halves are asserted.
