### B2034128 — Version history: see, open and restore earlier saved versions of a document `[library / doc-review]` (feature, amends B2022929) #library #doc-review #files #mobile  *(Owner request 2026-10-03 (NEW-1), after B2022928 kept earlier versions with no screen to see them.)*

`[x]` **What shipped:** a **Version history** action — in the Word/text editor toolbar, a **Versions** button in Review's header (any open file, PDFs included), and a **Versions** button on each Library file row (opens the file in Review with the history sheet already showing). The sheet lists saved versions newest first: version number, date and time, who saved it, file size, and a "restored from an earlier version" tag. **Open (read-only)** shows that version labelled "Earlier version — <date>", editing/formatting/Save/accept/reply tools hidden and the page not editable; **Restore** saves that content as a NEW latest version (the old latest is kept, nothing is rewritten or deleted) then reopens it editable; **Save a copy** files a separate Library file "<name> (copy of <date>).<ext>"; **Back to latest** leaves the read-only view. Unsaved edits are never silently discarded: the first tap on Open/Restore/Copy with unsaved edits asks "Discard my edits and continue". Opening a version never downloads. Phone: the sheet is a bottom sheet (side panel on desktop), never wider than the screen.
- **Survey (reuse before building):** NO new table, NO migration, NO new storage. The versions already exist as `sources[1..]` in the `doc_reviews` record's `data` jsonb (every Word/text Save stores a new Drive key and demotes the old source — B2022928). What was missing was a **save stamp**: entries carried no date or author. New module `doc-review/lib/docVersions.js` (`packSource` keeps `savedAt`/`savedBy`/`restoredFrom` through every snapshot; `saveVersion`/`restoreVersion` are the ONE save/restore path, with I/O injected). Versions saved BEFORE this change show "Date not recorded" / "Saved by — not recorded" — never an invented value.
- **PDFs — how handled:** the Library keeps exactly ONE stored file per PDF; a re-issued drawing is a SEPARATE file marked "superseded" (`fileFacts` state facet), not a revision inside one record. So for a PDF the sheet lists the one current version (date/author/size from its upload) with a plain note saying that, and offers no Open/Restore (there is nothing earlier to open). Not forced into the document model.
- **Signed out:** the replaced version stays listed and restorable for the session (bytes are in the session cache); it is not persisted to the record until a stored save (unstored prior entries are filtered out of the snapshot, as before). Save a copy needs sign-in and says so.
- **Adjacent cases (PR table):** file with ONE version → one row, "Only one version so far" note, no Open/Restore · `.txt` → same list, extension kept in the copy name · file with no project → copy filed under the same scope as the original (`project-unfiled`) · PDF → one row + note, known-good arm of the browser run · restore then undo-by-restoring-the-previous-latest → five versions, content back to the old latest, none lost · failed upload / unreadable earlier version → history unchanged, plain error · restoring the already-latest version refused.
- **Guards:** `test/docVersions.test.js` (16; red on main — the module does not exist there): saved three times → three versions in order · middle one reads back its own content · Restore → a FOURTH version with that content AND all three originals' entries and bytes unchanged · undo-by-restore · failure paths · signed-out · legacy entries · wiring guards (DocReview uses the shared ops; the sheet has no download call). `ui-audit/verify-version-history.mjs` (real Chromium, logged out, 14 checks incl. phone width and a known-good PDF arm).
