- **Live rows, re-queried while fixing (verbatim).** Trailers `e1454740ykduhm` / `e1454742ykduhm` are `attachedTo` building `e1454729ykduhm`, but their `forCourt` **and** `prevZone` both name `e1454700dshobp` / `e1454702dshobp` — courts belonging to a DIFFERENT building, `e1454629danlgq` (w 495 · rot 269). The `dshobp` trailers `e1454701dshobp` / `e1454703dshobp` reference those same courts correctly, so the later `ykduhm` batch (the duplicate) kept the original's ids.
- **Why it detaches — the mechanism, not just the symptom.** `relayoutSide` builds each side's chain by walking OUTWARD from the court: `prevZone` first, falling back to `forCourt`. Neither bond on the `ykduhm` trailers names a `ykduhm` court, so each chain is just `[court]` and **the trailer is never laid out at all**. It is `attachedTo` the building, so `wallKids` excludes it too (it carries `forCourt` + `noFit`) — nothing positions it on a host resize either. That is exactly the owner's "trailer parking just hovering by itself".
- **Root cause.** BOTH copy paths — `planClipboard.pasteClipboard` and `SitePlanner.duplicateGroup` — minted fresh ids and remapped exactly ONE back-reference, `attachedTo`. Every other id-bearing tag was copied verbatim. Audited the whole `ORPHAN_TAGS` family: `truckCourt` is `{side}`, `dogEar` is `{side,sign,along,proj}`, `oppSide`/`sideParkSide`/`sidewalkSide` are side names — no ids. The id-bearing set is `attachedTo` · `forCourt` · `forTrailer` · `prevZone`, and **`prevZone` was missing from `ORPHAN_TAGS` entirely** (a B495 gap), so a lone duplicate kept a chain link too.
- **Fix.** New pure `lib/bondRemap.js` is the ONE inventory + rule, used by both copy paths so they cannot drift again: a reference INSIDE the copied set is remapped, one OUTSIDE it is DROPPED — never left dangling to a foreign element. A non-string value is an inert legacy flag (`forTrailer: true`), not a bond, and is left alone. `prevZone` added to `ORPHAN_TAGS` and to the host-role set. Load-time repair `siteModel.normalizeCrossHostBonds` (first pass in the shared `normalizeBondedChildren`, so both read paths run it) re-points a zone whose bond names an element that is not a child of its own host at the corresponding **same-side** member of its own host's chain, dropping the reference when no such member exists, and logs every repair via `onHeal` (LOUD-FAILURE) so it rides the `exempt` commit set.
- **Tests.** `test/bondRemap.test.js` (13): duplicating a building with a full dock stack (court + trailer + buffer, both sides) — every back-reference lands inside the copy and none still names an original id · an out-of-selection reference is DROPPED rather than dangling · the `duplicateGroup` clone rule asserted the same way · the repair seeded with **exactly this plan's cross-linked shape** (two buildings, the copy's trailers pointing at the original's courts) re-bonds by side · a correct plan is returned BY IDENTITY · **end-to-end: the repaired chain then sheds B1123's spurious `alongLen` and tracks the court again** — the one assertion that proves the two heals compose in the right order.
