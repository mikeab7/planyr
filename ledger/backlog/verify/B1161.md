- **Finding.** `SitePlannerApp` hides map mode with `display: none` and deliberately does **not** unmount it (its comment says so). So for the whole session: the imagery layer and the labels layer had no cache ceiling at all; `overlayRefs` held a **duplicate** set of every enabled GIS raster overlay, separate from the planner's, each keeping a painted full-viewport `<img>` alive; and a `setInterval(sync, 45000)` kept re-syncing — and re-fetching — those overlays. Only `invalidateSize` and clearing the selection were gated on `visible`.
- **The fix, all eviction:** `boundTileCache` + `tileCacheLimit` on both layers, exactly as the planner does · on `visible === false` the tile caches are squeezed to a token ceiling and every esri raster overlay is torn down through the same `releaseLayer` the planner uses at toggle-off (`syncOverlayLayers` rebuilds whatever is still enabled on the way back in) · the interval is gated on `visible`, and the effect re-runs on it, so returning to the map syncs immediately and then resumes the heartbeat.
- **Nothing here changes what is DRAWN.** `detectRetina` is untouched — the owner has ruled out any retina downgrade — no cap on how much can be drawn, no spinner, no decimation. `capTileCache` never evicts a CURRENT tile, so it cannot punch a hole in the view; everything shed re-fetches on demand.
- **The cap is sized from the keepBuffer these layers ACTUALLY use** (Leaflet's default of 2 — neither layer passes one), rather than borrowing the planner's tuned value. Adding a keepBuffer here would have made them retain MORE, which is the wrong direction for a memory item.
