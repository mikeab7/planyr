- **Report.** Resizing a building leaves its trailer parking behind — wrong length and detached. On Goose Creek "Plan 1 (copy)" (site `sms69x8rb2qk`) the two trailers on building `e1454729ykduhm` are the ONLY elements in the whole plan carrying an `alongLen`, and the owner never typed a trailer length.
- **Live rows, re-queried against `site_elements` while fixing (verbatim).** building `e1454729ykduhm` w 822 · h 500 · rot 178.543241069641 → courts `e1454739ykduhm` (top) and `e1454741ykduhm` (bottom) both w 712 · h 135 · zd 135 → trailers `e1454740ykduhm` (w 708, `alongLen` 708) and `e1454742ykduhm` (w 707, `alongLen` 707), both rot 178.543241069641.
- **AUDIT-FIRST — the brief's stated root cause does not survive reading the code, and the correction matters.** The brief attributes a phantom length term to the HOST rotation (sin 178.543° ≈ 0.0254 → ~1.3 ft on a 50 ft trailer). `boxExtentAlong(zone, alongUnit(host, side))` is **already host-relative**: it dots the zone's own rotated half-axes with the host's along direction, so it returns w·|cos δ| + h·|sin δ| where δ is the zone's angle MINUS the host's — exact whenever the zone sits at its host's angle, which on this plan **both trailers do** (all three rows read 178.543241069641). Un-rotating by the host would have been the identical number. Two real defects sit underneath the report instead:
  - **(1) the measure is a bounding-box PROJECTION**, so as soon as δ drifts off a right angle the DEPTH leaks into the along measurement as h·|sin δ|. That drift is real in this owner's data, not hypothetical — `e1454737ykduhm` sits at 268.543241069641 under a host at 178.543241069641, and `e1454692dshobp` at 359 under a host at 269.
  - **(2) there was no notion of gesture INTENT at all** — and this is the one that bites. Whether the owner had set a length was inferred from geometry alone, so anything reaching that branch of `refitChildren` could pin `alongLen`, and a pin is by design never reset. **On this plan the pins are collateral from B1124:** the cross-linked `forCourt` had already detached both trailers, the owner dragged them to try to make them fit, that drag legitimately stamped a length — and the stamp then guaranteed they could never track again even once the bond is repaired.
- **Fix, three parts.** (a) `dockZones.zoneAlongExtent` / `zoneDepthExtent` read the along/across **dimension** in the host's frame whenever the zone is within a snap of it (every zone `layoutZoneByKind` produces is), falling back to the projection for a genuinely off-axis box — so a depth change moves the along span by exactly zero. (b) `resizedZoneAlongLen` gates the stamp on INTENT: `refitChildren` now takes the gesture (`userResize` + an edge drag's `dragAxis`), so a host refit, a relayout, a rotation, a court depth change and the load-time heal are all structurally incapable of stamping; a depth-only edge drag is refused outright. (c) `siteModel.normalizeZoneAlongLen` — a load-time heal in the ONE shared `normalizeBondedChildren` (so BOTH read paths run it, the B1097 trap) that DROPS an `alongLen` indistinguishable from the chain span the zone would derive anyway and re-lays the chain in the same pass, so plans already poisoned go back to tracking without the owner clearing anything by hand. Healed elements ride the existing `exempt` set, so the repair diffs and COMMITS (B1118).
- **Order is load-bearing:** the B1124 bond repair runs FIRST, or the length pass has no walkable chain to judge the pin against. Encoded in `normalizeBondedChildren` and asserted end-to-end.
- **Tests.** `test/zoneAlongLen.test.js` (16): a pure host resize NEVER stamps at rot 0 / 90 / 178.543 / 269 / 359 · a real along-axis drag DOES · a depth-only drag does not · the load-time heal clears a stamped-but-equal value while PRESERVING a genuinely user-set one · the court head's own `alongLen` is never touched · idempotent (untouched records returned by identity).
- **BUNDLE BUDGET — the fix shipped WITH a matching optimization, not a raised ceiling.** `bundle.siteRouteJsBytes` went red in CI: the three fixes cost 3,937 bytes of site-route JS and `origin/main` was already within 3,870 bytes of its 2,320,000-byte ceiling (measured 2,316,130 — the ceiling has been eaten by ordinary churn since B1042 set it against a 2,242,725 baseline).
