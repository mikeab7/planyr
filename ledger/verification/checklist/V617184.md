**Why this needs its own real pass.** The owner's own report (verbatim: *"you see how big the location text is? all the input text should be the same size"*) was measured with `getComputedStyle` against a **deployed** build (`8f09df1`) — this is by definition a claim about what serves from `planyr.io`, not about the source tree. The fix itself needs no sign-in, no real data, and no GIS — it's a pure CSS/style-object correction on a synthetic pasted row — so ordinarily this would be a same-session sandbox check. It isn't, only because of a separate, already-standing wall: this sandbox's headless Chromium cannot open **any** external URL at all, deployed app included (see **V477**, which first recorded this precisely — *"the agent proxy refuses Chromium's CONNECT even for a host whose `curl` request succeeds with HTTP 200"* — and V464240/V711/V445488/V447040/the many other entries citing the same wall). Re-confirmed directly this round rather than assumed from those older notes: `curl` reached both a Cloudflare branch-preview URL and `https://planyr.io/` cleanly (HTTP 200); a real headless Chromium session — launched with the documented required flags (`--ignore-certificate-errors`, `ignoreHTTPSErrors: true`) per this file's own "🤖 Self-verification" section — died with `net::ERR_CONNECTION_RESET` on both, twice each. The agent proxy's own status log shows why: `ws_closed_mid_exchange` on `planyr.io:443` and the branch-preview host, tunnel closed ~6s in, only ~39 bytes ever received back — a mid-transfer kill, not a policy 403, and not something a flag fixes.

**What was verified here, extensively, without a browser session on the deployed page.** The Location `<button>`'s bug and fix were root-caused precisely (a trailing `font: "inherit"` style shorthand clobbering the font-size/line-height an earlier `...textStyle` spread had already set correctly, discussed in full on `BACKLOG.md`'s B986096 Recurrence ×17 entry) and driven live, headless, signed out, against a fixture-seeded local plan built from the **identical shipped source** (same `CompEntryGrid.jsx` now on `main`) — twice: once via `npm run dev` right after the fix, and again via a full production build (`npm run build` + `vite preview`) as part of `npm run ci-parity`, both showing every cell in a pasted row (Type/Size/Unit/Location/Executed/Price/derived/party columns) at `12px`/`31px` line-height, Location included, both before and after a location is set — with only the row's own delete icon called out as a deliberate, separately-named `13px` exception. The full automated suite stayed green through five separate re-merges this fix needed while its PR was open (other sessions shipped competing changes to this same grid file in parallel) — including one round where a concurrent PR's own attempted fix of a related area still carried this exact same `font: "inherit"` bug in its own version of the line, confirmed by reading its diff directly; that PR's own new regression harness (`ui-audit/verify-comp-entry-grid-consistency.mjs`, 15/15) also passes clean against the final merged code. `npx vitest run` — 688/688 files, 14,207/14,207 tests green. `npx eslint` — 0 errors. `node ui-audit/design-drift-audit.mjs --check` clean.
