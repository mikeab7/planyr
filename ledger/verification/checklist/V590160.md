1. Open the same note (with the table still present) in both windows. In window A, leave it as is. In window B, right-click the table → "Convert table to text", and wait for it to save. **Expect:** window B now shows the contact lines as plain text with no table; window A is unaffected until you interact with it.
2. In window A, edit one unrelated word elsewhere in the note (so both windows now have unpushed, divergent edits) and let it save. **Expect:** no error or prompt yet in either window.
3. Bring both windows to the same page state (reload, or just wait for the next sync tick). **Expect:** exactly one window shows a COMPACT amber notice — one line of text plus a "Review changes →" button — no taller than an ordinary banner.
4. Click "Review changes →". **Expect:** a FULL-SCREEN surface opens, titled "Compare versions — ⟨note title⟩", "Redline" selected by default, a "✕ Decide later" control top-right (never a bare "✕"), and a line under the header stating both copies are safe and you can decide later.
5. Read the direction line at the top of the redline. **Expect:** it names the OLDER and NEWER copy by relative time (e.g. "Older version (edited …) → Newer version (edited …)") — never "This window"/"the other window" as the primary framing.
6. Read the redline body. **Expect:** the table shows a red **"− Removed"** tag (it only exists on the OLDER copy) and the converted contact lines show green **"+ Added"** tags (they only exist on the NEWER copy) — i.e. the direction matches which copy actually ran "Convert table to text", never the reverse. This is the data-safety check: if this is backwards, stop and file it as a regression of B1076177 rather than continuing the script.
7. Scroll down inside the redline body (pad the note with enough content first if needed). **Expect:** the legend stays pinned at the top of the visible area rather than scrolling out of view.
8. Read the two footer buttons. **Expect:** they read DIFFERENT text — "Keep the newer version" / "Keep the older version" — never the same string twice, and each is truthfully labelled (the one that keeps the converted-to-text copy says "newer" only if it actually is the more recently edited one).
9. Click "Side by side". **Expect:** two cards, headed the same way ("Newer version"/"Older version" + edited-when), each with its own distinctly-labelled button; the "nothing is lost" reassurance appears ONCE above the cards, not once per card.
10. Press Escape (or "✕ Decide later") without choosing. **Expect:** the review closes back to the compact notice; the note is UNCHANGED and still marked unresolved.
11. Reload the page entirely (not just close the review — an actual browser reload). **Expect:** the SAME compact notice reappears on its own, with "Review changes →" reopening the SAME comparison, both copies still intact — confirming B1076178's defer/reload claim on the real deployed app, not just in the store-level test.
12. Reopen and press "Keep the newer version". **Expect:** the note shows that copy's text; a new sibling page appears holding the OTHER copy's text, byte-for-byte; the notice clears.
13. Repeat on a fresh divergence and press "Keep the older version" instead. **Expect:** the mirror of step 12. Screenshot after this step and confirm neither version's text was lost anywhere in the process.
