A Playwright-driven check against planyr.io would not settle this either way: `navigator.webdriver` suppresses the NETWORK send (`networkReportSuppression`, `clientErrors.js`), so even a correctly-firing capture would never leave an automated tab.

**What was verified here (this session, sandbox).** `test/perfRecorder.test.js` (+8 tests) proves `perfTrigger.feedBootTask` in isolation: an ordinary boot's short tasks never trip either bar (single-task or cumulative); a single task at `bootSingleTaskMs` fires with `trigger:"single"`; several tasks under that bar but summing past `bootTaskBudgetMs` fire with `trigger:"cumulative"`; nothing fires past `bootWindowMs` or once a baseline has sealed (the two judgments never overlap in time); the boot judgment shares the steady-state `fires`/`cooldownMs`/`maxAuto` budget rather than a separate one; a non-positive or `NaN` duration is ignored; `bootTrigger` values stay on the fixed `BOOT_TRIGGER_VOCAB`. `node ui-audit/verify-perf-recorder.mjs --json` (GUARD 3, added this session) drove the real built app in headless Chromium: a CONTROL page opened and touched by nothing at all for the whole free-run window collected 150 real frames (proving the free-run itself runs despite zero interaction) and fired zero boot captures (proving the judgment doesn't fire on nothing); an EARLY-BURN page ran a 300 ms main-thread stall from an `addInitScript` — before the page's own first script could run, long before any idle callback could possibly fire the recorder's install — and still produced one boot capture (`bootTrigger:"single"`) once the recorder eventually installed, proving the buffered-observer retroactive pickup holds rather than being assumed. Overhead unaffected (0.07 µs/frame hot-path cost against a 2.0 bound; 0 ms ON-vs-OFF median delta against a 0.6 ms bound); the pre-existing steady-state anti-rot guard (a real induced stall) still fires 3/3 with 0 false positives.
