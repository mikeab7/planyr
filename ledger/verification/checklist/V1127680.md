**Why this needs its own live pass (as originally written).** Two of this bug's three legs are closed headlessly (below); the third cannot be. The flash rides a REMOUNT that only a signed-in boot performs — `applyUser` (`SitePlannerApp.jsx:350`) bumps `loadEpoch` when the cloud pull settles, and the planner is keyed `` `${activeSiteId}:${loadEpoch}` `` — and this sandbox cannot sign in (the egress proxy CORS-blocks the Supabase auth handshake). The sandbox arm proves the same structural event through a route-change remount, which changes the same React key and produces the same fresh mount; what it cannot prove is the `applyUser` path itself, on his data, on his phone. Timing/race and zoom-dependent rendering are both mandatory LIVE-VERIFY classes besides.

**⚠ What this session could NOT check, stated rather than routed around — two separate walls, both measured, not assumed.**
1. **WebKit could not be installed.** `docs/PHONE-TESTING.md` says WebKit installs on demand from a Claude Code session with normal network access. **That is not true of THIS session:** `npx playwright install webkit` is refused by the egress proxy (`403 request blocked: no rule or allowlist entry allows host "playwright.download.prss.microsoft.com"`). So the phone leg here is Chromium at iPhone dimensions — a real narrow viewport, not a real engine. Mobile Safari's own paint scheduling on a foregrounded tab is the one thing that could still differ, and it is exactly what step 1 below settles.
2. **The DEPLOYED build could not be driven from this session's browser, even though `curl` reaches it.** The obvious shortcut — point the rig at the PR's own Cloudflare preview and judge the bundle that actually shipped — was tried and does not work here: `curl` returns `200` from `https://claude-zen-heisenberg-glddce.planyr.pages.dev/`, while Chromium returns `net::ERR_CONNECTION_RESET` for the same URL, **with and without the environment's egress proxy passed at launch** (isolated with a bare Playwright script, no route interception and no init scripts, after two harness-level attempts failed — the "change the mechanism, not the parameters" rule). Browser egress to external hosts is blocked in this sandbox independently of `curl`'s, which is the same wall every harness here works around with `--no-tiles`. **The facility is committed anyway:** `node ui-audit/verify-boot-framing.mjs --base=<url>` runs every arm against an already-deployed build, through `HTTPS_PROXY` when one is set. Any session or machine with real browser egress can close the production half of this check with one command — see step 6.
