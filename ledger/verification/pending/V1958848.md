### V1958848 — B2509040: an uploaded Excel opens in Spreadsheet, edits save into the SAME Library file, survive a reload, and the downloaded .xlsx re-opens cleanly

**What the sandbox already proved (so this pass does not re-litigate it):** the parse, the open/save rules, the version history and the round-trip are covered by `test/spreadsheetFile*.test.js` against real fixture files and an in-memory Library. What it structurally cannot produce: the real Drive upload/download path, the real `doc_reviews` record + compare-and-swap, the real Library UI, and the real parse worker in a browser. That is this pass. It runs signed in as the throwaway test account (`ui-audit/lib/signedInSession.mjs`), reads `/version.json` in the SAME call as each assertion, and deletes everything it creates (owner rule 15 — no asking).

**Steps, each with a named expected result:**
1. Sign in as the test account on planyr.io (build hash matched to the merge commit). In the e2e fixture project's Library, upload a generated multi-sheet `.xlsx` (sheet "Assumptions" with a number and a serial-number date formatted m/d/yyyy; sheet "Model" with `=Assumptions!B1*2`; a frozen header row; a leading blank column and a header with trailing spaces). **Expect:** the row appears in the Library list.
2. Click the row. **Expect:** the Spreadsheet tab opens with both sheet tabs, the formula cell shows its computed value, the date reads as a date (not a 5-digit number), the header text keeps its spaces, the file bar names the file and says edits save to this file; no banner (the file has nothing unsupported).
3. Edit the input number and a formula input; wait for the save indicator. **Expect:** the dependent formula recomputes on screen; the header badge goes saving → saved with no error bar.
4. Reload with a cache-bust (`?cb=<time>`) and re-open the same row. **Expect:** the edits are there (the saved bytes, not the original), the formula is still a formula, the date is still a date.
5. File ▸ Download as Excel (.xlsx); read the downloaded file with ExcelJS outside the app. **Expect:** both sheets, the formula text with a cached value, the date as a real date with its format.
6. File bar ▸ Download original. **Expect:** the bytes equal the file uploaded in step 1 (original preserved as the prior version).
7. Upload a `.csv`, open it, edit a cell, wait. **Expect:** a note says edits go to a new Excel copy; a `<name>.xlsx` appears in the same Library folder; the `.csv` is unchanged; clicking the `.csv` row again opens the edited copy with the "Opened your editable Excel copy" note.
8. Upload an `.xlsx` containing a chart (the openpyxl fixture) and open it. **Expect:** it opens, and the banner names "1 chart" as not carried over; the original is downloadable unchanged.
9. Upload the password-protected fixture and a text file renamed `.xlsx`. **Expect:** each opens a "couldn't be opened" panel naming the file and what to do — no blank grid, no endless spinner.
10. Use File ▸ "Open Excel or CSV file…" inside the Spreadsheet with a small `.xlsx`. **Expect:** it is filed in the Library under the open project and opens exactly as in step 2.
11. Clean up: delete every file created (originals, copies), confirm they are gone from the Library list.
- Stopping rule: closes when steps 1–10 pass on a real signed-in session against the deployed build, with step 11 confirmed. A failing step is filed as a recurrence of **B2509040**, naming the step and the observed behaviour. WebKit/phone-width opening is checked in step 2's run at a phone viewport (`docs/PHONE-TESTING.md`) and reported as WebKit, not "iPhone".
