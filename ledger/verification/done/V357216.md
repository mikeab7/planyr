### V357216 — B683568: the View card shows "Loading…" instead of the old ornament-only layout while a signed-in plan's elements are still arriving `Blocker: auth`
**What was verified here — the mechanism, by source and by production data, and the component's rendered output.** Read-only queries against production (`lyeqzkuiwngunutlkkmi`) confirmed the root cause: a signed-in plan's cloud header carries no elements (`slimForCloud`), so `els`/`parcels`/etc. read as empty until `elementSync`'s rows fetch lands — and confirmed this is uncorrelated with `settings.hidden`, refuting the hypothesis the item was filed under. `test/viewMenuLoading.test.js` renders the real `ViewMenu` component (`react-dom/server`) and proves, by SHAPE: a mid-load empty snapshot with `elementsReady=false` shows a "Content" heading + "Loading what's on this plan…" and withholds the live rows; the same content, `elementsReady=true`, shows the live tri-state Elements master and per-type rows; a genuinely empty plan (`elementsReady=true`, nothing drawn) still shows no Content section at all, matching the pre-existing correct behaviour. Proven RED against the pre-fix component first (git-stashed, re-run, restored). `npx vitest run` 12,157/12,159 green (the 2 failures are pre-existing shallow-clone artifacts, confirmed unrelated). Build green.
**What is NOT proven:** this sandbox cannot sign in (Supabase auth is blocked by the egress proxy), so the actual TIMING — how long the loading window really is on planyr.io, whether the placeholder is visible long enough to matter, and whether the transition from "Loading…" to the real rows is visually smooth — has never been observed against the live rows engine.
