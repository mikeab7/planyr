**Results:**
1. **Settled baseline is real and specific to the cursor** — the point under a settled cursor reads a clearly elevated tint (r−b ≈ 5.8) against an untouched point's ambient baseline (r−b ≈ −0.86).
2. **No snap.** Immediately after the jump (one input event, zero settle time), the OLD point still carries most of its tint (r−b ≈ 6.5, i.e. still ABOVE the pre-jump baseline) and the NEW point has NOT jumped to the settled value (r−b ≈ −0.88, indistinguishable from ambient) — a lockstep implementation would read ≈5.8 at the new point immediately; it reads ≈0.
3. **Monotonic migration, no oscillation.** Sampled at t+150/350/700/1600ms: the new point's tint rises (≈−1.1 → ≈5.6 → ≈5.7 → ≈4.6) while the old point's falls (≈6.5 → ≈−1.0 → ≈−1.3 → ≈−1.4 → ≈−1.4), with no reversal at any step — the expected shape for a pure lerp, which cannot overshoot by construction.
4. **Settles within roughly a second, not several** — by t+350–700ms the new point already reads near its full settled tint; this is the "a beat of lag," not "a stall," distinction the brief asked for.
5. **`prefers-reduced-motion: reduce` still renders exactly one static frame** — two `toDataURL()` reads 900ms apart were byte-identical, in a fresh context built specifically to re-check this (not just cited from a prior pass on this file).
