- **NEW-RC-10 found + fixed + headless-proven this session (2026-07-18) — the specific bug Michael reported and reproduced live 3× (project "ZZ-THROWAWAY-TEST 2026...", a Building element, Properties → Fill opacity slider):** select an element, drag its Fill-opacity slider, then press Ctrl+Z **WITHOUT deselecting or clicking away first** → silently no-op'd. Root cause: the global keydown guard (`SitePlanner.jsx`) treated ANY focused `<input>` — including a `type="range"` slider, which has no native browser undo to protect — as "typing" and unconditionally swallowed Ctrl+Z/Ctrl+Y before they ever reached the app's undo dispatch. The toolbar Undo button and a click-away-then-Ctrl+Z both already worked (bypassing the guard), and the reverted value already persisted correctly across a reload once undone — so this was purely a keyboard-dispatch gap, not a persistence bug. **Fix:** the guard now lets ONLY the Ctrl/Cmd+Z / +Y chord through when focus is on a range/slider input; every other shortcut (arrows, Delete, letter tools) still respects the guard while a slider has focus, since those DO have real native slider behavior or would nudge/delete the still-selected element out from under the user. **Verified:** full unit suite green (4522) · lint 0 errors · build green · new describe block in `e2e/ctrlz-undo.spec.js` (2 tests, LOGGED-OUT, green in headless Chromium): (a) drag a Building's Fill-opacity slider then Ctrl+Z with focus still on the slider now correctly reverts it (proven via the persisted model value, since — matching the toolbar Undo button's own documented behavior — the app's `applySnapshot` deselects/closes the Properties panel as part of any undo/redo) and Ctrl+Shift+Z redoes it; (b) a no-regression check confirms Ctrl+Z with focus in a REAL text field (a callout's inline `<textarea>`, whose placement is already on the undo stack) still does **NOT** fire app undo — proving the fix is scoped to sliders only, not a blanket "any focused input" exception. Sanity-checked the test itself: reverted the guard fix, rebuilt, reran — test (a) failed exactly as expected (value stuck at the dragged-to value); re-applied the fix, reran green — confirms the test genuinely catches the regression rather than being a false positive.
