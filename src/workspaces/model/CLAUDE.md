# Model workspace (user-facing "Spreadsheet") — folder pointer

Internal id `model`, route slug `spreadsheet`. One workbook per project (`model_sheets`), several per
Organization (`org_model_sheets`), and — NEW-1 — a **Library file opened as a workbook** ("file mode").

> **⛔ THE UNIVER GRID IS THE GRID (owner decision 2026-10-30 — "It should just be the new grid."; cutover steps 8–9a, NEW-1/NEW-2, 2026-10-31).**
> Every account, every device, signed in or out, gets the Univer grid on the Spreadsheet tab, in project, Organization and Library-file mode alike; there
> is no switch to find. **The old `SheetView.jsx` grid is DEPRECATED, PENDING DELETION (step 9b — a separate later session, do not delete it in an
> unrelated one).** It survives for ONE reason: an owner-only per-device safety hatch for about a week — File ▾ → "Use the regular grid" / "Use the
> new grid", shown only when `is_admin()` is confirmed, the device flag lives under `planyr:model:regularGrid` (`lib/gridChoice.js`; the pre-cutover
> `planyr:model:univerGrid` key is dropped and never read, so no device lands on the old grid by accident). **Do not build on the old grid, do not
> fix bugs in it, and do not give a non-admin any route to it** (no URL flag, env var or second gate). Everything about `SheetView` /
> `Ribbon` / `FormulaBar` / `TabStrip` / `sheetEngine` below is HISTORY kept until 9b removes it; the Univer sections further down are current.
> Tests that read cells now go through Univer's facade (`window.__planyrUniverRead`, armed only when `window.__PLANYR_E2E === true`) — the e2e helper is
> the file named univerGrid in the repo-root e2e lib folder, the ui-audit pattern is the repo-root file named verify-univer-parity; the canvas has no cell DOM to query.

**Open an uploaded Excel / CSV (file mode).** A Library `.xlsx/.xls/.xlsm/.csv` row opens HERE (the Shell
routes it; `FileBrowser` right-click says "Open in Spreadsheet"; the File menu has "Open Excel or CSV
file…"). ONE source of truth: the Library file's stored bytes ARE the document — no second copy in a table.
- `lib/spreadsheetKind.js` — name → kind, `savesInPlace`, `xlsxNameFor`, `SpreadsheetFileError`. Dependency-free on purpose (the Shell and Library import it).
- `lib/spreadsheetFile.js` — bytes → workbook + "what didn't carry over" notes. Runs in `lib/spreadsheetWorker.js` (import discipline pinned by the repo-root `test/` suite **spreadsheetFileWiring**); `lib/spreadsheetClient.js` is the main-thread half (timeout, main-thread fallback). Uses `xlsxIO.js` (ExcelJS), `csvIO.js`, SheetJS for old `.xls`, `xlsxInspect.js` (encrypted / charts / pivots / macros detection; `stripNonCellParts` = the retry ExcelJS needs for any workbook with a chart).
- `lib/fileWorkbook.js` — the open/save RULES (pure, injected I/O). Only a real `.xlsx` saves in place (new stored version, the upload kept as the prior version; one version per editing session). `.xls/.xlsm/.csv` get a new `.xlsx` Library file beside them and the original links to it (`spreadsheetCopyId`). `lib/fileWorkbookStore.js` is the real I/O (reviewStore + the worker).
- `lib/useFileWorkbook.js` + `lib/fileDraft.js` — load / debounced save / status, and the on-device safety copy of unsaved edits. `lib/activeFile.js` — which file each place is showing. `components/FileBar.jsx` — file bar, "won't carry over" banner, open-failure panel.
- In file mode ModelApp's project load / write-through / cloud push are skipped (`fileMode`) — never let them write a file's cells into a project slot.
- Tests: repo-root `test/` **spreadsheetFile**, **spreadsheetFileWorkbook**, **spreadsheetFileWiring** (real fixtures in `test/fixtures/spreadsheet/`).

**Cloud sync base (B2450528).** `model_sheets.data` is jsonb, which re-orders object keys, so workbooks are compared ONLY through `sheetModel.sheetsDiverge`/`canonicalJson` (sorted keys) — never raw `JSON.stringify`. The device keeps `{ baseVersion, dirty }` beside the stored workbook (`modelStore.readSyncMeta/writeSyncMeta`); `lib/modelSyncBase.js` `decideLoadSync` is the ONE decision of which copy wins at load. The red "different copy" bar is only for "dirty AND the cloud moved past the base". Only a person's edit (ModelApp's wrapped commit/undo/redo) marks dirty — a load's `reset` never does. Guard: repo-root `test/` **modelSyncBase**; live: the ui-audit harness named verify-spreadsheet-sync-base.

**A cell's text starts in ONE place (NEW-1, B2525584).** `lib/cellTextLayout.js` is the single source for a cell's text padding (`cellPadding`) and for which cells may spill across empty neighbours (`canSpill`); both paths in `SheetView.jsx` use it, so clearing or refilling the cell beside a label never moves the label. **An indent (NEW-2, B2525585) only insets the text on its reading side (left for left-aligned, right for right-aligned, none for centred) and is clamped so a cell can NEVER be wider than its column — never write indent as symmetric or unclamped padding.** Increase/Decrease Indent step each selected cell from its OWN level (`sheetModel.adjustIndent`, capped at 15), not from the active cell's. Guards: repo-root `test/` **cellTextLayout**; e2e **model-clear-cell-layout** (also the indent-geometry cases: every cell edge in an indented row equals the header's).

**Chrome is FLAT and edge to edge (NEW-1, B2517376, owner-approved mockup 2026-10-29).** The toolbar (`components/Ribbon.jsx`), the formula bar (`components/FormulaBar.jsx`), the grid (`components/SheetView.jsx`) and the sheet-tab strip (`components/TabStrip.jsx`) are full-width strips with single hairlines — no floating card, margin, rounded corners or shadow anywhere. Do not bring the card back. Guard: the repo-root ui-audit harness named verify-spreadsheet-flat-chrome.

**Excel keyboard shortcuts, Alt key-tips, header selection and the real clipboard (NEW-1, 2026-10-29 — B2455072–B2455075).** Excel for Windows is the spec; ONE command registry (`lib/commandRegistry.js`) is what keys, key-tips, palette, ribbon and menus all run.
- `lib/keymap.js` — keystroke → command id (`CHORDS`, edit-mode subset, `navAction`); matched on `e.key` only. Ctrl+C/X/V are NOT here: they are native clipboard EVENTS.
- `lib/keyTips.js` — the Alt tree + pure state machine; `components/KeyTipOverlay.jsx` draws the badges (`data-keytip` on Ribbon controls) and the next-key strip. Alt starts only on a bare Alt keyup (`ModelApp.jsx`, capture-phase listeners).
- `lib/selection.js` — THE whole-row / whole-column / whole-sheet selection model (a range, never a cell walk); header clicks, drag, Shift+click, corner, Shift+Space/Ctrl+Space/Ctrl+A, the Name Box (`C:C`, `5:5`) and the structural keys all use it. **Headers are fixed labels** (`columnHeaderLabel` = the position's letter) — no rename route exists; `column.name` stays in the data only so old `[Name]` formulas keep resolving. A Ctrl+click on a header adds the whole line as another range via `selectionModel.js` (below); the whole-line rectangles here are the pieces it holds.
- `lib/clipboardIO.js` — pure: build text/plain + text/html (Planyr marker), parse Planyr / Excel-HTML / TSV, `applyClip`, `pasteMoveSameSheet` (cut = move; `lib/formulaMove.js` re-points references). Listeners live in `ModelApp.jsx` and are scoped off any text control. Fixture: `test/fixtures/spreadsheet/excel-range.html`.
- `lib/autofit.js` (column + wrapped-row autofit), `lib/editShortcuts.js` (F4, Alt+Enter, Ctrl+;), `components/ShortcutDialog.jsx`, hidden rows/columns (`sheet.hiddenRows`, `column.hidden`).
- Guards: repo-root `test/` **modelKeymap**, **modelKeyTips**, **modelSelection**, **modelClipboardIO**, **modelAutofit**, **modelHiddenRowsCols**; real-keystroke harness (the repo-root ui-audit file named verify-spreadsheet-keyboard; run it against main to see what each check protects).

**Drag-select autoscroll (NEW-1, B2452528).** Every range-extending gesture in `components/SheetView.jsx` (cell drag, column-header drag, row-header drag, fill handle) rides ONE session, `beginRangeDrag`: window pointer listeners + a rAF loop, the cell under the pointer found by coordinates against the full offset tables (a virtualised, un-rendered row is still reachable), the grid scrolling while the pointer sits at/past an edge even when held still. Pure geometry: `lib/dragAutoscroll.js`. Do not go back to per-cell `onMouseEnter` or ending the drag on `onMouseLeave`, and do not add `setPointerCapture` (it retargets the click and breaks double-click-to-edit). Guards: repo-root `test/` **modelDragAutoscroll**; e2e **model-drag-autoscroll**; live ui-audit **verify-spreadsheet-drag-autoscroll-live**. The Schedule grid (inlined by the `sync-sequence-selection` script under `scripts/`) and the Notes tables now share the *selection model and edge-scroll speed* (B2530690) but not the drag session itself — each surface owns its own pointer plumbing.

**Selection is a LIST OF RANGES (NEW-2, B2530689).** `lib/selectionModel.js` is now a re-export of the shared range-selection module (`shared/selection/rangeSelection`) (B2530690 — the SAME code the Schedule grid inlines and the Notes tables import; edit the shared file, then run the sync-sequence-selection script under `scripts/`; the repo-root `test/` suite **rangeSelectionInlineSync** fails on drift). The pure model: `{r1,r2,c1,c2,extra?}` — the four fields are the ACTIVE range, `extra` the earlier ones. Ctrl+click / Ctrl+drag / Ctrl+header add a range, Ctrl+click on a selected cell removes it, Shift extends only the newest, a plain click collapses; `applyToRanges` makes a command over every range one undo step (Delete, ribbon formatting, Ctrl+D, Ctrl+Enter). Commands Excel refuses on several ranges (copy, paste, insert/delete, freeze, sort, merge) show `MULTI_SELECTION_MESSAGE` — never a silent no-op. It rides `beginRangeDrag` (above); do not add a second drag engine. Guards: repo-root `test/` **modelSelectionModel**; e2e **model-multirange-selection**; live ui-audit **verify-spreadsheet-multirange-live**.

**Univer grid — THE grid for every account (NEW-1, B2557488 spike → cutover B2557489-series, default-on 2026-10-31). Read `docs/SPREADSHEET-UNIVER-SPIKE.md` (results, parity table, numbers, cutover plan) before touching any of this.**
- **WHY THE HEAVY DEPENDENCY IS ALLOWED (owner-supplied justification — do not re-litigate):** eleven grid-behaviour bugs were reported in ONE afternoon (Ctrl+Z in a cell, bare F going fullscreen, editable row/column headers, header click not selecting, Ctrl+click multi-select, drag-select stopping at the edge, clearing a cell nudging the neighbour, indent, the Excel shortcut set, clipboard, the false "different copy" bar). Every one was GRID BEHAVIOUR, not formula maths; the grid is hand-built (`SheetView.jsx` ~1400 lines, `sheetModel.js` ~1340, the shared formula engine ~2360, ~13k LOC) and Excel's grid has thousands of such rules, so the class keeps arriving. His words: *"make this as close to Excel as you can"*, *"I'd rather just copy someone's code"*, *"I'm not paying for anything"*. Excel behaviour is the spec.
- **Hard constraints:** open-source `@univerjs/*` ONLY, exact-pinned (`1.3.1`) — nothing from `@univerjs-pro/*`, no license key, no Univer server, no call to a Univer host, never Univer's exchange packages (xlsx/csv stay on ExcelJS / SheetJS / `csvIO.js`). `SheetView.jsx` and `sheetModel.js` are untouched (deprecated, pending deletion — step 9b). Guards: repo-root `test/` **modelUniverSwitch** (also pins that only `UniverSheet.jsx` imports `@univerjs/*`, that ModelApp reaches it through `lazy()`, and that the four grid-level window listeners stand down while Univer owns the keyboard).

- `components/UniverSheet.jsx` — the lazy chunk (the only file that imports Univer): mounts the grid, debounces edits (300 ms) into a whole Planyr workbook and hands it to ModelApp's ONE `commit` (so write-through, cloud push, file mode and org workbooks are the same path); an incoming workbook equal to the last one emitted is our own echo and is ignored. `window.__planyrUniverRead` (the facade handle for harnesses) answers only when `window.__PLANYR_E2E === true`. `components/univerSheet.css` + `lib/univerTheme.js` — flat chrome from Planyr's tokens. **THE THEME IS PER MODE (B2566048):** Univer's gray scale never flips (0 lightest … 900 darkest; dark mode picks the other end) and its canvas goes through a colour inversion in dark, so `buildUniverTheme(base, tokens, { dark })` puts the text in `gray.0` and the surface in `gray.800/900` for dark (the opposite of light) and writes the canvas hairline / header tint pre-inverted; `UniverSheet.jsx` rebuilds it from the live tokens on EVERY flip, never once at mount. Do not write a surface into `gray.0` or text into `gray.900` unconditionally. Guard: the repo-root ui-audit harness named verify-univer-theme-contrast (pixels, both themes, mounted and flipped) + the repo-root `test/` suite **modelUniverSwitch**.
- **THE HEADER IS ONE STRIP (B2574352 / B2574353, owner 2026-10-30).** `UniverSheet.jsx` runs Univer's `ribbonType: "collapsed"` — the Start / Formulas / Data / View row is a "Start ▾" dropdown at the strip's left and the tab's tools sit left-packed beside it (Univer's default "classic" is a centred tab row over the tool row = two headers). `univerSheet.css` flattens everything under `[data-u-comp="headerbar"]` (no radius, no shadow, the trigger is plain text, never Univer's dark pill). A tool another session registers lands in the strip's own groups — never position or centre individual tools, never add a second header row. Undo / redo are curved arrows (`components/univerIcons.jsx`, swapped in by registry name through `IconManager` right after `createUniver`; the old `Ribbon.jsx` glyphs are right-angle elbows and are NOT the model). Guards: the repo-root ui-audit harness named verify-univer-header (its pure verdict is the univerHeader module in the ui-audit lib folder; run the harness against `origin/main` to see it red) + the repo-root `test/` suite **univerHeaderVerdict**.
- `lib/univerBridge.js` — pure, imports nothing from Univer: Planyr workbook ⇄ Univer `IWorkbookData`, lossless for every stored field via a SIDECAR the host keeps (column ids, raw literal text, synthesised display patterns, dismissed-inconsistency and unsupported-formula maps — each entry self-validating so a sort or drag cannot make a stale one lie). What Univer cannot hold (vertical merges, `[Column]` formulas, typed-date text, in-cell rich text) is returned in `notes` and said out loud — never dropped quietly. Site.* / Plan.* / Comp.* become global defined names (`projectNamesToDefinedNames`; Univer accepts dotted identifiers as-is) and are NEVER saved back. Guard: repo-root `test/` **modelUniverBridge** (real fixtures + a workbook using every stored field).
- **Indent (NEW-1, B2572784).** Univer has no indent field or command; `lib/univerIndent.js` builds one on its cell PADDING (`pd`, which Univer's commands keep — a custom style field is stripped, measured): the indent N is stored as the cell's own `pd.l = 2 + 14·N` (so it follows its cell through insert/delete/sort/copy — NOT in the sidecar), drawn by a render-time `SheetInterceptorService` CELL_CONTENT interceptor on the reading side only and clamped to the column (same step and cap as the old grid's `cellTextLayout` / `sheetModel.adjustIndent`), changed by two commands — `INDENT_COMMAND_IDS` = `planyr.sheet.command.increase-indent` / `.decrease-indent`, the ids the Excel-keys plugin binds Alt H 6 / Alt H 5 to — each ONE `SetRangeValues` (one undo step, every cell from its own level), with buttons on the Start tab. `UniverSheet.jsx` only calls `installUniverIndent({...})` once after the first workbook loads (the sheets services do not exist before). The bridge maps `pd.l` ⇄ `styles[key].indent` (`indentOfStyle` / `storedIndentStyle`); never write a second copy of the number. Guards: repo-root `test/` **modelUniverIndent** + **modelUniverBridge**; the parity run's `indent` check (pixels) and section H of the live run (cross-grid, both directions).
