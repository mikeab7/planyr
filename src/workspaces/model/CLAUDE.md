# Model workspace (user-facing "Spreadsheet") — folder pointer

Internal id `model`, route slug `spreadsheet`. One workbook per project (`model_sheets`), several per
Organization (`org_model_sheets`), and — NEW-1 — a **Library file opened as a workbook** ("file mode").

**Open an uploaded Excel / CSV (file mode).** A Library `.xlsx/.xls/.xlsm/.csv` row opens HERE (the Shell
routes it; `FileBrowser` right-click says "Open in Spreadsheet"; the File menu has "Open Excel or CSV
file…"). ONE source of truth: the Library file's stored bytes ARE the document — no second copy in a table.
- `lib/spreadsheetKind.js` — name → kind, `savesInPlace`, `xlsxNameFor`, `SpreadsheetFileError`. Dependency-free on purpose (the Shell and Library import it).
- `lib/spreadsheetFile.js` — bytes → workbook + "what didn't carry over" notes. Runs in `lib/spreadsheetWorker.js` (import discipline pinned by the repo-root `test/` suite **spreadsheetFileWiring**); `lib/spreadsheetClient.js` is the main-thread half (timeout, main-thread fallback). Uses `xlsxIO.js` (ExcelJS), `csvIO.js`, SheetJS for old `.xls`, `xlsxInspect.js` (encrypted / charts / pivots / macros detection; `stripNonCellParts` = the retry ExcelJS needs for any workbook with a chart).
- `lib/fileWorkbook.js` — the open/save RULES (pure, injected I/O). Only a real `.xlsx` saves in place (new stored version, the upload kept as the prior version; one version per editing session). `.xls/.xlsm/.csv` get a new `.xlsx` Library file beside them and the original links to it (`spreadsheetCopyId`). `lib/fileWorkbookStore.js` is the real I/O (reviewStore + the worker).
- `lib/useFileWorkbook.js` + `lib/fileDraft.js` — load / debounced save / status, and the on-device safety copy of unsaved edits. `lib/activeFile.js` — which file each place is showing. `components/FileBar.jsx` — file bar, "won't carry over" banner, open-failure panel.
- In file mode ModelApp's project load / write-through / cloud push are skipped (`fileMode`) — never let them write a file's cells into a project slot.
- Tests: repo-root `test/` **spreadsheetFile**, **spreadsheetFileWorkbook**, **spreadsheetFileWiring** (real fixtures in `test/fixtures/spreadsheet/`).

**Cloud sync base (B2450528).** `model_sheets.data` is jsonb, which re-orders object keys, so workbooks are compared ONLY through `sheetModel.sheetsDiverge`/`canonicalJson` (sorted keys) — never raw `JSON.stringify`. The device keeps `{ baseVersion, dirty }` beside the stored workbook (`modelStore.readSyncMeta/writeSyncMeta`); `lib/modelSyncBase.js` `decideLoadSync` is the ONE decision of which copy wins at load. The red "different copy" bar is only for "dirty AND the cloud moved past the base". Only a person's edit (ModelApp's wrapped commit/undo/redo) marks dirty — a load's `reset` never does. Guard: repo-root `test/` **modelSyncBase**; live: the ui-audit harness named verify-spreadsheet-sync-base.

**A cell's text starts in ONE place (NEW-1, B2525584).** `lib/cellTextLayout.js` is the single source for a cell's text padding (`cellPadding`) and for which cells may spill across empty neighbours (`canSpill`); both paths in `SheetView.jsx` use it, so clearing or refilling the cell beside a label never moves the label. **An indent (NEW-2, B2525585) only insets the text on its reading side (left for left-aligned, right for right-aligned, none for centred) and is clamped so a cell can NEVER be wider than its column — never write indent as symmetric or unclamped padding.** Increase/Decrease Indent step each selected cell from its OWN level (`sheetModel.adjustIndent`, capped at 15), not from the active cell's. Guards: repo-root `test/` **cellTextLayout**; e2e **model-clear-cell-layout** (also the indent-geometry cases: every cell edge in an indented row equals the header's).

**Chrome is FLAT and edge to edge (NEW-1, B2517376, owner-approved mockup 2026-10-29).** The toolbar (`components/Ribbon.jsx`), the formula bar (`components/FormulaBar.jsx`), the grid (`components/SheetView.jsx`) and the sheet-tab strip (`components/TabStrip.jsx`) are full-width strips with single hairlines — no floating card, margin, rounded corners or shadow anywhere. Do not bring the card back. Guard: the repo-root ui-audit harness named verify-spreadsheet-flat-chrome.

**Excel keyboard shortcuts, Alt key-tips, header selection and the real clipboard (NEW-1, 2026-10-29 — B2455072–B2455075).** Excel for Windows is the spec; ONE command registry (`lib/commandRegistry.js`) is what keys, key-tips, palette, ribbon and menus all run.
- `lib/keymap.js` — keystroke → command id (`CHORDS`, edit-mode subset, `navAction`); matched on `e.key` only. Ctrl+C/X/V are NOT here: they are native clipboard EVENTS.
- `lib/keyTips.js` — the Alt tree + pure state machine; `components/KeyTipOverlay.jsx` draws the badges (`data-keytip` on Ribbon controls) and the next-key strip. Alt starts only on a bare Alt keyup (`ModelApp.jsx`, capture-phase listeners).
- `lib/selection.js` — THE whole-row / whole-column / whole-sheet selection model (a range, never a cell walk); header clicks, drag, Shift+click, corner, Shift+Space/Ctrl+Space/Ctrl+A, the Name Box (`C:C`, `5:5`) and the structural keys all use it. **Headers are fixed labels** (`columnHeaderLabel` = the position's letter) — no rename route exists; `column.name` stays in the data only so old `[Name]` formulas keep resolving. Multi-range selection is deliberately not supported.
- `lib/clipboardIO.js` — pure: build text/plain + text/html (Planyr marker), parse Planyr / Excel-HTML / TSV, `applyClip`, `pasteMoveSameSheet` (cut = move; `lib/formulaMove.js` re-points references). Listeners live in `ModelApp.jsx` and are scoped off any text control. Fixture: `test/fixtures/spreadsheet/excel-range.html`.
- `lib/autofit.js` (column + wrapped-row autofit), `lib/editShortcuts.js` (F4, Alt+Enter, Ctrl+;), `components/ShortcutDialog.jsx`, hidden rows/columns (`sheet.hiddenRows`, `column.hidden`).
- Guards: repo-root `test/` **modelKeymap**, **modelKeyTips**, **modelSelection**, **modelClipboardIO**, **modelAutofit**, **modelHiddenRowsCols**; real-keystroke harness (the repo-root ui-audit file named verify-spreadsheet-keyboard; run it against main to see what each check protects).

**Drag-select autoscroll (NEW-1, B2452528).** Every range-extending gesture in `components/SheetView.jsx` (cell drag, column-header drag, row-header drag, fill handle) rides ONE session, `beginRangeDrag`: window pointer listeners + a rAF loop, the cell under the pointer found by coordinates against the full offset tables (a virtualised, un-rendered row is still reachable), the grid scrolling while the pointer sits at/past an edge even when held still. Pure geometry: `lib/dragAutoscroll.js`. Do not go back to per-cell `onMouseEnter` or ending the drag on `onMouseLeave`, and do not add `setPointerCapture` (it retargets the click and breaks double-click-to-edit). Guards: repo-root `test/` **modelDragAutoscroll**; e2e **model-drag-autoscroll**; live ui-audit **verify-spreadsheet-drag-autoscroll-live**. The Schedule grid and Notes tables do not share this code.
