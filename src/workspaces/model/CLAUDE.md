# Model workspace (user-facing "Spreadsheet") — folder pointer

Internal id `model`, route slug `spreadsheet`. One workbook per project (`model_sheets`), several per
Organization (`org_model_sheets`), and — NEW-1 — a **Library file opened as a workbook** ("file mode").

> **⛔ THE UNIVER GRID IS THE ONLY GRID (owner decision 2026-10-30 — "It should just be the new grid."; cutover 2026-10-31; the old grid and its owner-only
> fallback were DELETED by the audit batch F2, 2026-11-23).** Every account, every device, signed in or out, gets the Univer grid in project, Organization and
> Library-file mode alike. There is no switch, no old hand-built grid or toolbar, and no second clipboard or selection
> engine; do not rebuild any of them. The retired device keys `planyr:model:univerGrid` / `planyr:model:regularGrid` are simply dropped by `lib/univerWarm.js`.
> `lib/sheetEngine.js` survives only for its dependency GRAPH (`evaluateWorkbook({ graphOnly: true })`, used by the trace tool) and shared helpers — Univer, run headless
> (`lib/univerEval.js`), is the only thing that computes a value. Tests that read cells go through Univer's facade (`window.__planyrUniverRead`, armed only when
> `window.__PLANYR_E2E === true`) — the e2e helper is the file named univerGrid in the repo-root e2e lib folder; the canvas has no cell DOM to query.

**Open an uploaded Excel / CSV (file mode).** A Library `.xlsx/.xls/.xlsm/.csv` row opens HERE (the Shell
routes it; `FileBrowser` right-click says "Open in Spreadsheet"; the File menu has "Open Excel or CSV
file…"). ONE source of truth: the Library file's stored bytes ARE the document — no second copy in a table.
- `lib/spreadsheetKind.js` — name → kind, `savesInPlace`, `xlsxNameFor`, `SpreadsheetFileError`. Dependency-free on purpose (the Shell and Library import it).
- `lib/spreadsheetFile.js` — (an old `.xls` is refused loudly with a "re-save as .xlsx" message; SheetJS was removed 2026-11-23, audit batch A) bytes → workbook + "what didn't carry over" notes. Runs in `lib/spreadsheetWorker.js` (import discipline pinned by the repo-root `test/` suite **spreadsheetFileWiring**); `lib/spreadsheetClient.js` is the main-thread half (timeout, main-thread fallback). Uses `xlsxIO.js` (ExcelJS), `csvIO.js`, `xlsxInspect.js` (encrypted / charts / pivots / macros detection; `stripNonCellParts` = the retry ExcelJS needs for any workbook with a chart).
- `lib/fileWorkbook.js` — the open/save RULES (pure, injected I/O). Only a real `.xlsx` saves in place (new stored version, the upload kept as the prior version; one version per editing session). `.xls/.xlsm/.csv` get a new `.xlsx` Library file beside them and the original links to it (`spreadsheetCopyId`). `lib/fileWorkbookStore.js` is the real I/O (reviewStore + the worker).
- `lib/useFileWorkbook.js` + `lib/fileDraft.js` — load / debounced save / status, and the on-device safety copy of unsaved edits. `lib/activeFile.js` — which file each place is showing. `components/FileBar.jsx` — file bar, "won't carry over" banner, open-failure panel.
- In file mode ModelApp's project load / write-through / cloud push are skipped (`fileMode`) — never let them write a file's cells into a project slot.
- Tests: repo-root `test/` **spreadsheetFile**, **spreadsheetFileWorkbook**, **spreadsheetFileWiring** (real fixtures in `test/fixtures/spreadsheet/`).

**Cloud sync base (B2450528).** `model_sheets.data` is jsonb, which re-orders object keys, so workbooks are compared ONLY through `sheetModel.sheetsDiverge`/`canonicalJson` (sorted keys) — never raw `JSON.stringify`. The device keeps `{ baseVersion, dirty }` beside the stored workbook (`modelStore.readSyncMeta/writeSyncMeta`); `lib/modelSyncBase.js` `decideLoadSync` is the ONE decision of which copy wins at load. The red "different copy" bar is only for "dirty AND the cloud moved past the base". Only a person's edit (ModelApp's wrapped commit) marks dirty — a load's `reset` never does. Guard: repo-root `test/` **modelSyncBase**; live: the ui-audit harness named verify-spreadsheet-sync-base.

**A cell's text starts in ONE place (NEW-1, B2525584).** `lib/cellTextLayout.js` is the single source for a cell's text padding (`cellPadding`) and for which cells may spill across empty neighbours (`canSpill`); Univer's cell padding and the indent bridge use it, so clearing or refilling the cell beside a label never moves the label. **An indent (NEW-2, B2525585) only insets the text on its reading side (left for left-aligned, right for right-aligned, none for centred) and is clamped so a cell can NEVER be wider than its column — never write indent as symmetric or unclamped padding.** Increase/Decrease Indent step each selected cell from its OWN level (`sheetModel.adjustIndent`, capped at 15), not from the active cell's. Guards: repo-root `test/` **cellTextLayout**; e2e **model-clear-cell-layout** (also the indent-geometry cases: every cell edge in an indented row equals the header's).


**Excel keyboard shortcuts, Alt key-tips, header selection and the real clipboard (NEW-1, 2026-10-29 — B2455072–B2455075).** Excel for Windows is the spec; ONE command registry (`lib/commandRegistry.js`) is what keys, key-tips, palette, ribbon and menus all run.
- `lib/keymap.js` — keystroke → command id (`CHORDS`, edit-mode subset, `navAction`); matched on `e.key` only. Ctrl+C/X/V are NOT here: they are native clipboard EVENTS.
- `lib/keyTips.js` — the Alt tree + pure state machine; `lib/univerExcelKeys/keyTipsController.js` draws the badges and the next-key strip. Alt starts only on a bare Alt keyup.
- Hidden rows/columns live in the workbook (`sheet.hiddenRows`, `column.hidden`). The real system clipboard, Ctrl+click header multi-select and every Excel key are `lib/univerExcelKeys/` (below); **headers are fixed labels** — no rename route exists, and `column.name` stays in the data only so old `[Name]` formulas keep resolving.
- Guards: repo-root `test/` **modelKeymap**, **modelKeyTips**, **modelHiddenRowsCols**; real-keystroke harness (the repo-root ui-audit file named verify-spreadsheet-keyboard).


**Selection is a LIST OF RANGES (NEW-2, B2530689).** The Schedule grid and the Notes tables use the shared range-selection module (`shared/selection/rangeSelection`; edit the shared file, then `npm run build:sequence-page` — the Schedule page loads it from the committed Schedule engine bundle, and CI fails if that bundle is stale). In the Spreadsheet, Ctrl+click / Ctrl+drag / Ctrl+header multi-range selection is Univer's own, with Excel's "won't work on multiple selections" refusals supplied by `lib/univerExcelKeys/`.

**Univer grid — THE grid for every account (NEW-1, B2557488 spike → cutover B2557489-series, default-on 2026-10-31). Read `docs/SPREADSHEET-UNIVER-SPIKE.md` (results, parity table, numbers, cutover plan) before touching any of this.**
- **WHY THE HEAVY DEPENDENCY IS ALLOWED (owner-supplied justification — do not re-litigate):** eleven grid-behaviour bugs were reported in ONE afternoon (Ctrl+Z in a cell, bare F going fullscreen, editable row/column headers, header click not selecting, Ctrl+click multi-select, drag-select stopping at the edge, clearing a cell nudging the neighbour, indent, the Excel shortcut set, clipboard, the false "different copy" bar). Every one was GRID BEHAVIOUR, not formula maths; the old grid was hand-built (~1400 lines, `sheetModel.js` ~1340, the shared formula engine ~2360, ~13k LOC) and Excel's grid has thousands of such rules, so the class keeps arriving. His words: *"make this as close to Excel as you can"*, *"I'd rather just copy someone's code"*, *"I'm not paying for anything"*. Excel behaviour is the spec.
- **Hard constraints:** open-source `@univerjs/*` ONLY, exact-pinned (`1.3.1`) — nothing from `@univerjs-pro/*`, no license key, no Univer server, no call to a Univer host, never Univer's exchange packages (xlsx/csv stay on ExcelJS / `csvIO.js`). Guards: repo-root `test/` **modelUniverSwitch** (also pins that only `UniverSheet.jsx` imports `@univerjs/*`, that ModelApp reaches it through `lazy()`, and that the four grid-level window listeners stand down while Univer owns the keyboard).
- `components/UniverSheet.jsx` — the lazy chunk (the only file that imports Univer): mounts the grid, debounces edits (300 ms) into a whole Planyr workbook and hands it to ModelApp's ONE `commit` (so write-through, cloud push, file mode and org workbooks are the same path); an incoming workbook equal to the last one emitted is our own echo and is ignored. `window.__planyrUniverRead` (the facade handle for harnesses) answers only when `window.__PLANYR_E2E === true`. `components/univerSheet.css` + `lib/univerTheme.js` — flat chrome from Planyr's tokens. **THE THEME IS PER MODE (B2566048):** Univer's gray scale never flips (0 lightest … 900 darkest; dark mode picks the other end) and its canvas goes through a colour inversion in dark, so `buildUniverTheme(base, tokens, { dark })` puts the text in `gray.0` and the surface in `gray.800/900` for dark (the opposite of light) and writes the canvas hairline / header tint pre-inverted; `UniverSheet.jsx` rebuilds it from the live tokens on EVERY flip, never once at mount. Do not write a surface into `gray.0` or text into `gray.900` unconditionally. Guard: the repo-root ui-audit harness named verify-univer-theme-contrast (pixels, both themes, mounted and flipped) + the repo-root `test/` suite **modelUniverSwitch**.
- **THE HEADER IS ONE STRIP (B2574352 / B2574353, owner 2026-10-30).** `UniverSheet.jsx` runs Univer's `ribbonType: "collapsed"` — the Start / Formulas / Data / View row is a "Start ▾" dropdown at the strip's left and the tab's tools sit left-packed beside it (Univer's default "classic" is a centred tab row over the tool row = two headers). `univerSheet.css` flattens everything under `[data-u-comp="headerbar"]` (no radius, no shadow, the trigger is plain text, never Univer's dark pill). A tool another session registers lands in the strip's own groups — never position or centre individual tools, never add a second header row. Undo / redo are curved arrows (`components/univerIcons.jsx`, swapped in by registry name through `IconManager` right after `createUniver`; the old the old toolbar glyphs are right-angle elbows and are NOT the model). Guards: the repo-root ui-audit harness named verify-univer-header (its pure verdict is the univerHeader module in the ui-audit lib folder; run the harness against `origin/main` to see it red) + the repo-root `test/` suite **univerHeaderVerdict**.
- `lib/univerBridge.js` — pure, imports nothing from Univer: Planyr workbook ⇄ Univer `IWorkbookData`, lossless for every stored field via a SIDECAR the host keeps (column ids, raw literal text, synthesised display patterns, dismissed-inconsistency and unsupported-formula maps — each entry self-validating so a sort or drag cannot make a stale one lie). What Univer cannot hold (vertical merges, `[Column]` formulas, typed-date text, in-cell rich text) is returned in `notes` and said out loud — never dropped quietly. Site.* / Plan.* / Comp.* become global defined names (`projectNamesToDefinedNames`; Univer accepts dotted identifiers as-is) and are NEVER saved back. Guard: repo-root `test/` **modelUniverBridge** (real fixtures + a workbook using every stored field).
- **Indent (NEW-1, B2572784).** Univer has no indent field or command; `lib/univerIndent.js` builds one on its cell PADDING (`pd`, which Univer's commands keep — a custom style field is stripped, measured): the indent N is stored as the cell's own `pd.l = 2 + 14·N` (so it follows its cell through insert/delete/sort/copy — NOT in the sidecar), drawn by a render-time `SheetInterceptorService` CELL_CONTENT interceptor on the reading side only and clamped to the column (same step and cap as the old grid's `cellTextLayout` / `sheetModel.adjustIndent`), changed by two commands — `INDENT_COMMAND_IDS` = `planyr.sheet.command.increase-indent` / `.decrease-indent`, the ids the Excel-keys plugin binds Alt H 6 / Alt H 5 to — each ONE `SetRangeValues` (one undo step, every cell from its own level), with buttons on the Start tab. `UniverSheet.jsx` only calls `installUniverIndent({...})` once after the first workbook loads (the sheets services do not exist before). The bridge maps `pd.l` ⇄ `styles[key].indent` (`indentOfStyle` / `storedIndentStyle`); never write a second copy of the number. Guards: repo-root `test/` **modelUniverIndent** + **modelUniverBridge**; the parity run's `indent` check (pixels) and section H of the live run (cross-grid, both directions).
- Harnesses (the repo-root ui-audit files named verify-univer-parity, verify-univer-live and measure-univer-vs-old): parity = the Excel checklist with real keystrokes, state asserted through Univer's facade because the grid is a canvas, run against the standalone host in the ui-audit univer-sandbox folder; live = signed in as the test account on a throwaway project (the default-on grid for a NON-admin with no switch anywhere, the owner hatch from both sides, mount, persistence, names; its sibling verify-univer-theme-live does the light/dark pixel check on the real app); measure = recalc / memory / first paint for both grids.
- **The Excel keys the free Univer build lacks are ONE Planyr plugin on Univer's own services (NEW-1, B2573632, cutover step 2) — `lib/univerExcelKeys/`, installed from `UniverSheet.jsx` (`installExcelKeys`) and disposed with it.** `index.js` registers each action as a real Univer command (`planyr.excel.<id>`, `ICommandService`) and each chord as a shortcut item (`IShortcutService`: binding = key code + modifier bits, `eventPreconditions` = the OLD grid's `keymap.js` predicate on `e.key`, `preconditions` = Univer's focus flags so nothing fires while the cell editor, the formula bar or the name box has focus — only Ctrl+5 joins B/I/U inside the editor, as `EDIT_MODE_CHORDS` says). `bindings.js` is the PURE half (key codes, Excel's number-format patterns, date/time serials, the Insert/Delete rules — unit-tested without Univer); `actions.js` runs Univer's own commands/facade, **each action inside ONE undo group**, and refuses several ranges with `MULTI_SELECTION_MESSAGE`; `keyTipsController.js` is the Alt machine (the SAME `lib/keyTips.js` table and `stepKeyTips` as the old grid; the Alt KEYUP is `preventDefault`-ed so Windows browsers don't take the menu bar; strip + toolbar badges are appended LAZILY because Univer's React root sweeps a child added at install); `dialogs.js` is Excel's shift-cells prompt and the width/height number prompt. **One list of keys:** *what a key means* stays in `keymap.js` / `keyTips.js` (the Keyboard Shortcuts page is derived from them), so adding a key is a row there + a row in `bindings.js` + an action; `chordCoverage()` and the repo-root `test/` suite **modelUniverExcelKeys** fail if an old-grid chord is neither native, built, nor a NAMED gap (`UNIVER_UNSUPPORTED_CHORDS`: Alt+=, F4 outside the editor, Shift+F11, Ctrl+PgUp/PgDn, Ctrl+S). Indent (Alt H 5 / H 6) runs the indent plugin's own `INDENT_COMMAND_IDS` (`lib/univerIndent.js`) in one undo group. The browser's own Ctrl+0/Plus/Minus zoom is stopped only by `preventDefault`, which a headless run cannot show. Harness: 33 strict checks in the repo-root ui-audit file named univerExcelKeysChecks (registered from verify-univer-parity; red on a build without the plugin — a check fails, never "not in the free build" — and each is required to be one Ctrl+Z); the live subset rides verify-univer-live.
- **The plugin also owns six behaviours the free build gets wrong (B2604256 / B2604258, default-on cutover; each has a parity check that is RED without it):** **movement keys** — Home, Shift+Home, Ctrl+Home, Ctrl+End, Ctrl+Shift+Home/End, PageUp/PageDown (+ Shift), Alt+PageUp/PageDown (`NAV_ACTIONS` + the pure `navPlan` in `bindings.js`; `scrollToCell` only when the target is off screen) · **Ctrl+PgUp / Ctrl+PgDn** step sheet tabs · **Enter commits a formula even with Univer's hint list open** (a shortcut above the hint's priority 1000, live only while that `<ul>` is on screen — Excel's Enter commits what was typed; Tab is for the list) · **Ctrl+C / Ctrl+X on several ranges** are refused with `MULTI_SELECTION_MESSAGE` (shortcut AND native copy/cut event) · **an empty paste says so** · and in `lib/univerTools` a colour equal to the app's default ink (either theme) is NOT a "manual colour", because Univer's editor stamps it on every cell it commits (typed numbers never turned input-blue). Open, filed, NOT built: B2604259–B2604265 (clipboard fill / Excel-HTML paste, Ctrl+Enter over several ranges, #REF! blank after a sheet delete, Name Box click-select + Ctrl+G, AutoSum, owner calls, an unconfirmed cross-project A1 report).
- **A cell's pixels, not its DOM (e2e):** the file named univerGrid in the repo-root e2e lib folder is the one helper. `getCellRect` ignores scroll and zoom (use its `visible*` helpers after a scroll); two clicks within ~0.5 s read as a double-click; "ink" is measured by LUMINANCE, because typed values are input-blue under the colour convention; the Site Planner tab, hidden but mounted, re-saves an injected local site edit ~0.6 s later.

- **LOAD TIME (NEW-1, B2587920, cutover step 4) — what is built and what is NOT.** (1) the repo-root scripts file named vite-plugin-univer-prune (registered in the app's Vite config for the app AND `worker.plugins`, and in the ui-audit sandbox config) removes Univer's ~77 lazy hyphenation-language chunks from the build (a sheet never hyphenates; `en-us` stays); it FAILS THE BUILD if a Univer upgrade changes the table it edits — never "fix" that by deleting the plugin (the formula worker then stops bundling). (2) `lib/univerFormulaWorker.js` runs Univer's formula engine in a Web Worker (`?worker` import in `UniverSheet.jsx`; same import discipline as `spreadsheetWorker.js`, pinned by repo-root `test/` **modelUniverWorker**); a worker that dies is a visible notice, a worker that cannot start falls back to the page. It costs ~0.7 MB compressed extra and buys back the main thread, NOT wall-clock. (3) `lib/univerWarm.js` + the shell's module-prefetch file: hovering the Spreadsheet tab (the shell's module-prefetch file, at idle time), and `ModelApp`'s own module scope, start loading the Univer chunk on EVERY device (skipped only where the owner's regular-grid hatch is on; **modelUniverWarm** pins it). univerCalcCache.js` remembers formula results ON THE DEVICE (IndexedDB, **never in the saved workbook** — a derived field there breaks `migrateWorkbook`/`sheetsDiverge`/the echo guard; keyed by the hash of exactly the workbook, never for volatile, spilling or `Site.*/Plan.*/Comp.*` formulas) so the first paint needs no calculation; ModelApp holds the grid back ≤150 ms for that read · the prune plugin also shortens Univer's hard-coded 300 ms render delay (shape-matched, fails the build if it moves — the one third-party edit; veto = delete the `UI_FILE` branch) · the repo-root scripts file named vite-plugin-spreadsheet-preload preloads the grid chunks at t=0 for a Spreadsheet URL. Guards: **modelUniversePrewarm**, **univerCalcCache**, **spreadsheetPreload**, **univerPrune**; ui-audit `verify-univer-calc-cache` and `verify-univer-parity` with `PARITY_PREWARM=1` (VOID unless an instance was adopted).
